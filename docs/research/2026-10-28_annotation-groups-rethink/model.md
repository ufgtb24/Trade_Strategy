本文中所有项目内路径均相对 repo root。mock 指 `docs/research/2026-10-26_annotation-workflow-polish/repro/mock_v3.html`（下称 `mock_v3.html`），polish 报告指同目录 `final_report.md`。用词以 `path2/GLOSSARY.md`、`path2_web/GLOSSARY.md` 为准；正例 = label `buy`，像但不买 = label `no_buy`（票 01 的叫法，`.scratch/annotation-path2/issues/01-structured-annotation.md:66`）。日期 2026-10-28。

## 0. 结论

1. **今天 `groups` 一节里至少捆了九样东西**，分属三家来源：用户给的（label、所属 pattern、成员）、界面从用户标注现算的（顶层特征串、画了没收）、用户标注和**会话写的对应表**比出来的（差）、**app 跑 K 线**得出的（app 判决），外加由它们合出的朱红，以及几样真正「一批共享」的东西（挪动单位、一键挪去、组头、组排序、`by:` 标识）。见第 2、3 节。
2. **除挪动单位外，所有轴都是「每个买点一个值」**。「组」只是「按某个轴取值相同把买点堆在一起」，而这个轴随阶段换（没 app 按顶层特征串，有 app 按差），连 label 是不是分组键也随阶段换（没 app 时 buy / no_buy 混在一组，有 app 时分开，`mock_v3.html:1216-1227`）。用户读不懂的根子在这里：同一个词「组」在三个阶段分别指三种不同的堆法。
3. **用户把主 / 偏离读成「和 app 比」，不算全错**。差的参照是对应表里的必须有、必须没有，这两级按 app 里的先后排、随 app 进 git（polish 报告 :91），组头那串「放量突破 → 回踩」正是 app 的 node 先后；差不看的只是 **app 跑出来的结果**。准确的分法是三家：用户的判断（label）、app **声明**要什么（经对应表，差）、app **实际**跑出什么（app 判决）。后两者都「和 app 有关」，名字和底色必须把「声明」和「跑出」分开，否则这个误读会一直在。
4. **差和 app 判决互不依赖，所以必然会不一致，而且两个方向都有**：用户补画或拿掉一个框只改差、永远改不动 app 判决（app 不读用户的框，`mock_v3.html:387-399` 只看 `st.matches`）。实测：把 TVRD 2025-04-28 的回踩移出成员，差立刻变 `−回踩`、app 判决仍是 buy。
5. **今天的合计 `app:buy k/n` 说「有几个」不说「是哪几个」**：缩略图不画 app 判决（`thumb()`，`mock_v3.html:1233-1262` 不调 `buyVerdict`），要知道是谁没买只能逐张点进去开 `compare` 看主图三角旁的签（`mock_v3.html:640`）。lead 说它是「全工具唯一的落点」——准确说法是：每个买点的判决主图上也有，唯一的是**跨图的合计和名单**。
6. **退役「groups」「主组」「偏离组」「by: sequence」「by: required」五个词**，原意各有承载者（第 6 节）。「偏离」这个概念留着（会话流程和盲看出口都要它），但只在讨论里用、定义写明「和对应表比」，界面上不出这个词。
7. **规模上有一个结构性差别**：label × 差 × app 判决的组合数由对应表的必须有、必须没有个数封顶，买点从 5 个涨到 500 个也不变多；顶层特征串是整串精确相等才算同一种，组合数随用户画过的特征数涨，背景框画不画、画了没收都会把同一种东西拆成碎组（第 5 节 h）。
8. **概念侧对 critic、flow 的回应**（第 4.1～4.9 节）：顶层特征串和差回答同一个问题（合不合骨架），差别只在有没有参照；已命名 pattern 页不按顶层特征串合并，混杂和忘切 pattern 从 features 区按特征进；像但不买只显示 label 和 app 判决；列表缩略图拿掉 ◂（改成员要在看得见图的地方）；**朱红一刀切**（app 判决和 label 不一样就朱红，拿掉偏离豁免，critic V1）——拆分后每一列只由自己的来源决定、朱红只由 label 和 app 判决决定，「原因多半在我自己的框」由差那一列说；「版本之间翻了哪几张」是一个要先选基准版本的新轴，偏向放会话的单子。
9. mock 有一处实情要知道：差为 `order`（必须有齐了但先后不同）的组，组头是空的——`diffTags()` 只画 `−X` / `+Y`、不画 `order`（`mock_v3.html:1091-1095`），主图签却用 `diffKey()` 写出 `order`（`mock_v3.html:641`）。

### 2.2 逐轴：用户拿它做什么、今天在哪里出现、和别的轴的不一致

**A label**
- 用途：表达判断；所有计数的分母只数 buy（N6，polish 报告 :95）；no_buy 必须说清像哪个 pattern（方向文档 :145）。
- 出现在：主图三角实心 / 空心、instance 页 `label`、缩略图三角、组上的 `buy n` / `no_buy n`。
- 在 groups 里的地位随阶段变：没 app 时 buy、no_buy 混在一组只分开计数（`:1217-1219`），有 app 时分进不同组（`:1221-1226`）。

**B 所属 pattern**
- 用途：决定买点算进哪个 pattern 的计数、对应表、app 对照。阶段 2（归组）在未归类页批量定。
- 在 groups 里不是分组键，是整页的范围（`sideSum()` 只取 `b.pattern === S.cur`，`:1106`）；`→ pattern` 是改它的批量入口。

**C 成员**：D、E、H 都从它派生；改它只在主图和 instance 页（缩略图 `◂` 是例外，点一下收进）。

**D 顶层特征串**
- 用途：写 app 前看一个 pattern 里是不是混了几种东西（方向文档第 8 节「能不能合并看骨架」，:165）；未归类页把「看起来同一种」的买点堆在一起好整批挪。
- **它不是方向文档的「骨架」**：骨架是「pattern 由哪几个 node 组成、它们之间的先后」（方向文档 :165），是 pattern 级的、按 node 说；顶层特征串是单个买点上、按用户画的特征名说，背景框（长下跌）、可有可无的（横盘）、会话还没处理的都在里面。写 app 前，它是用户拿来**猜**骨架的材料；写 app 后，骨架就是对应表的必须有按 app 先后排。mock 注释把两者混叫「骨架」（`:322`）。
- 出现在：没 app 的 pattern 页和未归类页的组头；缩略图的行（行 = 必须有 ∪ 这段时间画了的特征，`:1243-1245`）看得出它，但不是文字。

**E 差 / E′ 偏离**
- 参照：对应表里级为 `must` / `must_not` 的特征（`:328-333`）；可有可无、`excluded`、`unmapped` 的特征不影响（`flow.md:346`）。必须有的先后取自 app（`FAKE.musts`，`:133`）。
- 同一个值对 buy 和 no_buy 意思相反：
  - buy：`=` 是「对得上」；不为 `=` 叫偏离，要么图上其实有、去收进或补画，要么真没有、挪走或改 no_buy，要么「真没有也算」、改成有更好（单子 `dev` 三选一，`:1063`）。
  - no_buy：`−X` / `+Y` 是「为什么不买」的结构性理由（polish 报告 :90）；**`=` 反而是可疑的**——结构和正例一样，对应表分不开它和正例，理由只能在属性、备注或还没画的东西里（`flow.md:151`）。no_buy 的 `−X` 只算排在它最后一个已有必须有之前的（`:330`）。
- 用途：对正例，找出要修的（阶段 3 必须项检查、阶段 4）；按 polish 报告 :83，**它能暴露的 app 变严只是「新定的必须有有些正例没有」那一种**——全部正例都有、又没写定义的背景特征被定成必须有时，「训练段上没有偏离组……没有任何地方会暴露」，所以那一类改成不预填、必须用户选。对 no_buy，flow 定的用途是给会话当线索（`flow.md:151`）；用户在界面上拿它做什么，旧报告里没有写；本轮 flow 的任务 H 只找到 (no_buy, `=`, app 买了) 一格，而那一格会话会在单子里问，所以列表上不显示像但不买的差（4.2）。
- 出现在四处，时效不同：groups 的偏离组（现算）、`ask` 单子的 `dev` 条（会话上一轮写下的快照，图上改好后自动 `done`，`:1065`）、主图 `compare` 档三角下的签（`:641`，只对偏离的 buy）、instance 页成员链的空槽和划线块（`:907-928`）。挪走偏离有两个入口：groups 的 `→ pattern` 和单子的 `drop`。

**F app 判决**
- 只看 app 的 match 和买点日期（label 只决定容差），不看用户的框和对应表。
- 出现在：主图 `compare` 档三角旁的签（`:640`，琥珀底，对不上朱红）；groups 上每组的合计 `app:buy k/n`。instance 页和缩略图上都没有。
- 用途：看 app 和自己的判断哪里对不上（朱红不是用户待办，polish 报告 :73 阶段 4）；盲看出口的依据之一「剩余的朱红数」（`flow.md:159`）；调参后看丢了哪几张（sim F13：只显示当前一版，前后没处并排看）。

**G 朱红**：偏离的 buy 豁免，理由是「app 买了往往说明缺的那样其实在、只是没画」、「漏买该谁处理说不准」（ux D3，`ux.md:101`）。所以朱红不是「label ≠ app 判决」这么简单，用户要记住这一条例外。豁免背后其实是两种情形、两个理由：(buy, 偏离, app 买了) 是「缺的那样图上多半其实有、只是没画」；(buy, 偏离, app 没买) 是「对不上的原因在你自己的标注（缺了必须有），不先算 app 的错」。mock 的悬停只写了前一个（`:1204`），sim 在后一种情形下读成「这个没问题」（本轮 `sim.md:42`）。拆开后悬停要按 F 的值分开写。

**H 画了没收**：动作入口，不是分组轴。出现在缩略图 `◂`（groups、单子、两段之间的签展开的缩略图都有）、主图（选中买点时）、instance 页 `others` 排最前。

## 3. 为什么用户会觉得「组」混乱

1. **一个词三种堆法**：没 app 按 D 堆（buy、no_buy 混），有 app 按 E 堆（buy、no_buy 分），未归类页按 D 堆还带一键挪去。用户要记住「现在是哪一种」，`by:` 标识就是为此补的（M）。
2. **组头一行把三家来源排在一起，只有 app 那一家有底色**：差签是无底普通签，紧挨着琥珀的 `app:buy k/n`；主组组头又恰好是 app 的 node 先后——用户据此读成「主 / 偏离是和 app 比的」。实际差的来源是会话的对应表（会话那一侧现行用浅蓝，U36，polish 报告 :126）。
3. **「主」「偏离」两个形容词不带参照**：说不出「和什么比」。
4. **「组」里有一半东西是每个买点的属性，另一半是一批的动作**，用户问「组是什么」时没有一个答案能同时覆盖两半。

要记住的规则数（只算读懂 groups 这一节所需）：① 分组键随阶段换；② label 是不是分组键随阶段换；③ 差的参照是对应表不是 app 跑出来的；④ 偏离的 buy 不标朱红；⑤ no_buy 的 `=` 才可疑、buy 的 `=` 是好的；⑥ no_buy 的 `−X` 只算排在它最后一个已有必须有之前的；⑦ 可有可无、不放、还没处理的特征不影响分组，所以写完 app 组会重排。拆开后（不论界面怎么摆），① ② ⑦ 随「键不再随阶段换」消失；③ 靠名字和底色承载、不必记；④ ⑤ ⑥ 是差和朱红本身的语义，界面上只要还给用户看 no_buy 的差、还用一个朱红，就仍要记。再加上本轮和 critic 对齐的两条——像但不买不显示差（4.2）去掉 ⑤ ⑥，朱红一刀切（4.5）去掉 ④——七条都不必再记（前提是界面照第 4 节的约束做；没 app 的已命名页若仍按顶层特征串合并，① ⑦ 会回来）；③ 仍是最容易读错的一处，但它由列名「和对应表的差」与会话浅蓝底当场说出，不靠记。flow 按任务数出 9 条（`flow.md` 第 5 节），口径不同，以 critic 复数为准。

## 4. 拆开以后：概念层的约束（给 ui、critic）

这些是任何方案（含维持现状、整节删掉、lead 提的 instances 表）都要过的检查，不是界面方案：

1. **每个轴的来源要看得出**：A、B、C、D、H 是用户 / 从用户现算（无底），E 依赖会话的对应表，F 是 app 跑出来的（琥珀）。E 和 F 不能长得像同一家。
2. **键不随阶段换**：没 app 时 E、F 只是空着，不该换一种堆法；D 若保留，有 app 后也该是同一个意思。
3. **F 要能落到单个买点**：今天的合计只说有几个；要回答「是哪几个」，F 得出现在缩略图上，或作为合并行的一个键（flow v2 撤回了筛选控件，改按值合并）。
4. **挪动单位和显示分组脱钩**：今天能整批挪的只有「恰好同组」的那一批；未归类页整批挪的真实单位是「用户认定像同一种的那一批」，D 只是一个默认的预选。方向文档 :163 的原话就是「骨架相同的**排在一起**，由用户决定哪些算同一个 pattern」——排在一起，不是并成一组整批挪。
5. **一键挪去要按每个买点算**，不只看组里第一个（今天 `xs[0]`，`:1208`）；目标没 app 时整串相等的配对太脆（背景框画不画就配不上，见第 5 节 h）。
6. **偏离的四处出现**（groups、单子 `dev`、主图签、成员链空槽）若都保留，要分清哪处是现算、哪处是会话上一轮的快照：单子的 `dev` 条是会话上一轮写下的问题（图上改好自动 `done`，`:1065`），另三处是现算的当前状态——是「当前状态三处 + 一个已问的问题」，不是同一个东西出现四次，不必合并（critic M2 同判）。
7. 规模：A × E × F 的组合数有上限（由对应表的必须有、必须没有个数决定），D 没有。按前者汇总、按后者只做预选，规模才压得住。
8. **每一列只由自己的来源决定**：label 只看用户，差只看用户的框 × 对应表，app 判决只看 app；朱红只由 label 和 app 判决这一对决定（见 4.5）。今天的偏离豁免让朱红掺了差，三家来源搅进一个颜色，正是用户读错的那种混法。（初稿这里写「合计不上色」，是在保留豁免的前提下说的；采纳 4.5 后不再需要，合计照常按 label ≠ app 判决上朱红。）

### 4.1 顶层特征串和差：同一个问题、参照不同（回 critic M3）

- D 和 E 回答的是同一个问题：**这个买点合不合这个 pattern 的骨架**。没 app 时没有参照，只能让买点互相比（中性聚簇，没有对错）；有 app 后参照是对应表的必须有 / 必须没有（每个买点对一个参照，有对错）。所以「写完 app 从 D 换到 E」不是界面硬造的切换，是参照出现了。今天人为的是三件：一个「组」字把两种比法藏起来、要靠 `by:` 补；label 在一个阶段是键、另一个阶段不是；主组的组头只给一组显示参照。
- 但「按 D 整串相等合并」在已命名 pattern 页站不住：背景框画不画、可有可无的那段、画了没收、近义特征名没合并，各自都会把同一种东西拆开（演示里 WHLRP 2024-03-21 和 TVRD 2025-04-28 只差一个画了没收的横盘）。已命名页上要做的两个决定——查是不是混了别的（flow C）、忘切 pattern 混进来的那一批（critic F6，polish `critic.md:184` D7）——都是对**某个特征**做的：混进来的那批一定带着本 pattern 少见的特征（演示里的下跌、底部），从 features 区那个特征点开就是那一批。
- 所以概念侧的结论：**已命名页不按 D 合并**，前提是 features 区的特征行能点开、点开的那批能整批挪（这是 F6 的落点，交 ui）；**未归类页按 D 排**，作预选。若 ui 仍要在没 app 的已命名页按 D 合并：表头写出它是什么（顶层特征串，用户画出来的，无底色），不用 `by:`；有 app 后这一列让位给差和 app 两列，用户看到的是「多了两列」，不是「分法变了」。

### 4.2 像但不买的差显不显示（回 critic M1）

接受 critic M1：像但不买在列表上只显示 label 和 app 判决。概念侧理由：像但不买的差里唯一改变「谁动手」的是 (no_buy, `=`, app 买了) 这一格——结构和正例一样，要用户补一条分得开的属性或特征；而这一格必然朱红、会话下一轮会在单子里问（polish `flow.md` 第 12 节表 sim 第 1 条：「理由必填」不采纳，买了就朱红、会话问）。隐藏它换来少两条规则（第 3 节 ⑤ ⑥）。**代价**：两轮之间用户看到一个朱红的像但不买，分不出是「app 没用上一个结构差」（会话的事）还是「根本没有结构差」（用户该补特征），只能看缩略图自己比。flow 已在 v2 改为只留 label + app 判决（`flow.md` 任务 H），代价也写进了 H。

对会话单子的要求（sim 第 7 条提醒，本轮）：(no_buy, `=`, app 买了) 这一格的最后动手人是用户——对应表里没有任何结构分得开它，按地图总原则「脱离图的语言不能直接改 pattern」（`.scratch/annotation-path2/map.md` Notes），会话只能请用户把不买的理由画成一个特征、属性或必须没有。所以凡是给这一格的说明（单子条目、悬停）都不能写「你不用动」，要写「app 分不出你为什么不买：理由要画出来」；ui 变体 B 的悬停在这一点上是错的。

后续（本轮 sim 第三轮实测后，critic 裁定维持 M1，我同意）：不给「像但不买 · app 买了」那一格恢复可见签；分情形的那句从行上的 app 签挪到每张缩略图自己的悬停。理由：像但不买按 (label, app 判决) 合并，一行里可能同时有差为 `=` 和 `+派发` 的，行级悬停取第一张就会说错另一张，而这句话是每个买点的值。悬停按这张的差分开写：`=`——对应表里没有任何结构分得开它，理由要你画出来，会话会在单子里问；`−X` / `+Y`——结构差画了，app 没用上，会话按原因分流。悬停不进可见签，不加规则。演示里 TVRD 2025-05-08 的理由「回踩前一天放量长阴」只在单子的 label 翻转题里，不在任何框上，正是这一类。

### 4.3 版本之间翻了哪几张（flow I、J）是一个新轴

F″ **app 判决在两个版本之间翻没翻**：每个买点一个值，由两个 app 版本（或调参前后两套参数）的 F 比出。今天界面没有（flow I、J）。概念上它比其他轴多一个前提：要先选对比的基准版本（上一版 app、调参前、最近一次盲看用的那版），而「基准是哪个」本身就是用户要多知道的一件事。放进会话的单子或交付单时，基准由会话选定并写明，用户不用记；放进列表就得让用户知道「相对哪一版」。所以概念侧偏向放单子（critic F7 同）。不论放哪，数据层都要存每版每张的 F，或现场用旧版重跑。

### 4.5 朱红一刀切（回 critic V1）

- 同意 critic V1：app 判决和 label 不一样就朱红，拿掉「偏离的 buy 漏买不标红」这条例外。朱红只说用户自己定的那句话「app 结果和你的标注对不上」（polish 报告 :128 U38 起的用法）。
- 豁免原来防的是「挂朱红会把动手的人指成会话」（ux D3，`ux.md:101`）。拆开后不需要靠颜色防：朱红本来就不是用户待办、会话按原因分流（polish 报告 :73），偏离造成的漏买会被会话转成单子的 `dev` 题；「原因多半在我自己的框」由差那一列当场说。
- 悬停跟着改：「app 买了往往说明缺的那样其实在、只是没画」只适用于 (buy, 偏离, app 买了)，那一格本来就不红，句子挪到差签的悬停里，按 app 判决分开写；(buy, 偏离, app 没买) 写「这张缺了必须有，app 没买多半因此」。
- 代价：偏离的正例漏买现在也红，用户可能读成「app 错了、要会话改 app / 放宽 app」。过程记录：sim 第二轮在保留豁免的变体里，把不红的「buy · −回踩 · app no_buy」一眼读对了，critic 一度撤回 V1；随后认定「豁免那行也读得对」不构成保留豁免的理由（不变式优先），V1 仍定一刀切，并请 sim 按事先定的判据补测：读成要会话改 app 或放宽 app，才恢复豁免。**补测结果**：sim 在 A 第三版上测过（本轮 `sim.md` 第三轮，截图 `sim_r3_a_00_app.png`、`sim_r4_a_00_app.png`；`sim.md:226`），缺回踩那一行读成「app 没买，因为我的框缺回踩」，没有读成要会话改 app，按判据维持一刀切。限定：sim 自己打了折——那不是真正的第一眼，第三轮时它已经知道大部分签的意思（`sim.md:222`）。
- 规则数：第 3 节的 ④ 消失。

### 4.6 列表缩略图上的 ◂ 与未归类页的「相近」（回 critic V3、V4）

- V3 同意从列表缩略图拿掉 ◂：它改的是成员，是用户自己的标注；在看不见主图的地方一键改自己的判断，和「标注在看得见图时改」不一致（本轮 sim 第一轮第 6 条：不看图就收进）。主图、instance 页空槽、单子缩略图（点了跳图）里的同一入口都留着，H 这个轴不丢。
- V4 同意：已命名页不按顶层特征串合并（没 app 时只按 label）；未归类页把相近的串排在一起，只作顺序与批量挪的预选；不拿多数当参照（critic F5）。「相近」的口径（推的，待验证）：两条顶层特征串纯两两比较，相差几个特征（多一个、少一个各算一）就是多远，差得少的挨着；不用多数、不用对应表（未归类页本来也没有）。我给 critic 的第一稿用了「本页过半买点里出现的特征」，等于拿多数当参照，已撤回。

### 4.7 差那一列叫什么（回 critic V5）

- sim 第二轮第一眼把 `diff` 读成「和这个 pattern 该有的样子比」（critic V5）——**这个读法是对的**：参照就是这个 pattern 的必须有 / 必须没有，会话把它写进对应表、app 照着它写。会读错的只是挨着 app 列那一瞬间的「和 app 比」。所以列名要往「这个 pattern 的要求」上靠，不能出现 app。
- 两种说出参照的办法（交 ui 选）：(a) 用词——界面已有级的标识符 `must` / `must_not`（features 区与单子都在用），列名或悬停从它取，如「和 pattern 的 `must` / `must_not` 比」；(b) 直接把参照摆出来——在这一列的表头处显示一次这个 pattern 的必须有链（如「放量突破 → 回踩」）和必须没有（派发），值 `−回踩` / `+派发` 就是相对它说的。(b) 用的正是旧主组组头（K）的内容，但放对了位置：参照是 pattern 级的，只该在表头出现一次，不该当某一组的组头；代价是和上方 features 区重复一遍、占宽。
- 不论哪种，浅蓝底只说「这里有会话的份」，不足以说出参照（sim 没主动对上图例）；参照要靠字面。
- critic 取 (a)：(b) 与 features 区重复、占宽，字面说出「跟这个 pattern 的 `must` / `must_not` 比」就够，不加新词。我同意。
- ui 在页头加过一行偏离计数（`buy ≠ 1/3`）。概念上它和 app 判决的两个总数是同一类：pattern 级、由每个买点的值加出来。但页头那一行（`next` / `ask`）讲的是「现在等谁」，偏离已定不是用户待办，放在那里会被读成又一个待办数。另外 `≠` 和列里的 `=` / `−X` / `+Y` / `order` 是两套写法。要留的话（flow 的 G：剩余偏离个数就是补标注的进度，`flow.md` 第 4 节第 9 条），放在列表自己的汇总里，和 app 判决的总数在一处、用列里同一套词；否则不留。

### 4.8 features 区点开后要不要能整批挪（回 critic F6 落点）

要。critic 的主张是没 app 时误标的那批先不挪，写完第一个 app 后它们缺必须有、在列表里自成一行，再整行挪走，先挪后挪代价一样。**不一样的情形是：第一版 app 是在混进别人的数据上写的。**
- 定级规则：顶层特征出现在不到一半正例里的默认「不放」、不问（polish 报告 :80），只在 `excluded` 区写原因、不看那一区就不知道（polish 报告 8.1 残余风险 3）。混进来的买点撑大分母，本 pattern 的真特征会被悄悄压到一半以下。
- 演示例子：横盘突破回踩的 3 个正例里，横盘算 2 个（WHLRP 那张是画了没收，按规则也算「出现」），2/3 过半，会问；忘切 pattern 混进 AMST 2024-01-18、TVGN 2024-10-22 两个底部反转后变 2/5，横盘被默认不放、不问。
- 同一轮里，单子还会给下跌、底部这些别的 pattern 的特征出定级题，必须项检查也塞满混进来的买点。
- 写完再挪，挪本身一样便宜，但第一版已经按错的分母定了级，被默认不放的特征不会因为挪走就自己回来，要用户去 `excluded` 区点 ⚑，或会话下一轮重定。
- 「不挪也无妨」只在混进来的少、真特征离一半很远时成立。
- 代价：一个控件，复用列表上同一个 `→ pattern`，不添新概念。

### 4.9 critic 的三问（直接回答）

- (a) 偏离和像但不买的差是不是同一根轴：是，都是 E（这个买点收的框 × 对应表），对 buy 叫偏离、对 no_buy 是不买的理由。采纳 4.2 后，界面上只有 buy 显示差：一个词、一套签，不必靠 label 区分两种意思。屏上不出现「偏离」。
- (b) 顶层特征串和差是一根轴的两个阶段还是两根：是两个值（D 没有参照，E 有参照），回答同一个问题（4.1）。有 app 后，D 在已命名页没有列表任务（查混杂走 features 区），只剩行内缩略图的排序和未归类页的预选。
- (c) 每根轴的粒度：全部是每个买点一个值，`k/n` 只是合计。「组」就是按值相同合并显示，不是概念，不起名。

## 7. 对 lead 表述和旧报告读法的核对

1. lead：「先前研究定过偏离组还负责暴露『app 悄悄变严』（polish 报告 83 行）」。83 行说的是相反的那一半：全部正例都有、没写定义的背景特征被定成必须有时，训练段上没有偏离组、没有任何地方会暴露，所以改成不预填。偏离能暴露的只是「新定的必须有，有的正例没有」这一种变严。拆分后这一职责照这个边界写。（lead 已在本轮更正 `原始问题.md` 这一条，critic 同判。）
2. lead：「`app:buy k/n` 在整个工具里唯一的落点」。每个买点的判决在主图 `compare` 档也显示（`:640`）；唯一的是跨图合计和全部买点的名单。且这个合计不说是哪几个（缩略图不画判决）。
3. lead：「主组里的 buy 也可能 app 没买」——对，会朱红。反方向也有：偏离组里的 buy 也可能 app 买了（实测），不标红。
4. lead：「还没有 app 时没有主 / 偏离，按顶层特征串分组」——对；补一句：这时 buy 和 no_buy 在同一组里，有 app 后才分开。
