# user-proxy 走查笔记

扮演用户本人：策略方向的决策者，不读代码、不记内部字段名，色盲（靠冷暖和深浅分颜色）。只看方案描述、草图、截图，按六件典型任务「边看边说」，记下先看哪里、理解成什么、在哪卡住、一共点几下。

六件任务：
- a 打开 CRNC，看我标的样本 a / b / c 那三天 app 认没认出、认成了什么
- b 某个样本 app 没买，想知道是哪条条件没过
- c 一次阶跃之后，app 在新平台上哪些天买了、哪些天没买
- d 点 app 的一个 hit，看它由哪几段组成，并在 K 线上对上位置
- e app 的 plateau、step 这些轨分别对应我画的哪个框
- f 主视图和 compare 来回切，看是不是同一套东西

点击数只数「点、切换、展开」，滚动和悬停单列。

## 第 0 版：现状（基线）

依据：`images/14_compare_CRNC.png`、`images/15_hit_linked_selection.png`、`images/c01_annotate_CRNC.png`、`images/c02_compare_CRNC_full.png`。

### a 看 a / b / c 认没认出

1. 打开 CRNC，默认 annotate。主图上看到三个黑 ▲ a、b、c，底下 bracket 轨有三条虚线，底部平稳、站上新平台两行各一个虚线框，框前写着「a b c」。到这里都看得懂：这是我画的东西。
2. 点 `compare`（1 下）。K 线整个看不见了——副图把屏幕占满，最上面是 bracket，一串橙色条一行一个往下叠了二十多行。我第一反应是「这是什么、和我的 a/b/c 什么关系」。
3. 想判断 a 有没有被认出：只能拿眼睛把 ▲a 的位置往下对，找有没有哪根橙条的 ▼ 落在附近。▼ 很小、二十多行、没有竖线帮忙对齐。图上没看到任何「a 认出了 / 没认出」的字样（右栏 features 里只有总数 `in pos 11/11`，不说 a 是哪一个）。
4. **卡点**：答不出来。要么去数像素，要么回 annotate 看 ▲ 的日期再回来找。
- 点击：1 下，外加大量来回滚动与目测对齐。结论靠猜。

### b 某个样本没买，哪条没过

1. compare 里看不出哪个样本没买（同 a 的卡点）。
2. 即使知道是哪个，界面上没有从样本出发的入口。印象里诊断侧栏在 app 模式，要切过去、找 node、展开看候选——而那边说的是 plateau / step 这些英文 node，我得自己对上「站上新平台」。
- **卡点**：没有路。点击数无法估计（≥4 下，且需要记得诊断侧栏怎么用）。

### c 一次阶跃之后新平台上哪些天买了

1. compare 的「站上新平台」那行：几十行灰条夹着几段亮绿条。我猜绿 = 买了、灰 = 没买，但不确定（`detected_only` 这个标签我认得字面，但不知道它是不是「没买」的意思）。
2. 每根条代表哪一天？要看条的右端落在哪个日期——而 K 线不在屏幕上，日期轴也不在。
3. 好几簇条从不同起点开始，我分不出哪簇是「这一次阶跃」。
- **卡点**：读不出「哪些天」。点击 1 下（compare），大量滚动。

### d 点一个 hit 看由哪几段组成

1. 主视图（app 模式）里点一根 bracket（1 下），下面几条轨同时有条被加了黑框（图 15）。
2. plateau 轨是一摞十几根几乎一样长的亮绿条，其中一根有黑框——黑框和条的边一样细，在一摞绿条里很难找到；new_plat 轨是阶梯状深绿条，也是其中一根有黑框。today 处有一个红 ▼ 加红点。
3. 我能看出「大概选中了这几根」，但看不出它们拼成的是哪几段——old_plat 那根蓝条离 plateau 那摞很远，step 在哪我没找到。
4. **误解风险**：plateau 那摞亮绿和 new_plat 那摞深绿，对我来说是同一种颜色（都是暖色绿、深浅差得不够），我会把两摞当成同一种东西。
- 点击：1 下，但「看出是哪根」失败。

### e app 的轨对应我画的哪个框

1. 主视图轨名是 plateau、old_plat、step、new_plat、today；compare 里轨名是我起的「底部平稳」「站上新平台」。
2. compare 里「站上新平台」那行画的条，其实是 app 的 plateau（这一点只能靠别人告诉我）。我画的「底部平稳」那行在 compare 里只有我的虚线框，没有 app 的条——我会理解成「app 没认出底部平稳」，但其实也许是 app 根本没有对应的轨。两种情况在图上长得一样。
- **卡点**：没有任何地方写「站上新平台 ↔ plateau」。

### f 主视图和 compare 来回切

- 两边轨名语言不同、排列不同，像两个界面（这是之前就抱怨过的）。主视图有 K 线，compare 没有（被挤出屏幕）。
- 点击：1 下切换，但切过去以后要重新找方位。

### 第 0 版小结

| 任务 | 能否完成 | 点击 | 主要卡点 |
|---|---|---|---|
| a | 否（靠目测猜） | 1 + 大量滚动 | 没有「a 认出 / 没认出」的直接答案；K 线被挤掉 |
| b | 否 | ≥4，路不明 | 没有从样本出发的入口 |
| c | 部分 | 1 + 滚动 | 一天一行太多；看不到日期；灰绿含义要猜 |
| d | 部分 | 1 | 一摞嵌套条里认不出选中的那根；两种绿分不开 |
| e | 否 | — | 没有写对应关系；「没认出」和「没有对应轨」长得一样 |
| f | 勉强 | 1 | 两边语言、排列不同，切过去要重新找方位 |

## 第 1 版：fold-interaction 初稿 + compare-coexist 草图

依据：`notes_fold-interaction.md`（03:58 版）、`repro/mock_fold.png`（主视图折叠示意，合成数据）、`images/c10_mock_compare_CRNC.png`（compare 草图，compare-coexist 的笔记当时还没出）。

### 第一眼

- 主视图示意（mock_fold 右半边）：每条轨一行，一排小格子，高的是蓝、矮的是灰。我先看到的是「高低起伏」，马上能猜到高 = 好（进了 hit）。点中一个 hit 后有一条竖线穿过所有行，竖线上加粗的那格就是这次 hit 用到的——**图 15 的痛点基本消失**。
- compare 草图（c10）：最上面 K 线回来了；bracket 分 `user`、`app` 两行，我的 ▲ 在上、app 的 ▼ 在下；我的「站上新平台」行头下小字写着 `↓ plateau`，「底部平稳」框上挂着 `unmapped`。这三处我不用问就懂。
- 不懂的：右侧整片灰底是什么；`plateau ▸ step` 的 `▸`；为什么 step 露着、old_plat / new_plat / today 收起来。

### a 看 a / b / c 认没认出

1. 点 `compare`（1）。K 线在上，bracket 的 user 行里 ▲a ▲b ▲c，app 行里一串 ▼。
2. 要判断 a 认没认出，仍得自己看 ▲a 正下方有没有 ▼（▼ 三个挨在一起，哪个对着 a 要细看）。
3. 点 ▲a（1）：竖线落在 a 上，app 行有一个 ▼ 正在竖线上 → 认出了。
4. 往下看「认成了什么」：plateau 两行在竖线上**各有一格被框**，一行灰、一行绿。**误解**：我会以为 app 在 a 这天认成了两个东西。
- 点击：1 + 3（逐个点 a、b、c）= 4。**改进要求**：▲ 旁直接挂 match tag，不点就能读完三个；只框和 a 配上的那次 hit 用到的格。

### b 某个样本没买，哪条没过

1. compare 里点那个 ▲（1），竖线上看各行那一格的高低：矮 = 只检测到、中 = 条件都过了但没进 hit。能看出「卡在哪条轨」。
2. 「卡在哪条条件」要看右栏 selection 页（可能要再点 1 下切页）；主视图里则是点格后侧栏候选表自动滚到那行读 ✗。
- 点击：2～3。**未确认**：selection 页 / 候选表那一行是不是人话、是不是我的特征名；如果是内部表达式我读不懂。条件都过了却没进 hit（卡在段与段的关系上）时在哪看，也没说。

### c 一次阶跃后新平台上哪些天买了

1. plateau 那一族一行：高（彩色）= 买了的天，矮灰 = 没买。一眼看出节奏（比如「先买两天，停四天，再买两天」）。0 下。
2. 要确切日期就悬停格子（逐格悬停）或 ←/→ 走。
3. **小卡点**：同一时段有两行 plateau（两次阶跃的族重叠），我得先认出哪一行是「这次阶跃」——靠行左端的 `⊢` 起点和格子从哪开始；看 K 线上大阳线在哪能对上，但要想一下。
- 点击：0（看节奏），精确日期靠悬停。

### d 点一个 hit 看由哪几段组成，对上 K 线

1. 主视图点 bracket 行上那天的 ▼（1）：plateau 一格粗框 + 跨度细框，old_plat 整条框，step 一格框，new_plat 某一行一格框，today 一个框，全在竖线上或紧挨着。读得出「旧平台在这、阶跃在这、新平台到这」。
2. **卡点**：竖线只穿副图，不进 K 线。要在 K 线上对位置还得自己往上对。
3. **疑问**：new_plat 有两行（一行全灰），我不知道为什么一次阶跃有两行（其实是阶跃算一根还是算两根的两种认法，界面上没有任何提示）。
- 点击：1。

### e app 的轨对应我画的哪个框

- compare 里 `站上新平台 ↓ plateau`、`底部平稳 unmapped` 直接回答，0 下。
- **卡点**：plateau 有两行，我的框应该和哪一行比？图上没标。

### f 主视图和 compare 来回切

- fold-interaction 说两边同一套画法、同一套操作；但 c10 草图里格子一样高、只靠颜色，主视图示意靠高度。不统一的话我切过去会以为是两套东西。
- 主视图轨头只有英文 node 名，compare 有我的特征名，名字对不上的老问题还在。

### 第 1 版小结

| 任务 | 能否完成 | 点击 | 剩余卡点 |
|---|---|---|---|
| a | 能 | 4（逐个点样本） | 没有直接挂在 ▲ 上的 match tag；竖线上框了两格引起误解 |
| b | 部分 | 2～3 | 卡住那条条件的写法未知；关系不成立时去哪看没说 |
| c | 能 | 0 + 悬停 | 重叠的两族要自己认 |
| d | 能 | 1 | 竖线不进 K 线；两行 new_plat 没有解释 |
| e | 大体能 | 0 | 我的框和哪一行比没标 |
| f | 未定 | 1 | 两份方案格子画法不一致；主视图轨头没有我的特征名 |

### 已发出的反馈（第 1 轮）

给 fold-interaction：
1. 竖线穿进 K 线主图（任务 d）。
2. 「当前行」要看得见，否则 ←/→ 不知道会走哪一行。
3. 同一天两个 hit 时，按 → 竖线不动，我会以为按键没反应——给一个看得见的提示。
4. 族的悬停摘要写起点日期，帮我分两行 new_plat。
5. 赞同：调色板换中等深度、候选 bracket 的琥珀虚线改实线、hit 列表改成日期。

给 compare-coexist：
1. ▲ 旁直接挂 match tag。
2. 点样本后只框和它配上的那次 hit 的格。
3. 格子高度与主视图一致。
4. `plateau ▸ step` 与收起规则：要么全收要么全展；`▸` 看不懂。
5. 右侧灰底要有说明。
6. 标出 app 拿哪一行和我的框比、差几天。
7. 主视图轨头也小字带我的特征名。
8. 要一张现状 compare 第一屏截图。

补充（回答 fold-interaction 的三个追问）：
- 格子高低读得出；缩到 1～2px 宽时我估计只剩「高 / 不高」两档可读，对「哪天能买」够用，qualified 与 detected 的区别留给悬停即可。
- 竖线 + 加粗框在副图里够一眼；K 线那段仍要自己往上对，再次要求竖线穿进 K 线主图。
- ←/→ 两种走法讲给我能记住，但会在两处搞混：看不见哪一行在当家；在 band 行上走到没进 hit 的实例时 bracket 的选中突然消失，像按错了键。建议当家行头加记号；走到没进 hit 的实例时 bracket 那天给一个淡的「这天没有 hit」提示或保留上一个 hit 的淡框。

## 第 2 版：fold-interaction 修改版 + compare-coexist 初版笔记

依据：`notes_fold-interaction.md`（04:08 版）、重画的 `repro/mock_fold.png`、`notes_compare-coexist.md`（04:09 版）、重画的 `images/c10_mock_compare_CRNC.png`、现状第一屏 `images/c05_compare_CRNC_first_screen.png`。

### 现状第一屏（c05）

打开 compare 第一眼：整屏都是副图，K 线一根都看不到；最上面二十多行琥珀条，下面几十行灰条、绿条和 `detected_only` 标签。我第一眼不知道该看哪里。compare-coexist 查实是副图没有高度上限把 K 线挤成 0 高，已列为必修。

### 第一眼（新 c10）

- K 线在最上面，竖线从 K 线一直穿到最下面。
- bracket 的 user 行：一条虚线挂三个 ▲，旁边写 `a ✓` `b ✓` `c ✓`——**不点就知道三个都认出了**。
- 我的「站上新平台」框下面紧贴着 plateau、old_plat、step、new_plat、today 一组，左边一道竖线框住，行头写 `⇣ plateau`。框右边 `平台交界放量 true → step_vol ✓`。
- 竖线上只有「和 a 配上的那次 hit」的格加粗框，别的行竖线经过的格不框了。上一版的误解消失。
- 还是有点密：detected 档下满屏矮灰格和浅灰小 ▽，但高的蓝格一眼跳出来，不影响读。

### a 看 a / b / c 认没认出、认成了什么

1. 点 `compare`（1）。看 bracket 的 `a ✓ b ✓ c ✓`：认没认出，0 下读完。
2. 想看 a 认成了什么：点 ▲a（1）。顺着竖线往下：plateau 第三行粗框、old_plat 一根框、step 11-21 那格框、new_plat 中间那行竖线左边一格框（新平台截到前一天，要想一下）、today 那个 ▼ 框。右栏 diagnose 表列出 a 那天 app 的 3 个候选，▶ 标出配上的那个，step 一列写着阶跃日期。
- 点击：1（看结论）/ 2（看细节）。**待确认**：点 ▲ 后右栏是否自动切到 selection 页，否则每个样本 +1。
- 小疑问：new_plat 有两行在 a 那天都是高的蓝格（同一天两个 hit，阶跃算一根和算两根）；diagnose 表两行 in_hit 能说明，图上看不出。

### b 某个样本没买，哪条没过

1. 没买的样本会挂 `✗`（加朱红底），一眼找到。
2. 点它（1），右栏 diagnose 表 `failed` 列写着没过的条件。
3. **卡点**：条件名是 `old_flat`、`new_hold` 这类英文名。草图里下面有一行中文注释（旧平台平、新平台守住），但 compare-coexist 把这条注释列成「建议加」——没有它这一步我读不懂，等于没做。
- 点击：1～2。

### c 一次阶跃后新平台上哪些天买了

- plateau 那一族一行，高的蓝格 = 买了的天，0 下。日期靠悬停或点一格后 ←/→ 逐个走。
- 几族重叠时，要认出「这次阶跃」那一行：用竖线 + 粗框（点样本或点 ▼ 后）一下就定位，不用自己猜。

### d 点一个 hit 看由哪几段组成、对上 K 线

1. 主视图点 bracket 那天的 ▼（1）。每条轨一行，竖线经过、加粗的那格就是；细框描出各段跨度。竖线穿进 K 线，买入那天能直接对上。
2. 还差一点：「旧平台从哪天到哪天」在 K 线上的位置要从 old_plat 那根框往上对。fold-interaction 拒绝了淡底色（理由：太淡我看不出、和扫描窗外的灰遮罩混），我同意；提了一个可选替代（悬停某段时在 K 线上画它的左右两条细竖线）。
- 点击：1。

### e app 的轨对应我画的哪个框

- `站上新平台 ⇣ plateau`，0 下。
- 框和 plateau 哪一行比：点框（1），竖线落在框终点、配对那格粗框。框左端挂 `start not compared`（悬停出现），我知道左端对不齐不要紧。
- `底部平稳` 挂 `unmapped`：app 没有对应的轨，不是没认出。

### f 主视图和 compare 来回切

- compare 的 app 部分就是主视图那张副图，画法、点法一样；档位按钮两边共用一份。这一条基本成立。
- 还差：主视图轨头只有 plateau 这些英文名，没有我的特征名。
- bracket 的 app 行：fold-interaction 新版改成「第一个 hit 一根条 + 其余每个一格」，c10 草图还是整根琥珀条，两边要统一。

### 操作上的新顾虑

- **Delete 误删标注**：compare-coexist 查到，在 compare 里先选中我的框、再点 app 的格，这时按 Delete 会删掉我的框。对我来说这是最严重的一条——标注是花时间画的。要求改成必做：点 app 的东西时清掉框的选中。
- **←/→ 在 compare 里走什么**：点了 ▲a 再按 →，我期望走到 ▲b、▲c（逐个核样本）。fold-interaction 的规则是「在最后点的那一行里走」，如果 user 行也算一行，正好就是这个效果。
- **当家行看不出来**：mock 里当家行的标志是一条加粗的底线，贴在选中框下沿，不告诉我注意不到；建议行头名字一起加粗。
