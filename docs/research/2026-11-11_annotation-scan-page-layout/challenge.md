# 挑战稿：标注与扫描要不要拆页

本文件中所有项目内路径均相对 repo root。已删除的研究目录（`docs/research/2026-10-25_annotation-display-workflow/`、`2026-10-26_annotation-topology-grouping/`、`2026-10-28_annotation-web-loop/`）在提交 09047e4 里删掉，下文引用一律取自 `git show 09047e4^:<路径>`。

## 1. 历史决定：「标注是主视图的一种模式，不另开页面」从哪来、今天还成不成立

### 1.1 当时在两样什么东西之间选

- 规格 `.scratch/annotation-path2/spec.md` 第 5.1 节（第 331 行）的出处是票 01 第 1 节。票 01（`.scratch/annotation-path2/issues/01-structured-annotation.md`）Question 第 16 行问的是：「标注做成主视图的一个可编辑模式，还是**保留独立页面再加事件图层**」。
- 那个「独立页面」是具体的旧东西：第 25 行「现状：标注页 `AnnotChart.vue` 完全不画 path2 事件，`App.vue` 带 `?wf=` 时整页换成标注页」。也就是说，备选是一个**自带另一套画法、一个事件都不画**的页面。
- Answer 第 1 节（第 63 行）给的唯一理由：「防的是：标注和显示两套画法，标完对不回来」。10-25 的评论（第 29 行）说得更直白：「标注长在主视图上、用和副图同一套事件画法」。
- 这个决定从头到尾比较的是**画法是否同一套**，没有比较过页面外壳、左栏放什么、区域怎么分配。

### 1.2 理由今天还成立吗

- **成立，而且后来被加强了**：spec 5.8（2026-11-05 改）规定 compare 的 app 部分「和 `app` 模式完全同一套：同样的折叠、档位、选中与联动、当前日竖线……band 的显隐也是同一份状态」。代码上也是这样：`KlineChart.vue` 一个组件承担 annotate / compare / 两种 app 四种状态，`render/chart.ts` 的副图画法只此一份（inventory.md 第 2.1 节）。
- **但它约束的范围比「不另开页面」窄**：它要的是「同一个图表组件 + 同一份图表状态（档位、显隐）」。一个复用同一 `KlineChart` 和同一 `view` store、只是外壳不同的「页面」，并不违反这条理由。真正会违反它的，是把图表状态拆成两份（例如两个 HTML 入口各起一套 store），或为标注另写一套画法。

### 1.3 左栏为什么在标注时是扫描

- **不是谁定的布局**。用户认可、spec 5.1 说「只沿用它体现的决定」的原型 `mock_v4.html`（`09047e4^:docs/research/2026-10-28_annotation-web-loop/repro/mock_v4.html` 第 107 行）只有「图 + 右栏 380px」两列，**没有左栏**。注意：spec 5.1 写的原型路径在工作区里已经不存在。
- 实施票 `.scratch/annotation-path2-implementation/issues/04-open-by-symbol-shell.md` 的范围写「不改现有的扫描流程」「现有的扫描入口照旧能用」，自查里记了「左侧扫描面板有灰字中文提示……老部件，本票没改」。左栏留着扫描，是「范围外不碰」的副作用。
- 10-26 拓扑研究里写过一句「全工具只此一份买点列表……左栏仍按股票列」（`09047e4^:docs/research/2026-10-26_annotation-topology-grouping/final_report.md` 第 108 行）。在 spec 和说明书里查不到，按「研究里提过、没进规格」处理。

## 2. 对 options 领先方案的质疑

被质疑的是 `options.md` v1 的领先方案 B「一个页面、两套外壳」：顶栏最左一个 `page` 开关在 `annotation` / `scan` 之间切；`annotation` 外壳里 `mode` 三档，`app` 一律现算，左栏换成找图清单（`rally` 铺开 + `charts` 已标股票）；`scan` 外壳原样保留旧布局、没有 `mode` 组。

按分量排：

1. **B 的 `page` 开关等价于给 `mode` 加第四档**（剃刀）。`scan` 外壳底下只有一个状态，B 的全部状态正好是 4 个：标注×annotate、标注×compare、标注×现算 app、扫描×扫描 app。这和把顶栏 `mode` 改成 `annotate / compare / app / scan` 四档一一对应（`app` 只指现算，`scan` 就是今天 `appSource = scan` 的那个视图）。四档版本覆盖相同，却：
   - 不新增概念：`scan` 已是 `path2_web/GLOSSARY.md:11` 的词；`page` 要新进词表，还和侧栏的「pattern 页 / feedback 页 / selection 页」撞字；
   - 从扫描图到同一只股票的 compare 是 1 下，B 要先切 `page` 再点 `compare`，2 下；
   - 内部可以不动 `view.ts` 的 `mode` / `appSource`：顶栏只是把今天藏在一个 `app` 按钮里的两种来源拆成两个按钮，左栏按「是不是扫描视图」换内容；
   - 视觉上同样能分组：`annotate compare app │ scan`。
2. **F10（扫描列表抢键）不会「自然消失」，B 的两条默认互相矛盾。** B 同时要「各外壳记住清单、排序、滚动位置」和「扫描列表只在 scan 外壳挂载，按键监听随之卸下」。扫描列表的滚动位置和虚拟列表起点是组件内状态，卸载就丢；项目里 rally 弹层正是为留滚动用了 `v-show`（`TopBar.vue` 注释）。而用 `v-show` 或 `KeepAlive`，挂在 document 上的 keydown 监听不会卸。所以任何方案都要给扫描列表的按键加「只在扫描视图生效」的守卫，或者接受丢滚动。B 对 C 在「键盘被抢」一行的优势因此缩小。同类泄漏 options 没列的还有两处（inventory.md 1.3、1.6）：`Shift+P` 在 annotate 下照样打开参数副本抽屉；有扫描时休眠草稿横幅会出现在 compare 里。
3. **测试改动低估。** v1 算的是「两条 e2e 改写 + 快照」。实际有 15 个 e2e spec 是 `page.goto('/')` 后直接点左栏的「扫描 ⚙ / 打开历史」：hit-event-disambig、flow、scan-dialog、symbol-search、sidebar-chart-focus、subchart-* 四个、shift-pair-feedback、miss-detection-walkthrough、kline-ctrl-wheel-right-anchor、dev-ui-replication、annotate-open-by-symbol、annotate-rally-random；另有 fold-rows 经辅助函数 `e2e/smallScan.ts` 点同一个按钮。页面默认落在标注、这两个按钮只在扫描一侧时，它们都要先多一步（可收进一个辅助函数，但改动面是 16 个文件）。A / B / C / 四档都一样，不分高下，但工作量要照实写。
4. **漏查的历史：V-S1 记录里用户已经提过这件事**（`.scratch/annotation-path2-implementation/v-s1-notes.md`「界面改进」）。
   - 第 9 条（11-05）就是本题的前身：rally 和 random 的结果放进左侧列表，「点一下就切股，上下键挨个翻（主视图列表已有）」。v1 默认「↑/↓ 只在清单有焦点时切股」与此相反：画完框焦点就不在清单上，↑/↓ 失灵。应改成「焦点不在可编辑元素里时 ↑/↓ 翻清单」（全页目前只有扫描列表用 ↑/↓，不冲突）。
   - 第 2 条（11-03）要看出「只画了框、还没放样本的图」。v1「只画了框、没放样本的，`pattern` 列空」会让 rally 页上「只画了框」和「完全没碰」看起来一样，正好重现这条抱怨。rally 页要有一列能区分两者（如框数）。
   - 第 8 条（11-05）「标注模式和主视图割裂」，会话当时建议的原则是「标注只往主视图上加东西，原有操作和控件在每个模式下保持一致」。我当时的读法是「用户抱怨的是图上拖拽、缩放、分档的习惯不一致，图表层 B 没动，所以不冲突」；后来找到的原话（见 1.4）显示 rally 清单不在左侧列表也是「割裂」里最棘手的两件之一，所以左栏换成找图清单本身就在落实这条。「两套外壳」的提法容易被读成又分裂了一次，四档的提法更贴近这条。
5. **红线论证对 C 不公平。** v1 用「用户翻到 scan 页签时 app 输出会进 annotate」压低 C。但用户 10-26 定过「训练段上看着 app 标是自由」（票 01 第 46、91 行；compare 换图不退出也出于此），说明书第七节第 2 条防的是「默认就看见」，不是「自己点开去看」。今天真正越线的是「加载过扫描后，左栏在 annotate 下默认就并排摆着全池命中和收益」，B、C、四档只要默认不是扫描都能解决。C 真正的弱点只有一条：页签和 mode 无关，扫描列表可以在 compare 下可见、可按键，要另立「扫描行在 compare 下点了落哪」的规矩。
6. **「切换时带上当前股票」只对一个方向成立。** 扫描→标注带股票有用（今天就这样）。标注→扫描带股票：当前标注的股票未必在扫描文件里（扫描结果只收命中过的股票，`path2_web/scan.py` 的 `_aggregate_multi`），扫描视图拿一只不在结果里的股票画什么？今天 `selectSymbol` 只从扫描列表调，没碰到过；B 新造了这条边。应定为：标注→扫描回到扫描视图上次停的那只（或扫描第一行），不带。
7. **第 4 节「左边去哪看、右边眼前有什么」这一轮是过度设计。** 这一轮的产出（rally、charts 两页）没有它也做得出；它真正改变的是第二段盲看清单放哪（要改 spec 6.5），而盲看还没排期。把一条这一轮不产生任何差别的原则交给用户拍板，是增加决策负担，应挪到第二段做盲看时再提。另要写清 `charts` 页和右栏 pattern 页样本卡的分工：`charts` 按股票、跨 pattern、含只画了框的图；pattern 页按样本、只当前 pattern。
8. **「主视图」会变含糊。** spec 用了 12 次、说明书 4 次，多指今天的扫描 / app 视图（如「要看数字回主视图的诊断侧栏」）。改规格时要定它指哪边。
9. **A 与 B 差别很窄：同意。** 补一条：A 的扫描页不起标注 store，两个浏览器标签一边扫描一边标注时不会有两个标注写入者；B 开两个标签是两份标注 store（今天也这样，有冲突提示兜底）。不改变结论。
10. **漏了一道方向题：扫描界面今后的定位**——日常工具，还是偶尔用的调试工具。证据偏向后者：盘上没有一份扫描能在网页里正常显示（其余 4 份过不了数据墙、打开回 409；11-03 的 bo_only 打得开，但它是 match→hit 改名之前扫的，列表 0 行、图报错——按扫描文件不做兼容的规矩这是预期；inventory 在浏览器里核实），也就是 11-04 之后没人在网页里跑过扫描；`wc.json` 不存在；调参默认入口已是 tune-gates-v3 脚本；扫描侧组件 9 月后只有改名。它决定扫描入口要不要占顶栏常驻位置、扫描视图里和标注无关的毛病这一轮要不要一起收拾。

### 2.1 针对 options v2「B 与 C」一段的追加反驳

编号说明：本节的 K1–K4 用的是 options v2 的编号（K4 = 扫描选股不清图窗）。options v3 起改为 K1–K5：K4 = 休眠草稿横幅漏进 compare，K5 = 扫描选股不清图窗。

v2 把 B 领先的理由收敛为两条 C 覆盖不了的事：`app` 按钮不再管两种来源（用户这次问「标注的 app 是不是扫描结果」就是这个误解）；扫描部件在标注里结构上不挂载，漏键一类毛病（options 1.2 的 K1–K4）整体消失。

11. **这两条都不需要新开一根外壳轴。** 下文的 F 方案（`mode` 四档、左栏随视图换）把 `app` 按钮拆成 `app` 和 `scan`，误解同样消除；左栏按视图换，扫描面板的挂载范围和 B 完全一样。所以「B 与 C 覆盖不同」成立，但 B 与 F 覆盖相同，按 options 自己在 A 与 B 之间用的剃刀口径，应取 F。
12. **「K1–K4 结构上没有」说过头了。**
    - K1、K2（扫描列表挂在 document 上的按键）：只有扫描列表真卸载才结构性消失，但 B 同时承诺「两边各自的清单、排序、滚动位置都还在」（见第 2 条），两条承诺只能留一条，或者把滚动状态搬进 store。
    - K3（`Shift+P` 打开参数抽屉）：处理函数和抽屉都在 `ChartArea.vue`，和左栏无关。「只在扫描一侧」就是给它加一道视图判断，与 C 的「逐个加守卫」是同一件事。
    - K4（从扫描列表选股不清「打开时给定的图窗」）：是 `view.ts` 的 `selectSymbol` 少清一个字段。B 的「扫描→标注带上股票」走的正是这条路，不修就照样有。
    - 所以 B 相对 C 在这一行的真实差距只是：K1、K2 在「卸载、接受丢滚动」的前提下结构性消失；K3、K4 两边都要各修一处。F 在这一行与 B 相同。
13. **第 6 节第 2 道方向题（左右分工原则）仍留在「要用户定」里**，第 3 条的测试改动仍写两条 e2e，大涨段清单「只画了框的，`pattern` 列空、悬停写框数」不悬停就和「完全没碰」一样——这三处 v2 没有改。
