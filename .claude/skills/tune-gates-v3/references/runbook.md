# 执行、故障处理与落地

## 搜索前检查

读取 app 当前参数及检测代码，确认每个待调字段在哪起作用、哪些关系必须成立、是否会改变评价尺子或买点位置。评价的 horizon/k、买入价口径、股票池、买点 node 不是本轮待优化参数。

对买点当日可知性做真实核对：买点事件确认了，不表示祖先的后验字段、容器统计或最终关系当天已经可知。优先使用已有的因果性质测试；没有时可在训练数据上对照截到买点日的检测结果。如果对照失败，先修正研究范围或转入检测逻辑修复，不根据被泄漏抬高的成绩调参。

按股票池的历史长度安排日期；确认样本使用记录和本会话已看过的数据。v1 最新 open 的两个保留窗口仍受保护，即使旧记录尚未验证；无法判断范围时停止取数并核对。账本、app 名称和账本目录保持原样，已用过的数据就按用过处理。

回看起点 history_start 默认自动推算，它也登记为暴露范围；历史保护同时覆盖特征回看与未来标签。同谱系 app（bottom_burst、bb_v1 及其他 bb 系）一并人工核对：自动账本按 app 区分，跨 app 的暴露要靠这一步。

一个 app 在同一时刻只跑一种调参流程。v3 使用独立 JSONL 记录并读取 v1 已消费/保留范围；v1 不读取 v3 记录，所以反向切换需要显式检查两本记录。真实运行使用主目录的账本（或沿用既有 `TUNE_LEDGER_DIR`）；临时账本目录只给合成测试与冒烟用。

## 如何解释结果

主表并列原参数与候选的方向成绩、对随机日基线的差（择时 + 选股）、对同日普通买入对照的差（选股）、排名分及领先部分保留的比例与折扣状态（误差估计尚未校准）。另列固定 bo（同样三项）、前瞻收益、盘中回撤、原始与可评估机会数、先上/先下/未触线数量、条件先上比例、股票/日期/时段覆盖、近期买点数和行情没更新到位的股票数。方向成绩不等于收益率，未触线也不等于零收益。

偶然波动取 `noise.json` 的 `delta_sd`：相近参数之间的差别一般是它的一半左右，过去实测参数改动的效果约 0.03（待验证）。它的一半明显大于 0.03 时，这一轮基本分不出好坏；没用全部股票就提醒一次扩大股票池。现役自身方向成绩为负或不如同日普通买入对照时，醒目提示这个 pattern 这段时间整体不好，要不要继续用由用户决定；它不影响参数之间的比较。

训练里的分差是挑选后的观察值，主要用来决定值不值得送检，不是预期改善。不同配置新建多轮训练也算多次尝试；使用记录不会因文件夹换名而重置。单个 SQLite 给出本轮次数，累计次数从所有同 app 已登记运行的记录及结果核对；没有所有历史记录时明确「仅已登记的这些轮次可核对」。

| 状态 | 阶段 | 含义 | 落地 |
|---|---|---|---|
| `provisional` 暂用 | 最后检查 | 要求都满足、排名分高过原参数 | 写候选，交付复核日期与范围 |
| `retained` 继续使用 | 复核 | 同一规则再次通过 | 保持候选，应用记录改标继续使用；本轮关闭 |
| `reject` 不采用 | 最后检查 | 未满足要求、没有改善或无法比较 | 保留现役 |
| `rollback` 撤回 | 复核 | 未满足要求、没有改善或无法比较 | 恢复本轮原参数 |

「继续使用」是两次独立观察都改善，不是统计确认。只有一个冻结候选进入一次最后检查；没有改善就维持原参数，这也是完整结果。

## 行情未到齐

最后检查与复核先只读文件末日判断行情是否整体到齐（到齐比例 ≥90%），通过后才登记使用、计算标签。报「行情整体尚未更新：到齐 x / 应到 y，要求至少到 <日期>」时，本次检查没有登记，数据仍未用过；更新行情后原命令重跑即可。通过时没到齐的少数股票照常保留，名单在结果的 `stale_symbols`，报告股票数。

## 检测代码改过之后怎么做最后检查

源码摘要覆盖 `path2/`、`path2_apps/` 与本 skill 脚本；不一致时检查在登记前拒绝，数据不受影响。

- 报错给出冻结时的提交：在主目录建一个检出该提交的 worktree（`git worktree add <路径> <提交>`），在 worktree 根运行 `uv run python .agents/skills/tune-gates-v3/scripts/run.py validate --run-dir <主目录运行目录的绝对路径>`（复核换成 `review`），并设 `TUNE_LEDGER_DIR=<主目录账本目录的绝对路径>`。报错里已写好这两个路径。worktree 里 `uv run` 会建自己的环境；行情目录在配置里是绝对路径，不需要另外准备。跑完后删 worktree。
- 报错说没有可回退的确切提交（冻结时检测代码有未提交改动，或没有 git 信息）：这一轮无法在原代码上检查；按「故障与关闭」关闭本轮，重新冻结。

## 故障与关闭

读取标签前已写消费记录，因此扫描中断后不能假定没看见。完整 `final.json/review.json` 可重复只读；没有完整结果则报告本次检查未完成，该范围不再充当新一轮独立证据。程序故障可用已消费数据诊断修复，但不能改候选后再称一次独立验证。

训练中断可查 SQLite 的已完成尝试，现版不恢复 sampler 状态。关闭旧轮后，重新固定新一轮配置及总预算，再在训练数据重跑；保留历史尝试总数。终止命令：

```bash
uv run python .agents/skills/tune-gates-v3/scripts/run.py abandon --run-dir RUN
```

该命令关闭本轮，只释放未消费的预留范围，已见结果不会重新独立。没选出改动时自动关闭；最后检查不采用、复核继续使用或撤回后也自动关闭；暂用时保留到复核。

如果最后结果已保存、但随后关闭动作中断，保存结果仍有效；核对决策后可运行 `abandon` 补上关闭。不要对暂用轮次这样做，除非明确决定终止暂用并恢复原参数。

## 落地与恢复

脚本不覆盖正式参数，落地由 agent 在已有授权内执行，便于保留文件注释、应用特有格式及用户后来的更改。不要为普通可逆写入增加一套未经用户要求的审批；但若本次仅请求评估，必须先呈现确定结果，再就实际写入问一次。

1. 读取冻结配置、候选及最新 `final.json` 或 `review.json`，核对摘要与该轮使用记录。`provisional` 写候选；`retained` 保持候选并在应用记录改标继续使用；`reject` 保留现役；`rollback` 恢复本轮原参数。已被关闭的暂用轮次仅作历史记录，不再按旧 provisional 结果写入，因为复核预留已释放。只写整套候选或整套原参数。
2. 重新调用 `load_params().to_dict()`。首次写入必须仍等于冻结原参数；复核撤回必须仍等于这轮已经写入的候选。若不同，检查并解释并行修改，不能覆盖。找到 app 实际 YAML 来源，不能凭文件名猜路径。
3. 在本轮目录保存正式文件**原字节备份**、目标参数完整快照及待应用差异，状态标为待写。仅改必要参数值，保留无关字段与注释。复核撤回使用原字节备份，先核对没有其他合法修改。
4. 写后重新加载，要求 `Params.to_dict()` 与目标完整字典相等；用 `build_pattern` 检查声明可构建。失败即恢复备份并报告，不能宣称已采用。
5. 本轮写 `application.json` 记录 app、正式文件相对路径、来源结果摘要、写前/写后内容摘要、采用状态与时间、复核范围、备份路径；再读取核对。若未实际写入，明确“已给出采用结论，尚未写正式参数”。
6. 暂用状态交付时给出具体复核日期和数据范围。用户后来请求复核时，先查应用记录确认这套参数是否仍在使用；运行 `review` 后按继续使用或撤回完成上述相应写入/状态更新。过去仅出具的暂用建议如实说成建议，不说成已经发生的实盘试用。

若没有授权创建定时任务，不创建。保存在应用记录里的复核安排仍需用户或后续调用触发，不能承诺 agent 会自行持续监控。

## 验证维护

从仓库根运行：

```bash
uv run python -m pytest -q .agents/skills/tune-gates-v3/tests
uv run python .agents/skills/tune-gates-v3/scripts/run.py --help
```

测试只用合成价格和临时账本，包含真实 bottom_burst 的接口检查，及真实 Optuna 与排名分/消费规则的串联，以及 close 标签、同日普通买入对照缓存、固定 bo 和买点前缀检查。它们证明已覆盖行为的实现一致性，不证明真实市场提升；不能据测试通过给旧版或 v3 宣布胜负。
