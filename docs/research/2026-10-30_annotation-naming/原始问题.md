# 原始问题（2026-10-30，用户原话逐字）

“买点”是否包含 no_buy? 这很别扭。
关于下列几个概念，是不是应该梳理一下命名规范
- 标注的 buy 三角形
- 标注的 no_buy 三角形
- 标注的正例：一堆框构成的，像一个集合，不光是正例三角形，但是现在被统称为“买点”，明明不是一个点，而是很多框
- 标注的反例：一堆框构成的，不光是反例三角形
- app match 出的 pattern

以及 buy， no_buy 是否会挂靠到某个 pattern 之下，作为这个 pattern 的正例和反例，还是说 buy 和 no_buy 是不需要绑定 pattern 的？
用不同维度梳理一下上面的概念，给出更有调理性，不容易混淆的名词。我觉得“买点”这个词不好，因为它没有很贴合“标注”这个流程，而是一个业务词汇。“标注”是一个工程名词，对应的 正例 反例。
你可以重命名所有的东西，例如将 key 名 buy 变成 pos，no_buy 变成 neg。
