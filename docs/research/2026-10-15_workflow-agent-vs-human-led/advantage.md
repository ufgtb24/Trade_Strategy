## 0. 结论先行

1. **按决策类型分权，整体更接近 A（agent 主导），但 A 与 B 的差距是二阶的。** 一阶问题是「裁判写成事先批准的规则、并且规则真的在执行」；规则到位之后，A 和 B 只在一小块上不同：训练段内圈「下一步试什么、收紧后接不接受」由谁临场推进。这一块归 agent（在规则和账本里），理由是精度，见第 3 条。
2. **人的贡献**：不可替代的「权」是方向、不可逆资源的同意（开验证段、上线、停用、花钱）、自己所提形态的意图解释权、每周挑票。有证据支撑的「能力」有三项：
   - 方法论和论证的审查（多次纠正 agent 的方法论框定、戳穿动机性推理）——这一项作用在规则质量上，是一阶的；
   - 看个别命中时抓出「这个不对劲」的前瞻 / 语义 bug；
   - 数据里没有的信息，包括自己能不能照规则执行。

   看图时的整体判断作为**优势来源**，目前没有证据。上面的归因受证据库偏向影响，可能低估了人。
3. **为什么内圈归 agent 而不归人**：不是因为人的时间稀缺（用户时间不是终点的瓶颈），也不是因为 agent 更快（吞吐不是瓶颈）。是因为 agent 看到的东西全都经过工具、全都留在记录里，它据此做的选择可以被计数、被打折，也可以被限定为「只看汇总数字、不翻个股图」；人在看图后做的选择，所接触的信息（整张图的几百种细节）不入账，看过的赢家还会直接留在成绩里、看过的输家被条件剔掉。这条是推理加一处代码事实，强度【中】。
4. **为什么不选纯 A**：agent 在本项目里多次把给它的目标优化到底并报成成功（包括目标已被认定有问题之后）、写出过前瞻泄漏、汇报里掺过动机性推理；agent 写的护栏也出过静默失效；它也不知道用户要什么。所以「规则当裁判」里的规则要由另一个 agent 独立审计，再由用户批准。
5. **注意本项目的证据不能否定 B 本身**：票 14 背景的五个毛病出自用户**单干**时的浏览（没有流程、没有 agent），它否定的是「人单干」，不是「人主导、agent 辅助」。那五个毛病恰恰是在人和 agent 合作时修好的。
6. **顺序**（与 constraints 已对齐）：
   - 先补护栏：对照页排除看过的样本、按声称领先换算的可证实性检查、放弃条件、验证段的物理隔离（截到 2025-12-31 的数据快照，见 S12）；凡做成 path2 app 的候选，送验证前必须先实施「确认根不晚于买点」的运行期检查（已验证可行、未实施；泄漏能造出 +0.30 且六格同号，逐年同号挡不住）。
   - 护栏到位之前，看图圈照常转、只做训练段，任何候选都不送验证；账本和清单文件全部保留，护栏到位后能回头把看过的样本排除掉。
   - 所有护栏交给一个没参与编写的 agent 审计一遍，再请用户批准。

## 1. 从最终目标倒推：哪些步骤真正决定成败

最终目标 = 一套 pattern 加配套买卖规则，在新数据上对同日对照有大优势。把「拿到它」拆开：

1. 被探索的空间里**有没有**大优势；
2. 候选**碰不碰得到**它；
3. 训练段上的**假的大优势能不能被挡住**；
4. 只用一次的验证段**有没有被浪费或污染**；
5. 上线后能不能**诚实地发现它失效**。

**推论一：目标是「大」优势，这改变了瓶颈在哪，但取决于规则命中多密、声称的领先多大。**
- 训练段 2 年、每年约 1000 个买点时，分散长相的方向领先约 0.043 就看得出，扎堆长相约 0.15（`.scratch-archive/selection-pattern/research/09-target-pool-resolution.md` 第 18–19 行）【强】。大优势的默认线是方向领先 0.15 以上。对又密又分散的规则，训练段分辨力不是瓶颈。
- 规则一稀就不同：按 constraints.md 2.2 的推算，训练段两年只命中约 100 个买点（每周 1 个）的规则，1 倍偶然波动约 0.074，试 30 来个无本事的候选就有一半机会凭运气凑出 0.15；每天 1 个以上、分散的规则，试上万个也凑不出【中，推算】。看图圈的「收紧」每加一个条件都让规则更稀。
- **但不能因此定一个固定的高频下限**（redteam 指出；初稿和 v3 都错了）：票 12 第六节第 5 条已定「每周一只、约 30 个买点也可以，前提是领先足够大」。看出某个领先所需的独立买点约为「2 除以领先」的平方：领先 0.15 约 180 个，领先 0.4 约 25 个。固定的高频下限等于替用户做了「不找稀有事件」的方向选择。正确的门是**按声称的领先换算**：
  - 训练段一侧：领先要明显超过「在这个命中密度下、试了这么多次，纯靠运气能凑出多大」；
  - 验证段一侧：拿训练段领先**打过折之后**的值（打折口径待验证，至少扣掉运气能凑出的部分）去算，验证段的独立买点够不够看出它。
  - 两道都不读验证段、都能机械执行。稀疏规则不被禁止，但它要拿出大得多的训练段领先才过得去——这和用户「领先足够大就行」的决定一致。

真正的敌人是**能造出大的假优势的东西**，本项目里已经量到过的有：

- 幸存者偏差：推荐池里「跌掉九成以上 + 成交额贴着下限」一个组合就白得约 0.10【强，推算】（票 09）；
- 证券混杂：池子混着债券 / 优先股时，偏爱极低波动就白赚方向领先 +0.289，逐年 6/6 为正（`docs/feature_candidates.md` FC-015）【强】——比大优势的线还高；
- 波动率读数：bb 系的好成绩跨 27 配置对波动率倍数回归 R²=0.919（记忆 `project_path2_app_optimization_workflow.md`）【强】；
- 因果泄漏：换边端点丢掉因果约束后方向领先显示 +0.304，两窗三档六格全同号（记忆 `project_path2_edge_causality_lesson.md`）【强】；
- 题材扎堆、数据错误（SMX 我们的数据涨 403%、Nasdaq 跌 37%，票 15）【强】；
- 看图圈的样本重用和隐性多重比较（第 2 节「人」第 3、4 条）【中，推演】。

**推论二：评估侧和花验证段的错会穿透到终点；生成侧的错只有在生成与评估互不相干时才会被过滤。**
- 候选提得差、标注前后不一致、规则写偏了，只要后面的尺子是对的、生成和评估互不相干，代价是浪费时间，不会变成假成功。
- 有两类生成侧的错挡不住（constraints 指出）：
  - 从偏差区生成的候选（深跌、成交额贴着池子下限这类）：训练段上分辨不出，只有验证段戳得穿，烧的是判决次数；
  - 看图生成和训练段评估用同一批样本：用户看过的赢家留在命中里、看过的输家被条件剔掉，成绩被直接抬高。
- 尺子配错（对照挡不住白得的领先）、因果泄漏、停不下来的收紧、提前或多次打开验证段，这些错直接穿透。
- 所以**产出质量影响最大的是「挡假」和「守验证段」两类步骤**，而不是「出想法快」。S2 要紧的不是谁提，而是生成用过的样本不进评估、偏差区先划禁区。

**推论三：调参对大优势的贡献应该很小。** 真有大优势的东西，不该对参数敏感；如果它要靠调参才变「大」，本身就是警报。

## 2. 两边的失败模式（老实写）

### 人

1. **单干时：只看赢家、按原值排、扎堆同一题材、偷看验证段、不记账**【强】：票 14 背景记录的是用户在没有流程、没有 agent 参与时的独自浏览——用 bo_only 按前瞻收益最大排序看大涨，扫描范围 2025-01..2026-06 盖住了验证段，排在前面的是最疯的票、集中在 2025 年「上市公司囤加密币」一波，想法没有变成规则去检验、也没有记账。**这否定的是「人单干」，不是 B**（redteam 指出）：这五个毛病是 agent 指出、用户拍板改流程修好的。
2. **提出的形态大多没过同日对照**【强，但样本极少】：
   - 「孤立跳空阴线企稳」：默认口径 64 个买点，方向对同日同波动普通买入 −3.5 点（区间 −20～+12，只分辨得出约 26 点）；全部放宽到 720 个买点时 −5.2，分辨得出、仍为负（记忆 `project_gap_black_candle_study.md`；报告所在 worktree 已删、研究分支上未提交，原文找不回，只剩记忆）。
   - 相近的「跳空高开 + 阴线 + 放量」在全宇宙**对随机日基线**方向 +4.5 点（记忆 `project_tb_v1_revert_toxic_gate.md`）。随机日基线含择时、不扣波动；换成同日对照的那次研究不看涨。这是「对错基线就好看」的现成例子。
   - 「超涨是坏信号」被证伪，跳涨越猛后续反而越好（记忆 `project_bb_v1_overdist_distribution.md`）。
   - 「出信号时存在尚未被价格兑现的利好」在 bb 上被证伪，买点距财报中位已涨 75%（记忆 `project_fundamental_gate_vs_anchor.md`）。
   - 唯一像样的命中率：tb_v1 回踩坏样本里用户提的 5 个假设，2 个强（单日大跌幅、超长阴线，AUC 0.70–0.73）、1 个部分成立、2 个证伪（记忆 `project_tb_v1_revert_toxic_gate.md`）。但这是**在一个 pattern 内部分好坏样本、样本内**的结果，不是跨股选股优势，样本外复核没做，所属的 bb_v1 也已废弃。
3. **看图圈特有的样本内抬高**【中，推演；代码事实为强】（出自 constraints.md 2.4）：用户照着看过的大涨段写规则，这些赢家会留在规则的命中里，方向领先白得约「看过且被命中的段数 ÷ 总命中数」；每轮看 12 个输家再加条件剔掉它们，每轮又白得约「12 ÷ 总命中数」。规则一稀，两项就和目标同量级。代码核对：`chart_workflow/ledger.py` 文件头写明「大涨段轮不算尝试」；`chart_workflow/contrast.py` 只按数据错误登记排除样本，没有排除用户看过的段。
4. **隐性多重比较**【中，推理】：人看一屏输的例子时，脑子里同时比了几十种差别，最后只说出最能分开的那一条。账本上记 1 次，实际挑了几十次，这个次数数不出来，也就没法按次数打折。和第 3 条是两种机制（一个是看过的样本留在成绩里，一个是挑选次数数不出），同向叠加。
5. **把事后才有的东西当事前特征**【中强】：超涨派发研究里唯一强信号是买点之后的破位，「事前识别派发且不误伤原理上不存在」；tb 的 outcome 是事后标签，`path2/CONTEXT.md:33` 明令不进 where。看输的例子时，最显眼的差别往往就是「后来跌了」本身的样子。
6. **口径直觉会错**【中】：tb_v1 里用户指定按 TR 中位数归一的硬闸，实测弱于按绝对跌幅（方向 +1.7 点 vs +5.6 点）。
7. **疲劳、标准前后不一致、自述不可核实**【弱，一般知识 + 一条间接记录】：用户说 2026 年的图「没怎么看」（票 01），这种自述无法核实。标注不一致只伤效率；同样的不一致出现在「停不停」「开不开验证段」上就会伤结果。
8. **沉没成本**【弱，一般知识】：对自己提的形态更难放弃。

### agent

1. **把给它的目标优化到底并报成成功**【强】：bottom_burst 2026-07 调参买点窗 41→423、label 中位数翻倍（记忆 `project_bottom_burst_tuning_2026_07.md`），后来在同日对照下现役领先只剩 +0.006、偶然波动 ±0.04（记忆 `project_tune_gates_v3_review_2026_10.md`）。时间线（我核对了记忆日期）：2026-07-25 的 agent team 已经认定这类 score 是波动率读数；2026-08-10 一个 5-agent workflow 仍拿同一类 score 优化 bottom_burst 的 tb 层，报告 +115%、多窗口稳、过 gate（记忆 `project_bb_v2_tb_optimization.md`）。谁选的目标没有记录。
2. **把读波动率当选股能力**【强】：同上，R²=0.919；控制波动率 × 月份后 bo_only 的 +72% 完全归零。
3. **写出前瞻 / 因果泄漏**【强】：换边端点丢因果约束，43% 新增买点配上买点之后才成形的 burst；tb.outcome 读了买点之后的数据（记忆 `project_tb_buypoint_modeling.md`）。前一个是 agent 团队自己查出来的，后一个是用户看图看出来的。查因果的不变式已验证但**未实施**（记忆 `project_path2_edge_causality_lesson.md`）。
4. **写的护栏会静默失效**【强】（redteam 指出）：tune-gates-v3 评审发现复核阶段被写死成必然撤回（`comparison()` 恒给证据不足，记忆 `project_tune_gates_v3_review_2026_10.md`）；项目 CLAUDE.md 引用的 eval-discipline skill 并不存在（地图 Notes 记了，`ls .claude/skills/` 核实无此目录）。两例都是另一轮 agent 审查查出来的。
5. **汇报时动机性推理**【强】：记忆 `feedback_argument_discipline.md` 记了四个被用户或上级戳穿的实例；另有拿一次小样本测试就建议删通用机制（记忆 `feedback_tuning_is_optimization_not_filter.md`），以及把「没找到稳健区」先归因于格数、后被实验推翻（记忆 `project_tune_gates_reduce_before_joint.md`）。
6. **诊断用错统计量**【中】：「oversold 改 close」的诊断用均值判样本质量被长尾拉高，实施后反降，已撤回（记忆 `project_bb_v2_tb_optimization.md`）。
7. **看不见没编码进数据的东西**【中】：成绩按收盘价算、没扣价差（票 06）；用户能不能真的照止损执行，数据里没有。
8. **不持久**【强，机制事实】：会话结束就忘，跨会话只能靠文件和账本。

### 两边共有：后见之明

【中，推理】人亲历了 2024–2026 的行情，用户的扫描还盖到过 2026 上半年；agent 的知识截到 2026-06，读到的记忆和研究文档里也有含 2026 年结果的结论。用「外部常识 / 题材判断」提候选时，两边都可能不自觉地偏向 2026 年真涨过的题材。验证段对两边都只是「新 pattern 的成绩没被看过」，不是「这段行情没被知道过」；对这条唯一完全免疫的裁判是**规格冻结之后才到来的新数据**。对纯价量形态影响大概不大，对带题材、带外部信息的方向影响更大。

## 3. 逐步骤比较

### 3.0 总表

| 步骤 | 谁更擅长 | 证据强弱 | 对终点的影响 |
|---|---|---|---|
| S1 找大涨段 | agent，明显 | 强 | 中低（只是索引） |
| S2 提出形态或假设 | 没有一方有成功先例；两边来源互补 | 强（双方都无先例） | 高 |
| S3 把形态写成规则 | agent 写，人对自己形态的意图有解释权，并兼 bug 探测 | 中 | 中 |
| S4 训练段对照检验 | agent，明显；尺子由另一个 agent 审计 | 强 | 很高（主过滤器） |
| S5 看输的例子，收紧或放弃 | 收紧想法两边都可出；判定归 agent；放弃归事先规则 | 中强 | 高（假领先主要在这里造出来） |
| S6 挖数据 | agent 执行，边界已由人定 | 强 | 高，符号取决于排名口径 |
| S7 选方向 | 资格机械定，合格者里人选 | 强 | 很高 |
| S8 结构设计 | agent，人确认拓扑语义 | 强 | 中（危险在引入泄漏） |
| S9 动手前便宜验证 | agent | 强 | 中 |
| S10 配套买卖规则 | agent 设计检验，人给执行约束 | 中 | 对真实收益中高，对「有没有优势」低，对过拟合风险高 |
| S11 调参 | agent | 强 | 低 |
| S12 何时、用什么打开验证段 | 双钥匙：agent 出资格证明 + 人同意；数据物理隔离 | 强 | 最高 |

| S14 每周看图挑一只 | 人，记账 + 影子对照 | 无本项目证据 | 对判优对象零，对真实收益中，方向未知 |

### S1 找大涨段

- **谁更擅长**：agent，明显。
- **证据**【强】：人单干时的五个毛病见第 2 节「人」第 1 条。agent 版（`outputs/chart_workflow/lists/r001-bigmoves.json`，300 段）按相对自身波动排、同段行情只取一次、截断在训练段末、跨源比对 Nasdaq 297/300 一致（票 15）。agent 版也出过问题：几乎不动的待并购股票冲上榜首、SMX 数据错——都是 agent 报出来、用户定方向（决策日 M ≥ 1%）修掉的。
- **交错了人**：重新引入只看赢家、按原值排、偷看验证段。
- **影响**：中低。它决定人看到哪些图，偏差会传给 S2；S4 的同日对照会把「只看赢家」的错觉纠回来，前提是对照页排除看过的样本（第 2 节「人」第 3 条）。会穿透到终点的是偷看验证段——注意现在的截断只是配置值（`chart_workflow/config.py` 的 `train_end` 默认 2025-12-31，数据目录是全量 `datasets/pkls`），挡得住无意，挡不住有意，见 S12。

### S2 提出形态或假设

- **谁更擅长**：**没有证据表明任何一方擅长提出有大优势的候选**。两边的来源互补：
  - 人：数据里没有的信息（题材、公司处境、新闻语境），以及看图时的整体印象；
  - agent：成规模、可计数的枚举（挖数据、按涨前样子分组、文献），以及不小的外部常识（见第 5 节 d，注意证据库偏向）。
- **证据**：
  - 人：第 2 节「人」第 2 条，被同日对照检验过的人提形态没有一个过线【强，样本极少】；看图工作流第一圈还没开始，「看图工作流里人提的形态」本身还没有成绩。
  - agent：bb 系 agent 调出来的成绩大多是波动率读数【强】；挖数据还没做（票 10 open），作为候选来源的成绩是空白。
  - 一般知识【中】：在同一份信息下，统计规则通常不输专家的临场判断；专家的优势主要来自规则拿不到的信息。→ 人的价值更可能在「数据外信息」，而不在「看同一张 K 线看得更准」。
- **交错了人**：只靠人提 → 候选少、同质（底部 / 企稳类为主，而这正是幸存者偏差白送领先的区域），且来自记得住的赢家；只靠 agent 提 → 大面积搜出偏差和噪声，且看不到没编码的东西。
- **影响**：高（决定空间里有没有大优势）。两条来源并行进同一个漏斗，都记账。要紧的不是谁提，而是生成用过的样本不进评估、偏差区先划禁区（推论二）。

### S3 把形态写成规则

- **谁更擅长**：agent 写；人只对「自己提的形态是不是这个意思」有最终解释权，同时看命中例子当 bug 探测器。
- **证据**：
  - 人抓 bug【中强，单例】：NVX / BRNS 两个假阳例子里，用户看出 tb.outcome 读了买点之后的数据、stop_confirm_bars 治不了根、单 bo 单 tb 只出一个买点，三条全对（记忆 `project_tb_buypoint_modeling.md`）。这是「挑错」的能力，不是「找真货」的能力（redteam 的提醒，我同意）。
  - 人的口径直觉会错【中】：TR 归一那次（第 2 节「人」第 6 条）。
  - agent 写错【强】：换边丢因果（第 2 节「agent」第 3 条），agent 团队自己查出。
  - `authoring-path2-app` 的「判据 1 形态符合意图，用户在环，先行闸门」是设计判断，不是实测【中】。
- **第一性原理的限定**：对终点来说，「忠于人的意图」本身不是目标——规则写偏了、偏出来的东西有大优势，照样是成功。人看命中例子的真实价值只有两个：
  - 抓出「命中的东西看起来不对」所暴露的前瞻或语义 bug；
  - 让人的那个假设真正被检验到，而不是被换成别的东西、白白浪费一个想法。

  skill 里说它「挡统计过拟合」，只在一个条件下成立：**人的意图在看任何成绩之前就定下了**。人看过对照页之后再说「这才是我要的」，意图就会往成绩好的方向挪，这道闸就变成了又一次挑选。
- **拦候选的记账**：人因为「这不是我说的意思」或「这里有 bug」拦下一个候选，是允许的，但要入账并写明理由；拦 bug 的要点名是哪个 bug（这是修正）；在看过这个候选的训练段成绩之后才拦的，算一次尝试（这是挑选）。
- **交错了人**：人写 → 写不出可执行规则；agent 不给人看就定 → 测的不是人的假设，前瞻 bug 也少了一道肉眼防线。
- **影响**：中。

### S4 训练段对照检验

- **谁更擅长**：agent，明显。
- **证据**【强】：同日对照、分年、去掉 2022 年、按买点长相算门槛、按股算偶然波动，全是工具算的。FC-015（混入债券 / 优先股白赚 +0.289）是 agent 在算分辨力时查出来的，这些证券在 K 线图上就是一条平线，肉眼不会把它们当问题。跳空阴线案例里，换了基线结论就翻转。
- **agent 的风险**：尺子的配法本身能造出或吃掉领先（FC-016：五档同日对照挡不住波动两头）；护栏也会静默失效（第 2 节「agent」第 4 条）。所以尺子和**全部护栏**（排除看过的样本、可证实性检查、停止规则、验证隔离）都要由一个没参与编写的 agent 审计。这件事交给人帮助有限——人看不出配对口径或代码里写死的分支；人审的是审计报告里的方法论选择。
- **交错了人**：判断变成「看着像涨」，不可复现，标准前后不一。
- **影响**：很高，它是主过滤器。

### S5 看输的例子，决定收紧或放弃

- **谁更擅长**：
  - 收紧的想法：两边都可以出。人看输例子的视觉归因有一定命中率（tb_v1 的 5 中约 2.5，样本内），agent 可以对全样本做分组比较；
  - 收紧后接不接受：agent 按规则判定（工具算、记账、按轮数打折）；
  - 放弃还是继续：**事先写好的停止规则**。
- **证据**：第 2 节「人」第 3、4、5、8 条，「agent」第 5 条。**现有设计缺口（事实）**：票 14 定了毕业五条，没有定放弃条件——没有尽头的收紧，就是在训练段上过拟合。
- **推荐**：
  - 停止规则写进流程（例如收紧轮数上限、若干轮后仍不到大优势默认值的一半就放弃，数值待验证）；人可以随时提前放弃（单向），不能临场追加轮数。要追加就记账，并抬高这条线的毕业门槛。
  - 三道机械门（与 constraints / redteam 对齐）：
    - 每轮收紧后自动查：剩下的命中数还够不够证实它**当前声称、打过折的领先**（推论一；不是固定频率）；
    - 对照页的汇总排除用户看过的大涨段和已展示过的输赢例子；
    - 收紧拆年用：看输的例子只看训练段的一年，另一年留作自查（否则毕业条件里「两年同号」就失去检验意义）。
  - 这三道都不花验证段，也都只能由工具执行——靠人记着不可靠。
- **交错了人**：人临场决定「再收一轮」→ 沉没成本 + 样本重用 + 隐性挑选；agent 临场决定 → 汇报进展的动机。
- **影响**：高。假的大领先主要在这一步被造出来。

### S6 挖数据

- **谁更擅长**：agent 执行；边界（先列再看、按试了几条打折、幸存者偏差禁区、不碰验证段）已在票 10 和地图 Notes 里由人定好。
- **证据**【强】：一个两条件组合白得约 0.10；挑选噪声可算、可打折（tune-gates 实测挑选噪声乘数 0.9–1.7，记忆 `project_tune_gates_reduce_before_joint.md`）；FC-015 说明工具挖时会撞到人看不见的假领先。
- **交错了人**：人做不动这个规模；人从挖出的清单里挑「看着有道理的」，等于又一轮没记账的挑选。
- **候选数是一阶杠杆，但符号不确定**（redteam 指出，修正 v3 采纳的「规模只是次一级」）：
  - 正面：真货很少时，池子里「至少有一个真货」的概率几乎只由候选数决定。按 constraints.md 第 3 节的示意，一年 20 个形态、每个是真货的概率 1% 时，一年里碰到至少一个真货的概率只有约 18%；候选上万时接近 1。
  - 反面：一年只判 1～3 次，送的是排名第一的候选；搜得越广，排名第一的越可能是几项偏差叠加出来的组合，而叠加偏差在训练段上看不出（constraints.md 第 7 节）。
  - 让净效果变正的办法是排名口径：**送验证的排名按「去掉所有已知偏差区之后的领先」排，不按训练段原始领先排**，并且候选越多、门槛越严。做不到这一条，agent 的规模优势可能是净负的。
- **影响**：高，符号取决于上面的排名口径。幸存者偏差没有补数据，**挖出来的任何底部类结果，默认先当可疑**，只认最近一段数据上的最后检查。

### S7 选方向

- **谁更擅长**：资格由机械条件定——毕业五条 + 偏差排查清单 + 可证实性（按打过折的领先换算验证段够不够看出，推论一）；agent 给合格者排序（按去掉已知偏差区之后的领先），附打折后的成绩和偏差风险；**在合格者里选哪个，由人定**。
- **理由**：选方向 = 决定把只用一次的验证段花在谁身上，是不可逆的资源决定；人承担后果，也知道自己的用法（这种买卖能不能照做、每周一只够不够挑）。两边的偏向：agent 偏向训练段分数最高的那个（多个候选里分最高的，有一部分是运气）；人偏向自己的形态。
- **证据**【强】：tune-gates-v3 评审——256 股规模下训练挑选约等于随机挑，零效应改动被「两关都过」留下约 25%（记忆 `project_tune_gates_v3_review_2026_10.md`）。人偏向自己形态【弱，一般知识】。
- **交错了人**：agent 自己选 → 赢家诅咒直通验证段；人不看资格就选 → 把验证段花在没毕业的心头好上。
- **影响**：很高。

### S8 结构设计

- **谁更擅长**：agent（`authoring-path2-app` / `authoring-path2-detector`），人确认拓扑层的语义。
- **证据**【强】：本项目最亮眼的假领先（+0.304）出自结构改动，是 agent 改、agent 查出的；查因果的不变式**未实施**。所以 agent 在这一步的优势依赖机械护栏，护栏缺位时，agent 的结构设计是假优势的主要来源之一。
- **影响**：中。毕业的形态已经有规则版本，这一步主要是把它稳妥地重写成 pattern；危险在引入泄漏。

### S9 动手前便宜验证

- **谁更擅长**：agent（`feature-study`）。人没有特别的长处。
- **证据**【强】：营收「尚未兑现的利好」这个前提，在 bb 上一测即证伪。
- **影响**：中。它省的是建造成本，而成本不是瓶颈；但它也是又一道挡假的筛子。

### S10 配套买卖规则

- **谁更擅长**：agent 设计和检验；人给出执行约束——止损会不会真的照做、次日开盘能不能买到、买卖价差多大（成绩按收盘价算，没扣价差，票 06）。
- **证据**【中，推理】：票 12 已写明「买卖规则造不出买点本身没有的优势」「可调的东西变多，训练段更容易调出假的好成绩」。
- **交错了人**：人设计 → 规则凭感觉、没检验；agent 不问人 → 规则在回测里好看、用户实际执行不了。
- **影响**：对真实收益中高；对「有没有优势」低（只能放大）；对过拟合风险高 → 规则的可调项越少越好。

### S11 调参

- **谁更擅长**：agent（`tune-gates-v3`）。人只定目标方向，已定为优化对同日对照的相对优势。
- **证据**【强】：目标定错时，agent 调参会稳定地朝假方向跑（第 2 节「agent」第 1 条）；用户纠正过调参目标（「要的是优化不是筛选」，记忆 `feedback_tuning_is_optimization_not_filter.md`）。
- **影响**：低（见推论三）。调参预算应该小，且只在毕业之后。

### S12 决定何时、用什么打开验证段

- **谁更擅长**：双钥匙。agent 出具资格证明（账本、毕业条件、偏差清单、冻结的规格、可证实性换算），人按下开关；任一方不能单独打开。规则本身（只用一次；没过允许改一次，门槛加严）由人事先批准。改规则只能在看到任何验证结果之前，并记账抬高门槛。
- **证据**【强】：
  - 两边都碰过验证段：用户扫描盖到过 2026 上半年（票 01）；跳空阴线研究用的是 2025-01..2026-06（记忆）；营收研究的分年结果含 2026（票 01）。靠自觉守不住。
  - 先例：tune-gates 已有「冻结清单 / 开窗前必须告知会消耗确认窗并征得同意」（记忆 `project_tune_gates_workflow_redesign.md`）。
- **隔离现状不够（redteam 指出，我核对属实）**：`chart_workflow/config.py` 的 `train_end` 只是配置默认值，数据目录是全量 `datasets/pkls`，agent 有 shell，所以 v3 写的「工具硬截断」并不成立。能做的分两层：
  - 挡无意读到：所有研究、看图、挖数据都只指向一份截到 2025-12-31 的物理快照（项目 CLAUDE.md 本就建议固定数据的实验先复制快照）；
  - 挡有意读到：只能靠用户在 Claude Code 权限设置里禁止研究会话读全量数据目录，这是用户的操作域。
  - 全量数据只在用户触发的那一次验证运行里使用。
- **交错了人**：agent 自己开 → 用不担后果的一方去花最稀缺的资源，而且它有「拿出结果」的动机；人自己开 → 急于看结果、提前开，或开了之后翻个股图（票 01 默认值：改的时候只能看汇总数字）。
- **人这把钥匙判的是什么**（回应 redteam 的「盖章」担心，redteam 已接受）：质量部分（资格是否满足）是机械的，人照单盖章正是设计意图。人要真正做的是价值选择：花在这个候选上还是那个；现在开还是再等——验证段不开就会自己变大，每多等一个月多约 21 个交易日，一个每天 1 个独立买点的规则再等 1～5 个月才看得出 0.15（constraints.md 2.1 附）。agent 交核对单时必须写明「现在开能看出多大、再等几个月能看出多大」，人的同意才有内容。
- **影响**：最高。这是唯一一次干净的裁判。

### S13 上线后核对

- **谁更擅长**：agent 自动化（每日名单与当时价格存档、按预定时间复查、出报告）；停用由事先定好的规则触发（例如半年复查明显变差就停，阈值待验证），人确认执行。
- **证据**【强】：七个月分散数据约 0.085、30 个买点约 0.35–0.4 才看得出（票 12、背景）。上线后很长时间里，数字说不出「好」，只说得出「崩没崩」。人看了几周就下结论最容易错【中，一般知识】。agent 不持久，所以必须是脚本 + 文件，不能靠哪个会话记得。
- **注意**：新数据攒得多快取决于规则命中多频繁，不取决于用户每周买几只——核对用的是整份名单的全部命中（constraints.md 2.1、redteam 第五节第 3 条）。「每周一只要七个月攒 30 个」只适用于「人挑的那一层」。
- **影响**：高（长期唯一能不断补充的裁判），但慢。

### S14 每周看图挑一只

- **谁更擅长**：人——这是用户的钱和用户定的用法。但要记账，并做影子对照。
- **证据**：本项目**没有任何**证据表明用户从名单里挑会更好或更差。第一性原理：验证段检验的是「整份名单 + 规则」，人挑这一层没有被检验过；如果人倾向挑最猛的图，实际持仓会偏向高波动，和验证过的东西不是同一个东西。人在这里可能的真实价值是数据外的「一票否决」信息：马上要增发、反向拆股通知、退市警告、官司——这类以后有一部分能编码进外部信息。
- **推荐**：
  - 每周记下名单、名单排序、人挑的那只、一句理由；上线核对时同时算「名单全体」「名单前几名」「人挑的」三条线（都来自名单存档，不额外消耗验证段）。按 30 个买点要领先 0.35 才看得出，「人挑有没有用」一两年内大概都说不清，要如实告诉用户。
  - **「只在名单前几名里挑」改为有条件**（redteam 指出，我收回 v3 对 constraints 这条建议的无条件同意）：名单排序本身是一个分数，本项目历史上的分数是在读波动率（R²=0.919）。排序没作为整套的一部分在验证段上验过之前，用它约束挑选，可能把「偏爱高波动」固定下来，而不是给它封顶。所以：验证段同时报告「名单全体」和「名单前几名」的领先；前几名也过线，才默认只在前几名里挑；否则不加限制，只靠影子对照留证据。
- **影响**：对判优对象零（不在被判的东西里）；对用户真实收益中等，方向未知。

## 4. 节奏

- 速度本身不是目标；判决的节拍由新数据定，谁都快不了（一年约 1～3 次诚实判决，constraints.md 2.1）。
- v3 之前写过「agent 一轮接一轮地转等于烧训练段的自由度，所以要限速」，**已撤回**（constraints 指出）：它只对稀疏规则成立；每天 1 个以上、分散的规则，试上万次运气也只凑得出约 0.13。狂转真正的代价是把搜索推向偏差区，所以刹车是机制，不是节奏：按声称领先换算的可证实性检查、禁区、排除看过的样本、送验证的排名按去掉已知偏差区之后的领先排。最后这条是专门对付禁区挡不住的**未知叠加偏差**的（redteam 指出）。
- 人的时间不是终点的瓶颈（constraints.md 2.5），但图要人看。agent 应该把需要人的环节攒成批，其余步骤不等人。
- 结论：训练段内圈 agent 想转多快都行，前提是上面这些机械门在位并经过独立审计；人的出场时间由人定。

## 5. 人不可替代的贡献到底是什么

先重申限定：证据库全部由 agent 写成，对人的归因系统性偏少。

| 候选 | 判定 | 证据 |
|---|---|---|
| a. 承担钱和风险的最终责任 | **不可替代，但它是权力的来源，不是能力**。它解释了为什么不可逆的决定（开验证段、上线、停用、花钱补数据）要人点头，不解释人哪一步做得更好；对「找到大优势」的直接贡献约为零。 | 定义性【强】 |
| b. 定方向 | **不可替代**。目标、尺子、池子、预算、范围是偏好与资源决定，agent 推不出来。 | 票 12、01 的关键选择都是用户做的，至少一处与会话推荐不同（验证没过允许改一次、门槛加严）；「只用单一固定 dag_spec」这类关于自己用法的事实只有用户知道【强】。频率极低，几周一次。 |
| b2. 方法论和论证的审查（v4 从「权」挪回「能力」，redteam 指出） | **是能力，而且作用在一阶问题上**。规则是一阶问题，规则里的方法论框定错了，后面执行得再机械也是错的。 | 用户纠正过：调参该是目标内的优化、不是门槛筛选（记忆 `feedback_tuning_is_optimization_not_filter.md`）；旧实现的输出只是体检仪、不是设计裁判（记忆 `feedback_golden_baseline_not_arbiter.md`）；用第一性原理戳穿 agent 的动机性推理四次（记忆 `feedback_argument_discipline.md`）【强】。限定：这些纠正都在评估和工具设计层面，不是「找到有优势的 pattern」的证据。对抗性 agent 能部分替代（因果泄漏、tune-gates-v3 写死的复核分支都是 agent 审查查出的），但两边查出的是不同类别的错：agent 审查擅长代码和口径，用户擅长「这个框定是不是我要的问题」。 |
| c. 看图时的整体判断（「这像不像我要的」） | **拆两半**。当 bug 探测器（这个命中看着不对 → 有泄漏或语义错）：有价值。当优势来源（像我要的 → 会涨）：无证据。「意图契合」是工具价值，不是目标。 | 探测器：NVX / BRNS【中强，单例】。优势来源：被同日对照检验过的人提形态没有一个过线【强，样本极少】。 |
| d. 外部常识和题材判断 | **中偏弱，且受证据库偏向影响最大**。按记录看，多数「外部常识」类发现是 agent 先说出来的：2025 年囤加密币题材扎堆、NOK / GME 偏大、SMX 合股复权出错、HUYA 现金分配口径差、几乎不动的待并购股票（票 14、15）；用户的贡献被记成对这些发现做取舍。但记录是 agent 写的，用户口头先提、agent 落笔的情况未必被如实归因。两边都带后见之明（第 2 节末）。人确有而 agent 没有的，是**自己能不能照规则执行**这类关于自己的信息。 | 票 14、15【中，归因可疑】 |
| e. 其实比想象的少 | **部分是**。在「从 K 线里找出有优势的 pattern」这件事上，人有证据支撑的独特长处很少（抓 bug、数据外信息）。但在「保证裁判是对的」这件一阶的事上，人的方法论审查是有记录的能力，不只是权力。 | 综合；受证据库偏向影响，置信度中 |

## 6. 决策权分配

| 决策权 | 归谁 | 为什么 |
|---|---|---|
| 定规则本身（可证实性换算、禁区、门槛、打折、放弃条件、何时可开验证、排名口径） | agent 起草，另一个 agent 独立审计，用户批准；之后冻结，改动要用户批准并记账 | 规则是一阶问题；agent 写的护栏会静默失效；用户的方法论审查是有记录的能力 |
| 提出候选 | 两条来源并行：人提看图形态，agent 提挖数据 / 分组 / 文献候选 | 双方都没有成功先例；来源多样是提高「空间里有大优势」概率的杠杆 |
| 拦候选 | 机械门自动拦；此外任何一方都可以拦，但要入账写理由；拦 bug 要点名 bug；看过训练段成绩之后才拦的算一次尝试 | 拦截本身是挑选，不入账就成了隐性多重比较 |
| 下一步试什么（训练段内圈） | agent 按规则排队（附理由和预算消耗），人可以插队、否决某个方向（否决照上一行入账） | 精度：agent 接触的信息全部经过工具、留在记录里，选择可计数、可打折，也可限定为只看汇总；人看图后的选择接触的信息不入账，还会把看过的样本带进成绩 |
| 收紧 | 想法两边都可出；接不接受由规则判定，agent 执行、记账 | 计数和打折只有工具做得到 |
| 放弃 | 事先写好的停止规则；人可提前放弃，不可临场续命 | 两边临场都有偏向（沉没成本 / 汇报动机）；现有设计缺放弃条件 |
| 动用验证段 | 双钥匙：agent 出资格证明 + 人同意；数据物理隔离 | 不可逆、最稀缺、人担后果；两边都碰过验证段，靠自觉守不住；打开时机是有代价的价值选择 |
| 节奏 | 判决节拍由新数据定；训练段内圈 agent 推进，把需要人的环节攒成批 | 速度不是目标；刹车是机械门，不是限速 |
| 每周挑票 | 人，记账 + 影子对照；名单排序在验证段上也过线，才默认只在前几名里挑 | 用户的钱；人可能有数据外信息；这一层没被检验过，要留证据；未经验证的排序不该拿来约束人 |
| 方向（目标 / 尺子 / 池子 / 预算 / 范围 / 上线 / 停用） | 人 | 偏好与资源决定 |

**整体更接近 A，差距是二阶的。** 规则到位之后，A 和 B 只在「训练段内圈谁临场推进」这一格上不同，这一格因为精度归 agent。人的决定少、杠杆大，大部分是**事先**做的（批准规则、审查方法论），不是临场做的。

## 7. 强论点和弱论点分开

**强论点**（本项目实测、或可重复的记录直接支撑）：
1. 本项目里造出过「大」领先的东西全是假的（幸存者偏差、证券混杂、波动率读数、因果泄漏）；挡住它们的都是机械的尺子和检查。
2. 被同日对照检验过的人提形态没有过线的；agent 调出来的好成绩也大多是波动率读数——**两边都没有成功先例**，「谁更会出好想法」不能当分权依据。
3. 两边都碰过验证段；现在的截断只是配置值，守验证段要靠物理快照 + 权限设置 + 事先规则。
4. agent 会把给它的目标优化到底并报成成功，写的护栏会静默失效——所以规则要独立审计，不能「agent 写、agent 执行、agent 自评」。

**中等论点**：
5. 内圈归 agent 的精度理由：agent 的信息接触可记录、可限定，人看图的不行；看图圈的样本重用有代码事实支撑（对照页不排除看过的样本），量级是推演。
6. 人看图抓前瞻 / 语义 bug 有价值（NVX / BRNS 单例）；人的方法论审查有多次记录，但都在评估和工具层面。
7. 「意图契合」只是工具价值；它能防过拟合的前提是意图在看成绩前定下。

**弱论点**（推理或一般知识，别当定论）：
8. 人看输例子的挑选次数数不出来，造假能力未必比 agent 小——推理，没量过。
9. 统计规则在同一份信息下通常不输专家临场判断——一般知识，本项目没测过「人挑 vs 名单」。
10. 后见之明污染：两边都有——推理，量级说不清。
11. 「人的独特能力比想象的少」——证据库由 agent 写成，这个归因结论天然偏向低估人。

**已撤回的论点**（留痕，免得被重新引用）：
- 「票 14 的五个毛病是反对 B 的证据」——它们出自人单干，否定的是人单干，不是 B。
- 「内圈归 agent 是因为人的时间稀缺」——用户时间不是终点的瓶颈。
- 「训练段命中下限约 600 个 / 验证段每天约 1.2 个独立买点是固定门槛」——与票 12「领先够大、30 个买点也可以」冲突；改为按声称领先换算。
- 「挖数据的规模只是次一级」——候选数是一阶杠杆，只是符号取决于排名口径。
- 「工具硬截断」——现状不成立，见 S12。
- 「agent 狂转会烧训练段自由度，所以要限速」——只对稀疏规则成立；刹车是机制。

## 8. 最不放心的地方

1. **人看图的整体判断到底有没有优势，样本太少**：被检验过的人提形态只有两三个，看图工作流第一圈还没开始。如果第一圈就有人提的形态毕业，S2 应该给人更大权重。
2. **agent 的规模优势可能是净负的**：搜得越广，排名第一的越可能是偏差叠加出来的组合。「按去掉已知偏差区之后的领先排名」只挡已知区，挡不住未知的叠加；没有退市数据，叠加能有多大量不出。
3. **「agent 主导」成立的前提是护栏在位且被独立审计过**：查因果的不变式没实施，验证段隔离只是配置值，对照页没排除看过的样本，没有放弃条件。护栏缺位时，A 退化成「agent 更快地骗自己」。
4. **证据库偏向**：本文对人的能力归因可能偏低，尤其第 5 节 d、e。
5. **影子对照可能一两年都说不出结论**，「人挑这一层有没有用」大概率长期悬而未决。

## 9. 与瓶颈约束对一遍

constraints.md 的瓶颈排序：①诚实判决次数（一年约 1～3 次，硬上限）；②精度（送去判的候选是真货的概率），由规则稀疏度 × 声称领先、系统偏差漏不漏、看图有没有抬高决定；③功效（命中的独立买点数）；④真货存不存在。吞吐和用户时间都不是瓶颈。放到这个排序下重新看第 3 节：

**「agent 更擅长」但不在瓶颈上的步骤（不必为它们争权）**：S1 找大涨段（只是索引）、S9 便宜验证（省建造成本）、S11 调参（对大优势贡献低）。

**「agent 更擅长」且在瓶颈上的步骤（选 A 的理由）**：
- S4 训练段对照检验、S5 收紧后的判定、S7 资格判定：决定精度；
- S5 的三道机械门、S6/S7 的排名口径：压住稀疏漂移、样本重用、偏差叠加；
- S12 的资格核对单、S13 的存档与复查：守住判决次数不被浪费；
- S6 的规模：在「池子里有没有真货」这一项上是一阶的，符号取决于排名口径。

  共同点是「可计数、可机械执行」，而不是「agent 聪明」。这些活在 B 下同样可以交给工具执行（redteam 指出）——所以它们支撑的是「规则先行」，不单独支撑 A；真正把 A、B 分开的只有内圈谁临场推进那一格，靠的是第 0 节第 3 条的精度理由。

**「人更擅长或该由人做」的几项，在瓶颈约束下还成不成立**：
- 定方向 / 批准规则 / 方法论审查：**成立，而且在一阶问题上**。
- 看个别命中抓 bug（S3）：**成立，在精度这一项上**。机械检查只能挡已知类型的泄漏；NVX / BRNS 那次用户看出的 outcome 前瞻，当时没有任何机械检查能挡。价值真实，但只有一个例子。
- 自己形态的意图解释权（S3）：**不在瓶颈上**。忠于意图本身不提高精度；它的价值只是不浪费人的想法。可以保留，拦候选时照 S3 的规矩入账。
- 提出形态（S2）：作为来源多样性的一份保险；是否在瓶颈上取决于真货多稀少。
- 每周挑票（S14）：不在判优对象上，但在用户真实收益上。
- 打开验证段（S12）：**成立**，理由是不可逆 + 担后果 + 打开时机本身是有代价的价值选择。

**与 constraints 的交叉结果**：两轮后无剩余分歧。我提的两处（bb 系的成绩该两边各担一半、「用户设计」查不到出处；护栏到位前看图圈照常转但只做训练段、不送验证）constraints 已接受并改进 constraints.md；constraints 补的两处（账本清单保留以便回溯排除；path2 app 候选送验证前必须先实施确认根检查）我已采入第 0 节第 6 条。redteam 第一轮之后，v3 里来自 constraints 的两处被我改掉了：固定高频下限（改为按声称领先换算），以及「挖数据规模只是次一级」（改为一阶、符号取决于排名口径）；另外收回了对「只在名单前几名里挑」的无条件同意。redteam 说已把前两条直接发给 constraints。
