# sim：模拟用户走完整个标注流程

本文中所有项目内路径均相对 repo root。用词以 `path2/GLOSSARY.md`、`path2_web/GLOSSARY.md` 为准；界面上的标识符照抄原文（如 `elements`、`groups`、`in 2/4`）。

## 0. 做了什么、说明什么、不说明什么

我扮演用户，把「看图标注 → 归组 → 会话写 app → 对照迭代 → 盲看 → 调参 → 最后检查」走了 8 个场景。能在 mock 里演示的（标注、成员、归组、对照、pattern 页）都在浏览器里真点了：先把 mock 的演示数据清空，从 0 个标注开始在 4 只股票上标了 7 个买点，再归成两个 pattern；对照部分用 mock 自带的 bb_v1 演示数据。会话写 app、盲看、调参、最后检查 mock 里没有，按 final_report、票 01 / 08 / 09 的设计在脑中走，逐条注明「未在界面验证」。之后按 flow v1 / v2 / v3 各走一遍（脑中），在 ux 的改版 mock 上实操两轮（第二轮的 mock 还是 flow v1 口径，第三轮对齐 v3）。第 1 节是第一轮，第 2 节是第二轮与 flow 各版的走查，第 3 节是最后一轮和定稿小结。

它说明：哪些地方会让一个不记得内部术语、色弱、讨厌大段文字的用户停下来想、做错或卡住；lead 候选方案（背景第 3 节）在走流程时消掉了什么、又带来了什么。它不说明：这些摩擦在真实标注里出现得多频繁（只有 7 个手造买点）；也没量任何特征和涨跌的关系，没有副产品要登记。

mock 自身的偏差（不当作设计问题）：成员每次重画都现算，没实现「离开即冻结」；只有叫 `bb_v1` 的 pattern 有 app，新建的 pattern 永远 `app: —`。

### 1.3 lead 候选方案（背景第 3 节）走一遍的结果

**消掉了的模糊**
- 「app 都建好了，顶层还有 unmapped、`in 2/4`」：规定顶层恒为 N/N、顶层出现 unmapped 就标红后，用户原始问题的那个画面不会再合法出现。
- 「`unmapped` 到底是错还是正常」：只留在次级、改叫「还没放进 app」、悬停说原因，意思清楚了。
- 演示数据换成照标注写的假 app：F16 和「横盘、缩量在 bb_v1 里根本没有 node」造成的误读一起消失。
- 「会话写 app 前先查骨架唯一」：保证 app 不会在两种骨架上写出来。

**新引入或没解决的**
- **F1（高）**：门槛把「可有可无的前置段」逼成两条坏路——拆成两个 pattern，或回头把所有框改成属性。门槛该挡的是「写 app 时骨架还不唯一」，不是「归组时骨架不同」。建议：写 app 前允许 pattern 里有两种骨架；会话写 app 时把多出来的那个名字翻成邻近 node 的 where 或子槽（先问「没画还是没有」），从此界面上的「顶层」按会话的对应表算——被翻成某 node 的 where / 子槽的名字，在 `elements` 里挂到那个 node 下面显示，而不是按框有没有被包住算。这样「顶层恒为 N/N」仍然成立，标注时也不用分 node 和 where。
- **「先问没画还是没有」缩到次级**：最常见的「没画还是没有」恰恰是顶层（横盘 `in 3/4`）。顶层不许可有可无后，这一问在顶层要变成三选一：补画 / 挪到别的 pattern / 降成某一段的属性，不能直接删掉。
- **F2（高）**：一个红色盖住四种来历，出口各不相同。
- **F4（高）**：门槛只在会话里拦，界面上看不出某个 pattern 是否过了门槛、下一步该谁做；候选的五个阶段在界面上没有对应的显示。
- **F11（中）**：「顶层不再显示 `in`」在有意改骨架的过程中会让我丢掉「还剩几个旧买点没补」的数。

### 1.4 高频情景与思考模式（回应用户三次追加）

回应 `原始问题.md` 末尾用户的追加：哪些情景大概率会遇到、用户在想什么；灵活与规范的分界；包容用户的灵活性有时会造成后面更大的麻烦、有时不会，要分辨哪些思考模式流程该支持。按我走 8 个场景时的体感从常见到少见排（不是统计）。

各列：「现在允许吗」按 flow v1 加上一轮 final_report 的设计。「我希望」：**不管** = 随我，界面显示出来就行；**系统兜** = 别指望我记得，由界面或会话兜住；**拦我** = 要有人拦。「随我去的话，哪一步坑到我」用我自己的口吻写：如果流程当时由着我，后面哪一步会出事。

|---|---|---|---|---|---|---|---|
| H1 | 框的边随手画，和 app 事件起止差几天 | 差不多就行 | 「大概就这一段」 | 允许；对照不比起止 | 不管 | 基本不坑。只有画得太短、两段之间空出二十多根时，归组会多出一个 `−X` 小组 | 支持 |
| H2 | 选名字后以前用过的属性全带上，不逐条核对（F3） | 顺手接受默认 | 「它带的应该对」，或根本没看 | 允许；带上的直接算 true，退不回「没看过」，跨 pattern 也带 | 系统兜 | **写 app**：会话照我没看过的「true」写 where；**对照**：一堆 `detected` / `fail`，我以为 app 坏了；要清只能逐张重翻，还分不出哪些是我真看过的 | 不支持「带上就算数」：带上的先算待确认，点了才算 |

**按思考模式归总**

| 思考模式 | 情景 | 流程该不该支持 | 为什么 |
|---|---|---|---|
| 先画再说、差不多就行、看到什么框什么 | H1、H6、H9、H8、H21 | 支持 | 都是现算、看得见、撤得回；唯一要兜的是背景框混进主组骨架（H8，会话问一句） |
| 一张图想表达两件事 | H17、H18 | 支持 | 已有写法（两个买点、名字加属性），不增加后面的麻烦 |
| 换个词说同一个东西、手比脑快 | H14、H13 | 支持 | 碎组、归错组都看得见，挪一下或合并一下 |
| 有更好不强求、边标边改主意 | H12、H16 | 支持，由会话消化 | 想法本身合理；要我回头改框才能满足流程，就是要我标注时分 node 和 where（2026-10-25 定了不让用户做） |
| 对着 app 结果改、想纠正 app | H10、H15 | 支持 | 用户已定是自由；但纠正 app 要有自己的入口，不能借「我标宽了」 |
| 断点续做、心里清楚就行 | H11、H4 | 支持，系统兜 | 界面显示进度；定义在词进 app 前由会话补问 |
| 顺手接受默认 | H2、H7 | **只在默认不会造假时支持** | 默认成员看得见、可点改，支持；带上的属性直接算 true，事后分不出真假，不支持（带上先算待确认） |
| 拿现成的凑合 | H5 | 不支持 | 一个词装两种意思，事后从数据分不开；挑词时显示定义 |
| 拿结果倒推当时 | H3、H19 | **不支持** | 训练段随便看里唯一不该放开的：看可以，label 和理由只能说当天看得见的；不拦的话直到最后检查才露馅，撤不回 |
| 跳过图直接说结论 | H20 | 不支持 | 没有例子，改完没法核对 |
| 好奇看一眼 2026 | H22 | 硬拦 | 撤不回 |

**一句话分界**：判据是「流程由着我，代价会不会变成**看不见**的错证据、或**撤不回**」，不是「我想不想」。看得见、撤得回的都由着我；想法合理但要我回头改标注的，交给会话消化；会悄悄造假的，兜在界面默认上而不是靠提醒我；拿结果倒推当时和撤不回的，规定在我身上、有人核对或硬拦。除此之外，任何「请用户不要这么做」的规定，我几周后都会忘，等于没有。

### 3.4 定稿小结

- **第一轮**：高 4、中 11、低 7（F1～F22）。之后几版又陆续冒出 N1～N4、G1～G8、K1～K11、J1～J7，绝大多数在下一版里消掉。
- **最后一轮仍开着**：**高 1**（L1）；**中 4**（L2、L3、G1 的残余、F12 盲看未设计）；**低 8**（L4～L7、F8 观感、F13、F18、F21）；另有 J2～J4 三条因为「回答单子」没做出来而无从验证。F3 界面已改成默认 null，等用户定 D2。
- **最要紧的三条**：
  1. L1：随手画的两段首尾交叠，被「属于」的容差判成父子，一张图上的假子框就把整个 pattern 的轨标题和轨序改了，pattern 页还看不出来。建议首尾交叠一律按先后读、只有子框明显短于外框才算属于，名称级从属要多数买点同意才成立。
  2. L2：问题进了界面却答不了，在图上改好了也不消。这是 flow v3 每轮循环的入口，答不了就又回到「在终端里读、去浏览器找」。
  3. L3：近义词合并是批量改名，一选就生效、没有撤回。
- 流程上我作为用户最认可的变化：照常画、写 app 时会话问一次级（F1 的解）；偏离只在有 app 后出现、不标红、组头说清差在哪；页头 `next` 一格告诉我该谁动；属性默认 null。最担心的残余：第一次定 label 时看了后续走势，谁也查不了，只能靠最后检查兜（flow 已接受）。
