## 第一轮：现版

现版没有「还没 app 的 横盘突破回踩」这个状态，任务 1 用两个造出来的 pattern 代替：先把未归类页里两个「下跌→底部」开头的买点挪进新建的 `下跌底部突破`（没 app，2 个买点）；后面又把全部 8 个实例挪进新建的 `混合测试`（没 app，6 buy + 2 no_buy，两种骨架混在一起），这是任务 1 真正要测的样子。mock 不存盘，刷新即复原。

### 任务 1：还没 app，标了一批买点，想知道这个 pattern 里是不是混了两种东西

- 想干什么：看一眼就知道这批买点是一种走势还是两种。
- 第一眼看哪：`groups n=7  by: sequence`，然后一条条读组头的特征串。
- 读成了什么：
  - 8 个实例分成 7 组，几乎一组一个（`sim_15_noapp_mixed_8buys.png`）。分组规则是「顶层特征串完全相同才合并」，差一个尾巴（有没有画回踩）、少画一个横盘就另起一组。所以「组数多」不等于「种类多」，**组数这个数没法直接回答问题**。
  - 正确答案是两种骨架：长下跌 / 横盘 开头的一族（组 1、2、3、5）和 下跌→底部 开头的一族（组 4、6）。这个结论是我把 7 条特征串在脑子里按开头聚了一遍才得出的，界面没替我做。
  - 只有 2 个买点的 `下跌底部突破` 里（`sim_04_noapp_pattern_side.png`）分成 2 组，差别只是一个有回踩、一个没有。我第一反应读成「两种东西」，其实多半只是那张图没画回踩。真正像「两种东西」的是底部下面的 `V形 1/1 null 1`、`W形 1/1 null 1`：两个底部各判断了一种形状。可分组规则写着「套在里面的框不算」，属性更不算，所以 **groups 对 V 底 / W 底这种分叉完全看不见**，只能从 features 区的 `1/1 null 1` 倒推。
  - 没 app 时，同一条特征串下的 buy 和 no_buy 合在一组（组 1 是 `×2 buy 1 no_buy 1`）；有 app 时 no_buy 单独成组。同一个列表，两种合并规则。
- 点了几下：看列表 0 下；想确认哪个缩略图是哪只股票，每张要悬停一次（缩略图上不写股票和日期）。
- 要记住或换算的：7 条特征串两两比、聚成族；「套在里面的不算」这条规则；`1/1 null 1` 要翻译成「只判断过一个框」。
- 卡住的地方：分组粒度太细，最想回答的「两种还是一种」反而要自己做。

### 任务 2：从未归类页把一批买点归进 pattern

- 想干什么：把未归类的 3 个买点分到该去的 pattern。
- 第一眼看哪：未归类页的 groups（`sim_03_unsorted_full.png`）。3 个买点 3 组，每组 ×1。
- 过程：
  - `横盘→放量突破→回踩` 那组有一个按钮 `→ 横盘突破回踩`，点 1 下就归过去了。这一下很顺。
  - 两个 `下跌→底部…` 的组没有一键按钮（没有哪个已有 pattern 对得上）。我用组上的下拉选 `+ new`，弹框起名 `下跌底部突破`（2 下 + 打字），剩下那组再用下拉选它（2 下）。**新建的 pattern 没 app，所以哪怕特征串一模一样也不会出一键按钮**，第二个买点只能走下拉。
  - 「一批」在这里其实是一个一个挪：每组只有 1 个买点，组的「整组挪」没有帮上忙。
  - 买点自己的 `instance` 页里也有一行 `pattern` 可以选，单个挪也是 1 下。
- 点了几下：3 个买点共 1 + 3 + 2 = 6 下，外加起名打字。
- 要记住的：哪几组是同一种（又回到任务 1 的聚类）。
- 意外：挪完以后 `下跌底部突破` 里 AMST 2024-01-18 的缩略图冒出 `◂`，悬停写「买点前有一个没收进成员的『回踩』框（2023-09-06 起）：点一下收进」，图上那根回踩框也不变淡、挂 `◂`（`sim_05_amst_jump_unclaimed.png`）。可那根回踩是 AMST 2023-09-11 那个买点的成员（选中它，成员链是 横盘→放量突破→回踩），只是那个买点刚被我挪到 `横盘突破回踩` 去了。图上的提示写着「又不是别的买点的成员」，实际判断的只是「不是当前 pattern 里别的买点的成员」。挪之前（都在未归类时）没有这个 `◂`。照提示点下去，这根回踩就会同时被两个买点收着，而它在这个买点的下跌开始前一个多月，明显不是一回事。
  - model 按代码核过（事后补）：规则本来就只排除同一 pattern 的买点，因为一个框可以同时属于不同 pattern 的买点，所以不算逻辑错；错在悬停文字漏了「同一 pattern」这几个字。这一次是「同名、又落在 bracket 左边 40 根以内」这条猜法的误报，40 根这个窗口上一轮就标了待验证。

### 任务 3：有 app 了，想知道 app 哪里和我对不上、先看哪个

- 第一眼看哪：朱红底的 `app:buy`。默认数据里只有一处：`=` 组 `×1 no_buy 1 app:buy 1/1`（`sim_02_pattern_side_withapp.png`）。读成「我说不买、app 买了」，对。
- 把 AMST 2023-09-11 归进来以后，主组变成 `×3 buy 3 app:buy 2/3` 朱红（`sim_06_after_move_main_group3.png`）。**组上只说 3 个里有 1 个 app 没买，没说是哪一个**；缩略图上也没有任何 app 的记号。我只能挨个点：点缩略图跳过去，开 `compare`，看买点三角下的 `app:buy` / `app:no_buy` 签，三张里第三张才是（`sim_09_compare_tvrd_b.png`、`sim_10_compare_whlrp.png`、`sim_11_compare_amst_moved.png`）。4 下（3 张缩略图 + 1 次开 compare），还得记住哪几张看过。
- 顺带发现：每个买点的 app 结果其实在主图上有落点：开 `compare` 后买点三角下面挂 `app:buy` / `app:no_buy`，对不上的朱红，偏离的还挂 `−回踩`。所以「`app:buy k/n` 是全工具唯一的落点」只对「跨图汇总」成立，单个买点在 compare 里看得到。
- 卡住的地方：`−回踩` 组是「我标 buy、app 没买」，也是对不上，可 `app:buy 0/1` 不标红。悬停解释是「偏离组不标红：app 买了往往说明缺的那样其实在、只是没画」——说的是 app 买了的情况，而眼前这个是 app 没买，解释和眼前的情形对不上。我第一遍读成「这个没问题」。正确的意思是：对不上的原因在我自己的标注（缺了必须有的回踩），所以不算 app 的错。
- 「先看哪个」：界面给的顺序是偏离组排最前，可颜色把我先引到朱红的那两处。顺序和颜色指向不同的地方，我不知道该听谁的。

### 任务 4：想知道某个 buy 为什么排在最前那组

- 对象：`−回踩` 组的 TVRD 2024-12-24。
- 读成了什么：`−回踩` 我猜是「少了回踩」，悬停「必须有『回踩』，成员里没有」，猜对了。缩略图里回踩那一行有名字没有框（`sim_07_thumb_minus_huicai.png`），对得上。为什么排最前，要再悬停 groups 那一行的标题才知道「先是和对应表对不上的 buy」。
- 点了几下：悬停 2 次，0 下点击。
- 要记住的：「对应表」是会话写的必须有 / 必须没有那张表，不是我的标注本身。所以这个组头看着是我的东西（白底，图例里白 = user），其实是拿我的框去比会话的表比出来的。几周后回来我会以为是我自己标的「缺回踩」。
- 卡住的地方：知道了为什么，下一步干什么在这里看不出。答案在 `ask 4` 的单子里：同一个买点挂着 `−回踩` 和三个选项 `on_chart`（图上其实有，去收进）/ `keep`（真没有，仍算这个 pattern）/ `drop`（真没有，挪走或改 no_buy）（`sim_13_ask_open.png`）。**同一件事在 groups 和 ask 里各出现一次，能动手的在 ask，groups 那边只能看。**

### 任务 5：像但不买的点，app 却买了

- 对象：`=` 组的 TVRD 2025-05-08（no_buy c）。
- 读成了什么：`=` 我第一眼读成「正常 / 符合」。悬停「必须有的都有，必须没有的都没有」。对 buy 来说这是好事；**对 no_buy 正好相反：按会话的表，我的标注里找不出它和正例的任何结构差别，app 多半会买它。** `=` 这个符号在 no_buy 上指的是最糟的情况，可读起来像「没事」。（model 核过：说成「一定会买」过头了，app 还可能因为某段的门槛、两段之间隔得不对而不买。）
- 进一步：它的成员和 buy b 完全是同一批框（图上框外都写 `b c`），只是买点晚了 8 天。不买的理由不在 groups 里，也不在它的 `note` 里（空的），只在 `ask` 单子的一条「`buy → no_buy` 回踩前一天放量长阴，当天就看得见」里。这条是会话因为 label 翻过才问的。
- 对照：`+派发` 那个 no_buy 是健康的：有必须没有的派发，app 也没买（`app:buy 0/1` 不标红）。同样是 no_buy 组，`=` 是坏的，`+派发` 是好的，靠组头符号区分，我得记住「no_buy 组头是 `=` = 我没画出不买的理由」。
- 还有一处不一致：buy 的主组组头写的是特征串 `放量突破 → 回踩`，no_buy 对得上表的组组头却是 `=`。两个都表示「和表对得上」，写法不一样。

### 任务 7：几周后回来，只看 pattern 页，能不能说清每组是什么、每个标签谁给的

逐项说（括号里是悬停后才知道的正确答案）：

| 屏上的字 | 我凭记忆读成 | 实际是谁给的、什么意思 |
|---|---|---|
| `groups n=4` | 4 种走势 | 界面按规则算的分组；分组规则随 app 有没有而变 |
| `by: required` | 不知道；猜「按必须的」 | 有 app：只按必须有、必须没有（和先后）分组。features 区和 ask 里同一个意思写的是 `must`，这里写 `required`，**同一个概念三处三个写法**（必须有 / must / required） |
| `by: sequence` | 按顺序 | 没 app：按顶层特征串完全相同分组 |
| 组头 `放量突破 → 回踩` | 这几个买点的成员就是这两段 | 只是「必须有」那几段；缩略图里还有长下跌、横盘、缩量。没 app 时同样样子的组头却是完整的顶层特征串，**同一种外观两种含义** |
| `−回踩` / `+派发` | 我标的「缺了 / 多了」 | 我的框和会话的表比出来的；白底，图例里白 = user，来源看着像我 |
| `=` | 正常 | 和表对得上；对 no_buy 是坏消息 |
| `×1` / `buy 1` / `no_buy 1` | 对 | 我标的 label 计数 |
| `app:buy 2/3` 朱红 | app 和我对不上 | 对；但偏离组永远不红 |
| `◂` | 不认识 | 界面检测的「画了没收」，点一下直接收进，不跳图 |
| 缩略图黑框 | 这张有问题 | 当前选中的那个买点 |

能独立说清的：`buy` / `no_buy` 计数、`app:buy` 是 app 给的（黄底和图例对得上）。说不清的：组头符号的来源（看着是我、其实掺了会话）、`required`、两种分组规则、`=` 对 no_buy 的含义、黑框。

### 第一轮小结

1. 每次看 groups，我心里带的问题只有三类：**这批是不是一种东西**（没 app）、**app 和我哪几个对不上**（有 app）、**下一个该看谁**（翻图）。现版对第二类答得最好，但只到「组」，不到「哪一个」。
2. 没 app 时按完全相同的特征串分组太细，组数≈买点数，「一种还是两种」要我自己聚类；套在里面的框和属性不参与分组，V 底 / W 底这种真分叉看不见。
3. 组头一套符号（特征串 / `=` / `−X` / `+X`）在 buy 和 no_buy、有 app 和没 app 下意思都在变，`=` 对 no_buy 读反。
4. 组头的来源看着是「我」，实际是「我 × 会话的表」；颜色图例在这里帮倒忙。
5. 偏离组的事在 ask 里有一份能动手的，groups 里那份只能看。
6. `◂` 在买点分到不同 pattern 后会提示去收别的 pattern 买点的框（任务 2 的意外）。model 核过是悬停文字写错加猜法误报，不是逻辑错；但它说明缩略图里不跳图就「一键收进」，收的是哪根我看不见。

## 第二轮：正式变体（ui 定稿，文件 11:21:41 版）

### 任务 5：像但不买、app 却买了

- 三个变体 no_buy 上 `=` 的悬停都改成「跟正例一样。按现在的对应表分不出它为什么不买；app 买了它（朱红）多半就是这个原因」，悬停后能懂。第一眼看 `=` 仍读成「正常」，靠旁边朱红的 app 签才知道有问题。
