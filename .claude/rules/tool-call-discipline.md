# 工具调用纪律（防把调用写成字面文本）

**适用范围**：所有要调工具的回合，与场景无关——主会话、subagent-driven / executing-plans、agent team 的 leader 与 teammate。派发 subagent / teammate 时，把文末「可粘贴片段」原样写进其 prompt。

**故障模式**：工具调用偶尔被生成成正文里的字面 XML 文本（正文出现 `<invoke` 等字样）而非真正触发。运行时只认真正的调用块、不认长得像它的文字，于是该回合什么都没执行；若就此停笔，无人值守流程原地卡死。

## 正向操作规程（调工具那一刻照做）

1. **中途消息 = 至多一句状态 + 调用**：回合中段（之后还要继续调工具）的每条消息，正文至多一句纯自然语言状态行，随后直接发调用。状态行里不出现反引号、代码标识符、工具名、XML 字样。
2. **长篇内容只放收尾消息**：解释、决策、汇报、代码示例等长正文，只出现在「本回合不再调任何工具」的最后一条消息里。一条消息要么以调用结尾、要么是纯文字收尾，不写「长正文 + 调用」混合体。（注意：回合中途发不带调用的纯文字消息会直接结束回合——所以"先说后做"必须靠"一句状态行+调用"实现，而不是分两条消息。）
3. **不预告调用**：要做就直接发调用，不写「我现在去执行/调用 X」这类预告句——预告句最容易把调用滑成文字描述。

## 自救（违反后的恢复，比预防更重要）

- **写着写着发现正文里出现了调用语法的字面文本**：不要就此停笔结束消息——在同一条消息里紧接着发出真正的调用。字面文本本身无害，停笔才致命。
- **续跑/重发时发现上一回合没有任何工具真正执行**：零正文，直接重发调用。

## 可粘贴片段（派发 subagent / teammate 时原样放进 prompt）

> 调工具纪律：中途消息正文至多一句状态行（无代码 token、不预告"我去调用 X"），随后直接发调用；长篇解释只放不再调工具的收尾消息。若发现自己把调用写成了正文文字，不要停笔，在同一条消息里立即发出真正的调用。
