### 0.2 结论：**score 否决，奥卡姆选择**

> **工作流不该是搜索，该是一串绝对否决闸。**
>
> 闸阵 = 硬门（n≥200）· **因果可容许**（§0.3）· 标注单向否决 · `run_regress` 误伤 · 两窗不崩。
> **绝对闸不是比较 ⟹ 不累积选择偏差** ⟹ K 记账 / 平台中心 / optuna / 多保真度 / 门槛表**大部分退场**。
> 幸存者之间按**结构简单性**取（`mech` 独立收敛到同一措辞），**消耗零选择预算**。

这直接回答用户的原问题：他要"从顶层 dag 到底层 detector 的优化工作流"。
**在当前信噪比下「优化」这个词不适用；能做的是「排除」。**
这不是消极结论——它就是「最优化 > 最自动化」的最终形态：**最优化的做法是不做那件做不了的事。**

### 0.3 因果可容许闸（现场读代码定稿，机械可检）

`path2/atoms/breakout.py:128-190`：`BurstDetector` 的 `all_ends` 前缀族**在每个 end 即时物化**，
不等链结束（docstring:116 原文：**「买家因果：实例在 end 时刻即时物化，只读 ≤ end 的数据」**）。

```
因果可容许闸：  买点锚点字段的 bar  ≥  该 event 物化的 bar
```

**闸的对象不是 `end_node`，是「买点锚点用了 event 的哪个字段」。同一 event、两字段、判定相反：**

| 锚点 | 判定 |
|---|---|
| `burst.end_idx`（事件物化那根） | ✅ |
| `burst.start_idx`（簇首 bo，是过去的 bar） | ❌ 前瞻 |

经验规则：span event 的 `end_idx` 天然可容许，`start_idx` 一般不可容许。
每个 detector 声明一次"我在哪根 emit"，**这道闸就机械可检，不需要人做语义审查**。

**两个后果**：① **现任 bbb 通过**（买在 tb 确认日，晚于 burst 的 last_bo ≥1 根）⟹
**定案报告那 0.0719 不含因果不可容许成分，历史结论不需要重标**；
② **`burst_no_tb` 通过**（买在 `members[-1]` 那根 = `burst.end_idx`）⟹ 可实盘。

*（`opt` 用此闸枪毙 `end_node=burst` 的结论正确，但他给的机制「链要完成才知是链」不成立——
`all_ends` 的设计目的正是消灭这个等待。真正的违反是 `start_idx` 是过去的 bar。）*

## 0.5 一句话结论（第 1 轮，保留作对照）

**这个项目不缺搜索能力，缺的是把已有的目标函数接到层①②上。**
现有 score 口径扎实、评估器完备、批量漏检入口已存在；但目标函数目前只连着层③（参数）。
层①②的每一次改动，历史上都是靠**内部代理指标**（gating 率 / 触发率 / 共线性 / 窗口涨幅）
判定的，而唯一一次事后用 score 复核的结果是 **−79%**。

因此：**新建搜索循环是错误的投资方向；把 score 插进 `authoring-path2-app` 的验收口是正确的投资方向。**

### 四个可直接引用的实测数字

| 结论 | 实测值 |
|---|---|
| 评分标准的 SE 常数低估真实配置噪声 | **1.77x**（它精确描述的是"零信号配置"，§1.4）|
| K=40（定案实际搜索量）的选择门槛 | **0.024** 单窗 / **0.0134** 两窗最差分（§2.1 / §4.1）|
| 「两窗最差分」把选择门槛砍掉 | **30~48%**——现有方法论里最有效的抗过拟合装置（§4.1）|
| 定案配置扣除选择门槛后 | **honest ≈ 0.045，是门槛的 3.4 倍，站得很稳**（§4.1）|

**自动化的价签**：搜索量 40 → 1000，选择门槛从 0.024 涨到 ~0.039 ⟹
**一个由 1000 候选自动搜出的配置，必须比现在的配置再高约 0.015 分，才只是「同样可信」而已。**

**一条零成本的存量资源**：磁盘上有 3 个从未被用过的评估窗（2022 / 2023 / **2026 至 07-13**）。
定案报告写的「真正的验证需要未来数据」——**未来数据已经在磁盘上了，只是没人跑**（§4.2）。

### 一个现场做出来的存在性证明（§5.5.2）

我用**一个临时脚本、约两分钟、只读已有扫描输出、没跑一次全宇宙 eval**，
把目标函数第一次施加到「层① 结构变体」上：

| 配置 | n | median | q25 | lift | **score** |
|---|---|---|---|---|---|
| bo_only 基线 | 29502 | 0.1234 | 0.0483 | +0.0000 | 0.0000 |
| bbb 定案（含 tb） | 423 | 0.2293 | 0.0745 | +0.1059 | **0.0719** |
| **burst_no_tb（删掉 tb 节点）** | **974** | 0.2142 | 0.0619 | +0.0908 | **0.0754** |

两者 score 差 0.0035，**统计上无法区分**（SE 0.013~0.018）。但——
**删掉整个 pattern 里最复杂、近期几乎所有调参工作所针对的那个节点，
score 不降反微升，样本量翻 2.3 倍。**

> **一个"删掉一个节点"的结构候选，压倒了数月的层②③工作。
> 不是因为搜索得不够多，是因为从来没搜过那个方向。**

这同时证明了四件事：用户"当前 pattern 不够优"的直觉是对的；
原因不是缺搜索能力；B0 极简基线足以捕获它；「最优化 > 最自动化」是对的。

## 1. 实测：score 的真实噪声地板

### 1.1 数字

| 量 | 实测值 |
|---|---|
| SE(lift) @ n=423，iid bootstrap | **0.0175** |
| SE(lift) @ n=423，按周整块 bootstrap | 0.0186（design effect 1.06x）|
| SE(lift) @ n=423，按月整块 bootstrap | 0.0222（design effect 1.27x）|
| **SE(score)（n∈[200,1000] 区间）** | **0.012 ~ 0.015** |

### 1.2 我自己的假设被证伪（如实记录）

我进场时的假设是「买点在时间上强聚簇 ⟹ 有效样本量远小于 n ⟹ 噪声被严重低估」。**实测证伪**：
423 个买点散在 **163 个不同交易日**，日期 Herfindahl 等效独立日数 ≈ **115**，
单日最多 8 个，top5 单日合计只占 8.7%。整块 bootstrap 的 design effect 只有 **1.06~1.27x**。

**聚簇不是问题。** 这条假设作废。

### 1.3 但评分标准的 SE 表确实低估了 1.77x（真问题）

`pattern_config_scoring_standard.md` §2.2 那张表隐含 `SE(median) = 0.2024/√n`。
实测标定常数是 **0.3589**。后果：

> 标准里「n=200 恰好是能检出 +0.028（基线 23%）lift 的量级」**不成立**。
> 真实是 n=200 时 SE=0.0254 ⟹ **最小可检出 lift = +0.051（定案 lift 0.11 的 44%）**。

原因不是聚簇，是分布形状：`SE(median) = 1/(2·f(median)·√n)`，过滤后的 label 分布
在中位数附近密度更平，SE 就更大。`n₀=200` 是从 `BreakoutStrategy/mining/pipeline.py`
沿用的值，**从未在这个 label 分布上标定过**。

### 1.4 根因已精确定位：那个常数描述的是「零信号配置」

实测（n=423，4000 次重采样）：

| 样本来源 | SE(median) |
|---|---|
| 从 bo_only 池随机抽 423 个（= 零信号配置） | **0.00979** |
| 标准公式 `0.2024/√423` | 0.00984 |
| **真实定案配置的 423 个买点（bootstrap）** | **0.01734** |
| 比值 | **1.77x** |

**标准公式与「随机子集」吻合到小数点后 3 位。**

> **⟹ 评分标准的 SE 常数精确地描述了一个「什么都没筛出来」的配置，
> 而把真正携带信号的配置的噪声低估了 1.77 倍。**
> 这是一个可以直接写进标准去修的根因：它是从基线池的离散度推出来的，
> 但排序时比较的是**筛过之后**的样本，后者尾部更重、中位数附近密度更平。

**诚实边界**：我算的是窗均值列（scan 里的 `forward_return`，中位数 0.2333 = 报告的
`median` 列）。排序真正用的 `median_confirm` 是单日口径，方差只会**更大**。
所以 0.0175 是**下界**。

## 2. 选择偏差：数值上推翻了 naive 论证

K 个**独立**候选取最大值的期望膨胀（σ=0.013）：

| K | 期望膨胀 | 占定案 score 0.0719 |
|---|---|---|
| 10 | +0.0200 | 28% |
| **40（定案报告实际搜的配置数）** | **+0.0281** | **39%** |
| 100 | +0.0326 | 45% |
| 1000 | +0.0421 | 59% |
| 10000 | +0.0501 | 70% |

因为 `E[max] ~ √(2 ln K)`，**搜索量 ×25（40→1000），选择偏差只涨 1.5 倍**。

### 两条推论

**(a) 「自动化能跑上千次 ⟹ 过拟合爆炸」是错的。** 该说的是更难听的话：
现有人工流程已经在对数曲线的深处。定案报告那 0.0719，**约 39% 可能是选择噪声**。
这是现状，不是自动化引入的。

**(b) 反过来，自动化的边际真实收益同样小。** 这就是用户「最优化 > 最自动化」原则的定量版：
**在这个信噪比下，加搜索量的回报是对数级的；加数据量、加真信号的回报才是线性的。**

### ⚠ 决定性限定：K_eff 在三层上完全不同

max-of-K 公式假设候选**独立**。

| 层 | 候选相关性 | K_eff | 自动化风险 |
|---|---|---|---|
| ③ 参数 | 坐标扫描邻居共享绝大部分样本，高度相关 | **K_eff << K**（定案那 40 个可能只值 5~10）| 低 |
| ① 拓扑 / ② detector 代码 | 每个候选是语义不同的过滤器，命中不同样本子集 | **K_eff ≈ K** | **高** |

**⟹ 自动化层③基本安全；自动化层①② 才是选择偏差真正增长的地方——而那恰好是用户想要的那块。**

### 2.1 直接实测的「选择门槛」（不用高斯近似）

上面是解析近似。更硬的做法：跑一个**零信号 null 模型** —— 从 bo_only 池随机抽子集
当作「配置」（只缩小样本、不携带任何信息），套用真实评分标准（score / 硬门 n≥200 且
q25≥0），看搜 K 次之后**冠军报出来的 score 是多少**。用真实 label 分布。

**K 个 null 配置的冠军 score（中位数，400 次重复）：**

| K | n=200 | n=423 | n=1000 | 混合 n∈[200,1000] |
|---|---|---|---|---|
| 10 | 0.0112 | 0.0104 | 0.0080 | 0.0096 |
| **40** | 0.0168 | 0.0148 | 0.0113 | **0.0136** |
| 100 | 0.0198 | 0.0172 | 0.0133 | 0.0165 |
| 400 | 0.0240 | 0.0215 | 0.0160 | 0.0204 |

**null 门槛要乘 1.77**（§1.4：真实配置的样本比随机子集噪声大 1.77 倍）才是真实门槛：

| K | 真实选择门槛 | 定案 score 0.0747 扣除后 | 存活比例 |
|---|---|---|---|
| 10 | 0.017 | 0.058 | 78% |
| **40（定案实际搜索量）** | **0.024** | **0.051** | **68%** |
| 100 | 0.029 | 0.045 | 61% |
| 400 | 0.036 | 0.039 | 52% |
| ~1000（外推） | ~0.039 | ~0.036 | ~48% |

**两条必须一起说的结论：**

1. **定案配置扛住了选择校正——它大概率是真的。** 扣掉 K=40 的门槛后仍剩 0.051（68%）。
   但**报告里的 0.0719 应该被读成「约 0.05」**，不是 0.072。这不否定那轮工作，是给它标定精度。
2. **自动化的代价可以精确报价**：把搜索量从 40 推到 1000，选择门槛从 **0.024 涨到 ~0.039**。
   ⟹ **一个由 1000 候选自动搜索选出的配置，必须比现在的配置再高约 0.015 分，
   才只是「同样可信」而已。** 这是"最优化 > 最自动化"的价签。

## 3. 三道防护，两道对自动化无效

### 3.1 `q25 ≥ 0` 实测近乎虚设

bo_only 负收益占比只有 **4.3%**，q05 = 0.0000。从 bo_only 随机抽 2000 组子集：

| 子集规模 | q25 中位数 | **q25 < 0 的概率** |
|---|---|---|
| n=200 | 0.0487 | **0.00%** |
| n=423 | 0.0485 | **0.00%** |
| n=1000 | 0.0484 | **0.00%** |

一个「什么都没学到」的随机配置也能轻松过门。**它只能挡主动有害的配置，不是过拟合防护。
别把它算进防线。**

§2.1 的 null 搜索里再次直接验证：**5000 个零信号配置，被 `q25 ≥ 0` 淘汰的是 0 个。**

### 3.2 平台证据（plateau）无法迁移到层①②

定案报告自陈的抗过拟合证据是「前几名差距很小（0.064~0.074），平台而非尖峰」——
这是一个**参数邻域**论证。**离散的结构/代码候选没有邻域**，你无法问
「把这段判据改一点点 score 动不动」。

**现有方法论里最强的那道防护，在用户最想自动化的两层上直接失效。**
这不是可以补的细节，是层①②自动化必须自己发明替代品的地方。

可迁移的替代品只有一个，而且可计算：

```
要求 lift > σ·E[max_K] + margin
σ     = 0.0175 @ n=423，按 √n 缩放（实测）
E[max_K]：K=10→1.54σ  40→2.16σ  100→2.51σ  1000→3.24σ  10000→3.85σ
```

一行算术，不是新组件。但**必须由机制强制**——它的作用恰恰是惩罚搜索者自己的搜索量。

### 3.3 `n ≥ 200` 硬门恰好卡在方差峰值上

可解析证明：`SE(score) = c·√n/(n+n₀)`，对 n 求导 ⟹ **在 n = n₀ 处取最大**。
硬门恰好设在 n₀=200，所以**可采纳区间从方差最高点开始**：

```
 n      SE(lift)   w      SE(score)
   150   0.0293   0.429   0.01256
   200   0.0254   0.500   0.01269   ← 峰值，恰好是硬门位置
   423   0.0175   0.679   0.01185
  1000   0.0113   0.833   0.00946
  5000   0.0051   0.962   0.00488
```

max-of-K 搜索会系统性地把 n≈200~400 的配置顶上榜首（它们 score 噪声最大 ⟹ 最容易撞高分）。

**这条不是推理，已在 null 模型里直接测到**（候选的 n 从 [200,1000] 均匀抽，
所以「n<400」的基率是 25%）：

| 搜索量 | 冠军 n 的中位数 | 冠军 n<400 的占比 | 均匀基率 |
|---|---|---|---|
| K=40 | 448 | **41.8%** | 25% |
| K=400 | 356 | **60.0%** | 25% |

**搜索量越大，冠军越往硬门（=方差峰值）挤。** 人工搜 40 个时偏向已经可见（41.8% vs 25%），
自动搜几百个时它成为主导（60%）。**唯一还在起作用的那道门，本身对优化器是有偏的。**

## 4. 真正被自动化摧毁的是 holdout 纪律

选择膨胀是**可算的**（σ·E[max_K]），也是**可移除的**——一个从未被搜索过程看过的
holdout 就能给出无偏估计。而这正是自动化会破坏的东西：

- **人工流程天然只查询一次**：定案报告里 2024 是看到 2025 结果之后跑的一次复核。
  报告自己诚实标注「这不是真样本外」，但它至少只被消费了一次。
- **自动化循环每轮都要一个标量奖励**，而唯一干净的标量在你不该反复看的数据上。
  跑 200 轮的循环会把 2024 消费 200 次，跑完之后 2024 和 2025 一样脏。

数据总量是硬约束：7532 只 × 有限年份，n 已卡在 200 硬门附近。留 holdout 的代价真实：
年份一分为二，SE 涨 √2，最小可检出 lift 从 0.051 涨到 0.072。

### 4.1 ⚠ 自我更正：「两窗最差分」是正则化器，不是烧 holdout

我最初判定「每轮都报两年最差分 = 第一轮就烧掉 holdout」。**实测证明这个判定是错的，
我撤回它。** 这条规则是现有方法论里最有效的抗过拟合装置。

零信号 null 下（两窗各 n=423 vs 单窗 n=846，总样本量对齐），冠军 score：

| 搜索量 K | 单窗 | **两窗最差分** | 门槛降低 |
|---|---|---|---|
| 10 | 0.0155 | 0.0081 | **48%** |
| **40** | 0.0219 | **0.0134** | **39%** |
| 100 | 0.0257 | 0.0168 | 34% |
| 400 | 0.0300 | 0.0211 | 30% |

**两窗近似独立 ⟹ P(两窗都虚高) ≈ P(单窗虚高)²，选择门槛直接砍掉 30~48%。**

它比「平台证据」和 `q25` 加起来都管用，而且它在自动循环里**同样有效**——
K 越大它的相对优势确实缩小（48%→30%），但绝对降幅始终显著。

**⟹ 修正后的建议：两窗最差分不但要保留，还应该是自动化循环的默认判据。**

按此重读定案配置：两年最差 score = 0.0587，K=40 的两窗门槛 = 0.0134
⟹ **honest ≈ 0.045，是门槛的 3.4 倍。这个配置站得很稳。**

### 4.2 但「无偏估计」确实没了——而且解法是免费的

用两个窗**做选择**之后，两个窗都不再是无偏估计。定案报告自己也诚实标注了这点
（「2024 复核不是真正的样本外……真正的验证需要未来数据」）。

**这个限制是部分自招的。数据里有 3 个没被用的窗。** 实测抽样 600 只：

| 年份 | 有 >200 交易日数据的比例 |
|---|---|
| 2022 | 83% |
| 2023 | 86% |
| 2024 | 89%（在用）|
| 2025 | 97%（在用）|
| 2026 | 数据到 **2026-07-13**，约 6.5 个月 |

**⟹ 正确方案（成本几乎为零）：**
- **2024 + 2025 留在循环里做「两窗最差分」正则化器**（§4.1，别动它）
- **2026 年初至今这段留作 holdout**——它是最近的、真正意义上最接近样本外的一段，
  整个工作流生命周期内只解锁一次
- 2022 / 2023 作为备用窗（覆盖率降到 83% ⟹ n 约降到 0.85×，仍远高于 200 硬门）

报告里那句「真正的验证需要未来数据」——**未来数据已经在磁盘上了，只是没人跑。**

### 4.3 所以机制层要强制的是什么（修正后）

不是「锁住 2024」，而是：

1. **记 K**（搜了多少个候选），结论里必须按 §2.1/§4.1 的表报出对应门槛
2. **锁住 2026 那一段**，只允许解锁一次
3. **默认强制两窗最差分**，禁止退化成单窗排序

## 5. 项目历史的直接证据：瓶颈不在候选生成

`docs/research/2026-07-15_throwback-stop-drop-signal-generalization/` ——
一个**全 opus agent team**（3 专家 + skeptic + lead，7 份中间文档，5 股 3840 bar 实证），
推荐把 tb 止跌信号池换成稀缺池 `{lower_shadow, doji}`。
10 天后（2026-07-25）该判据第一次被放到 label 目标下测：

| 信号池 | n | score |
|---|---|---|
| 当前 3 类 | 423 | 0.0719 |
| **该 team 推荐的稀缺池** | **190** | **0.0154** |
| 完全不要求止跌信号 | 599 | 0.0712 |

**−79%。而且同一轮发现这整道判据关掉只差 1%——它本身几乎不创造 lift。**

**精确边界（避免我自己过度宣称）**：调参那轮测的是**只换 `_STOP_SIGNALS` 池**，
而 2026-07-15 的完整建议是 `FLOOR(M_floor=2) ∧ SPARSE_KLINE(pool={lower_shadow,doji}) ∧ DEPTH(1.0)`
——**几何门放松那一半没有被一起测**。所以被证伪的是该建议的**信号池组件**，不是整个包。
完整包（同时放松几何门）可能表现不同，无人测过。

失败机制**也不是**「LLM 生成候选能力不行」。那个 team 的测量是严谨的（Jaccard 共线性、
gating 率分解都对）。真正的问题在更前面一步：

> 那份报告 §1 自己写明，用户说的「过拟合」是术语误用，真意有 A（漏检）/ B（判据脆）/ C（语义不服）
> **三种可能**，并推断是 A+C 混合。**团队知道目标是歧义的，仍然把「更严不更松」当成既定目标交付，
> 全程没有问一句「更严对目标函数是好是坏」。**

**⟹ 这不是"测了错的量"这么简单，是"从未把目标函数纳入过考虑"。**
一个高投入、方法论严谨、自带 skeptic 的 LLM team，在目标函数缺席时会**沿着用户随口给的
方向性描述（"更严"）优化到底**，且内部无人能发现这个方向本身没被验证过。

更值得注意的是那份报告 §1 自己写下的一句话：

> 「若用户真意是漏检，**需提供 2-3 个具体漏检 ticker + 日期做 replay 验证**」

**这个请求从未被满足，方案就被实施了，然后被证伪。**

### 三条推论

1. **约束不在候选生成，在目标函数是否在环。** 任何「先用便宜代理筛候选、再用 score 复核少数」
   的设计，正是复现这次失败的配方。
2. 如果 eval 很贵，正确应对是**减少候选数**，不是**引入代理指标**。这与 §2 一致（回报对数级）。
3. 「LLM 提 detector 代码候选」的历史样本目前是 **1 次尝试、1 次被目标函数证伪**。
   而同期真正有效的改动（`stop_confirm_bars` 2→0，score −0.0012 → +0.0719）
   是**在 score 在环的消融里被机械发现的**，不是靠语义推理设计出来的。

### 5.1 同一个失败模式贯穿所有现有组件

| 组件 | 它排序/判定用的量 | 是目标函数吗 |
|---|---|---|
| `tune-pattern-strength` | score（lift × 收缩） | ✅ 是 |
| `scan-top-miss.py` | 窗口内 `close[end]/close[start]` 涨幅 | ❌ 代理 |
| 2026-07-15 detector 研究 | gating 率 / 触发率 / Jaccard | ❌ 代理 |
| `authoring-path2-app` Step 4 判据 2 | `run_regress` 的 added/removed | ❌ 代理（只看变化，不看好坏）|
| `tune-dagspec-to-match.js` | 目标票是否命中 | ❌ 代理（单样本）|

**目标函数只连着层③。这就是全部病灶。**

## 5.5 ⚠ 目标函数有一个未被封堵的刷分杠杆：入场位置

评分标准 §9 写了「lift 可能包含入场位置的算术效应」，但**从未量化**。我量化了，
结果比预期严重得多，而且它是本审查里**唯一一条直接威胁"自动化是否可行"的发现**。

对 bo_only 的全部 29502 个 bo 事件，把买点按平凡规则挪动，重算同一 label：

**① 单纯延迟入场（bo 后第 k 天收盘买）——没用**

| k | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 相对基线 lift | −0.0008 | −0.0019 | −0.0019 | −0.0012 | −0.0014 |

**② 平凡回踩入场（bo 后 k 天内最低收盘价那天买）——巨大**

| k | 2 | 3 | 5 | 7 | 10 |
|---|---|---|---|---|---|
| median | 0.1613 | 0.1724 | 0.1878 | 0.2004 | 0.2162 |
| **相对基线 lift** | **+0.0379** | **+0.0490** | **+0.0645** | **+0.0770** | **+0.0928** |

**对照：bottom_burst 定案 median=0.2333，lift=+0.1099。**

### 这意味着什么

规则 ② 是**零选股能力**的：它对全宇宙每一个 bo 事件无差别执行，不筛任何股票、
不看任何形态。它唯一做的事就是**把买点挪到附近的局部低点**。
（它用了未来信息、不可实盘复制——但**控制变量不需要可交易，只需要隔离机制**，
这是它作为对照列的合法用法，与"禁止用前瞻量做筛选"不冲突。）

### 5.5.1 ⚠ 自我更正：不能据此推断 bbb 的 lift 主要是入场算术

我最初据上表推断「bbb 头条 lift 的 60~70% 是入场算术」。**一个更干净的配对实验推翻了它，
我撤回这个推断。** 错误在于：我拿 bbb（选出来的 423 个）去比一个全宇宙规则（29444 个），
**两个总体不同**，差值里混着选股与入场，不能归给任一方。

**正确做法是配对**：在 bbb 自己的 423 个 setup 上，只改入场日期。

| 口径（同一批 setup） | n | median |
|---|---|---|
| bo_only 基线（全宇宙） | 29502 | 0.1234 |
| **B · 在锚点 bo（last_bo）当日买** | 423 | **0.3592** |
| **A · 在 tb 确认日买**（bbb 生产口径） | 423 | **0.2293** |

```
纯选股能力  B − 基线 = +0.2358
纯入场时机  A − B    = −0.1299      ← 是负的
合计        A − 基线 = +0.1059
```

**tb 确认距锚点 bo 的间隔中位数只有 1 根**（p90=2，max=6）——bbb 根本没有"延后买入"，
"买得更低"这个故事在数值上不成立。

> **⟹ 真相与我先前的推断相反：bbb 的 lift 全部来自 setup 选择（+0.236），
> 而「等待 tb 确认」这一步倒扣 0.130。**

*（诚实边界：B 不可实盘——它条件于"这个 bo 后来确实形成了 tb"，用了未来信息。
B 只作分解用的控制量，不是可交易基线。下一节给可实盘的版本。）*

### 5.5.2 顺着这条线的可实盘检验：整个 tb 节点是否值钱

burst 的三个 where（`first_drought≥20` / `distinct_pk≥4` / `vol_spike≥3`）
**全部在末 bo 当根即已知**。所以「只用 burst 条件、在末 bo 当日收盘买、完全不要 tb」
是一个**可实盘**的配置。实测（2025 全年，全宇宙，confirm 口径）：

| 配置 | n | median | q25 | lift | **score** |
|---|---|---|---|---|---|
| bo_only 基线 | 29502 | 0.1234 | 0.0483 | +0.0000 | 0.0000 |
| **bbb 定案（含 tb）** | **423** | 0.2293 | 0.0745 | +0.1059 | **0.0719** |
| **burst_no_tb（删掉 tb 节点）** | **974** | 0.2142 | 0.0619 | +0.0908 | **0.0754** |

（bootstrap SE：bbb 的 median 0.0180，burst_no_tb 的 0.0130。）

**判读要克制**：score 差 0.0035，**远小于两者的抽样误差，两者统计上无法区分**。
但方向很清楚：

> **删掉 tb —— 整个 pattern 里最复杂的节点、近期几乎所有调参工作的对象 ——
> score 不降反微升，样本量翻 2.3 倍。按奥卡姆剃刀，这是一个更好的配置。**

这与既有证据完全一致：调参报告发现「止跌信号池基本是装饰品」（关掉只差 1%），
而那轮唯一成功的改动 `stop_confirm_bars` 2→0 的语义就是「让 tb 少做事」。
**把这条线外推到端点，就是「别让 tb 做事」。**

**⚠ 这不是定案**：单窗口（2025）结果，必须按 §4.1 补 2024 窗的两窗最差分，
并跑 `run_regress` 误伤审查。我只主张它是一个**必须被评估的一等候选**。

### 5.5.3 这件事本身就是对 B0 极简基线最强的证明

上面这个结果，我用**一个临时脚本、约两分钟、只读已有的扫描输出**就拿到了。
没有新工作流、没有搜索循环、没有 agent 框架、没有跑一次全宇宙 eval。

**它之所以此前没被发现，唯一的原因是：从来没有人把目标函数施加到「层① 结构变体」上。**
——这正是 §5.1 那张表的诊断（目标函数只连着层③），也正是 §9 的 B0 要接的那一根线。

> **一个"删掉一个节点"的结构候选，在目标函数下的表现，压倒了数月的层②③工作。
> 这不是因为搜索得不够多，是因为从来没搜过那个方向。**

### 5.5.4 入场位置杠杆仍然是真的，但风险定性要改

§5.5 开头那个全宇宙实验的事实本身没错：**一个零选股能力的 oracle 回踩规则值 +0.065~+0.093**。
所以目标函数上确实存在一个未封堵的非选股杠杆，`median_dipctrl` 对照列仍然值得加。

但风险定性要改：**bbb 目前并没有在利用这个杠杆（它的入场时机是负贡献）。**
这是一个**预防性**护栏，不是对现状的指控。优先级相应下调——
排在「把目标函数接到层①」之后。

### 为什么杠杆本身仍是自动化的风险

评分标准已经封堵了**缩窗刷分**（靠 `median_confirm` 列），
但**没有封堵入场位置刷分**。而后者是目前目标函数上**最便宜的一截分**：
不需要任何选股能力就值 +0.065~+0.093。

- **人不容易滑进去**：人是按走势语义设计结构的，"把入场点往回踩低位挪"不是一个
  会自然浮现的设计动作。
- **最大化器会直奔它而去**：一个在层①②上自动搜索的循环，会很快发现
  "让 end_node 落在更低的位置"是最高性价比的方向，并把整个 pattern 往那儿拧。
  **它会报出很高的 score，而且完全通过所有现有硬门。**

**这是「最优化 > 最自动化」的一条技术依据：目标函数上存在未封堵的非选股杠杆时，
自动化搜索放大的是错配，不是能力。**（但见 §5.5.4：这是预防性的，不是对现状的指控。）

### 5.5.5 ⚠ 优先级降级：`opt` 的波动率发现使本节的修复变成"给要拆的墙刷漆"

`opt` 实测（同一批买点，只换 label 算式，两年独立复现）：

| 组 | n | max-high 20d | **持有到期 20d** | 胜率 | **最大不利偏移** |
|---|---|---|---|---|---|
| pk4（现任） | 423 | **+0.2293** | **−0.0632** | 41.8% | **−0.2301** |
| bo_only | 29502 | +0.1234 | −0.0040 | 48.3% | −0.1184 |
| 全宇宙随机日 | 3600 | +0.0704 | +0.0050 | 53.0% | −0.0636 |

`corr(score, 最大不利偏移深度) = −0.591 (p=0.003)`；MFE+MAE 对称计量 lift +0.0081（t=0.27）；
5/10/20/40 日持有到期全部为负且单调恶化。**⟹ pattern 把上行抬高 10.6 点、下行也压深 11.2 点，
两边几乎对称，而 label 只数上行那一半。**

**入场位置杠杆是同一个病的另一个症状**：买在局部低点 ⟹ 后续 MFE 更大 ⟹ 只数上行的 label 给它付钱。

> **⟹ 推荐：`median_dipctrl` 与「改 label 锚」两个方案都先不做。**
> 正确顺序 = **首次穿越检验 → 定 label 口径（路径依赖 / 对称计量 / 市场超额）→ 再看杠杆还剩多少**。
> 预判：换成路径依赖或对称口径后杠杆会自动大幅缩水（买在低点对"先触 +X 还是先触 −X"的帮助
> 远小于对 MFE 的帮助）。缩不掉再加对照列不迟。

**两条措辞收紧**（`team-lead` 提，接受）：
- 规则 ② 用了未来信息 ⟹ 它是入场效应的**上界** ⟹ 减完得到的是选股能力的**下界**。
  正确措辞：「选股能力**至少** +0.033~+0.046；头条 lift 里**至多** 60~70% 来自入场算术」。
  *（但注意 §5.5.1 已用配对实验推翻这个跨总体推断本身——此处仅为措辞纪律留档。）*
- 「算术效应」混了两样：**真实交易优势**（买得低是真钱）与 **label 定义伪影**
  （从低点弹回原价那一段被计进收益，实盘根本不是盈利）。**只有后者是纯刷分。**

### 修复（已按 §5.5.5 降级为 label 定案后的复查项）：加第三个对照列

```
median_confirm  ← 已有，封堵「缩窗刷分」
median_dipctrl  ← 新增，封堵「入场位置刷分」
                  = 同一 label 算式，买点取「end_node 锚点后 k 根内最低收盘」
                  k 取该 pattern 的 end_node 相对锚点的典型延迟
lift_selection  = median_配置 − median_dipctrl     ← 这才是"选股能力"
```

**报告时原始 lift 与 `lift_selection` 并列**，两者背离就是入场位置在做功——
与「`median` 与 `median_confirm` 背离就是窗宽在做功」完全同构。

## 6. `tune-pattern-strength` 到底缺什么（硬问题 1 的诚实诊断）

现场读了 `SKILL.md`(140 行) / `eval_skeleton.py`(205 行) / `sweep.py`(63 行)。

**结论：它在「目标测量」这件事上什么都不缺。它缺的只是「枚举非 dict 候选」的能力，
而那个能力比所有人想象的都便宜。**

依据 —— `eval_skeleton._eval_one` 的执行核心是：

```python
mod = _load(app)              # app 是模块路径字符串
res = mod.analyze(win, params)
```

而 app 的 `analyze` 是：

```python
def analyze(df, params):
    return _analyze(build_pattern(p), df, p)   # build_pattern(params) -> PatternSpec
```

**这条管线里没有任何东西是「参数特有」的。**

| 层 | 候选长什么样 | 现状可评估性 |
|---|---|---|
| ③ 参数 | nested dict | ✅ 已支持，`run_config(overrides)` |
| ① 拓扑 | 一个 `build_pattern(params) -> PatternSpec` 函数（`bottom_breakout_burst` 里**约 30 行纯声明**：nodes + edges + where） | ⚠ **仅差 `_eval_one` 接受 spec 工厂而非模块路径 —— 约 5 行** |
| ② detector 代码 | 注入 `build_pattern` 的一个 detector 变体实例 | ⚠ 可行但有真实摩擦，见下 |

**层①的评估能力其实每次运行都在用**：`baseline_median()` 跑的 `bo_only` 就是**另一个拓扑**
（单节点无边 vs 三节点一边）。**bo_only vs bottom_burst 本身就是一次拓扑对照。**
所谓「层① 没有评估能力」是不成立的——缺的是**廉价地生成拓扑候选**，
而现状要求为每个候选写一整个 app 目录（4 个文件 + `authoring-path2-app` 移交实现一轮）。

**层②的真实摩擦（诚实说清）**：`ThrowbackDetector.detect` 依赖**模块级私有函数**
`_find_start_idx` / `_find_end_idx` / `_has_stop_signal`（`path2/atoms/throwback.py`）。
子类**无法**干净地 override 它们。所以一个层②候选要么 monkeypatch 模块
（进程池下每个 worker 都要打，脆），要么把 `evaluate_throwback` + helpers 复制
约 200 行到变体模块。**这是一个非故意的结构性障碍，不是设计决定。**

### 这个发现是双刃的，必须连着说

技术上，「把 score 接到层①②」比任何人预期的都便宜（层① ≈ 5 行）。
**但正因为便宜，它必须与 §3.2 的 K 调整门槛和 §4 的 holdout 锁一起交付。**
把授权成本移除之后，就直接进入 K_eff ≈ 1000 的区间——恰好是选择偏差最恶劣的regime。
**授权成本此前一直在无意中扮演正则化项。移除它而不补上统计闸，是净负收益。**

## 7. 硬问题 2：该不该把 `authoring-path2-app` 改造成搜索循环

**不该。** 三条理由，按强度排序：

1. **统计上不需要**（§2）：层①的回报是对数级的，而层① 的 K_eff ≈ K 意味着它的
   偏差按满额计。搜 1000 个拓扑比搜 10 个多拿到的，几乎全是膨胀。
2. **该 skill 的核心资产恰好是搜索循环要丢掉的东西**：三层 gate 的价值在
   `AskUserQuestion` 逐层确认 + 「重开纪律」（重开是显式事件、要用户重新盖章）。
   这是**人类语义约束的注入点**，是层① 候选质量的唯一来源。
   把它改成无人值守循环 = 把唯一的语义先验拆掉，换来一个统计上没用的搜索量。
   该 skill 的 Red Flags 里已经写了「在本 skill 里重造实现循环 / 无人值守多轮改结构」。
3. **它已经有正确的接口**：Step 4 判据 2 就是验收口。**该改的是那一个口的内容
   （`run_regress` → score），不是整个流程的形态。**

## 8. 硬问题 3：LLM 生成 detector 代码候选的真实成功率

### 8.1 ⚠ 自我更正：基率陈述撤回（`team-lead` 挑战 2，我认输）

我原写「1 次尝试、1 次被目标函数证伪」，并称有效的 `stop_confirm_bars 2→0` 是
「在机械消融里被发现的」。**核实后撤回。**

`2026-07-25_tb-recall-quality-tuning/final_report.md` §3 的单因子消融表**只有 6 个配置**
（现状 / K=1 / K=0 / min_bos=1 / support=close / max_start_gap=12）——**手挑名单，
不是 21 个旋钮的盲扫**。而 §2 根因段引用的「`phase1_rise_before_confirm` 独占 30.6% 否决、
tb 产出率 6.5%（历史 34.2%）」正是召回崩塌那次**语义因果归因**的产物
（它把根因定位到 phase1 + `stop_confirm_bars`，而非当时头号嫌疑 `min_bos`）。
**有人先提名了这个旋钮，机械消融才有得确认。**

> **改为机制陈述**：**区分变量是目标函数是否在环，不是候选由谁生成。**
> 语义提名 + score 裁决 = 成功（`stop_confirm_bars`，效应 60 倍）；
> 语义提名 + 无 score = −79%（稀缺信号池）。**同一批人、同一种能力，差别只在有没有尺子。**

**同时收回一句过强的话**：「先用便宜代理筛、再用 score 复核少数 = 复现失败的配方」——
太强。**代理筛选**的失败模式是漏候选（召回损失，可控）；**代理决策**的失败模式是选中坏候选
（有效性损失，致命）。2026-07-15 是后者（全程没跑过 score）。两者代价不同，不该混为一谈。

### 8.2 原始论证（保留，其机制部分不受 §8.1 影响）

**可获得的直接证据：1 次尝试，1 次被目标函数证伪（−79%），见 §5。**

不要过度解读这一个样本——n=1 说明不了 LLM 能力上限。但它能说明一件确定的事：
**在没有目标函数在环时，一个高投入、方法论严谨的 LLM team 也会产出主动有害的 detector 改动，
且团队内部（含 skeptic）无法自查出来。** 这不是能力问题，是信息问题——判据函数的好坏
在数据上是可测的，在语义上是不可判的。

同期的反面证据同样有力：真正有效的那个改动（`stop_confirm_bars` 2→0，7 倍效应）
是**在 score 在环的单因子消融里被机械发现的**。它不需要语义洞察，
只需要有人把每个旋钮各动一次然后看分。

**⟹ 对 LLM 的正确用法是「生成少量候选 + 立刻交给 score 裁决」，
不是「用语义推理筛选候选」。LLM 的比较优势在生成，不在判定。**

**(a) B0 数不出自己的 K。** 我在 §10 要求「K 调整门槛，K 由记账得来」，但 B0 的每次用户调用

**(c) ⚠ B0 第 1 步靠人自觉落标注集，没有任何强制机制 —— 这是 B0 最致命的缺陷，我自己列出来。**

> **「记得问用户」不会自动发生。同一请求提四次仍然落空。**
> B0 第 1 步会以**完全相同的方式**落空。这是打败 B0 的唯一合法切入口，我自己写进来。

**补丁不是"加一个提醒环节"，而是 `mech` 那条最强的原则——让错误的东西不可表达**：
不是提醒人提供标注，而是**让缺标注的定案路径根本不存在**（`finalize()` 的签名要求标注文件，

## 11. 对 lead 简报两条候选杠杆的判定

**杠杆 1「成本常数决定一切」——判定：框架错误。**
成本不决定该搜多少（那由信噪比决定，而信噪比说别搜太多）。
成本只回答一个门槛低得多的问题：**能不能把一次真 eval 插进设计流的每个 gate。**

**杠杆 2「人类标注 N 个 (ticker,date) → recall 目标 → 双目标搜索」——判定：可疑，反对其「目标维度」形式。**

1. **recall 是免费的分**：score 有减基线保护（全放开退化成基线时 lift 恒为 0，摆烂刷不到分）。
   **recall 没有这个保护**——把过滤全放开，标注样本全部命中，recall=100%。
   它不是约束，是刷分杠杆。
2. **N 太小**：人看 K 线能标的量级是 10~50。SE(score) 是在 n=423 上测出的 0.012。
   N=30 的标注集上的 recall 差异几乎全是噪声，却会以硬约束形式把搜索钉死在一小撮样本上。
3. **`tune-dagspec-to-match.js` 的安全部件会在放大时被丢掉**：它有专门的
   Phase 3「健全性 + 全宇宙影响复核」——「让这只命中」从来不是终点。
   把 N=1 放大到 N=30 而不同步放大那道复核闸，是拆掉安全部件之后再放大。

**但人在环本身是对的，只是位置不同**：

> **人的价值在生成侧（候选的语义来源），不在选择侧（哪个候选更好）。**
> 唯一无偏的裁判是 holdout 上的 score，而且只能被查询有限次。
> 2026-07-15 那份报告自己请求的「给我 2-3 个具体漏检 ticker + 日期做 replay」
> 正是生成侧用法——它从未被满足，方案就被实施并证伪了。

### 11.1 同一份人力，两种用法在统计上符号相反

§2.1 的门槛表给了一把可以给「人在环」定价的尺子。任何人在环环节，
只有两种方式兑现价值：**降低 K**，或**提高 lift**。

- **人当候选来源**：把候选从 1000 个砍到 5 个 ⟹ **门槛从 0.039 降到 0.017**。
  这是一次真实的、可量化的 0.022 分贡献，而且不引入任何刷分维度。
- **人当优化目标（recall 维度）**：多一维可调 ⟹ **候选数增加 ⟹ 门槛上升**，
  同时引入一个没有减基线保护的刷分杠杆。

**同一份人力，一种降门槛，一种抬门槛。这是我反对双目标的最终依据。**

### 11.2 人看 K 线的最佳落点是 2026 窗

若方案里有「人看 K 线确认形态对不对」这一环，它应该落在 **§4.2 那个从未参与优化的
2026 窗**上。在搜索窗（2024/2025）上看，人看到的是被优化过的样本，
人的「这确实是我要的走势」会被搜索结果诱导；在未参与优化的窗上看，
形态判断才是独立信息。**零成本，只是换个窗口截图。**

### 12.4 一个贯穿全队的盲区（我认为这是本轮最该被记住的发现）

`arch` 的候选生成器（读 gate 归因）、`hitl` 的人类通道（"这里该被识别却没有"）、
`mech` 的缓存用途清单（估 σ / 响应面 / wall-clock / 门槛校准）——**三条独立设计的通道，
全部只能产出「放松 / 新增」类候选，没有一条能产出「删除」。**

- gate 归因的输入是**失败记录**，节点存在时不产生"它不该存在"这类失败。
- 人会说"它漏了我要的股票"，**永远不会说"这个节点净贡献为零"**。
- `mech` 自己证明了缓存的服务半径包含**所有节点子集拓扑**（`bo_only` 就是 `keep=("bo",)`），
  即"删掉一个节点"的候选**零 detect 增量、完全免费**——但他给缓存列的 4 个用途里没有这一条。

**而 §5.5.2 的实测说，价值恰好在那个所有人都提不出来的方向上。**

> **补救成本几乎为零**：从 `dag_spec.py` 机械枚举
> 「每个 node 各删一次 / 每条 where 各删一次 / 每条 edge 各删一次」≈ 3+3+1 = **7 个候选**。
> 不需要 LLM、不需要人、不需要新 detect。**这是结构层的单因子消融，
> 与 `arch` §5 那个参数层单因子消融同构——而全队只对参数层做了。**

## 12.5 复现方式

全部实验只读 `outputs/path2_web/scans/20260725T032931.json`（2025 全年全宇宙扫描，
含 `bo_only` 与 `bottom_burst` 两个 pattern 的 events + matches + `forward_return`）
与 `datasets/pkls/*.pkl`（取日期索引与 OHLC）。**没有跑过一次全宇宙 eval。**
临时脚本按纪律已删除，方法如下，逐条可重建：

| 实验 | 方法 |
|---|---|
| **噪声地板**（§1）| 取 bbb 423 个 match 的 `forward_return` 与 bo_only 29502 个；`match.node_index['tb']` → events 里查 `start_idx` → 配 pkl 切片 `[win_start, win_end]` 的日期索引得买点日。iid bootstrap 与按周/按月整块 bootstrap 各 2000 次，比较 SE(lift) |
| **SE 常数根因**（§1.4）| 对比「从 bo_only 池随机抽 423 个」的 median SE 与「bbb 自己 423 个 bootstrap」的 median SE |
| **选择门槛**（§2.1）| null 配置 = 从 bo_only 池随机抽 n 个；套 `score = n/(n+200)·(median−基线)` 与硬门；每轮取 K 个候选的最大值，重复 400 轮取中位数；再乘 §1.4 的 1.77 |
| **两窗最差分**（§4.1）| 把 bo_only 池随机对半分成两"窗"各算基线；null 配置从两窗各抽 n/2，判据取 `min(score_A, score_B)`；与单窗同总样本量对比 |
| **数据覆盖**（§4.2）| 随机抽 600 只 pkl，数各年 >200 交易日的比例 |
| **入场算术效应**（§5.5）| 对 bo_only 全部 bo 事件，买点改为「bo 后第 k 天收盘」与「bo 后 k 天内最低收盘那天」，重算同一 label |
| **配对分解**（§5.5.1）| 对 bbb 每个 match，用 `tb.anchor_bo_id` 查回锚点 bo 的 `start_idx`；同一批 setup 上比较「tb 确认日买」与「锚点 bo 当日买」 |
| **burst_no_tb**（§5.5.2）| 取 bottom_burst 的**全部** burst 事件（不只是进 match 的），按 `params_snapshot.burst` 的三个阈值过滤，取 `child_refs.members[-1]` 的 bo 的 `start_idx` 作买点，按 symbol 内 index 去重 |

label 一律用 confirm 口径：`max(high[t+1..t+20]) / close[t] − 1`，单日、与窗宽无关。
有效性 = 买点日 ∈ `[scan.start_date, scan.end_date)`。

## 13. 局限（本审查自身的）

- σ 是在**一个**配置（定案配置 2025 窗）上测的。不同配置的 label 分布形状不同，
  σ 会浮动。按 √n 缩放是一阶近似。1.77 这个折算比例同样只测于这一个配置。
- **null 模型是「随机抽 bo_only 子集」，但真实配置的买点不是 bo_only 的子集**——
  bbb 买在 tb 确认日、bo_only 买在突破日，是两组不同日期的观测。
  所以 null 模型捕捉的是 max-of-K 的**结构**，绝对水平靠 1.77 折算到真实配置的离散度上。
  这个组合是合理的，但不是严格的。
- **我的所有数字只处理抽样噪声，完全没有处理「算术效应」**：评分标准 §9 自己指出
  lift 里有一部分来自"买得更低"（tb 买在回踩低位、bo_only 买在突破高位，分母更小）。
  那是**系统性偏移不是噪声**，所以不影响选择门槛，但意味着 §4.1 那个 honest ≈ 0.045
  里仍有一部分是入场时机而非选股能力。**要拆开它需要另一个对照（同样买在回踩位的平凡基线），
  本轮没做，建议列入后续。**
- max-of-K 的 iid 假设给出的是**下界**：自适应采样（optuna/TPE）与"看着结果调下一步"
  的人工搜索都会超过它。我没有量化这个超出量。
- 「K_eff << K（参数） / K_eff ≈ K（结构）」这条区分是**论证**，不是实测。
  要实测需要跑多个结构候选看它们的样本重叠度，本轮未跑。
- §5 的 LLM 证据是 n=1。它足以说明"没有目标函数在环会翻车"，
  **不足以**给 LLM 生成 detector 候选的能力定上限。
- 我没有验证 `tune-pattern-strength` 自带的 `eval_skeleton.py` 与定案那轮真正跑出
  0.0719 的脚本（在 `$CLAUDE_JOB_DIR/tmp/`，未入仓库）是否为同一份。
  已请 biz 核实——这关系到「复用不要重写」这句话有没有实测背书。
