# path2_web

path2 的调试可视化工具：把分析结果投影成 JSON、再渲染成可交互的界面。这里是界面自己的词汇——事件在图上怎么摆、显示到哪一档、参数怎么试、漏检从哪查。

覆盖 `path2_web/`（FastAPI 后端）与 `path2_web_ui/`（Vue3 前端）。这一层不含任何走势语义：界面不知道 bo 和 burst 各是什么，只按 node 分轨、按 where 分列。核心词（event / node / match / where）见 [path2](../path2/CONTEXT.md)。

## Language

### 数据与流程

**扫描 / scan**：
对全宇宙股票逐只跑一遍选定的 app，把命中与统计落盘成一个结果文件。

**临时计算**：
用当前 yaml 参数即时重算一只选中的股票，不落盘、不进扫描结果，专给「改完参数立刻看效果」的调参循环用。

**Working Copy**：
某个 app 参数的可编辑副本；改副本的内容与让图表用不用副本，是两件独立的事。

**锚 pattern / active pattern**：
左栏列表按哪个 app 排序筛股叫锚 pattern，右侧图表当前渲染哪个 app 叫 active pattern；两者正交，点单元格只切股、不切 active pattern。

### 显示深度

**显示档位 / level**：
全局的显示深度旋钮，三档从浅到深依次是 detected、qualified、matched。

**detected / qualified / matched**：
一个事件的三档可追溯深度，依次收窄——被检测出来、通过了所在 node 的全部 where、进了某一次 match。

### 图上的几何

**主图**：
K 线蜡烛所在的图；声明为钉价格轴的点事件画在这里（如突破三角与它突破的那些峰）。

**副图**：
事件区，横轴与主图对齐；主图之外的事件都在这里，纵向没有价格含义、只表示「哪根 K 线上发生了什么」。

**band**：
副图里的一条轨，一个 node 一条。

**lane**：
一条 band 内部为了不让重叠事件互相压住而分出的泳道。

**bracket**：
一次 match 的时间跨度在图上的样子——一条带圈号的横带，圈号是它在本图内的编号。

### 面板

**拓扑面板**：
pattern 的 DAG 图，同时是 node 的控制器：点节点切显隐，双击拉这个 node 的诊断。

**诊断侧栏**：
右侧的漏斗总览与逐次命中留痕：每个 node 一行三档计数，展开看候选逐条卡在哪。

**漏检入口**：
回答「为什么这个事件或这条关系没被匹配上」的几个固定查询口径——按时段查失败的 attempt、按 node 看 miss 分布、指定两个事件问它们为什么没连上。
