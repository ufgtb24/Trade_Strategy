票 03 独立审查：需求一侧（code-review skill，固定点 cb6dbb9，审查时 HEAD d8910fa）

总体看，这张票要求的东西都做到了，没有发现缺漏。正确性问题只有一个：空槽和成员对"现在跨过样本日的旧成员"判法不一致。另有一条规则是 spec 没写的。

我用一个临时脚本把例子文件里全部 19 个例子跑过参照实现，全部通过。用 uv 跑完整 pytest 时卡在建环境、被终止了，所以 pytest 本身没有跑成。改动只有 4 个文件，没碰前端，也没碰 `api.py`；改动文件里也没有引用 `docs/research`。

**(a) 缺漏或做了一半**
- 票面列的 8 种情形都有例子，测试从 JSON 读答案，例子文件的位置也写进了模块说明。
- 一个留给下游的接口问题。Inherited Direction 写的是：「`GAP`、`NEAR` … 只在一处设定、各处去读那一处」。现在这两个数只定在 Python 模块里，前端读不到。票 06 负责做成"只在一处设定"，到时这两个数大概得挪到配置里，或由后端提供；模块说明里「别处都读这两个常数」那句也要跟着改。这不算 03 的缺陷。

**(b) 没要求的行为**
- 空槽多了一条排除：同一张图、同一 pattern 里，别的样本的成员不留空槽。spec 5.5 只写了「样本范围起点往前 `NEAR` 根以内、名字在这个 pattern 里用过、却没收进来的框」。这条来自原型，有道理，但应该列给用户过目。
- 测试 `test_session_reads_replayed_state_as_is` 的答案直接写在测试代码里，不在共用的例子文件中，前端不会核对这个例子。它不算抄答案，不过和「例子文件是唯一的事实来源」有点擦边。

**(c) 看似做了、但做错了**
- `empty_slots` 直接用存下的成员，`sample_members` 却会滤掉现在已经跨过样本日的成员。两者对同一份状态给出的答案不一样。
  - 复现：样本日 100，存下的成员是 x（10–105）和 z（90–95），y（20–30）和 x 同名。`sample_members` 只给出 z。`empty_slots` 却仍把 x 当成员：x 不出 `crosses_sample_date` 槽；范围起点被 x 拉到 10，于是本不该出现的 y 被报成 `unclaimed`。
  - 违背的是 spec 5.5：「跨过样本日的框…收不进成员」，以及「如果是因为同名框太长、跨过了样本日才收不进，悬停写明这一点」。例子 `frozen_sample_keeps_its_members` 自己也写了这种框「不再算成员」。
  - 改法：在 `empty_slots` 里，先按"框还在图上、终点不晚于样本日"过滤一遍存下的成员。

**手算核对的例子（都和文件答案一致）**
- `gap_chain_until_no_more`：边界从 110 起往前推：104≥90 收进，边界到 100；80=80 收进，到 70；50=50 收进，到 40；19<20 停下。
- `contained_and_attached_join`：先收 b1，边界到 60；b2、b3、b4 一起收进，边界到 50；b5 的 15<30，不收。成员顺序是 b3、b1、b2、b4。
- `current_sample_grows_with_new_boxes`：推断出 {b1, b2, b5, b8}，只取新画的得到 {b5, b8}，再手动拿掉 b8，结果是 b1、b5。
- `slot_reasons`：范围起点 60，往前 40 根到 20；b3 终点正好 20 算画了没收，b4 的 19 差一根；b5 原因是跨过样本日；排序正确。
- `tree_with_detach_and_attach`：b5 照默认归 b1，b4 归更短的 b2。

另外，模块说明说 spec 第 3 步（带上被成员包住的框、`attach` 到成员上的框）不用单独做，这个说法我核过，成立：这样的框和某个成员交叠，第 2 步已经收进来了；跨过样本日的那种照样收不进。
