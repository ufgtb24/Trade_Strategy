# 用看图标注做出 path2 pattern

## Destination

用户能通过看图标注得到较好的 path2 pattern：在没碰过的数据（2026 年起）上胜过同日普通买入。本地图终于一份规格加拆好的开发任务，覆盖结构化标注、app 盲看清单、串起「图 → 代码」循环的技能、现有技能改成以标注为输入、没碰过的数据上的检查与数据墙、两台机器的同步、「至少 k 条成立」组合子与复合事件写法约定、旧看图工作流代码的搬与拆；用这套工具做出第一个 pattern、写具体的 detector 都不在图上。

## Notes

- 总原则（2026-10-23 用户定）：结构化标注今后是构建 path2 pattern 的唯一方式，一切为结构化标注服务。各票拿不准时，按「怎样让标注直接变成 pattern、让 pattern 直接对回标注」来取舍。
  - 语言仍然需要，但只作为挂在图上某个位置的附注：新概念第一次出现时的一句话、盲看点「不是」的理由、pattern 想抓什么的一句话。脱离图的语言不能直接改 pattern：技能要反问「在哪几张图上看到的」，转去标注或指出已有标注。防的是：改动没有对应的例子，改完无法检验，以后的改动把它改坏也查不出。只调参数取值（tune-gates-v3）不受影响。
- 起点：`docs/research/2026-10-23_annotation-path2-direction/方向讨论.md`（下称「方向文档」），2026-10-20～10-23 与用户谈定的结论全在里面，各票按它来，不重新论证。要点：
  - 训练段不记账、随便看；2026 年以后的数据永远不给看；只有没碰过的数据上的检查要记次数（方向文档第 2 节）。
  - 七步流程：找图 → 标注 → 写 app → 拿 app 对标注 → 盲看 app 抓出来的图 → 调参数 → 最后检查；只有最后一步判输赢（第 3 节）。
  - 后续走势只在盲看那一步先藏后露（第 4 节）。
  - 一个 node 包容多种特征用复合事件，path2 现有机制够用（第 7 节）。
  - 结构化标注：用 path2 的事件来标，标注和显示一一对应，一次标注可以有多个 pattern，先看特征和先定目标分阶段配合，合不合并看骨架（第 8 节）。
- 画图时已定（方向文档第 13 节）："较好"沿用 tune-gates-v3 的「比同日普通买入多出的部分」；地图到规格加开发任务为止；组合子与写法约定在图内、具体 detector 不在；旧代码在图内，先搭新的再拆旧的。另有：盲看从整个股票池随机抓、新写技能串循环、新特征放在要用的地方量且看不出先留着（第 3 节）。
- 旧 effort「建一套找优秀选股 pattern 的流程」已归档在 `.scratch-archive/selection-pattern/`；它的评估纪律类结论（分辨力、幸存者偏差、股票池口径含 SPAC 排除、同日对照怎么配）沿用，见那份地图的 Decisions so far。
- 用词以 `path2/GLOSSARY.md`（框架与走势）和 `path2_web/GLOSSARY.md`（界面）为准，对用户说话时带上「文件:行号」出处；查词先 grep 再只读那一段。
- 每张讨论票照例调 grilling 和 domain-modeling 两个技能；研究票由子代理调 research 技能，结论写进 `research/<NN>-<slug>.md`；原型票调 prototype 技能，代码放 `prototypes/`。票的规矩见 `docs/agents/decision-tickets.md`（认领、先和用户对倾向、结论经用户批准后才动地图和别的票）。
- 对用户：用户是方向的决策者，不是参数的决定者；阈值类数值先给默认值并标「待验证」。提问用 AskUserQuestion，推荐项放第一个并标「(推荐)」；用户在问「为什么」或要求澄清时只回答，不紧接着挂选择题。说话用白话、不打比方。用户色盲，界面不靠色相区分。
- 用户有两台机器 pc 和 upc，现在的工作分支是 `annotation-path2`。
