# 标注的一轮

用户在标注工具里标样本、画框、写定义，在 `compare` 里对 app 买错的地方写反馈；会话把这些翻成 app，每改一版交一份改版报告。**方向归用户，翻译归会话**：用户不审批拓扑、detector 选型和门槛，他靠 `compare` 和下一轮的反馈验收；会话只把「要你定」的那几条拿去问。

本 skill 管一轮的顺序、每步交什么、怎么对用户说、怎么记账。一句 note 该翻成什么条件、几个 issue 是不是同一件事、一条该归清单的哪一段，是你的判断——依据只有四样：用户的 pattern 定义与特征定义、mapping 里写给用户看的说明、图上 app 实际认出的东西、K 线。

**标注是改 pattern 的唯一入口。** 用户脱离图直接说要改（「加一条：成交量要放大」），而标注里找不到对应的样本、框或反馈时，先请他指出是在哪几张图上看到的、在页面上标出来，再进一轮。只调参数取值不受这条限制（见「转给别的 skill」）。

本 skill 在主会话里跑（要向用户出选择题）。命令都从仓库根运行。

## 红线

1. **先定格，再碰 app。** 改 app 的任何文件之前，本轮的 round 文件必须已经存在；第 1 步做完之前不改任何 `.py`，哪怕它有毛病。旧版 app 的买点只存在这个文件里，改了 app 就再也算不出来。唯一的例外：app 导入不了或一跑就崩、定格不了，用户让你来修——只把它修到能导入、不再报错，不改任何判定条件（where、门槛、detector 的判据、边都不动），修完再定格。修完自查：`git diff path2_apps/<app>` 里不应出现 where 名单、`params.yaml` 的数值、边的改动。报错恰好出在某条 where、门槛或判据里（如某条 where 读了事件上没有的字段、`params.yaml` 多了没声明的键），不碰它就修不好时，**不修**：告诉用户这一轮拿不到改之前的对照，由他定——他先自己把 app 恢复到能跑的那一版，还是这一轮不要对照（那就照他的意思修到能跑再定格，并在第 3 步清单的第一行写明「这一轮没有改之前的对照」）。
2. **一轮只定格一次。** 有没走完的一轮就接着做（第 0 步），不重新定格：重新定格会把这一轮用户改的标注从报告里漏掉。
3. **旧版买点只从 round 文件取。** 不用 `git stash`、不切分支回旧版——主目录里用户没提交的改动会被一起收走。round 文件丢了，这一版就没有对照，下一轮从头来。
4. **标注只读。** 读标注只经现成函数（`start_round` / `round_digest` / `revision_report` 内部都走 `read_annotations`）；不打开、不写 `annotations/` 下的任何文件。要改标注的事（定义文字、样本、框）一律请用户自己在页面上做。
5. **行情只到 2025-12-31。** 只经现成函数读（它们读训练段副本 `datasets/pkls_until_20251231`）；不读 `datasets/pkls`。任何现成函数带行情目录参数而缺省是完整行情的，显式传训练段副本目录。
6. **不动用户开着的服务。** 不运行 `scripts/path2/run_path2_web.py`，不杀端口上的进程。用户的后端随 `.py` 改动自动重启，改完请他刷新页面即可。
7. **不拧门槛让记号变常色。** 只差门槛的留给调参（见「转给别的 skill」）。由 issue 推出的新条件，初始门槛按用户那句话的字面意思取，不按被挑刺那几天的实测值取。
8. **不提交。** 改动留在工作区，用户看过再说。

## 一轮的顺序

记 `<P>` = 标注里的 pattern 名，`<app>` = 第 0 步输出里写了这个 pattern 的那个 app，`<R>` = 本轮的 round 文件 `outputs/annotation_rounds/<P>/<YYYY-MM-DD>-<n>.json`（日期取今天，`n` 是今天第几轮，从 1 起）。同名的 `<R 去掉 .json>.plan.md`、`.report.md` 是这一轮的处理清单和改版报告。

### 0. 认对象，判断新开还是续跑

```bash
uv run python .claude/skills/annotation-round/scripts/round_state.py
```

它打印：标注里的 pattern 和各自的样本、反馈条数；每个 app 的 mapping 对哪个 pattern、有没有问题、会话段里有没有快照、`conditions` 与 `tags` 各几条；没注册上的 app；每个 pattern 各轮的文件。按下面的次序对，停在第一条对得上的：

1. 用户没点名、标注里又不止一个 pattern → 问一句是哪个；只有一个就不问。
2. 这个 pattern 有一轮标着「没走完」（有 round 文件、没有同名 `.report.md`）→ **续跑**那一轮：不做第 1 步，照 [references/resume.md](references/resume.md) 判断从哪一步接着做。不止一轮标着 → 告诉用户，停下（只要还有没走完的，定格命令就不让开新的一轮）。
3. 输出里有一行「注意: app … 的 mapping.yaml 读不出它对哪个 pattern」→ 那个文件写坏了（多半是手写会话段时弄坏了格式，或 `pattern` 那一行丢了），它对的 pattern 这时看不出来。**先把这个 `mapping.yaml` 修到读得出**（只动它；它不是 `.py`，修它不改变 app 认什么），重跑本命令，再从头对。没修好之前不往下，更不能照「还没有 app」走。
4. 输出里有一行「磁盘上有 mapping、app 却没注册上」，写的正是这个 pattern，或写着「读不出它写的 pattern」→ app 在，只是没注册上，**不是「还没有 app」**。不定格（旧版买点算不出来），也不自己动手修：把没注册上的原因原样告诉用户（「没注册上的 app」那一行里没有它的原因时，就告诉他这个目录的 app 没被认出来），停下等他处理。他回「那你修」时，照红线 1 的例外做——只修到能导入，不改判定条件；修完重跑本命令、再定格，并在第 3 步清单的第一行说明「这一轮的对照是修过的那一版」。
5. 「mapping 问题」写着这个 pattern 同时被几个 app 的 mapping 写了 → 告诉用户，由他定留哪个，停下。
6. 「会话段问题」不是 None → 定格前必须修好，只动 `mapping.yaml` 的 `session` 段，修完重跑本命令。
7. 这个 pattern 那一行写着「还没有跑过任何一轮」，后面却带一句「会话段里已经有快照」→ 先问用户「上一次我有没有把改版报告交给你」（换过工作目录、清过 `outputs` 都会这样）。交过就照常往下；没交过，那一轮的对照已经丢了（红线 3），照新开一轮走，并在第 3 步清单的第一行说明「上一次改到一半的那些，这次不能单独报」。输出末尾若有「各轮目录里有 <旧名字>」、正是这个 pattern 改名前的名字、其下有没走完的一轮，就不用问：那一轮是按旧名字记的，接不上了，按「没交过」办。
8. 没有任何 mapping 写这个 pattern，但某个 app 那一行后面带着「标注里没有叫这个名字的 pattern」→ 先问用户「这个 pattern 是不是改过名字，原来叫 <那个名字>」，不当成还没有 app。是 → 把那个 `mapping.yaml` 里 `pattern` 那一行改成现在的名字（只动这一行），重跑本命令再从头对；不是 → 往下。
9. 没有任何 mapping 写这个 pattern，而「各 pattern 的标注」里它的反馈不是 0 → 它一定有过 app（反馈只能在 `compare` 里对着 app 的买点写），不当成还没有 app：告诉用户找不到它的 app（`mapping.yaml` 可能被删了，app 目录可能挪走了），停下。
10. 已注册的每个 app 的 mapping 都读得出，其中没有一个写这个 pattern，「磁盘上有 mapping」那几行里也没有，上面几条都对不上 → 还没有 app，照下面「还没有 app 时」的表走。
11. 其余 → 新开一轮，做第 1 步。

另记两件事留到后面，都不拦定格：「mapping 问题」里别的内容（特征或说明指向了不存在的 node / where）留到第 5 步和 app 一起修；冲突、越界不是 0，或数据指纹不一致，写进第 3 步清单的第一行。

### 1. 定格

```bash
uv run python -c "from path2_web.annotation.revision import start_round; start_round('<P>', '<R>')"
```

它用改之前的 app 把这个 pattern 有样本或反馈的股票全跑一遍、存进 `<R>`，并打印一段 `session: {snapshot: ...}`。**立刻**把这段写进 `path2_apps/<app>/mapping.yaml`：已有 `session` 就只替换其中的 `snapshot`（`conditions`、`tags` 原样留着），没有就整段加在文件末尾。写之前先存一份原样，写完比一下：

```bash
cp --update=none path2_apps/<app>/mapping.yaml <R 去掉 .json>.mapping-before.yaml      # 写之前
diff <R 去掉 .json>.mapping-before.yaml path2_apps/<app>/mapping.yaml       # 写之后
```

`diff` 的输出里只应有 `snapshot` 那一段的行（原来没有会话段时，是末尾新增的整段）。出现别的行，就是写快照时碰了 `conditions`、`tags` 或文件别处——条数对得上、内容却变了，后面哪一步都发现不了——照存下的那份改回。

命令报错时，一律**不重试、不换文件名**：

| 报错 | 怎么办 |
|---|---|
| round 文件已存在 | 这一轮已经定格过：回第 0 步，按续跑走 |
| 这个 pattern 还有没走完的一轮 | 回第 0 步，按续跑接着那一轮做；不换目录、不换文件名去绕 |
| 没有哪个已注册 app 的 mapping 写这个 pattern（没传 `no_app=True`） | **不是加上 `no_app=True` 重试**：回第 0 步从头逐条对，对到「还没有 app」那一条才传 |
| 这个 pattern 已有 app，不要传 `no_app=True` | 你把有 app 的当成了没有：去掉它，回第 0 步重对一遍再定格 |
| 标注里没有这个 pattern 的任何东西 | 名字敲错了：对着第 0 步 `patterns` 那一行核对 pattern 名 |
| 会话段写坏了 | 回第 0 步第 6 条修 `session` 段，再定格 |
| 某个 app 的 `mapping.yaml` 读不出 pattern | 回第 0 步第 3 条，把那个文件修到读得出，再定格 |
| 某个 app 没注册上，而它的 mapping 写的正是这个 pattern（或读不出） | 回第 0 步第 4 条：告诉用户，停下 |
| 这个 pattern 被几个 app 的 mapping 写了 | 告诉用户，由他定留哪个，停下 |
| 别的异常（旧版 app 在某只股票上跑崩。读不到行情不算，那只会被记成「没比」） | 不自己改 app。把报错原样告诉用户（看得出是哪只股票就带上），停下。他回「那你修」时照红线 1 的例外做：只修到不再报错，不改判定条件；修完再定格，并在第 3 步清单的第一行说明「这一轮的对照是修过的那一版」 |

做完的标志：

```bash
uv run python .claude/skills/annotation-round/scripts/round_state.py <R>
```

「快照已写进会话段: True」，并且上面的 `diff` 只有 `snapshot` 那一段。此后用户再改的标注归下一轮。

### 2. 读齐输入

```bash
uv run python -c "from path2_web.annotation.revision import round_digest; print(round_digest('<P>', '<R>'))"
```

它是给你读的，不原样贴给用户。它按定格时的标注，一次给出：定义（pattern 与特征的原文、各特征对到哪个 node、没对到的）、mapping 的说明、账本、上一轮以来的变化、全部 issue（各处在**改之前**的 app 下还买不买）、全部样本（和 app 相反的排前）。固定在定格之后、改 app 之前调；改完 app 再调，状态不会变。摘要和报告里写的「第一轮」只表示没有上一轮的定格，和有没有 app 无关。

再读 app 现状：`path2_apps/<app>/dag_spec.py`（开头的说明与全部 where）、`params.yaml`。

然后**逐处看图上实际认出了什么**——每个 issue 的每一处、每张和 app 相反的样本：

```bash
uv run python .claude/skills/annotation-round/scripts/look.py <app> <股票> <起> <止>
```

它用现在的 app 跑这只股票，列出这段日期里每个买点的各段起止、每条 where 的实测值与门槛，没成买点的候选卡在哪条 where，以及那几天的 K 线（加 `--fields` 另列事件上现成的全部字段）。issue 的每一处用它标的那段日期；相反的样本用样本日前后几天。候选那张表是空的（连候选都没切出来），或某一行 where 全过却没买，才转 `diagnose-event`。

做完的标志：摘要里每个 issue、每张相反的样本、每个没对到 node 的特征、每条变化，你都能说出「用户的话是什么、定义怎么说、app 现在怎么认的」。只读了 note 没看图的不算。

### 3. 出处理清单

**先读 [references/checklist.md](references/checklist.md)**（三段各放什么、一条反馈怎样才算改好、每条必须交代什么、给用户看的格式）。

反馈的 issue、和 app 相反的样本、还没对到 node 的特征、上一轮以来必须问的变化，放进**同一份清单**，按去向分三段发给用户：「一、我这一版直接改」「二、要你定」「三、这一轮不改」。

**清单这条消息必须以一个工具调用结尾**：有题就紧跟出题（第 4 步），没有题就紧跟写 `.plan.md`（第 4 步末尾）。不能以清单收尾——会话中途发一条不带调用的消息，这一回合就结束了。用户对第一、三段有异议，随时可以说。

做完的标志：摘要里的每个 issue、每张相反的样本、每个没对到 node 的特征都落在某一段里，没有漏的。

三段都为空（没有 issue、没有相反的样本、没有新特征、没有要问的变化）：不发清单、不改 app，直接照第 7 步出报告，并照第 8 步末尾把它存成 `.report.md`（没有账要记）——不存的话，下次会把它当成没走完的一轮。「这一轮没有要处理的」写在第 9 步收尾消息的第一句，不单独发；原本要写在清单第一行的话（冲突、越界、指纹不一致，对照是修过的那一版等）也并进那条收尾消息。

### 4. 出题

只对第二段，用 AskUserQuestion，问法与固定选项见 [references/checklist.md](references/checklist.md)「出题」；第二段为空就不出题。

把清单全文连同每题的选择写进 `<R 去掉 .json>.plan.md`：有题的，题答完就写；没有题的，它就是清单那条消息结尾的调用。两种情况下，`.plan.md` 都必须在第 5 步动手之前存在——第 5、7 步和续跑都照它。

### 5. 改 mapping 和 app

改第一段全部，加第二段里用户选了「写进定义」或同意的。**先读 [references/writing-app.md](references/writing-app.md)**（考题怎么批、加一条条件要一起动哪几处、声明层的契约与会静默出错的写法），然后自己改完，不逐层找用户确认。

- 新加、删掉或改名的 where，同一步里更新 `mapping.yaml` 的 `notes`（给新条件写上用户原话）和 `dag_spec.py` 开头的对照表。第 0 步记下的 mapping 问题也在这一步修。
- 新特征对到 node：在 `mapping.yaml` 的 `features` 加一行（键是特征编号）。
- 改了声明或参数，同一步里改 `tests/path2_apps/<app>/` 中钉住它们的测试，新条件补一条测试。
- 其余情形见下面「转给别的 skill」。

### 6. 自查

```bash
uv run pytest tests/path2_apps/<app> -q
```

再重跑第 0 步的命令（`round_state.py`），并在一只有正样本的股票上跑一次 `look.py`（字段名、子段声明写错，只有在有事件的股票上才报得出来）。四项都满足才往下：测试通过；这个 app 不在「没注册上的 app」里，「mapping 问题」「会话段问题」都是 None；`look.py` 跑得通；摘要里用到的每个特征要么在 `features` 里有一行，要么已在清单里明说这一轮还没对上（重跑第 2 步的摘要，看「还没对到 node 的特征」一栏还剩哪些——这一栏按现在的 mapping 出）。其余股票由第 7 步的命令全部跑到。

### 7. 改版报告

```bash
uv run python -c "from path2_web.annotation.revision import revision_report; print(revision_report('<P>', '<R>'))"
```

它用现在的 app 重跑这一轮涉及的全部股票（app 出错会原样抛出——抛了回第 5 步修），和 `<R>` 求差。报告开头若有「mapping.yaml 里的定格不是这一轮开头那份」或「会话段读不到」，那是给你的提醒：先照做修好（把 `<R>` 里的快照写进会话段 / 修 `session` 段），重出报告；交给用户的那份里不应再有这两句。然后：

1. 报告里每条 `lost` 留了一行「待填」，逐条填上是改好了还是认法变了（如改了某段的长度，所有起点平移）。
2. 在报告后面补一段，条目与 `.plan.md` 的清单一一对应：

   ```
   ## 这一版按清单做了什么
   1. 「<理由原话>」：<改了什么，一句白话>。3 处里现在还买 1 处（链接）——<为什么还买 / 下一步>
   2. 正样本 AAPL 2024-03-08：现在买到了。
   4. 「<理由原话>」：你选了不写进定义，没改。
   5. 「<理由原话>」：这一轮没改——当天看不出。
   ```

3. 样本结论被这一版改坏的（报告「变坏」一栏：原来一致、现在相反）逐张点名，并说打算怎么办；不能悄悄留着。
4. 这时先不发给用户、也不存文件：紧接着做第 8 步。报告留到第 9 步，和交还的话放在同一条收尾消息里（中途单发一条不带工具调用的消息，这一回合就结束了，账会漏记）。

「改好了」只按报告里的新旧对照说，不凭单独一个数。这份报告只覆盖标注过的股票、不带后续收益，所以它说明的是「你指出的地方和你的样本现在怎样」，不说明这一版赚不赚钱。

### 8. 记账

**先读 [references/ledger.md](references/ledger.md)**，照它把这一轮记进 `mapping.yaml` 的会话段：每条条件一行（`state` 以 `from_definition` / `unmeasured` / `declined` / `for_tuning` / `not_worth` 之一开头）；改完还在买的每一处反馈一个原因标签；`lost` 的，你交代为「认法变了」、原来的毛病还在的按原因挂，交代为「改好了」的不挂；已经不买的去掉标签。

做完的标志：`.plan.md` 里每一条都能在账本里找到去处（一行条件，或各处的标签），且 `round_state.py <R>` 打印「快照已写进会话段: True」，且「mapping 问题」「会话段问题」都是 None（三样缺一不可：整份文件被写坏时「会话段问题」什么也不报）。

两样都满足后，把第 7 步那份报告（连同你补的那一段）整份存成 `<R 去掉 .json>.report.md`。它是「这一轮走完了」的唯一标记，所以放在最后才存：存早了，记账之前一中断，下次就认不出这一轮还差记账。

### 9. 交还用户

一条收尾消息，依次是：几句不带术语的话讲「这一版改了什么、这份报告说明什么、不说明什么」；报告全文（函数出的正文原样给，不改写、不删里面的编号和 node 名）；然后告诉用户刷新页面，在 `compare` 里看这一版，以及等他做的事——把你建议的那句话贴进 pattern 定义（选了「写进定义」的）、过目报告里「范围外砍掉的买点」、觉得不该砍的那天用 `point` 放一个正样本、新的毛病继续标反馈，下一轮再处理。不另起一套看图确认。

### 还没有 app 时

同一副骨架，差别只有：

| 步 | 还没有 app 时 |
|---|---|
| 1 | 定格命令带上 `no_app=True`：`start_round('<P>', '<R>', no_app=True)`（没有 app 可跑，round 文件里没有买点）。它是你对「真的还没有 app」的一次确认，不是遇到报错就加上的开关：只有第 0 步逐条对下来、停在「还没有 app」那一条时才传。打印的快照先留着，它也存在 `<R>` 里；没有 `mapping.yaml` 可比，不做 `diff`。这时「快照已写进会话段」是 False，属正常 |
| 2 | 摘要只有定义、样本；没有 issue、没有状态。逐张样本、逐个框看 K 线，认清每个特征在图上是什么：`look.py` 的 app 那一格写 `-`，不跑 app、只出 K 线——`uv run python .claude/skills/annotation-round/scripts/look.py - <股票> <起> <止> --before 30` |
| 3、4 | 清单只有「照标注怎么做」的条目；只问方向题（两种读法会做出不同的 app 时），不问拓扑、选型、门槛 |
| 5 | 新建 `path2_apps/<app>/`（app 名自己起：英文短标签，它会直接显示在页面上）、它的测试和 `mapping.yaml`，并把第 1 步的快照写进会话段（之后「快照已写进会话段」应为 True） |
| 7 | 同一条命令：没有旧版可比，报告只列第一版 app 下各样本的结论；补的那一段照写 |
| 8 | 没有反馈可挂标签；`conditions` 可以为空；报告照样在这一步末尾存下 |

## 对用户怎么说

这一节只管**你自己写的话**（清单、题目、收尾的那几句）；`revision_report` 出的报告正文原样给用户，不照这张表改写。

只讲业务：哪只股票哪段日期、他写的话、你打算怎么处理、会带来什么。下面这些留在你这边，不出现在你写的话里：

| 内部的 | 对用户说 |
|---|---|
| round 文件、`.plan.md`、定格 | 「我先把你现在的标注和 app 的买点记了一份，改完好对比」 |
| 会话段、`conditions`、`state` 的五个开头词 | 「我记了一笔」，或直接说内容（「这条你同意新加，还没量过」） |
| 函数名、脚本名、第几步 | 不说 |
| 反馈编号、样本编号 | 用理由原话、「股票 + 日期」指代 |
| where 名、node 名 | 用它对到的用户的词；必须提英文名时带上用户的词 |

页面上看得见的固定词可以说，带上中文意思：`matched`（app 还在买）、`lost`（起点认不出了）、`for_tuning`（留给调参）等。项目词照 `path2/GLOSSARY.md`、`path2_web/GLOSSARY.md` 的规范词用，先 `grep -n` 查到再用，第一次出现时附 `文件:行号`。
