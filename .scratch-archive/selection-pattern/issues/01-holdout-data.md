# 没碰过的数据怎么分配：第一遍用哪段，以后每一遍用什么

Status: resolved

## Question

### Purpose

流程每跑一遍，都要拿没碰过的数据给候选一次诚实的判决；这张票决定第一遍用哪段、以后每一遍用什么、检验过的候选变多后门槛怎么随之调整，它也是所有读 pattern 成绩的实验必须绕开的边界。

### 要决定的事

2026-10-16 地图终点改为「建一套找优秀选股 pattern 的流程」，本票的问题从「最后检查用哪段」扩大为没碰过的数据怎么分配。

过去的研究已把 2021-10 至今的大部分数据看过多遍（bb 系调参、特征研究、tune-gates-v3 训练段 2024-01..2025-10 等），但对一个新走势来说，它自己的成绩还没被任何人看过。要决定：

1. **第一遍的验证段用哪类数据**：
   - 规格冻结之后才到来的新数据——最干净，但要等若干个月才攒够买点；
   - 现在就从历史里划一段，所有实验都不碰；
   - 两者组合：历史划一段先查，新数据到了再复查。
2. **其余时段怎么用**：2021-10..2023-12 能不能进训练或作预检、2022 年怎么处理、要不要补到 2018。
3. **用几次**：划给最后检查的数据，第一次没过、改了再查，还算不算没碰过。
4. **检验过的候选变多以后，门槛怎么跟着加严**（2026-10-16 新增）。
5. **以后每一遍拿上线后的新数据当裁判，要攒多久才够**（2026-10-16 新增）。

2026-10-07 补充（来自「幸存者偏差会把哪类 pattern 的成绩抬多高」）：底部类的幸存者偏差随买入日变早而变大，最近一段数据最干净；bb_v1 预留的 2022-08..2023-11 那段恰在偏差最大的年份，不宜拿来检查底部类。

2026-10-07 补充（来自「照这份数据的分辨力，判优标准和终点要不要调」）：

- 用户提的分法作为起点：2024-01..2025-12 训练、优化、挖掘，2026-01 至今验证。
- 验证段只用一次；验证段之后靠每日名单存档在新数据上接着核对。
- bb_v1 已废弃，两段预留窗不再单独保护。
- 看图也算读涨跌。用户最近一次扫描覆盖 2025-01..2026-06（含 2026 上半年），用户说 2026 年的图「没怎么看」。
- 2021-10..2023-12 能不能也进训练、2022 年怎么处理（见地图报告规矩），一并在这里定。

2026-10-07 补充（来自「能接哪些外部信息：从哪来、历史多长、会不会偷看未来、花多少」）：之前营收那轮研究的分年结果包含 2026 年，「营收增长好的更容易先涨」在 2026 年的表现已被看过一次；选中的方向若以营收为核心，验证段对它不算完全没碰过。

2026-10-07 补充：想法来源加入了「从数据里系统地挖」。挖会试很多条，最后检查那段数据是唯一可信的判决，必须在挖之前划定，挖数据的票排在这张票之后。

2026-10-16 补充（来自 agent team 研究「找 pattern 的流程该 agent 主导还是人主导」，`docs/research/2026-10-15_workflow-agent-vs-human-led/final_report.md` 第 1、5、6、8 节）：

- 新数据攒得多快，看规则在整份名单上每天命中多少，不看用户每周买的那一只：每天命中 1 个约 8 个月够看出方向领先 0.15，每天 4 个约 2 个月。会话早先说的「每周买一只、七个月攒 30 个买点」把两件事混在了一起，它只适用于检验「用户挑的那一只」这一层。
- 验证段不打开就会自己变长，打开时机有代价：现在约 150 个交易日（2026-01 到 2026-08 初，再往后的买点观察期还不完整），看出 0.15 约要 176 个互相独立的买点，每周只命中 1 个的规则只能看出约 0.36。打开前 agent 交核对单，说明现在开能看出多大、再等几个月能看出多大，由用户决定开不开（地图 Notes「流程的工作方式」）。
- 2021-10..2023-12 若当预检：挡得住「只在 2024～2025 行情里成立」的假货和命中少的规则上的运气假货，挡不住幸存者偏差带来的；反复拿它给很多候选把关，它就不再算没碰过，要按次数打折。
- 事先登记多个冻结候选、按个数打折地一起送验证，不同于「照这份数据的分辨力，判优标准和终点要不要调」第六节禁止的不打折挑最好的；用不用是方向选择，代价表见同一研究目录的 `constraints.md` 2.1。
- 验证段要物理隔离：研究只用截到 2025-12-31 的数据副本（地图 Notes「开工前提：护栏」第 1 条）。挡有意读取只能靠用户在 Claude Code 权限设置里禁止研究会话读全量数据目录，属用户操作域，由用户自行决定。
- 验证段对人和 agent 都只算「新 pattern 的成绩没被看过」：用户扫过 2026 上半年的图，记录和模型知识里也有 2026 年的信息。对纯价量形态影响大概不大，对带题材或外部信息的方向更大；对两边都干净的只有规格冻结之后才到来的新数据。

需要的事实（由会话自己查，不问用户）：要等多久才攒够买点，取「这份数据能分辨多大的选股优势」给出的门槛，再按现有 pattern 的买点密度估——只数买点，不读涨跌。

## Answer

干净优先，宁可短一些（2026-10-07 与用户确认的方向）：验证段只算确实没被任何研究和看图碰过的部分，短了靠以后的新数据补。

### 结论

数值都是先取的默认值，标「待验证」的由会话按已定方向推出，不交给用户定。

**1. 三段数据各管什么**

| 时段 | 用途 |
|---|---|
| 2024-01..2025-12 | 训练段：研究、看图、挖数据、调参、收紧，随便用 |
| 2021-10..2023-12 | 预检段：只做送验证前的一道否决检查，不参与挑选（见第 3 条） |
| 2026-01-01 起 | 验证段：第一遍的最后检查，只用一次（加严重验那一次除外，见第 4 条） |
| 规格冻结之后到来的新数据 | 以后每一遍的裁判（见第 6 条） |

- 以营收为核心的方向例外：营收那轮研究看过 2026 年的结果，这类方向的验证段不算没碰过，只能靠新数据判。防的是拿已经看过结果的数据给它判决。
- 2018 到 2021-10 之前的数据不补（用户 2026-10-16 选定），地图「范围」不变；以后想做跨年代检查再单独提。

**2. 验证段怎么守、什么时候开**

- 物理隔离：研究、看图、挖数据只用一份截到 2025-12-31 的数据副本，全量数据只在用户触发的那一次验证运行里用（地图 Notes「开工前提：护栏」第 1 条）。防的是现在挡住 2026 年的只是一个配置项，agent 有 shell，无意中就会读到。挡有意读取只能靠用户在 Claude Code 权限设置里禁止研究会话读全量数据目录，属用户操作域，由用户自行决定。
- 打开要双钥匙：agent 先交核对单，写明候选扣掉运气后剩下的领先、验证段现在有多少独立买点、现在开能看出多大的领先、再等几个月能看出多大；用户决定开不开。防的是开得太早：验证段不打开会自己变长，候选本来证实得了，却因为数据不够判不出，白白用掉唯一一次判决。

**3. 预检段：只当预检**（用户 2026-10-16 选定）

- 用法：候选在训练段过线、送验证之前，在预检段上看方向领先有没有翻号，翻了就不送。它只能否决、不能证明，过了预检不加分；不在它上面调参、收紧或比较候选。
- 默认判法（待验证）：预检段整段方向领先不为负；按地图报告规矩另报一份去掉 2022 年的版本，只报告不判。判法细则随护栏一起由「这套流程分哪几步、每一步怎么进、怎么退」定。
- 记账：每拿它给一个候选把关记一次；把关过的候选多了，留下来的也算是在它上面挑出来的，要按次数打折，打折办法与训练段用同一套（由「这套流程分哪几步、每一步怎么进、怎么退」定）。防的是反复使用之后它变成又一段训练数据。
- 它挡的是两类假货：只在 2024～2025 行情里成立的，以及命中少的规则碰上的运气。挡不住幸存者偏差带来的：越早的年份偏差越重，这类假货在预检段上反而更好看，只能靠验证段和新数据戳穿。防的是这两类假货不经检查就花掉一次验证。

**4. 验证没过怎么办**（2026-10-07 用户选定）

- 允许改一次再验，门槛加严：第一次要求方向领先超过偶然波动的 2 倍，第二次 2.5 倍（待验证）；改的时候只能看第一次的汇总数字，不翻验证段里的个股图。防的是在验证段上反复试，把它也用成训练数据。
- 第二次还没过：这个候选放弃，验证段到此用完，之后的候选只能等新数据判。

**5. 上线与复查**（2026-10-07 用户选定）

历史验证过了就上线，新数据接着盯；按事先定好的时间点复查（默认每半年一次，待验证），明显变差就停用。

**6. 以后每一遍用什么当裁判**

- 验证段用完之后，裁判只有规格冻结之后才到来的新数据，来源是每日名单存档。核对的是整份名单的全部命中，不是用户买的那一只，所以新数据攒得多快取决于规则每天命中多少。
- 几个候选一起判（用户 2026-10-16 选定）：验证段只送一个最强的；新数据阶段允许事先登记几个冻结候选，按个数打折一起判。总误报率固定在约 2% 时，一起判 3 个，每个需要的数据约是只判 1 个的 1.33 倍；5 个约 1.47 倍；10 个约 1.68 倍。候选必须在用来判它的那段新数据到来之前冻结并登记。防的是看过新数据之后再决定判谁。
- 门槛怎么随候选变多加严（默认，待验证）：每段数据（验证段、预检段、每一段新数据）各记一本账，写明在它上面判过哪些候选、各判几次。同一段上一起判的按个数打折；同一个候选在同一段上重判，按第 4 条的加严重验处理。
- 判决时点事先定好（默认，待验证）：登记时按下面的换算算出攒够所需买点的日期，到点只判一次；中途只看是否明显变差（用于停用），不因为领先提前过线就宣布通过。防的是边攒边看、一碰到线就宣布过线，这样误报会远多于 2%。
- 要攒多久的换算：看出方向领先 L，约需（2 ÷ L）² 个互相独立的买点，加严时把 2 换成 2.5。以看出 0.15 为例约需 176 个：规则每天命中 1 个独立买点约 8 个月，2 个约 4 个月，4 个约 2 个月，每周 1 个约 42 个月。具体天数要等候选的命中频率定下来才算得出，命中多少又连着「候选名单的规格」里「命中少还是命中多」那道方向题。

### 留待实施阶段验证

**偶然波动的换算要按配套买卖规则重算。** 上面所有「要多少独立买点」的数字，都来自假 pattern 模拟（「这份数据能分辨多大的选股优势」第 3 节）：观察期 40 个交易日、线距 5、全部买点等权，独立买点按买点数的 0.7～1 倍算（只适用于分散长相）。

- 验什么：配套买卖规则和观察期定下后，按新规则重做一遍假 pattern 模拟，重算偶然波动和看出所需的独立买点数。
- 何时触发：第一遍选中方向的配套买卖规则冻结时；之后每换一次买卖规则或观察期就重算一次。
- 怎么判：重算值替换上面的默认值，核对单和新数据的判决时点都按重算值来；扎堆长相的候选按命中的不同股票数另算。
- 验证前能做什么：训练段内圈、预检都照常进行；验证段不得在重算之前打开。
- 重算后怎么办：如果按重算值，验证段看不出候选声称的领先，就按第 2 条推迟打开，或直接改走新数据；打开时机回到第 2 条重新估。

### 访谈记录

- **验证段起点：2026-01-01**。用户的扫描盖到过 2026 年上半年，但用户说那段的图「没怎么看」，这一点记入档案。以营收为核心的方向例外：营收那轮研究看过 2026 年的结果，这类方向只能靠新数据验证。
- **验证没过：允许改一次再验，但门槛加严**。这是用户的选择，不是会话推荐的那项。会话给的默认值（待验证）：

  - 第二次的方向领先要超过偶然波动的 2.5 倍，第一次是 2 倍；
  - 改的时候只能看第一次的汇总数字，不翻验证段里的个股图。
