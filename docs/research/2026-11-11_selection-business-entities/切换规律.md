## 键（2026-11-12 用户定）

**换键（2026-11-12，用户定）**：同一天那根轴的键从 Shift+← / → 改成 ↑ / ↓，和 ← / → 对偶；左侧列表切股票从 ↑ / ↓ 改成 PageUp / PageDown（按一下换一只）。文中讲新设计的地方已统一写成 ↑ / ↓、键帽 `↑/↓`；讲现在实现的地方（「现在：…」各行）保留 Shift+← / → 原样。

- 为什么能换：上一轮否掉上下键的唯一理由是漏按 Shift 会切股票、选中全丢；股票挪到 PageUp / PageDown 后这个风险没有了。↑ / ↓ 目前只有左侧股票列表在用（`path2_web_ui/src/components/SidebarResultList.vue` 的 `onArrowKey`），PageUp / PageDown 没有地方用；走动键的判定集中在 `path2_web_ui/src/components/walkKey.ts`；在输入框里打字时走动键本来就不接。
- 代价：切股票的手感要重新习惯；图上同一天的几次 hit 是并成一格画的，「上下」只是概念上的方向；什么都没选时 ↑ / ↓ 不再有作用；规格 1.14 写的是 Shift+← / →，实施前一并改。
- 会话默认（待验证）：↓ = 进去（落第 1 个）或换到下一个，↑ = 上一个（进去时落最后一个）；↑ / ↓ 被接住时拦掉浏览器的滚动；顶栏股票输入框自己的 ↑ / ↓ 不变；搜索框聚焦时切股票也跟着改成 PageUp / PageDown。
- 改动面追加：`walkKey.ts`（判定与键帽字）、`SidebarResultList.vue`（切股票的键）、`WalkStatusBar.vue`（第二个键槽的键帽）、规格 1.14 与说明书的键位节。

## 规律

**两根轴**：← / → 跨天（竖线会动）；↑ / ↓ 留在同一天（竖线不动）；Esc 往外退一层。

**每根轴用同一个判断，只看两个数**——选中的东西在这根轴上「里面装着几个」、「同一层还有没有别的」：

| 里面装着 | 同一层还有别的 | 这一下做什么 | 键槽写法 |
|---|---|---|---|
| 两个以上 | 不管 | 进去，在它们之间走 | `into X ×n` |
| 一个或没有 | 有 | 留在本层，换到旁边那个 | `X k/n` |
| 一个 | 没有 | 进那一个（唯一能去的地方） | `into X ×1` |
| 没有 | 没有 | 不响应 | 灰 `—` |

一句话：**里面有得挑就进去；否则本层有得换就换；两样都没有、里面只有一个，就进那一个。**

**换到旁边时落在对应的那个**：选着整天就落整天；选着某一次 hit 就落那天最像的那次（同一种切法）；选着 event 就落旁边那格里最像的那个（优先同一个起点）。

## 两个定义（各只定义一次）

**装着**（只有这几条，都是「同一行里沿日子排开」或「叠在同一天」的一串）：

- 跨天：一族装着它的买点日；一条反馈装着它收进来的买点日；一个 event 装着用到它的买点日；一个 node 装着它那条 band 上的 event。
- 同一天：一个买点日装着这天叠着的几次 hit；样本、框装着那天在场的几次 hit。
- 一次 hit 绑定的 event 不算：它们散在不同的 band 上，不是一行里的一串，选中时已全部画出粗框。

**同一层**：显示栏 `in` 最后一节里面（也就是 Esc 会退到的地方）；`in` 为空就是整张图上的同种东西。选着叠在某一天里的一个时，跨天的「同一层」是那一天所在的那一串。同一天的「别的」= 和它叠在同一处的另一个。

## 逐格推演（八种东西 × 两组键，没有一格要靠「它是哪一种」来定）

| 选中的 | ← / →：里面 / 同层 → 结果 | ↑ / ↓：里面 / 同层 → 结果 |
|---|---|---|
| 一族 | 买点日 ≥2 → 进去；只有 1 个 → 换到旁边一族（图上只有这一族才进那一天） | 没有 / 没有 → 不响应 |
| 反馈 | 同上：收进来的买点日 ≥2 进去；1 个换到旁边一条反馈 | 不响应 |
| event | 用到它的买点日 ≥2 → 进去；0 或 1 个 → 换到这条 band 上旁边那格（band 上只有它一个且牵出 1 天才进那一天） | 没有 / 同一格叠着别的 event → 换 |
| node | event ≥2 → 进去；1 个 → 进那一个（node 没有沿日子排开的邻居）；0 → 不响应 | 不响应 |
| 买点日 | 没有 / 这一串里别的买点日 → 换天，仍是整天 | 这天 ≥2 次 → 进去落第 1 次；1 次时这天就是那次 hit（两层合并） |
| 一次 hit | 没有 / 旁边的买点日 → 换天，落最像的那次（一次 hit 买好几天时最像的就是它自己，只挪竖线） | 没有 / 这天别的几次 → 换 |
| 样本 | 没有 / 别的样本 → 换样本 | 在场 ≥2 次 → 进去；1 次 → 进那一次；0 → 不响应 |
| 框 | 没有 / 别的框 → 换框 | 同样本 |

两族同一天都买：↑ / ↓ 只在点的那个 ▼ 上走（另一族的 ▼ 不在同一层），不需要另设规矩。

## 规律带来的三条后果（是规律的一部分，不是零散例外）

1. **一个键兼管「进去」和「换旁边」，按哪个由数据定。** 可预判靠的是：按之前键槽已经写明这一下是 `into …` 还是 `… k/n`。要完全不看数据只能再加一个「进去」键，而 ↑ / ↓ 已给了同一天那根轴、Enter 是反馈面板的保存，所以不加。
2. **只装着一个的东西，从它到那一个没有键**（它是本层唯一一个时除外）：只牵出 1 个买点日的 event、族、反馈，到那一天要用鼠标点 ▼。
3. **换旁边时碰到里面有得挑的，下一下就被带进去**：沿 band 换到一个牵出好几天的 event、换到一个有好几天的族，再按就进它里面；要越过它用鼠标点。Esc 退回它本身。

## 相比 `design.md` 改了哪几格

- event 只牵出 1 个买点日：原来落进那一天（`buys 1/1`，再按到头）→ 改为沿 band 换到旁边那格。
- event 没被任何 hit 用到：原来不响应 → 改为沿 band 换。
- 一族、一条反馈只有 1 个买点日：原来落进那一天 → 改为换到旁边一族 / 一条反馈。
- 框的 ← / →：原来不响应 → 改为换到旁边的框。
- 其余各格不变（样本、框只有 1 次在场的 hit 时 ↑ / ↓ 照旧进去，由表的第三行给出）。

## 相比上一条回复改了什么

- 沿 band 走的范围：上一条说「只走起点相同的那一串」，改为「band 上的下一格，落最像的那个（优先同起点）」。这和 hit 换天「落最像的那次」是同一句，不用专设范围；新平台逐天长一格（img26→img19）照样保住。
- 「推广到族、反馈」不再是单列的默认，是规律的自动结果。

## 没验证的

- 全部是纸面推演。别的 app 上同一条 band 混着「牵出 1 天」和「牵出好几天」的 event、几串起点不同的 event 终点日交错时，走起来顺不顺没看过。
- 沿 band 走的格数随档位变。
- 换框后按 Delete 删的是新选中的那个框，要不要防误删没看。
- 新键槽名 `hit_families k/n`、`feedbacks k/n`、`boxes k/n`、沿 band 换时的 `events k/n`，以及里面只有一个时的 `into X ×1`，是新界面名或新写法，进待认名单（族用 `hit_families`，因为 `families ×n` 已用于「跨了几族」）。
- 停在 hit 这一层换到旁边的样本或框，那边没有在场的 hit 时落在哪：默认落在那个样本 / 框本身，待验证。
- `challenge.md` 里 skeptic 的验收针对拍板前的规则；本规律未经 skeptic 走查。
