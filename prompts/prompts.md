关于 plan 的内容，我有更深的思考
feedback 和当前的 plan 所探讨的工作流不同：
- feedback: 我想构建自动工作流，让一个 skill 站在全局的统计结果去改进 dag
- plan: 我自己通过 web ui 来分析改进 dag，找到 label 大的和 label 小的，看K线图，找规律，分析原因。
但我确信，即使是在用 web ui 来自己分析的场景下，我也希望选股策略的评估和交易策略的评估进行解耦合。因此我怀疑按照 plan 中的方法纳入来模拟交易是否合适。
那么站在评估选股策略的出发点，我想知道 label 的作用是什么？有两种视角：
1. 方向性：
    如果 label 是用来评估选股策略对后续方向性的预测，那么应该平等的考虑涨跌。当前的 label 只看涨不看跌，所以方向性只能是正的。即使显示数值很大，其实也可能只是波动率的作用。那么是否应该纳入正负对称的统计方法？
2. 收益性：
    一个选股策略最终要变现，总是要经过交易的。那么对选股策略的最终效果的评估，是否应该包含交易模拟的结果？比如说，对于负面方向性的统计，是否有必要使用 min price，事实上，在实际交易中，我不可能任由一只股票无限下跌而不止损。而上涨时，我则是绝对逐利的，尽量追求 max price。也就是说，真实的交易在选股策略既定的情况下，后续收益的正负影响会受到人为因素(包括交易策略)的干预而必然呈现不对称。是否应该将后续的不对称囊括到对选股策略的评估中。选股策略的制定，如果采用非对称的反馈调节，那么可能会更有利于利益最大化。因为反馈调节的对象是一个完整的变现流程。相当于用端到端的方式训练一个由两个模型(选股+交易)组成的神经网络，而它的输出是利润。

关于 label 是否应该正负对称，上述两点是矛盾的。但是其实可以做两个版本的 label。(涨跌对称版 + 模拟交易版)
而当前的 label 只看涨不看跌，既不满足方向性，也不优化收益性。
