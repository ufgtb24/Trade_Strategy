# 调参 v3

在机会够用的前提下，让每次买入后的方向表现更好。资金有限，不把更多买点无限加分；方向分不是收益率或实际资金回报。完整代办参数梳理、训练搜索、冻结候选、一次验证及已有授权范围内的落地。

本入口独立于旧 `tune-gates`。普通调参只改参数，不改检测逻辑、拓扑、买点定义和评价期限。不寻找附近最差成绩，也不强制检测平稳区域。

## 固定口径

- 机会为唯一股票日期；同股同日去重，多日分别计算。用事件实际 `sample_bar_indices()`，不把整个事件跨度当买点。原参数取 `load_params()` 完整现役快照。
- 买点当天 close 为起点，当天已知波动尺度决定固定上下线。从次日起在固定期限内用 close 判首次穿越：先上 +1、先下 −1、未触线 0。未触线保留在分母；它不是坏数据，也不表示收益为零。兼容表列 `both` 恒为0，不得混入旧盘中标签。
- 每个连续时段内先求 `(先上数量−先下数量)/全部买点数`；枚举全部合法起点，再对非空时段按近期权重求平均。外层不按买点数再加权。默认21交易日时段、252交易日半衰权重是工程起点，须在看成绩前固定。
- 空时段保留状态，不能填0或补普通买入成绩；全未触线且确有买点的时段为0。报告近期机会和时段覆盖，不强迫每月出手。
- 普通买入按候选同日期、同波动档配比，池中包含候选自身。固定 bo 使用搜索前冻结的参数与自己的买点，单独比较；不与普通对照平均，不自动作为逐时段必须超过的门槛。
- 机会只设下限。空间和盘中回撤保留诊断；只有预先明确数值要求时才成为约束。搜索和训练内入选使用同一可行集合、同一方向主分，没有额外的原始空间改善资格。
- 统计折扣默认关闭。显式启用 `shrinkage.enabled` 后，整轮以“普通买入成绩＋按证据调整后的差异”排名，固定开关、尺度和相关跨度；同时保留原始方向分及对照差。它是未验证选参收益的实验性选项，不产生置信区间或自动确认能力，不将重叠时段数、买点数或股票数直接解释为独立证据。完整计算与能力边界见 [method.md](references/method.md)。

## 开始时

1. 读 [runbook.md](references/runbook.md)，核对 app 的参数、`Params`、`build_pattern`、`eval_meta`、`analyze`。门槛可松可紧；结构参数按改变的识别含义确定范围，不能凭数量增减解释松紧。只问尚未确定的业务方向；范围、预算、阈值由 agent 推导。
2. 核对买点当天全部成立条件，包括祖先、边、where 和容器字段。事件本身已确认不等于整组条件当时可知；把代码证据写进 `causality_note`，必要时用训练数据逐日前缀检查。不得以一句“无前视”代替核查。
3. 固定股票池、训练、最后验证与复核范围，包含完整未来尾部，互不重叠。查 `docs/sample_usage/<app>.jsonl` 与 `<app>.v3.jsonl`，以及已知同谱系 app 的记录；尊重 `TUNE_LEDGER_DIR`。人工看过但未记录的也算开发数据，不换 app 名或账本目录解锁。
4. 旧版和 v3 不在同 app 同时运行。旧版不自动读 v3 记录，切回前须核对两本。方法开发用 `UsageLedger.claim_development` 先登记到同一 v3 账本，无需虚设一次最终验证；前后拆分用于改方法后全部属于开发数据。
5. 按 [configuration.md](references/configuration.md) 准备本轮配置。标签、窗口、近期权重、普通对照定义、固定 bo、统计折扣设置、供给约束及预算在第一次看成绩前冻结，不交给 Optuna 随候选优化。

## 执行

从仓库根运行，CONFIG/RUN 换为本轮路径；不覆盖已有运行目录：

```bash
uv run python .agents/skills/tune-gates-v3/scripts/run.py search --config CONFIG --run-dir RUN
uv run python .agents/skills/tune-gates-v3/scripts/run.py validate --run-dir RUN
uv run python .agents/skills/tune-gates-v3/scripts/run.py review --run-dir RUN
uv run python .agents/skills/tune-gates-v3/scripts/run.py status --run-dir RUN
```

- `search` 先冻结与登记，再读标签。Optuna 支持整数、有限选项和无固定步长浮点数；只改声明的字段，先比较原参数。程序错误不吞成低分，非法参数关系明确记录。所有尝试及约束写 SQLite；原参数可能仍是最好选择。
- 仅当新参数满足统一约束且主分比原参数提高，才冻结唯一候选。没有改善就保留原参数并释放未消费的预留范围。固定 bo 只计算一次，结果随报告保留。
- `validate` 只检查冻结候选与原参数，不重选第二名或改公式。使用前登记，即使失败也不能当未见数据；完整结果再次请求时只读保存文件。除了系统日期已过，每股数据还须到齐预定未来尾部；文件滞后时失败并保留使用记录，不缩短检查区间。
- `review` 在预定新数据的完整未来到齐后检查一次；不自动延长观察。当前默认没有经过校准的确认区间，改善只能暂用，复核仍不足则恢复原参数。不能伪造区间以得到“确认”。
- 搜索中断不支持精确续跑。`abandon --run-dir RUN` 关闭本轮并释放未消费预留，历史使用不消失；重新搜索要累计报告尝试次数。

标签每股只计算一次；滚动最高最低、逐偏移批量首穿、普通对照预汇总与候选精确缓存均可复用。结构参数变化重跑检测；不将浮点取整作缓存键，不未经验证套旧网格快路径，不因股票成绩不佳中途丢弃它。

## 采用与交付

脚本保存结论与完整参数，不自行改正式参数。授权包含落地时，按 [落地与恢复](references/runbook.md#落地与恢复)执行；仅研究方法的任务不改 app 参数。

当前评分模块不提供自动确认所需的已校准证据，因此正常结果为：

- 暂用：要求均通过，方向主分观察上改善，但尚不足确认；保留原参数及复核日期。
- 不采用：未达要求、没有改善或无法比较，维持原参数。
- 撤回：暂用到预定复核仍未达到确认要求，恢复原参数；有并行合法修改时先核对，不覆盖。

采用函数保留“确认”分支供未来经验证的证据规则使用；当前不能声称该能力已实现。此限制不取消用户允许暂用的选择。

报告先说是否改善、是否达标、证据状态与实际动作。随后列本轮开关状态、新旧原始方向分、实际排名分、普通对照与原始差值；启用折扣时另列保留差异的比例、工作误差刻度及退化状态。再列固定 bo、三态数量、条件先上比例、上涨空间、盘中回撤、买点数、近期供给、股票/日期/时段覆盖和尝试总数。分清训练观察、开发检查、最后验证；不要将方向分乘100说成收益百分比。

## 运行时用语

| 内部内容 | 给用户说 |
|---|---|
| baseline_params | 现在这套参数 |
| objective / score | 按固定办法算出的方向成绩 |
| WindowPlan | 各个连续时段的计算安排 |
| shrinkage / factor / variance | 统计折扣／保留差异的比例／对成绩不确定程度的估计（尚未校准） |
| constraint | 必须达到的要求 |
| final / holdout | 留着没碰过的数据 |
| provisional / rollback | 暂用、之后复核／恢复原参数 |
| trials / manifest / hashes | 本轮比较过的参数数量／已固定的候选和规则 |

买点、首次穿越等项目词按 `path2/CONTEXT.md` 用语并附词条行号；本技能收盘判断与框架原盘中实现要明确区分。公式、默认数和内部文件由 agent 消化，不交给用户填写。
