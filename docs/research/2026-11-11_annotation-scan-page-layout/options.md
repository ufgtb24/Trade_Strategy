# 标注与扫描怎么安置：方案与评估

## 0. 结论

**标注时空着的主要是左栏。** 它在四种状态下完全一样，没有任何按模式的分支；留着扫描，是「票 04 不改扫描流程」的副作用，没有人拍过板（用户认可的原型根本没有左栏）。顶栏和右栏本来就基本按任务分好了。实测视口 2192 宽时，左栏 220、图 1652、标注侧栏 320；刚打开页面时中间整块空白，左栏两处写「未加载扫描结果」。推荐方案不是为了让图更宽——左栏放下大涨段清单后约 278 宽，图反而窄约 58px；收益是这一列从空着变成标注天天要用的找图清单，`rally` 浮层也不再盖住图的左边。

**推荐：不拆页面，把扫描做成 `mode` 的第四档。** 顶栏 `mode` 从 `annotate / compare / app` 变成 `annotate / compare / app │ scan`：
- `app` 从此只指「当前 pattern 的 app 在这只股票上现算」，`scan` 就是今天的扫描视图。一个按钮管两种来源的歧义没了——用户这次问「标注的 app 是不是扫描结果」，正是这个歧义造成的误解。
- 前三档的左栏换成找图清单：大涨段清单直接铺开、`random` 抽过的图也列进来（刷新就清空、不落盘）、加一页「标过的股票」，每行写标过哪个 pattern、几个样本、几个框；↑/↓ 挨个翻。这正是用户 11-03、11-05 自己提过、还待定的第 2、9 条界面改进。
- `scan` 档的左栏、图上方那条、右栏和今天的扫描视图一模一样。
- 图组件、图表状态、副图画法全部共用，没有新页面、没有新地址。票 01 当初「不另开页面」要防的「两套画法、标完对不回来」不受影响；用户 11-05 说「标注和主视图非常割裂」时点名的最棘手问题是拖拽、rally 股票列表、`compare` 里没有分档；拖拽已在 11-08 用 `tool` 按钮解决、`compare` 已有三档按钮，F 落实的是剩下的「rally 也用左侧股票列表」这一条，图上的操作一样不碰。点 `app` 时右栏和图上方那条照样会换，所以不能说 F 解决了「割裂」。

这就是用户说的「两种模式、界面不同、共用部分复用」，落成的形状比单独加一个「标注 / 扫描」开关更省：不新增概念、从扫描图去 `compare` 只要一下。

**扫描界面按「偶尔才用的调试工具」安置**：主目录现存的扫描没有一份能在网页里正常显示（唯一过得了数据墙的那份是 11-04 改名前的格式，列表 0 行），说明改名以后没人在网页里用过扫描。若用户其实常用，要告诉我们，默认会不同（第 6 节）。全池跑 app 的**能力**不在取舍之内，第二段的盲看还要用它。

**时机**：这一轮 annotation-round 交还用户、用户在 `compare` 里看完改版报告之后，下一轮开始之前，在独立 worktree 里一次做完。它不改 V-S1 验收的对象。

### 1.4 由此得出的框架

问题拆成两根正交的轴：
- **外壳轴**：扫描界面和标注界面怎么共处。这是用户问的「拆不拆」，第 2、3 节的取舍对象。
- **内容轴**：标注时左栏放什么。几种外壳下答案几乎一样（找图清单），单列在第 4 节。

真正的缝不在 `mode`，在 `app` 的两种来源（F4）：扫描来源的 `app` 属于扫描界面，现算的 `app` 属于标注（F11）。

「独立页面」有三种读法，代价差很多，分开评：
1. **另一个地址、各自启动、各自一份状态**（如 `/` 与 `/scan`，或两个 HTML 入口）——方案 A；
2. **同一个应用里的路由**（地址不同、状态仍是同一份）——除了地址，与第 3 种没有区别，而 `#` 已被直达链接占用、要另走路径路由；并入 B，作为「地址要不要反映外壳」的细节；
3. **同一棵组件树换外壳**——用户说的「两种模式」。它有两种落法：加一个「标注 / 扫描」开关（方案 B），或把扫描做成 `mode` 的第四档（方案 F）。

线框图记法：`等宽英文` 是界面固定文字（字段名、按钮、状态）；`«…»` 是业务内容（股票、pattern 名、用户写的字）；中文是对区域的说明，不是界面文字。每个方案都给「标注时」「扫描时」两张；和方案 F 相同的区域不重画，只画不同的那一条并写「同 F」。

### 方案 F · `mode` 加第四档 `scan`（challenger 提出；推荐）

顶栏 `mode` 四档：`annotate / compare / app │ scan`，竖线把「标注的三档」和「扫描」隔开。
- `app` 只指现算；`scan` 就是今天的扫描视图（扫描文件里的产物、扫描窗口的 K 线、扫描的 active pattern、参数副本、诊断侧栏、拓扑面板）。
- 左栏跟着模式换：前三档是找图清单（第 4 节）；`scan` 是今天的扫描面板与列表。图上方那条、右栏本来就随模式换，不变。
- 加载扫描、点扫描列表切到 `scan`；`symbol`、`random`、直达链接、找图清单、点前三档都不会落到 `scan`。
- 切换时股票怎么带：前三档 → `scan`，当前股票在扫描文件里就留着，不在就回到扫描列表上次停的那只（扫描视图画不了扫描文件以外的股票）；`scan` → 前三档，在 `scan` 档里点过扫描列表的行才把那只带回去（任何股票都能标），没点过就回到进 `scan` 之前的那只，免得「看一眼扫描」丢掉正在标的图。
- 扫描专用的东西只在 `scan` 档起作用：扫描列表的按键（K1、K2）、Shift+P 参数抽屉（K3）、休眠草稿横幅（K4）都加「只在 `scan` 档」这一个条件；扫描选股时清掉打开时给定的图窗（K5）。扫描列表在别的档隐藏而不卸载，滚动位置和虚拟列表都留着（和 `rally` 浮层今天的做法一样）。
- 只在界面上拆按钮时，`view.ts` 里 `mode` / 来源两个状态的表示可以不改：`scan` 按钮 = 今天的 `mode = app` + 来源扫描，`app` 按钮 = 现算，左栏看「是不是扫描视图」换内容。若把 `scan` 做成 `mode` 真正的第四个取值，要改约 15 处代码（`TopBar.vue`、`view.ts`、`KlineChart.vue`）和 13 个测试文件；默认取前一种。要改的是几处动作：进 `scan` 时的股票规则（记住扫描列表上次停的那只）、没有扫描文件时留在 `scan` 的空状态、扫描选股清图窗。
- 全部在根地址 `/`，直达链接和报告链接照旧。

## 4. 内容轴：前三档左栏放什么

几种外壳下都一样。
- `rally`：大涨段清单直接铺开（复用 `RallyList.vue` 的数据与排序，样式和按法照扫描列表），每行多两列：这只股票在这段图窗里标过的 pattern 名（业务内容，浅灰底）、框数。框数这一列让「只画了框」和「完全没碰」两种行看得出区别（用户第 2 条）。顶栏的 `rally` 按钮去掉。点一行打开那段图；↑/↓ 挨个翻（用户第 9 条）。
- `random`：抽图的入口仍是顶栏的 `random` 按钮（在哪一页都是 1 下出一张）；这一页只按抽的先后列出这次抽过的几张，可点回、↑/↓ 挨个翻（用户第 9 条）。只存在页面内存里，刷新就清空、不写文件也不写浏览器存储：spec 5.3「看过什么一律不记」防的是「看过」账本限制你看哪些图——票 01 第 70 行的理由原文是「记『看过』违背训练段随便看」，规格 5.3 不搬旧账本的理由也是「训练段随便看，这几样都只为旧账本服务」（`spec.md:368`）；这份列表什么都没记下、也不限制任何东西，和大涨段清单今天标着当前那一行同性质。列与 `rally` 页相同（日期段、pattern 名、框数）。
- `charts`：所有标过的股票，不限于大涨段清单，列出 pattern 名、正负样本数、框数；只画了框、还没放样本的也列（用户第 2 条指出 `pattern` 页的样本卡漏掉了这类图）。前端从标注状态现算（F9）。
  - 和右栏 `pattern` 页的样本表分工不同：`pattern` 页是**当前 pattern 的样本**，按判断和骨架分行，用来看这个 pattern 的全貌；`charts` 是**全部 pattern 的股票目录**，一只股票一行、含只画了框的，用来决定下一张去哪看。交集是当前 pattern 有样本的那几只股票。
- 三页只列用户自己存下的东西（和 `random` 这次抽到的图）：不出现 app 的任何结果（说明书第七节第 2 条），也不出现「看过 / 没看过」（spec 5.3「看过什么一律不记」）；「标过」只从标注文件推。
- 第二段做盲看时，盲看清单放左栏还是照规格 6.5 放右栏，到时再定（v2 曾想把「左栏放去哪看、右栏放眼前有什么」立成原则交用户拍板；这一轮它不产生任何差别，按 challenger 第 7 条撤回，不占用户的决定）。

## 6. 推荐方案下要用户定的、和可以取默认的

### 要用户定的方向（只有一道）

**扫描放在哪**：推荐「`mode` 加第四档 `scan`」。一个页面、一排按钮，标注的三档左栏是找图清单（大涨段、random 抽过的、标过的股票），`scan` 档就是今天的扫描视图；`app` 从此只指当前 pattern 的 app 现算，不再和扫描结果混在一个按钮里。别的路：
- 两个独立页面：多两个地址、来回要重读扫描文件，没多覆盖什么；
- 顶栏加一个「标注 / 扫描」开关：效果和四档一样，但多一个要起名的新概念，从扫描去 `compare` 多一下；
- 不分档、左栏分页签（扫描是其中一页）：能在 `compare` 下翻扫描列表逐张挑刺，代价是扫描列表和标注的按键、点行落在哪个模式都要另定规矩；而「从扫描结果挑图去标注或挑刺」目前没有用过的迹象。

这条推荐的前提是**扫描界面现在是偶尔才用的调试工具**：所以它只占顶栏一个按钮、页面打开不落在那里、扫描视图里和标注无关的控件这次不收拾。依据是 11-04 改名以后主目录里没有一份扫描能在网页里正常显示，也没人提过。如果你其实常用扫描界面，或者想在 `compare` 里对着全池命中逐张挑刺，说一声——那样「左栏分页签」更合适。

### 第二段再议（这一轮不产生差别，不占你的决定）

- `compare` 下左栏要不要显示每只股票上 app 与标注是否一致：要一条后端路由把当前 app 在所有标过的股票上跑一遍（和反馈状态一样只做买点日比对，不含走势语义）；规格 6.3 第二段本来就规划了按版本存每个样本的对照结果。
- 盲看清单放左栏还是照规格 6.5 放右栏。

### 实现细节（取默认，标「待验证」，列出请过目）

- 时机：这一轮 annotation-round 交还、你在 `compare` 里看完改版报告之后，下一轮开始之前，在独立 worktree 里一次做完（第 5 节；与 v-s1-notes 第 9 条「随时可插」一致）。
- `scan` 档在没加载扫描时照样能点：左栏是扫描面板（去扫描、打开历史）和空列表，图区空着、写 `no_scan`，股票不带过去。这是今天没有的状态（今天关掉扫描会被踢回 `annotate`）；删掉当前扫描时同样留在 `scan` 档、落到这个空状态。
- 切换时股票怎么带：前三档 → `scan`，当前股票在扫描文件里才留，否则回扫描列表上次那只（四档里唯一会换图的按钮）；`scan` → 前三档，只有在 `scan` 档里点过扫描列表的行，才把那只带回去，没点过就回到进 `scan` 之前的那只（`no_scan` 空状态同理）。这样「标注 A → 看一眼扫描 → 回标注」仍落在 A。待验证。
