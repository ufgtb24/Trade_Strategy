# 白话解读：那份工作流研究到底说了什么

> 这是 `final_report.md` 的通俗版，去掉了公式、统计量和实现细节，只保留结论和它们背后的道理。
> 想动手，看 `07_operational_spec.md`；想核对数字，看 `final_report.md`。

---

## 一句话

**你要的是"让 Claude Code 自动优化 pattern"，研究给出的答案是：先别自动化，因为你用来判断"优化没优化成"的那把尺子，量的不是你以为的东西。**

工作流本身也设计出来了，形状和预想的不太一样——它不是一个搜索引擎，是一串否决关卡。为什么是这个形状，也不是拍脑袋定的，是算出来的。

## 第一部分：先说那个可能比工作流本身更重要的发现

研究过程中，团队为了检验"目标函数体检"这道新工序到底有没有用，拿现有的 `bottom_breakout_burst` 试跑了一遍。**这道工序一开机就报了三条警。**

**其中第一条后来被推翻了**（2026-07-25 用户异议，成立）。先说清楚它错在哪，再说剩下两条为什么不受影响——**因为那两条才是重的**。

### 1. ~~换个算收益的方式，排行榜会反过来~~ ← 这条不成立，已撤回

原来的观测是：同一批买点，用现在的口径（买入后 20 天内摸到的最高价）算是 +0.23；换成"持有到期、第 20 天收盘卖"算是 **−0.06**（胜率 41.8%），而随机日是 +0.005 / 53.0%；两个口径给出的候选排名秩相关 **−0.186**，负的。当时的解读是"目标函数在度量另一个维度"。

**这个解读预设了两个口径应该一致，而对这个 pattern，它们本来就不该一致。**

pattern 的职责是找入场点，"未来一段时间内会涨"就是买点的定义；什么时候兑现是卖出程序的事，那是一个**尚未开发的独立模块**。连续突破捕捉的正是乘势而起、立刻爆发的行情——爆发不需要等到第 20 天，爆发之后回落到更低点，在这个分工下是可以接受的。

**用持有到期去评判一个短线爆发信号，换掉的是持有期语义，不是度量维度。** 这不构成"尺子坏了"的证据。

> **对 b 项这道检查本身的修正**：替代口径必须**与策略的持有期语义兼容**。对短线爆发型 pattern，合适的替代口径是"5 日内最高"、"首次穿越比例"、"爆发幅度分位"，**不是 20 日持有到期**。原文那句"换一个合理的替代度量"里，"合理"两个字承载的东西比写的时候以为的多——它必须包含持有期匹配这一层。

**但有一个残留信息不该跟着一起丢，只是它的指向变了**：持有到期 −0.063 / 胜率 41.8%，是**低于随机日的**（+0.005 / 53.0%）。在"pattern 找入场 + 程序负责卖出"的分工下，这不是对 pattern 的指控，但它是**对那个尚未开发的卖出程序的一条硬约束**——它必须在窗内兑现，不能容错到期末，因为期末的漂移是负的。这条约束的可行性目前还没被验证过。

---

**下面两条不受这个反驳影响。** 一条根本不问持有多久，另一条用的就是你认可的那把尺子。

### 2. 这些形态看不对方向

做一个很干净的检验：买入之后，往上 X% 和往下 X% 这两条线，哪条先被碰到？如果 pattern 真的有选股能力，"先涨"的比例应该明显高于随机日。

结果：在"年份 × 阈值档位"的 8 个组合里，**7 个低于随机日**。有一年在四个阈值档上全线落后。

**为什么"我只要爆发、不管 20 天后"驳不倒这一条**：首次穿越根本不问持有多久，它只问哪条线先被碰到。"立刻爆发、然后回落到更低点"完全满足"先触 +X%"——只要爆发在前，它就该赢下这个检验。**所以这一条问的恰恰就是"是不是真的乘势而起"**，它是三条里与你的策略语义最贴合的一条。

机理也查清楚了：pattern 确实把上行幅度抬高了大约 10.6 个点，但同时也把下行深度压深了大约 11.2 个点。**两边几乎对称，而现在的 label 只数上行那一半。** 注意这不是"先爆发再回落"的形状——那样的话上行应该先于下行发生；实际是两边振幅一起变大。

顺带一提：不光是 `bottom_breakout_burst`，整个突破族的"先涨比例"都在 0.5 附近——方向上接近无信息。

### 3. 分数的九成是波动率读数

**这一条和下一条用的都是"20 天内最高价"——也就是你认可的那个口径。** 它们没有换度量，只换了"跟谁比"。

跨 27 个配置做回归："这个配置的收益中位数"和"它命中的那批股票的波动率是全宇宙的几倍"，**R² = 0.92**。

也就是说，一个筛选器的分数，首先是它的波动率暴露有多高的读数，其次才轮到别的。

现任 pattern 命中的股票，波动率是全宇宙中位的 **2.46 倍**，72.5% 落在全宇宙的 75 分位以上。而且这不是自我度量的循环论证——换成买入前 40/80/120 天的波动率，偏斜基本不变，说明它是买入之前就存在的属性。

### 4. 控制住波动率之后，基线的优势完全消失

按"波动率十分位 × 日历月"做直接标准化，也就是：拿每个买点去和"同一个月、同一个波动率档位里的随机日"比，看它排在什么位置。0.5 表示毫无差异。**算的还是 max-high，变的只是对照组**——从"跟全宇宙比"换成"跟同波动率同月的随机日比"。

| | 2025 | 2024 |
|---|---|---|
| **bo_only 基线** | **0.513** | **0.501** |
| 现任 pattern | 0.563 | 0.532 |
| 现任 pattern 的最大回撤深度 | 0.421 | 0.409 |

`bo_only` 那个原始口径上看起来 +72% 的收益抬升，**控制住波动率和月份之后完全归零**。现任 pattern 还剩一点残差，但很小；而且即使控制住波动率，它仍然买在"两边振幅都更大、下行更深"的时点上。

### 5. 有一根"免费波动率杠杆"，而现在的配置正踩在它的极值上

只动 `bo.min_relative_height` 这一个旋钮，从 0.05 调到 0.60：

- 收益中位数翻了近 3 倍
- 命中集的波动率倍数翻了 3.5 倍
- **但波动率匹配之后的真实边际几乎不动**（0.520 → 0.584）
- 持有到期的口径上反而单调变差

这根旋钮上的整条分数梯度，就是波动率本身。唯一挡住它一路往上爬的，是评分里那个样本量收缩项 `n/(n+200)`——分数在 0.20（2025）和 0.35（2024）见顶。

**而 0.20 正是现在定案用的值。** 换句话说，之前的调参工作，实际上找到的是"波动率杠杆在样本量惩罚下的最优点"。

作为参照：这根杠杆贡献的 0.072 分，是自动搜索一千个候选时选择偏差门槛的 1.8 倍，是实测到的最大真实单旋钮效应的 7 倍。

### 6. 但"改成按波动率归一"不是解药

一个自然的反应是：那把 `relative_height ≥ 0.2` 改成"相对这只股票自己的波动率来衡量"不就行了？

试了。结论比预想的复杂：

- **归一化确实消除了 bo 层的偏斜**（1.56 倍 → 0.96 倍），但整个 pattern 只从 2.46 倍降到约 1.8 倍。另一半住在 `distinct_pk_min=4` 这类结构性要求上——"8 根 K 线内打穿 4 个不同的峰"这件事本身就天生偏爱快速运动的股票，**这里没有量纲可以归一**。
- **归一化之后分数从 +0.072 掉到 −0.013**，而波动率匹配后的真实质量几乎没变（差异不显著）。

所以：**改量纲是诚实性修复，不是提分手段，而且会被现在的目标函数重罚。** 如果把"应当归一化"写成推荐动作，执行的人会看到分数暴跌然后回滚。

**这件事最后是一个业务选择，研究组明确要求原样交给你拍板，不代拍：**

| 选项 | 意思是 | 后果 |
|---|---|---|
| 保持固定 0.2 | "我要的是**绝对意义上**走出 20% 台阶的形态" | 事实上主要在高波动股上开火；分数高，但那部分分数是波动率 |
| 改成自身尺度归一 | "我要的是**相对这只股票自己**罕见的抬升" | 命中集波动率回到全宇宙水平；分数掉到 0 附近 |

两条路都没有方向性优势，所以这不是"改了更好"的选择，是"你想要哪种形态语义"的选择。**而且不能用分数在这两条路之间挑**——因为分数在这条轴上度量的恰恰就是波动率。

### 7. 还有两条兜底的坏消息

- **数据是纯幸存者集**：7532 只 pkl 里一只退市股都没有，所有股票的首个交易日还都相同。这意味着上面所有的负面结论**只会更差**——在一批对 pattern 有利的样本上都没测出优势，真实情况只会更糟。另外"加数据把样本量提上去"这条路有硬上限，总共就 5 年。
- **一个没分离干净的混杂**：全宇宙收盘价中位数只有 13.8 美元，低价股和高波动高度共线。所以"这是个波动率选择器"和"这是个低价股选择器"，在这次分析里是同一件事的两种说法。两者的交易含义完全不同——前者关乎风险敞口，后者关乎流动性和能不能真的成交。**这是整份研究里最值得再追一刀的地方。**

## 第二部分：工作流该是什么形状

### 它不该是搜索引擎，该是否决闸阵

原本的设想是"生成候选 → 评估 → 挑最好的 → 迭代"。研究给出的判断是：**在当前的信噪比下，"挑最好的"这一步是在选噪声。**

判断依据不是感觉，是一个可以算出来的量：在所有通过硬门、非前瞻的候选里做两两配对比较，看有多大比例的配对能被统计上区分开。纯噪声的世界里这个比例大约是 5%。**实测是 1%。**

这个检验的好处是它什么都不需要——不需要分布假设，不需要约定门槛，就是数一下有多少对能被分开。

**结论：目标函数只用来否决，幸存者按奥卡姆剃刀取（结构更简单、样本量更大的那个）。排序类工具全部退场。**

### 但这个读数有两层限制，都不小

**限制一：它是用一把已经被证伪的尺子量的。** 第一部分说了尺子在量波动率。而且有直接反证：同一批候选，换一个度量（最大不利偏移深度）就分辨得动。**所以"分不动"是尺子的属性，不是候选空间的属性。**

**限制二：它只覆盖了机械邻域。** 测的候选都是"单旋钮邻域 / 删掉某个 where / 节点子集"这类。**没有测过 LLM 生成的全新判据代码**——而这恰恰是工作流里最有价值的那条通道会产出的东西。

所以研究里写死了一条强制规则：**信噪比读数低的时候，不许直接下"该用闸阵"的结论，必须先分诊。** 做法是拿同一批候选，换 2-3 个替代度量重算一遍。某个度量下分辨得动，就是尺子问题（回去修 label）；所有度量下都分辨不动，才是空间问题（该换候选来源了）。

**本项目的分诊结果：明确是尺子问题。**

这也意味着，**尺子修好之后要重算一次这个读数，档位很可能变**。研究里那份"贝叶斯优化、多保真度、K 调整门槛全部判死"的反面清单，是**条件性的判死，不是永久的**。

## 第三部分：工作流的五个阶段

### 阶段 0 · 目标函数体检（全新工序，最重要的方法论产出）

为什么排在最前面：一个未封堵的杠杆、或者一个测错东西的口径，会让下游所有自动化**加速收敛到错误方向**。人不容易滑进去（人是按走势语义在设计结构），但最大化器会直奔而去。记账做得再干净，记的都是一个错的数。

### 前置：先声明策略语义，再开始体检

**这一步是被第一部分那次翻车逼出来的。** 七项里至少有两项的判据，取决于策略打算怎么兑现——语义不声明，它们照样能跑出数来，只是那个数说明不了任何事。

要声明三件事：**信号在多长时间内兑现**（决定替代口径怎么选、方向性检验的窗口取多少）、**由谁兑现**（决定"期末收益为负"算不算 pattern 的毛病）、**允不允许回撤到买入价以下**（决定回撤类指标是体检项还是对下游的风险披露）。

**本项目的声明（2026-07-25 确认，已写死进报告）：**

- pattern 只负责找入场点，"未来一段时间内会涨"就是买点的定义
- 兑现由尚未开发的独立卖出程序负责，它在窗内择时
- **允许回撤到买入价以下** ⟹ 期末收益为负不构成对 pattern 的指控，但构成对卖出程序的约束
- **口径一致性检查的替代口径 = 20 日内最高 vs 40 日内最高**（同为 max-high 语义，只换窗口）

**这么一改，b 项问的问题就变了**：不再是"两种度量一致吗"，而是"**这个信号的优势对时间窗口有多敏感**"。而这个问题直接对应你那个还没写的卖出程序有多大容错空间——秩相关高，说明优势不依赖精确择时，程序好写；低，说明必须卡在特定窗口内兑现。

两个实施注意：**40 日口径会把尾部缓冲从 20 天推到 40 天**，进一步吃掉本来就只剩 3.5 个月的终局窗，所以这项只在搜索窗上跑；**这个检验目前还没做过**，现有采集脚本只跑了 20 日且只有两个配置，秩相关需要多候选，补它要重跑一轮。

### 七项检查

| 检查 | 在问什么 |
|---|---|
| **平凡对照** | 一个零能力的规则（随机日买、事后最低点买）能拿多少分？如果接近你的 pattern，说明分数不是选股能力换来的 |
| **口径一致性** | 换一个**与策略持有期语义兼容**的收益算法，排行榜还是同一个吗？（替代口径选错会给出假警报，见第一部分第 1 条） |
| **方向性检验** | 往上 X% 和往下 X%，哪个先被碰到？比随机日强吗？ |
| **因果可容许** | 买点用的那个字段，在事件成立的那一刻真的已知吗？ |
| **噪声标定** | 你在用的那些统计常数，是在你自己的数据上标定的，还是从别处抄的？ |
| **硬门体检** | 每道硬门实际淘汰了多少候选？淘汰率接近 0 的门不算防护 |
| **波动率暴露** | 这个候选的分数，是不是它波动率暴露的读数？ |

其中**方向性检验**是最便宜也最锋利的一项——复用同一批买点、秒级出结果、不受收益口径上偏的影响，直接回答"这个形态看不看得对方向"。研究建议把它作为任何新 pattern 的一等验收指标，和分数并列。

**它还有一条第一版没写出来的好处**：七项里只有它**完全不依赖持有期假设**。口径一致性那项要求你先想清楚"多久算兑现"，一旦这个前提和策略语义不匹配就会给出假警报（第一部分第 1 条就是这么翻车的）；而首次穿越只问"哪条线先被碰到"，无论你打算持有 3 天还是 30 天，它问的都是同一件事。**在持有期语义有争议的时候，优先信它。**

**波动率暴露检验有个诚实的边界要说清楚**：它是七项里唯一"能可靠告诉你出了什么事、但给不出下一步"的检查。其他六项 FAIL 都有可执行的处方；这一项 FAIL 之后该怎么办是开放问题——把目标函数改成对波动率中性？接受"这就是个波动率选择器"？还是撤回候选？**这套方法只保证把问题摆到你面前，不保证有解。**

还有一个张力没解决：方向性检验要做成通用的（阈值档位不能写死成某个 app 的数字），就得让阈值从命中池自己的分布里算出来——**但"从哪个分位算""判据取多少比例"这几个数又都是人拍的**。修 app 特异性的代价，是把常数从 app 里挪到了判据里。该做的是把这些常数显式列出来、算出即冻结，而不是假装它们不存在。

### 关于因果可容许闸：一个 6 倍分数差的例子

这是整份研究里最直观的一段，值得单独说。

同样是"删掉 tb 节点"这一个结构改动，只是买点锚在不同的字段上：

| 买点锚在 | 分数 | 合法吗 |
|---|---|---|
| **末**个 bo（事件成立的那一根） | 0.075 | ✅ |
| **首**个 bo（事件的 `start_idx`） | **0.436** | ❌ 等于回到过去买 |

后者三道硬门全过，统计上极度显著，看起来像是一个天大的发现。它实际上是在事件还没成立的时候就买入了。

**而现有的评估骨架 `eval_skeleton.py` 一律取 `ev.start_idx` 当买点。** 也就是说，走官方路径直接删 tb，你拿到的就是那个 0.436。

这就是为什么因果闸必须在候选进入比较之前生效，不能靠人事后审查。落地代价也不大：detector 协议加一个属性声明"我是在哪一根 bar 上物化的"，评估器加一句断言。**这件事引擎猜不出来**——同一个框架里，链式聚合类事件的物化点是 `end_idx`，确认类事件是 `start_idx`，恰好相反。

顺带一个正面发现：`median_confirm` 这种"只取买点窗第一天"的排序口径，一直被当作"防止缩窗刷分"的措施，**它实际上更重要的身份是因果闸在 label 侧的既有实例**。

### 阶段 1 · 候选从哪来：四条通道

**通道 A · 机械消融，包括"删除"方向** ← 这是本研究最重要的结构性发现

三条独立设计的候选来源——失败归因、人类漏检反馈、缓存用途清单——**全都只能产出"放松/新增"类的候选，没有一条能产出"删除"**。而且这有结构性原因：

- 失败归因的输入是失败记录，而一个节点存在的时候，不会产生"它不该存在"这种失败
- 人只会说"它漏了我要的股票"，**永远不会说"这个节点净贡献为零"**
- 缓存的服务半径明明覆盖所有节点子集，却没人把"删掉一个节点"列进用途

补救办法很机械：从 `dag_spec.py` 枚举"每个节点 / 每条 where / 每条边各删一次"。候选数量就是三者之和。

**而且这一步成本为零**——事件流缓存的键是 detector 对象，不是整个 spec，所以边、where、节点子集的改动全部复用同一次检测。

（一个警告：这条不变量会被静默破坏。只要有人把一个阈值从 `where` 挪进 detector 构造参数，缓存就开始给错结果**且不报错**。所以 detector 代码或参数结构一动，就该重跑本目录的 `check_stream_cache_invariant.py`。）

**通道 B · 表达面扩张：被忽视的两层**

原来的三层划分（拓扑 / detector 代码 / 参数）漏掉了两层，而它们恰好是"改动小、风险低、现有 skill 都覆盖不到"的真空：

- **新增 where 谓词**：`where` 只能引用 Event 已经暴露的字段——这才是 detector 层和参数层真正的接缝。字段已经存在的时候，加一条谓词只是 `dag_spec.py` 里几行声明式代码，零 detector 改动、零风险，而且新阈值立刻进入"零检测增量"的免费快车道。现状是大量已暴露的字段完全没被用过。
- **常量提参**：detector 里的模块级常量提成参数是纯机械改动，立刻新增可搜索的旋钮，而且默认值不变时可以用"零 DIFF"验证。

**通道 C · 让 Claude Code 读失败归因** ← 这是"不知如何让 claude code 介入"的答案

关键洞察是：**批量诊断需要的数据早就在算了，只是被丢弃了。**

评估器每次全宇宙扫描都会完整算出失败轨迹并附在结果上，但下游只读 `matches`，失败记录从来没离开过 worker 进程——代码注释自己写着"此路径目前无消费者"。

而这些失败记录自带**源码行号**、**对应的 yaml 参数名**、**实测值**。

**所以 LLM 顺着源码行号去读代码就介入了——不需要断点、不需要 IDE、天然可以批量。** 你自陈的两个劣势，是同一个东西的两面。

这条通道还有一个更可复用的方法论版本：**在讨论"要加什么新埋点"之前，先查有没有既存但没被消费的诊断通路。** 一个成熟系统里，失败信息常常已经算出来了，只是没人接线，这比新增埋点便宜一个数量级且零风险。

**通道 D · 人类看 K 线的形态直觉** → 见下面阶段 3

### 阶段 2 · 评估与判定

闸阵：硬门、因果可容许、标注否决、回归误伤、两窗不崩。每道门都要先过阶段 0 的"硬门体检"——淘汰率接近 0 的门不算防护，别把它算进防线。

**一条公平性要求值得单说**：结构候选必须跑完自己的内层参数搜索才准进比较。用没调过参的分数判结构生死是**单向有偏**的（只会低估不会高估），结果是系统性毙掉好结构。好在内层很便宜——where 层配置可以"检测一次、求解多次"，结果逐字全等。

还有一条跨 session 的记账要求：K 计数（目标函数被查询了多少次）、每次用的窗口、holdout 有没有被解锁。**没有落盘的记账物，任何"用 K 调整门槛"的方案都是空话**——每次 skill 调用都是全新 session，K 无从数起。而且机制层帮不上忙：Workflow 的 budget 是 token 预算，不是查询次数预算。

### 阶段 3 · 人在环

**人类判断有三个用途，都不进优化循环：**

1. **诊断过滤器**——把海量失败轨迹坍缩成一条可执行诊断。**N=1 就有用**
2. **单向否决闸**——"不许弄丢这些样本"。N=10~30
3. **候选生成的语义来源**——不限

**但绝不能当目标函数。** 理由是结构性的，不是统计上的：分数有减基线保护，退化成基线时 lift 恒为 0，摆烂刷不到分；**而 recall 没有——把过滤全放开，标注样本全命中，recall 就是 100%。** 也就是说，recall 一旦进目标函数，最优解本身就是退化解。这比"20 个样本太吵"致命得多。

**否决闸会误伤，所以不能自动 reject。** 它可能会否决掉一个"合法地找到了更好机会集"的候选，因为标注编码的是你**当前**的直觉。协议必须是**阻塞 + 归因 + 人裁三选一**：实现偏离（判据被改坏了）→ 必修；设计偏离（换了个更好的形态，我认）→ 接受并更新标注集；存疑 → 撤销改动、标注不动。

这样一来，标注集就从"一次写死的公理"变成了"随你的意图演进、留痕的证据集"——**它因此不需要是无误差的真值，只需要是可被复核和修订的证据**。这把"人的判断可靠性"从一个必须测量的风险，变成一个不必依赖的假设。

**几条红线：**

- 人提候选、人有否决权，**但人从不排序**
- 送到人眼前的队列，排序口径必须和目标函数一致——否则会悄悄把最贵的资源（你的注视）投在错的地方，而且不留痕迹
- 人的输入必须和目标函数正交（形态语义）。用分数相关的量决定人看什么，会破坏正交性——**而正交性恰恰是"人类收窄候选能真实降低选择门槛"的合法性前提**
- 人擅长相对判断，不擅长绝对判断。所以判定要设计成"和基线对拍"，不是绝对阈值
- **别把"必须先标注"写成硬前置**，那会卡死冷启动

**硬预算：单次定案周期 ≤20 个人类判定 / ≤20 分钟。** 三条依据：人时线性不可压缩、连续判定会疲劳、标注集本身也在被消耗（用同一组 20 个标注去筛 1000 个候选，就是在向这 20 个样本做选择）。

顺带一条实测：四种廉价的结构信号，收窄"该看哪些"只能提高 1.0~1.77 倍命中率。**也就是说第 200 次注视的命中率和第 20 次一样低——别设计"聪明排序省人力"的环节。**

两个静默陷阱：标注**存日期不存 bar 索引**（bar 0 随加载窗口变，存 bar 下一轮会静默错位）；**结论要持久、归因要按参数 hash 失效**（"这是横盘后启动"是价格行为的事实，改参数不会让它变；"死在 gap_max"只对某组参数成立）——这两个必须是两个文件。

### 阶段 4 · 定案与 holdout

先盘清数据的真实边界，这一步经常被跳过而它决定了整个方法的天花板。前面说了：跨度有硬上限、纯幸存者集。有一条有用的推论——**越近的年份污染越轻**，所以最近那段是数据里最干净的一段，最适合当终局 holdout。

把可用窗分成三类：搜索窗（2 个，留在循环里）、终局 holdout（最近那段，全生命周期只解锁一次）、备用窗。

**本项目实测：终局窗扣掉两头缓冲之后只剩约 3.5 个月，样本量过不了硬门。** 所以规格里写死了分支——够样本量就报完整统计，不够就只报"崩了没崩"这个符号判断。落地第一件事是实测这个数，别照抄推算值。

**holdout 的强制方式，按可靠性排序：** 数据通路隔离最强（搜索 harness 根本拿不到 holdout 的路径——**拿不到的数据不需要被禁止访问**）；其次是自惩罚记账（查得越多门槛越高）；hook 强制拦不住脚本内部读文件，是卫生机制不是安全机制。

**一条会改变判断的诚实边界**：搜索窗上看到的提升，在另一个窗只兑现 3%。这个数低到足以作为停止搜索的信号。

## 第四部分：Claude Code 的哪个机制适合干这个

### 总答案：这个问题问错了

八个机制（skill / subagent / agent team / workflow / ralph-loop / background agent / hook / cron）**全都是"编排 LLM 回合"的机制，没有一个会评估候选**——评估永远是一个外部进程。

正确的问法是"回路里哪些是 LLM 回合、哪些是确定性代码"。这个问题的唯一答案是 **Workflow**（唯一能把 JS 控制流 + 结构化返回 + 每 agent 独立上下文组合在同一个程序里的机制）。**但按第二部分的结论，现在还用不上它。**

### 三条设计律

1. **强制只能施加在"在强制边界上可见"的东西上。** 想让某个不变量可被机制强制，就得先把它抬到那个边界上——**机制能力反过来约束接口设计**。
2. **能做成"不可表达"的，就不要退而求其次做成"检查"。**
3. **没有判断的地方，不要放模型。想让一个 agent "足够笨"，最笨的办法是不用 agent。**

第二条有三个用法，一个比一个省事：

- **不可表达**：想强制"不许单窗打分"，不是加检查，而是让打分函数只接受多窗输入、只返回最差分——单窗打分函数根本不存在
- **抛异常而不是警告**
- **让遗漏自动显形为缺席**：比如归因榜规定"未声明量纲的 gate 直接落进 `excluded_no_unit`，不进榜"。想让自己的 gate 被看见，唯一办法就是去声明量纲——**没有人需要检查谁没声明，缺失自己就暴露了**。这一条把"合规"从成本变成了进入门票。

第二条有个高频误用要防：它**不是**"不要有开关"。可操作的形式是：**不要新增一条通往错误的表达路径，判据是相对现状的净增净减。** 同一份规格里的两个开关，用这条一算就清楚——把默认选点从 argmax 改成"平台中心"、argmax 降级为需写明理由的选项，错误路径净减少，该加；给"单窗排序"加一个受支持的模式开关，它现在只是"不是默认输出"，加了开关就成了一等公民，错误路径净增加，不该加。

三条的共同内核可以当一句话记：

> **把该发生的事，挂到必然会到达的位置上——而不是写成一句提醒。**

### 为什么需要工作流，而不是"写一份更好的建议"

这是整份研究里最强的一条论据，而且它是核实出来的事实：

一份既往研究里那句"需要用户提供 2-3 个具体漏检样本做 replay 验证"，**被三个不同的 agent 在四个地方独立写下，然后全部落空**——一次都没发生。

**所以：写进报告的建议不会被执行。** 每个设计步骤都必须回答"这一步靠什么机制强制发生"，"文档里写了要做 X"不算答案。

（研究组也坦白了这里的自指弱点：任何"落盘阻塞文件 + 每次调用先检测"的方案，本身也是一条约定在强制另一条约定。唯一的缓解是把检测放进一个物理入口。这个弱点没被掩饰。）

### 判死的那些做法

ralph-loop 当搜索循环（收敛判据由模型自我裁定）、cron（连"每晚跑一次"都做不到）、hook 当强制（拦不住脚本内部）、agent team 当搜索循环（无控制流无 schema 无 resume，成本翻 N 倍）、让 agent 直接读结果 JSON 挑最优（一份结果 25k token，而且 LLM 排序不可靠）、**fan-out 并行评估（伪并行——单个全宇宙 eval 已经吃满 CPU，K=2 和 K=4 实测都比串行更慢）**、多保真度（抽样子集在关键区间失效，真 top10 内的秩相关崩到 0.47）。

还有三个写脚本时会踩的实测坑，其中一个值得推广成通用规则：**动态模块重导入会静默串版本**——fork 型进程池里，已经 import 过某模块名的 worker 会把旧版本留在自己的 `sys.modules` 里，导致同一批候选评估静默混用两个版本的代码，不报错、不崩、结果是两版的混合物，**单次调用是假绿，连续 6 次以上覆盖才暴露**。

> **通用规则：凡是要批量评估 N 个候选的 harness，它自身的正确性必须由"多候选差分自测"证明，单候选冒烟测试一律视为未测。**

这已经是本项目第三次出现"平凡场景测试通过、多候选差分才暴露"的同型缺陷了。

## 第五部分：你现在该做什么

### 唯一的行动项（半天，新建 0 个文件）

**把评估器每次都算了却丢掉的失败记录接出来，用无量纲口径聚合。**

它是你两个自陈劣势的共同解药：

- **"无法批量处理，需要一个一个排查"** → 全宇宙失败归因一次跑出来，因为数据早就在算了
- **"不知如何让 claude code 介入"** → LLM 顺着源码行号读代码就介入了

几条格式纪律（都踩过坑）：输出要做成"根因直方图 + 钻取"而不是"每票一行的排行榜"（gate 名称整个库里就十来个取值，一张十几行的表比几十条散文信息量大还省 token）；排序键不能用计数（计数会把结构性噪声顶到榜首），要用"计数 × 近失占比"；**近失占比必须先做尺度归一**（诊断字段常是裸价格差，5 美元的票和 500 美元的票不可比——试跑时两个 gate 的优先级在归一前后发生了反转）。

验收用"已知答案检验"：近失的 ATR 归一 p50 必须复现 0.653 / 0.385。**一条检验同时验了归一口径、ATR 窗、近失定义三件事**，比写三个单元测试省事。

### 顺带可以做的（两小时，零新建组件）

全旋钮单因子消融 + 结构消融（每个节点/where/边各删一次）。

**关键：这一步的产出是"敏感度图"（信息），不是"配置"（选择）。** 你不是要从里面挑最高分——那才受选择偏差惩罚；你是要知道哪些旋钮根本不动结果（试跑时找到了不止一个可证伪的 no-op）、哪些一动就翻天、删掉哪个节点分数不降。这张图不进定案，不消耗选择预算。

顺带一条：**任何自动搜索之前都该先跑一遍 no-op 探测剪枝**，几分钟的事。

### 现在不要做的

按五个阶段完整串起来、建 ledger 和阻塞闸。**先等阶段 0 的体检结论**——第一部分那些发现可能会改变整件事的形状。

## 第六部分：这套方法自己的软肋

研究组把局限一条条写出来了，值得原样保留：

- **这次把"优化"落到了"排除"上，但那是信噪比读数决定的，不是方法的主张。** 而那个读数有两层已知缺陷（用坏尺子量的、只覆盖机械邻域）。**修好目标函数之后必须重算，档位一变，排序类工具就该回桌。**
- **阶段 0 的七项检查是从一次试跑归纳的，不是穷举。** 波动率暴露那一项就是跑到一半才被逼出来的——最初的六项里没有它。**这说明这张清单还会长。**
- **"删除通道"这个盲区是从三个样本归纳的。** 三个不算多，但它有机制解释，不只是巧合。
- **本方法没有解决"如何生成好的语义候选"。** 它只能保证坏候选被挡住、好候选被公平比较。候选质量的上限仍然由人和 LLM 的领域理解决定，这一段没有被自动化，研究组也不认为它应该被自动化。
- **所有机器侧的强制都挂在评估器上，因此有一条零覆盖的旁路**：人直接改 `params.yaml` 然后收工、不跑任何评估。这是边界不是缺陷（不跑评估就没有"结论"需要被担保），但不该被掩饰——**它意味着这套东西保护的是"经过评估的决定"，不是"所有的改动"。**

## 最后：过程本身的一条教训

这次研究里，7 个角色先后推翻自己 15 次；复审阶段又抓到 lead 三次（挑子集读符号、转述时丢掉限定词、写了一句不实的自我表扬），累计 18 次。

**而这 18 次里，没有一次是被论证推翻的——全都是被实测数字推翻的。** 论证在这个团队里从来没能改变过任何人的结论。

被推翻的往往还是最漂亮的东西。有一个阈值是从一个看起来很优美的推导得来的（黄金比例），提出者自己复审时戳破了它：那个根号完全来自把对照基准换了一下，而换不换基准是选的、不是推的。他的自评值得原样留着：

> **"一个'推导'如果推出漂亮常数，最可能的解释是某个自由选择被审美锁定了。"**

还有一条关于转述的：**上游 agent 的转述比官方文档更不可信，因为它多了一次压缩。** 最微妙的一次是——一个数字在转述中**算术上完全正确**，错的是它的**证据等级**：原始测量里一半是端到端真跑、一半只是组件级验证，所以结论是推算值；转述一次之后，它变成了一个和真跑读数并列的数。

> **转述数字时必须连同证据等级一起转述。**

### 一个可检验的判据

这份报告最强的论据之一是"写进报告的建议不会被执行"。**它自己面临同样的风险。**

所以研究组给自己留了一个判据：**三个月后回头看，`gate_failures` 有没有真的被接出来。有，则这套东西活了；没有，则它是那条建议落空的第五个实例**——而那反而会成为它自己最强的一个证据。
