# 调参全流程（tune-gates）

本 skill 是调 path2 pattern 参数的唯一编排入口：从「这个 pattern 有没有底子」一直走到「定案写进正式参数」。某个特征、某道闸该不该存在，交给 feature-study 判断，本 skill 在需要时调用它；两个 skill 共用一本样本使用账本 `docs/sample_usage/<app>.jsonl`（环境变量 `TUNE_LEDGER_DIR` 可改目录）。

贯穿全程的三条原则：
- **调参只能把已有的优势磨锐**：没有底子时挑出来的好成绩是运气，所以先查底子再调。
- **每一次挑选都记账**：筛选、联合识别、单格查询每次调用各记一条；定案时报这组参数一共被比较过几次。
- **留出的两段验证数据只开一次**：调参结束、验证清单冻结之后，两段各开一次。

口径公式、输出目录布局、续跑规则、实证坑在 `reference.md`；bb_v1 的真实运行记录在 `apps/bb_v1/notes.md`；给用户看的「结果什么时候能信」在 `docs/explain/tune-gates_调参判据卡.md`。

## 一、阶段与调用面（Claude 用）

### 1. 八个阶段

| # | 阶段（对用户只说业务名） | 系统做什么 | 调用 | 停不停 |
|---|---|---|---|---|
| 1 | 开局核对 | 从数据文件的实际覆盖划出训练期与两段留出的验证数据，写进账本；在任何人看收益之前完成 | `open_round` | 不停 |
| 2 | 先看有没有底子 | 闸全部放开的版本（宽进点）与现在这套参数（工作点）各自对比同一天、同样波动水平的随机日，逐年判「有底子 / 还不能确定 / 没有」；同时算分辨力 | `edge` | 不停，结论并入停 1 |
| 3 | 定范围 + 开工确认 | 每个检测参数提现值、松一档、紧一档；剔除尺子参数与非法档；标出每道闸的准入类别；估算检测组合数与耗时。**不输出任何收益** | `propose_ranges` → 停 1 → `record_ruling` 记 `ranges` 与 `delta` | **停 1** |
| 4 | 筛参数 | 两个底座上逐个改一档、逐道关闸，同一段买点只计一次、误差按股去簇、整族多重比较校正；在役闸查「删了不亏」；另附两两翻转探针、分年与分时段旗标、换没换一批股票 | `install(stage="screen")` → `scan` → `compare` → `screen` | 不停 |
| 5 | 机制复核 | 要动的改动带提醒（效果依赖其他闸开不开、两年明显不一样、各时段时好时坏、可能换了一批股票）或有闸删了不亏时，合成一条消息问；采纳规则一并确认 | 停 2 → `record_ruling` 记 `mechanism` / `delete_gate` / `adoption_rule`；删闸后 `screen(working_point=…)` 重算 | **停 2**（有需要才出现） |
| 6 | 几个参数一起调 + 冻结清单 | 只把筛选里分辨得出的参数（及与它们有交互的）放进联合网格，参照格是工作点；样本只够一次改一个参数时退化为「在单个改动里挑」。之后按采纳规则展开决策映射、冻结验证清单、报预期把握 | `install(stage="grid")` → `scan` → `compare` → `find` →（`cell`）→ `preregister` → 通知 → `record_ruling("power_notified", manifest_hash=…)` | 不停；预期把握不到一半时停（条件停点） |
| 7 | 用没碰过的数据验证 | 两段各开一次，按清单检验；清单里有闸时在同一次开窗里补检 | `validate(confirm_window="backward")`、`validate(confirm_window="forward")`；闸的补检见 3.6 | 不停 |
| 8 | 定案 | 按事先写好的映射机械给结论；用户只能确认写入，或整体不写、维持现役 | 停 3 → `adopt` 或 `record_ruling("veto")` | **停 3** |

顺序的理由：
- **优势检查在一切调参之前**：没有底子时，调参挑出来的成绩是运气。
- **定范围在优势检查之后、筛选之前**：优势检查不看各档收益；看过各档收益再定范围，范围本身就成了又一次挑选。
- **机制复核在联合之前**：被人否掉的参数不该占联合网格的格数。
- **独立验证在定案之前**：定案时手上才有唯一无偏的数字。

### 2. 调用面

`.claude/skills/tune-gates/tune.py` 是唯一调用面。每个函数是薄包装，机械闸与拒绝理由（人话）都在被包装的模块里：

```python
import sys
sys.path.insert(0, ".claude/skills/tune-gates")
import tune
```

| 函数 | 做什么 | 要点 |
|---|---|---|
| `tune.status(app, *, cfg=None)` | 阶段推导（只读，不写任何文件） | 返回 `stages`（每阶段 `done` / `valid` / `why` / `evidence`）、`next`（`action`、`why`，可选 `stage` / `window` / `working_point` / `topic` / `confirm_window` / `earliest` / `basis`）、`half_states`、`text`（人话摘要）。怎么处理见「六」 |
| `tune.open_round(app, *, cfg=None)` | 开局核对 | 抽样 400 只股票探测数据起止与交易日历，按首部缓冲与标签前瞻期算出两段确认窗，写 `open`。上次划出的两段还没都验证过 → 拒绝 |
| `tune.record_ruling(app, topic, value, *, manifest_hash=None, note="")` | 记人工裁定 | topic 取 `ledger.RULING_TOPICS`；取值约定见 `reference.md` §13 |
| `tune.resolve_delta(app, cfg=None)` | 最小关心改进 δ（比例） | 最近一条 `delta` 裁定（点）÷100，没有则 `Settings.min_effect_pt`/100；优势检查、筛选、联合识别、feature-study 共用 |
| `tune.edge(app, *, wide_overrides=None, cfg=None, restart=False)` | 优势检查 | `wide_overrides` 缺省取该 app 最近一个窗口声明的放开值，一个都没有时必须显式给；返回 `report`、`verdicts`、`source_note`、`delta`、`m_estimate`（`m` / `detect_params` / `gates_in_service`）；`restart=True` 清掉上次的扫描结果重扫 |
| `tune.propose_ranges(app, *, app_module=None, base_yaml="params.yaml", cfg=None, sample_stocks=200)` | 定范围 | 六部分 `ruler` / `legality` / `admission` / `suggestions` / `screen_design` / `readonly_gates`，另附 `probe`、`unclassified`。是机械建议不是判断，译成人话交用户增删改 |
| `tune.install(app, *, window, stage, wide_overrides, scan_grid, where_levels, tight_wheres=None, app_module=None, base_yaml="params.yaml", cfg=None)` | 准入 + 写窗口声明 | `stage="screen"`（工作点 + 单翻转 + 两两翻转）或 `"grid"`（笛卡尔积）；准入没过一个文件都不写；工作点由正式参数自动推出。写声明会让**该窗口**已有的扫描结果作废，所以换参数就换新窗口名，不覆盖有扫描结果的窗口 |
| `tune.setup(app, *, window)` | 从窗口声明重建分类表 | 幂等；静态守卫在这里失败 |
| `tune.scan(app, *, window, label_mode="full", cfg=None, **overrides)` | 扫描出候选长表 | 最贵的一步，断点续跑；与确认窗重叠时自动改走延迟标签模式；返回 `label_mode`（实际模式）与 `n_shards`。`overrides` 覆盖 Settings 字段（如先 `ticker_regex="^A[A-C]"` 小范围试跑） |
| `tune.compare(app, *, window, cfg=None, **overrides)` | 一致性验证 | 返回 `mismatch`（日志没有结论行时为 None）；红线 `mismatch == 0` |
| `tune.screen(app, *, window, working_point=None, cfg=None, **overrides)` | 筛选 | 返回 `survivors`、`joint_axes`、`m`、`n_probes`、`report`、`out_dir`；`working_point`（{参数键: 值}）用于删闸后在新工作点上重算，不需要新扫描 |
| `tune.find(app, *, window, cfg=None, **overrides)` | 联合识别 | window = 联合窗口；返回 `verdict`、`center`（{参数键: 值}）、`n_evaluable`、`optimism`、`joint_axes`、`report` |
| `tune.cell(app, *, window, note="", **levels)` | 查联合网格里的单个组合 | levels 的键一律是参数键（`**{"section.field": 值}`），本窗网格的每个参数都要给；每次查询记一条账，note 写用途 |
| `tune.preregister(app, *, changes, window=None, rule="default", alpha=0.05, method="maxT", round_id=None, extra=None, cfg=None)` | 冻结验证清单 | changes = 候选配置的改动 {参数键: 新值}（改前值取训练窗口工作点；已落地定案的事后验证自动取定案前的旧值，见 3.5）；extra = 用户开工确认时另提的闸或同批特征，随清单一起冻结；window 缺省 = 最近一次联合识别或筛选用的窗口；会先对两段确认窗做不读涨跌结果的扫描；返回 `manifest_hash`、`expected_power`（`backward` / `forward`）、`needs_user_consent`、`survivorship`、`gate_family`、`configs`、`text` |
| `tune.validate(app, *, confirm_window, cfg=None, manifest_hash=None)` | 在一段确认窗上按清单检验一次 | confirm_window ∈ `backward` / `forward`；manifest_hash 缺省 = 最新一份清单；返回 `text`、`interpretation`、`validation`（两段都开完才非 None，原样交给 `adopt`） |
| `tune.confirm_rows(app, confirm_window, combo, gate_cols, *, manifest_hash=None)` | 确认窗上闸补检的取数口 | feature-study `fs.run` 在确认窗上的缺省取数入口，一般不直接调；读之前自己过确认窗守卫（这段没按这份清单开过、清单没带闸子族、或闸子族在这段已检过 → 一行都不读） |
| `tune.record_discovery(app, *, fc, axes, window, note, ref=None, label_horizon=None)` | 记一条发现 | 登记簿条目确认追加之后调；fc = 条目编号列表，axes = 参数键或 `feature:名`，window = 看过涨跌结果的买点区间 {start, end}；ref 缺省 = 登记簿当前哈希，label_horizon 缺省取 Settings。改闸 / 删闸定案之前必须先有 |
| `tune.adopt(app, *, window, changes, provisional, verified, selects_on, depends_on, reason, confirm=False, validation=None)` | 定案写入 | `confirm=False` 只返回 diff 与检查（含比较次数 `checks["looks_text"]`）；三种用法见 3.7 |
| `tune.retire(app, *, confirm=False, delete_notes=False)` | app 退役清理 | `confirm=False` 只返回清单；复盘笔记默认保留，账本永不删 |

**Settings**（`tune.Settings`，frozen）：
- ★ 字段 `start_date` / `end_date` / `head_buffer` / `label_horizon` / `first_passage_k` / `price_min` / `price_max` / `volume_min` 决定「这批扫描结果测的是什么」。它们与研究声明、检测源码、底座、尺子四个指纹和标签模式一起进 `study_io.RUN_CALIBER`：同一窗口下任一项变了，续扫被拒绝，要换 window。
- 其余字段随便改：`ticker_regex`、`shard_stocks`、`workers`、`cmp_*`、`b_boot`、`boot_seed`、`split_half_seeds`、`top_n` 等。
- 预算与筛选：`min_effect_pt=2.0`（最小关心改进，点）、`min_segments_floor=30`（每折买点事件数下限）、`screen_fdr_q=0.10`、`noninferiority_pt=None`（None 取 `min_effect_pt`）。
- `data_dir` 默认读 `configs/path2_web.yaml` 的 `dataset_dir`。

**窗口**：研究声明是窗口级的，`apps/<app>/windows/<window>/{study.py, classification.json}`，app 级只留 `notes.md`；输出在 `outputs/tune_gates/<app>/<window>/`。
- 筛选窗口与联合窗口分开建：两份声明各有指纹，互不作废。两者放在同一输出根下，联合识别按筛选记录里的窗口名去找筛选扫描。
- `edge`（优势检查目录）与 `confirm_<backward|forward>_<8 位哈希>`（确认窗扫描）由系统生成，别手工占用这两类名字。

### 3. 各步要点

#### 3.1 开局核对

- `open_round` 抽样探测实际数据覆盖。训练期 = Settings 的买点区间；两段确认窗与训练期之间各隔一个标签前瞻期，边界不靠人记。
- 所有读涨跌结果的入口（`scan` 完整标签模式、`edge`、`screen`、`find`、`cell`、`preregister`、`validate`、`confirm_rows`，以及 feature-study 的取数）先过确认窗守卫：没有开局核对记录 → 拒绝；读取区间（买点区间 + 其后的标签窗）与任一确认窗重叠 → 拒绝。
- 现役参数里有暂定定案（状态摘要里是「定案已落地、待独立验证」）时，停 1 说明留出的两段数据最后会连它一起验。

#### 3.2 先看有没有底子

- 单配置扫描，输出在 `outputs/tune_gates/<app>/edge/`，只许训练期：检测参数取正式值，闸按放开值构造，每个样本 bar 写一行，另写逐日基线。
- 两个比较点：宽进点 = 全部行去重；工作点 = 同一买点日的多行里任一行过全部正式闸即算过。
- 判读（逐年 + 合并）：误差下限 > 0 → 有底子；误差上限 < δ → 没有；其余 → 还不能确定。宽进点不是有底子、工作点是 → 底子来自现在开着的闸。基线定向日不足 20 的层不参与比较，覆盖率低于 80% 时报告会提醒。
- 分辨力：工作点按股去簇的误差、设计效应、定向占比取本次实测；改动后的买点保留比例在筛选之前只能用标定先验，由它算出的分辨力标「估计」。公式见 `reference.md` §8。
- 对比族大小 m 在筛选之前只能预估 = 2 ×（检测参数个数 × 2 + 在役闸数）：每个检测参数按松一档、紧一档两个替代档计，尺子参数不计；报告与记录标「预估」。
- δ 取 `resolve_delta`：第一次跑时还没有 δ 裁定，按默认值判「没有」。停 1 用户定了别的 δ，记完裁定后重跑一次 `edge`（扫描结果复用），让「没有」的判读按新标准算。

#### 3.3 定范围（停 1 的素材）

`propose_ranges` 六部分这样译给用户：
- ① 尺子（`ruler`）：持有多久、涨跌多少才算数、基线怎么算，都不参与调；某个参数换档会让买点换到别的 node 上 → 它也是尺子，不进网格；首部缓冲不够的档剔除。
- ② 逐档合法性（`legality`）：非法档的原因原样译成人话；等价档合并，说「这个取值在机制上等于没设，自动跳过」。
- ③ 闸的准入（`admission`）三类：确实有用（可以取多档）/ 在役未审定（只许开、关两档，只查删了亏不亏）/ 未在役且未审定（不进这一轮，想加先交 feature-study 验证）。检测参数不看准入。
- ④ 建议松 / 紧一档（`suggestions`）：候选来自代码默认值、参数文件注释、按正式值铺的阶梯、feature-study 的建议档、优势检查样本的分位；检测参数的紧档要求保留 30%~70% 的买点（无标签探针计数）。
- ⑤ 筛选的检测组合数与耗时（`screen_design`）。
- ⑥ 只读闸清单（`readonly_gates`）：参数键 → node.field + 运算符 + 正式值。
- `unclassified` 里判断不了类型的参数，把原因原样带给用户，不悄悄丢弃、不强行分组。

用户定完：`record_ruling(app, "ranges", …)`、`record_ruling(app, "delta", 点数)`。

#### 3.4 筛选扫描、联合扫描、一致性验证、联合识别

**筛选扫描**：`install(app, window=<筛选窗口>, stage="screen", …)` → `scan` → `compare` → `screen`。
- 准入：检测参数每维 ≤3 档、含正式值、没有等价档；在役未审定闸档位恰为 [最松档, 正式值]；where 阈值在放开值里不紧于最松档。
- 入口（机械闸 8 等）：账本有优势检查记录且那之后代码没变；一致性验证跑完且全部对上；窗口工作点覆盖全部轴；确认窗守卫放行。
- 对比族 = 两个底座（工作点为主、宽进点作旗标）×（每个检测参数的每个翻转档 + 每道在役闸「关 − 开」）。两年合并的按股去簇 z 在整族上做多重比较，q = `screen_fdr_q`，族大小 = 实际对比数。
- 旗标：分年 z；年交互 z（|z|>2）；按标签前瞻期等长时间窗的异质性检验（p<0.05）；两个底座的差中差（效果依赖其他闸）；换没换一批股票（两臂对逐日基线的层匹配差之差 ≥ δ/2）。
- 在役闸：工作点「关 − 开」原始差的单侧 95% 下界 ≥ −δ → 删了不亏。
- 交互兜底：两两翻转探针 |z|≥2 且一方已幸存 → 另一方也进联合，结果在 `joint_axes`。
- 产物在 `<window>/screen_<工作点哈希前 8 位>/`：`report.md`（人话）、`contrasts.csv`、`probes.csv`、`fc_drafts.md`（待验证行草稿）、`result.json`；最后写 `select`。
- 删闸：用户在停 2 同意后，先把 `fc_drafts.md` 里这道闸的草稿确认后追加进 `docs/feature_candidates.md` 并用 `record_discovery` 记账（见 3.7），再 `record_ruling(app, "delete_gate", {参数键: 关闸值})`、`screen(app, window=…, working_point={参数键: 关闸值})`。决定不删记 `record_ruling(app, "delete_gate", {})`。

**联合扫描**：`install(app, window=<联合窗口>, stage="grid", …)` → `scan` → `compare`。网格里档数 > 1 的参数必须 ⊆ 筛选的 `joint_axes`，其余参数单档取正式值。

**一致性验证**：每个要做筛选或联合识别的窗口都要有自己的验证日志——跑完、`mismatch == 0`、比过的股票不少于 500 只（扫描范围本身不到 500 只时须全部比过），且日志首行记录的研究声明与尺子版本与现在相同，否则 `screen` / `find` 拒绝；抽样不够时 `compare` 直接拒绝执行，放宽 `cmp_ticker_regex` 再做。确认窗扫描不要求。为什么是 app × 拓扑 × 分类的联合性质、抽样覆盖与耗时见 `reference.md` §2。

**联合识别** `find`：
- 入口（机械闸 1、2）拒绝：窗口工作点没覆盖全部轴；同一段训练期上没有工作点一致的筛选记录；网格里要调的参数超出 `joint_axes`；筛选扫描结果不在或与本窗口径 / 代码不同；没有优势检查实测（功效线要用）。
- 功效线 = ceil(n_pl(δ))，设计效应与定向占比取最近一次优势检查实测。可评估 = 每折四态总数 ≥ 功效线、每折买点事件数 ≥ `min_segments_floor`、且不是退化格（收紧一档一个买点事件都没多筛掉）。
- 参照格 = 工作点；两折取较差 → r=1 邻域最小 → 排序；联合网格之外的单翻转 / 两两翻转格由筛选扫描补上。
- 校正：按股 bootstrap 连筛选一起重做（每个副本先重挑「一起调」的参数，再重做联合挑选），optimism 是真实外推损失的下界；对半分验证在联合网格内照报。
- 机械闸 2 的两种拒绝：
  - 「样本只够一次改一个参数」（同时移动两个及以上参数的格一个都不可评估）→ 退化为在单个改动里挑：候选只放一个改动（筛选里工作点上分辨得出、证据最强的那个），直接 `preregister`，window 用筛选窗口。
  - 「样本只够维持现值」→ 维持现役；本轮只剩删了不亏的闸可以走验证。
- 产物：`cells.npz`（全量格张量，买点事件口径）、`cells.csv`（候选格排名前 5000）、`region_report.md`；最后写 `select`。
- 查任意组合走 `cell`，不要去 `cells.csv` 里捞；每查一次记一次账，查之前想清楚用途。
- 推荐取值落在试的范围边上：扩大范围重扫耗时 30 分钟以内自动扩，记 `record_ruling(app, "expand_range", …)`（算又挑一次）；超过就问。

#### 3.5 冻结验证清单

- `preregister(app, changes=…)`。候选配置 K = 联合识别的 `center` 相对工作点的改动；退化时是单个改动；只删闸时是 {参数键: 关闸值}；已落地定案的事后验证时是 {参数键: 现值}（见下）。
- 系统做：
  1. 谓词类参数改到最松档归「删闸」（检验不比改前差），其余归「检测参数」（检验更好）；
  2. 按默认采纳规则（整套 → 按训练 z 从强到弱的每个单项 → 维持改前）展开确认子族与决策映射，含检测参数的比较用优效、只含删闸的用非劣效；
  3. 冻结确认窗怎么扫；两段确认窗各做一次不读涨跌结果的扫描，按买点事件数把训练误差换算成窗口误差；
  4. 预期把握：往前那段 = 映射第一项同时通过的概率（效应扣掉联合识别报的挑选偏差）；往后那段 = 整套改动不比改前差且方向一致的概率；
  5. 幸存者偏差预检；
  6. feature-study 的闸子族（K 里保留的在役闸）非空时并进清单；
  7. 写 `preregister`。
- 采纳规则只实现了默认一种（`rule="default"`）；用户要别的规则时如实说做不到。
- 之后把 `text` 里的预期把握告诉用户（两段都不低于一半时是一条不打断的通知），再 `record_ruling(app, "power_notified", True, manifest_hash=h)`。`needs_user_consent=True` 时走条件停点；用户同意照样打开 → `record_ruling(app, "open_low_power", <确认窗名>, manifest_hash=h)`。
- 用户在停 1 另提的想法（加一道候选闸、改在役闸的切点、同批验证的特征）用 `extra` 原样交给 feature-study 的闸子族，随这份清单一起冻结、在同一次开窗里检验；元素格式见 `fs.plan` 的 extra 参数。开窗之后再提的只能排到下一批。
- **已落地定案的事后验证**（状态摘要「定案已落地、待独立验证」，下一步就是 `preregister`）：直接 `preregister(app, changes={参数键: 现值})`。新值等于正式参数现值、且账本里该参数最近一条定案的新值就是它时，改前值自动取那条定案的旧值（「改前」= 定案前，「整套」= 现值）；只写了检测参数的旧窗口，工作点缺的轴取正式参数现值；改前、改后值落不到训练窗口的档位上 → 拒绝。之后照常告知预期把握、两段各开一次，停 3 按 3.7 的「已落地定案记验证结论」或「撤回」落账。
- 确认窗扫描声明照抄冻结清单，不经参数准入。轮外的 feature-study 闸清单不挡开窗：守卫判「清单是否最新」只在调参验证清单之间比。

#### 3.6 用没碰过的数据验证

- `validate(app, confirm_window="backward")`、`validate(app, confirm_window="forward")` 各一次。
- 守卫拒绝条件（任一成立，一个标签都不读）：这份清单没有冻结记录，或冻结不早于开窗；没告知预期把握；该段把握不到一半且用户没同意；该段已开过；清单不是最新一份。
- 过守卫后：按清单冻结的扫描声明做延迟标签扫描（续跑）→ 核对冻结后代码没变 → 现算涨跌结果写 `labels/` → 按买点事件口径汇总。
  - 往前那段：族内逐步 max-T（清单冻结的方法）→ 按映射选配置；幸存者偏差旗标为真时主确认按「不显著」读。
  - 往后那段：映射选出的配置（没选出时用整套改动）相对改前，查不比改前差出 δ 以上、方向与训练期一致。
  - 两段齐了按判读表给结论（`interpretation`）。结果写确认窗扫描目录下 `<清单哈希前 12 位>_<确认窗>.json`，再写 `extrapolate`。
- 判读表（主确认 × 往后核对）：
  - 往后那段比改前差出容忍范围 → 撤回（不看主确认）；
  - 主确认显著 + 往后同号 → 采纳；主确认显著 + 往后反号 → 暂定采纳，往后数据攒满 1 年复验；
  - 主确认不显著 + 往后同号 → 暂定采纳；主确认不显著 + 往后反号 → 不写进正式参数（已在正式参数里的维持暂定），攒满 1 年复验。
- **闸的补检**（清单带闸子族时，每段开完后做；状态里是 `gate_family_check`）：按 feature-study skill 的方式加载 `fs`，取账本里这份清单的 `manifest["gate_family"]`，然后

```python
plan = fs.default_plan_dir(app, gate_family["window"], gate_family) / "plan.json"
res = fs.run(plan, confirm_window=w, manifest_hash=h)
fs.close(plan, res)
```

#### 3.7 定案（停 3 之后）

- **普通定案**（候选还没写进正式参数）：`adopt(app, window=<训练窗口>, changes=<映射选出的配置>, provisional=<判读是暂定采纳>, verified=True, selects_on=<挑选过的参数键>, depends_on=<效果依赖的其他参数的现值>, reason=…)`。先 `confirm=False` 看 diff 与比较次数，用户确认后 `confirm=True`。`depends_on` 取筛选报告里标了「效果依赖其他闸开不开」的那几道闸的现值，没有就给空 dict。
- **已落地定案记验证结论**（接 3.5 的已落地定案事后验证）：changes = {参数键: 现值}，`validation` = `validate` 返回的 validation，`verified=True`，provisional 按判读；值不变，参数文件注释追加一行验证结论。
- **撤回**：changes = {参数键: 定案前的旧值}，普通写入。
- **整体否决 / 按判读表不写**：`record_ruling(app, "veto", True, note=<理由>)`；两段数据照样算用掉。
- **改闸或删闸之前必须反向登记**：账本里要有该参数的发现记录，否则 `adopt` 拒绝。草稿确认后追加进 `docs/feature_candidates.md`，再 `record_discovery(app, fc=["FC-0xx"], axes=["section.field"], window={"start": <训练期起>, "end": <训练期止>}, note=<出处>)`。

- 未经独立验证的定案，参数文件注释与账本双标注；`depends_on` 里的背景参数之后变了，状态会报需复核。

## 二、什么时候停下来问用户

其余情形——参数怎么翻译、什么时候该扫、日志怎么读、数据怎么分段、每个参数试几档、冻结验证清单、断点续跑、归因与冲突拆解、删闸验证不过时按事先写好的规则退回——都自己定、只报结果。**同一时刻碰到多个停点，合并成一条消息问。**

交付筛选、一起调或验证的结果，或用户想自己判断「结果能不能信」时，把 `docs/explain/tune-gates_调参判据卡.md` 发给用户。

每个「有用 / 没用」的说法都带两样东西：这份数据能分辨多大的差别（超不出就说「分辨不出」，不说「没用」）；效果靠多少段买点撑着。

### 1. 三个停点与条件停点

#### 停 1 · 开工确认（定范围之后、开始筛参数之前）

必须包含：底子逐年说；分辨力（筛参数时、只验一个事先写好的改动时、同时改两个参数时）；请用户定「改进不到几个点不算数」，说清它用在三处、开跑后不能改；每个检测参数的松紧取值，范围最好现在定死；闸这一轮只查「删了不亏」；两段留出数据的起止与「各用一次」；有别的想法现在说；总耗时，超过半小时的一致性验证在这里一并批准。

> 先看了一眼底子。最宽松的版本和同一天、同样波动水平的随机日比，首次穿越率（先碰到上方目标线的比例）［某年］高约［a］个点，误差下限刚过 0，算有底子但不厚；［另一年］高约［b］个点，但误差范围从［c］到［d］，还不能排除其实没有优势。调参只能把已有的优势磨得更锐，所以后面每个结论我都分年说。你要是觉得该先回去改结构，现在说。
>
> 再说这份数据能分辨多大的差别。算上同一只股票反复出现、同一段买点被好几条命中共享，筛参数时要一起比一大批改动，大约［x］个点以上的差别才分辨得出；最后只验一个事先写好的改动时约［y］个点；同时改两个参数，这个数还要再大七成左右。［改动后买点能留下多少，现在只能按经验估，所以这几个数是估计。］
>
> 我按「改进不到［2］个点不算数」来规划。这个数用在三处：判断底子有没有、判断一个改动有没有用、判断一道闸删了亏不亏。有个后果先说清：两年数据下，底子这一项几乎不可能判成「没有」，多半只能判成「还不能确定」。这个标准要在开跑前定，看完结果再改，就等于换一条及格线重挑。你觉得几个点才值得改，现在说。
>
> 接下来我打算把［n］个检测参数各试松、紧一档，看单独动它有没有用，取值如下［表］。范围最好现在定死，看完结果再改范围，等于在同一份数据上多挑一次。单个参数的效果比分辨力小时，我会如实报「分辨不出」，那时维持现在的参数是正常结局。
>
> 闸这边：闸有没有用，要在时间上没碰过的数据里复现才算数，所以这一轮对闸只查「删了不亏」。［这几道］还没被单独验证过的闸，只比开着和关掉两种；［这几道］现在没在用、也没验证过的，不进这一轮，想加得先单独验证。
>
> 没碰过的数据留了两段，都放到最后、各用一次：往前一段是［起止］，往后一段是［起止］。候选定下后，我会报这次验证大约有几成把握［；上次暂定写进正式参数的［改动］也一起验］。如果你有别的想法要验证（某个特征、某道闸有没有用），现在说，它会和候选改动放进同一份清单一起验；开窗之后再提的，只能排到下一批。
>
> 全部跑完大约［N］分钟［，其中一致性验证约［M］分钟］。可以的话我就开始。

示例（bb_v1 上约）：底子 2025 年有但不厚、2024 年还不能排除是 0；筛参数时约 4.8 个点以上才分辨得出，只验一个事先写好的改动约 3.5 个点。

#### 停 2 · 机制复核（筛参数之后；要动的改动带提醒、或有闸删了不亏时才出现）

必须包含：筛选结果一句话（「一共比了 N 个改动，k 个分辨得出」，刚过线的说「刚过线」）；需要人判断的机制；删了不亏的闸——买点变化、是不是走势定义的一部分、这是初步结论、验证不过按规则退回；改进伴随买点少三成以上时的质量与数量取舍；采纳规则，必须在打开验证数据之前定。

> 筛完了：一共比了［N］个改动，［k］个分辨得出［，其中［参数］刚过线］，其余的差别在分辨力以内。
>
> 「［参数］」需要你判断一下：［收紧它，首次穿越率往上走，但买点少三成；它本质上是「多等几天再买」，可能只是在跟趋势，不是更会挑股票］。要把它放进下一步一起调吗？
>
> 「［参数］」的好处靠每年约［n］段买点撑着，［而且只在现在这几道闸开着时才出现，闸全放开时为零］。我会记下它依赖这几道闸，以后动这些闸要复核。
>
> 另外有［m］道闸关掉之后，首次穿越率最坏也只差［x］个点以内，删了不亏，买点还能多［p%］：［闸名］。删之前确认一下：它们是不是你心目中这个走势定义的一部分？是的话我只把它固定在现在的值、不删；不是的话，它会和其他改动一起放进最后那份验证清单。这是按调参数据得出的初步结论，最终要等验证完；到时不满足「删了不亏」，就按下面的规则退回，不再另外问你。
>
> 最后定一下验证完之后怎么采纳，这个规则现在定、验完不能改：按训练数据上各改动单独贡献多大排，［整套改动全部通过就全改；否则只改证据最强的那一项；再不行只改次强的那一项；都不过就维持现在］。规则里列的组合越多，每一套验出来的把握越低。

#### 条件停点 · 验证把握不到一半（冻结验证清单之后、打开验证数据之前）

> 候选定下来了：［改动］。按你定的规则，验证完之后会在这几套里选：［映射］。
>
> 开窗之前要先问你一件事。往前那段没碰过的数据只能用一次，也不会随时间变长。扣掉训练期反复挑选带来的虚高，再算上这次一共要验［k］套，验出结论的把握只有约［x］成。现在用，多半得到「分辨不出」，这段数据也就用掉了。
> - 现在就验：有约［x］成机会得到确认；分辨不出时，只要最近几个月没有明显变差、方向一致，改动按「暂定」写。
> - 先留着往前那段：这一轮只核最近几个月，改动最多按「暂定」写。最近几个月的数据会越攒越多，往前那段不会。
> - 这轮不改，维持现在这套。
>
> ［没有别的更大候选在排队的话，我倾向现在就验。］

把握都不低于一半时不停，只发一条通知：

> 验证清单定好了：［改动］，验证完按［映射］选。往前那段验出结论的把握约［x］成，往后那段核对通过的把握约［y］成。我接着打开这两段数据验证，完了告诉你结果。

#### 停 3 · 定案（两段验证数据都开完之后）

必须包含：按规则算出的结论；训练期两年读数、买点变化、扣掉挑选偏差后的数字、这组参数一共被比较过几次；往前那段读数（分辨得出 / 分辨不出，附事先估的把握）；往后那段读数（有没有明显变差、方向是否一致）；两段数据已用掉；只能确认写入或整体不写。

> 按事先定好的规则，这次的结论是：［采纳哪套配置 / 暂定采纳 / 撤回 / 维持现在］。依据如下。
> - 训练用的两年：首次穿越率分别 +［a］/ +［b］个点，买点数变成原来的［c］倍；扣掉反复挑选带来的虚高之后［仍然为正］；这组参数在训练数据上一共比较过［N］次。
> - 往前那段没碰过的数据（［起止］）：候选比现在高［d1］个点，［分辨得出 / 分辨不出，这次验证的把握本来约 x 成］。
> - 往后那段（［起止］）：高［d2］个点，［没有明显变差，方向和训练期一致］。
> - 两段都已用掉，以后不能再当独立检验。
>
> 这个结论是规则算出来的，不能换成别的组合，也不能只写其中一部分。要按它写进正式参数［并标「暂定」］吗？不写就维持现在这套，这两段数据照样算用掉；方便的话说一句为什么不写，我记下来。

用户想换一个组合采纳时：

> 这组结论是事先定好的规则算出来的。换组合、或者只写其中一部分，都等于在验证数据上又挑一次，这段数据就不算确认了。可以按规则写，也可以这次全部不写。

示例（bb_v1 上约）：2026-09-08 暂定写进正式参数的两处改动（提高突破幅度门槛、删掉峰龄闸），训练两年首次穿越率约 +2.3 / +3.9 个点，买点数约为原来的 1.05 倍。

### 2. 不可逆

- **退役清理**：「要把这个 pattern 的调参存档清掉吗？复盘笔记和样本使用记录我会保留，其余的删掉就找不回来了，确认吗？」
- **改衡量尺子**（持有期、目标线、首部缓冲、基线口径、训练时间窗）：「改了尺子就等于开一份新口径，之前所有结论都不能直接比，这一轮要从头来，确认吗？」
- **写入正式参数**：即停 3。
- **要验的候选不在事先写好的清单里**：「这个候选不在事先写好的清单里，用这段数据验它不算确认，还要验吗？」
- **验证把握不到一半时开窗**：即条件停点。

### 3. 超过半小时

- **扫描、一致性验证**：尽量并进停 1 一次批准，之后续跑不再问。单独碰到时：「接下来这一步大概要跑［N］分钟，我现在开始，跑完告诉你结果，可以吗？」

### 4. 真研究决定

- 停 1、停 2、条件停点、停 3。
- **没有底子**（两年都判「没有」）：「最宽松的版本两年都不比同样波动水平的随机日好。调参只能磨锐已有的优势，现在没有可磨的，从很多组合里挑出来的最好成绩多半是运气。我建议先停，回去改结构；要坚持调，结论会标『没有底子』。」
- **筛参数后没有分辨得出的改进**：「［N］个参数单独松紧，都没有大到这份数据分辨得出的改善，现在的参数保持。其中这几道闸关掉最坏也只差［x］个点以内，删了不亏，买点能多［p%］。要不要把它们放进验证清单？」
- **推荐取值落在试的范围边上、扩大范围要超过半小时**：「推荐的取值在试的范围边上，真正好的区域可能在外面。扩大范围重扫大约要［N］分钟，而且算又挑一次，要扩吗？」
- **改进伴随买点减少三成以上**（并入停 2 或停 3）：「这个改动首次穿越率 +［a］个点，但买点少［b%］。要质量还是要数量，是业务取舍，你定。」
- **两边说法相反、拆开之后仍冲突**：「两边说法相反，拆开之后仍然冲突：［两条结论］。可以先暂不采纳，也可以登记下来等数据攒够再核对，你定。」
- **独立验证没给出确认**：按停 3 模板说结论，并说明「同一段数据上不能再换别的候选验」。

### 5. 红线触发

- **一致性验证没通过**：「验证没通过，现在这批扫描结果不可信，我不会往下做筛选或一起调，得先查问题出在哪。」
- **旧结果复现不出来**：「上次这个 pattern 的扫描结果，用现在这份代码已经对不上了（代码或参数可能改过），这份存档不能再当结论用，要不要重新跑一遍？」
- **几种读数互相矛盾**（比如挑出来的分数看着不错，扣掉反复挑选带来的虚高之后翻了负）：「这次找出来的推荐组合，几种独立的检查方式结论对不上，不构成一个稳的推荐。我建议只取筛参数里最强、机制最清楚的那一个改动去验证，要不要这样？」
- **留着没碰过的数据已经用过**：「留着没碰过的数据已经在［日期］用来验证过［候选］了，再用它验新候选，结果会偏乐观。最早［日期］能攒出新的一段。」
- **本轮途中代码变了**：「从［阶段］开始的结论要重做，因为［检测逻辑 / 默认参数 / 涨跌结果的算法］在［日期］改过，大约要［时间］。」
- **单独验证用的数据和调参数据对不上**：「验证数据和调参数据对不上，这批验证不作数，闸暂时保持现状，我先查原因。」

## 四、判据与纪律

- **指标契约**：首次穿越率 = up/(up+down+both)，none 不进分母，按定向 bar 合并；边界宽度与前瞻期取 Settings 的 `first_passage_k`、`label_horizon`。前瞻收益只报幅度。win_rate 废弃：高基率 pattern 上它是基率复读，对子集区分无增量。
- **观测单位 = 买点事件**：同一检测组合内同一买点事件只计一次；任一前缀行过该格全部闸，就算这个买点事件过闸。口径细节见 `reference.md` §9。
- **误差按股去簇**：比率线性化残差按股求和、乘 n/(n−1)；时间维只作旗标。
- **最小关心改进 δ**：默认 2 点，停 1 由用户定，开跑后不改。三处共用：优势检查「没有」= 误差上限 < δ；feature-study「无信号」= 误差上限 < δ；「删了不亏」= 单侧 95% 下界 ≥ −δ。
- **一切判断带对照**：对照锚是同日同波动层的随机日、或改前配置；孤立数字（绝对计数、无基线的提升）不下结论。
- **算术效应归因**：改进要说清是选得准（换成了更好的样本）、买得低（入场价系统性下移）、还是买点窗口变了白拿；只有第一种算真改善，后两种在报告里点名。
- **推荐 ≠ 采用**：采用只经独立验证 + 停 3。

### 红线（硬约束）

- **顺序**：闸的存在先由 feature-study 定；检测参数在工作点上筛选；筛选里分辨得出的参数再一起调。
- **尺子不进网格**：持有期、目标线、基线口径、换档会让买点换到别的 node 上的参数，都不进网格（准入机械拒绝）。
- **先验有底子才调**：筛选入口要求本窗有优势检查记录、且那之后代码没变（机械闸 8）。两年都判「没有」时建议停，不硬调。
- **筛选在两个底座上做**：工作点为主，宽进点作旗标；平均主效应不等于工作点上的效应，不在两档全因子上取平均代替。
- **每次挑选都记账**：`screen` / `find` / `cell` 每次调用写一条 `select`；`adopt` 报这组参数累计被比较过几次。
- **新闸与移动在役闸阈值要 feature-study 结论**：调参数据只能给出「删了不亏」；未审定新闸由准入拒绝，在役未审定闸只许开 / 关两档。
- **调参证据改闸必须反向登记**：改闸或删闸定案之前，登记簿要有待验证条目、账本要有 `discover`（`adopt` 机械检查）。
- **两段确认窗各只能经 `validate` 打开一次**：调参前不开任何新数据（开局核对在看任何收益之前划窗）；开窗前冻结清单（候选、回退、决策映射、预期把握）并告知用户；与确认窗重叠的扫描只记买点事件、不算涨跌结果，清单冻结前读不到；禁止在同一段数据上换候选再验。
- **确认窗隔离与缓冲**：确认窗与训练期之间隔一个标签前瞻期（`open_round` 自动算）；训练与验证用同一首部缓冲——首部缓冲是隐式过滤器，别借缓冲差异改变事件集。
- **宽进时检测参数保持现役值**：闸可以全放开，检测参数松到病态会改变事件语义。
- **样本全程在场，不降功效线硬凑**：功效线由 δ 反推（买点事件口径 + 本窗实测设计效应），按格按折判；不可评估 ≠ 坏；小样本报计数不报比例。
- **分年只作旗标**：分年 z 与年交互 z 照报；两年同号不作门槛（零假设下同号概率就有一半）。
- **单闸结论可被组合推翻**：两两翻转探针 + 两个底座的差中差旗标；定案写 `depends_on`，背景变了复核。
- **联合空间，禁两段式**：闸与检测参数在同一张网格里一起算，不在宽进态找区、再事后单独收紧闸。
- **联合放在减法之后**：`find` 要求先有筛选记录，网格里要调的参数 ⊆ 筛选的「一起调」参数（机械闸 1）。
- **不取 argmax、不用绝对阈值选区**：两折取较差 → r=1 邻域最小 → 排序；选平台不选峰值。
- **选择后必须校正**：bootstrap 连筛选一起重做，结果视为外推损失的下界；对半分验证照报；朴素分数单独为正不下结论。
- **折计数、功效线、参照增量必须同口径**：不同首部缓冲、不同标签模式的扫描结果不跨表比较（续扫口径冲突机械拒绝）。
- **不引入优化 / 采样框架**（optuna / LHS / GP / racing）。
- **先一致性验证、后读结果**：`screen` / `find` 入口核验证日志。

## 五、失败与降级

| 情形 | 用户看到 | 默认处置 |
|---|---|---|
| 两年都没有底子（误差上限低于 δ） | 「没有可磨的，挑出来的好成绩多半是运气」 | 建议停、回去改结构；坚持调则结论标「没有底子」 |
| 只有一年证实或两年都未证实 | 并入停 1，逐年说 | 继续，结论带「底子未证实」 |
| 筛选后没有分辨得出的改进 | 「单独松紧都没有大到分辨得出；其中这几道闸删了不亏」 | 维持现役，或走删闸 + 验证 |
| 现役参数最近的改动本身在分辨力以内 | 「不一定错，但也没被证明是改进」 | 放进验证清单做独立验证 |
| feature-study 判某道闸挑的是低波动率的票 | 「它靠挑低波动的票；删掉会真的损失，保持现状；要不要改成明确的波动率条件属于改结构」 | 固定现值，不问 |
| 两边结论方向相反 | 自动拆解（feature-study 对账），拆得开就在报告里说明 | 拆不开才停 |
| 推荐取值落在范围边缘 | 「真正好的区域可能在外面」 | 耗时 30 分钟以内自动扩（记一次挑选），超过就问 |
| 样本只够一次改一个参数（`find` 拒绝） | 「同时改两个时，误差比你关心的改进还大」 | 只在单个改动里挑 |
| 样本只够维持现值（`find` 拒绝） | 「改动任何一个参数，样本都不够分辨你关心的差别」 | 维持现役；删了不亏的闸仍可走验证 |
| 改进伴随买点减少超过三成 | 并入停 2 或停 3 | 由用户在质量和数量之间取舍 |
| 独立验证否定或没给出确认 | 按判读表的人话 | 撤回或暂定；禁止在同一段数据上换候选再验 |
| 留着没碰过的数据已经用完 | 「它在某日已经用来验过某候选，再验会偏乐观」 | 等数据积累，报状态里的最早日期 |
| 停 2 同意删的闸在验证里不满足「删了不亏」 | 停 3 里说「按事先写好的规则保留它」 | 按映射退到不含删闸的配置，不临时问 |
| 用户在停 3 想换组合 | 「换组合等于在验证数据上又挑一次」 | 按规则写，或这次全部不写 |
| feature-study 的自检门失败 | 「这批验证不作数，闸暂时保持现状」 | 这批判定作废，调参继续 |
| 本轮途中代码变了 | 「从某阶段开始的结论要重做，大约要多久」 | 状态里 `confirm_redo`，确认后重做受影响的部分 |

## 六、状态探测与入口协议

### 入口协议（换 app 或复用已有 app 必走，Claude 不许跳）

用户指明 app X 后：

```
1. 接入了没有:path2_apps/X 能 import、导出 eval_meta(没有就先补,web 与本 skill 都认它)
2. 已有窗口声明与分类表对得上吗(apps/X/windows/ 下逐个窗口):
   ├─ study_io.check_study_matches(分类表, study_path) 不通过 → tune.setup(X, window=…) 重建分类表
   └─ 想看是检测源码、底座还是声明变了 → study_io.check_report(...) 三行对比;重不重建由用户裁定
3. 已有扫描结果还能用当前代码再生吗:study_io.check_regenerable(<窗口输出目录>/longtable)
   └─ (False, 原因) → 红线「旧结果复现不出来」,问要不要换新窗口重扫
4. tune.status(X) → 按 next.action 走(下表);next.action = none 时报 next.why
```

`check_regenerable` 的 True 只表示「没发现不可再生的证据」，已知盲区见它的 docstring。

### next.action 怎么处理

一轮从选参（优势检查、筛选、联合调参、单格查询及它们的裁定）开始，到定案或整体否决结束；定案结论按账本分五种：整体否决、已通过独立验证、独立验证后暂定采纳、独立验证后已撤回、还没经过独立验证（可带暂定）。确认窗扫描目录按 `tune.CONFIRM_PREFIX` + `backward|forward` + 8 位哈希识别，归属本轮清单的续跑直接给成 `preregister` / `validate`，没用上的清单留下的只作附注。

`status` 按五步顺序给出第一件要做的事：① 有被打断的长任务 → ② 指纹漂移（正式参数、检测代码、尺子、训练数据范围变过；定案背景变了）→ ③ 待落账的人工裁定 → ④ 最早未完成的阶段 → ⑤ 全部完成。对用户说 `text` 里的话即可，下表是 Claude 自己接着做什么。某一步的结果文件在、账本没记录时，`status` 给的就是那一步本身（带 `window` 或 `confirm_window`）：重跑补上记录，扫描结果与已算好的涨跌结果复用，结论不变，不算多挑一次或多开一次。

| action | 什么时候出现 | 对用户怎么说 | 自己接着做什么 |
|---|---|---|---|
| `resume_scan` | 训练扫描或优势检查的扫描有没提交的分片、或还有股票没扫完 | 「接着把没扫完的扫描跑完，还剩约［N］只股票」 | `next.window` 是 `edge` → `edge(app)`；其余 → `scan(app, window=next.window)`，Settings 与上次相同 |
| `rescan` | 有分片却没有提交清单：第一批结果提交之前就被打断 | 「这批扫描判断不了是否完整，清掉重扫」 | 优势检查 → `edge(app, restart=True)`；窗口 → 清掉该窗口的 `longtable/`、`baseline/`、`segments/` 分片与提交清单后 `scan`；确认窗扫描目录（带 `confirm_window`）→ 清掉后重调 `preregister`（清单还没冻结）或 `validate` |
| `rerun_compare` | 一致性验证日志在、没有结论行 | 「上次验证没跑完，要重跑」 | `compare(app, window=next.window)` |
| `confirm_redo` | 正式参数 / 检测代码 / 涨跌结果的算法 / 训练数据范围在某些阶段之后变过 | 「从［阶段］开始的结论要重做，因为……，大约要［时间］」 | 问是不是有意的；是 → 从 `next.stage` 起按阶段重做（改了声明就换新窗口） |
| `review_background` | 仍在生效的定案依赖的背景参数变了 | 「这条定案是在旧设置下做的，现在设置变了，我在现在的设置下复核一下」 | 不问，在现在的正式参数上新开筛选窗口重做筛选，看这条改动是否仍分辨得出、方向是否一致，结论在下一次汇报里说 |
| `open_round` | 还没开局核对；或这次开局核对留出的数据已被别的清单用过 | 「先做开局核对」/「留出的验证数据已经用过，要重新划」 | `open_round(app)` |
| `ask_ruling` | 裁定问过但没落账；`next.topic` 说是哪一项 | 带着已有证据重问，不重算 | `ranges` / `delta` → 停 1；`mechanism` → 停 2；`power_notified` → 发预期把握通知；`open_low_power` → 条件停点；`decide` → 停 3。答复后 `record_ruling` 或 `adopt` |
| `gate_family_check` | 某段验证数据已开、清单里保留的闸还没补检 | 「在这段留出的数据上补检清单里保留的闸，同一份清单，不算再开一次」 | 3.6 的 `fs.run` + `fs.close` |
| `edge` | 还没做优势检查；或优势检查报告在、账本没记录 | 「先看这个 pattern 有没有底子」/「上次的结果没记上，重跑一下补上，结论不变」 | `edge(app)`（扫描结果复用）；之后 `propose_ranges` 备停 1 |
| `screen` | 还没做筛选；带 `window` 时是该窗口的筛选报告在、账本没记录；带 `window` 与 `working_point` 时是删闸裁定之后要在新参数上重算 | 「开始把每个参数单独松紧一档筛一遍」/「在删闸之后的参数上重算筛选，不用重新扫描」 | 带 `window` → `screen(app, window=next.window, working_point=next.working_point)`（没有 working_point 就不传）；否则没有筛选窗口 → `install(stage="screen")` → `scan` → `compare` → `screen` |
| `find` | 还没做联合调参；带 `window` 时是该窗口的联合识别报告在、账本没记录 | 「开始几个参数一起调」 | 带 `window` → `find(app, window=next.window)`；否则没有联合窗口 → `install(stage="grid")` → `scan` → `compare` → `find` |
| `preregister` | 还没冻结验证清单（含已落地定案待独立验证）；或冻结清单时的确认窗扫描被打断 | 「把验证清单和及格线先写下来」 | `preregister(app, changes=…)`，见 3.5；扫描被打断时用同样的 changes 重调，扫描断点续跑 |
| `validate` | 清单已冻结、`next.confirm_window` 那段还没开；那段的确认窗扫描 / 涨跌结果补算被打断；或那段的验证结果文件在、开窗记录缺 | 「打开留着的那段数据做独立验证」 | `validate(app, confirm_window=next.confirm_window)`，被打断的扫描与补算从断点接着做 |
| `adopt` | 走到定案 | 停 3 | 3.7 |
| `revalidate` | 暂定定案到期复验 | 「上次暂定的定案到期了，要用新攒的数据复验」 | 先 `open_round` 划出新的验证数据，再按 `preregister` → `validate` 走 |
| `none` | 全部完成，或本轮维持现役 | 报 `next.why`（含下一次可做独立验证的最早日期 `next.earliest`） | 不动手 |

跨会话限制要如实交代：新会话里只说「继续」两个字，任何 skill 都不会被触发，要带上 pattern 名或「调参」字样。

## 七、与 feature-study 的衔接

- **分工**：feature-study 回答「这个特征 / 这道闸该不该信、该不该存在」，本 skill 回答「定下来放在哪、取什么值」。用户说「验证 XX 有没有用」「XX 是不是只是波动率在起作用」「把登记簿里的候选跑一遍」，走 feature-study。
- **准入读它的判定**：`propose_ranges` / `install` 按账本里 feature-study 的 `verify` 记录给闸分三类；判定之后代码或标签定义变过，判定作废。
- **闸子族**：`preregister` 调 `fs.plan(in_round=True)`，把 K 里保留的在役闸并进同一份清单；确认窗上的补检见 3.6。
- **反向登记**：改闸或删闸定案之前登记（3.7）。
- **冲突**：两边方向相反时先由 feature-study 的对账（`fs.reconcile`）自动拆解，拆不开才停。
