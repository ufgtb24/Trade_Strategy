# 波动尺度、未来最高价与标签包装的计算研究

日期：2026-10-02。项目内路径均相对 repo root。原始计时、环境、正确性标记见同目录 `rolling_results.json`。本研究只使用合成完好行情，未读取实际行情或最后验证集，未修改正式算法。

## 结论

这批数据的主要浪费不是比较价格，而是反复调用 Python 窗口函数、逐买点切 DataFrame、格式化日期与构建记录。用内置滚动中位数、数组价格运算和整列构表，可以在保持同一口径的前提下显著减少工作。现有库已经足以完成大部分优化，无须先缩小股票池。

全 5000 只、每只输出 504 日的波动尺度，使用数组 TR 和内置滚动中位数实测约 0.65 秒；未来最高价用普通滚动最大值约 0.22 秒，编译队列约 0.03 秒。保留原 `high/low` 首次穿越和兼容旧表结构的整个准备流程实测 16.39–16.42 秒。这不含读取行情、pattern 检测、Optuna 搜索和最终评分，因此不能称为整套搜索只需十几秒。

基于这些结果，推荐先用简单的全量一次计算和持久缓存。若候选在多轮搜索中逐渐覆盖大部分训练日期，复杂的按需分块初始化不一定值得；需要先实测真实读取、检测、内存成本。当前实验不能证明读取 5000 个文件也很快。

## 同一口径与实现替换

### 波动尺度

源函数为 `path2/calc/atr.py` 的 `rolling_atr_pct_nanmedian`。

1. `TR[t] = max(high[t]-low[t], abs(high[t]-close[t-1]), abs(low[t]-close[t-1]))`；首日没有前收盘，只有 `high[0]-low[0]` 生效。
2. `M[t] = median(TR[j]/close[j], j=t-W+1..t)`，窗口包含买点当日，头部 `W-1` 日尚不能计算。
3. 保持默认 `min_periods=W` 和偶数中位数取中间两数平均，直接将 `rolling(W).apply(np.nanmedian, raw=True)` 替换为内置 `rolling(W).median()`。
4. 可进一步把拼接三列表的 TR 计算换为数组 `fmax`，保持同样的运算顺序，再调用内置滚动中位数。对本次完好数据，两者逐位相等。

这里的收益既来自取消大量 Python 调用，也来自内置的连续窗口计算；没有将中位数近似为均值，没有缩短回看期。[pandas 2.3.3 的滚动中位数文档](https://pandas.pydata.org/pandas-docs/version/2.3/reference/api/pandas.core.window.rolling.Rolling.median.html)说明默认使用已编译的扩展实现。

### 未来最高价

源包装代码为 `.claude/skills/tune-gates-v3/scripts/daily.py` 中 `_prepare` 的逐行循环。

每买点空间仍为 `max(high[t+1:t+H+1])/close[t]-1`，未来包含 `t+H`，不包含买点 `t`。不能把已有的 `high` 最大值代替拟议收盘穿越需要的 `close` 最大值，它们是不同输入。

测试三种精确实现：

- 将最高价倒序做滚动最大值，再倒回并移一日，取得 `[t+1,t+H]`；保持只有完整前瞻窗才有值。[pandas 滚动最大值文档](https://pandas.pydata.org/pandas-docs/version/2.3/reference/api/pandas.core.window.rolling.Rolling.max.html)
- 对 `high[1:]` 建滑动窗口视图，按行取最大值。视图减少复制，不会消除 `O(NH)` 的比较；短窗口下常数可以很小。[NumPy 官方说明](https://numpy.org/doc/stable/reference/generated/numpy.lib.stride_tricks.sliding_window_view.html)
- 编译后的单调队列：倒序扫描，每个价格至多入队、出队各一次，每步移除窗口外下标与不可能再成为最大值的尾项，队首为该窗口最大值，总工作量 `O(N)`。本实验 Numba 已安装，没有新增依赖。

队列最快，但从 0.22 秒降至 0.03 秒的绝对收益很小，应排在删除逐行 DataFrame 切片之后；不能为了这 0.19 秒忽略十几秒的包装成本。

### 包装和完整准备流程

旧循环不只求最大值，还会对每个买点切片、创建两个数组视图、检查未来价格、格式化日期、追加元组、再把记录转成 DataFrame。新原型按股票批量计算整列、批量构表；相同日期字符串可以复用。最终仍输出原有的 `symbol/date/upside/up/down/both/none/M` 列及原有 dtype，未以仅返回数组冒充等价构表。

完整准备原型另保留了日期规范化、原始输入复制、价格列转换和完好性检查、检测输入截断、逐股数据 hash、旧 `high/low` 首次穿越和最终表拼接。只更换波动尺度与空间/包装算法。第一批 100 股的所有标签列、检测输入帧、数据版本 hash 与现有 `DailyEvaluator._prepare` 逐位一致。

它仍是旧 high/low 定义的等价优化基准，不能把它与同伴的纯 close 穿越内核组合成一个“已经跑过的完整 close 系统”计时。

## 可复现输入与计时范围

- 随机种子：`20261002`，NumPy `default_rng`。
- 股票 `S=5000`、输出交易日 `D=504`、主实验前瞻 `H=60`、波动窗口 `W=20`。每只输入 `T=W-1+D+H=583` 日，包含首部热身与尾部前瞻。输出共 2,520,000 行。
- `close = 100 * exp(cumsum(Normal(0.0002, 0.018), axis=day))`。
- 首个前收盘在生成 high/low 时取首个 close，其余取前一日 close；`spread=Uniform(0.002,0.018)`。
- `high=max(close,prev_close)*(1+spread)`；`low=min(close,prev_close)*(1-spread)`。随机数组依次生成收盘收益、spread；没有缺失或非法价。
- 日期为从 `2023-01-02` 开始的工作日序列，仅作对齐用，不代表真实美股交易日历。计分日期为下标 `[19,522]`。
- 只使用内存中的合成行情。数据生成、输入 DataFrame 创建、M、空间极值、包装、完整准备分别计时。使用 `perf_counter`，每轮前 `gc.collect()`，垃圾回收本身不计入该轮。
- 通过 `flock /tmp/v3-compute-optimization-bench.lock` 与团队其他性能实验互斥；BLAS/OMP/NumExpr/Numba 线程数均为 1。
- Python 3.12.12，NumPy 2.2.6，pandas 2.3.3，Numba 0.61.2；更多机器信息见本目录 `environment.json`。
- pandas 方法一般重复 2 次，队列暖运行重复 3 次。样本少，因此保留原始值；不是严密的跨机器性能结论。除首次编译外没有重新启动进程模拟冷缓存。

## 正确性核对

独立逐行参考实现直接写 TR 标量公式，用 Python 排序取中位数，并显式循环 `[t+1,t+H]` 取最高价，没有调用被比较的滚动函数。

1. `W∈{1,2,19,20}` 与 `H∈{1,20,60}` 的 12 种组合，每种用随机走势、恒定重复价格、取整重复价 3 只合成股票；中位数与空间各实现都逐位相等，热身与尾部不可评价位置一致。
2. 5000 股全规模的新 M 实现彼此逐位一致，旧 M 与新 M 在前 100 股逐位一致。
3. 5000 股在 H=20/60/120 下，三种最高价实现的所有有效位置和尾部空值逐位一致。
4. 包装与完整准备新旧比较前 100 股，所有返回列、dtype、次序一致；完整准备的检测输入与数据 hash 也一致。
5. 这是完好数据下的验证，未延伸为坏数据处理、未来业务口径或未来依赖版本的保证。

## 输出存储

旧字符串表在 pandas `memory_usage(deep=True)` 下估算 335,160,132 字节。这个深度估算会重复计入共享的 Python 字符串对象，**不等于进程 RSS**。

对 252 万行，两个 float64（M、空间）和四个 int8 状态的数值载荷合计 50,400,000 字节；另用两个 int32 存股票、日期编号需要 20,160,000 字节。若未来将互斥状态压成一个 int8，还可再减小。这里只比较载荷，不含行情缓存、DataFrame 索引、临时分配和候选缓存；不预设实际最终接口。

## 与同伴的交叉质疑

- 与穿越组确认：本组 M 包含当日、首日 TR 用 high-low，空间 high 最大值不能冒充 close 穿越最大值。穿越组显示核心可能远快于构表，不能用核心倍数宣称整个系统倍数。
- 提供编译队列给穿越组作为“先判整窗不可能触线”的备选。该筛选本身也有成本，在 H 较小、经常早触线时可能得不偿失，须把预筛成本算进去。
- 与对照组确认：预汇总只在日期/固定波动档内每行权重相等时等价。若改成排除候选自己或按股票单独配对，需要扩展统计；当前含自身的普通对照适用。不触线数量不能因预汇总而消失。
- 全池核心并不慢，按需初始化不应作为不可更改的前提。是否做按需分块，应由真实读取与覆盖比例决定，不能仅由“250 万条”这个数字推断。
