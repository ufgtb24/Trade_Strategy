## 原报告

只审「实现是否忠实于需求」。主体做到了;1 处实现跟规则不一致,2 处超出本票,2 处只做了一部分。前端 8 个单测文件 93 条全过,03 的 20 个例子逐条通过。

**(c) 看似实现但做法不对**
- **改起止的框也会并进当前样本**。spec 5.5:「样本是『当前样本』期间,**新画的框**按默认规则并进它」;03 约定也只是「新画的框」。实现把「改了起止的框」也算进 fresh(`stores/annotation.ts` `resizeBox` 调 `currentOn(…, id)`,单测「改起止…也并进来」专门守它)。后果:手动点掉的框只记在本页内存,刷新后再选中这个样本、拖一下那个框,它会被悄悄收回,违背「手动点进点出……永远算数」。

**(b) 没被要求的行为**
- unsorted 下负样本显示 `pattern?`(PatternPicker 与样本页,e2e 也断言了)。这是 07 的「挂在 unsorted 的负样本显示 pattern?」,不属本票。
- 当前 pattern 存 localStorage、刷新后还在、不存在时退回 unsorted。需求未写,影响小。

**(a) 缺失或只做了一部分**
- 「拍截图自查……实心和空心的三角分得清;暗一档以后 K 线仍看得清形状」:worktree 里还没有 `evidence/06/`,这项验收没交。
- 「换掉当前样本以后,再补画的框不会并进旧样本」:e2e 只测了「点空白处」一种换法;单测标题写着「选另一个样本」,内容里没有这一步,「换到别的样本」这条路两边都没测到。
- 「同一张图、同一 pattern 的样本按日期标 a、b、c」:只给当前 pattern 的样本标字母,别的 pattern 的样本无字母。可视为有意取舍,但与原文不完全一致。

## 处理(修改后的提交见完成记录)

- (c) 已改:只有当前样本期间新画的框会自动并进;改起止只在「新画的框」被拖进推断范围时让它并进,旧框拖了也不并。补单测「改起止只让当前样本期间新画的框并进;拖一下旧框不会把它收进来」。
- (a) 「选另一个样本」:单测补上这一步(选回旧样本、再放一个新样本,之后画的框只进新样本)。
- (a) 截图自查:截图在 `evidence/06/01`～`06`,结论写在完成记录。
- (a) 字母只标当前 pattern 的样本:保留。框旁的小字母说「它是哪几个样本的成员框」,几个 pattern 都标的话,同一张图上会有两个 a,框旁的字母就说不清是哪一个;别的 pattern 的样本画淡、只读,换到那个 pattern 后它们就有字母。
- (b) `pattern?`:保留。这里是 selection 页样本的 pattern 一格(本票的页面),spec 1.3「挂在 unsorted 时,显示『待选』」管的是样本在哪里显示;07 的 unsorted 页那一行另做。
- (b) 当前 pattern 记在浏览器里:保留。刷新后不记的话,新放的样本会悄悄落进 unsorted;记的只是本机界面的一项选择,不是标注。
