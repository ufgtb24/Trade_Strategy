# Update AI Context Skill

维护 `.claude/docs/` 下的 AI 上下文文档。这些文档是 Claude 下次 session 冷启动的先验知识，**只反映当前代码状态**。

## 核心原则：文档写代码给不了的东西

文档和代码不是二选一，是**按信息类型分工**。判断每一句该不该进文档，只问一件事：

> **这句话会不会因为有人改个函数名、加个字段就变错？**

- **会 → 别写进文档，或改写到抗漂移的粗粒度。** 签名、字段名、字段数、阈值、枚举清单、工厂清单——这些"是什么"的事实，代码是唯一权威，`grep` 一下就能核实。文档去镜像它们**纯是负债**：一份**陈旧的镜像比没有更糟**——它会把冷启动的 reader 引向一个已经不存在的概念（如文档写 `(Event, MatchContext) -> bool`，而 `MatchContext` 早删了）。省略只是把 reader 送去代码（权威），镜像却把他送错。所以宁可用**指针**代替复刻：写「c1_off 的 5 个源见 `_solve.py::compile_plan`」，别把那 5 条抄进来。
- **不会 → 这才是文档挣钱的地方，写准写透。** 为什么这么设计、什么**不变式**必须成立、模块**边界**在哪，以及**负知识**——"试过 X、会静默弄坏 Y""顶层 clause 恒 AND、别拆成平级 clause""改 INV-C 剪枝核心必须先 fuzz"。这些要么根本不在代码树里（理由散在早已消失的 commit / fuzz 结论里），要么要遍历一堆文件才能重建。**代码只说"有什么"，说不了"为什么"和"别做什么"。**

一句话：**Why / 不变式 / 边界 / 负知识 → 写；能一 grep 核实的 What → 指过去，别复刻。**

粒度推论：越细的内容（逐字段、逐签名）与代码耦合越紧、烂得越快；越粗的内容（边界、理由）越抗漂移。**别为了凑架构意图硬写**——某模块若确实没有 why 可讲，一行边界 + 指向代码即可，不要注水。

## 机械约束

- ❌ 不写历史演进、不写"之前是 X 现在是 Y"（陈旧对比本身也会烂）
- ❌ 不写未实现模块、未来计划、TODO
- ✅ 顶部标注 `> 最后更新：YYYY-MM-DD`（无"已实现"标签）
- ✅ 单个模块文件 ≤ 200 行；`system_outline.md` ≤ 100 行
- ✅ 模块文档文件名不用数字编号前缀（直接 `<模块名>.md`）

## 操作 A：更新单个模块文档

目标：把代码给不了的架构意图，写入 `.claude/docs/modules/<模块名>.md`。

流程：
1. 定位模块核心代码（`__init__.py` + 公共入口类）。
2. 文件已存在则读取，**先抓漂移**：把文档里出现的代码标识符（函数名 / 类名 / 字段名 / 字段数 / 枚举 / 签名串）逐个回代码核实。对不上的，按核心原则处理——删掉、或改写成指针，**绝不原样留着**（陈旧镜像是本 skill 要消灭的头号目标）。
3. 增量补新内容时，每句同样过那道关：**"改名会不会烂？"** 会烂的换成指针或提到更粗的粒度。
4. 按此优先级提炼（越靠前越该写、越该细）：
   - **关键决策与理由（Why）+ 不变式 + 负知识**（别做什么 / 踩过的坑）——最高价值；
   - **模块边界与对外依赖**（指向代码，不复刻签名/参数列表）；
   - **核心流程**（Mermaid，画数据/控制流走向即可，不画字段级细节）。
5. 同步更新 `.claude/docs/system_outline.md` 中该模块的行（新模块则追加）。

## 操作 B：刷新 system_outline

目标：重扫代码顶级目录（path2 主线 `path2/` `path2_apps/` `path2_web*/` + 前身 `BreakoutStrategy/`），保证 outline 与代码一致。

流程：
1. 列出各顶级包目录。
2. 对比 outline 模块表：代码有但表里没的 → 追加；表里有但代码没的 → 删除；目录改名的 → 同步。
3. 数据流变化（新增/删除核心模块）→ 更新数据流图。
4. 表里每行只留"这是什么模块、边界在哪、指向哪份 module 文档"——不进字段/签名细节（同核心原则）。
5. 术语表已外移至 `.claude/docs/glossary.md`，本 skill **不维护**它（仅用户明确指定时由会话直接追加）。

## 触发判定

- 用户明确说"更新模块 X"/"提炼 XX 的实现意图" → 操作 A
- 用户说"刷新 outline"/"同步系统概览"/"重新扫描模块" → 操作 B
- 代码结构刚发生变化（新增/删除/重命名模块）→ 主动建议运行操作 B

## 与另一 skill 的边界

本 skill **绝不**写入 `docs/` 下的任何目录。如果用户请求的是"写研究报告"/"写代码解释"/"保存临时计划"，应使用 `write-user-doc` skill。
