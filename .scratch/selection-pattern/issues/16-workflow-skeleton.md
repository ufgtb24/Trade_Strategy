# 这套流程分哪几步、每一步怎么进、怎么退

Type: grilling (HITL)
Status: open

## Question

### Purpose

流程能反复跑，靠的是每一步都有照着做的规矩；这张票定流程的骨架，后面各步的票和第一遍试跑都按它来填。

### 要决定的事

从拿到候选一直到上线核对，列出流程的每一步，每一步写清：

- 进入条件；
- 放弃条件，放弃后退回哪一步；
- 记什么账；
- 谁做：照地图 Notes「流程的工作方式」分工。

数值一律先取默认值、标「待验证」，不交给用户定，只把方向层面的选择留给用户。通用步骤只设计到第一遍用得上的程度，并记下哪些只适用于这一次（地图 Notes「图内动手」）。

### 已有的输入

来自 agent team 研究「找 pattern 的流程该 agent 主导还是人主导」（2026-10-16 用户批准写入地图，`docs/research/2026-10-15_workflow-agent-vs-human-led/final_report.md` 第 3～7 节）：

- **步骤草图**：候选来源（看图圈、挖数据、外部信息、文献）→ 用户确认规则是不是自己的意思 → 训练段内圈，由 agent 推进 → 过了规则后用户盲看命中例子挑错 → 验证段双钥匙 → 上线：每日名单存档、新数据接着核对 → 用户每周挑票并记账。
- **规则里要事先写定的几项**（地图 Notes「开工前提：护栏」的细则，都在开挖之前写定、由工具执行）：
  - 可证实性条件：扣掉运气和已知偏差后剩下的领先，要在验证段的独立买点数下看得出。默认约 ≥（2 ÷ 剩下的领先）² 个独立买点，剩 0.15 约 176 个，剩 0.4 约 25 个；换观察期或买卖规则要重算（待验证）。
  - 按年份拆开看与判，排除看过的样本作补充。
  - 禁区：幸存者偏差等已知偏差白送领先的区域。
  - 按尝试次数扣运气，范围和算法都要定。会话推荐的默认（待验证）：凡是争同一次验证机会的尝试，不分同一个 pattern 调参数还是换一个 pattern，记在同一本账上；运气上限的求法是把每次尝试都换成同日随便买重跑，看所有尝试里最好的那个能有多好，真实成绩只有超出它的部分算数，相似的变体自然只抬高一点上限。看大涨段那一轮要不要计入也在这里定（现在账本不计入）。
  - 送验证的排名口径：默认按去掉已知偏差区之后的领先、再扣运气来排。
  - 放弃条件。
  - 用到 path2 app 的候选，「确认根不晚于买点」的运行期检查。
- **看图圈已定设计里要重议的三处**（「看图找规律的工作流怎么设计」已解决、不改动，改动在这里定）：
  - 第 5 步毕业线第一条「训练段方向领先 ≥0.15」，改成按扣掉运气和已知偏差后剩下的领先判；
  - 对照页排除看过的样本，并按年份拆开；
  - 收紧每轮记一次尝试，并设放弃条件。
- **几个候选一起判**（2026-10-16 由「没碰过的数据怎么分配：第一遍用哪段，以后每一遍用什么」定，这里只接结论、不再重议）：验证段只送一个最强的；新数据阶段允许事先登记几个冻结候选，按个数打折一起判。那张票同时定了几样要排进步骤里的东西：送验证前在预检段上做一道否决检查；验证段打开前交核对单、用户双钥匙；没过可加严重验一次，再不过就放弃、验证段用完；每段数据各记一本账；新数据的判决日期登记时就定死、到点只判一次。留给本票定的是：预检的判法细则（默认整段方向领先不为负，待验证），以及预检段按次数打折的办法（与训练段同一套）。
- **已由「看图标注省力化：阶段 0」先建的护栏零件**（2026-10-17 用户批准）：截到 2025-12-31 的行情副本（护栏 1 的读取源；拿它当验证段的屏障，仍要独立复核后由用户批准）、本轮看图只露 2025 年、打开清单自动记「看过」、记账类文件只存一份并进 git、对照页每生成一次自动记账并按指纹存档规则文件、对照页命中按年份过滤。它们只是记录和过滤的机制，细则照旧由本票定：按尝试次数扣运气的范围和算法、看大涨段那一轮算不算尝试、对照页怎么排除看过的样本、判 2024 年的环节。研究「看图标注智能化」把两条判 2024 年的要求留给本票（`docs/research/2026-10-16_smart-annotation-design/auditor.md` 第 2 节 E5、F3）：判 2024 年时去掉观察期跨进 2025 年的买点；同时报 2025 年的成绩和两年之差，差值就是看图挑选把成绩抬高了多少。
- **「看过」以哪一级为准**（2026-10-17，来自「看图标注省力化：阶段 0」）：用户的看法是一屏六张小图看不清 K 线，不放大、不标注就谈不上看过，也不会去刻意记住看了什么。阶段 0 两级都记：打开清单（整份）和单张图（放大了哪张、标了哪张）。对照页排除看过的样本、判 2024 年时剔除看过的样本，以哪一级为准由本票定。
- **调参和特征研究工具仍读全量数据**（2026-10-17，阶段 0 的护栏复核发现，用户定为交本票）：网页看图的地方阶段 0 都截到了 2025 年；tune-gates-v3 与 feature-study 的读取没改，仍能读到 2026 年。把它们接进流程时改读截断副本；在那之前，不用它们给本流程的候选算成绩，地图护栏第 1 条也不算完全到位。
- **调试视图算出的 2025 年成绩算不算一次尝试**（2026-10-17，阶段 0 第三轮护栏复核发现）：调试视图的扫描列表给出每个 pattern 的命中数、前瞻收益中位数和首次穿越比，单股预览给出每个命中的前瞻收益，任意 pattern 都能算，范围已截到 2025 年。现在只记「看过」，不进账本、不算尝试。调试视图算开发工具还是算尝试，由本票写定；如果算尝试，就要接进账本，或者在它上面关掉成绩。
- **要不要内置一条「按卡判」规则**（2026-10-17，阶段 0 定向复核提出的方向题）：现在规则要声明来自哪张形态卡，必须逐日和卡核对一致，容差是 0。这样实际上只有「逐日调事实表、照卡上定义判」的规则过得了；独立写的规则、用 app 算信号的规则，在边界日几乎必然差一两天。内置规则的意思是：来源是形态卡时，信号直接按「卡说成立」逐日算，按构造就和卡一致，不用核对。代价是对照页全池逐日算事实表要跑很久：单进程约 4～10 小时，事实表算一次存起来，以后每张卡都能复用。阶段 0 不做，由本票定。
  - 延伸（2026-10-18，用户问「path2 app 能不能当规则写法」时谈到，未定）：手写一个 app 去实现平的形态卡不合算。要每天都和卡判得一样，app 里的检测参数、回看窗口、峰的口径都得和事实表逐项相同，做到了也只是把卡抄一遍；app 多表达的先后关系卡上没有，逐日核对必然拒。合适的方向是把卡编译成 path2 app：事实对应检测出的字段，要素对应 where，有它就不买对应取反的 where，触发对应买点 node。按构造和卡一致，不用核对。以后卡上加「先 A 后 B」这类边，也能照样编译。代价是要写编译器、把事实表改成逐日算全池，卡上加边还要设计用户怎么说出先后。进入信号：用户信的某个形态非靠先后关系不可，而事实表里又没有现成的一行。
- **代理冒烟的账本行算不算尝试**（2026-10-18，合并阶段 0 时迁旧账发现）：最初建看图工具时，代理自己跑过一轮对照（规则「当日量倍数≥3 且收盘创 20 日新高」，盲看一份、对照一份）。这两行连同两份大涨段清单已迁进主账本，标了 agent_smoke，清单名加了 smoke- 前缀。现在的计数不认这个标记，所以累计尝试次数从 0 变成 2，方向偏保守（扣运气扣得多）。代理替用户试规则算不算尝试、冒烟行要不要剔掉，由本票定。
- **流程状态全在文件里**：agent 会话不持久，任何新会话读账本、清单、规则版本就能接着推内圈。

护栏的建造从本票的答案里拆成任务票。
