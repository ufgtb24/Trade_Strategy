## 工作循环(每次 iteration,fresh context,靠文件恢复进度)

1. 用 grep 找下一个未完成 step:
   ```
   grep -n '^- \[ \]' docs/superpowers/plans/2026-05-25-path2-pattern-framework-cycle1.md | head -1
   ```
   得到首个 `- [ ]` 的行号。
2. Read plan 该行号附近 ~80 行,获取该 step 的完整代码 / 命令块。
3. 执行该 step:
   - 写文件用 Write / Edit
   - 跑命令用 Bash(如 `uv run pytest ...`)
   - commit 用 Bash(commit message **必须照 plan 模板**,含 `Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>`)
4. 测试 step(`uv run pytest <test>`):**通过才进下一 step**。失败则修复,不进推。
5. 用 Edit 把 plan 中该 step 的 `- [ ]` 改成 `- [x]`(保留 step 内容不变)。
6. 继续下一 step / 下一 task。
7. 当 plan 最后 Task 18 全部 ✓:
   - 跑完 §"完成检查清单"
   - 输出**单行**:`<promise>CYCLE1 COMPLETE</promise>`
   - 不再继续。

## BLOCKED 条件(输出 `BLOCKED: <原因>` 并停止,**不要盲猜**)

- **spec 模糊**到无法决定 → `BLOCKED: spec ambiguity at <章节路径>`
- **spec 与 plan 矛盾** → `BLOCKED: spec/plan conflict at <位置>`
- **同一测试连续 3 次失败**,无法定位根因 → `BLOCKED: stuck on <test path>`

- **需要新增 plan 未列文件 / 接口** → `BLOCKED: plan gap, missing <path or interface>`

## 硬规则(违反即任务失败)

- **不修改 spec 或 plan 本身的内容**——只允许把 `- [ ]` 翻成 `- [x]`,其他字符不动
- **不 import BreakoutStrategy**(`from BreakoutStrategy import ...` 或 `import BreakoutStrategy` 均禁止)
- **不写 placeholder**(`TBD` / `TODO` / `pass # implement later` / 空 docstring 等)
- **每个 step 完成后跑对应测试,通过才进下一步**——红测必须先转绿才能 commit
- **每个 task 一个 commit**,commit message 用 plan 给的 HEREDOC 模板
- **不修改既有协议层文件**:`path2/core/`、`path2/operators.py`、`path2/stdlib/` 与 `path2/__init__.py` 现有 import / `__all__`
- **Python 3.12**,**uv 包管理**(`uv add` / `uv run pytest` / `uv sync`)
- **测试与实现必须 TDD 顺序**:plan 是 "Step 1 write failing test → Step 2 run fail → Step 3 implement → Step 4 run pass → Step 5 commit",不跳序
