# 这套流程分哪几步、每一步怎么进、怎么退

Type: grilling (HITL)
Status: open

## Question

### Purpose

流程能反复跑，靠的是每一步都有照着做的规矩；这张票定流程的骨架，后面各步的票和第一遍试跑都按它来填。

### 要决定的事

从拿到候选一直到上线核对，列出流程的每一步，每一步写清：

- 进入条件；
- 放弃条件，放弃后退回哪一步；
- 记什么账；
- 谁做：照地图 Notes「流程的工作方式」分工。

数值一律先取默认值、标「待验证」，不交给用户定，只把方向层面的选择留给用户。通用步骤只设计到第一遍用得上的程度，并记下哪些只适用于这一次（地图 Notes「图内动手」）。

### 已有的输入

来自 agent team 研究「找 pattern 的流程该 agent 主导还是人主导」（2026-10-16 用户批准写入地图，`docs/research/2026-10-15_workflow-agent-vs-human-led/final_report.md` 第 3～7 节）：

- **步骤草图**：候选来源（看图圈、挖数据、外部信息、文献）→ 用户确认规则是不是自己的意思 → 训练段内圈，由 agent 推进 → 过了规则后用户盲看命中例子挑错 → 验证段双钥匙 → 上线：每日名单存档、新数据接着核对 → 用户每周挑票并记账。
- **规则里要事先写定的几项**（地图 Notes「开工前提：护栏」的细则，都在开挖之前写定、由工具执行）：
  - 可证实性条件：扣掉运气和已知偏差后剩下的领先，要在验证段的独立买点数下看得出。默认约 ≥（2 ÷ 剩下的领先）² 个独立买点，剩 0.15 约 176 个，剩 0.4 约 25 个；换观察期或买卖规则要重算（待验证）。
  - 按年份拆开看与判，排除看过的样本作补充。
  - 禁区：幸存者偏差等已知偏差白送领先的区域。
  - 按尝试次数扣运气，范围和算法都要定。会话推荐的默认（待验证）：凡是争同一次验证机会的尝试，不分同一个 pattern 调参数还是换一个 pattern，记在同一本账上；运气上限的求法是把每次尝试都换成同日随便买重跑，看所有尝试里最好的那个能有多好，真实成绩只有超出它的部分算数，相似的变体自然只抬高一点上限。看大涨段那一轮要不要计入也在这里定（现在账本不计入）。
  - 送验证的排名口径：默认按去掉已知偏差区之后的领先、再扣运气来排。
  - 放弃条件。
  - 用到 path2 app 的候选，「确认根不晚于买点」的运行期检查。
- **看图圈已定设计里要重议的三处**（「看图找规律的工作流怎么设计」已解决、不改动，改动在这里定）：
  - 第 5 步毕业线第一条「训练段方向领先 ≥0.15」，改成按扣掉运气和已知偏差后剩下的领先判；
  - 对照页排除看过的样本，并按年份拆开；
  - 收紧每轮记一次尝试，并设放弃条件。
- **验证段要不要一次送多个冻结候选、按个数打折**：方向选择，由「没碰过的数据怎么分配：第一遍用哪段，以后每一遍用什么」定，这里只接它的结论。
- **流程状态全在文件里**：agent 会话不持久，任何新会话读账本、清单、规则版本就能接着推内圈。

护栏的建造从本票的答案里拆成任务票。
