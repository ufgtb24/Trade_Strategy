## 0. 结论

1. **用户照常画，「是不是必须」在写 app 时由会话问一次、分四级**：必须有 / 可有可无（挂在它依附的那一段下面）/ 必须没有 / 不放。写完 app 后 pattern 页按级分层，顶层只剩必须有、每个正例都有。这回答了用户原问的「模糊只该在写 app 之前」——成立，但收拢的方式不是「规定同一 pattern 必须同一拓扑、让用户回头改图」，而是由会话定级。lead 原候选（`背景.md` 第 3 节：一个 pattern 一种顶层骨架、顶层不可选由用户画法保证）被替换；替换理由见 2.1。
2. **app 一侧只有一种拓扑是 path2 决定的**：一次 match 要求求解集里每个 node 都绑上事件（`path2/GLOSSARY.md:95`；`path2/dag/_solve.py:99-108`，不挂边的 node 不求解、`solve=False` 的不进 match）。可有可无只能落在 where（`W.any` `path2/dag/where.py:86`、`W.attr` 遇空判不满足 `where.py:23-26`、`W.children` `where.py:123`）或复合事件（`path2/GLOSSARY.md:62`）的子事件里；必须没有用否定边（`path2/dag/edges.py:215`）。级是意思、不是写法：必须有也可以写成相邻 node 上一条必过的 where（例：`path2_apps/bb_v1/dag_spec.py:53` 的「突破前沉寂够久」）。
3. **灵活与规范按「补救代价随什么涨」分五档**，不按「撤不撤得回」一刀切（2.2）。必须规定用户别做的只有四条，其中两条由数据墙和会话的进门清单机械拦，**用户自己要记的只有两条**：一个特征不装两种意思（特征名随便改，定义的意思不能改，要改就另起一个特征）；label、像但不买的理由、属性有没有都只按买点那天及以前看得到的判。两条都在发生那一刻由界面提醒（点下特征名时定义直接显示一行；选中买点时这天之后的 K 线暗一档）。
4. **每轮循环的入口是界面里的一张单子**（pattern 页 `ask n`），不是对话。机械能算的条目界面现算：画了没收在标注时就由界面标在图上，不进单子；缺了必须有进单子、改好即消；框归哪个买点只在界面里定，会话不推不问（U27～U30，2026-10-28 用户追加）；要判断的条目（定级、「那天看得见吗」）给选项、预填会话的猜测、回答由界面记下。整条流程只有一道真拦：送最后检查。
5. **界面改版 26 项**（ux U1～U26，mock_v3 已做），最影响效率的三项：画框与选中合并（拖 = 画、点 = 选、拖框边 = 改起止）；「当前买点」定义清楚、自动并进跟着它走；页头 `next` 一格说现在等谁。偏离不标红，朱红只留给「app 和你的标注对不上」。

交用户定两道方向题 D1、D2（均已定：D1 照常画，D2 默认没看过）和一道词表题（第 6 节）；另有四项推出来的改动请过目（第 7 节）。

## 2. 流程

### 2.1 为什么换掉 lead 原候选

原候选要求「同一 pattern 只有一种顶层骨架，有时有的要用户改写成后一个框的属性或套进大框」。sim 第一轮实测（`sim.md` 1.2 F1、1.4 H12）：横盘有时出现在放量突破前，用户自然把它画成单独一段；按原候选，归组时冒出 `−横盘` 碎组，用户要逐张改框，套在横盘里的缩量也跟着掉出成员。这等于要用户在标注时区分 node 和 where，与票 01 已定的「标注时不分 node / where」冲突。critic Q1 同判。改成「照常画，写 app 时会话定级」后，这一类不再累积成逐张改图。

### 2.2 灵活与规范的分界（回应用户两次追加）

判据：由着用户，代价是不是随**图的张数**涨、会不会变成**看不见的错证据**、撤不撤得回。

| 档 | 代价的样子 | 流程怎么对待 | 例子（思考模式，`flow.md` 2.2 M1～M17） |
|---|---|---|---|
| A | 当场看得见，改一处就好 | 支持，不管 | 先画再说、框边差不多就行；手比脑快（忘切 pattern）；一张图想表达两件事；对着 app 结果改框和属性 |
| B | 会累积，但清理成本随特征个数涨，会话或界面一次消化 | 支持，由会话 / 界面接住 | 看到什么框什么（背景框每张都框）；有更好不强求；边标边改主意；心里清楚就行、断点续做；顺手接受默认成员 |
| C | 会累积，只能逐张回头清 | 在发生那一刻引导，或给一个一次清完的操作，把它变成 B | 同一个特征起了两个特征名 → 起特征名时相近的已有特征排前 + `features` 页合并；跳过图直接说结论 → 会话要图 |
| D | 悄悄变成错证据，事后从数据分不出 | 不支持：能做成界面默认的做成默认，做不成的规定在用户身上 + 系统能查处查 | 顺手接受带上的属性（→ 默认改「没看过」，D2）；拿现成的词凑合（X2）；拿结果倒推当时（X3）；借 `let_go` 纠正 app（→ 改名 `not_sample` 挪位） |
| E | 撤不回 | 硬拦 | 看 2026 年起的数据（X1）；未过进门清单就送最后检查（X4） |

sim 的一句话版本（`sim.md` 1.4 末）：看得见、撤得回的由着用户；想法合理但要用户回头改标注的交给会话消化；会悄悄造假的兜在界面默认上而不是靠提醒；倒推当时和撤不回的规定在用户身上、有人核对或硬拦。任何「请用户别这么做」的规定，几周后都会忘。

**必须规定的四条**（`flow.md` 2.4）：

| # | 别这么做 | 谁拦 |
|---|---|---|
| X1 | 看 2026 年起的数据 | 数据墙，机械拦 |
| X2 | 一个特征装两种意思（含改定义换意思；特征名随便改，意思变了另起一个特征） | 用户自己记；点下特征名时定义直接显示一行，改特征名或定义时显示「用在 n 个框上」 |
| X3 | 用后来的涨跌定 label、写像但不买的理由、判属性有没有 | 用户自己记；选中买点时之后暗一档；会话每轮列出无结构原因翻过的 label 和盲看揭开前后判断相反的，问「那天看得见吗」 |
| X4 | 跳过进门清单送最后检查 | 会话列清单；用户坚持送检可以，记在账上 |

### 2.3 阶段表（按 pattern 算，`flow.md` 第 3 节）

| 阶段 | 用户 | 会话 | 出口门槛 |
|---|---|---|---|
| 0 找图 | 大涨段清单 / 随机一张 / path2_web | 不参与 | 无 |
| 1 标注 | 画框、点特征名、属性、框套框；在当前 pattern（默认未归类）下放买点，选 buy / no_buy；框归哪个买点由界面先给默认、在框或买点任一边点选改 | 不参与 | 无（未归类、定义空、属性没看过、默认成员没核对都允许） |

| 5 盲看 | 是 / 不是，「不是」写理由 | 理由翻成改动回阶段 3；理由里有买点之后才看得到的，当新想法 | 用户判断剩下的毛病值不值得修 |

| 7 最后检查 | 点头 | 进门清单：版本参数冻结；无 `unmapped`、无没答的问题；最后一次结构改动后盲看过；调参丢的标注看过；训练段四样成绩给看过 | **唯一硬门槛** |

**定级规则**（阶段 3 ②，`flow.md` 第 3 节）：
- 定义里说清了的照定义。
- **顶层特征**出现在不到一半正例里的默认「不放」、原因「出现太少」，不问（一半待验证）。「出现」把画了没收的也算上，免得默认成员切短把一个特征压到一半以下。
- **次级特征（子框、属性）不按出现多少默认不放**：方向文档第 7 节要的正是把不典型分支并进同一个 node（如「W 形 6/9、V 形 3/9 取其一」），按一半门槛 V 形会被悄悄定成不放（critic R14）。
- 其余问一次。选项随种类变：顶层框的特征「买的理由 / 有更好 / 只是背景 / 有它就不买」；属性和子框「必须有 / 有更好 / 有它就不买 / 无关」。
- 会话预填猜测；**出现在全部正例里、又没写定义的顶层特征不预填**——这正是每张都顺手框的背景那类，预填成必须有、用户不看就同意，app 悄悄变严，训练段上没有偏离组、盲看「是」率也不变，没有任何地方会暴露。
- 用户可只答一部分说「先写」：没答的这轮按「不放」写，原因「等你回答」。

**必须项检查**（阶段 3 ③）：只对必须有的特征列缺它的正例（配缩略图，画了没收的点一下收进），用户逐个答：补上，或「真没有，所以不算」（挪走或改成像但不买）。有必须没有的、必须有齐但先后和 app 不同的正例同此（不列出来会被当成 app 的错去放宽先后，方向反了）。

### 2.4 偏离与像但不买

- **规矩只管正例**；所有计数的分母只数正例。像但不买常常正是缺一样、多一样才不买，那个差就是理由，按差分组（`−X` / `+Y` / `=`）给会话当证据。像但不买的 `−X` 只算排在它最后一个已有必须有之前的（买点在突破当天的，还没到回踩，不算缺回踩）。
- **偏离只在写过 app 后才有**：正例缺了必须有、有了必须没有、或先后与 app 不同；参照是对应表的这两级（随 app 进 git），不按多数现算。不标朱红，排在最前，组头差签。

### 2.5 不变量（`flow.md` 第 4 节，摘要）

N1 app 没有可有可无的 node（path2 结构如此）；N2 写过 app 后每个特征都有一级，`unmapped` 只会是上一轮之后新出现的；N3 正例都有全部必须有、都没有必须没有，像但不买不受限（不拦，偏离组留着也能跑）；N4 是不是必须有由回答 / 定义 / 默认定，记在对应表，不由框套没套决定；N5 复合事件里可能没有的子事件不用 `W.child` 读（4.3）；N6 分母只数正例；N7 买点只属于一个 pattern、框不属于任何 pattern；N8 标注文件只由界面写；N9 2026 年起的数据只在最后检查时读、每次记账（唯一一道拦）；N10 改 pattern 的说法要指到图上；N11（2026-10-28 用户追加）框归哪个买点只在界面里定——界面给默认、用户在框或买点任一边改，会话只读存下的成员清单，不推、不问归属；会话只管翻译（同一买点两段同名时哪段对应哪个 node）。

## 4. 对用户原问的直接回答

### 4.1 是否应规定同一 pattern 必须同一拓扑？
app 一侧必然只有一种（path2 决定）；用户一侧不规定，照常画。差别由会话定级吸收，写完 app 后 pattern 页顶层只剩必须有。维持多种拓扑的必要性：用户标注时不该被迫区分必须与否（要看过好几张图才说得准）。

### 4.2 app 已建好，为什么还有 unmapped？
旧 mock 里的 `unmapped` 是演示数据的毛病：拿标注前就写好的 bb_v1 硬配演示标注，横盘、缩量在 bb_v1 里没有 node。定稿后 `unmapped` 只会是上一轮之后新出现的特征；会话决定不放的另显示为 `excluded` 并写原因。

### 4.3 「可选」只发生在次级 node？
写完 app 后是的：可有可无挂在它依附的那一段下面，落成 where 分支、可空字段或可空的一组子事件。**写法有坑**：`W.child` 不做保护（`path2/dag/where.py:113-120`），子事件不存在时基类 `child` 抛 KeyError（`path2/core.py:137`），burst 的 `child` 直接取 `members[0]`（`path2/atoms/breakout.py:113-118`）实测抛 IndexError（`repro/optional_child.py`）；求解时 where 过滤不捕获（`path2/dag/_solve.py:234-235`），整只股票的分析中断。安全写法：用可空字段或 `W.children` 读一组；复合事件不论有没有子事件都产出。约定归票 06。

## 6. 交用户定的方向题

**D1 可有可无的东西在哪里表达？**（critic 6.4、flow 第 11 节、ux 同）——**2026-10-27 用户已定：照常画，写 app 时会话问。**
- **照常画，写 app 时会话问（推荐）**：每个特征只问一次；写完 pattern 页按级分层。代价：pattern 页的层级与图上框的套法可以不同（横盘在图上是单独的框、在页上挂在放量突破下），用级标签 `optional` / `must_not` 与几何 `⊂` 两种记号分开；写 app 时多一张单子。
- **画的时候就表达**：单独的框 = 每个正例都得有；有时有的改写成后一个框的属性或套进大框。好处是页与图一致。代价：画框时就得定是否必须；定错要逐张回头改图；与票 01「标注时不分 node / where」冲突；横盘这种排在前面、套不进后一段的只能改写成属性。

**D2 选特征名时带上的属性默认「有」还是「没看过」？**（sim F3、critic R4 / X5、ux 方向题 1）——**2026-10-28 用户已定：默认没看过。** 这改了票 01 已定的「默认有」，批准后并入票 01 Answer 时一并改。
- 现行（票 01 已定）：默认有，按图勾掉没有的。ux 已消掉一半问题：候选只取当前 pattern 里用过的，`true` / `false` 再点回 null。剩下的：漏勾的「有」与确认过的「有」存成一样，会话照着写 where，事后分不出。
- **默认没看过，点一下才算有（推荐）**：代价每个新框多点几下。mock 顶栏 `carry` 可切两种对比。
- 维持默认有：最快；代价是勾漏的成了用户没判断过的证据。

## 8. 残余风险与待验证

### 8.1 残余风险（接受，交实施阶段盯；critic 6.5）

1. **第一次定 label 时看着后续走势**：机械上查不了，只能由最后检查兜，而最后检查撤不回。界面能做的只有选中买点时之后暗一档。两条用户规矩里这条最常见、最晚爆。
2. 默认成员仍是地基：少收的有「画了没收」兜，标注时选中买点即见（U29）；两个及以上买点时框外左侧的字母直接显示归属（U28）；只有一个买点时，落在 bracket 跨度里却没收的框仍要选中买点才看得见（选中时标 `◂`）。
3. 定级预填与一半门槛：用户可能不看就接受；最危险一类已不预填；顶层不到一半默认不放只在 `excluded` 区写原因，不看那一区就不知道。
4. pattern 页层级与图上框套法不一致（D1 选推荐项时）：两种记号是否一眼分得开要用户亲眼看。
5. 两条用户规矩靠记忆，只在点特征名和选买点两个时刻提醒。
6. 当前买点的自动并进会把顺手画的探索框并进（bracket 当面伸长，看得见）。
7. 严格包含的代价：子框边画出去一点就按先后读，直到手动挂上；提示只有框上边沿没出现 `⊂`。代价只在那一个框。
8. 近义词只靠同字冒出来（「横盘 / 平台」冒不出），兜底是事后合并（可拆回）。
9. 显示数要亲眼判：之后暗一档 7% 与非成员框透明度 0.3 分不分得开；浅琥珀 `#fdecc0` 与浅灰（分不开换 `#f0c674`）；拖框边热区 5px 在短框上挤不挤。
10. `ask` 单子依赖票 09 把会话的问题存成随 app 的文件；票 09 没做之前单子只能在对话里列。
11. 小别扭只记不改：虚线在主图（你的框）与侧栏（空着 / 缺）意思不同；选中买点后变暗盖住后面的买点三角（sim L7）；mock 悬停文案曾漏内部编号（sim L5，已告 ux）。
