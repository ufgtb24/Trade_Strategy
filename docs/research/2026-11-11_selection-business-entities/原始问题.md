# 原始问题（2026-11-11，用户原话逐字）

hit 族有必要被选中，因为我会在上面附着 feedback。
而 event 族就算点横条也无法被选中，因为 event 族其实是一种显示上的简化(防止垂直堆叠)，但是没有业务上的意义，对么？
判断是否应该取消选中 event 族。只能选中有业务意义的实体。
我对业务意义的看法： event族就不需要被选中，因为没有业务意义，只是显示简化。而 hit 的最后一天(买点)如果发生同日堆叠，我确信每个 hit 买点
肯定有业务意义的。但是堆叠整体是否有业务意义，还是只是显示简化？
帮我分析有业务意义的实体，让选择操作只需要针对有业务意义的实体即可。假如你认为同日堆叠整体无意义，当左右切换切换到这个堆叠日，就选中索引1的个体就行(现在的 hits
移动似乎已经遵循这个原则[Image #24])。

让 shift + C 完全针对选中内容，而不再使用循环来切换(不明确，且低效)，也就是所选即所复制。
这需要保证：
- 鼠标键盘可以完成所有有业务意义的内容的选中。
- 当前选中的内容有明确的显示，让用户知道现在选中了什么，比如在选中栏明确显示 [Image #19]，这点目前还有写不明确的地方，比如说选中 step，显示 [Image #25] 。而选中
 new_plat 则显示 [Image #26]  。目前是把当前选中什么，属于什么，包含什么，切换操作的工作范围混合到一起显示了，需要更明确这3者。

## 报告之后的拍板与追加（2026-11-12）

**第 ① 题（点 ▼ 选中什么）用户已定：选这一天整体。**

**第 ② 题（选中 event 后 ← / →）用户的提议，原话逐字：**

是不是有一个统一的  ← / → 功能标准：
选中 hit: 切换 hit 日
选中 event: 优先定位选中实体所属的 hit 日。如果只属于一个 hit 日才切换 event。

**用户对族、天的理解（原话逐字）：**

- 选中 hits 族的作用：因为反馈功能中，如果有问题，那么通常是很多连在一起的 hits 都有问题，它们都不该出现，所以需要把它们集体汇报给会话，因此「选中族」可以省去一个一个汇报每一个 hits 的麻烦。
- 选中天的作用：和选中族类似，也是选中一个集合，可以用来省去列举所有判定这天是卖点的 hits 的麻烦。
- 如果选中 hits 族中有的天会有日内的叠加，等于是一次性把两层循环遍历的 hits 对象取出来。

**用户第五次追加（原话逐字）：**

再仔细打磨一下通用切换规则，尽量在不同场景下遵从统一的可预判的规律，而不是每种情况零散设置，且规律能够用清晰的语言描述。

**第 ②～⑥ 题用户随后全部拍板（2026-11-12）：**

- ② 采用通用规律（同目录 `切换规律.md`）：里面有得挑（两个以上）就进去；否则本层有得换就换到旁边；两样都没有、里面只有一个，就进那一个。
- ③ 换天落最像的那次（同一种切法）。
- ④ Esc 往外退一层，到头再清空。
- ⑤ 显示栏形态 C：固定九格 + 选中卡。
- ⑥ 点样本只选中样本。
