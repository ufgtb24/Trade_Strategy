# 执行、故障处理与落地

## 搜索前检查

读取 app 当前参数及检测代码，确认每个待调字段在哪起作用、哪些关系必须成立、是否会改变评价尺子或买点位置。评价的 horizon/k、买入价口径、股票池、买点 node 不是本轮待优化参数。

对买点当日可知性做真实核对：买点事件确认了，不表示祖先的后验字段、容器统计或最终关系当天已经可知。优先使用已有的因果性质测试；没有时可在训练数据上对照截到买点日的检测结果。如果对照失败，先修正研究范围或转入检测逻辑修复，不根据被泄漏抬高的成绩调参。

按固定股票池的历史长度安排日期；确认样本使用记录和本会话已看过的数据。v1 最新 open 的两个保留窗口仍受保护，即使旧记录尚未验证；无法判断范围时停止取数并核对。不要删除记录、改 app 名称或改账本目录来解锁。

配置必须明确允许的回看起点history_start；它也登记为暴露范围。禁止为了预热读取该起点以前的价格，历史保护同时覆盖特征回看与未来标签。同谱系app应一并人工核对；现有自动账本按app区分，不能宣称已自动关联所有名字。

一个 app 在同一时刻只跑一种调参流程。v3 使用独立 JSONL 记录并读取 v1 已消费/保留范围；v1 不读取 v3 记录，所以反向切换需要显式检查两本记录。使用既有 `TUNE_LEDGER_DIR`，不要创建临时真实账本以重获“没见过的数据”；仅合成测试使用临时目录。

## 如何解释结果

主表先说明本轮是否启用统计折扣；启用时并列原始方向分、调整后主分、保留差异比例及误差估计状态，不能把它包装成已校准信心。主表至少包括原参数与候选的方向主分、匹配普通买入与差值、固定 bo、上涨空间、盘中回撤、原始与可评估机会数、先上/先下/未触线数量、条件先上比例、股票/日期/时段覆盖和近期供给。方向主分不等于收益率，未触线也不等于零收益。当前统计证据规则没有校准，不能根据覆盖数量或观察上改善自动称为确认。

不同配置新建多轮训练也算多次尝试；使用记录不会因文件夹换名而重置。单个 SQLite 给出本轮次数，累计次数从所有同 app 已登记运行的记录及结果核对。没有所有历史记录时明确“仅已登记的这些轮次可核对”，不报虚假的全历史次数。

统计折扣默认关闭；显式开启后，搜索到复核均使用配置冻结的调整公式，并同时报告原始成绩。它是实验性选项，最终比较仍不生成已校准误差区间：满足要求并观察上改善时可按既定政策暂用；到期仍不足确认则撤回。采用函数的confirmed分支是后续证据规则接口，当前自动执行不可到达。不得为保留暂用而临时加看或任填区间。

这份技能不以“训练更好”直接替代“值得实盘采用”。只有一个冻结候选进入一次最后检查。没有改善可维持原参数，这也是完整结果。

## 故障与关闭

读取标签前已写消费记录，因此扫描中断后不能假定没看见。完整 `final.json/review.json` 可重复只读；没有完整结果则报告本次检查未完成，该范围不再充当新一轮独立证据。程序故障可用已消费数据诊断修复，但不能改候选后再称一次独立验证。

训练中断可查 SQLite 的已完成尝试，现版不恢复 sampler 状态。关闭旧轮后，重新固定新一轮配置及总预算，再在训练数据重跑；保留历史尝试总数。终止命令：

```bash
uv run python .agents/skills/tune-gates-v3/scripts/run.py abandon --run-dir RUN
```

该命令关闭本轮，只释放未消费的预留范围。不会使任何已见结果重新独立。正常没选出改动时会自动关闭；最后决定不采用或确认采用后，未使用的暂用复核范围自动释放；暂用时保留到复核。

如果最后结果已保存、但随后关闭动作中断，保存结果仍有效；核对决策后可运行 `abandon` 补上关闭。不要对暂用轮次这样做，除非明确决定终止暂用并恢复原参数。

## 落地与恢复

脚本不覆盖正式参数，落地由 agent 在已有授权内执行，便于保留文件注释、应用特有格式及用户后来的更改。不要为普通可逆写入增加一套未经用户要求的审批；但若本次仅请求评估，必须先呈现确定结果，再就实际写入问一次。

1. 读取冻结配置、候选及最新 `final.json` 或 `review.json`，核对摘要与该轮使用记录。只有 `confirmed/provisional` 可以写候选，`reject` 保留现役，`rollback` 恢复本轮原参数。已被关闭的暂用轮次仅作历史记录，不能再按旧 provisional 结果写入，因为复核预留已释放；confirmed 的正常自动关闭不受此限制。不可挑某几项拼成未经验证的第三套。
2. 重新调用 `load_params().to_dict()`。首次写入必须仍等于冻结原参数；复核撤回必须仍等于这轮已经写入的候选。若不同，检查并解释并行修改，不能覆盖。找到 app 实际 YAML 来源，不能凭文件名猜路径。
3. 在本轮目录保存正式文件**原字节备份**、目标参数完整快照及待应用差异，状态标为待写。仅改必要参数值，保留无关字段与注释。复核撤回使用原字节备份，先核对没有其他合法修改。
4. 写后重新加载，要求 `Params.to_dict()` 与目标完整字典相等；用 `build_pattern` 检查声明可构建。失败即恢复备份并报告，不能宣称已采用。
5. 本轮写 `application.json` 记录 app、正式文件相对路径、来源结果摘要、写前/写后内容摘要、采用状态与时间、复核范围、备份路径；再读取核对。若未实际写入，明确“已给出采用结论，尚未写正式参数”。
6. 暂用状态交付时给出具体复核日期和数据范围。用户后来请求复核时，先查应用记录确认这套参数是否仍在使用；运行 `review` 后按确认或撤回结果完成上述相应写入/状态更新。不能把过去仅出具的暂用建议说成已经发生的实盘试用。

若没有授权创建定时任务，不创建。保存在应用记录里的复核安排仍需用户或后续调用触发，不能承诺 agent 会自行持续监控。

## 验证维护

从仓库根运行：

```bash
uv run python -m pytest -q .agents/skills/tune-gates-v3/tests
uv run python .agents/skills/tune-gates-v3/scripts/run.py --help
```

测试只用合成价格和临时账本，包含真实 bottom_burst 的接口检查，及真实 Optuna 与方向评分/消费规则的串联，以及close标签、普通对照缓存、固定bo和买点前缀检查。它们证明已覆盖行为的实现一致性，不证明真实市场提升；不能据测试通过给旧版或 v3 宣布胜负。
