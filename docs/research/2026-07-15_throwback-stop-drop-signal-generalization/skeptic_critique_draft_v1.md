# skeptic critique — throwback 止跌信号泛化动议

**批判派 v1 初稿** · 2026-07-15

## 概述与最初立场

用户对 `path2/atoms/throwback.py:158-159` 的止跌判据不满：

```python
if (lo_i >= lo_p and lo_p >= lo_pp
        and (_has_stop_signal(df, i - 1) or _has_stop_signal(df, i))):
```

主张"三根 low 严格非降 + 3 选 3 K 线信号"是过拟合，希望换成"多种信号 OR 融合"。

**我的最初立场**：**倾向反对**动议本身，同时同意"术语澄清 + 阈值再校准"是有价值的次级议题。核心质疑不是"能不能做出更好的判据"，而是**用户提出的诊断（"过拟合"、"信号池太窄导致漏检"）在样本证据上不成立**。若前提不成立，后续设计方案是解错题。

关键实证发现（5 只样本股 AAPL/ABBV/AAL/ACRS/MBI，各 770 bar，2026-07-15 由本 teammate 用 `datasets/pkls_live/` 跑）：

| 判据 | 下跌上下文触发率 |
|---|---|
| 单几何门（连续两根不创新低） | 18.3% |
| 几何门 ∧ 现行 3-OR K 线门 | **17.9%** |
| 几何门 ∧ 扩展 5-OR K 线门（含 doji/gap_up） | **18.3%** |

**几何门本身就是几乎全部 gating**。K 线门只挡了 0.4 个百分点、扩到 5-OR 后回补到 18.3% 上限——这意味着用户希望"通过泛化 K 线信号池提高召回率"，理论上限只有 +2.2% 相对增量（0.4 / 17.9）。若 tb 召回不佳，方向大概率不在 K 线门。

## 1. 假阳膨胀的数学

用户建议"多种信号 OR 融合"。数学上，N 个近独立信号 OR 融合的触发率是 `1 - (1-p)^N`，例：

| 单信号触发率 p | N=3 OR | N=5 OR |
|---|---|---|
| 0.10 | 0.271 | 0.410 |
| 0.20 | 0.488 | 0.672 |
| 0.30 | 0.657 | 0.832 |

实证数据（全期，5 股 aggregate）：

- `bullish`: 49.1% · `close_up`: 50.2% · `gap_up`: 50.1%（这三个各占全期一半！）
- `lower_shadow`: 17.3% · `doji`: 11.8%（相对稀缺）

**若 5-OR 融合全 5 信号，全期触发率 = 82.1%**、下跌上下文触发率 = 62.6%。作为"止跌信号"，这已经不筛任何东西了。

现行 3-OR（去掉 doji + gap_up）全期触发率 = 63.0%、下跌上下文 24.4%。**这与下跌上下文的 lower_shadow 单信号率 16.0% 相比已经膨胀了 50%+**。

**推论**：K 线门单独看不是几何门那种紧门；它的信息含量已经被 3-OR 稀释。再扩池只是把"止跌判据"变成"这一根不算死的证据"。

## 2. 信号共线性

Jaccard 系数（全期，样本聚合，n=3845 bar）：

| 信号对 | Jaccard | 共现/联合 | 结论 |
|---|---|---|---|
| **bullish ∧ close_up** | **0.755** | 1642 / 2175 | **近似等价**，加进 3-OR 相当于双计 |
| close_up ∧ gap_up | 0.443 | 1184 / 2671 | 中等共线 |
| bullish ∧ gap_up | 0.308 | 897 / 2917 | 中等共线 |
| doji ∧ lower_shadow | 0.256 | 228 / 892 | 中等共线（长下影常伴小实体） |
| lower_shadow ∧ 三大红蓝 | 0.13~0.16 | | 弱共线（独立信息） |
| doji ∧ 三大红蓝 | 0.08~0.12 | | 弱共线（独立信息） |

条件概率：`P(bullish | close_up) = 0.851`、`P(close_up | bullish) = 0.870`。**bullish 与 close_up 是近-等价信号**——一根阳线绝大多数时候同时收涨、反之亦然。

**这直接砸中用户 prompt 里举的三个候选（阳线 / close_up / 长下影线）**：其中前两个信号严重共线，实质是"1.2 个信号 + 1 个信号"而不是"3 个独立信号"。若"多种信号 OR"意在增加正交证据，方向应该是加 `lower_shadow` / `doji` / 反转形态族（morning star、engulfing），而不是继续在阳线/收涨/缺口这一族里堆材料。

**教科书组合信号（morning star / hammer / engulfing）的本质**：都是若干原子信号的合取（例：hammer = 长下影 ∧ 小实体 ∧ 低位 ∧ 阳线）。若在同一个 OR 池里把 hammer 单列一格 + 又列 lower_shadow 一格 + 又列 doji 一格，就是把 hammer 的合取当独立信号双计。融合前必须先做**信号命名空间的正交化**，否则堆越多越糊。

## 3. 参数腾挪的过拟合

**用户"过拟合"这个词用得可疑**（详见 §7）。若真按字面理解：

- **现行参数量**：`_STOP_SIGNALS` = 一个固定的 3 元组，`_positive_signals` 的 5 个阈值均是 Nison/Bulkowski 教科书数（body/rng≤0.10、lower_shadow≥0.50）。**有效可调参数 ≈ 0**（信号成员与阈值全硬编码）。
- **换成 N-of-M 时序**：N（多少根触发）、M（窗宽）、成员集合 S ⊆ 5 信号（2^5-1=31 种）、若加权重则每信号一个 w、阈值 σ。**自由度直接 5+**。
- **回测调优触发**：一旦 N/M/S/w 全上桌，"通过调这几个数让某笔单子回测漂亮"的空间就打开了。这才是真正会**制造过拟合**的地方。

**关键悖论**：用户以"过拟合"为由要泛化，泛化后的自由度反而变高。真正的过拟合风险在改判方向上放大，而不是缩小。

## 4. 与下游门的耦合

现行 tb 判据是三重门串联：

1. 几何门（连续两根不创新低）
2. K 线门（3-OR）
3. 深度门（`pullback_min_atr × atr`，默认 1.0）

**门的 gating 谁强谁弱**（下跌上下文，本 teammate 实证）：

- 几何门：18.3%
- 几何 ∧ K 线：17.9%（几乎不 gating）
- 深度门：本 teammate 未量化，但从代码看它只在几何 ∧ K 线通过后被评估，触发的场景更少

深度门是"这次回撤的绝对幅度够不够"的物理保护，几何+K 线是"这个回撤是否已止跌"的形态保护。**若形态门（几何+K 线）放松，深度门会承接更多"浅回撤但含止跌形态"的候选**：这在纯 pullback 稀薄的窗口内会污染 start_idx 的语义（"回撤根本不深、只是几根盘整根就被认作止跌"）。

**建议 fusion-architect 明确**：若采纳 OR 融合，pullback_min_atr 是否需要同步上调？否则整体 event 产出率会失控（尤其在低波动票上，本身 ATR 就小，深度门更弱）。

## 5. trough_idx 与止跌确认根的解耦

现行：`trough_idx = argmin(low over [bo+1, i])`，与"止跌确认"独立。**这是设计上很干净的一步**——止跌信号往往滞后于真实低点 1~2 根，`trough_idx` 拿的是真低点位置，start_idx 语义是"最早可买入位置"而非"止跌确认根"。

**若改成 K 线信号 OR，`trough_idx` 定义不变但触发时机会前移**：

- `bullish` / `close_up` 通常在真低点次日或第 2 日；
- 加进 OR 后，`_find_start_idx` 的 `i` 会更早进入 return 分支；
- `trough_idx = argmin over [bo+1, i]`，i 早 → 覆盖窗口短 → 可能选到还没跌到真低点的位置作 trough。

**语义漂移风险**：start_idx 变成"更早出手但可能没到真低点"。这对下游"最早可买入位置"的语义是伤害而非改善。

**建议**：若真的泛化 K 线门，必须重审 trough_idx 的定义——比如从"扫描期内 argmin"改成"扫描完成后在触发窗前后 K 根内再 refine 一次"。这个副作用不在用户最初提议里，但改判会强制打开。

## 6. path2 契约影响

- `phase1_no_trough_timeout` gate 的 label = `'max_start_gap 扫满'`。判据变了后，label 语义仍准（"窗口扫满未确认止跌"是形态层的独立事实）。但**若引入新 gate name**（如 `phase1_kline_signal_absent` 与 `phase1_geometry_absent` 分开 emit），前端 formatters.ts 需加 case。
- `MeasuredKindAware.kind` 新增（如 `'nofm_count'`）会走 default 分支，前端 tooltip 显示原值不报错，但没前缀——最好加 case。
- `ThrowbackDetector.__init__` 若加新 kwarg（如 `stop_signals: tuple[str, ...] = ('lower_shadow', 'bullish', 'close_up')`、`nofm: tuple[int, int] = (2, 3)`），现有 spec 的显式 kw 引用不破坏；但会污染 detector 的 param surface，走 `configs/params/` YAML 时也要同步更新。

**这块技术负担不重，可加 case**。契约压力小，但**新增可调 param 加深 §3 的过拟合担忧**。

## 7. "过拟合"术语澄清——本轮真正的第一步

用户 prompt 里说的"过拟合"是**术语误用**。学术定义：模型在训练集拟合过好、测试集泛化失败。tb 判据是规则式的，无训练过程，谈不上"过拟合"。

用户实际可能是想说三种不同的东西之一：

| 用户可能真意 | 补救方向 |
|---|---|
| A. **漏检严重**（recall 太低，漏了很多真止跌） | 放宽判据（本轮方向），但**要有具体漏检样本**佐证 |
| B. **判据太脆**（微扰一变结果就翻） | 加冗余（如 N-of-M 时序窗），但不必扩池 |
| C. **判据缺乏语义合理性**（哲学上不服"必须几何门+K 线门"这个组合） | 重新论证判据设计原则，非工程改动 |

**这三个方向的补救不重叠、甚至冲突**：

- A 的正解：查已知 tb 案例、看漏检根的 K 线形态，再决定加什么信号；
- B 的正解：现行 3-OR 已经是"i-1 或 i 两根"的时序松弛，进一步松只增假阳；
- C 的正解：讨论第一性原理，不做工程改动。

**批判要点**：本轮讨论应先要求用户澄清"你要的是 A/B/C 中的哪个"，否则三方（用户 / fusion / signals-taxonomist）在解不同的题。**我强烈建议先要求 A 的实证**：用户能否给出 2~3 个具体漏检案例（ticker + 日期），让我们在样本上先 replay、看漏在几何门还是 K 线门还是深度门？

**在 A 的实证到手前，任何"泛化信号池"的方案都是设计驱动、非证据驱动**。

## 8. Nison / Bulkowski 阈值本身

现行阈值（body/rng ≤ 0.10、lower_shadow ≥ 0.50、close > open 等）来自技术分析教科书，很多研究表明教科书阈值对**日线 vs 分钟线**、**大盘股 vs 小盘股**、**低波 vs 高波**的适配性有差异。

- doji 的 0.10 body/rng 在低波动票上过严（低波票的 body 本身就小、body/rng 反而不小）；
- lower_shadow 的 0.50 在高波动票上过松（宽 range 下更容易凑到 50% 下影）。

**但这是次级议题**——即使把阈值全部参数化（body/rng ∈ [0.05, 0.15], lower_shadow ∈ [0.40, 0.60]），也是 §3 的自由度膨胀继续加剧。

**建议**：阈值参数化留待"参数敏感性分析"专项，本轮不并入。若并入，必须**同时**提供固定值兜底 + 参数区间的 golden baseline 对拍，防止后续偷调阈值。

1. **【最优先】要求用户提供 A/B/C 澄清 + 具体漏检案例**——现在讨论方向发散，缺证据；

3. **信号命名空间正交化**：bullish 与 close_up 共线 0.755，是否合并为一个语义槽（如"红根系"）再讨论融合？signals-taxonomist 主责；

5. **深度门是否同步收紧**（§4）：若形态门放松，pullback_min_atr 是否 1.0 → 1.2 / 1.5？fusion-architect 主责；
6. **N-of-M 时序 vs 单根 OR**：本 teammate 快算 N=2/M=3 的现行 3-OR 全期触发率 = 69.3%，比单根 3-OR（63.0%）还高——时序不会自动收严，方向搞反了。fusion-architect 要仔细设计 N-of-M 才有意义（如 M 加长 + N 相对增加）；
7. **"过拟合"术语**（§7）：本轮全体（含用户）先对齐语言，再谈方案。

## 我的三档立场

三档：**"保留几何门为下限"** / "全信号 OR 融合" / "N-of-M 折中"

**我选：保留几何门为下限**，且再加一个 §7 澄清前置作为并行诉求。

**代价**：

- 若用户真的漏检严重（A），保留几何门可能挡住其中一部分——但**只挡下相对增量 ≤ 2.2%**（几何 ∧ 5-OR = 18.3% vs 几何 ∧ 3-OR = 17.9%，最多再回补 0.4pp）；
- 若用户是脆感（B），"保留几何门为下限" 对脆感缓解无帮助——脆感的正解是加冗余（如 N-of-M），此档不直接回应；
- 若用户是哲学层反弹（C），此档等于"不动"，用户不满意的哲学层压力仍在。

**为何仍选此档**：本轮尚未看到漏检的实证，也没看到脆感的具体触发场景。**在证据到手前，保守挡不动是最小信息量的合理立场**。改判可以随后跟进，前提是澄清 + 实证到位。

**若被 outvote 强制推进泛化**，我的次优选：**N-of-M 折中，但 N/M 与信号成员集合固定、不进 configs/params/**（避免自由度落进 YAML 后被无声调优），且 pullback_min_atr 同步收紧至 1.2 以对冲 §4 的耦合风险。
