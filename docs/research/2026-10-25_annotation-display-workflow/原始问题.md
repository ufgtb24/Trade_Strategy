# 原始问题（2026-10-25，用户原话逐字）

> 是不是我在标注时就已经能在图中看到已有 detector 的检测图标了？
> 是否有必要在标注时看所有已有 detector 的图标？这样会不会增加不必要的运算量？当前的 web_ui 只是显示选中 pattern 所需 detector 图标，如果显示所有 detector 会比当前运算慢。
> 还是说应该在标注完再由系统计算发现我要的 node 已经有，或者类似？
> 复用还是新建的判断时机应该放在哪？是在标注的实时可见并由用户选择(可能会慢)还是在标注完后给推荐并由用户选择(不直观)。
> 其实我是想要知道自己标注的特征图标和根据标注创建的 app 代码最终计算的 node 图标的出入的，这样可以评估 app 对用户需求的满足程度，只是我不要求完全拟合(起止位置)，但是我还是希望我标注的内容被 app 识别出来。
> 为了让 app 满足用户的需求，是否要在 app 创建完后在标注图中进行 feedback 来完成反馈修正，还是只根据在非标注图中盲选就可以完成修正。为了得到满足用户需求的 app，工作流应该怎样设计。
> 启用 agent team 分析上述问题，并且基于用户心智规律，功能实效性，给出标注显示的最佳方案。这其中既设计标注的显示交互方案，也涉及到工作流方案。不要受已有决策影响，从第一性原理分析。
