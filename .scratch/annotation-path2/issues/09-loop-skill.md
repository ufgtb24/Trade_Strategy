# 串起「图 → 代码」循环的技能

Type: grilling
Status: open
Blocked by: 01, 08

## Question

### Purpose

用户只管在网页上标注和点「是 / 不是」，把这些变成 app 改动并反复对回去的那一串步骤由这个技能代办，这张票定它管什么、怎么管。

已定：新写一个技能，用户说一句「看看我的标注」就进循环；它按顺序调现有的写 app（`authoring-path2-app`）、写 detector（`authoring-path2-detector`）、node 诊断（`diagnose-event`）、特征验证（`feature-study`）等技能（方向文档第 3 节末）。要定：

- 每一轮读什么（新标注、新的「是 / 不是」）、做什么（写或改 app、拿 app 对标注、生成盲看清单、把「不是」的理由翻成 node / where / 边的改动、新特征放在要用的地方量）、交给用户什么（用白话，不抛内部机制）；
- 归组：把「未归类」的买点连同事件结构列出来、骨架相同的排在一起，由用户决定（方向文档第 8 节）；
- 循环什么时候算完：盲看里「不是」少到什么程度就转去调参数和最后检查（尺度给默认值、标「待验证」）；
- app 的版本怎么记，让标注、盲看标记、检查次数都能对到同一版；
- 技能的触发词取用户会自然说出口的词（项目 `CLAUDE.md`「创作 skill」节）。

来自「在要用的地方量一条特征：现有工具能不能直接做」（已批准）：量特征的入口挂在本技能上。它在同一个评价器上带 / 不带这一条各跑一遍，计算代码按路径调用 tune-gates-v3 的那几个类，只读截到 2025-12-31 的副本、不写样本使用账本。结论四选一：看得出更好 / 看得出更差 / 看得出没多大用（默认不并、交用户定）/ 看不出（先留着、标「待验证」）。报「看不出」时同时说多出来几个买点日、落在几只股票、这份数据最多分辨得出多大的差别、实测值。每条结果记录带特征名、app 版本、k 和这一组有哪几条、训练段范围、数据指纹、多出来的买点清单。四选一判法在第一次出真实结论前要先校准（细节见那张票的「留待实施阶段验证」）。

来自「训练段用多长：样本多，还是和现在的市场像」（已批准）：技能交给用户的训练段成绩（量特征、拿 app 对标注之后的整体表现），除了合并数，还要按半年拆开给出，最近一个半年单列。防的是：优势只来自某一段旧行情、或在最近半年已经翻号的 pattern，合并数上看不出来，要到白白用掉一次没碰过的数据上的检查才暴露。训练段读同一个设置（默认 2021-10-08～2025-12-31）。

2026-10-24 用户同意（理由见方向文档第 15 节）：技能交给用户的成绩固定四样，口径和「没碰过的数据上的检查」那张票一致——比同日普通买入多多少（选股，判输赢）、比随机日多多少（选股加择时）、两者之差即择时贡献并附踩中几段独立行情、绝对收益；后三样只当参考。防的是：只报选股领先时，带择时的 pattern（如大跌后才出现的底部反转）赚的钱从哪来用户看不到，绝对收益为负时也可能被误读成赚钱。
