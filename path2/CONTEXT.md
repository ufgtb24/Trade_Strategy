# path2

把股票走势建模成多级不可变事件，再用 DAG 约束求解出命中。这里是这套建模的全部词汇：走势本身的词（bo / burst / tb）、事件与检测的词、声明与求解的词、以及衡量命中好坏的词。

覆盖 `path2/`（框架与走势-无关的检测器）与 `path2_apps/`（各走势形态的声明）。界面词汇见 [path2_web](../path2_web/CONTEXT.md)。

## Language

### 走势与形态

**bo / 突破**：
价格向上穿越一个已登记的峰、并因此被记下来的那一根 K 线。
_Avoid_: 勿按 BreakoutStrategy 的「突破点」理解，那是另一个上下文的词。

**pk / 峰**：
被登记为阻力位的高点，来源分凸点峰（convex）与大阴线高点（bear）两种。

**峰三态**：
alive / broken / eaten 不是峰身上的字段，而是从引用关系反推的——被某根 bo 引用为它突破的峰即 broken，被另一个峰引用为它取代的旧峰即 eaten，都没有则 alive。

**drought**：
一根 bo 距上一根 bo 的 K 线根数，衡量突破的稀疏程度；序列第一根没有前序，值为 None（意思是「无前序」，不是「未知」）。

**burst**：
一串在时间上密集相连的 bo 聚合成的一个宽事件，携带簇内根数、突破过的不同峰数、最大量比等预算好的标量。

**tb / 回踩**：
一次突破之后的回踩期里，价格企稳、可以执行买入的那段窗口。

**企稳段**：
tb 内部的一个买点单元，从企稳确认根到退出根；一个 tb 可以含多个段，段内每一根都是「当时已知买点仍开」的买入日。

**outcome**：
一个段或一个 tb 的退出方式（回升脱离 / 下跌脱离 / 满窗 / 派发 / 跌破锚点），是事后贴的标签，只用于诊断统计，不进 where、不进评估。

**trend segment / 走势区段**：
按均线逐根变化切出的一段连续同态区间，态分下跌 / 横盘 / 上涨三种。

**platform / 平台段**：
一段振幅被控制在阈值以内的窄幅震荡区间。

**dist / 派发**：
高位放量、收阴、且带长上影的单根 K 线。

**app**：
一个走势形态的完整声明（拓扑 + where + 参数取值），可以独立扫描与评估；同一走势的不同版本是彼此平级的 app，不是主从关系。

**bo_only**：
只含突破本身的参照系 app，用来对照另一个 app 到底漏掉了什么，它自己不是一个走势。

### 事件与检测

**event / 事件**：
一次观察结果的不可变记录，锚定在 K 线的一段索引区间上。

**点事件 / span 事件**：
几何上只占一根 K 线的事件叫点事件（口头也说 spot），跨多根的叫 span 事件。

**detector**：
事件的生产者：吃 K 线或上游事件流，吐出一条事件流。

**事件流**：
一个 detector 一次调用产出的事件序列；一个 detector 可以同时产出多条命名流（如突破检测同时产 bo 流与 pk 流），每条流都必须有 node 认领。

**confirm_idx / 确认根**：
站在这一根收盘、只读它及之前的数据就足以断定事件已经发生的那根 K 线；任何买点字段落在它之前就是前瞻偏差。

**确认型 / 回顾型**：
事件的两分类——确认那一刻即区间起点的是确认型（如 tb），区段走完回头才能确认的是回顾型（如 burst、trend segment、platform）。

**node_id**：
一个 node 的唯一名字，也是拓扑主键；同一个 detector 挂在两个 node 上就是两个 node_id。

**instance_id**：
一个事件实例的唯一身份，形如 `bo_1234#0`，由引擎在物化时注入。
_Avoid_: event_id、span_id、source_tag、class_id —— 都是已退役的旧身份体系，代码里已不存在。

**引用槽**：
一个事件声明它引用了哪些别的事件（如一根 bo 引用它突破的那几个峰），引擎统一把这些引用翻译成 instance_id。

**复合事件**：
把一串子事件聚合成的一个宽事件（如 burst 聚合它的成员 bo），子事件存在它的 child 槽里、可被边的端点选择器取到。

**attempt**：
detector 一次「试图产出事件」的判据评估；绝大多数 attempt 都在中途短路、不产事件，所以 attempt 数远大于事件数。

**gate / 闸**：
attempt 里的一道判据；没通过的那道会被记下来上报，是回答「为什么没检测到」的原始材料。

### 声明与求解

**pattern**：
一个形态的声明：一组 node 加一组边，引擎照着它求解。

**node**：
声明里的一个位置：由哪个 detector 供货，以及占据这个位置的事件要满足什么一元条件。

**where**：
单个事件够不够格占据某个 node 的一元条件，只看事件自身属性、不看拓扑。
_Avoid_: 定语、约束、条件。

**qualify / qualified**：
一个事件通过某 node 的全部 where 叫 qualify（动词），通过之后的状态叫 qualified。

**edge / 边**：
两个 node 之间的二元关系，共六类：时序、包含、起点包含、交叠、同段、否定。

**satisfies**：
一对具体事件之间某条边的关系成不成立（边的判定动词，与一元的 qualify 对称）。

**anchor / 锚**：
一种边关系——dst 事件的某个字段里明确写着它绑的就是那个 src 实例，用身份连而不是用几何连。

**端点选择器**：
让一条边连到复合事件内部的某个子事件（如「burst 的最后一根 bo」）而不是整体。

**子结构 node**：
被父容器物化出来的 node（如 tb 的企稳段），不自己产流、不参与求解、不能当边端点，只用于诊断与展示。

**只显示 node**：
声明为不参与求解的 node：照常检测、照常渲染，但不进匹配（如 pk）。

**solve / 求解**：
枚举出所有同时满足全部 where 与全部边约束的事件组合。

**match**：
一次完整命中：每个参与求解的 node 各绑定一个具体事件。

**diagnose / node 诊断**：
按 node 做的局部健康检查——这个 node 有哪些候选、卡在哪条 where、找不找得到关系伙伴；单 node 通过不代表能凑成完整匹配。

**trace**：
一次完整 match 的判定留痕：每条 where 和每条边在那次命中里的实测值与阈值。

### 度量

**前瞻收益 / mfr**：
买点之后固定窗口内的最大上行幅度；含波动率，量的是盈利潜力。
_Avoid_: 收益率（没说清是最大值还是终值）。

**forward_drawdown**：
前瞻收益的下行镜像：买点之后窗口内的最大下行幅度。

**首次穿越 / FP**：
买点之后价格先触上行线还是先触下行线的方向度量，几何对称、剥离了波动率。
_Avoid_: 读成 false positive —— FP 在本项目里恒指 first passage。

**随机日基线**：
从全宇宙随机抽日算同一指标得到的对照值；任何「好 / 坏」判断都必须对着它说，孤立数字不下结论。

**买点 / 样本 bar**：
一次命中里真正用于计算收益的那些根 K 线。

**eval_meta**：
每个 app 必须声明的评估元数据——买点落在哪个 node、需要预留多少首部缓冲交易日；缺了它这个 app 不会被发现。
