## 2. 必须补的

### P1 ★ 分辨力体检：怎么判断自己处在哪种信噪比情形（Q2 的核心缺口，直接给形式）

**为什么必须有**：报告的整个决策架构（闸阵而非排序、奥卡姆而非 argmax、判死 optuna/BO/多保真度）只在低分辨力下成立。**一个只在某种情形下成立的方法论，必须自带"我现在在哪种情形"的判据，否则它就是在把一次观测冻结成教条。** 报告目前没有这个判据。

**建议作为新的 §5.0 插在 §5 最前面**，全文如下：

---

#### §5.0 分辨力体检（每批候选评估完、决定"排序还是闸"之前必跑）

**成本**：秒级。逐买点明细在评估时已在手，ticker bootstrap 不需要新的全宇宙跑（依据 `05_opt_methodology.md` §2.5）。

**步骤**

1. **先过滤到 contender 子集**：只保留过了硬门 + 因果闸、且 score ≥ 现任的一个合理下限的候选。
   ⚠ **这一步不能省。** 同一批数据上，全体候选算出 `τ²/(τ²+σ²) = 0.993`（层①②）/ `0.877`（层③），contender 子集算出 **0.000**。**前者是假的**——它全靠几个明显坏掉的候选（退化成基线的、n=22 的）撑起来。**在全集上算这个比值会得出"分辨力很好、可以放心排序"的相反结论。**

2. 对全部 `C(K,2)` 个配对，算差值 `Δ_ij` 与配对标准误 `SE_ij`（ticker bootstrap，公共随机数）。

3. 算三个量：

   ```
   σ̂²    = mean(SE_ij²)                        # 噪声方差
   τ̂²    = max(0, Var(Δ_ij) − σ̂²)              # 候选间真实质量方差（矩估计）
   ρ_rel = τ̂² / (τ̂² + σ̂²)                      # 可靠度比 / 收缩因子
   ```

   同时记录：`中位 |z|`、`|z|>2 的占比`、`K`。

**判读**

`ρ_rel` 的含义是可以直接用的：在随机效应模型下，**你观测到的冠军优势里，期望能真实兑现的比例就是 `ρ_rel`**（这就是收缩/均值回归因子）。

| 档 | 判据 | 该用什么 |
|---|---|---|
| **闸阵档** | `ρ_rel < 0.2`，或 `\|z\|>2 占比 ≤ 5%`（未超过纯噪声下的期望占比） | **不排序**。绝对闸过滤 + 幸存者按奥卡姆取。排序类工具（optuna / BO / 多保真度）全部不适用 |
| **有限排序档** | `0.2 ≤ ρ_rel < 0.62` | 可排序，但必须报 K + 按门槛表扣除 + 两窗最差分。**预期只有 `ρ_rel` 比例的观测优势会兑现**，据此判断值不值得 |
| **排序档** | `ρ_rel ≥ 0.62` | 排序类工具重新上桌。搜索的期望收益超过选择税 |

**0.62 这个门槛的来源**（机制推导，非实测）：设选择税 = 纯噪声下 K 个候选的期望最大值 `σ̂·E[max_K]`，观测冠军优势 `≈ √(τ̂²+σ̂²)·E[max_K]`，期望兑现 `= ρ_rel × 观测优势`。要求「期望兑现 > 选择税」：

```
ρ_rel·√(τ̂²+σ̂²)·E[max_K] > σ̂·E[max_K]
⟹ τ̂²/√(τ̂²+σ̂²) > σ̂
⟹ 令 u = τ̂²/σ̂²，则 u² > u+1 ⟹ u > (1+√5)/2 ≈ 1.618
⟹ τ̂/σ̂ > 1.27  ⟺  ρ_rel > 0.618
```

**注意 `E[max_K]` 在两边约掉了**——所以「该排序还是该用闸」**与候选数量无关**，只取决于可靠度比。这也解释了为什么"多搜一点说不定就有了"是错的：候选数增加时，收益和税同比例增长。

**这套判据的一个已验证点**：本项目 contender 子集实测 `τ̂²=0 ⟹ ρ_rel=0 ⟹ 预测兑现率 ≈0%`；独立的跨期实测兑现率 **3%**。**判据在本项目上标定过一次且吻合。**（证据等级：τ̂² 与 3% 均为真跑；0.62 门槛为机制推导。）

**强制重跑的触发条件**（这是 §5.0 与 M2 的接口）：
- **换 label / 改评分口径** —— τ̂² 是在特定尺子上估的，换尺子必须重估；
- **候选来源换类**（从机械邻域换成 LLM 生成的新判据、或人类形态提名）—— 现有 τ̂²=0 未覆盖这一类；
- **样本量变化 ≥2 倍**（加数据、放宽硬门）—— σ̂ 随 n 变。

### P2 §0 缺一句平白话：用户要的「最优」在这套方法里变成了什么

**问题**：用户诉求原文是「最终输出**最优**的 path2_apps 代码 + 参数」。报告的实际答案是「最优在当前信噪比下不可判定，能交付的是排除坏的 + 幸存者按奥卡姆取一个」。这个意思报告有（§1 口号「最优化的做法，是不做那件做不了的事」+ §11 第 1 条），**但没有任何一处把它作为对用户诉求的正式回复讲明白**。§0「交付物」讲的是文档结构，不是诉求转译。

一句口号不等于讲清楚。口号读起来像"我们做了个更聪明的选择"，实情是"你要的那个东西现在测不出来"。**后者才是用户需要知道的，而且它是可量化的**（ρ_rel、3% 兑现率），不该只以格言形式出现。

**建议改法**：§0 加一小节，三句话即可：

> **你要的和你能得到的**
> 你要的是"输出最优的代码 + 参数"。**在当前的目标函数与样本量下，"最优"不可判定**——实测候选之间的分数差异完全能由噪声解释，搜索窗上看到的优势跨期只兑现 3%。
> 所以本方法交付的是：**一组通过全部否决闸的候选，加一条从中取一个的规则（奥卡姆）**。它保证你不会选到坏的，不保证你选到最好的。
> **这个降级是有条件的，条件可计算**——见 §5.0。分辨力上来了，"最优"就重新可谈，本方法也应随之换档。

## 5. 复审第二轮：lead 提出的两处复核（critic 裁定）

### 5.1 `ρ_rel` 门槛：0.5 还是 0.618？—— **两个都对，因为它们回答的是不同的问题；但都不该写第三位小数**

**你的 0.5 的判据**：`ρ > 1−ρ`，即"观测到的冠军优势里，真实成分 > 噪声成分"。这是一个**描述性**判据。

**我的 0.618 的判据**：期望兑现 > 纯噪声下 K 个候选的期望最大值（选择税）。这是一个**决策性**判据。一行推导：

```
随机效应：X_i = μ + θ_i + ε_i,  θ~N(0,τ²), ε~N(0,σ²),  s² = τ²+σ²
观测冠军优势     A_obs = s·E[max_K]
期望真实兑现     E[θ|selected] = ρ_rel · A_obs        ← 收缩/均值回归，这是定理不是经验
纯噪声基准(τ=0)  A_null = σ·E[max_K]

要求 ρ_rel·s·E[max_K] > σ·E[max_K]
  ⟹ ρ_rel·s > σ  ⟹  τ²/s > σ  ⟹  τ² > σ√(τ²+σ²)
  令 u = τ²/σ² :  u² > u+1  ⟹  u > (1+√5)/2 = 1.618
  ⟹ τ̂/σ̂ > 1.272  ⟺  ρ_rel > 0.618
```

`E[max_K]` 两边约掉 —— 但**要诚实说清这是"我让基准也随 E[max_K] 缩放"带来的，不是天然规律**。若把基准换成单次比较的 SE（`σ` 而非 `σ·E[max_K]`），K 就不再约掉，门槛随 K 下降。

#### 【第三轮修订 · critic 认错】lead 的诘问是对的，答案是 (a)，而且主数值应当写 0.5

lead 追问「1.63 从哪来」，答案是 **(a) 我用了更严的基准，而那个"更严"是选的、不是推的**。精确的差额可以写出来：

```
lead 的税 = (1−ρ)·σ_obs·a_K          （观测优势里的虚假成分）
我   的税 = σ·a_K                     （纯噪声下 K 个候选的期望最大值）
两者之比 = σ/((1−ρ)·σ_obs) = 1/√(1−ρ)      ∵ 1−ρ = σ²/σ_obs²

⟹ lead 的判据：ρ > 1−ρ      ⟹ ρ > 0.5
⟹ 我  的判据：ρ > √(1−ρ)    ⟹ ρ² + ρ − 1 > 0 ⟹ ρ > 0.618
```

**所以 0.618 不是 0.5 的近似，两者是同一族判据在"税"的定义上取了不同基准；黄金比例是 `ρ > √(1−ρ)` 的根，代数上真实，但那个根号来自我的基准选择。**

**我撤回"写 0.5~0.65 的带"，改为：主数值写 0.5，把更严的档作为可调旋钮注明。** 三个理由，第三个是我上一轮没想到的、也是最重要的：

2. **`τ̂²` 自身的估计误差远大于 0.5 与 0.618 的距离**，且实际读数几乎不落在带里（本项目 0.000）。判据的可操作内容全在低端闸，精度该花在低端。

   真要按期望收益比，排序策略的期望真实收益是 `ρ·σ_obs·a_K ≥ 0`，闸阵+奥卡姆是 `0`（若奥卡姆与 θ 无关）。**⟹ 只要 ρ>0，排序在期望上就永远弱优于闸阵。** 所以"该不该排序"根本不是由期望收益决定的，而是由三件判据之外的东西决定：搜索的算力与人力成本、K 被消耗后未来断言的门槛抬升、以及**你会不会把 `ρ⁻¹` 倍的虚假增益当真而污染下游决策**。

| **那次标定** | **一次退化确认** | 明写"在 ρ_rel=0 处预测 0、实测 3%，是未被证伪，不是被验证" |

**同时建议把主闸换成一个不依赖模型的检查，`ρ_rel` 降为分级细化**：

> **主闸（无模型）**：contender 配对中 `|z|>2` 的占比是否超过纯噪声期望的 ~5%？
> 本项目实测 **1%**（低于 5%）⟹ **没有任何证据表明候选之间存在真实差异**，到此为止，不排序。
> **细化（有模型）**：主闸过了，再用 `ρ_rel` 判该排到多细、期望兑现多少。

这么改有三个好处：① 主闸不需要高斯假设、不需要约定门槛、不需要 `τ̂²`；② 它和 `τ̂²=0` 是同一批数据的两种独立读法，互为交叉验证；③ **它把"n=1 标定"的负担从主闸上卸掉了**——主闸只是一个显著性计数，不需要标定。

**⟹ 净结论**：`ρ_rel` 该留在 §1，因为 §1 需要的是"存在一个可计算的判据"这件事本身，而这件事成立。该降的是**它的数值精度与确定性语气**，不是它的位置。

### 5.3 【第三轮】`ρ_rel ≈ 0` 的分诊：怎么区分"空间平"与"尺子坏"

lead 加的那条反向使用说明（低读数可能意味着尺子坏了，别拿它当不修尺子的借口）**是这一轮最好的补充，比我 P1 原稿里的任何一条都重要**。但它目前只说"靠阶段 0 体检来区分"，而阶段 0 是六项检查的整套流程。**其实有一个更快的分诊，而且本项目已经无意中做过一次：**

> **`ρ_rel ≈ 0` 分诊（秒级，不用跑阶段 0 全套）**
> 拿**同一批 contender**，换 2–3 个合理的替代度量（持有到期收益 / 对称计量 / 路径依赖 / 甚至只是"所选名字的波动率"），重算候选间的散布。
> - **若在某个替代度量上分辨得动** ⟹ **尺子问题**。候选空间里有结构，只是当前这把尺子不看那个方向 ⟹ 回阶段 0 修 label，修完重量。
> - **若在所有合理度量上都分辨不动** ⟹ **空间问题**。这批候选确实彼此等价 ⟹ 闸阵档成立，且换尺子也救不了，该去换候选来源（通道 C/D）而不是换尺子。

**本项目的读数**：`corr(score, 最大不利偏移深度) = −0.591 (p=0.003)`、`corr(中位 max-high, 中位 MAE) = −0.717 (p=1.2e-4)`——**同一批 contender 在"波动率深度"这个维度上分辨得很动。⟹ 本项目明确是尺子问题，不是空间问题。**

这条分诊有三个好处：
1. **它让"低读数"变成可行动的**，而不是一个只能停下来的终点；
2. **它复用阶段 0 的 b 项**（口径一致性）的同一批计算，几乎零增量成本；
3. ★ **它堵死了 lead 担心的那个后门**。若只写"靠阶段 0 区分"，读者仍可能跳过；写成"`ρ_rel≈0` 时**必须**先跑这一步分诊"，就把体检变成了低读数的**强制后继**，而不是一条可选建议。**这与 §8.3「写进报告的建议不会被执行」是同一条纪律：把该发生的事挂到一个必然会到达的位置上。**

**⚠ 一个诚实边界**：`corr(score, MAE) = −0.591` 与 `τ̂²(score) = 0` 之间有表面张力——若 score 在候选间纯属噪声，它不该与任何真实量相关到 `p=0.003`。最可能的调和是**两个统计量算在同一批买点上、抽样误差相关**。这不推翻分诊的用法（分诊要的就是"换度量后散布是否变大"，用配对差分的 `|z|` 分布比用相关系数更稳），但**分诊的实现应当用替代度量下重算的 `|z|>2` 占比，不要用两个度量之间的相关系数**——后者会被共享抽样噪声污染。

### 6.3 【点 3】两处现场纠偏

**① `materialized_at` 的 `TYPE_CHECKING` 守卫 —— 现场核实，完全成立 ✔**

`path2/core.py:100-115` 读到，docstring 逐字写着：Python 3.12 下 `runtime_checkable` 的 `isinstance` 结构检查会把 Protocol 里**任何（哪怕只声明、带默认值的）**属性纳入必须项；`on_gate` 正是因此才放进 `if TYPE_CHECKING:`（`core.py:114-115`），否则所有现有 conforming class 会判定失败。**operator 的"照抄 `on_gate` 的写法"是对的**，其推论"**真正的运行时强制来自 evaluator 里那句不带默认值的 `getattr`，Protocol 不会替你把关**"也是对的——属性在守卫内，`isinstance` 确实看不到它。伪代码 `mat_bar = getattr(ev, det.materialized_at)` 写法也正确（先取 `det.materialized_at`，缺声明即 `AttributeError`）。

> **⚠ 但这里有一个 operator 没发现的能力边界**：`materialized_at` 取值域被限定为 `"start_idx" | "end_idx"` 两个**字段名**。而 §3.4 结尾声称这道闸也抓得住 `dip_entry_k` 规则（"`materialized_at = bo_end+k > buy_bar`"）——**`bo_end+k` 不是 event 上的任何字段，这个协议表达不出来**；而且 `dip_entry` 是 `stage0_probe` 里的一条评估侧规则，根本不是 dag 节点，`_eval_ticker` 的断言不会在它身上跑。
> ⟹ **"这道闸抓得住的两个真实洞"里，第二个实际上不是被这道闸抓住的**，是被人读定义判死的。建议改成："拓扑候选由本闸机械抓住；**评估侧自定义入场规则（如 dip-entry）不在本闸射程内，必须人工判**"——否则读者会以为加了这道闸就不用管入场规则了。这正好是 f 项精神（别把不淘汰东西的门算进防线）的又一次自我应用。

**② 埋点数量 14/6 vs 13/7 —— 处理方式对，但给的理由是错的**

处理方式（不裁定、把"现场 grep 别照抄文档"写进改动条目本身）**是对的，确认**。

但 operator 给的理由——"两个数不一致本身就是'别引用文档内嵌快照'这条红线的实例"——**诊断错了**。我现场 grep：

```
grep -rn "GateFailure(\|_emit_tb_gate(" path2/ --include=*.py   → 15 行
```

三个数都不错，**差异全部来自"什么算一个埋点"**：
- **15** = 裸 grep 全部行；
- **14** = 15 − `throwback.py:97` 那行（`_emit_tb_gate` 的 `def` 定义行）＝ operator 的数；
- **13** = 真正的调用点：`breakout.py` 9 处 `GateFailure(` + `throwback.py` 4 处 `_emit_tb_gate(...)`（162/177/192/222）＝ `06` 的数（`throwback.py:116` 是 helper 内部唯一那次构造，不是调用点）。

⟹ **不是文档过期，是口径不同。** 这个区别有操作后果：**throwback 那 4 个调用点共享一个 helper，`unit` 只需在 helper 签名上加一次**——按 14 或 15 去估工作量会高估。

### 6.4 【点 4】否决 `WINDOW_MODE`：**结论对，两条理由里第一条是错的**

**结论我支持**，但支撑要换。

- **理由 1「`sweep.py` 里单窗打分本来就不可表达」—— 事实错误。** 现场读 `sweep.py:40-51`：`row["windows"][w] = s` 逐窗存了完整 score dict，且 `OUT.write_text(json.dumps(out ...))` 把它整个落盘。**单窗分数是被算出来、被写进文件的**；只有**控制台那张排行榜**用了 `worst_score`。所以准确表述是"**单窗排序不是默认输出**"，不是"不可表达"——拿输出 JSON 按单窗排序是平凡的。
- **理由 2（设计律②）—— 形式对，但与 operator 自己加的 `SELECT_MODE` 表面矛盾**，因为 `SELECT_MODE` 同样是"加一个开关、让 `argmax` 成为一等公民"。**缺的那条原则我补上**：

> **律② 的可操作形式不是「不要有开关」，而是「不要新增一条通往错误的表达路径」。**
> - `SELECT_MODE`：现状默认就是 argmax（skill 原文"以最优点为中心"）。加开关把默认从**错**改成**对**，argmax 降级为需写理由的 opt-in ⟹ **净减少**一条错误路径 ⟹ 该加。
> - `WINDOW_MODE`：现状单窗排序**不是**任何脚本的默认出口。加开关等于把它提为受支持的一等模式 ⟹ **净增加**一条错误路径 ⟹ 不该加。
>
> **判据是"相对现状是净增还是净减错误路径"，不是"有没有开关"。**

- **理由 3（holdout 由数据通路隔离承担，`datasets/pkls_search/`）—— 成立，而且它自己就够**。这条不依赖 `sweep.py` 里能不能表达单窗，是三条里最结实的。**建议把它提为主论据，理由 1 删掉或改成"不是默认出口"。**
