# 结构化标注：存什么、界面和主视图怎么合

Type: prototype (HITL)
Status: claimed
Claimed: 2026-10-25 主目录 annotation-path2 分支会话

## Question

### Purpose

用户在图上留下的标注，是让代码学会用户所见、再拿代码对回用户所见的唯一原料，这张票定这份原料的样子。

做一个粗糙的原型给用户看，定下：

- 标注里存什么：事件（点选系统已有的，或自己框的）、事件的名字和可选的一句话、事件的角色（在 pattern 里扮演哪个 node，可空）、事件具备哪几条特征（打勾，不填数）、买点、正例 / 像但不买、所属 pattern（可「未归类」）、当时用的数据指纹。存成能和 app 输出叠在同一张图上比的格式。
- 界面：标注做成主视图的一个可编辑模式，还是保留独立页面再加事件图层；系统事件一键关掉只看干净 K 线；「当前 pattern」怎么切；新名字怎么起。
- 「拿 app 对标注」时两层怎么叠着显示：用户的框和 app 产出的事件差在哪、怎么一眼看出来。

方向文档第 8 节是这张票的方向，不重新论证：标注就是「用户期望的显示」，web_ui 的显示就是「app 实际的输出」，按意思对应，三处不对称（阈值只标有无、标注侧多出新种类和正例判断、显示侧多出 detected 档与尝试痕迹）；事件层不属于任何 pattern，买点和角色属于某个 pattern；先看特征和先定目标分阶段配合。存储要守方向文档第 10 节第 3、4 条：每批一个新文件、文件名带机器名、只新增不改旧文件；记数据指纹。

来自「训练段用多长：样本多，还是和现在的市场像」（已批准）：找图、大涨段清单读同一个训练段设置（默认 2021-10-08～2025-12-31），不各自写死年份。防的是：看图、盲看和调参说的不是同一批样本，结果互相对不上。

来自「在要用的地方量一条特征：现有工具能不能直接做」（已批准）：标注里的特征勾选要和 app 里 where 分支同名；界面要能按特征显示量特征的结果（四选一结论、多出来几个买点日 / 几只股票、能分辨的最小差别、实测值），并能把「多出来的那些买点」调出来逐张看；结果记录里带 app 版本，app 改过后旧结果要显示为过期。

现状：标注页 `path2_web_ui/src/components/AnnotChart.vue` 完全不画 path2 事件，`App.vue` 带 `?wf=` 时整页换成标注页；主视图的事件画法见 `path2_web/GLOSSARY.md` 的副图、band、bracket、诊断侧栏。

## Answer

**确认的倾向**（2026-10-25 与用户对定）：「标得顺手」和「标完能直接拿 app 对回来」冲突时选后者。落到最后，「对得回」不靠让用户标注时就用 app 的事件和词，而靠标完由会话写的对应表、加上对照时和主视图同一套画法；标注本身因此可以干净、省事。下面每条都已逐项经用户拍板（2026-10-25，见 Comments）。

**一句话**：标注是主视图的一个模式，标的时候只有 K 线和自己的框；框的名字和说明用用户自己的词、存成一份跨图共用的清单，新图上点选即可；把这些词翻成 node、where 还是边、用现成 detector 还是新写，都是会话的事，结果写进对应表给用户看；对照只说人话的「认没认出」，不比起止、不给数字。

### 1. 界面

- 界面文字分两类、看一眼就分得开：用户输入和会话输出（每条都独一无二的业务内容，如词、定义、注释）用自然语言、无衬线，输入框外的再加浅灰底；程序固定内容（字段名、状态、按钮、标识符）用简短的标识符风格、等宽，可用英文对上代码里的符号，不写口语化的说明句、不重复已显示的内容。文字一律黑色，两类靠浅灰底和字体区分，灰字只表示空着或没选上（2026-10-26 改）。防的是：信息量过大，业务内容淹没在程序文字里。
- 标注是主视图的一个模式（看图 / 标注），不另开页面。防的是：标注和显示两套画法，标完对不回来。
- 正式版建在现有 web_ui 主视图上，原型代码不沿用、只沿用决定。看图模式的功能全部照旧（含悬停 tooltip、诊断侧栏）。标注模式下：K 线的悬停信息保留；系统事件不画，事件的悬停信息随之不出；对照开着时，悬停只出三层状态，不出诊断树里的实测值和门槛，要看数字就切回看图模式。防的是：数字从悬停这个侧门回到对照里，把用户拉去一张张调门槛。
- 标注模式只画 K 线、成交量、用户自己的框和买点；不画任何系统事件，不提供「点系统事件来标」。防的是：描述被现成事件带偏；点选收下的框拿去对照等于 app 自己考自己。拖框明显太慢时再考虑加回点选。
- 唯一例外：用户的概念本身相对某个算出来的东西定义（如「突破了前面好几个峰」）时，可以按种类单开那一种参照层（如峰的水平线），默认关、换图回关。防的是：这类概念离开参照根本标不出来。
- 「当前 pattern」在顶栏切；买点归当前 pattern，框不属于任何 pattern（方向文档第 8 节「事件层不属于任何 pattern」）。
- 从大涨段清单或「随机一张」（股票池 × 训练段随机取一段）进来的图，默认落在干净的标注模式。

### 2. 存什么

界面用词（2026-10-26 用户定，下文沿用讨论时的中文说法）：框的「说明」叫**属性**（attr），状态 true / false / null（null 即没看过）；词的一句话叫**定义**；框和买点的一句话叫 **instance 注释**；正例 / 像但不买的标识符是 label buy / no_buy。


- **用户自己的词，一份跨图、跨 pattern 共用的清单**：每个词有编号、措辞、可选的一句话。不分「名字类」「特征类」，任何词都既能当名字也能当说明；不提供 app 的 where 名单和现成事件种类名作选项。防的是：现成选项框住看图的视线；每张图重写同一个特征（加重操作，还逼会话去猜「放量」和「量很大」是不是一回事）。
- **框**：起止日期、一个名字（词的编号）、若干说明（词的编号 → 有 / 没有）、可选的一句话。框只记词的编号，所以改措辞只改清单一处、处处生效；意思变了就另建一个词。防的是：改一次措辞要改遍所有框，且和「只新增不改旧文件」的存储冲突。
- **新图上的操作**：画框 → 点一个词当名字 → 以前和这个名字一起用过的说明默认全带上 → 勾掉这张图上没有的 → 需要时当场加新说明。
- **说明三态**：有、没有、没看过。框上没列的说明 = 没看过（标这个框时这条说明还不存在），不当「没有」。发现新说明时不用回翻旧图；等它要进 app 且看过的框太少时，会话才把同名的旧框列出来请用户补点。防的是：后想到的特征被算成「少数图才有」，越晚发现越吃亏。
- **框套框 = 属于**：时间上被另一个框包住的框，默认算属于它；推断不出时才在图上问。也可以不画小框，只在大框上写说明。防的是：子事件（如 W 形底的两个低点）没有地方表达。
- **名字第一次出现时配一句话说意图**（如「W 形、V 形都算，有一个就行」）。防的是：数据只能显示「各占一部分」，分不出「取其一」「其实是两个 pattern」「都是加分」，这三种翻出来是完全不同的 app。
- **买点**：日期、所属 pattern、正例 / 像但不买、可选的一句话（像但不买时写买点那天就看得见的理由）。
- **不存角色**：框在买点里扮演哪个 node 不手填，会话按名字、位置、框套框推断，推不出（同一买点前两段同名的框）才在图上指给用户问。防的是：每个框多一步，且逼用户标注时按 app 的结构想。
- **「放过（我标宽了）」**：只把这一处从样本里拿掉，不改 app。
- 存储照方向文档第 10 节：每批一个新文件、文件名带机器名、只新增不改旧文件（改措辞也是新记一条）；记数据指纹；框按日期存、不存系统事件编号（app 改了编号会变）。

### 3. 对照

- **「对照 app」开关**：标注模式下、当前 pattern 有 app 时才能开；照主视图原样画 app 输出，显示档位到 detected（`path2_web/GLOSSARY.md:25`、`:28`），app 的事件和用户的框叠在同一条轨上（原型三种叠法只留这种）；每换一张图自动关。防的是：只画 matched 时多数图上什么都没有，「看到了但不够格」那档看不见；开关常开会让用户的印象慢慢往 app 的样子靠。
- **三层只给状态**，不比起止、不给数字：框是 qualified / detected / missing（认出 / 看到了但不够格 / 没认出；另有 unmapped 还没进 app、let_go 放过）；两框之间是 link ok / broken / pending；买点是 app:buy / no_buy（正例看附近，像但不买看前后一天）。有「取其一」时按分支拆开报（如「W 形 6、V 形 3」）。数字按名字汇总后只交给会话。防的是：看着实测值和门槛一张张放宽，app 变成拟合那几张图。
- **每层配一个底**：同样宽的框随便挪个位置也被判认出的比例，高了在汇总页提醒「这一行的数说明不了多少」。防的是：走势区段这类铺满时间轴的东西，随手一框也「认出」。
- **主要看法是每轮的汇总页**：对应表（你标的 → app 里由谁来认 → 认出几处，只写个数）、买点（正例几个 app 会买几个、像但不买几个 app 买了几个）、前后没连上的，问题排前；每行可点「这一行不对」。app 改版（含调参）后旧汇总标为过期、重出。单张图的对照开关是次要看法。
- **没认出的按原因分流，不让用户逐处拍板**：结构性的（没认出、没连上、一段被切成两段）会话直接修；只差门槛的不逐张追，按名字汇总、留给调参统一定；会话拿不准的进拍板单，配图、买点之后的走势先藏。
- **翻译归会话**：把用户的词翻成 node、where 还是边，用现成 detector 还是新写，都由会话按跨图证据定，写进对应表，where 按用户的词命名。现成的先试（所有 app 的 node，加上不在任何 app 里的平台段、走势区段等），认得出就用；只有要新写 detector 或改别的 app 也在用的 detector 时，才先给用户看一列小图。认不出时先排除判定口径的问题（回踩事件只记企稳后能买的那段，用户的框常连下跌一起框），不在任何 app 里的 detector 认不出时先怀疑参数，再下「要新写」的结论。防的是：复用 / 新建这种要懂 detector 规则、要跨图看的判断，落到用户在标某个框的那一刻去做。

### 4. 拍板时一并定下、归后续票落实的

- 盲看清单 = 随机 15 张 + 这次改动新增的、去掉的各最多 5 张（node 有「取其一」时少见分支补抽），混着看、分开报，只有随机部分算比例（张数待验证）。→ 票「app 盲看清单：抽多少、显示什么、标记存什么」。
- 训练段成绩每轮不主动报，只在用户问、准备调参、调参后最后检查前给，明显为负时主动提醒。调参先放开搜，调完报丢了哪几张标注、由用户定接受还是限范围重调，看的时候藏买点之后的走势。对照与盲看每轮都做；考卷回归只报不拦；按「剩下的毛病值不值得修」停。→ 票「串起「图 → 代码」循环的技能」。
- 划掉地图「还没想清」里「从框过的例子给 detector 定参数默认值」：标注是定性的、框的边是随手画的，量出的天数和深度不可靠，参数取值归调参。

### 6. 留待实施阶段验证

1. **默认数值**（框外容差 2 天、正例买点前后 3 天或落在回踩事件里、像但不买前后 1 天、偶然提醒线三成、盲看 15 / 5 / 5）。触发：第一批真实标注出第一份汇总页时。判法：会话逐个列出每个数让哪些框或买点翻了档，请用户过目（只看方向，不让用户定数）。验证前照默认值用。不合适就改数，不回头改本票的方向。
2. **回踩可能系统性判成没认出**（回踩事件只记企稳后那段，用户的框常连下跌一起框）。触发：第一批含回踩框的标注。判法：回踩框里，有多少只因 app 事件落在框外才判成没认出。若有，改判定口径（如改看事件的关键位置），不改 detector。
3. **「一点全带上」让人懒得核对**。触发：攒到二十来个同名框时。判法：默认带上、从没改过的说明里，有多少在对照时正是让框「不够格」的那一条。若多，把「默认带上」改成「默认没看过、点一下才算有」，回到用户面前确认。
4. **底的计算**：报告里过了 where 那一档的底只在一处算过。触发：汇总页第一次真算底时。判法：用汇总页自己的代码重算，与报告的量级对照；对不上先查代码。
5. **接受、不验证的风险**：单张图的对照开关看多了，用户的印象会往 app 的样子靠，这个影响记不下来，只能靠汇总页当主要看法、开关换图自动关来压低；「意图本身是从涨了的图里挑出来的」这条，循环内没有办法查，只由没碰过的数据上的最后检查来判。
