# critic：反方与剃刀（groups 重想）

本文中所有项目内路径均相对 repo root。polish = `docs/research/2026-10-26_annotation-workflow-polish/`（上一轮研究）。mock = `polish/repro/mock_v3.html`。用词照 `path2/GLOSSARY.md`、`path2_web/GLOSSARY.md`；「正例」= label `buy`，「像但不买」= label `no_buy`，「对应表」「必须有」「偏离」「主组」照 polish 的用法（这几个词两份词表都没有，polish `final_report.md:179`）。

## 结论（先读这里）

1. **整节删掉不可行，但「组」这个概念可以删。** 列表承担的三件事（全部买点的名单、app 跨图总数、批量挪）没有别处可去；而列表上的每一样东西（label、和对应表的差、app 判断）都是每个买点一个值，「组」只是「值都相同的并成一行」，不需要用户知道。
2. **推荐 ui 的 A 第三版**（`repro/variant_a_columns.html`）：一张 `instances` 表，`label` / `must / must_not` / `app` 三列各管一个来源，三列相同的并一行；页头加两个 app 总数；已命名页的列不随阶段换，没 app 时后两列空着、只按 label 两行；顶层特征串只在未归类页出现；features 区数正例的 `in k/N` 点开就地列出有它 / 缺它的那几张，可整批挪。
3. **心智负担**：概念 11 → 8，要记的规则 8 → 1，固定词 17 → 18（第 5 节）。
4. **改了两处先前裁定**：朱红一刀切（取消偏离 buy 漏买不红的豁免，经 sim 按事先判据实测）；已命名页不再按顶层特征串分组。
5. **没有悄悄丢的职责**：第 1.1 节 J1～J8 逐条有去处（J4 像但不买的差、J7 列表上的 `◂`、J8 `by:` 是有意删的，理由见 M1、V3、P7）。

## 0. 停止线

- **防谁**：防用户读错、要记的东西变多、该暴露的事不再暴露。不防措辞和像素。
- **剃刀的顺序**：每个方案先问「flow 的哪个任务要它」，没有任务对应的部分删；再问删了丢什么；最后数用户要知道的概念数、要记的规则数、屏上固定词数。三个数变多就是退步，哪怕看着更全。
- **来回**：同一问题与对方来回两轮没结论，写双方理由交 lead 裁定。

### 1.2 一处读错（lead 在 `原始问题.md` 第 3 条也这么写）

polish `final_report.md:83` **不是**说「偏离组负责暴露 app 悄悄变严」，说的恰恰相反：每张都顺手框的背景特征若被预填成必须有，所有正例都有它，**根本不会出现偏离组**，盲看「是」率也不变——没有任何地方会暴露。那里的防线是「这一类不预填，必须用户自己选」，落在 ask 单子上，不在 groups。偏离组能暴露的是另一种：把只有部分正例才有的特征定成必须有（polish `critic.md:227` R17「错了在分层上看得见」），没有它的那几个正例掉成偏离组。

所以：删掉或改名偏离组，**不会**动到 83 行那道防线；但会动到 R17 那一种的暴露（之一，另有 ask 的必须项检查和 pattern 页分层）。

### 1.3 现版已知的读错与负担

1. 用户本人把「主 / 偏离」读成「app 认出来了」（`原始问题.md` 末两条）。实际是「用户的框 vs 对应表」，不看 app。
2. 偏离和朱红都**不是用户待办**（polish `flow.md:352` 6b；`final_report.md:73` 阶段 4「朱红不是用户待办」）。groups 上没有一样东西是用户必须处理的；用户在这里真正动手的只有挪 pattern、点缩略图跳图、点 `◂`。它是阅读和跳图的地方，不是工作队列。
3. 缩略图上不显示这个买点 app 买没买（mock:1233-1262 的 `thumb` 只画框和三角），`app:buy 2/3` 要逐张点开才知道漏的是哪张。
4. 同一套签（`=`、`−X`）在 buy 上叫偏离、在 no_buy 上叫理由；分组键写 app 前后不同；朱红规则按组的种类不同。
5. 「主组」「偏离组」「骨架」「对应表」都不在词表里，界面上出现就是用户要额外记的词。

## 2. 独立预判（未看 flow / model / ui 稿前写下）

先自己列一遍用户打开这份列表的时刻（等 flow 的任务表来了对照）：

| 任务 | 时刻 | 用户心里的问题 | 看完动手吗 | 现版靠 |
|---|---|---|---|---|
| T-a 归组 | 未归类攒了一批 | 哪些买点是一回事 | 动手：整批挪进 pattern | J1 + J5 + J6 |
| T-b 要不要拆 | 没 app 的 pattern 页 | 这个 pattern 是不是混了两种骨架 | 偶尔动手：挪一批出去 | J5 + J6 |
| T-c 看 app 对得怎样 | 每轮对照之后，最高频 | 哪几个正例 app 没买、哪几个像但不买 app 买了，是 app 的毛病还是我没画全 | 不动手（朱红归会话），只跳图看 | J1 + J2 + J3（现版要逐张点开才知道漏的是哪张，1.3 第 3 条） |
| T-d 新标的齐不齐 | 两轮之间标了几张 | 我新画的和必须有对不对得上 | 可以先自己补框，不补也行（会话下一轮会问） | J3（标的当下 instance 页空槽已先给了一遍） |
| T-e 几周后回来 | 断点续做 | 这个 pattern 什么状态 | 不动手 | 页头 `next`、`instances` 为主，列表为辅 |

由此的预判：

- **P1 整节删掉不可行，但「组」这个词可以删。** J1、J2、J6 没有别处可去，未归类页会变空。可删的是概念：所有轴（label、和对应表的差、app 判断、顶层特征串）都是**每个买点一个值**，「组」只是「值都相同的合并成一行」。合并本身用 `×n` 一看就懂，不需要用户知道一个叫「组」的东西、更不需要知道「主组」「偏离组」。
- **P2 lead 候选的核心收益是真的。** app 判断当合并键之后，漏买的那几张自成一行，T-c 从「逐张点开」变成「直接点那几张」。三列各一个来源，正对着用户读错过的那一处。
- **P3（补法后被 V4 改掉：已命名页不按串合并，串只在未归类页）lead 候选有一个洞：没有 app 时只剩 label 一列。** diff 和 app 都要有 app 才有值，没 app 时表只按 buy / no_buy 合并，T-a、T-b 的依据（J5 顶层特征串）就没了，未归类页也分不了组。必须在没 app 时显示顶层特征串那一列。这一列随阶段换掉，就是 `by:` 换了个样子回来——差别是表头自己写着按什么分，不用另记一条规则。
  - 另一条路：写了 app 之后也一直按顶层特征串分、差签只作行上的附注。好处是没有阶段切换、写完 app 行不会突然合并；代价是可有可无的特征每多一个，行数就翻一番（会话定级正是为了把这类差别吸收掉，分组却又按它拆开）。预判倾向切换列，待 ui 的变体实测行数。
- **P4 label 当合并键的代价。** 同一串的 buy 和 no_buy 会分成两行，未归类页整批挪时多点一下，漏挪的像但不买留在未归类、显示 `pattern?`，看得见、撤得回。比「这一页 label 合并、那一页不合并」少一条规则，预判接受。
- **P5 列名必须说出参照是谁。** `diff` 不说跟谁比，用户已经把它读成过「跟 app 比」；换了列名还会照样读错。参照是会话写的对应表（必须有 / 必须没有），列名或悬停要点出来。
- **P6（后被 V1 推翻，定为一刀切）朱红只在 app 列，且「buy 缺了必须有、app 没买」那一行不标朱红**（Q5、X1 的例外要保留）。按「app ≠ label 就朱红」一刀切会把这类读成「app 又错了」；而 diff 列就在旁边，正好让用户一眼分清「漏买是因为我没画全」还是「我画全了 app 还是没买」——这是 diff 列在 T-c 里最大的用处。
- **P7 无任务对应、直接删**：`by:` 标识（J8）、「主组」「偏离组」两个隐含概念、组数 `n=`。缩略图的 `◂`（J7）零概念成本，留着。像但不买的差（J4）只要和 buy 同一列、同一套签、同一个定义，保留不加规则；单独处理反而多一条。

J1（全部买点名单）、J2（跨图合计）、J6（批量挪）没有别处可去，未归类页会变空。**不可行。** 但它证明了一件事：要留的只是「名单 + 每张的标记 + 批量挪」，「组」这个概念本身没有任务撑着。

## 5. 概念数、规则数、固定词数对比

**数法**（三个方案用同一把尺）：
- **概念**：用户要知道「它是什么」才能读对这一节的东西。同一含义多处出现算一个；整个工具通用、不是这一节引入的（buy / no_buy、pattern、点缩略图跳图）不算。
- **规则**：用户要记住才能读对或用对的条件句（「X 时 Y」）；屏上直接写着的（列名、块名）不算。
- **固定词**：这一节屏上出现的不同程序固定词（表头、签、按钮、符号）；特征名、pattern 名等用户内容不算；同词算一次。
- 都按代码与截图数，不是计时实测。

**现版要记的 8 条规则**（model.md 第 3 节 7 条 + 1）：① 分组键随阶段换；② label 是不是分组键随阶段换；③ 差的参照是对应表、不是 app 跑出来的；④ 偏离的 buy 漏买不朱红；⑤ 像但不买的 `=` 才可疑、buy 的 `=` 是好的；⑥ 像但不买的 `−X` 只算排在最后一个已有必须有之前的；⑦ 可有可无 / 不放 / 未处理的特征不影响分组，写完 app 组会合并；⑧ 一键挪只在「对得上」时出现，有 app、没 app 两套判法。

## 6. 未解决的分歧与交 lead 的事

团队内没有来回两轮仍不一致的分歧。V1（朱红一刀切）是唯一来回过的：critic 先提、一度撤回、flow 与 model 在交叉消息里转而接受并给出更硬的理由，最后按事先定的判据由 sim 实测定案（4.3）。

交 lead 的：

1. **J：每轮翻了哪些只放会话的交付说明**（F7）。flow 接受，但这是它最不放心的一处：交付说明在对话里，没有缩略图和跳转，要看哪张得自己按股票、日期找。critic 倾向维持（进单子就要加一类「不用答的条目」并规定 `ask n` 不数它）。

### 6.1 残余风险（接受，交实施阶段盯）

1. **一刀切读对靠的是同一行的差签**：sim 自己打折——它前两轮已知这一行的意思，不是真第一眼。若以后排版把 `must / must_not` 那格和 `app` 那格拆开或挤走，朱红可能又被读成「app 错了」。
2. **未归类页仍按整条顶层串精确相等成行**，少量买点时几乎一张一行；「相近的排在一起」的口径（两两相差几个特征，model）是推的，待验证；归组靠看缩略图，界面只给顺序。
3. **features 区点开后整批挪**的理由（F6）依赖定级的一半门槛：混进来的少、真特征离一半远时，这个入口只是省几下。
4. **像但不买的差不显示**（M1）：两轮之间看到一个朱红的像但不买，分不出是「app 没用上一个结构差」还是「根本没有结构差」，只能看缩略图自己比；会话下一轮会在单子里问。
5. 数是按代码与截图、按第 5 节的口径数的，不是计时实测；sim 用自己的口径数的规则数（`sim.md` 对比表）与本文不同，不要混着比。

4. **B、C 两个变体的文件还在 `repro/`**，只作记录，不是待选方案；ui 让三者只差列表的样子，共同改动（一刀切、像但不买不挂签、去 `◂`、属性计数不可点）三个都有。
