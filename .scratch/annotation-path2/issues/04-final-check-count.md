# 没碰过的数据上的检查：沿用 tune-gates-v3，跨次计数怎么补

Type: grilling
Status: open

## Question

### Purpose

训练段随便看以后，pattern 有没有用只能靠在没碰过的数据上的检查来说明，而检查次数一多就会挑出运气，所以这张票定怎么检查、怎么记次数。

现状：tune-gates-v3 的最后检查和复核各在一个 run 里只能跑一次，读取记在 `docs/sample_usage/<app>.v3.jsonl`；但跨 run 一共查过几次没有现成统计，代码版本存在 run 的配置里而不在账本行里（见 `.claude/skills/tune-gates-v3/scripts/run.py`、`governance.py`）。要定：

- 新流程直接用 tune-gates-v3 的最后检查，还是需要别的入口；
- 每个 app（以及它的各个版本、合并出来的 pattern）一共查过几次怎么数、在哪里给用户看；
- 2026 年起的数据只有约九个月，查到第几次应提醒用户、或者应换用更晚攒下来的数据（默认值标「待验证」）。
- 训练段（2026-10-24 由「训练段用多长」的批准定）：默认 2021-10-08～2025-12-31，保留 v3「一年前的成绩只算一半」的近期加权；调参读同一个训练段设置，训练段成绩按半年拆开、最近半年单列；改训练段须拿得出证据，不许按行情像不像或成绩好看来挑。
- 同日对照的配法和股票池（2026-10-23 由「在要用的地方量一条特征」的批准并入本票）：v3 现在是「同一天按当天波动切五档」、全部股票；旧 effort 判过这种配法会漏（偏爱平时很疯的股票，方向白输约 0.02、最坏一年 0.08，登记簿 FC-016），推荐「同一天、同一池子里波动最近的 10 只」并用它的默认股票池（`.scratch-archive/selection-pattern/issues/11-control-matching.md`），至今没换。换不换、什么时候换：它同时决定调参、最后检查和量特征的口径（量特征只调用 v3 的对照代码，v3 一换就跟上），量级约数百行。换了以后，已量过的特征要按原记录重量一遍、结论变了的列出来（量特征那张票的「留待实施阶段验证」第二项）。
