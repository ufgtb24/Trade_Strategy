## 1. 逐条审查发现

### 审查项 1 · 循环论证(用结果反推定义)

**结论:基本干净,但 directional 有一处语义越界风险。**

- payoff §4.4 明确排除「用 strategy_return 给 pattern 排名」、§6.6 论证端点收益是客观未来位移读数——都正确,不循环。
- decoupling §2 的 2×2 把「方向性」与「变现」分作正交轴,归因外生于任一单 label——不循环。
- **风险点(directional)**:若把端点收益当「方向预测力的度量」并用它评 pattern,会和 feedback c 项(首次穿越)给出矛盾结论(端点收益因漂移/少数大涨可为正,c 项说先涨比例不高于随机日)。这不是循环、是矛盾,但**信谁**是关键——见审查项 5,我裁定信 c 项。directional draft §3.1 把端点收益称「从根本上规避波动率混淆」「这正是用户要的」措辞偏强,有把「补盲工具」拔高成「方向预测力度量」的越界,需收窄。

### 审查项 2 · 前瞻偏差 / 用未来信息

**结论:payoff §5.2 的红线论证是三份 draft 里最扎实的一条,通过。**

- payoff §5.2 把「扫参选最优止损/止盈」定性为「用 label(未来收益)选参数、再用同一 label 报利润 = 循环 + 前瞻」,且 §5.3 进一步指出连「据结果事后调参」都污染——这条比一般的「别扫参」警告更深一层,建议 final_report 原样吸收为全队红线。
- 三份 draft 对此无异议。directional 端点收益不含交易参数、无此风险;decoupling §4.4 要求「参数调整只联动模拟交易 label」从 UI 层守住隔离。
- **唯一残留风险**:payoff §5.4 自己点出——可编辑输入框在语义上诱导扫参。这条要落成 UI 硬约束(见 §4 给 final_report 的 H2),不能只停留在「建议」。

### 审查项 3 · over-engineering(是否真需要两个 label)

**结论:两个 label 都需要,mfr 降级为披露;但 per-match 方向 label 的具体形态有更奥卡姆的替代,留作未闭合疑点。**

- 三份 draft 一致主张「方向性 + 模拟交易」两 label,decoupling §4.5 进一步把 mfr 降级为披露项——克制得当,我同意。最终体量「方向性 + 模拟交易(主)+ mfr(披露)」可接受,不算 over-engineering。
- **对 directional 的奥卡姆追问(未闭合)**:directional 主张引入「端点收益」作新语义。但 mfr 已是 max_high(上端极值),**最小改动是再加一列 min_low(下端极值)**,成「双端极值对」,同样解决 XAGE(都显示 -83%),且与 mfr 同构(只把 max 换 min)、保留过程极值、不丢信息;端点收益是「落点」、丢过程(directional §6.2 自己承认)。directional 弃 min_low 的理由是「双极值**合成**丢顺序」(候选 B)——但若**不合成、两列独立并列**(像 OHLC),就没有合成问题,各自保留极值语义。所以「端点收益」vs「mfr+min_low 并列」是真取舍,不是定论。我倾向后者(更小改动、不丢过程),但留待 directional 回应后再收口。这条不阻塞 final_report 的主结论,只影响 v1 实现形态。

### 审查项 4 · 重蹈 feedback §0 覆辙(payoff 越界当选股尺子)

**结论:payoff §3.3 的「信息 vs 目标」边界 + decoupling §4 的 UI 落地抓住了要点,但边界必须落成硬约束。**

- payoff §3.3 区分「当信息(反事实投影)」正当、「当目标(挑 pattern)」不正当——这是把 feedback §0 的解耦精神正确平移到人工场景。decoupling §1 进一步论证人工场景的解耦动机从「机械必须」降为「认知必须」(归因能力),同源不同形——论述扎实。
- **但风险是结构性的**:只要 payoff 在 UI 里和 mfr/方向 label 同级展示,用户**必然**会拿它给 match 排序、据此调 dag——这就是 §0 错误从自动 score 搬到人工 UI。decoupling §4.2(语义标注)+ §4.4(参数只联动 sim)是正确缓解,但还不够。需补一条硬约束(见 H1):**strategy_return 不进「选股质量」排序键**,只能进「交易投影」视图/面板。

### 审查项 5 · 对标 feedback 已有结论(directional 是否重新发现 c 项的失败)

**结论:部分是复显,但有增量;端点收益的真价值是「补跌盲区 + 个案可见性」,不是「产出方向有优势的新信息」。与 c 项冲突时以 c 项为准。**

- feedback 已证:**c 项(首次穿越)pk4 口径 8 个「年×阈值」单元 7 个先涨比例低于随机日、2024 四档 t=−3~−4;基线自身先涨比例 ≈0.5**——突破族方向上接近无信息。**A.1/g:控制波动率后 bo_only +72% lift 完全归零;label 中位与波动率倍数 R²=0.919**——任何 selector 的 score 首先是它的波动率读数。
- directional 的端点收益会把 c 项这个集合级结论在 per-match 层「复显」(用户看端点收益列会发现涨跌参半、净位移不偏涨)——**这是复显,不是新信息**。directional draft §5.4 也承认这一意图。
- **增量在哪**:mfr 永远 ≥0,看不到「跌」这半轴;端点收益(或 min_low)把负半轴还回来,让用户在个案层看见 XAGE 那种「mfr +1.3% 但实际暴跌」的 case。这是 mfr 给不了的可见性,是真实增量。
- **但绝不能宣称**:端点收益能产出「pattern 有方向优势」的新结论。feedback 已证没有。端点收益只会让「没有方向优势」这件事在个案层更清楚,不会把它推翻。
- **冲突时的裁定**:端点收益(净位移)与首次穿越(顺序)会矛盾(端点收益正、首次穿越说无方向)。信**首次穿越**——它与幅度解耦、与随机日比,是干净的方向检验;端点收益混了漂移(见 §2 漂移漏洞)和幅度。所以 per-match 端点收益是**次于集合级首次穿越**的退而求其次,定位应降级(见 H3、H4)。

### 审查项 6 · XAGE 案例(`tb_208_213` 暴跌 -83%、mfr +1.3%)

**结论:三份方案都比 mfr 强,但 payoff 的 -8% 是参数投影、非客观读数,必须标清。**

## 2. 三份 draft 各自的最致命问题

### 2.1 directional · 「期望中性 ⟹ 剔除波动率混淆」是偷换概念(核心支柱是空的)

这是 directional 整份 draft 的论证支柱(§3.1),但它混了两个不同的命题:

- **它证明了的**:端点收益对 σ **期望中性**——去掉 mfr 的选择偏差(`max` 选上端,`E[max]≥E[close]`,被 σ 单调抬高),鞅假设下 `E[close[t+N]]≈close[t]`,σ 只移动方差不移动期望。这一点技术正确。
- **它没证明、却当成已证的**:期望中性 ⟹ **单 match 排序不被波动率支配**。这是偷换。

**为什么是偷换**:用户在 web UI 看的是**单个 match 的实现值**,并按它排序。单 match 实现值 = `E + 噪声`,噪声的**幅度随 σ 放大**(directional §3.1 自己写「σ 决定 close[t+N] 的离散程度」)。所以高波动股的端点收益**实现值散布更大**:既出 +30% 也出 -30%;低波动股挤在 0 附近。用户排序时,「数值大/极端」的仍然**系统性是高波动股**——和 mfr 一样的病,只是病灶从「均值被选择偏差抬高」换成「方差放大致极值更极端」。

feedback g 项(A.1)的真正内核正是「label 的**方差**由 σ 解释」(R²=0.919),不是均值。端点收益去掉了 `max` 的选择偏差,会让那个 R² 系数**变小**,但绝不会到 0——因为单 match 实现值的散布仍由 σ 决定。所以 directional §3 标题「剔除波动率混淆的机制」名不副实。

**诚实表述应是**:端点收益去掉了 mfr 的**选择偏差**(max 选上端),但**没有**去掉波动率尺度对单 match 实现值的支配。波动率混淆的干净解法仍是 feedback 的路子(集合级首次穿越 + 随机日基线 + 披露波动率倍数,不打分),不是 per-match 端点收益。

**这条不否决 directional 的 label 本身**(端点收益补跌盲区的价值仍在),只否决它的**论证支柱**。directional 需把 §3 重写:支柱从「剔除波动率」换成「补 mfr 的跌盲区 + 让方向在个案层可见」。改完仍是「需要方向性 label」,但理由诚实了。

### 2.2 directional · 漂移漏洞(单 match 层混市场漂移,与 §0 批 payoff 同构)

directional 自己在 §7 提了漂移问题,但低估了它。集合级配随机日基线扣漂移——OK。但 directional §3.2 明说「单 match 级不需要基线」——这正是口子:单个 match 端点收益 +0.10,用户分不清「pattern 选对了」还是「这只股本来就在漂移上行」。

这和 payoff 被 feedback §0 批的「联合体」问题**同构**——payoff 混的是交易参数,directional 的端点收益在单 match 层混的是**市场漂移**。两者评的都不是「纯选股」,而是「选股 + 某个外生东西」的联合体。directional 把自己定位为「选股纯度诊断」(decoupling §2 也这么采信),但单 match 端点收益的读数并不纯。这是 directional 与 decoupling 之间需要校准的点。

### 2.3 payoff · §6.3 与 §6.5 内部自相矛盾(「必要非充分条件」论断站不住)

- §6.3 设想一个方向准确率只有 30%(70% 亏)的 pattern,论证「止损封顶 70%×(-8%)、跟踪止盈吃 30%×(+20%) 覆盖损失 ⟹ strategy_return 仍可盈利」——即**不对称结构使方向 mostly 错也能赚**。
- §6.5 却写「directional 是 strategy_return 的**必要**非充分条件——方向不对**一定不赚钱**(止损封顶撑不住高频亏损)」。

两者直接打架:§6.3 说「方向 mostly 错也能赚」,§6.5 说「方向不对一定不赚」。**裁定:§6.3 对,§6.5 的「必要」论断应撤回**。不对称结构(止损截断下行)恰恰使「方向对」**既非必要**(§6.3 已证方向差也能赚)。这反过来**加强**了 payoff 自己的核心论点「sim 不能当选股尺子」——既然方向差都能靠交易规则赚,sim 的正就更要警惕(虚假 alpha)。payoff 应把 §6.5 的「必要非充分」改成「两者各自独立提供信息、无蕴含关系」,别留这个硬矛盾给 final_report。

**v2 状态(2026-07-30)**:payoff 大修订了多处(§1.4 路径顺序独有价值、§3.4 UI 不变式、§6.7 波动率红利警示),但 §6.5「必要非充分——方向不对一定不赚钱」(行 256)**仍未改**,已两次要求。此外 §6.7 新增「directional 是期望-波动率中性的解药」**过强**(继承 directional 的错误支柱:directional 只在集合期望中性、per-match 实现值方差仍随 σ 放大)——见 H8。这两处须在 final_report 前闭合。

### 2.4 decoupling · 2×2 的「方向性轴」读数可靠性依赖 directional label 质量(打折)

decoupling §2 的 2×2 正交归因是漂亮且实用的红利框架,但它的价值取决于「方向性好/差」这一轴的读数是否可靠。若这轴用 directional 的端点收益量,则继承 §2.1、§2.2 两个污染(单 match 方差随 σ 放大 + 混漂移)⟹ 2×2 的方向轴读数打折,整个归因可靠性也打折。

**建议**:decoupling 在 draft 加一条——2×2 的方向轴,**集合级**用首次穿越(干净,feedback c 项口径)、**个案级**用肉眼+端点收益(辅助、带折扣读)。别让读者以为 2×2 的方向轴是可靠的定量轴。另:decoupling §2 末「交易策略评估 = 模拟交易 label 中无法被方向性 label 解释的部分」概念优雅,但量纲不可减(decoupling 自己承认),final_report 必须把它写成**定性归因**,不是可计算的数值减法。

## 3. 三份 draft 的强项(诚实承认,建议 final_report 吸收)

怀疑者不为怀疑而怀疑。以下论点站得住,是真贡献:

1. **payoff §5.2 扫参前瞻偏差论证**:把「扫参」定性为「用未来选参数、再用同一 label 报利润」的循环+前瞻,且 §5.3 指出连事后调参都污染——比一般警告深一层。全队最扎实的红线表述。
2. **payoff §2.3 + §6.3**:「方向准确率相同、sim 却差很多」(平滑趋势 vs 尖刺型)+「30% 准确率仍可盈利」——两条合起来从正反两面证明「sim 不是选股尺子」。§6.3 同时是 decoupling §6 虚假 alpha 的微观基础。
3. **decoupling §6 虚假 alpha**:把 feedback A.1(控 σ 后 lift 归零)+ c 项(方向无优势)合起来推出「方向无优势 + 高波动 + 不对称交易 ⟹ 模拟交易 label 假阳」——**决定性论证,应作 final_report 核心警示**。
4. **decoupling §3 端到端类比边界**:澄清「类比的形式(联合体+输出利润)归属模拟交易 label 的评估端,但训练端(梯度反传)在人工场景无对应物」——堵住「端到端 ⟹ UI 自动反优选股」的大误区。
5. **decoupling §1 机械必须→认知必须**:正确刻画人工场景解耦动机的降级,论证解耦仍「必须」(归因能力)。
6. **directional 弃候选 B/C 的理由**:对齐 feedback line 369(幅度统计丢顺序、双端被 σ 放大),扎实;把首次穿越(D)放 summary 层、per-match 用标量的分层合理。

## 4. 给 final_report 的硬约束(skeptic 红线)

final_report 必须满足以下硬约束,否则不予认可:

- **H1(配对解读铁律)**:strategy_return 绝不能单独下「选股有 alpha」结论;必须与方向性 label 配对解读。方向性差 + 模拟交易好 = 警报(很可能波动率红利/幸存者偏差,非选股功劳)。(出处:decoupling §6 + payoff §6.3)
- **H2(参数外生 + UI 禁扫参)**:交易参数是用户风险偏好的外生声明,默认值须有先验正当性(非数据调出);UI 不提供批量扫参入口,可编辑参数旁加反扫参警告;连「据结果反调参数」都视为污染。(出处:payoff §5.2–5.4)
- **H3(方向 label 不宣称剔除波动率)**:方向性 label 的定位是「补 mfr 的跌盲区 + 让方向在个案层可见」,**不是**「剔除波动率混淆」。波动率混淆的判据仍是集合级首次穿越 + 随机日基线 + 波动率倍数披露(feedback c/g,不打分)。draft 不得沿用「期望中性 ⟹ 剔除波动率」的表述。
- **H4(冲突时以首次穿越为准)**:per-match 方向 label(端点收益等)与 feedback c 项(首次穿越)结论冲突时,以 c 项为准——c 项与幅度解耦、与随机日比,是干净的方向检验;per-match 端点收益混漂移+幅度,读数带折扣。
- **H5(mfr 保留 + min_low 补方向诚实)**:mfr 有 feedback §0 背书(score = mfr median 增量 + 顺序闸 + 因果闸都基于它)且 R²=0.92 波动率读数本身有诊断价值——**保留**,不替换。它「只看涨」的缺陷用 **min_low 伴随量**(`min(low)/close-1`,与 mfr 同构、零框架成本)补,让 per-match 方向诚实。XAGE(-83% vs +1.3%)说明 mfr **单独**不能当决策依据,但作 score 基底 + 乐观上界披露仍保留。(据 decoupling v2 §7/§8)
- **H6(虚假 alpha 必为核心警示)**:final_report 必须把「方向无优势 + 高波动 + 不对称交易 ⟹ 模拟交易 label 假阳」作为核心警示写出,不得埋没。(出处:decoupling §6)
- **H7(反 over-claiming,最重要)**:本次讨论**不改变** feedback 的核心负面结论——pattern 在方向上无优势(c 项)、lift 是波动率而非方向优势(A.1/g)。新 label 的作用有二,且**都是负向的诚实化,不是创造 alpha**:① **止住 mfr/sim 对「无优势」的粉饰**——mfr 只看涨会把无优势粉饰成 +72%,min_low/方向 label 让「涨跌参半、净位移不偏涨」在个案层可见(feedback 负面结论的可视化);② 让交易层有一个外生投影。**绝不是**「换把尺子就能量出 alpha」。final_report 不得暗示换 label 会反转 feedback 的结论,否则就是给用户虚假希望、重蹈「换尺子找 alpha」的循环。(据 decoupling v2 §9)
- **H8(sim 虚假 alpha 的三层规避,不只靠 directional)**:sim 的波动率红利(方向无优势 + 高波动 + 不对称交易 ⟹ 假阳)单靠「与 directional 共读」**不充分**——directional(端点收益)在 per-match 实现值上也有方差污染(§2.1),per-match 层两个 label 都带噪声。完整规避需三层:① per-match 共读(directional + sim);② **集合级统计闸**(feedback c/g 口径,独立于任一 label:命中集波动率倍数 + **控 σ 后 sim 条件百分位**——类比 bo_only +72% lift 控 σ 后归零,若 sim 正期望控 σ 后归零即标红「波动率红利,非 alpha」+ 首次穿越方向检验);③ UI 标注 sim 的波动率暴露。(回应 payoff 反向问题;纠正 payoff §6.7「directional 是完全的波动率中性解药」之过强)
- **H9(UI 闸门:sim 不进默认选股排名)**:sim 不作为「与 mfr 同级的 label」参与选股排名,独立 readout 面板、可按需排序(信息用)、明确标注身份、无「按 sim 选 pattern」入口、不与选股指标合成综合分。原 plan「同级 label」定位须改。这是 H1 在 UI 层的物理闸门——光靠人类自律不够,靠 UI 默认值堵住「目标用法」。(据 decoupling v2 §4)
- **H10(扫参红线精确化)**:红线不是「参数**值**是否来自数据」,而是「**参数选择程序**是否在样本上对 sim 做 argmax」。允许灵敏度分析(报告参数敏感性,诊断用),禁「据结果选 argmax 当纪律」;连「据事后观察调参」都视为污染(因不可审计)。参数须来自数据之外的先验(资金管理规则、心理承受度、别的市场经验)。(据 payoff v2 §5.2-5.3,精确化其判定标准)

## 6. 对「是否需要两个 label」的最终裁定

**需要,各管一层,mfr 降级:**

- **方向性 label(directional)**:需要。真价值 = 补 mfr 的跌盲区 + 让方向在个案层可见。**不是**剔除波动率(那是假支柱)。per-match 形态待收口(端点收益 vs min_low);集合级方向预测力判据仍是首次穿越(feedback c 项)。

### 7.2 收敛后设计的整体怀疑论评估:站得住,但有一条战略保留

把收敛后的设计当一个整体审:**mfr(保留·披露)+ min_low(新增·最小)+ strategy_return(新增·隔离 readout)+ 端点收益(暂缓·YAGNI)**。

- **min_low 通过怀疑论审查**:零框架成本(与 mfr 同构、只 max→min/high→low,核实自 `path2/eval.py:39`)、解决 mfr 在 XAGE 上「+1.3% 粉饰」的可见性盲区、(mfr, min_low) 双端极值的「背离即信号」有 triage 价值(批量扫描时用数值快速捞出灾难型 match,这是逐个点开 K 线做不到的)。诚实成本承认到位(方差仍被 σ 支配,同 mfr)。**性价比高,通过。**

- **strategy_return 有条件通过,战略保留如下(lead 须写进 final_report 的诚实成本)**:
  - payoff §7.7 自己已采纳我的战略疑虑并写明:「web UI 里路径肉眼已可见(K 线就是路径),sim 把路径压成一个数、损失恰是肉眼能看的细节 ⟹ sim『路径/顺序独有信息』在 UI 场景的增量 < 在无 K 线的自动 score 场景」。这点我独立确认、加重:**sim 在「有 K 线的 web UI」场景下,其最核心的独有价值论证(§1.4 路径顺序)被 K 线本身部分架空**。
  - 残留价值仅两条,且都不强:① 「mfr 现实主义砝码」——但 min_low 的 -83% 比 sim 止损截断后的 -8% **更诚实**(sim 的 -8% 反而会把 -77% 的裸位移灾难粉饰成「小亏」),砝码角色 min_low 已胜任、sim 在这一点上是**冗余且更弱**的;② 「个人风险偏好投影」——合法,但那是用户的**交易决策**辅助,不是选股评估,且参数依赖(整套 §5 纪律的成本只为此一项)。
  - **战略保留(skeptic 立场,非否决)**:sim 值得做(用户明确要、且让「交易层」从抽象变具体),但其复杂度预算(3 参数 + UI 隔离 + 扫参红线 + 三层虚假 alpha 规避)远高于 min_low,而其在 web-UI 场景的边际收益是这套设计里**最薄的**。⟹ 优先级上 min_low 必须先做、sim 后做;定位上 sim 必须克制(砝码 + 个人投影,**不追求独立决策列**),强约束与 directional/min_low 共读。这正是 payoff §7.7、decoupling §4 已落定的姿态,skeptic 确认无误。

### 7.3 ★ 最重要的一条:H7 必须作 final_report 的框定,不是脚注

**怀疑论者最终的、最重的异议不在任何单个 label,而在整个任务的 framing 风险。**

用户进场的话术是「mfr 是问题、只看涨失真」。但:
- feedback §0 已定案:mfr 的「只看涨」是**特性**(量上涨触碰潜力),不是 bug;XAGE 的 +1.3% 是 mfr 在**正确量它该量的**(那 40 天盘中确实摸过 +1.3%),所谓「失真」是用户拿 mfr 回答了它不该回答的问题(持有收益/方向)。
- feedback c 项已证:**pattern 在方向上无优势**(首穿 8 单元 7 个低于随机日);A.1/g 已证:lift 控 σ 后归零、label R²≈0.92≈波动率。

⟹ **新 label 的产出将是什么?** directional/min_low 会显示「涨跌参半、净位移不偏涨」(复显 c 项),sim 会显示「任何正期望控 σ 后归零 = 波动率红利」(复显 A.1),min_low 会显示「高波动」(复显 g 项)。**三个新视角,都在用不同方式确认 feedback 已有结论。**

这不是无用——诚实化有独立价值(止住 mfr 把「无优势」粉饰成「+72%」、让交易层有投影)。**但 final_report 必须以此为框定**:本次 label 设计是「让既有负面结论在个案层更可见 + 给交易层一个外生投影」,**绝不是「换把尺子去量出 alpha」**。任何措辞若让用户产生「新 label 可能反转 pattern 评价」的预期,就是给虚假希望、重蹈 feedback §0 警告的「换尺子找 alpha」循环。

**这条比任何技术细节都重要。** 我在启动审查清单里点过(「用户是否混淆了驱动力度量与方向预测度量;真正问题可能不在 mfr 而在误用」)——经全队讨论,这条未被推翻、反而被 feedback 数据加强。lead 写 final_report 时,**第一段就该把这条摆出来**,而不是埋在「诚实项」里。

### 7.4 最终优先级建议(给 lead 的可执行结论)

按怀疑论/奥卡姆排序(边际收益 ÷ 复杂度成本):

1. **先做 min_low**(最小、最高性价比):零框架成本、补 mfr 盲区、批量 triage 灾难 match、诚实化「无优势」。**这是唯一该立即实施的。**
2. **strategy_return 后做、克制定位**:独立交易层 readout、UI 隔离、参数外生固定、禁扫参、必须与 min_low/方向共读。**不追求独立决策列。** 边际收益最薄、复杂度最高,排在 min_low 之后。
3. **端点收益暂缓(YAGNI)**:min_low 不足以回答「净终点方向」时再补;v1 不上。
4. **mfr 保留不动**:§0 背书 + 诊断价值,补而非换。
