# 智能层设计：标注越用越聪明（smart，第一轮草稿）

> 本文所有项目内路径均相对 repo root。状态：定稿（2026-10-16）。第一轮独立起草；第二轮对齐 needs、ux（用词统一为「要素」「形态卡」「触发」「事实表」，三种「放弃」分开，系统提议只进待回应）；第三轮回应 auditor 的 S1～S6 与 needs 转达的 N3 来源判定、ux 第三稿拿掉猜形态横幅。修订处标「第二轮」「第三轮」；与 auditor 的逐条对照见第 14 节，auditor 审计结论为通过。
> 词表里的词照用并带出处；本文的「尝试」一律指账本里按次数扣运气的那种，不是词表里 detector 的 attempt（`path2/CONTEXT.md:88`）。

## 0. 一句话结论

**算得出来的事实由机器写，信不信由用户点。** 用户点好买点之后，系统在 0.1 秒内算出一张「事实表」（按收盘和按最高价各越过几个峰、哪几天放量、买点前缩没缩量、有没有派发、买点当天发生了什么……），用户只在信的那几行上点「必需 / 加分 / 必须没有」（不点＝无所谓），在口径真有分歧时点选一个口径，再从几个候选里点一个触发和一条买前失效条件。备注从「从零写一段话」变成「对一张算好的事实表打勾」，自由输入框保留，任何推荐都能改。（第二轮：态度档位、事实表固定顺序与 needs 第 2 节、ux 第 3.1 节对齐。）

「越用越聪明」靠的是**只学用户怎么描述、怎么选**（用户的说法变成要素库的别名、答过的口径记成默认、用户认领一张形态卡后按卡预勾只改差异、用户以前选过的触发与失效原因排在前面），**不学哪些要素后来涨得好**——后者是挖数据，留在现有的对照页和账本里走挖数据的纪律，标注界面里不出现。

第 0 阶段（本周就能用、不花 API 钱、界面只补约 1 天：多买点、正例范围可空、色盲友好的 K 线）：用户照旧框选、点买点、选正反例，备注写三五个字或干脆不写；会话对每条标注跑事实表脚本，新形态时先请用户说三五个字，再在对话里把事实表列成编号清单，只问两三个会改变规则的问题，用户回「1 收盘必需、3 加分、触发 A、失效 2」这样的短答。

## 1. 缺口在哪：下游要什么，用户想怎么偷懒

下游（写成规则草稿 → 做成 path2 pattern → 对照判）从一张标注里要这几样（lead 对第一张图的点评，见 `背景.md` 第 3 节；最终清单以 needs 的信息契约为准）：

| 下游要的 | 现在从哪来 | 机器能不能替用户写 |
|---|---|---|
| 形态由哪些要素构成，每个要素的口径（按最高价还是收盘、「近期」指哪几天） | 用户的一行备注，口径常常含糊 | **能写事实，不能替用户判断哪些重要**：要素是否存在、具体数值、口径分歧都能算；「哪几条是你买它的理由」只能用户点 |
| 为什么是这一天买（触发条件，决定规则哪天出信号，最要紧） | 备注里通常没写 | **能列候选**：买点当天发生了什么可以算出来，用户点一个 |
| 什么情况放弃（第二轮：分成买前失效 / 买后离场 / 研究级放弃三种，见 2.2 节末） | 没写 | 买前失效**能给模板**，用户勾；买后离场可跳过；研究级放弃不进标注 |
| 形态叫什么（归类） | 没写 | 名字由系统按勾选拟、用户可改；之后的图由用户从自己的卡列表数字键认领，系统不猜 |
| 为什么会涨（一句直觉） | 没写 | 不能代写，只能把用户的三五个字扩成一句让用户确认；可空 |
| 正例 / 反例 / 数据有误 | 已有单选 | 不变 |

用户想要的偷懒方式：点选、确认、改错，不从零写；用户追加说明「用户也可以自己输入，可以修改推荐」——所以每一项都留自由输入，每一条推荐都能改。

## 2. 核心机制：事实表 + 勾选

### 2.1 可行性试验（已做，便宜，只读买点当天及以前的数据）

脚本 `repro/prefill_facts.py`，输出 `repro/prefill_facts_out.json`。做了什么：拿用户的第一张标注（QMMM，框 2025-02-28～07-14，买点 07-14）和用户提到的另一个买点（07-08），再加清单里另外 8 段（框取决策日前 90 个交易日，买点取清单决策日），读入行情后**立刻截到买点当天**，用现成的 path2 detector 和几条简单计算起草事实表。说明什么：lead 对着图手工核出来的每一条，机器都能自动算出来，而且算得比人眼细；不说明什么：这些事实和后来涨不涨有没有关系（完全没读买点之后的数据，也不该在这一步读）。

QMMM 07-14 自动算出的事实表（原样整理）：

- **框内的峰**：按最高价有两个峰，3/13（2.08）和 5/28（1.63），买点收盘 1.82 只越过了 5/28 那个；按收盘价，3/12（1.68）、5/23（1.48）都越过了。——**正好复现 lead 点出的「按最高价只突破一个、按收盘是两个」**，这条分歧机器能自己发现并转成一个点选题。
- **成交量**：量比 ≥3 的放量段有三段：3/4～3/11（平均约 4 倍）、5/8～5/9（最多 26 倍）、6/20～7/3（平均约 6 倍、最多 10 倍）；买点当天量比 0.62，买点前三天均量只有最强放量段的约 12%。——复现「6/20～7/3 放量、买点前三天明显缩量」，同时暴露「近期量很大」到底指 5/8 那天还是 6/20～7/3 那段，又是一个点选题。
- **买点前 20 天**：涨 78%，七成收阳，最大回撤 8%，走得很直（对数价格对时间的直线拟合度 0.95）。——把「连续稳定上涨」变成了数。
- **派发**：5/28 有一根派发（`path2/CONTEXT.md:42`，放量 3.4 倍、长上影）。——用户写的「没有过于剧烈的派发迹象」，机器会把这根列出来请用户点「这根不算」或「买点前 N 天内没有派发才算」，于是「过于剧烈」第一次有了口径。
- **买点当天发生了什么**：「前 5 天从近 10 日高点回落 26% 后，当天收盘越过前一天最高价（回落收回）」「当天缩量」。07-08 那个买点则是「当天是突破（`path2/CONTEXT.md:11`）、收盘首次越过框内的峰、收盘创 20 日新高」。——两个买点被自动区分成两种触发时机，正是 lead 说的「两个版本」。

另外三个观察：

1. **耗时**：每张图 0.02～0.1 秒，实时预填没有性能问题。
2. **触发条件库一开始很空**：另外 8 段在清单决策日上，6 条预置触发模板几乎都没命中（只有 1 条命中「创 20 日新高」）。原因是清单决策日是机械挑的、不是用户的买点；但这也说明**触发条件这一栏必须靠用户补词来长**——「没匹配到任何触发模板」本身就是请用户说一句「这天你看到了什么」的最好时机（第 5 节来源 b）。
3. **path2 的突破检测默认参数和用户眼中的「峰」不完全一致**：默认参数下突破检测登记的峰偏短期（20 根窗口），框内列出了 5 次突破；用户说的「两个峰」是更大尺度的。事实表里要同时给「大尺度的峰」（两侧各 10 根更低，待验证）和 path2 突破两种，最终规则用哪个尺度由用户的点选决定，这正是把口径问清的价值。

### 2.2 事实表长什么样（第二轮：版式以 ux 第 3.1 节为准，条目以 needs 第 5 节的 14 条为准）

第一轮我提的是「只列这张图上出现了的事实」；第二轮改采 ux 的做法：**固定顺序的事实表**，每张图同样的条目、同样的顺序、写明本图的数（没有也写「没有」），不按系统觉得重要的程度排序。理由是 ux 说的——它是一张检查单，不是推荐榜；固定顺序也让「无预填抽查」（第 9 节）的对比干净。智能层负责的是每一行背后的计算和下面三件事：

1. **口径分歧拆成并排两行，只在这张图上结论不同时才拆**：每个要素自带几个口径变体（按最高价 / 收盘、近 3 / 5 / 10 天……）。在这张图上几个变体结论一致，就只显示一行；不一致才拆成两行，用户勾哪行就是在答分歧题（QMMM：「按收盘越过 2 个峰」「按最高价越过 1 个峰」）。用户答过一次，记成这位用户对这个要素的默认口径，同一形态卡以后不再问（第 7.3 节机制 2）。
2. **每一行带图上标记**：勾选或鼠标移上去，图里对应的峰、放量段、派发那根加粗。用户一眼确认「是这个意思」，不用读数字。
3. **可知性标注**（needs #14）：回顾型事件（`path2/CONTEXT.md:72`，如走势区段、平台段）要走完才确认；若它在买点那天还没确认，这一行写明「这一段在你点的那天还没走完、当时看不出来」。试验里 QMMM 的最后一段上涨走势区段（7/2 起）到买点那天正是这种情况。

勾选档位按 needs：**必需**（进第一版规则的条件）/ **加分**（不进第一版，收紧时优先试，并记成「用户事先说过的」收紧）/ **必须没有**（买前失效，和要素同一种东西）/ 不勾＝无所谓。

事实表之外的几格（触发、买前失效、形态、为什么会涨），智能层给的候选：

| 格子 | 智能层给什么 | 用户操作 |
|---|---|---|
| 触发（每个买点一个） | 买点当天发生了什么：QMMM 07-14＝「回落收回」，07-08＝「当天突破、收盘首次越过框内的峰」 | 预填，下拉可改；「都不是，我说一句」 |
| 买前失效 | 按已勾要素给 1～3 条默认（「收盘跌回被突破的峰之下」「出现派发」） | 勾 / 改 / 自己写 |
| 形态 | 第三轮（随 ux 第三稿）：**不再弹「像你的某某」横幅**。用户从自己的卡列表认领（按用户自己最近用过的先后排、配数字键），点买点加一个数字键就完；系统拿被认领的卡去对这张图，对不上才弹三选一（机制 5）。确定性的逐条对照样在后台算，只用来统计「用户认领」与「卡定义」的一致率，以及给形态库「未归类」里的图排序 | 数字键认领 / 新建 |
| 为什么会涨 | 不代写；用户说三五个字时扩成一句请确认 | 看图时可空，规则草稿交用户确认前必须补一次（needs） |

两个买点怎么记（needs 裁定）：同一触发的两个点（如两次突破当天）是同一版本的两条测试用例；触发不同（QMMM 07-08 突破当天、07-14 回落收回）是同一形态卡的两个版本，各算一次尝试；连要素都不同就是两个形态。

第一轮把三种「放弃」混成一格，第二轮按 needs 第 3 节分开：**买前失效**（形态出现后、触发前，这次机会作废）进标注；**买后离场**是配套买卖规则，形态级可跳过；**研究级放弃**（候选收紧几轮还不行就整体放弃）由 agent 设，不进标注工具。

## 3. 要素库（用户说的「单因子库」）怎么表示

用户说的「单因子」，本文叫**要素**：图上一件能用代码判定有没有、并能给出数值的事。叫要素而不叫因子，是因为它不必是一个数（「框里有两个峰被越过」是结构），并且避免和挖数据里的「因子」混成一回事。（这个词要不要进词表，交 lead 判断。）

### 3.1 一条要素记录

| 字段 | 内容 | 例子 |
|---|---|---|
| 编号 | 稳定的英文短名 | `peak_cleared` |
| 人话名 | 显示给用户 | 收盘越过框里的峰 |
| 别名 | 用户说过的各种说法，自动累积 | 突破前高、过前高、连续突破了两个峰 |
| 事实表分组 | 峰与突破 / 成交量 / 涨跌与位置 / 派发 / 平台与回踩（ux 第 3.1 节）；另有触发、买前失效两类 | 峰与突破 |
| 计算定义 | 一个只读买点当天及以前数据的函数，返回「有没有、数值、一句人话、图上标记」 | 见 `repro/prefill_facts.py` 的峰与放量段计算 |
| 口径变体 | 会让结论不同的几种算法 | 按最高价 / 按收盘价 |
| 参数 | 默认值，全部待验证 | 峰两侧各 10 根 |
| 对应的 path2 零件 | 用哪个 detector、哪个事件字段，写规则时直接搬 | 突破 `path2/CONTEXT.md:11`、峰 `:15`、burst `:24`、回踩 `:27`、平台段 `:39`、走势区段 `:36`、派发 `:42` |
| 来源 | 种子（path2 词汇）/ 通用知识 / 用户的话 / 系统发现 | 种子 |
| 状态 | 只有名字（待写代码）/ 可计算 / 已有 path2 detector | 已有 detector |
| 使用统计 | 只记用户行为：出现几次、被勾必需 / 加分 / 必须没有各几次、推荐了被改掉几次 | — |

存法：要素的定义（代码 + 一份描述文件）随代码进 git，定义一改就生成新版本号；用户相关的部分（别名、默认口径、使用统计）放 `outputs/chart_workflow/` 下（不进 git），全部由操作日志算出（第 7 节）。具体放哪交 arch。

### 3.2 形态卡

一张形态卡 = 名字 + 若干「必需」「加分」要素（带口径）+ 若干「必须没有」要素（即买前失效条件）+ 一个或几个触发 + 可选的买后离场偏好 + 一句为什么会涨 + 例图列表（字段草案以 needs 第 5 节为准）。**形态卡就是规则草稿的输入**：必需要素对应 path2 的 node 与 where（`path2/CONTEXT.md:102`），触发对应买点落在哪个 node，买后离场偏好对应配套卖出规则。同一张卡的不同触发是它的不同版本，以后各算一次尝试。

### 3.3 种子库（冷启动，不和用户耦合）

第一天就有的要素来自两处：

1. **path2 现成的事件**：突破、峰、burst、回踩、企稳段、平台段、走势区段、派发，加上 `chart_workflow/features.py` 的涨前位置、近 60 日涨幅、波动宽度、跳空、量倍数。代码已有，只需包成「一句人话 + 图上标记」。
2. **通用技术分析常识**：缩量回调、放量过前高、均线多头排列、底部逐步抬高、长下影试盘、跳空缺口未补、波动逐步收窄等约 30 条（数量待验证）。由会话一次性写成代码、配测试、冻结版本，**不让大模型去查「哪些在 2025 年管用」**（那等于借未来，见第 8 节）。第二轮：这一类不直接进事实表，作为「系统提议·通用知识」在待回应里按形态级问（第 6 节），用户采纳了才进事实表。

## 4. 从已标注的图里归纳：主成分分析合不合适

**不合适做要素库的生成器**，理由四条，都是它的工作方式和这里的需求对不上：

1. 主成分分析的产出是「所有指标按某个比例混在一起」的一个方向（比如 0.4 份量比减 0.3 份回撤再加……），不是一个能起名字、能点选的单个要素。用户要的「单因子」恰恰是它给不出的东西。
2. 它找的是被分析的那批图**彼此差别最大**的方向；归纳用户倾向要找的是这批图**共同有**的东西，而判断要素有没有用要找的是**赢家和输家**之间的差别。两件事它都不做。
3. 只有几十张图、而指标有几十个时，它找出来的方向很不稳定，多标一张图就可能整个翻过来。
4. 它只能在事先算好的指标里打转，发现不了库里还没有的要素。

推荐的替代做法，按用得上的时间排：

| 想回答的问题 | 做法 | 从第几张图起用得上 | 读不读涨跌 |
|---|---|---|---|
| 用户常看重什么 | **直接计数**：每个要素被勾「必需」「加分」的次数和比例 | 第 1 张 | 不读 |
| 这几张图是不是同一个形态，共同点是什么 | **共同要素（只数用户勾过的）**：同一张形态卡下的图，按用户自己的勾选列出「每张都勾了」「多数勾了」「偶尔勾」的要素，请用户确认哪些定为必需。第二轮补：**不数「每张图上都出现、但用户没勾」的要素**——那是系统在一批按结果挑出来的赢家里找共性，等于读了涨跌（见第 10 节第 2 条） | 同一形态 3 张起（待验证） | 不读 |
| 新来的图像不像已有的形态 | **逐条对**：按「出现了哪些要素」算新图和每张卡的重合度。第三轮：不在界面上猜，只在后台统计「用户认领」与「卡定义」的一致率，并给形态库「未归类」里的图排序 | 有第一张卡起 | 不读 |
| 有没有用户没意识到的分组 | **按用户勾选的重合度分组**，把建议分组给用户看、让用户起名或合并——只用来整理用户自己的标注，不当找因子的手段（auditor B3） | 约 20 张起（待验证） | 不读 |
| 哪些要素能把赢家和输家分开 | **单要素对照或决策树式归纳**，必须对着同日普通买入对照（`path2/CONTEXT.md:155`）做 | 不在标注工具里做 | **读，属于挖数据，入账** |

主成分分析唯一合适的位置是将来（几百张图之后）的诊断：找出几条说的其实是同一件事的要素（比如「量比」和「放量段均量」），用来精简事实表。不进第 0～2 阶段。

## 5. 自动预填：哪些靠确定性计算，哪些值得用大模型

| 环节 | 谁来做 | 理由 |
|---|---|---|
| 事实表所有数值与「有没有」 | **确定性代码** | 可复现、零成本、不借未来（只读买点当天及以前）；试验表明够用 |
| 口径分歧检测与追问 | **确定性代码** | 跑几个变体比一比就知道，不需要语言理解 |
| 触发条件候选（买点当天发生了什么） | **确定性代码** | 同上；模板不够时转来源 b |
| 买前失效候选 | **模板 + 用户历史排序** | 固定几种，用户以前选过的、「像但不买」的原因排前面 |
| 形态匹配（像哪张卡） | **确定性代码** | 要素重合度，透明 |
| 把用户的三五个字对到要素上（「双峰突破 缩量」→ 勾哪几行） | **大模型**（便宜的就够） | 中文口语、交易黑话（「老鸭头」「N 字」「洗盘」）需要语言理解；输入里没有任何标的信息 |
| 用户的话对不上任何要素时，起草一个新要素的定义 | **大模型起草 → 代码计算 → 用户在图上确认** | 起草需要理解，但数值永远由代码算，大模型不判断这张图上有没有 |
| 把三五个字扩成「为什么会涨」一句话 | **大模型**，用户确认 | 纯改写 |
| 读图找库里没有的要素 | **大模型**（读匿名图，第 3 阶段） | 价值在扩词汇；风险见第 8 节 |
| 定期整理要素库（合并同义、提议新形态卡、给新要素写代码草稿） | **会话里做**（零 API）或付费 API 批处理 | 低频，不需要实时 |
| 预测涨不涨、给图打分 | **不做** | 见第 10 节 |

一个奥卡姆观察（与 arch 的 0.4 节一致）：跑着的 Claude Code 会话本身就是能读图的大模型。凡是「用户发送一批之后」才需要的智能（解析备注、起草形态卡、整理要素库），都可以在会话里做，不花 API 钱。付费 API 只在**用户一边在网页上标、一边要即时反馈**时才是必需的（主要是「把三五个字实时对到要素上」）。

会话也是大模型，而且它看得到代码和日期，所以同样受第 8.2 节约束（第三轮，与 arch 4.4 / R1 一致）：会话给用户的选项只能来自三处——事实脚本、用户自己的说法库、冻结的通用种子表；它不凭自己的知识新提要素。整理要素库（同义合并、给用户已说过的新要素写代码）不算「给用户提选项」，可以照做，产出进库时来源标 session；需要发挥的起草交给只拿脱敏事实表的子代理去做。

## 6. 推荐库里还没有的要素：从哪来

| 来源 | 怎么做 | 记成什么来源 |
|---|---|---|
| a. 用户的话对不上库 | 大模型起草定义 → 代码算 → 图上高亮请用户确认「是这个意思吗」 → 进库 | 用户 |
| b. 买点当天什么模板都没命中 | 只问一句「这天你看到了什么」；同时给出「这一天和这只股票自己过去 60 天比，最不寻常的三件事」（量、振幅、实体、收在当天什么位置、跳空、离均线多远等约 20 项，各自对本股历史标准化后排名，待验证） | 用户确认的算用户；只是系统列出的算系统提议 |
| c. 通用技术分析常识 | 种子库第 2 类那约 30 条。两个入口，都不按「在赢家图上出现多少次」触发（那是 auditor B1 禁止的）：用户随时可以打开词库浏览、自己挑；用户说的话被对到其中某条时，作为「是不是指这个」提出 | 用户自己挑的算用户；被对上后确认的算「采纳推荐·通用知识」 |
| d. 大模型读匿名图 | 第 3 阶段：截到买点、无代码无日期、价格归一的图，请它列出「图上有、但下列清单里没有的特征」 | 系统提议（大模型） |
| e. 挖数据 | 哪些要素后来涨得好 | **不进标注界面**。属于想法来源之三，走挖数据的纪律和账本 |

**出现在哪（第二轮，按 ux 第 4.1 节第 3、4 条）**：系统提议不混进每张图的勾选区，攒到形态级、放进「待回应」用选择题问，带「别再问」；每个形态每周至多 3 条（待验证）。唯一例外是来源 b 的「最不寻常三件事」：它只在用户点了「都不是，我说一句」之后才出现在那一格旁边，作为提示——用户先动手，系统后出，不违反「说形态时用户先动手」。被采纳的提议进事实表末尾，永久带「系统提议」来源。

来源 b 的「最不寻常的三件事」只和这只股票自己的过去比，不读任何后来的涨跌，所以不花尝试；它的价值是把「用户看到但说不出来」的东西变成可点的选项。

试验（`repro/anomaly_rank.py`，同样 10 个买点，12 项单日指标对本股前 60 天标准化）：QMMM 07-14 排出「下影长、收在当天高位、远高于 50 日均线」，正是「回落收回」那根 K 线的样子；07-08 排出「当天大涨、远离均线」，是突破日的样子；SMX 排出「成交量偏离近 3 个标准差、近 5 日振幅放大」。但多数买点上前三名只偏离 1～1.5 个标准差，算不上真不寻常。所以**只在偏离达到约 2 个标准差时才显示（待验证）**；按这条线，10 个买点里只有 2 个有东西可显示。宁可少列：列出来的每一条都加长了用户挑选的菜单（第 9 节）。

## 7. 迭代学习：两类信号的防火墙，以及「越用越方便」靠什么

### 7.1 两类学习信号必须分开

- **信号 A：学用户怎么描述、怎么选。** 输入只有用户的操作：点了什么态度、选了哪个口径、哪个触发、改掉了哪条推荐、打了哪些字、套了哪张卡、每张图花了多久。**不读买点之后的任何价格**。这是「越用越聪明」的全部来源，可以放开用，不额外花尝试。
- **信号 B：学哪些要素后来涨得好。** 读涨跌，就是挖数据。不进标注界面的推荐排序，只出现在现有的对照页和账本里（`chart_workflow` 的对照清单与记账），每拿一个要素或一张卡去对照看成绩就入账一次。由 auditor 审具体规矩。

防火墙怎么落到代码上（交 arch，都是可自动检查的）：

1. **未来扰动测试**：把买点之后的所有 K 线换成随机数，事实表和推荐必须一字不差。
2. **不准引用标签**：推荐模块不得引用 `chart_workflow/labels.py` 及清单里的结果字段（rise、rel、peak_date 等），用一条导入检查测试守住。
3. **推荐排序只用信号 A 的统计**，排序依据显示在界面上（「你点过 7 次」），用户看得见为什么推这条。
4. **每张标注同等对待**（第二轮，采 auditor B5）：学说法时不因为那段涨得多就让它的说法更重，按涨幅加权就是在读涨跌。
5. **只读截断副本、只碰 2025**（第二轮，采 auditor E1、E2、E4、E6）：事实计算、形态匹配、操作日志统计、大模型调用一律只读截到 2025-12-31 的副本；检索和统计的候选只含 2025 年的决策日；智能层在 2024 年上不算任何东西。回看跨进 2024 年只以数字进事实表，不画成图（E3）。第 0 阶段护栏 1 的副本还没建好时，脚本读全量文件后立刻截断（现在的 `repro/prefill_facts.py` 就是这样），副本建好后改读副本。
6. **驱动推荐的统计只数用户主动的操作**（第二轮，采 auditor C4）：决定排序、折叠的使用次数，只数用户主动点的；「预勾后保留」「一键套卡」不计入，否则系统的预填会自己喂大自己。预勾只来自匹配上的那张卡；用户在别的形态里的习惯只用来排序和折叠，不用来预勾。

### 7.2 一切从操作日志出发

每一个界面动作追加一行到一份只增不改的操作日志（推荐给了什么、用户点了什么、改成什么、用了多久、来源标签）。别名、默认口径、使用统计、形态卡建议，全部是「日志 + 要素库定义」的纯函数，随时可以从头重算、可审计。这就是用户要的「把所有历史标注操作作为大数据挖掘的素材」——但挖的只是用户自己的选择习惯。

### 7.3 「第二个小时比第一个小时方便、第二个月比第一个月方便」的机制

| 机制 | 第一次的样子 | 用一阵之后 | 何时生效 |
|---|---|---|---|
| 1. 用户的话变别名 | 「近期量很大」要大模型猜对到哪行 | 直接命中，零调用 | 说过一次即生效 |
| 2. 默认口径 | 每张图问「按收盘还是最高价」 | 同一形态卡答过一次不再问 | 同一小时内 |
| 3. 从没勾过的行收进「更多」 | 事实表 14 行 | 用户连续约 20 张都没勾过的行收起，位置不变、点一下展开（待验证） | 约 20 张后 |
| 4. 认领形态卡后预勾 | 每张图逐行勾 | 用户数字键认领一张卡后，按卡预勾，不符合的那条加粗，回车即过（第三轮：认领由用户做，系统不猜） | 有第一张卡起 |
| 5. 复现检查（needs #13） | — | 用户点下买点后，自动看卡的当前版本在这天触不触发；不触发就指出卡在哪个要素，让用户三选一：改卡 / 这张算例外 / 改判「像但不是」 | 有第一张卡起 |
| 6. 买前失效与故事模板 | 从模板里挑 | 用户自己用过的排最前；「像但不买」的原因回流成候选 | 第 2 张起 |
| 7. 新要素进库 | 用户说一句，系统起草、确认 | 下次直接出现在事实表末尾 | 进库即生效 |

第二轮删掉了第一轮的「按全局习惯预选」：needs、ux、auditor（S2）都要求预勾只来自用户认领的那张卡——拿别的形态里的习惯去预勾，会把新形态往旧形态上拉，而新形态正是最需要干净信号的时候。跨形态的习惯只用来排序和折叠。

**买点不预标（已解决）**：说形态时不预标候选买点日；用户点完后才显示「按形态卡，本图会在某天发信号」作对照，不一致进复现检查。预标只留给「对规则」盲看模式。needs 已采纳（needs.md #1）。理由：在全是赢家、看得到结果的图上预标买点，等于让用户在系统选的日子上点头，采集到的就不再是用户自己的买点。

**形态匹配要不要学习型**（回答 ux 第 10 节）：不要。后台按要素逐条对（卡上必需的满足几条、必须没有的违反几条，加分项只用来打破平局）透明、可解释。auditor A3 禁止大模型判「像不像你的形态」，ux 第三稿又把猜测从界面拿掉，所以它只用于后台统计和「未归类」排序。

量化目标（以 ux 第 5 节为准）：新形态首张约 10 下；已知形态全符合约 2 下、5 秒。日志同时给出「每张图动手用时」「推荐被改掉的比例」「对不上库的说法占比」，这三个数决定要不要进下一阶段（第 11 节）。

冷启动用通用知识（种子库）但**最后尊重用户的选择**：种子要素从不预勾；用户在待回应里采纳了，才进事实表。

## 8. 大模型：哪步用哪个、多少钱、怎么防它借未来

### 8.1 分工与成本

价格（每百万 token，输入 / 输出）：Opus 5.5 4 / 20 美元，Sonnet 5.5 2 / 10 美元，Haiku 5.5 0.10 / 0.50 美元；重复的前缀（要素库定义）走提示缓存，读缓存约一折；不赶时间的批处理半价；一张图约 1000～1500 个输入 token（约等于宽 × 高 ÷ 750）。

| 步骤 | 模型 | 频率 | 每次约 | 重度使用一个月（按 300 张图） |
|---|---|---|---|---|
| 把用户的三五个字对到要素上、起草新要素定义、扩写一句话 | Haiku 5.5（实测不准再换 Sonnet 5.5） | 每张图 0～1 次 | 不到 0.1 美分 | 约 0.2 美元 |
| 读匿名图找库里没有的要素（第 3 阶段） | Sonnet 5.5 | 每张图至多 1 次 | 约 1.5 美分 | 约 5 美元 |
| 要素库整理、形态卡起草（每周或每 20 张） | Opus 5.5（或在会话里做，零 API） | 每月约 4～10 次 | 约 30 美分 | 约 1.5～3 美元 |

合计每月约 7～10 美元；按思考过程把输出 token 放大三倍估，上限约 30 美元。**钱不是约束，借未来和塑造信念才是。** 第 0～1 阶段不需要任何 API。

### 8.2 怎么防大模型借未来（回应背景第 5 节第 1 条）

大模型可能记得 2025 年乃至 2026 年的行情（例如 QMMM 后来暴涨后停牌）。四道措施：

1. **按任务给最少的信息**：
   - 解析用户的话：只给用户原话（先用规则剥掉股票代码、日期、价格数字）和要素库定义。没有标的信息，借未来的风险约等于零。
   - 读图：只画**买点当天及以前**的 K 线（用户自己看的图包含后来的大涨，给大模型的图不含）；不写代码、不写日期，横轴只用相对序号，价格按窗口首日重定基、量按自身均量归一，不出现真实价位和成交额；图上不留任何标题或水印；**也不告诉模型这是哪一年**（第二轮，采 auditor A1：给了年份等于帮它把形状对上已知事件）。
2. **只问描述，不问判断**：永远不问「会不会涨」「这是不是好买点」「给这张图打分」「这张图像不像你的形态」，只问「图上有哪些特征」「这句话对应清单里哪几条」（auditor A3）。形态猜测因此一律用确定性的逐条对（第 7.3 节）。
   **只收纯价量的描述**（第二轮，采 auditor A4）：模型提议里涉及题材、行业、新闻、事件类型的（「像临床利好」「像散户狂炒」）一律不进要素库——auditor 的小实测里，模型正是从图形推出了「像生物药临床数据」，而它对这类有单一新闻事件的股票记得最牢。提示词里明说只描述价量形状，返回后再过一道过滤，题材、事件类的条目丢弃并记日志（auditor S1）。
3. **数值永远由代码算**：大模型提议的要素必须有代码定义，「这张图上有没有、有多少」由代码对 K 线算出。大模型最多影响「列出哪些要素」，影响不了任何事实。
4. **留痕**：每次调用的输入（脱敏后的原文）和输出都存日志；自动检查发出去的内容里不含股票代码、日期、真实价格。

**残余风险**：一张特别有名的走势，即使匿名、截到买点，形状本身也可能被认出来；认出来之后它可能倾向于提议「恰好解释了后来大涨」的要素。auditor 已做了小实测（`auditor.md` 第 1 节）：匿名图上两个模型 4 张一张都没认出、年份也猜错，但给了代码加日期，8 只里 4 只说得出具体事件；模型还能从形状推断事件类型。缓解：大模型提议的要素一律标「系统提议（大模型）」来源、只收价量描述；读图放在第 3 阶段，上线前按 auditor 的建议用没有上下文的子代理（指定与 API 同款的 Sonnet / Haiku，只许读图）把小实测扩到约 20 张图（含跳变最极端的几张）再跑一次——不花 API 钱，第一轮我提的「付费测 1 美元」改为这个做法。危险线按 auditor S5：任何一张图在模型的前三个猜测里说中代码，就不做读图，或把那一类极端形状排除在读图之外（待验证）。

种子库里的通用常识是多年前的公开知识，不针对具体股票，借未来的风险低；但**不让大模型去总结「最近哪些形态管用」**，那是在借它对 2025 年行情的记忆。

## 9. 留痕与来源区分（回应背景第 5 节第 3 条）

推荐会塑造用户的信念。不能完全避免，但要做到**事后分得清**：

- **每个字段带来源标签**（字段名以 needs 第 2.1 节为准）：用户自己写的（user_written）/ 采纳推荐原样（suggested_adopted）/ 改过的推荐（suggested_edited）；推荐类再记推荐方——用户自己的形态卡、detector 算出的事实、大模型、通用知识——以及推荐原值；摆过但被拒的推荐也记。我补一个推荐方细分：「最不寻常三件事」单列，便于事后看这一路提示带偏了多少。
- **事实表的行永远算推荐**（第三轮，auditor N3 经 needs 转达，已接受）：用户勾事实表的一行、点一个触发候选、勾一条默认失效行，都记 suggested_adopted（推荐方 detector），不记 user_written。只有当这一行和用户「先说的一句」对得上（said_first_match）、并且用户勾了它，才记 user_written，原话留作凭据。对齐靠机制 1 的别名表或 Haiku 解析，但对齐只是「提议对上」，要用户勾那一行才算确认；由大模型按用户的话勾上的行显示成「按你的话勾的，请确认」，未确认的不算用户来源（auditor）。从用户自己库里复用的条目继承入库时的来源：当初采纳 detector 推荐进库的，复用时仍算 detector，不洗成用户来源。
- **可选的「先说一句」**：点完买点后、事实表出来之前，给一个可跳过的输入框「一句话说说你看到了什么」。说了的部分记为「看单之前自己说的」，是最干净的用户来源；不说也能继续。第三轮定案（auditor C2 / N3）：只在新形态的首张图上必填（事实表出现之前；打字、按住 V 或从自己用过的说法里点选都行，ux 估一个形态约 5～10 秒），同一形态之后的图可选、跳过记下来。ux 第三稿把说话框做成打开这张图起就在，点买点之前说的都记为「看表之前自己说的」。
- **默认无所谓、不预选种子**：系统从不把通用知识或大模型的提议预先勾上；预勾只来自用户自己的形态卡。
- **无预填抽查（第二轮，采 ux 第 4.1 节第 6 条、needs #20、auditor C 节建议）**：随机抽一部分图（ux 默认 10%、auditor 建议 20%，按 auditor 推算的样本量定，待验证）不预勾、不猜形态。拿它和有预填的图比勾选是否一样，量出「形态卡预勾」带偏了多少。第二轮我曾提议抽中的图也必须先说一句，用来量事实表本身的影响；第三轮撤回：N3 把事实表上的每一次勾选默认记成「采纳 detector 推荐」，事实表的影响已经按最保守的方式记在账上，不必再多要用户一句话。抽查图只是不预勾，照常记 said_first。
- **记下每张图给用户看了多少条**：菜单越长，用户在看得见结果的赢家图上「挑出恰好出现的要素」的机会越多。日志里记下每张图显示过的要素数，供 auditor 估这份放大。看一年、在另一年上判（`背景.md` 第 4 节）是兜底的量尺。

## 10. 逐条回应背景第 5 节的五个张力

1. **大模型知道未来**：见 8.2。核心是「信息最少、只问描述、数值由代码算、留痕」，残余风险用一次小测试量化，读图放到第 3 阶段。
2. **清单按结果挑出**：智能层对「要素能不能分开赢家和输家」不下任何结论。共同要素、计数、形态匹配都只描述用户标过的赢家；界面上的归纳结论都附一句「只说明你标的这些图里常见，能不能分开赢家和输家要到对照页看」。第二轮把界线划清：
   - **只数用户的勾选** → 不读涨跌（这是用户的选择，碰巧发生在赢家图上）。
   - **系统数「这批图上都出现了什么」再拿来提议**（ux 第 3.6 节待回应第 3 类「你这 5 张图里有 4 张买点前缩量」）→ 系统在按结果挑出的赢家里找共性。**auditor 已裁定（B7，与 arch R5 同）：任何阶段都不做。** 这个数只描述赢家、没有区分力；若按「每个要素算了一次与结果相关的数」入账，三四十个要素每次全算一遍，尝试成本远超价值。真想找「赢家共有、用户没说的」，走挖数据（先列候选、对着同日普通买入对照、只在 2025、入账），属于想法来源之三，不在标注工具里。标注工具里只允许对用户卡上已有要素做一致性追问（「这条到底是必需还是加分」）。
   - 池子基数（auditor B6）：**逐要素的池子基数标注时不显示**；**卡级命中密度**（这张卡在 2025 年池子里大约每周命中几个股票日）可以在形态库或规则草稿阶段显示，只用 2025 年。整张卡一个数，能提醒「条件太宽、几乎天天有」，又不会让用户逐条拿赢家去比。
3. **推荐塑造信念**：见第 9 节。
4. **尝试记账**：信号 A 不读结果，不产生新的尝试；尝试发生在**一张形态卡的某个版本被拿去对照看成绩**的那一刻，每个版本一次，按来源标签分账（全用户来源 / 含系统提议）。智能层不会因为「列了 30 条要素」就产生 30 次尝试，但它加长了用户挑选的菜单，这份放大由第 9 节的「显示了多少条」记录、由另一年的成绩量出。
5. **奥卡姆剃刀**：见第 11 节。第 0 阶段零界面改动、零 API，直接解开票 05；之后每一阶段都挂一个可测的「加不加」信号。

## 11. 分阶段路线

第二轮：界面侧的阶段以 ux 第 9 节为骨架，这里只写智能层在每一阶段加什么。

| 阶段 | 智能层加什么 | 进入信号（数值待验证） |
|---|---|---|
| **0（本周，解开票 05）** | 界面只补约 1 天（arch R0：多买点、正例范围可空、空心 / 实心 K 线加对数坐标；ux 第 3.8 节的四格最小表单降为备选）。智能层只做一件事：事实表脚本（`repro/prefill_facts.py` 转正）。会话对用户发来的每条标注跑一遍；新形态时先请用户说三五个字（auditor C2），再在对话里列出编号事实表，只问会改变规则的题（口径分歧、触发是哪种、买前失效），用户短答；会话写成形态卡草稿与规则草稿。零 API | 立即 |
| **1** | 事实表进界面（后端按买点即时算，每张 0.1 秒内）；口径分歧拆行；图上标记；可知性标注；认领形态卡后预勾 + 复现检查（机制 4、5）；默认口径记忆（机制 2）；操作日志与逐格来源标签；无预填抽查；新形态首张先说一句；防火墙两条测试 | 第 0 阶段说完一个形态，用户仍嫌对话来回麻烦，或会话每张图要问超过 2 道题 |
| **2** | 实时把用户的话（打字或语音转写）对到事实表的行上（Haiku 5.5）、对不上时起草新要素（机制 1、7）；共同要素汇总（只数勾选）；从没勾过的行收起（机制 3）；待回应里的形态级追问（必需还是加分、先跑哪个版本） | 形态卡 ≥2 张且每张 ≥5 张图；日志显示用户仍在大量打字、或对不上库的说法占比高 |
| **3** | 系统提议：通用常识种子、「最不寻常三件事」、读匿名图（上线前先用子代理把认图小测试扩到约 20 张，不花钱）；每周要素库整理。「来自赢家共性」的提议任何阶段都不做（auditor B7） | 触发「都不是」占比高，或用户反映事实表漏了自己看到的东西 |

ux 第 9 节第 2 阶段的「对规则」盲看模式，智能层要提供的是「按一张形态卡在池子里找出命中日」——这其实就是跑规则草稿本身，不是新的智能，归 arch 与流程骨架。

## 12. 明确不建议做的

- **用主成分分析生成要素库**：理由见第 4 节。
- **按「后来涨得好」给推荐排序，或在标注界面显示要素的历史成绩**：那是挖数据，混进标注界面就分不清来源、也逃过了记账。
- **让大模型预测涨跌、给图打分、替用户判正反例**：借未来的通道最宽，而且产出的不是用户的信念。
- **让大模型自动标完剩下的图**（用户标 15 张，模型照着标 100 张）：产出的是「像用户的」标注，其实是模型来源，会冒充用户来源。
- **用不透明的图像或时间序列向量做相似检索**：找到的相似说不出「哪里像」，变不成规则里的要素。
- **为几十张图微调模型**：样本太少、不透明；要素库加计数已经透明地做到了同样的事。
- **问大模型「最近哪些形态管用」来充实种子库**：借它对 2025 年行情的记忆。
