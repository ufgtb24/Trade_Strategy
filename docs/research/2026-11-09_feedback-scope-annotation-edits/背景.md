# 背景（leader 整理，供 teammate 读；所有路径相对 repo root）

## 这个问题从哪来

- 标注流程（`.scratch/annotation-path2/spec.md`，用户说明书 `.scratch/annotation-path2/manual.md`）：八步 找图 → 标注 → 归组 → map 与写 app → 对照 → 盲看 → 调参 → 最后检查，只有最后检查判输赢。方向归用户，翻译归会话；会话不写用户的标注文件。
- 第一个 pattern `new_step`：6 只股票、10 个有效正样本，第二版 app 已和标注大体吻合，差异全是 app 多买的日子（约 98 天）。为了让用户给这些差异反馈，今天设计了「反馈 / feedback」功能（spec 1.11、6.13；词条 `path2_web/GLOSSARY.md` 的 `feedback`），并做了一轮审查：`docs/research/2026-11-09_feedback-design-review/` 下的 `背景.md`（用户这一轮 12 条决定）、`final_report.md`（审查结论、5 件待用户拍板的事）。用户在拍板前先问了本题。
- 反馈的定位（已定）：只评 app 已经买了的地方，答 `neg`（样子对、这时不该买）或 `off_pattern`（样子不对）；不评 `pos`；漏检用正样本表达；反馈存进用户的标注文件，作为每次改版的回归核对。审查里另有一条待拍板：为保住被砍的一天放的「没画框的正样本」只用来核对、不进定级计数。

## 现有规则里和「改标注」有关的（先读这些，grep 定位后只读相关段）

- spec 1.1：「标注是做 pattern 的唯一入口：脱离图的话不能直接改 pattern」。
- 说明书第 437 行一带：「看着 app 的结果去标是你的自由、工具不记录」；对照页的数「只量忠实，不量有效」。
- 用户 2026-10-26 的决定（会话记忆）：否掉了把标注按「接触过 app」拆成新 / 老的设计。理由：训练集可以随便看，看不看着 app 标是用户的自由；**迭代 app 时用户会刻意对着检测结果改标注**；如实检验只靠盲看和留出数据（2026 年起的验证段）；防「看着 app 标导致虚高」的护栏防的是撤得回的东西，不该加。另一条相关取向：护栏只拦撤不回的。
- 成员冻结（说明书第 281、294 行；spec 5.5）：换了当前样本以后，旧样本的成员冻结，后来补画的框不会悄悄改掉旧判断。
- 改判检查（说明书第 304 行；spec 6.1）：样本从 `pos` 改成 `neg`（或反过来）而它收的框没变，会话问「改判的理由那天看得见吗」。
- 说明书「十几种错法」表（第 87～119 行一带）：E1 后见之明、E5 悄悄改意思、E7 几张图上拟合、E9 看着结果判断、E10 忠实当有效、E13 反复检查碰运气（「改个样子、换个名字当新 pattern 再查」）。
- 检查次数（spec 1.4、6.7；说明书 ⑧）：按单个 pattern 记、各版本累计；没过的 pattern 改个样子、换个名字再上，算它的新版本。
- 「翻了哪几张」（spec 6.3、说明书第 426 行）：每改一版 app，会话报哪几个样本的结论翻了。
- 标注文件是按机器分文件的追加操作，重放出当前状态（spec 5.9、`path2_web/annotation/store.py`）——每次修改都有带时间的记录。
- V-S1（spec 第 7 节）：验证「标注格式装不装得下用户的意思」，通过标准是用户的两句话；会话要记「哪句话只能写进 note、哪一层翻译只能靠猜」。V-S1 尚未记为通过。

## 今天已经出现的「想改标注」的实例

- SMX 2025-11-24 那个正样本建在数据错误（疑似合股没复权）上，用户早就同意删，要在界面里自己删。
- app 的旧平台固定取阶跃前 15 根；用户画的「站上新平台」框大多从更早开始（CRNC 约 45 天、GEVO 约 37 天）。
- 审查里用户模拟发现：想说「冲高回落不是这个走势」时，可能想把它画成一个特征框或属性。
- 用户只标了几个有代表性的日子；app 多买的日子里有不少用户会认为「也可以买」。

- 色盲；界面文字规则见 `~/.claude/rules/ui-text-style.md`。
- 两台机器都标注。
- 熟悉界面上的 pattern、sample（▲ / △）、box、point、hits 行、band、compare；记不住内部字段名。
- 看图时后续走势是看得见的；会刻意对着 app 结果改标注（10-26 自述）。
