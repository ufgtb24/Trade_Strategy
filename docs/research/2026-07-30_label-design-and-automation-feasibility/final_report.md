## 背景（用户两个相关问题）

1. **label 怎么开发**：站"评估选股策略"角度，label 作用是方向性预测还是收益变现？当前 mfr 只看涨，既（可能）不满足方向性也不优化收益性。两视角矛盾——方向性要正负对称、收益性要不对称交易模拟。是否做双 label？
2. **自动化改 dag_spec 可行吗**：feedback 设想的"skill 站全局统计改进 dag"是否值得投入？cc 不懂 K 线规律、陷统计陷阱（选股少就放松阈值）、看图不如人。

用户还区分两个工作流：**feedback**=自动工作流（skill 改 dag）；**plan**=用户用 web ui 人为分析改 dag。

## TL;DR · 两个核心结论

**结论一 · label**：label 根本作用 = **方向性预测能力**，不是收益变现。当前 mfr 连"上涨驱动力度量"这唯一职责都没尽到（score 是波动率读数 R²=0.92、bbb 方向无优势）。
- **P0 补对称方向 label**（= 落地 §0 未实现的顺序闸 + web ui 对照列）：首次穿越方向比例，作否决闸 + 诊断列，不进 hands-off score。
- **P1 模拟交易 label**（按现有 strategy_return plan + 补"不进 score"红线）：服务人为诊断。
- **不做**：任一 label 进 hands-off 自动 score。

**结论二 · 自动化**：**hybrid，但极不对称，强烈偏向"不为闭环自动化投入"。两个工作流不是二选一，是两层。**
- **(A) 闭环搜索自动改 dag_spec = 不值得**（τ²=0、97% 跨期蒸发、任何 path-based label 对波动率单调有免费通道、bbb 方向无优势）。
- **(B) 诊断辅助 = 值得，唯一行动项**（接 `gate_failures`，半天，仍 pending）。
- **(C) 体检/枚举/否决自动化 = 值得，部分已固化**（产出是信息/否决，不是选择）。
- **label 合法角色 = 反馈/检查点（对照列 + 否决闸），不是自动驱动信号。**

## 第一部分 · label 设计（label-strategist 主笔）

### Q1 · label 根本作用：方向性预测 vs 收益变现？

**= 方向性预测能力，收益变现不进选股评估。** 背后是硬约束——**因果归因的可分离性**：尺子一旦含交易参数，它评的就不是 pattern 而是「pattern+交易参数」联合体，分数下降时分不清改 pattern 还是改交易，两层各自失去独立迭代能力（§0 结构性论证，非妥协）。推论：任何把交易参数引进 score 的 label（含模拟交易 label）都违反这条，不论它多"真实"。

### Q2 · 怎么设计"对称方向 label"？哪种最纯？

三候选：

| 候选 | 量什么 | 裁定 |
|---|---|---|
| **(A) close 端点收益** close[t+N]/close[t]-1 | 持有到期结果 | **违反已声明语义**（§3"兑现由独立卖出程序负责、允许回撤到买入价以下、期末为负不指控 pattern"；A.1 已驳回持有到期口径） |
| **(B) max_up/max_down 对称幅度** | 双向幅度对称度量 | 受波动率污染；pattern 选的股双边对称（+10.6/−11.2），对称幅度会相互抵消、掩盖"方向其实不对" |
| **(C) 首次穿越方向比例** | 只问方向符号 | **最纯**：与波动率解耦、不受幅度偏斜影响、秒级、与持有期无关 |

**最纯是 (C)**——方向预测里符号是前提，符号都不对（先跌多于先涨），幅度再大也是噪声。(C) 应从"体检闸"提升为**一等 label**：与 mfr 并列、作"方向纯净度"度量。

> ⚠ "对称"要拆两维（**team 解读，待用户确认本意**——依据是用户"平等考虑涨跌"原话 + §0"a<b"，合并有支撑但属意图解读，非已证事实）：用户"方向性正负对称"team 解读为**度量对称**（涨跌都进 label，修正 mfr 只数涨）；§0 顺序闸（机理本身是事实）要求**阈值非对称**（先跌 a% vs 先涨 b%，a<b，反映止损窄、止盈宽的交易心理）。两者不矛盾——方向 label = **度量对称 + 阈值非对称**。§3 c 项的"对称阈值 ±X%"已被 §0 推翻（"测不会被使用的规则"），`repro/opt2_collect.py:70` 复用的 fp 正是被否决的对称版，落地需改非对称 a<b。

### Q3 · 模拟交易 label 属选股还是交易？怎么和 §0 调和？

**属交易层评估的雏形，不是选股 label。** 用户"端到端训练选股+交易两模型"类比在 ML 意义成立，但 §0 恰是它的反命题：**不能端到端**（归因不可分离 + 可调交易参数会把优化引向"调止损"梯度捷径）。调和方式（与 §0 不冲突）：**不进 score**（红线）+ **作披露/对照**（同波动率倍数地位）+ **服务 plan 工作流（人为）**。

现有 strategy_return plan 技术设计（checkbox 默认关、最小展示、不碰 score）**恰好符合**展示/披露定位——**但 plan 缺一个显式红线声明**（grep §0/移出/耦合 = 0 命中）。P1 实施必须补："strategy_return 仅展示/披露，永不进 score、不作自动优化反馈依据"。这是 plan 当前唯一实质缺口。

### Q4 · "mfr 既不满足方向性也不优化收益性"——对吗？

**对一半。**
- **"mfr 不满足方向性"——对，真缺陷。** mfr 只数上行，把"双边躁动"读成"单边驱动力"。
- **"mfr 不优化收益性"——对，但这是设计边界非缺陷。** §0 + scoring §9 明确 mfr 是"相对比较尺度"非"收益预期"。

真正发现：mfr 连它被赋予的"上涨驱动力度量"职责都没尽到（g 项 R²=0.92）。问题不是"mfr 该不该优化收益"，而是"mfr 作为方向/驱动力度量本身不合格，需纯净方向 label 补位"。

### Q5 · 双 label 是正确方向吗？

是，两者定位/服务层/优先级不同，**不是二选一**：

| label | 回答什么 | 服务工作流 | 进 score？ |
|---|---|---|---|
| **对称方向 label**（首次穿越提升版） | pattern 看对方向了吗（选股职责） | feedback + plan（人为诊断） | 候选，但**先作闸/列，是否升级等 ρ_rel 重算** |
| **模拟交易 label**（strategy_return） | 套固定规则能变现吗（交易层诊断） | plan（人为，对照 mfr 暴露陷阱） | **绝不**（§0 红线） |

最终三列对照：mfr（上行捕获）+ 方向比例（方向对不对）+ strategy_return（带止损下场），**都是人为诊断对照列、都不进 hands-off 自动 score**。"一把尺子"约束的是**可攀爬目标**——既然不该有 hands-off 可攀爬目标，多列对照不违反它。

### Q6 · 开发优先级

> **关键区分**：§10.1 判死的是"改 label 救现任 pattern"（bbb 方向不行，救不了）；§10.6 同时支持"建方向尺子"。**P0 属于后者**——不是修尺子让 bbb 变好，是补齐尺子让评估对现任和未来 pattern 都诚实。

- **P0 — 对称方向 label 落地**（= 实现 §0 未落地的顺序闸 + web ui 对照列）：首次穿越 4 档（5/8/10/15% **冻结**保跨轮可比，显式承认是人设常数）报**整条曲线 vs 随机日**（冻结一档会藏免费通道）、同根命中桶规模作披露项、**否决闸非可攀爬标量**。成本可控（§9.5 设计成熟、第二轮跑过约 4 分/年；`repro/opt2_collect.py:70` 有可复用逻辑但口径需改非对称）。
- **P1 — strategy_return 按现有 plan 实施 + 补红线声明**：服务 plan 工作流（XAGE 式陷阱对照），严格止步展示/披露。
- **不做 — 任一 label 进 hands-off 自动 score**。

## 第二部分 · 自动化可行性（automation-analyst 主笔）

### 三种形态（可行性天差地别）

| 形态 | 是什么 | 裁定 |
|---|---|---|
| **(A) 闭环搜索自动改 dag_spec** | 生成候选→打分→挑最优→迭代（TPE/optuna/ralph 当搜索循环） | **不值得**——bbb 上已被实测判死，不是修尺子能救 |
| **(B) 诊断辅助自动化** | 接出 `gate_failures` + cc 顺 code_location 读源码做批量归因 | **值得**——唯一行动项，半天，高 ROI，但仍 pending |
| **(C) 体检/枚举/否决自动化** | 阶段0 七项体检、通道A 删除枚举、因果闸、闸阵否决 | **值得，部分已固化**——产出是信息/否决，不是选择 |

leader 框架的"feedback 工作流 = skill 自动改 dag_spec"对应 (A)，不可行；真正可行的"feedback"= label 作否决闸/对照列反馈给人为改进，恰由 plan 工作流（web ui）承载。

### 根本障碍（2a/2b/2c）

- **2a 定性理解是 dag 改进核心（语义层），统计不能替代只能否决。** 机械层（参数旋钮、删除枚举、常量提参）不需定性理解；语义层（新 detector/边/形态、看图→认出吸筹派发→提新形态=通道D）必须人。用户怀疑"cc 看图不如人"在"看图→提新形态"链上成立，正是通道D，不该自动。
- **2b 统计陷阱（选股少就放松阈值）自动化避不开。** 任何 path-based label 对波动率单调（`max(high)/close` 类算式的结构性性质）⟹ 有免费通道；§0 三闸是事后否决不提供梯度。任何 hands-off score 驱动方案须正面回应"score=波动率读数 R²=0.92"——回应是"无法回应、所以不该建"。
- **2c 自动化天花板 = (B)+(C)**：诊断 + 否决 + 机械枚举；天花板之下（语义生成）必须人。
- **workflow 的 hands-off 精确化**：反对的不是"hands-off"本身（workflow 确有阶段1↔2 脚本内循环，但是"生成+否决"非"score 最大化"；另有 R2.C 半自动=LLM 读 gate_digest 顺行号提候选、人决策），是"hands-off **用 score 驱动最大化**"；且此判死**条件性**（§9:586：尺子修好 + ρ_rel>0.5 则排序工具回桌）。

### 边界（自动 vs 人）

**自动**：参数③旋钮、通道A 删除枚举、层2a 常量提参、阶段0 体检(c/g)、因果闸、通道C 失败归因聚合（接 gate_failures）、闸阵否决。——产出=敏感度图/信息/否决，非配置/选择。
**人**：新 detector/边/形态概念、看图操舵、否决裁定、pattern 二选一。
一句话：**自动做"诊断（信息）+ 否决（拒绝）+ 机械枚举"；人做"选择（幸存者间按奥卡姆/语义）+ 生成（语义候选）"。**

### label 够格当自动反馈依据吗？——两条独立死因（关键）

**当闭环驱动信号 → 不够格。** 两条独立死因必须分开：
- **(i) 尺子侧**：mfr 分辨不动 contender（τ²=0，§1.2b），任何 path-based label 还有免费通道。
- **(ii) pattern 侧**：bbb 本身在方向上无优势（c 项 7/8 单元低于随机日），这是比 τ²=0 更硬的否决。

**label 修复（建方向尺子）只解决 (i) 让评估诚实，解决不了 (ii)**——方向尺子造好后量出来的还是"pattern 没方向"，只是量得准。**所以停滞主因在 pattern 不在尺子，label 修复解不开停滞。** 自动循环要"复活"只有两条路，都跳出 label 工程：通道 C/D 语义重生（§11 明说不该自动化的那段）或新数据（opt §4.5：更多数据测一个无方向的 pattern = 更精确地测零）。且新 pattern 还须过 c 项方向闸——建这把方向尺子正是判定新 pattern 合格的**前置**，不是现任 bbb 自动循环的解药。

**当否决/检查点反馈（人为改进时看）→ 够格，但有深层隐患。** 够格部分：基线扣减/因果闸/顺序闸/波动率倍数披露都是否决级信号。**隐患**：`bo_only` 基线本身方向上接近无信息（0.46–0.53）⟹ "lift vs bo_only"量的是"比裸突破多榨多少波动率"，不是方向优势——方向性只能靠 c 项首次穿越这个否决闸单独验。但这把"基线问题"从隐患转成了**"为什么需要独立方向 label"的正面论据**。

## 统一行动建议（按 ROI 排序）

1. **接出 `gate_failures`**（半天，新建 0 文件）——唯一行动项，解决"无法批量排查 + 不知如何让 cc 介入"两个痛点。`eval_runner.py:69/78` 已算，加消费者即可。第 5 次面临落空风险，应优先。
2. **补顺序闸（非对称首次穿越）live 落地 + web ui 对照列**（= label P0）——§0 用户第 1 条，grep 零命中。便宜（秒级）、方向性一等验收指标、不受 mfr 上偏影响。
3. **阶段0 方向(c)+波动率(g)体检自动化**（秒级，复用同一批买点）——纯诊断。**⚠ `stage0_probe.py` 未随 skill 落地**（只有 `eval_skeleton.py`）⟹ 此行动 = 先按 `07_operational_spec` 建 `stage0_probe.py`（复用 eval_skeleton 底座）再跑，不是"跑现成的"。
4. **strategy_return 按现有 plan 实施 + 补"不进 score"红线**（= label P1）——服务 plan 工作流人为诊断。
5. **机械枚举出敏感度图**（通道A 删除 + 参数③ 平台枚举）——信息层，找 no-op 旋钮和"删了不降分"的节点。产出是图不是配置。
6. **不要建 hands-off 自动改 dag_spec 的闭环**——含不要把 strategy_return 或对称方向 label 压成 score 去攀爬。label 作对照列/否决闸，不作驱动。

## 关键区分与红线

- **P0 不是救 bbb**：bbb 在幅度尺（=波动率）和方向尺（7/8 不及格）下都不行，是 pattern 去留问题（靠人的语义重生，通道 C/D），不是 label 工程。P0 是补齐尺子让评估对现任和未来 pattern 都诚实。
- **停滞主因在 pattern 不在尺子**：label 修复只让评估诚实，解不开 bbb 方向无优势的停滞——后者靠语义重生或新 pattern，都不在 label 工程射程。
- **strategy_return 不进 score——且要结构性强制而非仅声明**：plan 对 §0 零意识就是"光声明会漂移"的先例。三重机制守：① score 公式（offline `opt2_null.py`）显式不含 strategy_return；② serialize 层 simulate 默认关（plan 已是）；③ "strategy_return / 方向 label 不得进任何排序键"写进 `pattern_config_scoring_standard.md`。与"排序函数签名不接受方向 label 当键"（§8.2 律②不可表达）同构——机制比声明抗漂移。XAGE 两把尺子相反恰是 plan 价值（揭示 mfr 偏置），不进 score 则"相反"是 feature。
- **任何 label 都不当 hands-off 攀爬目标**：mfr→波动率、首次穿越→同根率/高波动先冲偏好、strategy_return→跟踪止盈偏好高波动，任一标量 maximize 都找免费通道。
- **安全来自闸圈住坏尺子，不来自尺子本身准确（必入的关键张力）**：留下当唯一标量的 mfr-lift 本身是坏尺子（波动率读数 R²=0.92）。这套架构的安全不来自 score 好，来自方向闸/因果闸/波动率披露把坏尺子圈住、不让它不受约束驱动决策。故"mfr 留在 score"必须配一句：它的合法性来自被闸 circumscribe，不来自它本身准确。
- **诚实的例外（不能藏）**：若未来换一个有真方向优势的新 pattern 且测出 ρ_rel>0.5，有限搜索自动化可能回桌——但这是未来证据驱动，非现在投入理由。bbb 上方向无优势（c 项 7/8 单元低于随机）是比 τ²=0 更硬的否决。

---

**一句话**：label 修不好 pattern，但能让评估诚实——方向 label（P0）补齐被 mfr 掩盖的方向维度、模拟交易 label（P1）补上变现维度的诊断，两者都服务人、都不进自动 score；自动化只值得做诊断/体检/否决层，闭环改 dag_spec 的投入会被波动率免费通道吸走。两个工作流不是二选一，是两层：自动层做诊断/否决支撑人层做语义改进。
