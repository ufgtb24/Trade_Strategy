# ux：标注界面审视与改版

本文中所有项目内路径均相对 repo root。审视对象：上一轮定稿 `docs/research/2026-10-26_annotation-topology-grouping/final_report.md`（下称「上轮报告」）§2.2～§2.9 与其 mock `docs/research/2026-10-26_annotation-topology-grouping/repro/mock.html`（下称「旧 mock」）；`背景.md` 第 3 节 lead 的候选方案（下称「候选」）。改版 mock：`repro/mock_v3.html`，对齐 flow v3（`flow.md` §12）。用词照 `path2/GLOSSARY.md`、`path2_web/GLOSSARY.md`；词表里没有、本文在用的几个词见 §7 第 2 题。

## 0. 白话摘要（先读这段）

**做了什么**：把旧 mock 的每个界面元素逐个过了一遍——它回答用户哪个问题、哪一步用、去掉会怎样、有没有和别处重复、有没有一个记号两种意思；然后按 flow 的流程（v1→v3）、sim 三轮实操的摩擦点、critic 的三十来条质疑，改了四版 mock（sim 实操了前三版，第四版只修第三轮的高、中项）。我没有开浏览器，实操交给 sim；每版脚本都过了语法检查，并用一个最小假页面把主要操作路径跑通、没有报错。

**说明什么**：
- 旧界面最拖效率的是「画框」和「选中」是两个互斥的工具：画框工具下点一下框，会造出一个一天的框。改后拖动就是画框、点一下就是选中，拖框的左右边就是改起止。
- 最容易误读的是 pattern 页：几种骨架混在一起时，elements 把名字串成一条链，读起来像先后；`unmapped` 一个词装了「出错」和「先不放」两种意思；`TrendSegment:sideways` 这种写法让人以为「它在 app 里」。改后：写 app 前平铺，只在一起出现过的名字之间画箭头；写 app 后按对应表分层——顶层只有「必须有」，可有可无的挂在它依附的那一段下面、前面写级；不放的、会话还没处理的各进底部一区。
- 偏离不标红。红只留给「app 和你对不上」，偏离（缺了必须有、多了必须没有）用普通签 `−回踩`、`+派发`，买点 edit 里缺的位置画成空槽；如果这张图上买点前其实画过、只是没收进成员，空槽就是一个按钮，点一下收进。
- 页头一格 `next` 说这个 pattern 现在等谁（等你答会话的问题 / 等会话 / 该盲看 / 该你定），你的待办只有会话问你的那几条。会话每轮开头的问题单直接放进界面：点开 `ask`，每条已经按会话的猜测选好（蓝底），只改不同意的再提交；背景框那种「每张都框、又没写定义」的名字不替你猜；缺回踩这类图上改好了就自动消掉。
- 「属于」按框边严格判：整个落在一个更长的框里才算属于，只要伸出去一点就按先后读。框边没画进去、其实想表达属于的，在子框 edit 里点一下 `⊂` 手动挂上。（试过给子框留容差，sim 第三轮实测一个随手画歪的框就让整个 pattern 的轨序倒过来，于是撤掉。）合并两个词先显示「n 个框：A → B」、点一下才改，改完存成一条记录、在 vocab 里能拆回。
- 三处「引导」做在当下、不靠说明文字：起新词时相近的已有词自动排到最前；同一个特征画成过子框的，属性栏里就不再给「有」，只能画框；选中一个买点时，主图上这天之后那段暗一档，提醒 label 只按当天看得见的判。

**不说明什么**：颜色能不能分开只能用户亲眼判断；点击数是按代码数的，不是计时实测；流程上的规矩（例如有时有的东西在哪一层表达）归 flow 和用户，界面只管它长什么样。

## 2. 重复、歧义、「看着像别的」

**两处（或更多）说同一件事**
- D1 买点的 buy / no_buy：三角实心空心、三角下的字、edit 的 `label`、members 链末尾的 `buy` 标签，四处。留三角和 `label`（一个看、一个改），删另两处（U4、U5）。
- D2 「这个 pattern 的买点谁缺了什么」：顶层名称的 `in k/N` 与 groups 各说一遍。改后两处分工：elements 只在「不是每个 buy 都有」时给个数（`in k/N`，分母只数 buy，顶层次级同一条规则），groups 的偏离组给「是哪几个」和差在哪（`−X`）；个数和名单是两个问题，保留两处（U16、U2）。
- D3 偏离的买点同时挨两个信号：偏离组 + 朱红 `app:buy` 漏买。漏买该谁处理说不准（可能是没画、也可能 app 真漏），挂朱红会把动手的人指成会话。改后偏离组照常显示 `app:buy`、不标红（critic X1：app 买了往往正说明缺的那样其实在、只是没画）（U2、U4）。
- D4 词的定义在 edit 与 vocab 两处可改：改后 edit 里空着时是输入框，写过后显示成一行只读文字（不靠悬停，sim 第二轮：点下名字的那一刻就该看见它），修改只在 vocab 一处（U11）。

**一个记号两种意思 / 两种记号一个意思**
- D5 `unmapped`：候选下顶层出现 = 出错、次级出现 = 先不放，同一个签两种意思；checks 表里同一件事又写成 `n/a`。按 critic Q8 拆成两态 `unmapped`（会话还没处理）/ `excluded`（处理过、没放进 app，悬停写原因），两处同写法（U3）。
- D6 子名称的记号：pattern 页子块前缀 `⊃`、members 链 `横盘 ⊃ 缩量`，主图子框角 `⊂`——同一件事两个方向（sim K8）。统一成「子在下、前面挂 `⊂`」：pattern 页子块、members 链（父块在上、子块竖着挂下面）、主图子框角都一样；轨标题 `缩量 ⊂ 横盘` 是两边都写出名字的中缀，不动（U14）。有 app 后的分层页里「挂在某段下面」是另一回事（落在那一段的 where / 子事件 / 否定边），前面写级（`optional` / `must_not`），不用 `⊂`（critic 5.2）。
- D7 虚线：主图上 = 用户的框；侧栏里 = 空着 / 不在（`others` 块、`null n`、`pending`、`unmapped`、`excluded`）。两个区域各自一致，记录不改（critic Q14 同判）。
- D8 朱红：已定 = app 和你对不上、该会话修 app。候选的「偏离骨架标红」是用户的标注和 pattern 定义对不上、该用户挪组 / 补框，动手的人相反。不用朱红（U2，接受 critic Q5）。

**看着像别的东西**
- L1 `buy@底部反转` 的 `@` 写法像代码里的标识符或用户名，混在 K 线上（U4）。
- L2 画框工具下点一个已有的框：看上去是「选中」，实际在那一天造了一个新框（旧 mock `mouseup` 不判断拖没拖动）（U7）。
- L3 未归类页、或几种骨架混在一起的 pattern 页里，elements 把所有名称并成一条竖链、用 ↓ 连起来，读起来就是「这个 pattern 的先后」，其实那几个名字从没同时出现过（sim F5）（U6、U16）。
- L4 来源底色：浅琥珀 `#fdecc0`（明度 L* 93.7）与用户内容的浅灰底 `#e9e9ec`（L* 92.4）只差 1.3，只靠偏黄撑着，上轮已列待验证 V5。checks 表里两者左右相邻。改版不动（用户暂未报看不清），备用值 `#f0c674`（L* 81.9，与浅灰差 10.5，与中蓝 `#93c5fd` L* 78.0 一冷一暖），用户报看不清时直接换。

## 3. 候选方案落到界面上

| 候选 | 会不会带来新混乱 | 改版取法 |
|---|---|---|
| 同一个 pattern 只许一种顶层骨架；「可有可无」只在次级 | 会：用户在画框那一刻就得定「这个是不是必须的」，横盘这种排在突破前、套不进后一段的，只能回头改写成属性（sim F1、critic Q1）。flow v2 起改走「照常画、写 app 时定级」 | 界面跟 flow v3：写 app 前平铺、不判偏离；写 app 后按对应表四级分层（必须有 / 可有可无 / 必须没有 / 不放） |
| 顶层不显示 `in` | 会：规则跟层级走；加了新必须项、旧买点还没补框时顶层本来就会缺，藏了就看不见（critic Q7） | 不按层级藏：`in k/N` 只在「不是每个 buy 都有」时出现，分母只数 buy，顶层次级同一条规则；有 app 时 elements 也按全部 buy 算（sim K1） |
| 有 app 后第二种骨架标红 | 会：朱红变两种意思、动手的人相反（D8）；no_buy 常常正是差一样的，标红逼人挪走最有用的反例（critic Q2）；一个红盖四种来历（sim F2） | 偏离只看 buy、以对应表的必须有 / 必须没有为准；组头差签 `−X` / `+Y` / `order`（普通签），排最前；照常显示 `app:buy` 但不标红（critic X1） |
| `unmapped` 只在次级、改「还没放进 app」悬停说原因；顶层出现标红 | 会：中文短句当状态违反界面文字规则；「还没」对「量过决定不放」是错的；`TrendSegment:sideways` 那种第三写法让人以为在 app 里（critic Q8、sim F6） | 两态标识符 `unmapped`（会话还没处理）/ `excluded`（会话看过、定成不放，悬停写原因）；不分层级、都不标红；在分层页底部各成一区 |
| 未归类时 pattern 页显示什么 | 候选没说 | 只剩 groups（flow、critic 同判）；组和某个已有 pattern 对得上时多一个一下挪过去的按钮 |
| mock 演示数据换成照标注写的假 app | 不换的话 sim 会把旧 mock 的问题当成设计的问题 | 见 U1 |

### 5.1 最短操作路径

情景按 sim 1.4、flow v3 §2.2 的常见程度挑。「下」= 一次点击或一次拖动。

| 情景 | 改版后的路径 | 下数 | 旧界面 |
|---|---|---|---|
| 画一个已有名字的框 | 在那个名字的轨里拖；新图上必须有的名字已经有轨 | 1 | 先点 `box`；新图上没有轨，先拖到 `unnamed` 再点名字（3） |
| 画一个新名字的框 | 在空处拖 → 打新词（相近的已有词自动排前，是同一个就点它）→ 回车 | 1 + 打字 | 回车不生效，要点 `+` |
| 改框的起止 | 拖框的左右边 | 1 | 没有办法，只能删了重画 |
| 改属性 | 点框 → 点 `true` / `false`（点错再点一下回 null） | 2 | 先切 `select` 工具（3），退不回 null |
| 放买点 | `buy` → 点那根 K 线；成员默认推好，工具自动回 `box` | 2 | 2，之后还要切回工具 |
| 先放买点后画框 | 买点保持为当前买点；每画一个框自动并进，edit 顶上的链看还缺什么 | 每框 1 | 画完框侧栏跳走，要回去点三角才看得到 |

### 5.2 三档在界面上的样子

flow v3 §2.1 按「代价怎么长」分五档；落到界面上是三种待遇。原则：**不加说明文字，不弹窗**——提示靠排序、加框、空槽、变暗、灰字占位这些界面元素本身；说明只在悬停里。

**随你（A、B）**：不提示、不拦，只把状态摆出来。例：框边画得差不多（伸出去的按先后读；想表达属于就在子框 edit 里点一下挂上）；先放买点后画框；对着 app 改框（对照开关不自动关）；背景框画不画（写 app 时会话问一次级）；断点续做（`next` 一格）。

**引导（C 档，以及能挪到界面默认上的 D 档）**：在发生的那一刻，让对的做法成为最省事的那一下，不事后报错。

| 思考模式（flow v3 §2.2） | 当下的界面 | 用的界面元素 |
|---|---|---|
| M5 换个词说同一个东西 | 打新词时相近的已有词排到最前、加框，悬停看定义；已经起重了，vocab 里一下并掉 | 排序 + 加框；`→ merge` 下拉、`unmerge`（U23、U13） |
| M10 顺手接受默认成员（收少了） | 缺的必须有画成空槽，这张图上其实画过的，空槽就是收进按钮；缩略图同一行一个 ◂ | 空槽按钮、◂（U5、U15） |
| M6 同一个特征有时画子框、有时写属性 | 这个名称下画成过子框的词，属性栏里只剩「画框」这一种「有」 | 一行 `⊂ 词`，不给 `true`（U22） |
| M11 顺手接受带上的属性（悄悄造假，D 档挪成默认） | 带上的属性列出来但默认 null，只取当前 pattern 里用过的 | 灰色虚线 `null` 签（U21；默认值待方向题 D2） |

## 7. 交用户定的方向题

1. **给框选了名字后，以前和这个名字一起用过的属性，是直接算「有」，还是先列出来算「没看过」、点一下才算有。**（与 flow v3 方向题 D2 是同一题，合并问）现在（票 01 已定）是直接算有，省点击。sim 实测的坏处：属性跟着名字走，在别的 pattern 里加过的属性也会带成「有」——用户没看过，pattern 页却显示成证据，会话照着写 where，事后分不出真假。改版已经把候选缩到「当前 pattern 里用过的」，跨 pattern 那一半消掉了；剩下的是同一个 pattern 里「没看过的被算成有」。推荐：先算没看过，点一下才算有；代价是每个新框多点几下。mock 顶栏 `carry` 可切两种做法对比。
2. **词表题（交 lead 转问）**：界面和讨论里在用、两份词表都没有的词——「骨架」「主组」「偏离组」「必须有 / 可有可无 / 必须没有 / 不放」「当前买点」「画了没收」，以及界面标识符 `elements`、`groups`、`members`、`others`、`next`、`ask`、`not_sample`（sim F21：几周后回来要重新摸）。按 CLAUDE.md 的信号③，要问一句要不要进词表。
