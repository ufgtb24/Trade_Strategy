## 先用几句话说清

**做了什么**：把八种可选中的东西和图上其余显示物之间的数据关系逐条列出来（第 1 节）；在用户正在用的真页面（CRNC、new_step、`compare`、档位 `in_hit`）上逐个设了 19 种不同的选中状态，读出每种状态下图上、显示栏、选中卡、`diagnose` 各画了什么，并截了副图（第 2 节）；把图上已经被用掉的颜色、线型、粗细、填充等通道和它们的含义列成表（第 3 节）；从规格、说明书和上一轮的用户任务清单归纳每种选中下用户要看到什么（第 4 节）；写了 ECharts 在这里能做、不方便做的事（第 5 节）。

**说明了什么**：用户报的三个困扰都能在数据上找到原因——「选中的那一个」和「一起亮出的」「被牵出的 hit」用的是同一种深色实线框，只差 1 像素；被选中的买点日（▼）任何时候都不画；选中 event 时一条旧规则会按「第一个找到的复合事件」点亮一串东西，而子事件被几十个复合事件共用，挑中的常常不在任何 hit 里、在当前档位下画不出来或在视窗外。

**不说明什么**：不给设计结论。只看了 new_step 一个 app，换别的 app（一次 hit 占好几个买点日的那种）时数量关系会不同，表里注明了。new_step 没有钉价格轴的 node，主图上的价格点高亮在这只股票上核对不了。下面这些只读了代码、没在页面上看到：app 模式的侧栏；「点样本」（区别于「聚焦样本」，没点是为了不改用户的当前样本）；闪烁本身（静态截图看不出）；点记号走进买点日后的白底琥珀边（09 测的是格，不是点）；档位不是 `in_hit` 时组成型规则点亮什么。

**怎么复现**：`repro/probe.js`（playwright MCP 的 `browser_run_code_unsafe` 用 filename 跑，跑完把选中、视窗、侧栏页签恢复原样），原始读数 `repro/matrix.json`（状态 01–18）、`repro/matrix_extra.json`（19–24），截图 `repro/screenshots/01.jpeg`–`24.jpeg`（副图，视窗约 46 根 K 线）。几处说明：16 是无效状态（挑的 event 不在那个样本的 `diagnose` 卡片里），由 21 取代；19、20 是 12、13 移了视窗后的重拍；22、23、24 是 02、07、05 在用户原来约 280 根 K 线的宽视窗下的样子；`matrix.json` 里 03 的标签写成 11-05，实际是 10-11。

规格说的「路径上有 hit 的一族的那一行」（`spec.md:546`），代码里叫「当家行」；上一轮已指出这个代码说法本身就让人看不懂，本文写作「那一族的行」。

**用词**：band（`path2_web/GLOSSARY.md:39`）、lane（`path2_web/GLOSSARY.md:42`）、显示档位与 detected、qualified、in_hit（`path2_web/GLOSSARY.md:25`、`:28`）、hit（`path2/GLOSSARY.md:95`）、买点（`path2/GLOSSARY.md:118`）、event（`path2/GLOSSARY.md:44`）、node（`path2/GLOSSARY.md:76`）、复合事件 / 子事件（`path2/GLOSSARY.md:62`，下文 plateau 就是 old_plat、step、new_plat、today 四个子事件的复合事件）、样本、样本日、成员框（`path2/GLOSSARY.md:152`、`:167`、`:171`）、反馈与「一族」（`path2_web/GLOSSARY.md:71`）。词表外、规格里有定义的：买点日、当前日竖线、族底线、个数行、显示栏、选中卡、反馈记号、反馈带、竖带、user 行、hits 行、配对、牵出（`.scratch/annotation-path2/spec.md:501`–`:549`）。`bracket` 词条（`path2_web/GLOSSARY.md:45`）还写「带圈号的横带」，现在画的是梳子、没有圈号，本文不用这个词，改说「hits 行」。

## 2. 现状矩阵

### 2.1 画法的三种「框」先说清

代码里点亮 event 只有三种画法（`render/chart.ts:400`、`:1214` makeRenderHighlightWithGeom、`:1019` buildHlShape），都是同一个深色 #1e293b：

- **focus**（选中的那一个）：2.5px + 阴影。
- **group**（一起亮出的）：1.5px + **同样的阴影**。
- **pendingDisambig**（从 event 走进买点日后，那个 event）：格与整条画 2.5px + 阴影 + 闪烁（和 focus 同色同粗，只多一闪）；点记号和主图价格点画白底、琥珀边、本色闪烁。

格记号（整格、整条）每点亮一个 event 画**两个框**：从它那一族起点到它终点的细跨度框（1.5px，无阴影）+ 它那一格的框。点记号（band 上的三角）和主图价格点（bo 盒、pk ▽）画成**放大 1.4 倍的实心复本** + 描边。

hits 行另有一套（`render/chart.ts:1530` makeRenderBracket），同色：
- 选中的那次 hit 的格：族起点到 hit 终点的细跨度框 + 那一格的框；那一格在「路径上没有 event」时 2.5px + 阴影，**路径上有 event 时只有 1.5px + 阴影**；
- 被牵出的 hit 的格：1.5px，无阴影；
- **▼ 从来不画任何框**（▼ 分支只画黑三角和个数）。

### 2.3 从矩阵读出来的几条规律性问题

1. **「是不是选中的」只靠 1px 粗细区分**，而且三种东西共用这一个画法：选中的（2.5px）、一起亮出的组成（1.5px + 同样阴影）、被牵出的 hit（1.5px）。同一列上常同时出现两三种（02、04、05、14），用户分不出。
2. **选中的那一个有时根本没画**：买点日 ×2（02、09）；被选中的 event 在当前档位下不画（08、21）；聚焦样本（14）。反过来，**有时粗框落在不是选中的东西上**（10：选中的是一次 hit，粗框在 step）。
3. **「一起亮出」的集合有三种来源，混在同一种画法里**：一次 hit 的组成（04、15、17）；一整天几次 hit 组成的合集（02、09，同一条 band 上框两个，像选中了多个）；组成型规则从「第一个找到的复合事件」点亮的一串（05、07、08、21）。前两种规格里写了（`spec.md:546`），第三种不在规格「图上」那一句里。
4. **组成型规则挑中的复合事件常常不在任何 hit 里**：05、07、08、21 四例挑中的 plateau 全是 detected。它的子事件一部分画在视窗外（05、08、21 的 old_plat 09-16、step 10-07），一部分在当前档位下不画（07 的 new_plat 11-25、today 11-26），剩下画出来的那一两个和用户关心的 hit 毫无关系（21 的 today 11-29 甚至落在竖线上，冒充选中）。这就是「step 选中了，下面的 new_plat 却没被选中」的直接原因。
5. **竖线的日子和被细框的 hit 可以不在一处**（07：竖线 11-22，细框在 11-27…12-26；12/19：反馈不动竖线）。
6. **路径前缀决定画法，而路径对用户不可见**：同一个「12-02 第 2 次 hit」，从一族进来是 hits 格粗框 + 族底线粗（04 类）；从 step 进来是 hits 格细框 + step 粗框 + 族底线不粗 + 另 10 格细框（10）。
7. **密度**：用户默认视窗约 280 根 K 线时，格只有 2–3 像素宽，粗框 / 细框 / 不框肉眼分不出，个数行挤成「2222」（截图 22–24）；放大到约 46 根才分得出。

### 2.4 悬停（真页面 showTip 读出）

- band 格：并着几个时逐行 `events j/m 区别`，再写 `hits ×n`（被几次 hit 用到），下面是 Identity / Clauses / Attributes（实测值与门槛都在）。
- band 点记号（today）：`hits ×2` + Identity 等。
- hits 行的格与 ▼：`hits ×2`、逐次 `hits j/m 区别`、`ret_20` / `d_20`，再写「组成 hits 1/2 (1 events): plateau: plateau_774_795#0」——只列复合事件、用内部编号，子事件不列。
- 悬停内容不随选中变，只有「组成」那段跟着当前那次。

| event（用户这次的预期） | 选中 step 时用户预期 new_plat 也被标出（原话：「会有很多 hits 被选中，但是下面的 new_plat 却没有被选中」） | `原始问题.md` | 规格没写；现在靠组成型规则偶然画出，见 2.3 第 4 条 |
| node | 那条 band 上有几格、走到哪；它对的用户特征 | 显示栏 `into events ×n`；表头 | 表头写用户特征名（`spec.md:505`） |
| 反馈 | 它那段里有哪几次 hit 让它还红着、买在哪几天；点出的 node；状态；日期范围 | U11；说明书 `:500`、`:507` | 是：竖带（`manual.md:501`、`:507`）、细框（`spec.md:546`） |
| 样本 | 配对那次 hit 的组成；那天在场的几次；`match` ✓ / ✗；`diagnose` 分块（进 hit 的、没进 hit 的、档位、没过的 where）；成员框 | U5；`spec.md:507`、`:510` | 是：配对那次细框 + 组成亮出（`spec.md:546`、`:507`）；`diagnose`（`:210`、`:510`） |
| 框 | 它对的 node（那组表头加粗）；框终点在场的几次、配对那次 | U12；`spec.md:505`、`:507` | 是：表头加粗（`spec.md:505`）；配对那次细框（`:546`） |
| 任何 | 现在选中的是哪一个、它属于什么、按键会去哪；`Shift+C` 复制的就是它 | 显示栏、选中卡、`spec.md:512` | 是 |

上一轮立下、仍适用的约束（U 文末）：数字必须看得出数的是哪个集合；跟着选中走的东西（面板、`selection` 页、复制内容）必须一起走；不塞参数给用户。

## 5. 渲染能力边界（和设计有关的）

已在本仓代码里用过、可以确定能做的：

- **淡化无关的**：两种现成手法——在记号上叠一层白蒙复本（Shift 配对用的 shift-veil，`render/chart.ts:1395`，z 22）；或逐个记号设不透明度（标注框的 0.28 / 0.4，`render/annotateLanes.ts:398`）。每次选中变化副图都整张重画（`KlineChart.vue:1009` `setOption(opt, true)`，监听在 `:1529`），所以「按选中算每个记号该多淡」没有额外的刷新代价。
- **层次（z）**：副图从下到上：族底线 8 → 格 9 → 点与 hits 族底线 10 → hits 格与 ▼ 11 → 反馈记号 12 → 高亮 20–21 → 白蒙 22 → 竖线 30；compare 的用户框 10、样本跨度 9。高亮层一律不接鼠标（silent），悬停与点击穿到下层本体。
- **闪烁**：可以，但所在系列必须显式开动画（顶层关了动画会连带跳过，`render/chart.ts:999` 的注释），每帧都在重绘；截图看不出闪烁状态。
- **跨主副图的东西**：两张图是两个独立 ECharts 实例，横轴对齐。贯穿两图只能用 DOM 叠层（反馈竖带、拖选竖带、十字准星都这么做）或两边各画一次（当前日竖线）。
- **按 band 加粗表头、给轨名描边、悬停整行垫底**：都已有（`render/chart.ts:768`、`:777`、`:728`）。
- **文字**：rich text 可在一段里混字体、底色（样本字母后的 ✓ / ✗ 已这么做）。

推断可做、没实测的：

- **在当前日竖线上加记号**：竖线是 custom series（`render/chart.ts:1380` renderCursor），返回一个图形组，可以往里加子图形；但它现在是个不带几何信息的函数，要知道各条 band、各 lane 的 y 坐标，得像高亮那几个函数一样（`makeRenderHighlightWithGeom`）改成带几何的闭包。副图竖线在 z 30 最上层，加上去的记号也会在最上层；主图竖线在 z 10，压在价格记号下面。

不方便或要另做的：

- **视窗外的东西没有任何提示**：渲染只裁到视窗；要「左边还有一个被点亮的」得自己在图区边缘画（坐标系能拿到图区边界，可做，未实测）。
- **档位滤掉的东西不在图上**：高亮靠「它在图上的位置」反查，找不到就跳过（`render/chart.ts:404` pushHl）。要给「选中的但没画出来」一个替身，得另算它该在的位置（lane 分配目前只对画出来的做）。
- **密度**：描边宽度是固定像素，不随缩放变；格宽 2–3 像素时 1px 的粗细差、相邻格的框都会糊在一起（截图 22）。靠粗细区分的规则在宽视窗下天然失效；靠颜色深浅、整片淡化、竖线上的记号受影响小。
- **▼ 和个数数字**：▼ 是 hits 格系列里的一个分支，现在不读选中；要给它画法需在那个分支里加。数字被副图竖线（z 30）压住时会被挡。
- **一条 band 一格里并着的几个**是同一个记号，高亮时按「族 + 格」去重只画一次；要区分「一格里选中的是第几个」只能靠旁边的文字或悬停，图形上分不开。

## 6. 顺带发现的代码与规格不符（不改代码，只列出）

1. 规格「最外一节是样本时 `user` 行粗底线」（`spec.md:546`）：代码只把 `user` 两个字加粗（`render/annotateLanes.ts:322`），没有底线（截图 14）。
2. 规格「选中的那一个粗框」：买点日（▼）任何情况都不画；路径上有 event 时粗框画在 event 上、选中的那次 hit 只有细框（矩阵 02、09、10）。
3. band 族底线的「那一族的行加粗」永远不成立（D3）。
4. 「一起亮出」排除焦点时只认「走进去」的那种焦点（`render/chart.ts:426` 只比 focusedInstanceId），直选的 event 若是复合事件会被画两层（矩阵 05、06、07）；视觉上看不出，但说明两种画法本来就重叠。
5. hits 行悬停的「组成」一段用内部编号、只列复合事件（2.4）；1.13 去掉了反馈记号悬停里的内部编号（`spec.md:207`），这里没跟上。
6. `bracket` 词条仍写「带圈号的横带」（上一轮已报，未改）。
