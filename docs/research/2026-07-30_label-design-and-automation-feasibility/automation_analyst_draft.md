# 自动化 dag_spec 修改可行性 · 分析草稿（automation-analyst）

> 角色：automation-feasibility-analyst。任务：裁定"用 skill 自动化修改 dag_spec"是否值得投入 vs 人为优化。
> 状态：草稿，待 label-strategist / evidence-auditor 回核后收紧。最终结论发 leader。

---

## 关键澄清：三种"自动化"必须分开

leader 的任务把"feedback 工作流"描述为"skill 站全局统计自动改进 dag_spec"。但读完全套文档，"自动化"在这个项目里其实有三种形态，可行性天差地别，必须先拆开：

| 形态 | 是什么 | 文档立场 |
|---|---|---|
| **(A) 闭环搜索自动修改** | 生成候选→全部打分→挑最优→迭代（TPE/optuna/multi-fidelity/ralph 当搜索循环） | **判死**（opt §5/§6、final_report §8.4 反面清单） |
| **(B) 诊断辅助自动化** | 接出 eval_runner 丢掉的 gate_failures + cc 顺 code_location 读源码做批量归因（根因直方图） | **背书**（10_写给普通读者.md「最后该做的那一件事」、final_report §10 唯一行动项） |
| **(C) 体检/枚举/否决自动化** | 阶段0七项体检（纯计算）、通道A 删除枚举（机械）、因果闸（机械）、闸阵否决（自动） | **背书，但产出是"信息/否决"非"选择"**（final_report §3/§4/§5） |

leader 所说的"skill 自动改进 dag_spec"如果指 (A)，是不可行的；如果指 (B)+(C)，是可行且值得的、但本质是"诊断+否决"，不是"自动修改"。**这个区分是整份分析的关键。**

---

## Q1 · 自动化愿景具体是什么

10_写给普通读者.md 描绘的"自动化愿景"**不是**一个自动修改 dag_spec 的闭环。它由两段组成：

1. **它先论证了自动优化的危险**（「为什么这件事让"自动优化"变得危险」节）：自动优化不看形态、只认分数；分数里有一条"多选躁动股加分"的免费通道；自动优化会在几百次尝试内把这条通道榨干，然后报告"成绩提升 40%"——而那 40% 全是波动率。
2. **它给出的 AI 角色**（「AI 在这件事里到底能做什么」节）：八个机制（skill/subagent/team/workflow/ralph/hook/cron/bg）全是"编排 LLM 回合"的，没有一个会评估候选——所以"哪种机制擅长优化"是错位问题。真正让 cc 介入的入口是：评估器每次全宇宙扫描其实已经把每次失败的完整原因算出来了（code_location + threshold_param + measured），算完就扔；只要不扔，cc 顺着行号读源码就介入了，天然可批量。

**所以文档背书的"自动化"= 形态 (B)：把已算出但被丢弃的失败记录捡起来，cc 顺行号读源码做归因。它是诊断辅助，不是决策、不是闭环修改。** 唯一行动项（§10）是半天工作量、新建 0 个文件。

final_report §11 最后一条局限性把这一点钉死：**"本方法没有解决'如何生成好的语义候选'。它只能保证坏候选被挡住、好候选被公平比较。候选质量的上限仍然由人和 LLM 的领域理解决定，这一段没有被自动化，本研究也不认为它应该被自动化。"**

## Q2 · 根本障碍多大

### 2a · cc 无法融入定性理解——是 dag 改进的核心吗？统计能替代吗？

是核心，且统计不能替代——但只在**语义层**。

dag 改进按 final_report §4 分四条候选生成通道 + 三层（拓扑/detector 代码/参数）。其中：

- **机械层（参数③ / 通道A删除 / 层2a常量提参 / 层2.5已有字段加where）**：不需要定性理解，统计/枚举能做。但这些是"放松/删除/微调"类，产不出新形态。
- **语义层（新 detector 判据 / 新边语义 / 新形态概念 / 通道D人类直觉）**：这才是"改进 pattern 能力"的来源，且**必须**靠定性理解（放量=机构资金、K 线形态=吸筹/派发）。统计在这里只能事后 veto。

关键证据：opt §10.6 自己界定——机械邻域 τ²=0 不证明语义空间也到底了，"新 detector 判据 / 新边语义 / 新形态概念不在本次枚举范围内，其收益未被测量"。**但** §10.1 立刻加硬约束：必须配方向性检验（c 项首次穿越）当验收，否则新形态照样可能只是换一种波动率选择器。

cc 的定性理解能力评估：文档把 cc 的角色限定在"顺 code_location 读源码"（通道C，读代码做归因）+ 聚合格式纪律。**生成好的语义候选被划给通道D（人类形态直觉）**。用户的具体怀疑"cc 对 K 线图理解不如人类"——在"看图→认出吸筹/派发→提出新 detector"这条链上成立，这正是通道D，文档不认为该自动化。

**结论 2a**：定性理解是 dag 改进的核心（在语义层），统计不能替代它，只能否决。这与用户怀疑一致。

### 2b · 统计陷阱（选股少就放松阈值）——自动化能不掉进去吗？

不能，**只要它是闭环地攀爬任何 label**。这正是 feedback §0 否决的，也是 opt 的核心发现：

- score 是波动率读数（R²=0.92，跨27配置）；现任 min_relative_height=0.2 恰落在"波动率杠杆在样本量惩罚下的 argmax"（A.4b）——此前的调参实际找到的是"能榨出的最大波动率"。
- feedback §0 推翻"覆盖面广⟹泛化"：同期买点非独立、样本量本身是调参产物。
- 顺序：放松阈值 → n 变大 → 表面 score 可能升（更多躁动股进来）→ 真实方向优势纹丝不动（A.4b：波动率匹配后百分位 0.520→0.584 几乎不动）。

automation 能否避开？只有两条路：
1. **不攀爬 label**——把 label 当否决闸不当目标函数（final_report 的闸阵方案）。但这就不是"自动修改 dag_spec"了，是"自动否决坏候选"。
2. **修一把没有免费通道的尺子**——但 feedback §0 已经移除了止损止盈，保留的 mfr-lift 仍然主要奖励波动率；即使换成 strategy_return 模拟，跟踪止盈同样偏好大波动股（大波动才有大 peak 给跟踪线锁利）。**任何只看价格路径的 label 都对波动率单调**（这是 max(high)/close 这类算式的结构性性质，§3 g 项原文）。

**结论 2b**：闭环自动化必然掉进这个陷阱，因为它正是"拿数量/分数当目标"。§0 的三道闸（基线/顺序/因果）是事后否决，不能阻止一个攀爬器在它观测的维度上找到免费通道——它只能在新候选进比较前否决掉明显的坏方向。

### 2c · cc 看图不如人——dag 改进多依赖看图？天花板在哪？

依赖看图的部分 = 通道D（人类形态直觉）+ 通道C 的诊断操舵（"这只股本该被选中，为什么"需要先看图认出它该被选中）。这部分文档明确划给人。

天花板：cc 能做通道C 的"读代码+聚合作归因"（不需要看图，只读失败轨迹的 code_location），但不能做"看图→提新形态"。所以自动化的天花板 = 形态(B)+(C)：诊断 + 否决 + 机械枚举；天花板之下（语义生成）必须人。

## Q3 · 自动能做什么、不能做什么（边界）

| dag 改进动作 | 类型 | 自动化？ | 依据 |
|---|---|---|---|
| 参数层③（where/edge 阈值、detector 参数）旋钮调整 | 机械 | **半自动**：免费精确区粗网格全枚举→报"噪声内等价集"→取平台中心+max-n。**不叙述最优点、不做坐标下降** | opt §5.1/§11、final_report §5 |
| 通道A 删除候选（每 node/where/edge 各删一次） | 机械 | **自动枚举**，但产出=敏感度图（信息），不是配置（选择） | final_report §4通道A/§10 |
| 层2a 常量提参 | 机械 | 自动（零 DIFF 验证） | §4通道B |
| 层2.5 在**已有字段**上加 where 谓词 | 半机械 | 字段已暴露→声明式几行；**但"加哪个谓词"需语义**（哪个字段该设门槛是领域判断） | §4通道B |
| 阶段0 七项体检（a平凡/b口径/c方向/d因果/e标定/f硬门/g波动率） | 纯计算 | **自动**（d 已实现，c/g 秒级） | §3 |
| 因果闸（confirm_idx） | 机械 | **自动**（已实现） | feedback §1 / A.3 补记 |
| 通道C 失败归因聚合（根因直方图+钻取） | 诊断 | **自动**（接 gate_failures，cc 顺行号读源码） | §4通道C/§10 |
| 闸阵否决（硬门/因果/标注否决/回归误伤/两窗不崩） | 判定 | **自动否决**（不做比较、不累积选择偏差） | §5 |
| **新 detector 判据 / 新边语义 / 新形态概念**（层2c、通道D） | 语义 | **不可自动** | §11、§10.6 |
| **看图→"这只该被选中"→诊断操舵** | 语义 | **不可自动**（人） | §6 |
| **否决裁定**（实现偏离/设计偏离/存疑三选一） | 判断 | **不可自动**（人） | §6 |
| **两种语义不同的 pattern 二选一**（如固定0.2 vs 自身尺度归一） | 语义 | **不可自动**（人拍，不能用 score 挑） | A.4b |

边界一句话：**自动做"诊断（信息）+ 否决（拒绝）+ 机械枚举"；人做"选择（幸存者间按奥卡姆或语义偏好）+ 生成（语义候选）"。** 这正是 final_report §10 那句"产出是敏感度图（信息），不是配置（选择）"。

## Q4 · label 够格当自动反馈依据吗

要分两种"反馈"：

1. **当闭环自动驱动信号**（攀爬目标）→ **不够格**。理由：见 Q2b，任何 label 都有免费通道；且 opt 实测 contender 间 τ²=0，根本没有可攀爬的真实梯度。§0 三闸是事后否决不是梯度。**把 label 当驱动 = 在噪声/免费通道上做梯度下降。**

2. **当否决/检查点反馈**（人为改进时看）→ **够格，但有深层隐患**。
   - 够格的部分：基线扣减（bo_only）能抓"筛选没产生增量"；因果闸能抓"回到过去买"；顺序闸能抓"方向反了"；波动率倍数披露能抓"分数是波动率换来的"。这些都是否决级信号，对人为改进有用。
   - 深层隐患（待 label-strategist 确认 C 题）：**bo_only 基线本身在方向上接近无信息**（c 项先涨比例 0.46-0.53）。那么"相对 bo_only 的 lift"衡量的不是"我的 pattern 有没有方向优势"，而是"我的筛选比裸突破多榨了多少波动率"。这意味着即使做到 lift>0，也不代表有方向性——label 作为反馈只能告诉你"没比基线差"，不能告诉你"有真方向"。方向性只能靠 c 项（首次穿越比例）这个**否决闸**单独检验，而它本身不是 label、不能被攀爬。

§0 的基线/顺序/因果三闸是不是为防过拟合？是。它们防的是最恶劣的几类（复读市场平移、回到过去买、对称阈值作弊）。**但它们不能把 label 变成指向真规律的指南针**——它们只是把几条最显然的错路堵死。堵不死的是"在 label 奖励的维度上慢慢漂移"，而这正是任何闭环攀爬器会走的路。

## Q5 · 结论（初判，待收紧）

**初判 = (c) hybrid，但 hybrid 的形态非常不对称，且强烈倾向于"不值得为闭环自动化投入"。**

具体：
- **自动层（值得投入）**：形态(B)+(C) —— 接出 gate_failures（半天，唯一行动项，高 ROI）+ 阶段0 体检自动化 + 机械枚举出敏感度图 + 因果闸（已实现）。这些是诊断/否决，不碰 dag_spec 的语义。
- **人层（不可省）**：语义候选生成、看图操舵、否决裁定、pattern 二选一。
- **闭环自动修改 dag_spec（不值得投入）**：形态(A) —— 在当前 n、当前 label、当前语义空间下，τ²=0、97%跨期蒸发、任何 label 都有免费通道。投入一个"skill 自动改 dag_spec"的闭环 = 投资一个会被波动率通道吸走的攀爬器。

**leader 的"feedback 工作流 vs plan 工作流"框架需要修正**：它们不是二选一的两条路，而是两层。自动层（诊断+否决）是支撑人层（语义改进）的基础设施；label 的合法角色是反馈/检查点，不是自动驱动。leader 框架里"feedback 工作流 = skill 自动改 dag_spec"对应形态(A)，不可行；真正可行的"feedback"是"label 作为否决闸反馈给人为改进"，而这恰好由 plan 工作流（web ui 人为分析）承载。

**诚实的例外（不能藏）**：final_report §11/§1.2 留了一条后门——"修好目标函数之后必须重算 ρ_rel；档位一变（ρ_rel≥0.5），排序类工具回桌。" 所以"闭环自动化永远不值得"是条件性的：如果未来 (i) 换一个有真方向优势的新 pattern（不是 bbb），(ii) 在新 pattern 上测出 ρ_rel>0.5，那么有限度的搜索自动化可能回桌。**但这是未来证据驱动，不是现在投入的理由。** 现在的 bbb 上，方向性没有优势（c 项 7/8 单元低于随机），这是比 τ²=0 更硬的否决。
