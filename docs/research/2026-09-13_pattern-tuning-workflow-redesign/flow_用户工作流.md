## 0. 结论先行

1. **结构上既不新增 skill，也不合并两个 skill。** tune-gates 升格为「pattern 调参」唯一的编排入口，管对话、状态、阶段推进，也保留执行端机制。feature-study 仍是独立的学习端：用户可以直接触发它，编排入口也会在「这道闸该不该存在」这一步调用它。两端都会消耗的持久资源放在两个 skill 之外，一个是已有的登记簿，一个是新增的样本账本。取舍见 §2.1。
2. **端到端分八个阶段，常规只停三次，而且三次都在看过数据之后。** 第一次是开工确认，发生在优势检查之后。第二次是机制复核，只问自动核查解决不了的问题，可能一次都不用问。第三次是定案，发生在独立验证之后：结论按停 2 定好的规则算出，用户只确认写不写。另有一个条件停点：候选定下之后，如果验出结论的把握不到一半，先问要不要现在就用往前那段没碰过的数据。
3. **「继续」靠一条原则落地：进度完全从持久产物推出来。** 系统不依赖任何 skill 记得去更新一个进度文件。只有人的裁定推不出来，所以只有裁定才写账本。
4. **样本比算力紧得多，而且紧到会改变流程形状。** 时间上没碰过的数据只有两段，都不够长（stats 方案 §4.6）：
   - 往前一段 2022-09 ~ 2023-11-03，约 14 个月，最多分辨约 3.7 个点，但股票池不含退市股；
   - 往后一段 2026-03-02 ~ 06-18，约 3.5 个月，干净，但最多分辨约 7.5 个点。
   本轮真实效应只有 2~3 个点，所以两段各开一次、用同一份预先写定的清单：往前一段做主确认，往后一段只核「没有明显变差、方向一致」。结论常常只能是「暂定采纳」，这一点开工时就要告诉用户（§3.2 停 1）。另一个后果是闸「确实有用」的判定只能在最后得出，只影响下一轮的网格（§3 阶段 4、阶段 7）。
5. **对 bb_v1 来说，「分辨不出」很可能是常态结局，不是失败。** 三方定稿的读数有三组：
   - 开工前能分辨的差别：筛参数时约 4.8 个点，只验一个事先写好的改动时约 3.5 个点（stats 答复第 5 条）；
   - 09-08 两处定案的证据强度差别很大：提高突破门槛按回踩段去重 z 3.13，刚过 2.99 的门槛；关峰龄闸 z 0.99，无可检出效应；
   - 按「改进不到 2 个点不算数」，这份样本只够一次改一个参数（executor 方案 §5）。
   所以流程必须在开工前讲清「这份数据能分辨多大差别」，并把「维持现役」当成一等结局来设计（§3、§6）。

## 1. 从用户位置推出来的四条需求

1. **用户的心智预算只花在三类判断上**：值不值得调；某个机制在业务上能不能接受；要不要采用。先后顺序、用哪段数据、用什么指标、参数怎么分组、偏差怎么校正，全都是系统的事（CLAUDE.md「创作 skill」节；背景 §3.5）。
2. **跨两端的先后顺序现在没有主人。** 09-07 那一轮顺序做反，不是因为工具缺功能：两个 skill 各自的「上游 / 下游」条款都写了，但没有谁负责「下一步该调哪一端」。结果这件事落回用户头上，正是创作 skill 那一节要消除的负担（背景 §2、§3.1）。
3. **样本是两端共同消耗的资源，需要一个两端都读写的账本。** 实证：登记簿 FC-007~010 的发现样本是全宇宙 `w2024` / `w2025` 两个窗，09-07 调参的训练窗是 2024-01-01..2026-01-01（`outputs/tune_gates/bb_v1/main/longtable/run_meta.json`）。两端在同一段数据上各看了一遍，却没有任何地方记下这件事。
4. **用户隔天回来只会说「bb_v1 调到哪了」或「继续调 bb_v1」。** 系统必须据此知道下一步做什么、哪些结论仍然有效，而且不重跑。现有 `tune.status` 只覆盖执行端路径 B 的扫描、验证、识别三步。

## 2. 入口与路由

### 2.1 skill 结构：四个方案的取舍

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A 维持现状 | 两个 skill 各自独立，靠文档里的上下游条款衔接 | 零改动 | 顺序靠用户记，09-07 轮已经证明会做反；「继续」没有人接 |
| B 新增编排 skill | 第三个 skill 只管对话与阶段推进，两端退为被调用方 | 编排与机制分文件 | 三份 description 抢同一批触发词。tune-gates 要么让出「调参数」这类用户说法、只剩机制词（用户不会说机制词，等于再也不会被直接触发），要么和编排入口重复命中。「什么时候停下来问」「人话译法」两套规则要么重复、要么整体搬家 |
| C 合并两个 skill | 一份 skill 同时管学习与执行 | 只有一个入口 | 学习端的独立用途（「排行榜前排都是 XX」「XX 和收益什么关系」、批量跑登记簿）被迫背上调参状态机。「批量多重性防线只在学习端」这条纪律失去物理边界。两份机制文档合并后 400 多行 |
| **D（推荐）** | tune-gates 升格为调参唯一入口：顶层换成阶段图、对话规则、状态探测，执行端机制下沉到参考文档。feature-study 身份不变，编排入口在需要时调用它 | 触发词自然分工：参数、闸、调参、稳健区域归 tune-gates；特征、直觉、形态、登记簿归 feature-study。结构改动最小 | tune-gates 的 SKILL.md 要重排。编排知识和执行机制住在同一个 skill 里，学习端的改动如果影响流程，要回头改 tune-gates |

**为什么 D 优于 B。** 编排入口唯一需要、而两端都没有的东西是「跨两端的状态」。这件事靠共享的持久产物加一个只读的聚合探测就能解决，不需要为它单独开一个 skill。B 多出来的只是文件分离，需求覆盖和 D 一样，按剃刀选 D。

**为什么编排归执行端，而不是学习端。** 八个阶段里有六个在执行端（§3）。用户说「调参数」时指向的也是执行端。学习端的独立用途用不上阶段图。

**共享产物放在两个 skill 之外。** 登记簿 `docs/feature_candidates.md` 已经是这个模式：规则推送登记，学习端拉取消费。样本账本照同样的要求设计：git 跟踪、只追加、两端都能写、编排入口只读。它不能放 `outputs/`，那里被 gitignore，不持久。也不宜放 `tune-gates/apps/<app>/`，否则学习端独立触发时要跨 skill 写别人的目录。现有的 `exposure.jsonl` 可以作为它的一个子集并入。R2：两端已统一采用 learner 方案 §3.4 的 `docs/sample_usage/<app>.jsonl`，executor 方案 §7 另补四项。

### 2.2 用户怎么开口 → 路由到哪一步

编排入口的第一个动作永远是状态探测，只读、不写（§4）。下表的「路由」都以探测结果为前提。

| 用户会说 | 意图 | 路由 |
|---|---|---|
| 「调一下 bb_v1 的参数」「bb_v1 重新调一轮」 | 完整一轮 | 编排入口，从第一个未完成或已失效的阶段开始 |
| 「bb_v1 调到哪了」「上次调参进度」 | 查进度 | 编排入口，只汇报进度与下一步建议，不动手 |
| 「继续」「接着调」「继续调 bb_v1」 | 续跑 | 编排入口，直接执行下一步，遇到停点才问（§4.3） |
| 「峰龄闸还要不要」「这道闸有用吗」 | 某道闸该不该存在 | 在训练数据上做「删了不亏」检验，满足且用户确认它不是走势定义的一部分，才可以先删、标暂定；「确实有用」的判定要在时间上没碰过的数据里复现，放进下一份验证清单，等下次开窗。检测参数由执行端在现役参数附近单独松紧筛。有进行中的轮次就并入 |
| 「distinct_pk 定 3 还是 4」「这个阈值放哪」 | 定阈值位置 | 已判「确实有用」的闸，直接进联合网格定位置；没判过的先走上一行 |
| 「验证一下 XX 有没有用」「XX 和收益什么关系」「排行榜前排都是 XX」 | 特征假设 | feature-study 独立触发。结论进登记簿，下次调参时编排入口会自动读到 |
| 「把登记簿里的候选跑一遍」 | 批量验证 | feature-study |
| 「bb_v1 到底比随机买好吗」「这个 pattern 有没有用」 | 优势检查 | 编排入口只跑优势检查这一个阶段 |
| 「新数据来了，上次定的参数还成立吗」 | 独立验证 | 编排入口查样本账本，有没碰过的新窗口就对现役参数做独立验证 |
| 「持有期改成 20 天再调」「止损线换一下」 | 改衡量尺子 | 停下来问（§7），因为这等于开一份新口径，之前的结论都不能直接比 |
| 「给 bb_v1 加个节点」「改一下回踩的结构」 | 结构修改 | authoring-path2-app。改完后下次调参时，状态探测会发现代码变了 |

**「上次调到哪了」和「继续」的区别**：前者只读、只汇报，后者会执行。只有一个未完成的轮次时，「继续调参」不带 pattern 名也能直接接上。有多个时，列出来让用户点名。

**跨会话的限制（如实交代）。** 新会话里单说「继续」两个字，任何 skill 都不会被触发。用户需要带上 pattern 名或「调参」字样。这是 description 触发机制本身的边界，工作流设计绕不过去。

### 2.3 与 authoring-path2-app 的边界

authoring-path2-app 的 description 写着「纯调阈值数值（不碰结构）经入口分诊短路」。它的 Step 0 分诊把参数问题引向「评估器迭代（param_overrides 内存迭代）」，这是一条绕开调参流程的旁路，会跳过优势检查、筛选和样本记账。建议分诊结果改为转到 tune-gates 编排入口（§8）。

## 3. 端到端阶段图（业务语言）

从「有一个 pattern」到「参数定案并经外推验证」共八个阶段。阶段名是给团队用的内部标签，**对用户只说业务名**（「先看有没有优势」「筛参数」「几个参数一起调」「用没碰过的数据验证」），不报编号。

| # | 阶段 | 系统自动做什么 | 用户 | 需要谁提供 |
|---|---|---|---|---|
| 1 | 开局核对 | 认出 pattern；比较代码、底座、尺子自上一轮以来有没有变；**从实际数据文件探测覆盖范围**；按时间段切出训练段（2024~2025）、往前确认段、往后核对段，并在任何人看收益之前写进账本 | 不停（例外见 §7） | executor：数据覆盖探测、切分规则；stats：切分规则 |
| 2 | 优势检查 + 分辨力 | 只读两个配置、不需要网格。宽进点（检测参数在现役值、闸全关）回答事件结构本身有没有底子；现役参数点回答现在部署的版本有没有底子。两者都对比「同一交易日、当日同一波动层」的随机日，看首次穿越率，每年各判有底子、未证实、没有底子三类，另报两年合并。不匹配同日时，2025 年读数是 +6.8 点，匹配后是 +3.0 点，约 2.3 倍（stats R2 答复，e5b）。匹配的时间粒度会改变结论，属于尺子，事前定死。executor R2 已改为同日匹配。同时算出这份数据「能分辨出多大的差别」，以及按用户关心的最小改进，最多能同时动几个参数。分辨力只用这次运行的数据就能算，不必扫描：bb_v1 筛参数时约 4.8 点，只验一个事先写好的改动时约 3.5 点（stats 答复第 5 条）。耗时约 3~5 分钟，不需要一致性验证。因为不需要网格，这一步排在定范围之前 | 不停；结论并入第 3 步的消息 | executor（tune.edge；learner 已删去自己的 fs.edge）；stats：分辨力与基线口径（stats 方案 §3.4、§6 已给） |
| 3 | 定范围 + 开工确认 | 每个候选参数提一对松、紧取值；自动剔除尺子参数与退化档位；标出每道闸在学习端的审定状态；估算耗时 | **停 1** | executor：取值建议、耗时估算；learner：闸的审定状态 |
| 4 | 筛参数 | 同一次扫描上先后做两件事。先筛检测参数：在现役参数点（为主）和宽进点（看效果是否依赖在役闸）两个底座上，逐个松一档、紧一档。同一个回踩段只计一次，按去掉个股重复后的显著性做多重比较校正，分年读数只作旗标。再筛闸：在役闸在现役参数点上做「删了不亏」检验，即关掉后首次穿越率的单侧 95% 下界不低于负的最小关心改进。闸「确实有用」的判定要在时间上没碰过的数据里复现，而那段数据要等候选定下来、在阶段 7 才一次打开，所以本轮新得出的闸判定只影响下一轮网格；本轮能进联合网格的闸，只限以前已判过「确实有用」的（顺序后果，learner、stats 已确认）。对外三栏：确实有用 / 没用、删了也不亏 / 判不了。自动附带三件事：算术归因、冲突检测与拆解、顺手发现的登记 | 不停 | executor：筛选表与删闸检验；learner：闸的存在性假设写进清单 |
| 5 | 机制复核 | 自动核查能定的先定掉（例如「是波动率代理」由学习端判）。留给人的只有三类问题，合成一条消息：一是检测参数的机制在业务上能不能接受；二是建议删的闸是不是这个走势定义的一部分，是的话只固定、不删。删闸的依据只是训练数据上关与开的对比，属于初步结论，要对用户说明「这轮对闸的最终判断要等最后一步验证完才出来」。三是验证完之后采纳哪套参数的规则。默认规则：改进类改动按训练数据上各自单独贡献多大排，先整套、再逐项去掉最弱的一项；删闸类改动单独看删了亏不亏，可以单独采纳；都不过就维持现役。「贡献多大」的算法事先写死：在候选配置上按段去重、按股票去簇算 z，从大到小排，平手按参数声明顺序。用户可以在这里改规则，开窗之后不能改。要对用户说明：规则里的组合越多，每一套验出来的把握越低（stats 答复；删闸单列是 flow 按 stats 给的 bb_v1 映射归纳的） | **停 2（有候选改动或删闸时才停）** | executor / learner：归因与代理核查结果 |
| 6 | 几个参数一起调 | 只把幸存参数放进联合网格，以现役参数点为参照，加档位找稳健区域，档位以学习端给的分箱形状为中心；按噪声地板自动减档。**样本只够一次改一个参数时，这一步退化为「在幸存者的单个改动里挑」**，并如实告诉用户。候选 = 联合推荐 + 停 2 同意删的闸。**联合之后两端一起冻结一份清单，早于开窗写进账本**，清单包括五样：候选配置整体和其中每一项改动（Holm 校正）；未被提议删除的闸的存在性假设（BH 校正，条件总体预先定为这份候选配置）；对照（现役参数）与及格线；每项的预期功效；「哪些检验通过 → 采纳哪套配置」的映射，按停 2 定的规则机械展开，映射里每个回退配置的检测参数改动都单独进确认子族，因为突破门槛这类效应依赖闸开着。确认假设一律单侧。每道闸只进一个子族：被提议删的闸只做「删了不亏」，不再做存在性检验（stats 答复）。映射展开出来的每一套配置，其假设都进确认族。清单冻结后发通知：具体映射，以及映射第一项的验证把握。这个把握要打两次折扣：一是用扣掉训练期反复挑选虚高之后的效应，二是按族内校正后的门槛。把握不到一半时改为打断，问用户现在就用往前那段数据，还是留给以后效应更大的候选：这段数据不会随时间变长，等下去不会让它的把握变高（stats 建议，flow 采纳） | 不停；把握不到一半时停（条件停点） | executor：联合识别与预注册；stats：及格线 |
| 7 | 独立验证 | 两段没碰过的数据各开一次，用同一份预先写定的清单：候选改动（Holm 校正）加本批闸假设（BH 校正）。往前一段（2022-09 ~ 2023-11-03）做主确认，看候选相对现役的配对差是否显著，闸假设也在这里判；它不含退市股，只用于配对比较，不用于优势检查。往后一段（2026-03-02 ~ 06-18）只核两条：没有明显变差（单侧下界不低于负的最小关心改进），方向与训练期一致。每个配置按三档读：主确认显著且往后核对通过，采纳；主确认不显著但往后核对通过，暂定采纳；往后核对的「没有明显变差」不通过，撤回（stats 方案 §4.6）。最终采纳哪套，按清单里的映射机械得出。两段都写账本，标为已消耗。闸的存在性结论只影响下一轮网格；bb_v1 的在役闸在往前那段的最小可检出效应是 2.8~7.1 点，按 2 点标准功效预检全部不足，预期结局是「判不了，固定现值，下一轮再看」（stats 答复） | 不停。清单与预期功效早于开窗写进账本，并且预期功效已告诉用户；功效低于一半时明说「大概率给不出结论」 | executor |
| 8 | 定案 | 按映射给出结论，把结论和依据翻译给用户。用户只能确认写入，或者这次全部不写、维持现役。不能换成映射外或映射里的别的配置，只写映射配置的一部分也算换。不写时两段验证窗照样记为已用，不能改清单后在同一段数据上重开；不写的理由记进账本，报出的效应量不管写不写都照记（stats 答复）。停 2 同意删的闸、检测参数的改动、对已有定案的核对结论，都在这里按验证结果和清单里写好的规则一次写进正式参数；删闸验证不满足「删了不亏」时按映射退到不含删闸的配置，不再临时问；本轮中途不改正式参数 | **停 3** | — |

### 3.1 为什么是这个顺序

- **优势检查放在一切调参之前。** 调参只能磨锐已有的优势。没有优势时，从很多组合里挑出的最好那个，期望上一定为正，但那是运气（背景 §3.3 第 2 层）。
- **定范围放在优势检查之后、筛选之前。** 这一步让人看的是优势检查结果、特征取值分布与历史记录，不给看各档位的收益。看过各档收益再定范围，范围本身就成了一次在同一份数据上的挑选（细化背景 §3.5，见 §10）。
- **机制复核放在联合之前。** 被人否掉的参数不该占联合网格的格数。联合网格的格数决定选择偏差（背景 §3.1）。
- **独立验证放在定案之前。** 这样定案时手上有唯一无偏的数字。反过来先采纳再验证，拍板就发生在「数据说话之前」。
- **采纳规则定在开窗之前。** 看完验证结果再挑采纳哪个组合，等于在确认数据上又挑一次。所以用户在停 2 定规则，停 3 只确认写不写。「这次全部不写」只会少采纳，不会让误采纳变多（stats 确认）。但如果是看效应小才不写，多轮下来留下的采纳在效应量上会偏大，所以不写的理由和这次的效应量都照记。

## 4. 状态与续跑

### 4.1 三条原则

1. **进度是持久产物的函数，探测只读。** 这沿用现有 `tune.status`「不写任何文件」的做法，范围扩大到两端加两本账。
2. **只有人的裁定写账本。** 裁定包括范围确认、机制复核、采纳，以及「看了结果后改范围」这类会产生选择的动作。它们是唯一从扫描结果、登记簿、代码里推不出来的东西。
3. **每条证据都带「基于哪版代码、底座、尺子、数据窗」。** 结论是否失效靠比较这几样判断，不靠谁记得去作废。

### 4.2 每个阶段靠什么证明已完成、什么时候失效

| 阶段 | 完成的证据 | 失效条件 | 提供方 |
|---|---|---|---|
| 开局核对 | 账本里有本轮开局记录：pattern、代码与底座指纹、尺子、数据切分 | 代码、底座、尺子任一变化 | executor |
| 优势检查 | 账本里有优势结论，带指纹与窗口 | 代码或底座变化；窗口变化 | executor |
| 定范围 | 账本里有范围确认裁定 | 候选参数集合变化，例如代码新增了参数 | executor |
| 筛参数（检测参数） | 筛选扫描完成、一致性验证通过、筛选结论落账 | 代码或底座变化；范围变化 | executor |
| 筛参数（闸） | 本轮「删了不亏」检验结论落账；闸有没有用的判定在独立验证后由学习端回写登记簿，判定所基于的代码版本仍然有效 | detector 语义变化（实例：FC-008 注明 `first_drought` 在 `ed9a9a8f` 改过语义，之前的读数不可比） | learner |
| 机制复核 | 账本里有复核裁定，含删闸语义与采纳规则 | 筛选结论变化 | executor |
| 一起调 | 联合识别完成，验证清单冻结落账 | 上游任一阶段失效 | executor |
| 独立验证 | 账本里有验证结果；窗口标为已消耗 | 候选变化。但窗口不会因此「恢复」成没碰过 | executor |
| 定案 | 账本里有采纳裁定，并且当前 `params.yaml` 与采纳的候选一致 | 有人手改了正式参数 | executor |

**一个必须处理的「预期中的变化」。** 定案会改 `params.yaml`，底座指纹随之变化。现有 `tune.status` 因此报 `base_stale=True`，notes §1 已注明「那是预期的，不是异常」。状态探测必须能分辨两种情况：底座变成了本轮采纳的候选，这是「定案已落地」；底座变成了别的东西，这是「代码变了，要重来」。R2：executor 已按此设计，判据是当前底座快照是否等于账本采纳记录里的候选快照；不等就报「代码或参数被改过」。

**登记簿关闭行缺一个字段。** 现有关闭格式是「ID · 名称 · 口径 · 判定 · 验证样本 · 报告路径」，没有代码版本。续跑时判断不了一条旧判定在当前代码下是否仍有效。请 learner 补。R2：learner 方案 §4.4 已给判据。新判定带 git_head 与源码指纹；旧关闭行查关闭日期之后是否有提交改过该轴 detector 的源码，纯 git 查询。每条轴的状态分为有效、进行中、已失效、未开始四种。

### 4.3 「继续」的决策顺序

按顺序检查，命中第一条就执行：

1. **有被打断的长任务**（扫描、一致性验证、学习端数据构建）→ 断点续跑。开跑时已经批准过，不再问，只说一句「接着跑，还剩大约 N 分钟」。
2. **代码、底座或尺子自最近一个有效阶段以来变过** → 算出哪些阶段因此失效。若定案本身导致了这个变化，按 §4.2 视为预期。否则告诉用户哪些结论不再有效，以及重做的大致代价。若会作废已有结果，停下来问（§7）。
3. **有一个人的裁定还没做**（例如机制复核问过了但会话断了，账本里没有裁定）→ 带着已经算好的证据重新问，不重算。
4. **最早一个未完成的阶段** → 执行。
5. **全部完成** → 汇报「本轮已于某日定案」，并给出下一次能做独立验证的最早日期（按数据积累推算）。

**「上次调到哪了」的汇报模板**

> bb_v1 这一轮：底子检查做完了，2025 年有底子但不厚，2024 年还不能排除其实没有优势。参数范围和「改进不到 2 个点不算数」这个标准，你 9 月 13 日确认过。检测参数筛完了，只有提高突破门槛分辨得出、刚过线；6 道闸的「删了不亏」检验也做完了，关峰龄闸可以删，其余保持，闸有没有用要等最后验证。下一步要请你判断「关峰龄闸」是不是走势定义的一部分。数据方面，2026 年 3 月到 6 月那段还没碰过。

### 4.4 样本账本：业务需求（格式交 executor）

- **每次「看了某段数据上的收益、并据此做选择」都记一笔。** 包括稳健区识别、单闸切片查询、组合回放、学习端验证、独立验证、人看了结果后改范围。反例：09-07/08 轮定案环节做了约 40 次单闸查询和 9 次组合回放，只记在 notes §11 的一句话里，`exposure.jsonl` 里一条都没有。
- **工程验证类的查看要能和决策查看区分开。** 实例：`exposure.jsonl` 的两行里，一行是 `run=main`（决策识别），另一行是 `run=verify_all`（09-12 内存根治后的等价性验证，可评估格 150470，远小于 main 的 2245822）。不加区分的话，「这批数据已经看过几遍」会被虚增。
- **窗口有三种状态**：没碰过；已用于某些决策（按参数族记，不是全局一刀切，stats 已确认）；独立验证已消耗。
- **预注册要早于查看。** 候选、对照、及格线三样写入账本的时间必须早于独立验证那次查看，状态探测据此判断验证是否干净。

**R2 两端已统一**：executor 方案 §7 采用 learner 的格式，另补四项：优势检查记录、每次单格查询一条、采纳时记依赖的背景、尺子指纹。**R2 对照 learner 方案**：learner §3.4 的「样本使用登记」满足上面四条需求。它放在 `docs/sample_usage/<app>.jsonl`，git 跟踪、merge=union、只追加，并把 `exposure.jsonl` 并了进去。其中「只有做选择才烧、按轴记」回答了本节「按参数族记还是全局记」的问题，以 stats 审定为准。**stats R2 裁决**：挑选次数按参数族记，与已烧参数在池内 |ρ|≥0.3 的算同族，用于报告某项采纳背后比较过多少次；时间上独立的验证窗全局只用一次，对任一候选看过之后，对所有与之时间重叠的候选都不再干净。「没碰过的数据用完了」这条红线的定义是：当前确认窗已经为某份清单开过。同一段数据换候选再验的规则（stats 答复第 7 条）：清单内多个候选一次 Holm 校正；开窗后才加的候选只算探索读数；确认失败后改候选再测，同一窗不再算确认。每道在训练数据上做过「删了不亏」检验的闸，都计入该参数族的比较次数（stats 答复）。停 3 选择不写时（stats 答复）：两段验证窗照样记为已用；不写的理由记进账本；这次报出的效应量照记。条件停点选择「先留着往前那段」时，账本记往前窗未开、往后窗已用。

## 5. 报告形态

### 5.1 每个阶段给用户看什么

每条汇报都是三件套：**一句话结论 → 业务代价 → 证据在哪**。证据指研究目录下的报告，用户想复核时去看，消息里不贴内部表格。

| 阶段 | 一句话结论 | 业务代价 | 证据 |
|---|---|---|---|
| 开局核对 | 「代码自上次调参后改过三处，上次的结论不能直接用」/「数据只够这样分：……」 | 要重做哪些，大约多久 | 账本开局记录 |
| 优势检查 | 「和同一天、同样波动的随机日比，2025 年有底子但不厚，2024 年还不能排除是 0」这类分年说法 | 没有优势时，调参挑出来的好成绩多半是运气 | 优势检查报告 |
| 定范围 | 「每个参数这样试松紧：……；这几个是衡量尺子或机制上等于没设，不参与」 | 范围看完结果再改，等于多挑一次 | 取值建议表 |
| 筛参数 | 「这一轮一共比了 N 个改动，k 个分辨得出；m 道闸删了不亏」 | 每个分辨得出的参数带来的买点数变化 | 筛选表 + 学习端报告 + 登记簿新行 |
| 机制复核 | 「这个效果可能来自多等几天再买，不是选股」 | 放进去可能换来更高的首次穿越率，也可能只是在跟趋势 | 归因报告 |
| 一起调 | 「推荐这组取值，旁边的取值小改也不太影响」/「没找到稳健区域」 | 买点数变化；扣掉挑选偏差后的数字 | 识别报告 + 判据卡 |
| 独立验证 | 「往前那段上分辨得出 / 分辨不出；最近几个月没有变差、方向一致」 | 两段都用掉了；把握不到一半时事先说明 | 验证报告 |
| 定案 | 「已写入正式参数」 | 下一次能做独立验证的最早时间 | notes + 账本 |

**每个「有用 / 没用」的说法都必须带两样东西。**
- **分辨力**：这个差别有没有超出数据能分辨的范围。超不出就说「分辨不出」，不说「没用」。
- **靠多少个回踩段撑着**：效果集中在少数回踩段上时，要说出这个数。实例：提高突破门槛在定案前的闸组合下两年 +3.09 / +3.28 点（按回踩段计），靠每年 33 / 41 个掉出的回踩段撑着，首次穿越计数 81 / 99（learner 方案 §6.3 R2，同一回踩段只计一次）。给用户说「靠每年 33~44 段回踩撑着（合计约 80~100 个定向买点日）」，不把回踩段叫买点（learner R2：词表里「买点」指买点日）。

**判据卡要跟着扩。** `docs/explain/tune-gates_调参判据卡.md` 现在只讲识别结果怎么读。新流程下还要补三节：「优势检查怎么读」「筛选结论怎么读（有用、没用、跨年相反各代表什么）」「独立验证怎么读（两段数据、三档结论）」。

### 5.2 新增的人话译法（补 tune-gates SKILL.md §三）

| 边际效应筛选 / 两档筛选 | 「把每个参数单独松一档、紧一档，看动它有没有用」 |

|---|---|---|---|
| **pattern 没有优势**（两年都判「没有」，即优势的误差上限低于最小关心改进；两年数据下很少出现，多数结局是「还不能确定」） | 「最宽松的版本两年都不比同样波动的随机日好。调参只能磨锐已有的优势，现在没有可磨的，从很多组合里挑出来的最好成绩多半是运气。」 | ① 停止调参，回去改结构；② 换股票池或时间窗再看，但会多用一段数据；③ 坚持调，结论标注「无底子」 | ① |
| **底子只在一年证实，或两年都未证实**（bb_v1 是 2025 年有、2024 年未证实） | 不单独停，并进开工确认（停 1 模板第一段）：按年说清哪年有、哪年「还不能排除是 0」。一年有、一年没有时说「底子随年份变」 | 用户可以当场喊停、回去改结构 | 继续；报告分年说，两年都未证实时结论带「底子未证实」 |

| **一起调之后找不到稳健区域，或几种读数互相矛盾** | 沿用现有模板（tune-gates SKILL.md §二「几种独立读数互相矛盾」） | ① 保持现役；② 只采纳单参数筛选里最强、机制最清楚的一个改动，走独立验证 | ② |

## 7. 什么时候停下来问（完整清单）

沿用 tune-gates SKILL.md §二的四类。**同一时刻碰到多个停点，合并成一条消息问。**

### 7.1 不可逆

| 动作 | 何时问 | 人话 |
|---|---|---|
| 作废已有扫描结果（已取消） | 不再问：executor 方案 §9.1 改为按窗口存放研究声明，新开一份、旧的保留 | — |
| 退役清理 | 始终问 | 沿用现有模板 |
| **动用没碰过的数据** | 通常不停：预先写定的清单（含预期功效）早于开窗写进账本，且预期功效已告诉用户，就自动开。两种情况要问：一是折扣后的验证把握不到一半，走条件停点（stats 建议）；二是要验的不在预先写定的清单里（stats 方案 §4.6） | 「往前那段只能用一次，这次验出结论的把握只有约 x 成，现在用还是留着？」／「这个候选不在事先写好的清单里，用这段数据验它不算确认，还要验吗？」 |
| **改衡量尺子**（持有期、目标线、首部缓冲、基线口径、时间窗） | 始终问 | 「改了尺子就等于开一份新口径，之前所有结论都不能直接比，这一轮要从头来，确认吗？」 |
| 写入正式参数 | 即停 3 定案 | — |

### 7.2 超过半小时

扫描、一致性验证、学习端全宇宙数据构建。**尽量并进停 1**，一次批准整段筛选。之后续跑不再问。

新流程下的耗时量级（executor 方案 §13，推导）：

| 动作 | 量级 |
|---|---|
| 优势检查 | 已有基线表时秒级；首次建表分钟级 |
| 筛选扫描（bb_v1 为 73 个检测组合） | 全宇宙几分钟 |
| 联合扫描（至多 4 维 × 5 档） | 5~10 分钟 |
| 一致性验证 | 约 47 分钟；同一 app、同一分类、只改检测参数档位时可免 |
| 连筛选一起重做的 bootstrap | 秒级到一分钟 |
| 独立验证 | 几分钟 |

所以正常一轮里，只有「新接入 app 或改了 detector 之后的一致性验证」会超过半小时。这一项的批准并入停 1。学习端的耗时（learner 方案 §8.3）：闸判定直接读执行端扫描结果，秒级取数、分钟级算完；往前确认段另开一次扫描约 13 分钟；新特征全宇宙重放估 5~20 分钟。都在半小时内。

### 7.3 真研究决定

- 开工确认，即定范围（停 1）。
- 机制在业务上能不能接受、删闸是不是走势定义的一部分、验证后的采纳规则（停 2，有候选改动或删闸时）。
- 验证把握不到一半时，现在就用往前那段数据还是留着（条件停点，联合调参之后）。
- 定案（停 3）：只确认按规则写入，或这次全部不写。
- 没有优势时要不要继续（§6）。
- 筛选后没有幸存参数时怎么办（§6）。
- 独立验证没通过时怎么办（§6）。

**learner 提的五个拍板点怎么处理（R2）**：
1. 删闸前问「是不是走势定义的一部分」：保留，并入停 2。
2. 预注册冻结前问「要不要加直觉」：不单独停，并入停 1 的一句话；之后再提的想法排到下一批。
3. bb_v1 过渡期的样本分配：R2 已不存在这个选择。learner 撤回棋盘，2022-09 ~ 2023-11-03 全部股票作为往前那段确认数据，闸假设与候选改动放进同一份清单、一次打开。
4. 功效不足时等数据还是接受弱结论：不问。默认保持现值、不进网格、排进下一批，并告诉用户最早什么时候数据够。只有用户明确要对一道判不了的闸动手时才问。
5. 核对结论影响已有定案：结论是「暂定、等验证」时自动标记、不问。结论是「撤销」时要改正式参数，本轮内并入停 3，单独发起时单独问。

learner R2 已把拍板点减为三个：删候选的语义职能、冻结前加直觉、对账拆不开时的处置。flow 的处置：第一个并入停 2；第二个并入停 1 的一句话；第三个是条件停点，归 §7.4 红线「两端冲突拆不开」。learner 第二轮回复已接受这些处置。

**executor 方案 §13 提的五个拍板点怎么处理（R2）**：
1. 最小关心改进：保留，并入停 1，开跑前定；开跑后再改算新一轮。
2. 往前扩窗换样本量：R2 已不存在这个选择。2022-09 ~ 2023-11-03 作为往前那段确认数据，执行端不拿它当第三个年折。退市股覆盖由系统自动核查，偏差明显时才在停 1 告诉用户。
3. 在役未审定闸要不要先删：并入停 2，和「是不是走势定义的一部分」合成一个问题。
4. 依赖背景的定案复核：不问。只要几分钟，背景一变就自动复核，结果在下一次汇报里说。
5. 是否对 09-08 定案立即做独立验证：开局核对发现现役参数里有「暂定」改动时，把它放进本轮预先写定的清单，并在停 1 说明「没碰过的数据最后会连它一起验一次」。用户单独提出时单独问，因为这会用掉那段数据。

### 7.4 红线

- 一致性验证没通过。
- 旧结果用当前代码复现不出来。
- 几种读数互相矛盾。
- 两端冲突拆不开。
- 没碰过的数据用完了，即当前确认窗已经为某份清单开过（stats 答复）。
- 本轮途中代码变了。

### 7.5 全部自动、不问的事

路由到学习端还是执行端；删闸验证不过时按映射退回；冻结验证清单并展开具体采纳映射；清单冻结后发验证把握通知（把握不到一半时改为停下问）；哪段数据做什么用；用什么指标；每个参数试几档、怎么分组；按噪声地板减档；读写登记簿；登记顺手发现；断点续跑；算术归因；冲突拆解；预注册；生成报告。

**对比现状**：现有流程里的「网格设计」是在读完代码、看任何数据之前让用户拍板 12 维网格（背景 §2），属于「拍板在数据说话之前」。新流程把它换成优势检查之后的「定范围」，而且用户不再逐维增删，只看松紧取值。

## 8. description 修订建议

**tune-gates（升格后）**

> 调 path2 pattern 参数的全流程，从头到尾代办：先看这个 pattern 比随机买入有没有优势，再把每个参数、每道闸各试松紧一档，筛出真正起作用的，几个参数一起调找稳健区域，最后用没碰过的数据验证后定案。用户说「调一下 XX 的参数」「这个参数 / 这道闸还要不要」「阈值放哪」「找稳健区域」「XX 调到哪了」「继续调 XX」「新数据来了，上次定的参数还成立吗」「这个 pattern 比随机买好吗」「把 XX 的闸都过一遍」「这道闸该不该删」「上次调参定的改动和新发现对不上」时先调本 skill。

改动理由：
- 现 description 里的「宽进扫特征」「逐闸平台图」「程序判定」「候选长表」都是机制词，其中「长表」还在它自己 §三的禁止词表里。
- 新增的「XX 调到哪了」「继续调 XX」「上次定的参数还成立吗」「比随机买好吗」四组，对应新增的续跑、独立验证、优势检查能力。按创作 skill 节「功能扩展后必须回头改 description」补上。

**feature-study**

> 验证某个特征、几何量、K 线形态或直觉跟后续涨跌到底有没有关系、该不该信时调。用户说「验证 XX 是否有利」「XX 和收益什么关系」「排行榜前排都是 XX」「XX 是不是只是波动率在起作用」「把登记簿里的候选跑一遍」时必读；调参过程中判断某道闸该不该存在，也会转到这里。

改动理由：
- 去掉「学习端 skill」「label(forward_return)」「tune-gates(执行端)」三个内部说法。
- 加「XX 是不是只是波动率在起作用」，这是 FC-009 之后用户会自然问出口的问题。
- **R2 与 learner 的分歧（已解决，learner 第二轮接受）**：learner §8.3 提议给 feature-study 加「这道闸有没有用」「该不该删这道闸」「把某个 pattern 的闸都过一遍」「两边结论对不上」「这个 pattern 到底有没有优势」。flow 建议这些词放 tune-gates，理由有三。一是这些问题的回答会动正式参数，要走停点、样本账本和状态探测，这些都在编排入口。二是同一句话同时命中两份 description，路由会不确定。三是「两边」是两端架构的内部说法，用户不会这么说，改成「上次调参定的改动和新发现对不上」。feature-study 仍在编排入口内部被调用，能力不受影响。

**authoring-path2-app（只改一句）**

把「纯调阈值数值（不碰结构）经入口分诊短路，不走设计全流程」改成「只调参数取值、不碰结构的，转调参流程」。正文 Step 0 分诊的参数分支同步改为转 tune-gates，理由见 §2.3。

### 9.2 新流程下用户会经历什么

**对话 1（一个会话，常规三个停点）**

1. 用户：「detector 改完了，重新调一下 bb_v1。」
2. 自动完成开局核对：发现代码变了；把旧扫描结果另存，不覆盖；探测到数据覆盖到 2026-08-17；按时间段切分：2024~2025 全部股票用于发现、筛选、联合；2022-09 ~ 2023-11-03 作为往前那段确认数据，最后一次打开，同时装闸假设与候选改动，只用于配对比较；2026-03-02 ~ 06-18 留作独立验证。
   - 同时读登记簿：5 道 where 闸加 1 道过滤闸都没有「已关闭」判定。distinct_pk（FC-007）、first_drought（FC-008）、vol_spike（FC-003 / FC-010）都还是待验证状态；peak_age 只在 FC-009 的方法结论里出现；`KNOWN_SIGNALS` 里一个闸都没有。所以这 6 道闸都不直接进网格。
3. 自动完成优势检查。只按波动层匹配时，宽进点首次穿越率 2024 年约 −0.3 点、2025 年约 +6.7 点（FC-007）。改为同一交易日、当日同一波动层匹配后，2024 年 +2.5 点 [−0.4, +5.4]，2025 年 +3.0 点 [+0.2, +5.8]（stats R2 答复，e5b）。判为「2025 年有底子但不厚、2024 年还不能排除是 0」，流程继续，报告分年说。同时算出分辨力：筛选时约 4.8 个点，只验一个事先写好的改动时约 3.5 个点，同时改两个再大七成左右（stats 答复第 5 条）。按默认「改进不到 2 个点不算数」，这份样本只够一次改一个参数（executor 方案 §5.2）。
4. **停 1**：用户看到的消息包括四件事：
   - 6 个检测参数的松紧取值；
   - 「闸按功效预检全部会判不了，这一轮主要调检测参数」；
   - 「筛选时约 4.8 个点以上才分辨得出；按改进不到 2 个点不算数，只够一次改一个参数；底子这一项多半只能判到『还不能确定』」；
   - 预计耗时：筛选只要 73 个检测组合，上一轮是 4096 个。
   用户回「行」。
5. 自动完成筛参数。以下读数来自 executor 方案 §1.5、§3.3，learner 方案 §6.3，以及 stats 的答复。
   - 检测参数在现在这套参数附近逐个翻转。按 executor R2 与 stats 统一后的判据，只有提高突破门槛 0.003→0.0075 幸存：在改前参数点上约 +3.1 点（误差约 1 点），按回踩段去重 z 3.13，BH 门槛 2.99，刚过线（stats 答复第 12 条）；两年各 z 2.10 / 2.28。这套判据是两个底座（现役参数点为主）、同一回踩段只计一次、去掉个股重复后的 z 经 BH 校正（q=0.10，stats 方案 §11.5 定稿）。回踩最长跨度 20→10 是 z −2.32 的变差，不幸存，保持 20。
   - 关掉峰龄闸：无可检出效应（去重后 z 0.99），不幸存；但它满足「删了不亏」：executor 按 stats 定稿的门槛（等于最小关心改进）重算，仍然通过。峰龄闸是还没审定过的在役闸，这个观察自动登记为待验证。其余四道在役闸（vol_spike、first_drought、distinct_pk、单日跌幅）按新门槛重算后都不满足，不能删；其中关 vol_spike 是 −1.91 ± 1.55 点，下界约 −4.5 点（executor 第三次回复、stats 方案 e4）。
   - 闸：本轮只做「删了不亏」检验（见上一条）。闸有没有用的判定放进最后那份清单，在 2022-09 ~ 2023-11-03 上一次打开；按 stats 的功效预检，这几道闸在往前那段的最小可检出效应是 2.8~7.1 点，按 2 点标准全部不足，其余五道闸的存在性结论预期都是「样本不够，下一轮用 2026 年 6 月之后的新数据再判」，固定现值（learner 回复）。被提议删的峰龄闸不进存在性检验，只作为候选做「删了不亏」。
   - 冲突拆解自动完成：提高突破门槛的好处只在 burst 闸打开时出现，靠每年 33~41 段掉出的回踩撑着；闸全关时是 −0.16 / +0.25 点（learner 方案 §6.3 R2）。判为交互型，不算和 FC-006 正面冲突，但这条改动要记下「依赖 burst 闸开着」。
6. **停 2 问两件事**：一是「关掉峰龄闸，买点多 13%，首次穿越率分辨不出变化，最坏也只差 2 个点以内，删了不亏。它是不是你心目中这个走势定义的一部分？不是的话，它会作为候选放进最后那份验证清单；这是按调参数据的初步结论，最终判断要等最后一步验证完。」二是验证完之后的采纳规则：「两处改动的检验全部通过就两处都改；否则只改突破门槛那一项通过，就只改它；否则只删峰龄闸不亏，就只删它；都不过就维持现在。这个规则现在定，验完不能改。」
7. 「几个参数一起调」退化为「在单个改动里挑」，候选就是提高突破门槛这一处。如果用户在停 2 同意关掉峰龄闸，两处同时改已超出分辨力，只能靠独立验证看方向。然后预注册候选、对照（改前参数）与及格线。清单里还有：其余 5 道闸的存在性假设，条件总体定为这份候选配置；按停 2 规则展开的采纳映射；每项的预期功效。验证的是整套候选配置，也验其中每一项改动；映射里每个回退配置（只改突破门槛、只删峰龄闸）的效应也单独进确认子族，因为突破门槛的效应依赖闸开着；确认假设一律单侧（stats 答复）。映射要验 3 套配置：两处都改、只改突破门槛、只删峰龄闸。清单冻结后发通知：具体映射，以及第一项「两处都改」按两次折扣算的验证把握。
8. 自动完成独立验证，两段各开一次（stats 方案 §4.6）。往前 2022-09 ~ 2023-11-03 做主确认，对 +3.2 点效应的检出功效约 67%，这是单检验、未扣挑选虚高的上界；往后 2026-03-02 ~ 06-18 核「没有明显变差（单侧下界不低于 −2 点）、方向一致」，功效约 22%。开窗前已在停 1 把「主确认最多约三分之二的把握」告诉用户。清单冻结后按两次折扣重算映射第一项的把握再报。突破门槛的改进刚过线，扣掉虚高后效应会变小，把握可能不到一半，那时会先走条件停点（推测，折扣后的数字未算）。
9. **停 3**：「按事先定好的规则，这次的结论是［两处都改 / 只改突破门槛 / 只删峰龄闸 / 维持现在］。依据：提高突破门槛在训练期高约 3.1 个点，算上这一轮一共比了 36 个改动仍然分辨得出，但刚过线；它依赖 burst 闸开着，以后删了这些闸要复核；底子方面 2024 年还不能排除是 0。往前那段没碰过的数据上［分辨得出 / 分辨不出］，最近几个月［没有明显变差、方向一致］。这个结论是规则算出来的，要按它写进正式参数吗？不写就维持现在这套。」

**要特别说明的一点**：按这组读数推演，新流程下 bb_v1 这一轮大概率落在和实际相近的改动上，也就是提高突破门槛，外加一个可选的关峰龄闸。区别在三件事：
- 它的证据强度被如实写清：训练数据上分辨得出、依赖 burst 闸，独立验证给出的是「采纳」还是「暂定采纳」；
- 写进正式参数之前，已经在两段没碰过的数据上各验过一次；
- 采纳哪套在开窗前就定了规则，验完不会再挑一次；
- 用户在开工前就知道「只够一次改一个参数」，不会再有 265 万格那一轮。

R1.5 按全因子平均效应推出的「维持现役」已撤回：executor 方案 §1.1 实测，平均效应和在现役参数点上的效应系统性不同，而调参要改进的是将要部署的那组参数。
