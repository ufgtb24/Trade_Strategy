### 已定方向

#### D1 单子的问题和选项移到会话里，标注工具只放每道题要看的图（用户 2026-10-29 拍板）

**起因**：用户实际看 mock_v4 的单子时看不懂题，以为两张缩略图是前两道题（长下跌、收在高位）的配图。

- 两道定级题（Q1、Q2）除了会话的一句依据，名字上连悬停都没有，屏上没有任何地方写「这个名字该定哪一档」。

- J1 真正要解决的是「找图」。用深链接就能解决，不必把题和选项搬进界面。J1 的感受来自模拟用户，真实用户的反馈正好相反。

**定下的分工**：

### 4.1 单子选项词会读反，「不放」一级有三个名字（作废，被 D1 取代）

**涉及 issue**：newbie-r1-5（r3 又报，补了 `on_chart`）、rival-r1-9。

**现象**：
- Q4 的 `later` 会读成「稍后再答」，实际意思是「后来才看出来」。
- Q3 的 `keep` / `drop` 紧挨着 `−回踩`，会读成「保留 / 去掉回踩这条要求」。实际 keep = 这张仍算这个 pattern，drop = 这张不算。drop 的误读结果，正好是 keep 的真实效果。
- `on_chart` 会读成「跳到图上看」，实际是一个回答：「图上其实有」。
- Q1 的 `background` 会读成「当作背景条件放进 app」，实际是「不放进 app」。它和 Q2 的 `irrelevant`、pattern 页的 `excluded` 是同一级，三个名字（baseline 疑点 8）。

**选项**：
- A. 保留原词，靠悬停解释。代价：不看悬停的人会点反，错误回答进了记录，会话下一轮会照着它改对应表或 label。
- B. 换成直接说出「选了会怎样」的标识符，并把三个「不放」合成一个词。代价：推翻 U17，用户要重新认 3～4 个词；固定词总数不增加，概念少一个。
- C. 词不动，每道题前加题头。代价：固定词变多，`later` 的歧义还在。

**reviewer 推荐**：B（newbie 两轮、rival 都是）。**我推荐**：B。单子是答题的唯一入口，读反会直接变成错数据，悬停兜不住。具体用词由实现时拟一版给用户看（待定）。

### 4.2 顶栏「按下」的意思不统一

**涉及 issue**：rival-r1-3、func-r1-6、code-r1-3、rival-r2（tool / labels 那一条）。

**现象**：
- r1 改动 10 把 mode 一组改成了「按下 = 图正按什么显示」。没 app 时显示 annotate 按下，但 S.mode 还是 compare，切回有 app 的 pattern 会自动回到 compare（U39）。
- 于是同一个画面背后有两种状态。用户点一下看上去已经按下的 annotate，会悄悄取消「自动回 compare」。
- 同一条顶栏上，tool（app 档里 `box` 按着又灰着）和 `labels`（annotate 档里勾着又灰着）还在用旧画法。所以「选了但这一档用不了」有两种画法。

**选项**：
- (a) 维持 r1 做法。代价：有一个看不见的状态；一条顶栏上两套规则。
- (b) mode 退回旧画法，三组统一成「按下 = 你选的，变灰 = 这一档现在用不了，能用时自动恢复」。代价：baseline 疑点 R1 的读法（「compare 正开着」）回来，只能靠变灰和悬停来说明。
- (c) tool 和 labels 也照 r1 的新规则：用不了时不显示按下。代价：切回能用的档时，按钮会突然又按下，同样要记「切回自动恢复」。
- (d) 没 app 时真的把 mode 切成 annotate，取消 U39 的自动恢复。代价：从没 app 的 pattern 回到有 app 的 pattern，要多点 1 下 compare。

**reviewer 推荐**：rival-r1 推 (b)，rival-r2 推 (c)，两人不一致。**我推荐**：(b)。
- 理由一：它是唯一既没有隐藏状态、三组又同一条规则的做法。
- 理由二：「变灰 = 用不了」本来就是 H6 给灰色留的意思。
- 理由三：R1 的读错只是「以为对照开着」，图上马上就能看出没有对照内容，读错的后果小。
- (c) 把「自动恢复」藏得更深，(d) 要推翻用户亲自定的 U39。

**实施时**要撤回 r1 改动 10（`renderTop` 里 mode 组的按下判定）。

### 4.3 进了 match 的 burst 本色红和朱红，色弱分不开（已定不改，见 D2）

**涉及 issue**：rival-r1-11、newbie-r2-2、rival-r2。

**现象**：burst 本色 #FF1500 和朱红 #D55E00 都是暖色，相对亮度约 0.218 和 0.22，几乎一样，正好是 H7 点名要避开的一对。每张 compare 截图里都有进了 match 的 burst，于是「朱红 = app 和你的标注对不上」这个唯一的改动信号，常年被一块同样观感的红冲淡。

**选项**：
- (a) 保持 node 本色（和主视图同色）。代价：色弱用户只能靠「这是条还是签」来区分。
- (b) 只在本工具里，把进了 match 的 burst 换成和朱红冷暖相反、或明暗拉开的颜色。代价：同一个 burst 在两个工具里颜色不同。
- (c) 改 burst 的本色，主视图跟着改。代价：动主视图配色，用户说过主视图配色不动。
- (d) 换掉朱红。代价：朱红是用户确认过的「对不上」色，全原型都要改。

**reviewer 推荐**：newbie 推 (b)，rival-r1 推 (c)。**我推荐**：(b)。主视图里没有「朱红 = 对不上」的用法，换色只影响本工具。新颜色从用户确认过的色弱安全色板里选冷色，待验证。不考虑去掉色相、只用明暗：用户明确说过别退成黑白。

### 4.10 「能一下收进的同名框」宽条件、窄条件并存

**涉及 issue**：code-r2-1（接替 code-r1-2 中判定条件那部分）。

**现象**：同一种深色虚线，在两处的判定条件不同：
- 成员链的空槽和缩略图按 `nearestLeft` 判，范围宽：买点前任何一个没收进的同名框都算。
- others 列表和主图 ◂ 按 `unclaimed` 判，范围窄：只算 bracket 内或左边 NEAR 以内、而且不是同一 pattern 别的买点成员的框。

**选项**：
- (a) 全部用窄条件。代价：离得远、或已经被别的买点收了的同名框，空槽里不再提供一下收进，要去 others 里点。
- (b) 全部用宽条件。代价：others 和 ◂ 会多出很多误报，和已定的「画了没收」定义（NEAR）冲突。
- (c) 两个条件都留，换成两种画法。代价：多一种样式，规则数 +1。

**reviewer 推荐**：(a)。**我推荐**：(a)。「深色虚线 = 画了没收」全界面只剩一个意思，也不推翻已定的定义。

注意它和 4.15 有关：窄条件下，列表里能一下收进的情形更少，所以 4.15 的「3 下」会碰得更多。

## 5. web-loop 模板本身的问题（给 skill 维护者，不影响本次结论）

1. **finalize 拼 PAUSED 节时没检查 `converged`**（`finalizePausedBlock`），已收敛的 run 也会被写上「PAUSED」。
2. **treadmill 判据的口径对不上**：拿全局每轮新增 must 的累计数（8 → 9 → 9），去比单个 lens 自己修好的 must 数。code、func 两个 lens 整个 run 都没报过 must，修好数为 0，于是判据恒真。应该按 lens 分别统计新增数。

5. **capture 没有固定视口**：三轮分别是 1037、1600×900、1600 视口 ×1.6 倍像素。跨轮的坐标比较因此失效，r1 的截断 must 也部分来自这个视口。states 或 capture 应该写死视口。
