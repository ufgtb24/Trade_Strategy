## 0. 拍板结果（2026-11-12，用户已定）

第 7 节的六条方向已全部拍板。与下文冲突处以本节和同目录 `切换规律.md` 为准；下文已改的段落标「（2026-11-12 改）」。

1. 点 ▼（或它那一列的格）：选这一天整体（只有一次 hit 时两层合并，点下去就是那次 hit）。
2. 选中 event 后 ← / →：**不取原来的三条路**，改用用户提出、经打磨的通用规律——里面有得挑（两个以上）就进去；否则本层有得换就换到旁边；两样都没有、里面只有一个，就进那一个。八种东西、两组键（← / → 跨天、↑ / ↓ 同一天）都用这一句，逐格推演见 `切换规律.md`。
3. 停在一次 hit 上换天：落最像的那次（同一种切法）。
4. Esc：往上退一层，到头再清空。
5. 显示栏：形态 C（固定九格 + 选中卡）。
6. 点样本：只选中样本。
7. （后加）同一天那根轴的键：**↑ / ↓**，取代 Shift+← / →；左侧列表切股票从 ↑ / ↓ 改成 **PageUp / PageDown**。规律不变，只换键。

**换键（2026-11-12，用户定）**：同一天那根轴的键从 Shift+← / → 改成 ↑ / ↓，和 ← / → 对偶；左侧列表切股票从 ↑ / ↓ 改成 PageUp / PageDown（按一下换一只）。文中讲新设计的地方已统一写成 ↑ / ↓、键帽 `↑/↓`；讲现在实现的地方保留 Shift+← / → 原样。

- 为什么能换：上一轮否掉上下键的唯一理由是漏按 Shift 会切股票、选中全丢；股票挪到 PageUp / PageDown 后这个风险没有了。↑ / ↓ 目前只有左侧股票列表在用（`path2_web_ui/src/components/SidebarResultList.vue` 的 `onArrowKey`），PageUp / PageDown 没有地方用；走动键的判定集中在 `path2_web_ui/src/components/walkKey.ts`；在输入框里打字时走动键本来就不接。
- 代价：切股票的手感要重新习惯；图上同一天的几次 hit 是并成一格画的，「上下」只是概念上的方向；什么都没选时 ↑ / ↓ 不再有作用；规格 1.14 写的是 Shift+← / →，实施前一并改。
- 会话默认（待验证）：↓ = 进去（落第 1 个）或换到下一个，↑ = 上一个（进去时落最后一个）；↑ / ↓ 被接住时拦掉浏览器的滚动；顶栏股票输入框自己的 ↑ / ↓ 不变；搜索框聚焦时切股票也跟着改成 PageUp / PageDown。
- 改动面追加：`walkKey.ts`（判定与键帽字）、`SidebarResultList.vue`（切股票的键）、`WalkStatusBar.vue`（第二个键槽的键帽）、规格 1.14 与说明书的键位节。

通用规律相对原设计改了四格：event 只牵出 1 个买点日时沿 band 换到旁边那格（原为落进那一天）；没被 hit 用到的 event 沿 band 换（原为不响应）；一族、一条反馈只有 1 个买点日时换到旁边一族 / 一条反馈（原为落进去）；框的 ← / → 换到旁边的框（原为不响应）。规律自带三条后果：一个键是进去还是换旁边由数据定（键槽在按之前写明）；只装着一个的东西，从它到那一个没有键（本层唯一时除外）；换旁边时碰到里面有得挑的，下一下被带进去。规律是纸面推演，没在页面上跑过。

## 1. 直接回答

**用户问「event 族就算点横条也无法被选中，因为它只是显示简化，没有业务意义，对么？」**

- 事实：对。band 的族底线（图层 `family-lines`）在点击处理里没有分支，点了什么都不发生（`path2_web_ui/src/components/KlineChart.ts:78-108` 的 handleChartClick，只有悬停摘要）。但提示条仍会写 `event_family …`：点 band 上的一格、且用到它的 hit 只买在一天时，这一批就是 event 族（`path2_web_ui/src/stores/view.ts` focusMark），img26、img19 就是这样来的——它写的是 ← / → 走动的范围，不是选中的那一格。
- 结论：**event 族不该被选中，同意；理由要换。** 「只是画法折叠」站不住：hit 族用的是同一条折叠规则（`path2_web_ui/src/render/fold.ts` foldBand / foldHits，起点相同就并）；在 new_step 里 step 的一族恰好就是「一次阶跃」、today 的一族就是那天的买点日。能干净地拿掉它，靠的是：① 它的意思随 node 变（step 是一次阶跃、today 是买点日、plateau 是 hit 族的别名、new_plat 把一个新平台拆成两族），前端是类型无关渲染器，不能只让某几种 node 的族可选；② 凡是它恰好等于用户概念的地方，那个概念已由 hit 族或买点日承载；③ 当走动范围时它「第几天」数的是格的终点（new_plat 上比买点早一个交易日，竖线正好落在另一次 hit 的买点上），个数还随档位变（new_plat 11-22 那族 `in_hit` 下 ×11、`qualified` 下 ×39）。（`entities.md` 4.6，`challenge.md` 第一节 B、第三节）

**用户问「同日堆叠整体是否有业务意义，还是只是显示简化？」**

- **有，而且它是写反馈的单位——和用户的直觉方向相反。** 同一天叠着的几次 hit 整体就是那天的**买点日**：point 反馈只记日期、不认哪次 hit（`path2_web_ui/src/annotate/model.ts:64` 的 AnnFeedback 没有 hit 编号；feedbackClickTarget 注释「只认日子,不认是哪个 hit」）；反馈状态判 matched、样本 match、调参计数、扫描的首次穿越计数都按买点日，同一天几次只算一次。例外：扫描结果的收益统计按 hit 次数算，那是调参评估的口径，不影响写反馈、比样本、指给会话这一层。（`entities.md` 4.2，`challenge.md` 第一节 C、D）
- 用户说的「hit 买点」其实是两样交叉的东西：**买点日**（回答「这天买得对不对」）和**一次 hit**（回答「app 把这里认成了什么样子」）。一个买点日可叠几次 hit，一次 hit 可占几个买点日（bottom_burst、bb_v1 那种买点 node 的 event 跨几天时；new_step 一次 hit 只有一个买点日，所以看起来像上下级）。
- 所以「左右切到堆叠日就选中第 1 个」的前提不成立。改为分两层：← / → 在「天」这一层走，停在整天；↓ 才进到某一次。另外现状本来也不是落第 1 次，而是沿同一种切法落（sk 现场 `sk_04`：从 11-27 第 2 次按 →，落 11-29 第 2 次）；用户在 img24 看到 1/2，是因为从第 1 次出发。

**用户的判据「能附着 feedback 才有业务意义」**：作为充分条件成立，作为必要条件太窄——照它，一次 hit、一个 event、一个 node 都不算，和用户自己「每个 hit 买点肯定有意义」以及已定的规格 1.13（引擎层的查看能力「可以不看、不该没有」）、1.14（event、node 能指给会话）冲突。采用的判据：是**写反馈、指给会话、看 app 怎么认**三种用途之一的对象；再加两道筛——复制给会话时不能被它的上下级代替、它的意思不能随 node 变（`entities.md` 第 3 节）。

## 3. 选中模型

**层级**：hits 行这一侧是 一族 ⊃ 买点日 ⊃ 一次 hit；反馈、event 也可以当最外层（反馈 ⊃ 它收进来的买点日 ⊃ 一次 hit；event ⊃ 用到它的买点日 ⊃ 一次 hit）；band 这一侧是 node ⊃ event；用户这一侧是 样本 / 框 → 在场的 hit。

**点决定从哪种东西开始**：点 ▼ 或它那一列的格 → 买点日；点 hits 行族底线 → 一族（app 模式也放开，现在只有 compare 能点）；点 band 上的格 / 条 / 点 → event；点轨名 → node；点反馈记号 → 反馈；点 ▲ / 框 → 样本 / 框；band 的族底线 → 不响应、不清掉现有选中。

**两组键，任何时候同一句话**（分界只看里面装的东西怎么排）：

- **← / →：跨天，竖线会动**（2026-11-12 改，`切换规律.md`）。只看两个数：选中的东西里面装着几个沿日子排开的（一族、反馈、event 装着买点日，node 装着 event）、同一层还有没有别的。**里面两个以上 → 进去**：找竖线那个方向最近的一个，竖线那天本身有就先落它；只在落进去这一下，那个方向没有就取另一边最近的。**否则同一层有别的 → 换到旁边那个，落对应的**：买点日换买点日、一次 hit 落旁边那天最像的那次（现在的 landIndex 规则）、样本换样本、框换框；只牵出一个或零个买点日的 event 沿 band 换到旁边那格里最像的那个（优先同起点）；只有一个买点日的族、反馈换到旁边一族、一条反馈。**两样都没有、里面只有一个 → 进那一个。** 走到头停，不绕回。「同一层」= `in` 最后一节里面，为空就是整张图上的同种东西。
- **↑ / ↓：竖线不动，在同一天里进去或换**——从买点日、样本、框进到第 1 次（↑ 进最后一次）；在同一天的几次 hit 之间换；在 event 上，换这条 band 同一天结束的另几个 event。
- **Esc：往上退一层**，退到最外层再按才清空；先关反馈面板、熄工具、取消配对的顺序照旧；点空白仍一下清空。

**取消的状态**：「还没选」（`day –/n`）没有了，它其实是选中了外面那一层（一族、event 或反馈）。「两样同时当前」（点 new_plat 格时 event 和用到它的 hit 同时加粗；点 ▼ 时反馈面板说这天、提示条说其中一次；点样本时样本和配对那次 hit 同时当前）、「什么都没选却有一批」（点 step 格后，看着选中了 step，实际当前 event、当前 hit 都是空，sk `sk_02`）、「选中了却不显示」（选轨名、从侧栏跳到一条反馈、被档位筛掉的 event，提示条空白）——三种状态全部消失。

**竖线**：总停在选中物自己的日子上（买点日、一次 hit → 那一天；event → 它的终点；样本 → 样本日；框 → 框终点；一族、反馈、node → 不动）。

**走出视窗时图跟着平移**：这是**现有毛病**（sk `sk_06`：视窗到 12-03，按 6 下 → 竖线走到 12-16，提示条照写 `day 7/11`），不是新设计引入的，一并修；按键带出的平移不能触发现有的「视窗一变就关反馈面板」（`path2_web_ui/src/components/KlineChart.vue` 约 1382 行），否则写了一半的 note 会丢；用户自己拖、缩放仍照旧关面板。

## 4. 显示：按维度拆开、每维标准化（推荐形态 C「维度格栅 + 选中卡」）

先梳出「选中一个东西时用户可能想知道的」29 个维度，逐个定放在哪：栏（按键时每一步都要看）、卡（追问时才看）、悬停（只对一个格子有用）、图上（已画出来的不重复）、别处（顶栏、面板页头已有）（`design.md` 5.1）。

**栏**：副图上方一行，**九格，从左到右永远不动**：

```
kind [buy] │ node — │ date 2024-11-27 │ name — │ diff — │ in hit_family 2024-10-31 │ ←/→ buys 1/11 │ ↑/↓ into hits ×2 │ Esc
```

| 格 | 回答 | 写法 |
|---|---|---|
| `kind` | 选中的是什么（白底 2 像素黑边、字加粗，整条最显眼） | `hit_family` / `buy` / `hit` / `event` / `node` / `feedback` / `sample` / `box` |
| `node` | 对应的 node | event 所在、node 本身、框经 mapping 对到、反馈点出的 |
| `date` | 哪天 / 哪段 | `YYYY-MM-DD` 或 `起→止` |
| `name` | 用户那边的叫法 | 样本 `字母 判断`；框、node 写特征名 |
| `diff` | 同一天叠着几个时它和别的差在哪 | `node→YYYY-MM-DD`（现成的 first_diff） |
| `in` | 属于什么（走进来的路径，末节 = Esc 退到哪） | 身份用 ` › ` 由外到内连 |
| `←/→` | 按 ← / → 去哪、第几个 | `buys k/n`、`samples k/n`，2026-11-12 加 `events k/n`、`hit_families k/n`、`feedbacks k/n`、`boxes k/n`；落进去 `into buys ×n`、`into events ×n`（只有一个时 `×1`） |
| `↑/↓` | 按 ↑ / ↓ 去哪、同一天第几个 | `hits j/m`、`events j/m`；落进去 `into hits ×n` |
| `Esc` | 键帽；悬停写退到哪 | 不参与截断 |

**用户点名的四件事各落在哪**：选中什么 = `kind`；属于什么 = `in`；切换的工作范围 = 两个键槽（范围名词 + `k/n`）；**包含什么不单独占一格**，由键槽的 `into buys ×n`、`into hits ×n`、`into events ×n`（按了会落进它装着的几个）和卡的 `buys`、`hits`、`nodes` 三行承担。

**卡**：右侧栏 `selection` 页顶上，十一行、行序固定：`buys`（牵出的买点日）、`hits`（牵出的 hit，跨两族以上接 `families ×k`）、`nodes`（一次 hit 的组成）、`family`（结构上的那一族）、`feedback`（盖住它的反馈、状态、原因标签）、`sample`（相关样本与 ✓ / ✗）、`paired`（配对的另一方）、`level`（档位）、`failed`（没过的 where）、`id`（编号）、`copy`（Shift+C 会复制的全文）。「这一处买得对不对」（反馈状态、样本对没对上）在卡里常驻。

**统一写法**：一天 `YYYY-MM-DD`；起止 `起→止`；一组日子 `首…尾 ×n`；第几个 `k/n`；个数 `×n`；身份 `kind node date name`；键槽用被走那一组的复数名词（`buys`、`hits`、`events`、`samples`，取代 `day`、`same_day`、`in_set`）。**不适用：格子照占、写灰色 `—`、键帽画灰**（灰约 RGB(107,112,120)，浅灰底上对比约 4.4 : 1）；**适用但空：黑字 `none`**——用户分得出「这种东西没有这一维」和「这次没有」。什么都没选时九格全灰 `—`。

**宽度**：用户屏幕上提示条实测 1596 px、约 218 个等宽字符（dpr 2）；九格固定宽约 176 字符，`in` 实得约 42。窄时依次省：`in` 从最外一节换成 `…›` → `name`、`diff` 截成省略号 → 标签挪进悬停；`kind`、`date`、两个键槽、`Esc` 永远不省。日期不在中间折断。

**为什么推荐 C 不推荐 B**（`design.md` 5.4）：用户第三次追加定的方向是「按维度拆开、每个维度标准化」。A（单行混写，只改内容）的选中块是一句话，日期位置随种类变；B（标签贴着竖线）答案在选中物正上方、按键不用挪眼睛，但位置跟着竖线和种类挪，违背「同一维度永远在同一位置」。C 是唯一三条都满足的：一格一维、位置不随种类挪、写法统一。C 的代价：按键走动时要把视线挪到条右端读键槽；栏里常有几个灰 `—`；compare 下右侧栏的样本那块被选中卡往下推。

**用户四个现场在 C 下的样子**（`design.md` 5.5 逐字）：
- img24 点 11-27 的 ▼：`kind [buy] … date 2024-11-27 … in hit_family 2024-10-31 │ ←/→ buys 1/11 │ ↑/↓ into hits ×2`；↓ 后 `kind [hit] … diff step→2024-11-21 … ↑/↓ hits 1/2`。
- img25 点 step 那格：`kind [event] │ node step │ date 2024-11-21 … in node step │ ←/→ into buys ×11 │ <↑/↓> —`；按 → 落进 11-27（`buys 1/11`），即上一轮用户要的 1/11、2/11。
- img26 点 new_plat 起于 11-22 那格：`kind [event] │ node new_plat │ date 2024-11-22→2024-11-26 … ←/→ events 1/n │ ↑/↓ events 1/2`（2026-11-12 改：它只牵出一个买点日，按 → 是沿 band 换；同一天另有一个起于 11-25 的 new_plat 也终于 11-26）。
- img19（在 new_plat 上按 → 想看平台再长一天）（2026-11-12 改）：按 → 沿 band 换到下一格，落同一个起点的那个：`kind [event] │ node new_plat │ date 2024-11-22→2024-11-27 … ←/→ events 2/n │ ↑/↓ events 1/2`。选中的仍是 event，竖线停在它的终点（终点 11-27 取自 sk 现场记录：现在第 2 步竖线落在格的终点 11-27），用到它的那次 hit（买在 11-29）只画细框。

**图上**：粗框只给选中的那一个；路径上的外层用它自己的「在用」样子；和它有关的加细框（`design.md` 第 4 节）。band 格悬停去掉 `day k/n`，成员只数 event（修现状把 event × hit 条数当成 m 的错，`entities.md` 第 2 节末第 4 条）。

## 5. Shift+C：所选即所复制

拼法：`股票 pattern` + 栏的前五格（`kind node date name diff`，跳过 `—`）+ 卡的 `buys`、`hits` 两行 + `[编号]`。行里不写 `k/n` 这类位置号。例（CRNC）：

- 买点日：`CRNC new_step buy 2024-11-27 hits ×2`
- 一次 hit：`CRNC new_step hit 2024-10-31→2024-11-27 step→2024-11-21 buys 2024-11-27 ×1 [hit 编号]`
- event：`CRNC new_step event step 2024-11-21 buys 2024-11-27…2024-12-26 ×11 hits ×11 [event 编号]`（「被几次 hit 用到、买在哪段」并进 event 行；规格 1.14 定会话只靠行内文字定位，不配脚本）
- 一族：`CRNC new_step hit_family 2024-10-31 buys 2024-11-27…2024-12-26 ×11 hits ×22`
- 什么都没选：`CRNC new_step day 2024-11-29`

`path2_web_ui/src/annotate/copyRef.ts` 头注释现有 14 种行：留 9 种（多数按统一拼法重排）、砍 5 种（`hits buy DAY ×m <这一批>`、`hits_using …`（并进 event 行）、`events NODE …`、`event_family …`、`hits sample_day / box_end …`），砍掉的都能由留下的某行代替（`design.md` 第 7 节逐行表）。判「当前指的是哪样」的优先级逻辑（resolveTarget、lastPick）随之简化：只有一份「选中」，栏、卡、复制都读它。

## 6. 代价（相对现在的方案 B，`design.md` 第 8 节）

失去：① 点 ▼ / 那一列的格不再直接落定一次 hit，要看某种切法多按一下 ↓，推翻 spec 5.8 当天定的「▼ 点下去总是落定一次」，compare 里 new_step 没有鼠标直接点到某一次的地方；②（2026-11-12 改）沿 band 走只对牵出一个或零个买点日的 event 有，从这样的 event 到它那一天没有键；③（2026-11-12 改）换旁边时碰到里面有得挑的会被带进去，要越过它用鼠标点；④ Esc 不再一下全清（从 step 进到的那次 hit 要按四下，或点空白）；⑤ Shift+C 砍 5 种行，样本、框不再和当前那次 hit 写在一行；⑥ 点 band 格不再顺带选中用到它的 hit，点样本不再顺带选中配对那次（组成改细框，↓ 进去才加粗）；⑦ 反馈记号的粗边与竖带不再「点了别的也一直留着」；⑧ 栏常驻九格、常有几个灰 `—`。

多出：一眼看出选中什么；买点日（反馈与判断的单位）一下选中、一下复制，和弹出的反馈面板是同一样东西；（2026-11-12 改）点 band 格后选中的始终是那个 event；按 ← / → 是落进买点日还是沿 band 换仍由数据定（和现在跨天走 `hits_using`、不跨天走 `event_family` 的分法相近），但现在点之前看不出、提示条第一格还换名字，改后键槽在按之前写明；一族在 app 模式也能点；竖线不再停在别的 hit 的买点上；同一样东西永远复制同一行；少 `event_family`、`in_set`、`hits_using` 三个界面名。

改动面：选中模型（`stores/view.ts`、`render/walk.ts`）、显示栏重写（`components/WalkStatusBar.vue`）、新增右侧栏选中卡与一个「从选中算出九格十一行」的纯函数模块、键盘与 Esc 链与平移（`components/KlineChart.vue`）、点击分流（`components/KlineChart.ts`）、画法与悬停（`render/chart.ts`）、复制（`annotate/copyRef.ts`、`stores/copyRef.ts`）、`stores/compare.ts`、`stores/feedback.ts`、`DetailSidebar.vue`、`SampleDiagnose.vue`，以及对应单元测试与 5 份 e2e；批准后同步改 spec 1.14、5.8、6.13，manual 复制指代与键位两节（文件清单见 `design.md` 第 8 节末）。

## 7. 交用户拍板的方向（`design.md` 第 10 节，按要紧程度）

> **2026-11-12 已全部拍板，结果见第 0 节。** 第 2 条没取下面三条路，改用通用规律。下面是拍板前的原文，留作经过。

1. **点 ▼（或它那一列的格）选中什么。** 推荐**这一天整体（买点日）**：反馈面板、显示栏、复制说的是同一样东西；代价是推翻 spec 5.8 当天定的一句、看某种切法多按一下 ↓。备选：这天的第 1 次 hit（现在的做法、用户的原提议）：少按一下，但一次点击两样当前。
2. **选中 band 上的一个 event 后 ← / → 走哪**（在决定：从 event 出发，按键是去看「它让 app 在哪些天买了」，还是「这条 band 上的下一个 event」）。三条路：
   - 推荐：**落进用到它的买点日，没进任何 hit 的 event 不响应**。点 step 后按 → 就是 1/11、2/11，Esc 一层层退回，全程键盘；代价：不能沿 band 逐格走、同 band 别的 event 只能点、上一轮第 10 个用户任务（沿同一行看没进 hit 的 event）没了。
   - 同上，但没进 hit 的 event 沿 band 走：接住那个任务；代价是同一个键的意思随数据变（键槽里会写出来）。
   - 一律沿 band 走：任何 event 都按得动、同 band 的 event 键盘都到得了；代价：从 event 到它的买点日没有键，位置随档位变、几族混走。
   - 两条主路在「只用键盘能不能选到」上各缺一块，lead 判为打平（`design.md` 第 12 节对比表）；三名 teammate 都倾向第一条。
3. **停在一次 hit 上按 ← / → 换天落哪一次**：推荐同一种切法的那次（现在就是这样）；备选一律第 1 次（更好预测，但粗框可能在两种切法间跳）。
4. **Esc**：推荐往上退一层、到头再清空；备选一下全清（现在）。
5. **显示栏形态**：推荐 C 维度格栅 + 选中卡；备选 B 标签贴竖线（按键不挪眼睛，但违背「同一维度同一位置」）。
6. **点样本选中什么**：推荐只选中样本（↓ 才进配对那次）；备选样本和配对那次同时当前（现在）。

## 8. 不依赖方向选择、现在就存在的毛病（实施时一并修）

1. 按键走出视窗时图不平移，选中物可在画面外（sk `sk_06`）。
2. band 一格「叠着的」个数按 event × hit 拆：CRNC today 11-27 那格只有一个 event，提示条写 `same_day 1/2`，复制成 `events today 2024-11-27 ×2`（`entities.md` 第 2 节末第 4 条，现场证实）。
3. 点被几天共用的 event（step 那格）后它其实没被选中：黑粗框画在 step 上、当前 event 为空；按 → 之后 step 本身复制不出来（sk `sk_02`）。
4. 点 new_plat 那格时 event 和用到它的那次 hit 同时加粗，复制只给 event（sk `sk_03`）。
5. 选轨名、从侧栏跳到一条反馈、被档位筛掉的 event：选中了，提示条却空白。
6. `hits_using` 只记点中的第一个 event，一格并着几个时名字与编号只写第一个（`view.ts` 约 877-880 行）。
7. app 模式下 hits 行族底线不接鼠标，整族只能连按 Shift+C 拿到。

## 9. 不说明什么

- 是设计，不是原型：键位、落点、平移、卡片的手感都没在真页面上试过；样张是静态页（sk 用终版重新渲染核过版式：十行九格不截、不溢出、左边界对齐，`repro/screenshots/sk_17_mock_final_*.png`；什么都没选且没有面板 / 工具 / 配对可退时 Esc 键帽画灰，是终验前最后一处补改，也在终版里）。

- compare 下真点 ▼ / 族底线会弹反馈面板，为免写入标注没有真点；相关结论来自代码与选择函数驱动。
- step 那条 band 在当前档位下画出几个 event（`into events ×n` 的 n）没数；样张里标「示意」的格子是按规则推的形状。
- （2026-11-12）通用规律是纸面推演，未经 sk 走查、没在页面上跑过；别的 app 上同一条 band 混着「牵出一天」和「牵出好几天」的 event 时走起来顺不顺没看过。静态样张 `repro/walkbar_mock.html` 仍是旧规则，没重做。白话版是就地修补，不是重跑。
