# 原始问题（2026-10-30，用户经 /agent-team 提出，逐字记录）

假装现在已经开发完标注工具，现在要教会一个新用户如何使用的视角，写一份说明书。
需要通俗易懂，告诉用户每个功能在整体中的作用，为什么而服务，用了这个功能，用户能什么事。所谓功能作用，我希望说明书不要沉湎于这一步是做什么，而要和找到 pattern 的终极任务关联，让用户不仅明白某操作的‘作用’，更了解这个操作在整个工作流中的‘意义’。
这份说明书会为接下来项目的开发提供一个宏观视角。在后期的决策中，其优先级高于现有的原型代码。
除了说明书本身，还要形成 final_report。
说明书的撰写可以参考现有原型：
- 如果发现现有原型中的某些功能无法兑现说明书中的承诺，那么可以提出修改或增加功能的方案， 同样记录于 final report 中。
- 如果发现现有原型的某些功能不能解释其存在的‘意义’，则在说明书不写原型中改功能，并且把这个冗余功能记录到 final_report 中。
说明书的撰写风格是白话版。 需要体现标注工具的强大。给用户留下好印象。同时也要有严谨的逻辑性，说明功能为什么要这样设计，让用户在使用时知其所以然。
假设目标读者是很了解 path2 框架的。
