# label 两个视角的第一性原理论证（label-strategist 产出）

> 状态：草稿，待 evidence-auditor / automation-analyst 事实核实后定稿。
> 任务：裁定 label 接下来怎么开发（方向性 vs 收益性）。

## 锚定事实（一手材料核实）

- **mfr 实现**（`path2/eval.py:16-44`）：买点窗 [start_idx,end_idx] 逐进场日 t，`max(high[t+1..t+N])/close[t]-1` 取均值。只用 high，不惩罚回撤。
- **score 口径**（`docs/research/pattern_config_scoring_standard.md`）：`score = w·lift`，`lift = median_配置 − median_基线`，`w=n/(n+200)`；排序用 `median_confirm`（只取买点窗首日）；基线 = bo_only；硬门 n≥200 且 q25≥0。
- **§9 明言**：label 系统性上偏，"适合相对比较，不适合绝对承诺"。→ mfr 被接受的身份是"配置间相对比较的尺度"，不是收益预期。
- **§0 裁定**（`feedback.md`）：pattern 职责 = "确定未来存在上涨驱动力"；赚钱是交易层。止损止盈期望值**完全移出 score**，理由是参数耦合 ⟹ 评的是「pattern+交易参数」联合体 ⟹ 分数下降时分不清改哪层 ⟹ 失去迭代方向。波动率归一化降级为披露项。
- **g 项实测**（final_report A.1）：score 与命中集波动率倍数 `R²=0.919` → mfr 实际量的是波动率，不是方向优势。bo_only 控制波动率后 +72% 抬升**完全归零**（0.513/0.501）。
- **c 项实测**（final_report A.1 / feedback 疑问 2）：首次穿越 ±X%，pattern 在 8 个（年×阈值）单元里 7 个"先涨比例"低于随机日；上行抬 +10.6 点、下行压深 −11.2 点，**两边对称**，而 mfr 只数上行那一半。

## 逐条论证

### Q1. label 根本作用：方向性预测 vs 收益变现？

**label 根本作用 = 度量 pattern 职责是否尽到 = 度量"上涨驱动力是否存在" = 方向性预测能力。** 收益变现不在选股评估射程内。

这不是随意切分，背后是一条硬约束——**因果归因的可分离性**。§0 的论证是结构性的：尺子一旦含交易参数，它评的就不是 pattern 而是「pattern+交易参数」联合体；同一 pattern 配不同止损值得分不同 ⟹ 分数下降时无法定位该改 pattern 还是改交易 ⟹ 两层各自失去独立迭代能力。所以"选股评估不碰收益"不是妥协，是维持迭代能力的必要条件。

推论：任何把交易参数引进 score 的 label（含模拟交易 label）都违反这条，不论它多"真实"。

### Q2. 怎么设计"对称方向 label"？哪种最纯？

方向预测的本质 = "买点之后价格往哪走" = 符号（对不对）+ 幅度（够不够）。三个候选：

| 候选 | 量什么 | 利弊 |
|---|---|---|
| **(A) close 端点收益** close[t+N]/close[t]-1 | 持有到期结果 | 对称，但**违反已声明语义**：§3 前置声明"兑现由独立卖出程序负责、允许回撤到买入价以下、期末为负不指控 pattern"。A.1 用户异议正是用持有到期当替代口径被驳回的实例。量的不是 pattern 职责。 |
| **(B) max_up/max_down 对称幅度** | 双向幅度对称度量 | 仍是幅度类，受波动率污染；A.1 实测 pattern 选的股双边对称（+10.6/−11.2），对称幅度组合可能相互抵消、反而掩盖"方向其实不对"。 |
| **(C) 首次穿越方向比例** | 只问方向符号 | **最纯**：与波动率解耦（c 项不做波动率控制，独立于 g）、不受幅度偏斜影响、秒级、与持有期无关。缺点：丢幅度。 |

**最纯地量"方向预测"的是 (C)**。理由：方向预测里**符号是前提**——符号都不对（先跌多于先涨），幅度再大也是噪声（g 项已证幅度类度量主要被波动率解释）。(A) 量错对象，(B) 会被对称性抵消掩盖问题，只有 (C) 直接回答"看对方向了吗"。

但 (C) 只回答符号，不承载幅度。所以方向性 label 应**分层**：
- 一级（**闸**）：首次穿越方向比例 — 符号对不对（c 项已有逻辑）
- 二级（**度量**）：对的方向上幅度有多大 — 但这又回到 mfr 的波动率污染问题

关键洞察：**现行框架已经是"方向闸(c) + 幅度度量(mfr)"两层**。问题不在分层，在于 mfr 作为幅度度量被波动率污染（g 项）。所以"对称方向 label"的真正缺口不是再造一个，而是——

**(C) 应从"体检闸"提升为"一等 label"**：与 mfr 并列、进 score 候选，作为"方向纯净度"度量。final_report §1.2b 实测"换'最大不利偏移深度'度量就分辨得动"，正是方向类度量天然带分辨力的证据。

### Q3. 模拟交易 label 属选股评估还是交易评估？怎么和 §0 调和？

**属交易层评估的雏形，不是选股 label。** 它评的是"在这个 pattern 的买点上套一组固定交易规则能赚多少" = pattern+交易参数联合体。

用户"端到端训练选股+交易两模型"的类比，在机器学习意义上成立（联合优化），但 §0 的论证恰好是它的反命题：**不能端到端**，因为 (1) 归因不可分离、(2) 可调交易参数会把优化循环引向"调止损"的梯度捷径而非"改 pattern"。

调和方式（与 §0 不冲突）：
- **不进 score**（不作自动优化反馈依据）—— §0 红线
- **作为披露项 / 诊断对照** —— 与波动率倍数、价格分布并列，报数不判定
- **服务 plan 工作流（人为）**：web ui 上让用户对照 mfr vs strategy_return，暴露"mfr 漂亮但模拟亏钱"的 XAGE 式陷阱

这正契合已存在 plan（`2026-07-30-strategy-return-label.md`）的设计：checkbox 默认关、最小展示。它在**展示层**服务人，不在**评分层**服务自动循环——与 §0"移出判定链"一致（§0 移出的是判定链，没说不算不看）。

**⚠ plan 背景核实（git log）**：该 plan 无独立 commit 历史（随 `181b7d9 clean docs` 进入）、无对应 spec 文件、顶部 Goal/Architecture **未引用 §0、未声明"不进 score"**。其技术设计（checkbox 默认关、前端展示列、不碰 score 公式）**恰好符合**展示/披露定位，与 §0 不冲突——但 plan 缺一个显式红线声明。⟹ **P1 实施时必须补一句**：strategy_return 仅作展示/披露，永不进 score、不作自动优化反馈依据；否则未来维护者会因它"更真实"而接进 score，重蹈 §0 耦合坑。这是 plan 当前唯一的实质缺口。

### Q4. "mfr 既不满足方向性也不优化收益性"——对吗？

拆两半：

- **"mfr 不满足方向性"——对，且是真缺陷。** mfr 只数上行（max high），A.1 实测 pattern 选的股上行+10.6/下行−11.2 对称，mfr 只数上行那一半 ⟹ 把"双边躁动"读成"单边驱动力"。用户质疑**不是混淆**，是戳穿 mfr 作为"方向性度量"的不合格。
- **"mfr 不优化收益性"——对，但这不是缺陷，是设计边界。** §0 + scoring_standard §9 明确 mfr 是"相对比较尺度"非"收益预期"。要求它优化收益性 = 要求它做它被明确排除的事。

综合：用户这句话**对一半**。真正的发现是：mfr 连它被赋予的职责"上涨驱动力度量"都没尽到（g 项 R²=0.919，量的是波动率）。所以问题不是"mfr 该不该优化收益"，而是"mfr 作为方向/驱动力度量本身不合格，需要纯净的方向 label 补位"。

### Q5. 双 label 是正确方向吗？

是，但两者定位不同、服务层不同、优先级不同。不是"二选一"，因为回答不同问题：

| label | 回答什么 | 服务工作流 | 进 score？ |
|---|---|---|---|
| **对称方向 label**（首次穿越提升版） | pattern 看对方向了吗（选股职责） | feedback（自动，修尺子后重算 ρ_rel）+ plan（人为诊断） | **候选**（替代/并列 mfr） |
| **模拟交易 label**（strategy_return） | 套固定规则能变现吗（交易层诊断） | plan（人为，对照 mfr 暴露陷阱） | **绝不**（§0 红线） |

红线（来自 §0 + §8.3）：**两者不能同时进 score 当自动反馈依据**，否则重蹈"联合体、归因不可分离"。模拟交易 label 必须止步于展示/披露。

### Q6. 开发优先级

> **必须先讲清的关键区分（读 `05_opt_methodology.md` §10.1/§10.6 后修正）**：
> final_report §10.1/§10.2 **判死了"改 label 口径能救现任 pattern"这条路**——现任 pattern 在方向上没有优势（首次穿越 7/8 单元不及格、整个突破族先涨比例 0.46~0.53 接近无信息），换任何 label 口径都改变不了**这是 pattern 的属性**。
> 但 §10.6 行 681 同时建议：**把首次穿越比例作为任何新 pattern 的一等验收指标，与 score 并列**——因为它便宜、不受 max-high 上偏影响、直接回答"看不看得对方向"。
> ⟹ **这两件事不矛盾**：判死的是"现任 pattern 还有没有方向救药"（没有），支持的是"建设方向尺子让评估对现任和未来 pattern 都诚实"（要建）。下面的 P0 属于后者，**不是"修尺子让现任 pattern 变好"**。

**P0 — 对称方向 label（首次穿越方向度量落地为一等 label）**
1. 它是 final_report §10.6 已有建议的落地，不是新发明。定位三重：
   - **分诊第二把尺子**：§1.2b 强制 ρ_rel≈0 要先分诊，分诊要"换替代度量重算 |z|>2 占比"；方向类度量正是 final_report §1.2 实测"分辨得动"的那类（"最大不利偏移深度"分辨得动 ⟹ 方向/顺序类度量天然带分辨力）。落地后可重算 ρ_rel、决定档位是否从"闸阵"升级。
   - **一等验收闸**（§10.6）：未来任何新 pattern 都须过方向检验，否则只是"换一种波动率选择器"。
   - **web ui 展示列**：服务 plan 工作流，让人一眼看到"方向对不对"。
2. **成本可控**：首次穿越逻辑设计已成熟（§9.5：四档阈值 5/8/10/15%，[t+1,t+20] 内首触 high≥c0(1+X) vs low≤c0(1−X) 比较先后，同根 both 排除），第二轮已跑过（约 4 分钟/年）。脚本是否进版本控制待 evidence-auditor 核实（repro 目录未见独立脚本，可能在 opt2_collect.py 内或随 temp_code 删除）；即便不在，按 §9.5 描述复现成本低。
3. **不立即替代 mfr 进 score**：先作分诊尺子 + 验收闸 + 展示列。是否升级进 score，等 ρ_rel 重算结果再定（避免重蹈"一把被证伪的尺子"覆辙）。

**P1 — 模拟交易 label（strategy_return，按现有 plan 实施）**
1. 已有完整 plan（`2026-07-30-strategy-return-label.md`），技术风险低。
2. 服务 plan 工作流：让用户在 web ui 对照 mfr vs strategy_return，暴露"mfr 漂亮但模拟亏钱"的 XAGE 式陷阱。
3. **严格止步于展示/披露，不进 score**（§0 红线）。

**不做 — 把模拟交易 label 进 score**：违反 §0，重蹈"参数耦合 ⟹ 归因不可分离 ⟹ 失去迭代方向"。

核心逻辑：**P0 补齐尺子让评估诚实（不是为了救现任 pattern，它已判死），P1 加诊断工具服务人为分析**。两者并行不悖，服务不同工作流、不同层。

## 队友核实后的修正与定稿（2026-07-30）

### 载重事实采纳（evidence-auditor `fact_pack.md`）
- **label_horizon 不一致**：yaml=40（生效）vs config.py=20（fallback）⚠ live 小坑，leader 知悉。
- **live scan 只注入 mfr 展示、不算 score**；score 只 offline/repro。
- **§0 顺序闸（用户第1条，非对称首次穿越）grep 零命中、未实现**，仅提案 ⟹ P0 落地的具体缺口。
- **strategy_return plan 是 §0 移出的"止损止盈期望值"、晚于 §0**；XAGE e2e 演示两把尺子相反 = §0 警告的耦合微观缩影。

### 核心修正（automation-analyst A/B/C 裁定后）
- **A. 任何 label 都不该是 hands-off 可攀爬目标**。根因不是 label 不够好，是"无人监督的标量最大化"范式与"pattern 是语义结构"根本不兼容——mfr→波动率（R²=0.92）、首次穿越→同根率/高波动先冲偏好、strategy_return→跟踪止盈偏好高波动，任一标量 maximize 都找免费通道。把 c 项改造为 maximize 目标会换通道（同根桶 pk4 23.9% vs bo_only 9% 本身是波动率）。例外仅"结构严格限定 + label 诚实 + 配闸阵的有监督搜索"（§11 后门），当前 bbb 不满足。
- **B. §0 label 组合作人为反馈够格**（机制=揭示改动后果，非给改方向）；前提是顺序闸必须落地 + lift 作用域被收窄。
- **C. bo_only 基线无方向信息 ⟹ mfr-lift 量的不是方向优势**。但不推翻 lift 当反馈，**收窄其作用域**：lift 只答上行捕获增量，方向优势只靠独立方向尺子。基线问题转化为"为何需要独立方向 label"的正面论据。
- **双 label 最终定位（Q4/Q5）**：mfr（上行捕获）+ 方向比例（方向对不对）+ strategy_return（带止损下场）= 三列对照，**都是人为诊断对照列、都不进 hands-off 自动 score**。"一把尺子"约束的是可攀爬目标——既然不该有 hands-off 可攀爬目标，多列对照不违反它。
- **strategy_return plan 处置**：不砍（展示层设计与 §0 相容）；唯一缺口是必须补红线声明"仅展示/披露、永不进 score"。XAGE 两把尺子相反恰是 plan 价值（揭示 mfr 偏置），不进 score 则"相反"是 feature。

### P0 形态细化（二次定稿 · 含 evidence-auditor Q2 修正 + automation 护城河）
方向 label（首次穿越）= **否决闸 + web ui 对照列**，含实现 §0 未落地的顺序闸（用户第1条）。

**⚠ 度量对称 vs 阈值非对称（关键辨析，贯穿 Q2/Q5）**：
- 用户"方向性视角要求正负对称" = **度量对称**：涨和跌都进 label（修正 mfr 只数涨）。这是方向性视角的核心诉求。
- 但 §0 顺序闸明确"**必须非对称**：先跌 a% vs 先涨 b%，a<b"，批评"对称版（±5%）测不会被使用的规则"。即**阈值**要非对称（反映止损窄止盈宽的真实交易心理），a/b 由用户一次性声明（风险偏好，非搜索参数）。
- 两者不矛盾：方向 label = **度量对称（涨跌都看）+ 阈值非对称（a<b）**。mfr 的错在度量不对称（只数涨）；§0 进一步要求阈值别用对称 ±X%。
  - **诚实标注（evidence-auditor 指出）**：「用户方向性视角正负对称 = 度量对称」是 label-strategist 的**意图解读**，非已证事实。依据是用户两处原话——方向性视角「平等考虑涨跌」⟹ 度量对称、§0 line 41「a<b」⟹ 阈值非对称；合并有原话支撑，但"用户本意确是如此"属解读，**最终需用户确认**。§0 顺序闸机理本身（赛跑式同时考虑涨跌两向 + 屏障距离非对称）evidence-auditor 已核实为事实。
- **§0 在此推翻了 final_report §3 c 项**（c 项写对称 ±X%，§0 判其测不会被使用的规则）。

**现成基建（evidence-auditor 核实）**：`opt2_collect.py:70 _labels` 的 fp 存在且可复用（未被 temp_code 清理），但实现的是**被 §0 否决的对称版** ±X%；落地需改非对称 a≠b。同函数算出的 mh20/cc20/mae20 也都在 repro、未进 live/skill。

设计要点：
- **阈值非对称 a<b**（用户声明，非搜索）；可报多档 (a,b) 保跨轮可比，但 a、b 是人设常数，显式承认。
- **方向比例 vs 随机日**（非 candidate 排名），整条曲线非单点。
- **同根命中桶规模作披露项**（pk4 23.9% vs bo_only 9% 本身是波动率证据）。
- **否决闸，不可攀爬标量**；机制守护（automation 红线）：**排序函数签名不接受方向 label 当键**（§8.2 律②不可表达），防它偷变第二把尺。
- **live 计算路径需新建**：方向闸/confirm 口径都不在 live（score/median_confirm 只在 repro `opt2_null.py` + scoring_standard），不能直接复用 `match_forward_returns`（它返回窗均值）。

**叙事护城河（automation）**：P0 别挂"解自动循环停滞"——停滞主因在 pattern 不在尺子（§10.1 方向问题 + §1.2b 尺子问题两条独立证据），label 修复只让评估诚实、解不了 pattern 没方向。P0 价值落在 manual 工作流 + 未来 pattern 验收（§10.6：新 pattern 须过方向闸才算数）。

成本：fp 逻辑第二轮跑过（约4分/年），改非对称是小改；live 落地是新增计算路径（中等）。

### 不变（一手材料已扎实）
- **Q1** label 根本作用 = 方向性预测能力；收益变现不进选股评估（§0 结构性硬约束，非妥协）。
- **Q2** 对称方向 label 最纯候选 = 首次穿越方向比例（close 端点违反已声明语义、max_up/down 对称幅度被双边对称抵消掩盖）。
- **Q3** 模拟交易 label 属交易层雏形；§0 调和 = 展示/披露不进判定链。
- **Q4 一半** mfr 不满足方向性 = 真缺陷；"不优化收益性" = 设计边界非缺陷。
