# 普通买入、固定 bo 与随机窗口的计算优化

日期：2026-10-02。所有项目内路径均相对 repo root。原始任务见同目录 `原始问题.md`；原始计时和误差见 `baselines_results.json`。

## 结论先行

本轮用合成状态做了实际 5000 只股票、504 个交易日的计算，没有读取真实行情。普通买入对照不需要在每组 Optuna 参数下重新扫描全池：先按日期和固定波动档位保存各方向的数量，每次只按候选买点的日期、档位分布重新组合。合成实验中，36 个候选的方向汇总从 0.337 秒降为 0.0109 秒；这是一个汇总模块的时间，不是完整搜索时间。

固定 bo 对照的 200 个窗口成绩可以提前计算一次。随机窗口的数量由每日累计数量相减得到，窗口有重叠或重复都不影响该计算。上述优化不减少股票池、不减少候选买点，也不抽样近似全池；整数计数保持一致，普通对照的小数配比出现了约万亿分之一以下的方向比例舍入差。

不应把这个结论扩大到空间中位数、可信度校正或者旧版股票重抽。它们保留了什么信息、如何计算，需要分别处理。

## 1. 被优化的定义

每个可评价股票日只有一个唯一行号。方向是新设计的收盘穿越标签：`up`、`down`、`none`；本实验直接生成这三个状态，不运行价格穿越代码，也不检验哪个评价口径更有市场意义。计算约定仍为 `up / (up + down)`，同时完整保留 `none` 数量。如果将来把未触线加入方向评分，三个数量仍足够重新计算，但本报告的方向数字不代表该新公式。

普通买入包含当日全池，也包含 pattern 自己命中的股票，不以排除这些股票为前提。每个日期的波动分档先在全池固定，候选不会重新划分档位。候选只改变每组应有的权重。

固定 bo 使用它自己在窗口内的买点，不强制匹配候选买点的日期和档位。因此固定 bo 的窗口值不随候选改变。如果将来改为与候选完全匹配的 bo 对照，就必须重新配比，并处理候选所在组没有 bo 买点的情况；不能继续把整个 bo 对照视为候选无关。

200 个窗口各为一个 21 交易日的连续窗口，起点随机、有放回，同一批窗口供全部候选使用。每个窗口独立得到方向计数与比例，再交给上层评分；不能把所有窗口数量相加后只算一个比例，替代“逐窗口计算、外层取中位数”的设计。

## 2. 为什么可以先按组汇总

令一个组是一个确定日期、一个固定波动档；组中全池股票日数量为 `n_g`，候选命中数量为 `c_g`，全池该组上穿、下穿、未触线数量分别为 `A_g,k`。

逐行方法给组内每只股票相同权重 `c_g / n_g`。因此一个状态的加权数量可直接改写为：

```text
组内逐股票相加：Σ股票 [c_g / n_g × 该股票是否属于此状态]
                  = c_g / n_g × A_g,k
```

这不是估计近似，而是先后求和顺序不同。预先保存 `A_g,k / n_g` 后，每个候选只需：

```text
候选各组命中数 = 对候选唯一行号按日期、档位计数
普通对照每日状态数量 = 当日各组 (候选命中数 × 全池该组状态比例) 相加
候选每日状态数量 = 对候选唯一行号按日期、方向计数
分别建立每日累计数量
窗口数量 = 窗口末端累计数 - 窗口起点累计数
窗口方向 = 窗口上穿数 / (窗口上穿数 + 窗口下穿数)
```

必须先组合数量、再计算方向比例。直接平均各组 `up / (up + down)` 会在各组未触线比例不同的情况下改变答案。匹配后的普通对照总权重等于候选真实股票日总数；本实验逐窗口也核对了这一点。

组内仍按股票买点日计数；一次命中多只股票的日期可以在窗口内部贡献更多数量。优化没有偷偷改成日期等权。外层窗口等权是另一层规则。

## 3. 复杂度与数据结构

记 `N` 为全池股票日数，`C` 为候选唯一股票日数，`D` 为日期数，`G` 为波动档数，`W` 为窗口数，状态数固定为 3。

| 步骤 | 何时执行 | 数量级 |
|---|---|---|
| 全池波动分档、唯一行号与分组编码 | 数据及评价定义固定后一次 | 需遍历全池，本次包含实际分位切点计算 |
| 全池方向分组计数 | 一次 | `O(N + D×G)` |
| 固定 bo 的日计数和窗口计数 | bo 规则及窗口固定后一次 | 已有 bo 买点时 `O(C_bo + D + W)`；不含 bo 检测 |
| 每候选计数、普通对照配比与窗口结果 | 每次 trial | `O(C + D×G + D + W)` |
| 原逐行配权后按日汇总 | 每次 trial | `O(N + C + D + W)` |

两种对比方法都已经使用 NumPy 和累计数量，本实验没有故意选择 Python 逐股票慢循环作为参照。组汇总的进一步收益来自消除每个 trial 对 `N` 条全池行的遍历。

5000×504 时，全池共 2,520,000 行；日期×档位只有 2,520 组。三个状态的 `int64` 分组数量表是 60,480 字节，组大小表 20,160 字节；提前保存三态比例另占 60,480 字节。固定 bo 的 200×3 窗口数量是 4,800 字节。

这些小表不等于全部数据存储需求。实验同时保留逐股票日状态 `int8`（2,520,000 字节），日期、组、日期状态整数编码等数组，以支持候选查找和独立核对；其中某些编码可以按具体布局省去。旧版相关性检查、逐股票重抽、错误定位或未来评价扩展可能仍需股票维度，不能只留下小表并删除明细。

## 4. 实测结果

设备为 Intel Core i7-14700KF，Linux x86_64，Python 3.12.12，NumPy 2.2.6。所有数学库线程设置为 1；计时进程持有 `/tmp/v3-compute-optimization-bench.lock`，避免本团队同时计时。没有 JIT，故无首次编译成本；每种汇总方法暖跑一次，再按固定顺序完整运行 36 个候选，重复 3 轮。以下时间未做外推。

### 一次性工作

| 工作 | 秒 |
|---|---:|
| 生成合成波动值、状态、窗口和 bo mask | 0.05957 |
| 计算全池每日波动分位切点并编码 | 0.06464 |
| 全池三态按日期、档位汇总 | 0.00521 |
| 已生成的 bo mask 提取买点并缓存 200 窗数量 | 0.00153 |
| 生成全部 36 个候选唯一行号 | 0.14753 |

合成输入生成时间仅用于交代实验过程，不是预计的真实读盘时间。bo 一行仅测 mask 到汇总表，**没有测 bo detector**。真正的穿越计算、波动计算及行情读取由其他研究项分别测量。

### 每候选方向汇总

每种候选类型各 12 个，共 36 个；单候选中位时间基于 12 个候选×3 轮的 36 次测量。两种方法均包含候选分组计数、候选与普通对照的 200 窗数量及方向比例；固定 bo 已缓存，没有再算。

| 候选分布 | 真实候选股票日数范围 | 逐全池行配权 + 累计数量 | 预先分组汇总 + 累计数量 |
|---|---:|---:|---:|
| 稀疏分布在全期 | 981–1,567 | 8.360 ms | 0.0684 ms |
| 集中在 10 个日期 | 2,975–4,034 | 8.437 ms | 0.0760 ms |
| 广泛分布在全期 | 100,697–128,422 | 9.710 ms | 0.7546 ms |
| 三类合计 36 个候选 | — | 0.33677 s | 0.01086 s |

整组约 31 倍只描述这段计算；初始化、模式检测、标签读取、空间中位数、最终评分和 Optuna 自身都不在此倍数中。一次实验、一个机器环境也不足以承诺生产时延。

广泛候选的开销更大，因为必须读取和统计更多真实候选行；预汇总不会消除候选自身的计数成本。

### 窗口查询单独测量

固定一个广泛候选，使用已聚合好的 504×3 日数量：

| 200 个窗口的计算方式 | 每次 200 窗的中位时间 |
|---|---:|
| 每个窗口分别截取日数量并求和 | 201.3 μs |
| 建一次累计数量，再向量化相减 | 8.40 μs |

每个测量批次执行 100 次，重复 5 个批次。另有独立正确性参照：每个窗口直接扫描约 21×5000 条全池行并配权，200 窗约 0.0310 秒；这一项只作为独立核对与成本量级，不与包含不同输出的整套 trial 直接计算倍数。

## 5. 一致性与边界验证

- 36 个候选的三态计数和方向结果全部比较；候选自身整数计数完全相同。
- 逐全池行配权与先分组后配权的最大状态数量差为 `4.73e-11`，方向比例最大差为 `8.72e-15`。两者是 float64 加法顺序造成的舍入差，不宣称逐位相同。
- 独立按窗口扫描全池行与累计数查询，最大加权数量差为 `9.34e-10`。后者包含长累计数相减，以及前者在较多行上逐项累加的舍入差。
- 刻意加入重复窗口、第一个可用起点和最后一个可用起点。约定左端包含、右端不包含；重复窗口在同一算法下产生完全相同结果。
- 空候选返回零数量、方向未定义；全部未触线也返回方向未定义，不返回 0% 或 50%。
- 固定 bo 在窗口没有买点时，返回零数量和方向未定义，不能将候选自动判为胜过 bo。
- 当全池某组没有可用行且候选也没有该组行，贡献为零；如果候选声称在该组有买点，属于支持集不一致，必须拒绝，不能除零或把方向填零。本实验断言逻辑覆盖这两个分支，主性能输入各组均有支持。
- 同股票同日多次 pattern 匹配必须先去重成唯一行号再计数。主性能输入原本就唯一，重复行例子另验证去重约定；**去重耗时不在上述 trial 时间内**。
- 主性能输入的波动值来自连续分布，没有覆盖大量相等值。另用 4 天×12 只股票的确定输入覆盖全部值相同、两档重复值、恰好等于分位切线、10 个空档位，并给候选故意加入重复行。分档使用现有代码的 `np.unique(quantile(...))` 和 `searchsorted(side='left')`；去重后先分组与逐行求和的最大日计数误差为 `1.11e-16`。具体波动值、切点、档位和候选行号保存在 JSON 的 `tie_correctness`；此项只核对正确性，没有追加性能测试。正式实现必须冻结同一组切线及同一个边界归档规则，不能把“数值相等时进左档”改成按排序名次拆散。

这些是原型函数的验证，不代表正式 skill 已实现或通过同样测试。

## 6. 与现有代码的关系

现有 `.claude/skills/tune-gates-v3/scripts/scoring.py` 的 `_matched_baseline` 已具有按日期、波动档位配比的业务定义，但每轮仍计算全池指纹，重新访问明细，并计算加权空间中位数。`assess` 又会对候选、原参数与全池多次作 `_rows` 校验和汇总；`SamplingPlan` 中的索引与支持集处理也会再次扫描。

应该把不可变数据快照加载时的完整验证、日期/股票编码、分档与固定基线汇总移到一次性准备阶段，候选只验证并查找自身行号。这个方向不是“删掉校验”，而是让快照不可变并在恰当边界校验。缓存身份、过期规则与验证成本由主报告统一说明。

本报告的时间来自按新口径编写的临时 NumPy 原型，不是对旧 `assess` 做修改后的测速。旧 `SamplingPlan` 是股票与日期块分别重抽，再相乘成为逐行权重；仅有日期、波动档计数不能重现这种股票权重。要保留旧股票重抽就必须额外保存股票维或回读明细。**不能把新的单窗口设计称为旧方案的无损计算优化。**

## 7. 不能混为一谈的后续工作

1. **空间中位数不能由各组中位数替代。**固定 bo 的窗口中位数可提前算一次；普通买入随候选配权的中位数仍要准确处理各值及其权重，不能套用三态计数的加法。如果空间会影响每次候选合格与否，就不能只为最终候选计算后声称搜索等价。
2. **缓存计数不等于增加证据。**200 个重叠或重复窗口仍来自同一段历史，不能用查询数量作为独立样本数。后续可信度校正可能需要股票、日期关系，原始细节须保留。
3. **稀疏组并非数据坏。**候选没买点、bo 没买点、全部未触线都是完好数据下的自然结果。计算层应如实返回数量和未定义标记，是否纳入评分由冻结的评分规则决定。
4. **若改变配比定义，重新推导等价性。**当前证明限于每个日期、波动档内部所有池子股票权重相同。个股特定权重、股票重抽、连续波动值的逐股匹配或逐候选波动分档都会使简单小表不足；如果改成排除 pattern 自身，还需从池子计数减去候选贡献并处理余下数量为零，不能直接沿用本结果。

## 8. 可重建输入与计时方法

原始结果 JSON 保存全部窗口起点、各候选真实数量、逐轮时间、环境、状态误差和内存字节数。临时代码路径为 `/tmp/v3_compute_baselines.py`，研究交付时删除；没有修改正式代码或依赖。

生成器为 `numpy.random.default_rng(2026100203)`，严格按以下顺序消耗随机数，均使用 C-order 日期优先布局：

1. `D=504, S=5000, G=5, W=200, L=21`；生成 `(D,S)` 波动数组 `lognormal(-3, 0.4)`。
2. 生成 `(D,S)` 均匀随机数组 `u`。第 d 日 `u < 0.34 + 0.07*sin(d/27)` 为 up；否则 `u < 0.73` 为 down；余者为 none。三个状态分别编码 0、1、2。
3. 生成 200 个均匀整数起点 `[0,D-L]`；前 5 个覆盖为 `[0,D-L,20,20,0]`，右端为起点加 L。
4. 生成 `(D,S)` 均匀随机数组，`<0.02` 为合成 bo mask。
5. 按每天全池波动值计算 `[0.2,0.4,0.6,0.8]` 分位切点，以 `searchsorted(side='left')` 分档；生成 `group_id=date_id*5+bin_id` 和 `date_state_id=date_id*3+state_id`。此阶段不消耗随机数。
6. 对 k 从 0 到 11，依次生成三类候选。稀疏：长 `D*S` 均匀随机数 `<0.0004+0.00002*k`。集中：先无放回选择 10 个日期，再在这些日期生成 `(10,S)` 随机数 `<0.06+0.002*k`。广泛：长 `D*S` 随机数 `<0.04+0.001*k`。每类取 `flatnonzero` 得到唯一行号。
7. 使用 `np.bincount` 生成分组大小、分组三态数量、候选分组数量及候选每日三态；窗口查询使用零行开头的 `np.cumsum(axis=0)`，再按两端相减。逐行参照先建立长度 `D*S` 的组权重数组，再按 `date_state_id` 作带权 `bincount`。
8. 两种方法先暖跑第一个候选，然后按上述 36 候选顺序循环三轮。每个候选和每整轮独立用 `time.perf_counter` 计时。独立全行窗口参照固定最后一个广泛候选执行三轮。窗口查询单项各执行 5 批、每批 100 次。

启动形式：`flock /tmp/v3-compute-optimization-bench.lock env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1 .venv/bin/python /tmp/v3_compute_baselines.py`。

未计入的成本：读取行情、波动计算、close 首次穿越、实际 bo 和 pattern 检测、字符串到整数映射、逐候选去重、DataFrame 验证与指纹、空间中位数、可信度公式、Optuna 提议参数和持久化。没有新增依赖，没有读取训练或验证行情；没有符合市场发现登记条件的副产品。

## 9. 同伴核对

已与 `compute_rolling` 直接交叉核对：它确认组内恒定权重的等价前提，并指出这仍保留窗口内部买点密集日期的较大权重；若排除候选自身、逐股配对或连续波动值匹配，须增减计数或增加索引。其提醒已纳入上文。

已与 `compute_passage` 直接核对接口：当前汇总只需最早触线的三态结果，不需分别保存两边首次日期；最早位置可作为可选诊断信息。逐股日状态与唯一行号的对应仍须保存，不能把先后位置缓存或统计小表误称为新增独立证据。双方亦确认 close 三态与旧 high/low 四态属于评价定义变化，不能借加速混同。
