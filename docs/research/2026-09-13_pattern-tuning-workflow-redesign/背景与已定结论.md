## 1. 业务系统现状

### 1.1 调参对象

path2 把一个股票走势 pattern 声明为多级事件 + DAG 约束（`path2_apps/<app>/dag_spec.py` + `params.yaml`）。
参数有两种性质：detector 构造参数（改了必须重新检测）与节点上的 where 闸（一元谓词，可以在检测结果上事后切）。
现役调参对象是 `bb_v1`（burst 突破串 → tb 回踩段买点）。

### 1.2 两个 skill 的现有分工

**feature-study（学习端，`.claude/skills/feature-study/`）** —— 回答「这个特征 / 直觉该不该信」
- 假设来源：用户直觉；研究副产品登记簿 `docs/feature_candidates.md` 的待验证条目。
- 方法：每个概念 ≥3 种口径 → `extract.py` 重放对齐 + 两道自检门（match 集逐股对齐、label 重算 <1e-12）→
  `run_battery.py` 三关：FDR q<0.05 → 控制变量秩回归 |t|≥2 且同号 → 股内簇 + 时间桶双维去簇各自 p<0.05 且同号
  （时间桶少于 20 个时关 3b 按未检处理、判定降级）→ 五类判定（有信号 / 代理 / 反转 / 不稳 / 无信号）+ 分箱形状（按 median 判）。
- 条件宇宙：样本 = pattern 已成立的 match。label 目前是 forward_return。
- 控制列 = 通用波动率地板 `c0_atr_pct` + `apps/<app>/adapter.py` 的 `KNOWN_SIGNALS`。
- 产出：候选信号（特征 + 方向 + 推荐口径 + 分箱形状）；回写登记簿「已关闭」段；判「有信号」的加进 `KNOWN_SIGNALS`。
- 批量多重性防线（FDR / 控制变量 / 去簇）只在这一端。

**tune-gates（执行端，`.claude/skills/tune-gates/`）** —— 回答「特征已定案，阈值 / 参数放哪」
- 路径 A：单闸事后切档 → 平台图（`tune.plateau_report`；**从未实战调用**）。
- 路径 B：多维稳健区。调用序列 `tune.status` → `tune.propose_grid`（读 pattern 代码，探针测维度分类、提档位）→
  `tune.install` → `tune.setup` → `tune.scan`（一次扫出候选长表）→ `tune.compare`（长表与逐格引擎结果的一致性验证）→
  `tune.find`（识别稳健区）→ `tune.cell`（按坐标查格）；另有 `tune.retire`。
- 维度分类（探针自动测）：W = where 谓词（事后切）、F = filter 字段谓词（事后切，不进检测笛卡尔积）、
  D = detector 参数（必须重检测）、E = 只影响边（只影响求解）。
- 扫描用每股反转循环：上游流按影响集缓存、每个检测组合只重做求解；实测 4096 个检测组合 ≈345ms/股。
- 稳健区推荐 = r=1 邻域最小分最高的格；按股 bootstrap 估 optimism，split-half 多种子报均值 ± SE，
  同首部缓冲的外推窗是唯一无偏数字；`apps/<app>/exposure.jsonl` 记录同一批数据被识别过几轮。
- 执行端不设批量多重性校正。

**两端分工条款**（tune-gates `SKILL.md` 已写明）：
- 「新闸引入经学习端定案口径……跳过学习端直接引入属流程违章」。

## 2. 触发本研究的实证：2026-09-07/08 bb_v1 全宇宙调参

原始记录：`.claude/skills/tune-gates/apps/bb_v1/notes.md` §11；网格声明：同目录 `study.py`；产物：`outputs/tune_gates/bb_v1/main/`（长表分片 + `cells.npz` 等）。

- **网格 12 维**：D 维 6 个 × 4 档（`bo.exceed_threshold`、`bo.min_relative_height`、`burst.gap_max`、`tb.max_rise_k`、`tb.max_span`、`tb.stop_confirm_bars`）= 4096 检测组合；
  F 维 1 个（`burst.min_bos` 4 档）；W 维 5 个（`distinct_pk_min` [1,3,5]、`first_drought_min` [0,40,80]、`peak_age_min` [0,60,120]、`vol_spike_min` [0,3,6]、`max_day_drop_pct` [None,0.2]）。
  合计 4^7 × 3^4 × 2 ≈ 265 万格。
- **规模**：1517 只股 / 3522 万行长表 / 识别约 20 分钟（期间整机 OOM，已根治，不在本研究范围）。
- **识别结果**：最高格 naive = +0.144；按股 bootstrap optimism = +0.150 ± 0.0064 → corrected = −0.0066；
  split-half = −0.179（多种子 sd≈0.076）；bootstrap 稳定性 0.04。**没找到稳健区。**
- **年份依赖**：收紧有效的比例 2024 = 54.2%、2025 = 19.5%。
- **事后补救**：逐闸单维切片，发现峰龄闸是负增量、突破幅度提高有益。2026-09-08 定案写入 `path2_apps/bb_v1/params.yaml`：
  - `bo.exceed_threshold` 0.003 → 0.0075：两年首次穿越率各 +1.6 / +2.8 点，买点 −8%；
  - `burst.peak_age_min` 60 → 0（停用）：买点 +13%，两年首次穿越率各 +0.6 / +1.3 点；
  - `tb.max_span` 定 20：20/30/50 几乎无差，10 明显更差。
  - **这些定案全部来自执行端证据，没有经过学习端。**
- 现存长表是按旧底座（定案前参数）扫的，当前声明已再生不出它；作为方法实验的数据仍然可用。

## 3. 已定结论

### 3.1 问题 F：联合分析必须放在减闸之后——理由是统计，不是算力

联合空间格数 = 各维档位数之积，样本量固定。格数越多，每格样本越少；从越多格里挑最好的，选择偏差越大
（粗略地，最大值的噪声抬升随 √(2 ln K) 增长、随 √(每格样本) 缩小）。265 万格时 optimism 恰好吃光 naive——
算得动也白算，内存 / CPU 救不了。那一轮顺序做反了：扫描 → 12 维直接找稳健区（失败）→ 才做单闸切片。
「没找到稳健区」是两个原因叠加：年份依赖是真实机制；265 万格的偏差也实打实吃掉了信号。不分清会把「流程用错」误读成「pattern 没东西」。

### 3.2 「最节约资源」的目标函数

算力已经不是瓶颈（反转循环 + 内存根治）。真正稀缺、且每次使用都会消耗的是**样本**：固定股票池 × 固定时间窗里的买点。
每多比较一个格子，就多一次从噪声里挑最大值的机会。
目标 = 每次比较用到尽可能多的样本 + 比较的总次数尽可能少 + 不在同一份数据上重复挑选。

### 3.3 七层优化（初稿；第 1 层与第 3 层已被 §3.4、§3.5 修正）

1. **不花数据就砍维度**：~~定义性参数不调~~（**已被 §3.5 推翻**）；只有一个合法档位的参数不进网格。
2. **先验有没有边际**：最宽一格 vs 层匹配随机日基线（首次穿越口径），没有边际就停。调参只能磨锐已有优势；K 个噪声格里挑最大，期望必为正。
3. **用边际效应替代格子**：按单参数档位切开、其他参数全部合并，每档用「总样本 / 档位数」而非「总样本 / 格数」；方向跨年翻转 = 没有信息，删。在已有宽进长表上做，不重扫。（**§3.4 已拆分此层**）
4. **按交互强度分组**：同节点参数交互强、跨节点弱；组内全因子联合、组间只看边际；分组假设用长表估两两交互来验证，不靠猜。
5. **由粗到细，每层换一折**：粗筛与细化是两次挑选，用年折 / 半年折分离，事前不让偏差进来。
6. **把挑格子换成拟合响应面**：选择偏差由有效自由度决定而非格数；拟合等于把邻格样本合并。
7. **扫描前算噪声地板**：给定关心的最小效应量与每格样本数，反推样本撑得起多少格，超了先减维，做成提网格方案时的机械输出。
   每格有效样本按股 × 时间簇去簇后算（同股 40 日标签窗内重叠的买点不独立）；首次穿越率方差有界，作主判据比中位收益抗噪。

可选：股票池逐轮淘汰（四分之一池跑全格淘汰差格，剩余股票只算幸存格），淘汰与确认天然用不同股票。

### 3.4 与 feature-study 的互补评估

- **第 1、4、5、6、7 层纯执行端，互补。** 第 5 层是把学习端「分界 = 是否用同一份数据」的原则用到执行端自己的多阶段流程；
  第 7 层对应学习端「少于 20 个时间桶就降级」的功效闸；执行端算有效样本应借用学习端的时间桶去簇（执行端目前只有按股 bootstrap）。
- **第 2 层是两端都没做的空档**：学习端的条件宇宙是「pattern 已成立的 match」，回答不了 pattern 本身有没有边际；
  执行端的增量是相对参照格算的，不是相对基线。做的时候按 FC-004 层匹配、按 FC-009 用首次穿越率。
- **第 3 层越界，要拆**：
  - **W / F 维（闸）**：存在与否由学习端判（有信号 / 代理 / 无信号）。执行端「两年方向一致 + 买点代价」的判据分不清「有信号」和「波动率代理」——
    FC-009 就是反例，2024 年数据会把四道 burst 闸全判成有效。F 在这一侧的修正是「未审定的 W 维不进网格」，而不是「进了网格再筛」。
    tune-gates 现有的「单特征质检」（逐个算 AUC，出局不算证伪，疑问转学习端立项）只是个别漏网候选的过渡通道。
  - **D / E 维（检测参数）**：学习端「每条 match 一行、特征对 label」的装置评估不了它们——改一个检测参数，match 集合本身就变了。
    这部分的边际筛选是执行端独有的职责，互补成立；用首次穿越率算，跨折方向一致复核。
- **一处两端方向相反、还没对账**：学习端 FC-006（突破幅度越大，首次穿越越偏下行；未验证，样本是 bo 全流）vs 执行端定案「提高 `exceed_threshold`」。
  不一定矛盾：提高检测阈值会删掉弱 bo、改变 burst 组成、进而改变哪些回踩成为买点，这不等于在 match 上挑高幅度。
  需要拆：收益来自 (a) 删弱 bo 改变了 burst 结构，还是 (b) 选出了高幅度的买点；若是 (b)，与 FC-006 正面冲突。
- **接口缺三条管道**：
  1. **正向**：提网格方案时只读代码、不读学习端结论。应读 `KNOWN_SIGNALS` 与登记簿：W 维限定在已验证信号上（未审定的至少打标），
     档位以学习端报出的分箱形状（饱和点、甜点位置）为中心收窄，而不是 3~4 档铺满全程。这一条直接决定格数。
  2. **反向**：执行端切片看到的东西（峰龄闸无增量、旱期闸跨年翻号）是假设，不是判定，应登记成 FC 条目交学习端换样本验证。
     删闸与加闸风险不对称（删一道没增量的闸比加一道闸安全），但判定权在学习端，至少要登记。本轮删峰龄闸走的是执行端证据。
  3. **指标**：两端统一到首次穿越率（执行端稳健区打分已是首次穿越口径；切片与基线对照要跟上）。

### 3.5 修正：「定义性参数」不是可用判据（推翻 §3.3 第 1 层前半）

反例：bottom_burst 调参最大的改进来自 `stop_confirm_bars` 2 → 0（买点窗 41 → 423，label 中位数翻倍）。
按「定义性参数不调」，这个参数会被钉死，那个发现就不会出现。人在扫描前凭语义做的判断会悄无声息地挡掉真实改进。

**真正不进网格的只有两类，都由工具机械判定：**
- **尺子参数**：标签窗口、首次穿越阈值 k、首部缓冲、基线口径——凡参与 label / 基线计算、或写进运行口径的，一律不是网格维度（用收益挑尺子是循环论证）。
- **退化档位**：detector 拒绝的非法值（本轮 `stop_confirm_bars=0` 被拒）、只剩一个合法值的参数、机制上与「不设闸」等价的格
  （如 `first_drought_min ≤ gap_max` 时一个都拦不下）。探针应逐档探合法性。

**其余参数一个都不由人事前否决，但分两步进：**
- **第一步筛选**：全部候选参数各取两档（宽 / 紧）全进，看每个参数的边际效应。假设数 = 参数个数，每个估计用约一半样本，选择偏差很小。
- **第二步联合**：只有筛选幸存的参数进联合网格，在这里加档位、找稳健区。幸存者通常两三个，格数几十到几百。

**人剩两件事，都在数据说话之后：**
- 给每个参数一个合理的取值范围（筛选的宽 / 紧放在哪）——工具从代码默认值与历史调参记录提建议，人看一眼，一次性、便宜。
- 对筛选结果做机制复核：问「为什么有效」；如果答案是「它是波动率代理」，交学习端，不进联合网格。
  如果数据说确认根数该是 0，且跨年复现、换样本也成立，正确反应是更新定义并记录。
