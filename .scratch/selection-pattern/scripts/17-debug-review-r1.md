## 发现（按严重度）

**1. 【中，有条件】调试模式下记「看过」不限制在调试段，正式段的接触会记进调试账（已实测）**
- 在哪：`chart_workflow/views.py:176-187`。只有聊天贴图会查范围，而且加 `--allow-outside` 就能放过；用户手动看图那一类根本不查。
- 怎么触发：在调试模式下记一张 2025 年的图，手动看图那一类直接记进了调试账；聊天贴图加 `--allow-outside --reason …` 也一样进了调试账。正式账里一行都没有。
- 后果：用户确实看过的训练段图，正式的看过记录里没有，调试账一清空就彻底没了。之后正式模式按看过记录判断哪些图没露过底时，会把它当成没看过。
- 修法：调试模式下，图窗或清单条目只要越出调试段就一律拒绝，不分手动还是聊天，也不认 `--allow-outside`，并提示去掉模式变量、在正式模式下记。

**2. 【低，有条件】后端没连上时，调试横幅静默不出现（读代码确认，实测没复现）**
- 在哪：`path2_web_ui/src/stores/mode.ts:10` 读失败时置空，`ModeBanner.vue:20` 只在挂载时读一次。`tests/components.mode-banner.spec.ts:46` 还把「读不到就按正式模式处理」写成了预期行为。
- 怎么触发：页面加载那一刻模式接口失败（后端还在启动、正在重启或卡住了），横幅和标签页的【调试模式】前缀都不出现，之后也不重试，直到手动刷新。我重启了一次启动脚本，这次后端先好了，所以没复现。
- 后果：数据护栏在后端，不受影响。但界面看起来和正式模式一模一样，用户可能以为自己在正式模式里标注，实际标注进了调试账，等于白标。
- 修法：读不到模式时挂一条醒目的「模式未知：后端没连上」并定时重试；或者让调试启动脚本也给前端传一个模式变量，前端和后端报的模式对不上就报警。

**3. 【低，有条件】调试账的默认位置如果是符号链接，清空会删掉链接指向的那个目录里的东西（模拟验证）**
- 在哪：`chart_workflow/debugroot.py:79/97/100`。目标路径和默认位置都先解析成真实路径再比，相等就放行，然后删掉除 `cache/` 以外的一切。
- 怎么触发：在 scratchpad 里把默认位置换成一个指向普通目录的链接，clear 把那个目录里的文件全删了。真实场景要有人把主目录的 `outputs/chart_workflow_debug` 换成链接，又指错了地方。指向正式账、主目录、受 git 跟踪的目录都会被别的检查拦住，只有「不受 git 跟踪的普通目录」挡不住。
- 修法：默认位置本身是链接就拒绝（判断时用解析前的路径）；或者清空只删认识的那些文件和目录名。

**4. 【低，有条件】两个环境变量同时指错时，调试账能建进正式账的目录里（只调了拦截函数验证，没有真建）**
- 在哪：`chart_workflow/state.py:234`、`chart_workflow/debugroot.py:84`。「和正式账重叠」只跟环境变量 `CHART_WORKFLOW_STATE_ROOT` 指的那份正式账比。
- 怎么触发：正式账变量指到临时目录，调试账变量指到真正式账下面一个还不存在的子目录，拦截就放行了，`init` 会在受 git 跟踪的正式账目录里建调试账。去掉正式账变量就会被拦。
- 后果：调试文件以未跟踪文件的形式出现在正式账目录里，可能被一起提交。不过它们不进水位，也不算进正式账的各类文件。
- 修法：同时跟环境变量指的正式账和主目录默认的正式账比；或者往上找，任何一层有 `STATE_ROOT.md` 就拒绝。

**5. 【测试空白】**我把 23 处护栏逐个改坏，21 处测试变红，漏网的是下面两处：
