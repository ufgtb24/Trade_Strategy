## 0. 结论

1. **你照常画；写 app 时，会话给每个名字定一级**：必须有、可有可无（挂在它依附的那一段下面）、必须没有、不放。定义里写清了的照定义，出现太少的默认不放，其余问你一次「它是买的理由（每个都得有）、有更好，还是只是背景」。写完以后 pattern 页按级分层：顶层只有必须有，每个正例都有；可有可无的都挂在次级。这正是你问的「模糊只在写 app 之前，写完顶层不再可选」。（v1 推荐的「画法即声明」已撤回，理由见第 15 节。）
2. **级是意思，不是写法**：必须有的东西，会话可以写成一个 node，也可以写成相邻 node 上一条必过的 where（bb_v1 的「突破前沉寂够久」就是突破串上的 where，`path2_apps/bb_v1/dag_spec.py:53`）。你只回答「必须有吗」，不回答「是不是 node」。app 本身只有一种拓扑，这是 path2 决定的（`path2/GLOSSARY.md:95`）。
3. **「没画还是真没有」只对必须有的名字问**：列出缺它的正例配缩略图，同一张图上有同名框却没收进成员的，界面机械标出来，不靠缩略图够不够宽。你逐个答：补上，或者「真没有，所以不算这个 pattern」（挪走或改成像但不买）。
4. **规矩只管正例**。像但不买常常正是因为缺一样、多一样才不买，那个差就是理由，按差分组摆出来给会话当证据。所有计数的分母只数正例。
5. **偏离只在写过 app 后才有**：正例缺了必须有，或有了必须没有。不标红，排在最前；参照就是对应表里这两级，随 app 进 git。
6. **灵活和规范按「代价怎么长」分**（第 2 节）：当场看得见的随你；会累积但能一次清掉的，由会话或界面接住；只能逐张回头清的，在发生那一刻引导，或者给一个一次清完的操作；会悄悄变成错证据的不支持；撤不回的硬拦。**必须规定你别做的只有四条**：看 2026 年起的数据、一个词装两种意思、用后来的涨跌定 label 或写像但不买的理由、跳过进门清单送最后检查；其中第一条由数据墙拦、第四条由会话的清单拦，**真要你自己记着的只有中间两条**。
7. 整条流程只有一道真拦：送最后检查。

## 1. 两层：你的说法，app 的写法

| | 你这一侧 | app 一侧 |
|---|---|---|
| 是什么 | 正例的成员框：名字、先后、套框、属性 | node 加边（`path2/GLOSSARY.md:73`、`:76`、`:86`） |
| 谁产出 | 你画；界面现算分组 | 会话写 |
| 中间 | 对应表：每个名字一行，记**它是哪一级**和**由谁来认**（哪个 node、哪条 where、哪条边） | |

path2 里核实过的硬事实：

- **app 没有可有可无的 node。** 求解集 = 挂在某条边上、不是否定边终点、有 detector、`solve=True` 的 node（`path2/dag/_solve.py:99-108`）；不挂边的不求解，注释原话「孤立即不属 pattern」（`_solve.py:100`）；`solve=False` 的只显示、不进 match（`path2/dag/nodes.py:60`，bb_v1 的 pk 即如此，`path2_apps/bb_v1/dag_spec.py:48`）。所以「可有可无」只能落在 where 或子事件里。
- **可有可无、取其一写得进 where**：`W.any`（`path2/dag/where.py:86`），`W.attr` 遇到空值判不满足（`where.py:23-26`），`W.children`（`where.py:123`）。
- **必须没有写得出**：否定边（`path2/dag/edges.py:215`），它的终点不进 match。
- **复合事件里可能没有的子事件有坑**：`W.child` 不做保护（`where.py:113-120`）；子事件不存在时基类 `child` 抛 KeyError（`path2/core.py:137`），burst 的 `child` 直接取 `members[0]`（`path2/atoms/breakout.py:113-118`），实测抛 IndexError（`repro/optional_child.py`）；求解时 where 过滤不捕获（`_solve.py:234-235`），整只股票的分析中断。写法约定归票 06，安全写法见 5.3。

| 级 | 意思 | 会话可以写成 |
|---|---|---|
| 必须有 | 每个正例都得有，是买的理由 | 一个 node；或相邻 node 的一条必过 where / 字段 |
| 可有可无 | 有更好，或几种里有一种就行 | 依附那段 node 的 where 分支（`W.any`、票 06 的「至少 k 条」）、可空字段、可空的一组子事件；看不出有没有用的放在要用的地方量（票 05） |
| 必须没有 | 有它就不买 | 否定边；或依附那段 node 的一条 where |
| 不放 | 只是背景、有没有都一样、或已经被别的管了 | 不进 app，对应表写原因 |

## 2. 灵活和规范的分界

### 2.1 判据

只看「撤不撤得回」不够：有的事在单张图上撤得回，但由着它，麻烦会随标注量累积，到归组、写 app、盲看时一次爆出来。所以看**代价怎么长**，分五档：

| 档 | 代价的样子 | 流程怎么对待 |
|---|---|---|
| A | 当场看得见，改一处就好 | 支持，不管 |
| B | 会累积，但会话或界面能一次消化：清理成本随「名字的个数」涨，不随「图的张数」涨 | 支持，由会话或界面接住 |
| C | 会累积，而且只能逐张回头清：成本随图数涨 | 引导：在发生那一刻让对的做法最省事，或给一个一次清完的操作，把它变成 B |
| D | 会悄悄变成错证据，事后从数据里分不出来 | 不支持：能做成界面默认的做成默认；做不成的规定在你身上，系统能查的地方查 |
| E | 撤不回 | 硬拦 |

D、E 两档才需要「规定你别做」。规定你记着的事，几周后多半会忘（sim 1.4 末），所以 D 档能挪到界面默认上的都挪过去，真要你记的只剩四条（2.4）。

### 2.2 常见的思考模式

情景编号见 `sim.md` 1.4（按常见程度排的 22 条）。

### 2.3 情景落档（`sim.md` 1.4 的 22 条）

- **随你（A）**：H1、H6、H9、H10、H13、H17、H18、H21。

### 2.4 必须规定你别做的（四条）

| # | 别这么做 | 防的是什么 | 违反了会怎样 | 谁来拦 |
|---|---|---|---|---|
| X1 | 看 2026 年起的数据 | 唯一一份没碰过的数据 | 最后检查不再是没碰过的数据，结论作废 | 数据墙，机械拦（方向文档第 2 节） |
| X2 | 一个词装两种意思，包括改一个词的措辞去换它的意思（意思变了另建一个词） | 同名框是同一样东西 | 同名框一半认得出一半认不出，会话误当成门槛问题去调；改措辞换意思还会让所有旧框悄悄跟着换了意思；事后要逐框回看才分得开 | 靠你；界面在点下名字后直接显示定义一行、改措辞时显示用在几个框上；会话发现同名框明显分成两类时提醒 |
| X3 | 用后来的涨跌定 label、写像但不买的理由、判属性的有没有 | label 只说「这一天有没有那个样子、当时会不会买」（方向文档第 3 节第 2 步）；像但不买的理由和写成「没有」的属性同样只按买点那天及以前看得到的判（critic R10）；后来才看出的只能当新想法去验证 | 训练段上一路对得好，最后检查才没过，撤不回，还查不出是哪几张 | 靠你；会话每轮列出上一轮以来翻过 label、又不是因为结构变化而翻的买点（含盲看揭开前后判断相反的），问「翻的理由那天看得见吗」，看不见的建议改回、理由记成新想法；翻译像但不买的理由时同问。第一次定 label 时看了后续走势，查不了，只能由最后检查兜 |
| X4 | 跳过进门清单送最后检查 | 不白用一次没碰过的数据 | 用掉一次，撤不回 | 会话列清单；你坚持送检可以，那是你的方向决定，记在账上 |

X1 由数据墙机械拦、X4 由会话的清单拦，你都不用记。**真要你自己记着的只有 X2、X3 两条**，两条都有界面或会话在发生的那一刻帮一把。除此之外，任何「请你别这么做」都改成界面默认或会话的活。

## 3. 阶段表

**阶段按 pattern 算**：某个 pattern 进了主循环，其余买点照样自由标、挂未归类（方向文档第 8 节）。3～5 是主循环，每轮由你一句「看看我的标注」开始；循环里随时可能把某样东西改成必须有，所以定级与必须项检查放在每一轮开头，不当门槛。

### 阶段 0 找图
- 你：从大涨段清单、「随机一张」或 path2_web 进来。会话不参与。界面默认干净的标注模式（已定）。允许一切，无出口门槛。

### 阶段 1 标注
- 你：画框、点名字、写属性、框套框；在当前 pattern（默认未归类）下点买点，选 buy / no_buy；成员默认推断，推错点名称块。
- 会话：不参与。
- 界面：主图的框、bracket（`path2_web/GLOSSARY.md:45`）虚线、`⊂`；edit 栏 members / others。改动：
  - **自动并进跟着「当前买点」走**：当前买点 = 这张图上最后一次放下或选中的买点，画框、选中框都不改变它，选中别的买点才换，换图或点空白处清掉，它的 bracket 一直加粗（sim K6，critic 与 ux 对齐的定义）；从缩略图跳来，跳到的买点就是当前买点。有当前买点时，新画的框、以及改动后伸到当前 bracket 范围以外的框，按默认规则并进、bracket 当场伸长；已有的框在 bracket 范围以内改动，不自动并进（critic R12：再买一次时，用户专门从买点 2 排掉的第一段回踩，拉一下就会悄悄并回，bracket 长度不变、看不出来）。没有当前买点就不并。取代「只在放买点那次停留里」。
  - 有 app 的 pattern 下，members 链按必须有对齐，缺的位置画空槽（ux U5），画上就填满；不另挂提示签，免得先点买点后画框时冒出一长串（sim N3）。
  - 起名时措辞相近的词排在前面，点下名字后定义直接显示一行；带上的属性默认没看过（D2）；选中买点时买点之后的 K 线暗一档（X3 的当场提醒）。
- 允许：未归类；定义空着；属性没看过；默认成员没核对；背景框画不画都行。无出口门槛。

### 阶段 2 归组
- 你：在未归类页按组点 `→ pattern`（新 pattern 起名、写定义）。
- 会话：可在对话里给建议（近义词、哪两组像），不写标注文件（已定）。
- 界面：
  - 未归类页只有 groups：组头即这组的顶层名字串，buy / no_buy 分开计数；没有 elements、定义、识别器。
  - 没有 app 的 pattern 页：定义、elements、groups。elements 平铺这个 pattern 正例里出现过的名字，子框按几何套着；`in k/N` 只数正例、不足全数才显示（ux U2）；像但不买的计数另列。箭头只画在确实一起出现过、先后确定的名字之间。groups 按顶层名字串分，**不判偏离**。
- 允许：一个 pattern 里有几种顶层名字串；定义空着。无出口门槛，随时可以叫会话写 app。

### 阶段 3 会话写 / 改 app（每轮）
- 你：只回答会话停下来问的（第 8 节）。
- 会话，按顺序：
  1. 读上一轮以来的标注变化；对所有名字机械查「画了没收」（同一张图上买点左边任意远处有同名、没收进成员的框），不受下面任何门槛限制（critic R11）。

## 5. 五个点名的问题

### 5.1 改了顶层骨架，旧买点怎么办
- 改的是某个名字的级，不是改一份「骨架」。你说一句「以后都得有下跌」，指出几张图（已有标注里有下跌的，会话直接指给你，不用重标），会话把它定成必须有，当轮列出缺它的旧正例，配缩略图、标出画了没收的。不用「多标几张投票」（sim N1）。
- 逐个答：补上（从缩略图跳过去，买点处于选中，画上或拉长就自动并进，列表的数随之减少，就是进度）；或「真没有，所以不算」——整组挪到新 pattern 保留旧想法（一下），或改成像但不买（`−下跌` 就是它的理由，不会被当成事后翻 label）。
- 去掉一样必须有：降成有更好或不放，没有正例会因此偏离，不用动旧图。
- 没有要迁移的数据：对照状态、认出数、`app:buy` 都按「app 版本 × 标注」现算（上一轮 `final_report.md` 2.1）；盲看标记、量特征的结论随 app 版本过期（票 05 硬要求 7）。

### 5.2 一个买点同时像两个 pattern
- 已定：挂两个买点，框共用，成员各推各的（方向文档第 8 节）。
- 常见情形：P2 = P1 前面多一样必须有的横盘。P2 的正例在 P1 的 app 下多半也会 match，不需要再挂一个 P1 买点：对照只看挂在 P1 下的；P1 盲看时抽到它，答「是」就对了。
- 同一天「P1 正例、P2 像但不买（缺横盘）」是同一件事的两面，也是两个买点。
- 两个 pattern 的必须有完全相同也允许（区别在你心里，比如大环境）。

### 5.3 子名称「可有可无」怎么写
- **你这一侧**：子框和写在父框上的属性是同一样东西的两种写法（票 01 已定两种都行），计数合并：画了子框或属性写有 = 有；属性写没有 = 没有；都没有 = 没看过。同一个父框里既画了缩量子框、属性又写了「没有」时，以框为准（框是带位置的观察），界面上那个属性随之锁成「有」（critic R4）。
- **意思靠名字的定义**（已定）：有没有都一样 → 不放；有一个就行 → `W.any`；凑够几条 → 票 06 的「至少 k 条」；说不准有没有用 → 放在要用的地方量（票 05）。
- **代码这一侧**（框架现在就能写，约定交票 06 定稿）：父事件的 detector 把可选子事件算成字段（没有时为空），where 用 `W.attr` 读，空值判不满足；或保留一组可空的子事件，`W.children` 配一个自己处理空组的判断（实测空组返回 False）。不要用 `W.child` 读单个可选子事件。陷阱：`W.not_` 包 `W.attr` 时空值取反变成满足（`where.py:96-97`），「没有缩量」和「缩量没算出来」被当成一回事。

### 5.4 「还没放进 app」和「会话决定不放」
- **要分**，因为你能做的事不同：前者是会话欠的活，下一轮自然消失；后者是会话做过的判断，不同意就点 ⚑。
- **只要两态**：`unmapped`（对应表里没有这一行）、`excluded`（级是不放，悬停写原因：「只是背景」「出现太少」「等你回答」「量过，看得出没多大用」「已由放量突破的沉寂字段管了」）。「会话选了 detector 但没接进 app」（如 `TrendSegment:sideways`）这一态取消：会话要么接进去，要么定成不放。
- 都不标红；pattern 页头只显示个数。

### 5.5 未归类时 pattern 页显示什么
- 只显示 groups：未归类不是一个 pattern，没有定义；把不相干的几组名字并成一张表再给计数，正是 sim F5 撞上的假话。每组组头本身就是它的顶层名字串。

## 6. 提升空间

**能省掉或合并的步骤**
- **P1 「没画还是没有」只对必须有的名字问**，和定级、偏离、切短合成每轮开头的一张单子，一次列完、可以只答一部分。票 09 原来的硬步骤（每个翻成可有可无的名字都要问）、上一轮转给票 09 的「首次归组时的切短检查」都并进这张单子；有更好、只是背景的名字，缺了也不用问。
- **P2 定义能免掉提问**：名字的定义里写了「有更好」「只是背景」「W 形 V 形都算」，会话就不问级、不问意图。
- **P3 改必须项不用「投票」**：你说一句、指出图，会话改级、列旧正例（5.1）。

**能交给界面或会话机械做的**
- **P4 偏离只在写过 app 后算**，参照是对应表的两级；写 app 前不判，不会出现「什么都没改、偏离跳到另一组」。
- **P5 像但不买按差分组**：理由多半从差里读得出，不用写字。
- **P6 自动并进跟着「当前买点」走**（定义见阶段 1）：补一个缺的框从「跳过去、画框、进 edit 的 others 点收」三四下变成两下；「第一次停留会并、回来就不并」的前后不一随之消失（sim F11）。上一轮的冻结规则防的是以后补画的框悄悄进了旧买点，现在只进当前买点、只在 bracket 当面伸长时并进，不再悄悄。
- **P7 「画了没收」机械查**：同一张图上买点左边任意远处有同名、没收进成员的框，就在缩略图那一行和必须项单子里标出来，缩略图往左画到它为止（sim N2、critic R3：固定窗口总有更远的，WHLRP 的横盘在 53 根外）。
- **P8 近义词一次合并**：vocab 里「并进另一个词」，只新增一条记录，所有框随之换名。这是把 M5 从「逐框改名」变成一次操作的唯一办法；起名时相近词排前、悬停显示定义，减少重起。
- **P9 label 检查只看翻过的**：成本随翻转次数涨，不随总图数涨（critic R9）；因结构变化而翻的（改了必须项后改成像但不买）自动跳过。
- **P10 名称轨顺序**：一律照上一轮的两两比先后（按时间），有没有 app 都一样；分层只在 pattern 页做。必须有的名字在还没画过它的图上也给一条空轨，缺什么一眼看得出。（v3 原写「有 app 时可有可无紧跟它依附的那一段」，撤回：名称轨是画框的地方，一个买点要读成从左上到右下的台阶，横盘时间上在放量突破前面，把它的轨挪到放量突破后面台阶就断了——ux 第二版意见，接受。）

**你要记的能去掉的**
- 进度和下一步谁做：pattern 页头的事实（第 12 节第 7 条）。
- 背景框画全没有、哪个是背景：写 app 时会话问一次。
- 哪些词进了 app、是哪一级：pattern 页的分层本身。
- 像但不买为什么不买：多数情况结构差已经写了。
- 朱红要不要我处理：不要。

**先不做、等证据的**
- 偏离组上一键「把标出的画了没收的都收进来」：等第一批标注证明切短常见再做（V1）。
- 界面上「交给会话」的按钮（sim F14）：界面不连会话，做了也只能写一个请求文件等下次会话读；先靠技能的触发词（「看看我的标注」「XX 到哪了」）和页头的个数提醒（转票 09）。

## 11. 交用户定的方向题

**D1 可有可无的东西在哪里表达？**（critic 5.2 的提法）

这决定画框那一刻你要不要想「这个是不是必须的」。

- **照常画，写 app 时会话问（推荐）**：你看到什么画什么；会话写 app 时，对出现在一部分或全部正例里、定义又没说清的名字问一次「买的理由 / 有更好 / 只是背景」，必须有的才逐张核对缺没缺；写完后 pattern 页按级分层——顶层只剩必须有，有更好的挂在它依附的那一段下面（比如横盘挂在放量突破下面，虽然图上它是单独的框）。代价：pattern 页的层级和图上框的套法可以不一样，要用两个不同的记号分开；写 app 时多一张单子要答。
- **画的时候就表达**：顶层框就等于「每个正例都得有」；有时有的，要写成后一个框的属性或套进一个大框。pattern 页和图上一样，所见即所得。代价：画框时就要定它是不是必须的；定错了要逐张回头改图，图越多越费事；横盘这种排在前面、套不进后一段的，只能改写成属性。

推荐第一种：「是不是必须」要看过好几张图才说得准，放在写 app 时问一次，比每张图画的时候定更省、更准；它也守住了票 01 已定的「标注时不区分 node 和 where」。

**D2 同一个 pattern 里，点名字时带上的那些属性，默认是「有」还是「没看过」？**（sim F3；与 `ux.md` 第 7 节第 1 题是同一题）

已定的做法是「默认全带上、按图勾掉没有的」，待验证里只担心你懒得核对。sim 实测出过两个更直接的问题，界面已经消掉一半：属性原先跟着名字走、不分 pattern，会把别的 pattern 里用过的属性带进来——ux 已改成只带当前 pattern 里同名框用过的；原先退不回「没看过」——已改成再点一下就回去。剩下的一半：同一个 pattern 里，带上的属性如果直接算「有」，你没逐条看的那些也成了「有」，会话照着写 where，事后分不出哪些是真看过的。

- **默认没看过，点一下才算有（推荐）**：带上的属性照样列出来省得你找，但都是「没看过」，点 `true` 或 `false` 才算判过。代价：每个属性多点一下。
- **维持默认有**：标得最快。代价：上面那批假证据，只能靠你逐个勾掉；勾漏的你和会话都看不出来。

**推出来的改动（不单独问，请过目）**

- 对照开关换图不再自动关（ux 方向题 1 同此）：自动关原本防「看多了 app，标注往 app 的样子靠」，你 2026-10-26 定了看着 app 标是你的自由，理由已经没了。
- 自动并进跟着选中的买点走，取代「只在放买点那次停留里」（P6）。
- 像但不买不受偏离规则限，计数分母只数正例：由「像但不买」的定义推出。
- 会话每轮列出无结构原因翻过 label 的买点问「那天看得见吗」：由方向文档第 3 节「label 只说当天」推出，成本只随翻转次数涨。
- vocab 加「并进另一个词」：近义词是唯一会随图数累积、又只能逐框清的一类，这是把它变成一次操作的最小改动。
- 「骨架」「顶层」「必须有」「elements」「groups」等要不要进词表（sim F21、ux 方向题 3）：按项目规矩只提示，交 lead 一并问。

## 12. 牵涉界面的改动（给 ux）

与上一轮 `final_report.md` 不同的地方；配色、字体、悬停规则照已定。U 编号指 `ux.md` 第 4 节。

1. **pattern 页两种样子**：没有 app 时平铺（名字、子框按几何套、属性计数，`in k/N` 只在不足全数时出现、分母只数正例，U2），**不按多数定主组、不判偏离**（mock_v3 照 v1 在写 app 前就按多数判了偏离，要改：S 下写 app 前把没横盘的正例标成偏离、旁边就是挪走的下拉，等于请你挪走会话一问很可能答「有更好」的样本，critic 同此）；有 app 时按对应表分层：顶层 = 必须有（按 app 先后），每段下挂依附它的可有可无、必须没有；底部 `excluded`、`unmapped` 两区（U3）。「挂在下面」的记号和框套框的 `⊂`（U14）分开。
2. **偏离**：以对应表里的必须有、必须没有为准（U2 的「参照骨架」改成这两级）；没有 app 不判。偏离组 `−X` / `+Y` / `order`（必须有齐了但先后和 app 不同），普通签不标红，排最前（U2 同）。有 app 后 groups 只按这两级分，可有可无、`excluded`、`unmapped` 的名字不影响分组；第一次写完 app 时组会突然合并（有横盘、没横盘并成一组），groups 标题旁一个等宽小标识说明现在按什么分（如 `by: required`，sim）。
3. **像但不买**：按差分组（`−X`、`+Y`、`=`），附 `app:buy k/n`；`−X` 只算排在它最后一个已有必须有之前的（sim N4）；属性计数里正例和像但不买分开（sim F7）。
4. **「画了没收」标记**：同一张图上买点左边任意远处有同名、没收进成员的框，在缩略图那一行和必须项单子里标出，点这个标记一下就收进（sim：远处的框拉一下并不进，只能去 others 点）；缩略图往左画到它为止（P7）。缩略图的行 = 必须有 ∪ 这段时间画了的名字，缺的那行空着（U15）。
5. **买点 edit 块**：有 app 时 members 链按必须有对齐、缺的画空槽（U5），不另挂提示签（sim N3）。
6. **自动并进跟着「当前买点」走**（P6）。「当前买点」= 这张图上最后一次放下或选中的买点；画框、选中框都不改变它（sim 第二轮：mock 里画完框选中物就变成框，买点不再是选中的）；选中另一个买点就换成它，换图或点空白处清掉；它的 bracket 在主图上一直加粗，edit 栏可以同时显示正在编辑的框。从缩略图跳来时，跳到的买点就是当前买点。前提是框能拖边改起止（sim 第二轮：mock 里从框边往外拖会新建一个重叠框）；P6、E2、阶段 1 都假设框能这样拉长。
6a. **elements 一律按这个 pattern 的全部正例算**，不只按主组（sim 第二轮 K1：只按主组算时，偏离一多 n 就很小，取其一的另一支会显示成 0/0 被藏掉）。写 app 前平铺、写 app 后分层，分母都是全部正例。
6b. **偏离组不催用户**：它不算 `ask`，界面上只有挪走 / 改成像但不买的下拉，没有任何「待处理」提示。「真没有也还算这个 pattern」的答法不在界面上，在会话的单子里答（等于把它从必须有改成有更好），所以界面不需要第三个落点（sim 第二轮第 2 条）。
7. **pattern 页头：一套，不两套**（sim F4、ux U17、critic 同步意见）。ux 的 `todo user / session` 和这里的事实条合成一行，全是现算、不新存状态，为 0 或没有就不显示：
   - `next`：按优先级机械推出一个——`answer`（`ask` > 0）> `session`（还没 app，或 `unmapped` > 0，或有没处理的 ⚑）> `blind`（最近一次盲看的 app 版本旧于当前版本）；都不是就显示 `next: you`，悬停「继续改、调参还是送检，你定」（这一步取决于你对「剩下的毛病值不值得修」的判断，机械推不出；空着会被读成「没事了」，sim J5）。
   - `ask n`：你的待办只数这一项（会话问了你还没答的），点开看是哪几个问题。偏离组、定义空着、名称没定义都不算你的待办——它们要么会话会在单子上问（变成 `ask`），要么只在要用时才问。
   - `unmapped n`、`⚑ n`：会话欠的。
   - `app` 编号与版本、最近一次盲看的 app 版本、`holdout k`：进度事实，可放悬停。
   - 数据来源：对应表文件（app 版本、哪些名字有行）；会话问题文件（`ask`，每条记问题、指向的名字或买点、问出时的 app 版本、答没答；归票 09）；⚑ 记录（会话在对应表里标「已处理到哪条 ⚑」）；盲看标记（每条带 app 版本，票 08）；最后检查的账（票 04）。
8. **属性三态**：用 ux 的做法——保留 `true` / `false` 两个按钮，再点一下已选中的那个回到没看过（单按钮循环要记顺序、「没有」要点两下，两个按钮一眼看得出当前态）；带上的属性默认没看过（D2 推荐项）；同名子框存在时那一行锁成有，显示「⊂ 缩量 true」、不给按钮（同一特征只留一种入口）。属性候选只取当前 pattern 的买点成员里同名框用过的（ux），跨 pattern 带入因此消掉。
9. **起名**：措辞相近的词排在前面，悬停显示定义；**点下名字后，edit 里名字下面直接显示它的定义一行**，不靠悬停（sim：X2 要在挑词那一刻提醒，没人会去悬停；ux U11 把写过的定义收进悬停，正好拿掉了这个时刻，要改）；改一个词的措辞时显示「用在 n 个框上」。vocab 加「并进另一个词」。
9a. **X3 的当场提醒**：选中买点时，主图上买点之后那段 K 线蒙一层浅灰（不藏，暗一档），一直提醒「这之后是后来的事」；label 在 buy 和 no_buy 之间改的那一下，按钮旁一行小字「理由要在这天看得见」（sim）。

10. **`let_go`**：从对照结果那一栏挪到框自己的编辑区（sim：它挨着朱红的 `missing` 最顺手，误用一次就悄悄丢一个反例）；标识符改成直接说作用的词，别和会话的 `excluded` 撞（critic R10，取名交 ux）；悬停「只表示你标宽了，这一处从样本里拿掉；app 认错不用标，系统已经知道」。

11. **对照开关换图不自动关**（U8 同）。
12. **朱红的意思**：表示 app 和你对不上，不是你的待办（sim F8）。框一级的 `missing` / `detected` 不改色、不作方向题（ux 判，flow 接受）：框级的红只在你自己打开对照时出现，回答的正是「app 在这一段上认没认出」；「读成我的待办」已由悬停和 `next`（待办只有 `ask`）接住；为少一点红去动你定的配色规则不值。
