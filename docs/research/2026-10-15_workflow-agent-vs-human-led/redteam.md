# 红队：agent 主导 vs 人类主导

本文件所有项目内路径均相对 repo root；记忆文件指 `~/.claude/projects/-home-yu-PycharmProjects-Trade-Strategy/memory/` 下的文件。
读者是下一轮 AI。本轮不跑任何读涨跌的实验，所有数字都出自已有的票和记忆，标「推演」的是我从已有数字推出来的，没有实测。

状态：终稿。第 1 步（独立论证）见第一～七节；第 2、3 步（审 constraints.md / advantage.md，各一轮七条挑战，全部化解）见第八、九节；收敛后仍悬着的事见 9.3。

**一句话结论**：「谁主导」是个假二分。决定结果的是裁判独不独立、验证数据有没有浪费，这两样都该写成事先批准、经独立审计的规则。规则到位后，A、B 只差「训练段内圈谁临场推进」这一格，归 agent（理由是它的每步选择都入账、可打折），差距是二阶的。非要二选一选 A，但 agent 不当裁判、不决定动用验证段。

## 零、先把问题拆开：A 和 B 到底差在哪

评判轴只有一个：最后拿到的 pattern 加买卖规则，在新数据上是否真有大优势。从这个目标倒推，结果由三个因子相乘决定：

1. **候选池里有没有真货**：生成候选的来源够不够宽、够不够好；
2. **训练段挑选会不会把假货当真货送上去**：挑选越宽，靠运气或靠系统性偏差冒出来的假货越多；
3. **没碰过的数据能不能认出真货**：验证段只用一次，30 个分散买点要方向领先约 0.35～0.4 才看得出（`issues/12` 第六节第 5 条）。

第 3 个因子完全由数据决定，跟谁主导无关。所以 A 和 B 的差别只能落在 1 和 2 上。

再看工作内容本身。两种方式下，写 detector、跑扫描、算对照、出图、记账这些活都是 agent（以及它写的代码）在做；看图、说形态、每周挑票都是用户在做。**两种方式真正不同的只有一小块：谁决定下一步试什么、谁决定什么时候停、谁决定把候选送去验证。** 把这一小块讲清楚之前谈「谁主导」，容易把「谁干活」和「谁拍板」混在一起。

## 一、替 A（agent 主导）写的最强论证

**A1. 用户自己定义的角色就是 A 的形状。** `~/.claude/CLAUDE.md` 写明用户是「策略方向的决策者」，不是参数的决定者，要节约心智负担。B 的字面含义是用户决定每一步试什么，这恰好是用户说过不想做的那一层。这一条单独看是「用户偏好」，不在评判轴上；它进评判轴的路径是**可持续性**：唯一干净的裁判是上线后的新数据，按每周一只要约七个月攒 30 个买点（背景文件第二节难题 1）。一个要用户每步拍板的流程，跑不满几个月就会被放下，最后那个裁判根本攒不起来。

**A2. 用户最看好的来源是 agent 原生的活。** 用户认为公开规律和常见形态的优势多半已被做掉，挖数据「是唯一可能找到没人写过的东西的来源」（`issues/10` Purpose）。挖数据要把几百条特征逐条按同日对照算一遍，这是 agent 和代码的活。B 会把挖数据的节奏卡在用户的注意力上。

**A3. 诚实记账要求完整记账，只有 agent 记得全。** 判优要按「试了几条」打折（`issues/10`）。agent 的每次尝试都是一次运行，能完整记下来；用户看图时脑子里想过又放掉的形态，账本记不到。现有账本连「大涨段轮不算尝试」都写进了规则（`chart_workflow/ledger.py` 文件头），也就是说看 300 段赢家时想过的东西从设计上就不计数。

**A4. 大优势的门槛够高，宽搜索的「运气税」交得起（推演）。** 训练段 2 年、买点分散时，看得出的方向领先不到 0.05（`issues/09` 第 69 行：白得的 0.10「是分散长相 2 年门槛的两倍多」）。大优势默认要 0.15，约是这个门槛的三倍。在 K 条互不相干的候选里挑最好的，运气能摆出来的幅度大致随 K 的对数缓慢增长；试 100 条和试 10 条相比，运气税只多出约一半（推演，按独立候选估，候选相关时更小；`project_tune_gates_reduce_before_joint.md` 实测相关候选的挑选噪声乘数 0.9～1.7、与格数几乎无关）。所以「搜得宽会过拟合」在 0.15 这个门槛下不是主要风险。**（审 constraints.md 后修正：这一条只对每天命中一次以上、分散的规则成立。constraints.md 2.2 的表显示，每周命中一次的规则试 100 条就能凭运气凑出约 0.17，运气税在稀疏规则上很重。）**

### A 的致命弱点

**宽搜索在这份数据上首先找到的是系统性偏差，不是运气。** A4 只算了运气税，没算偏差税。本项目的历史正好说明：

- 现有 score 跨 27 个配置回归波动率 R²=0.919，bo_only 的 +72% 控制波动后完全归零（`project_path2_app_optimization_workflow.md`）；
- bottom_burst v2 由 5 个 agent 组成的 workflow 调参，score +115%、「过 gate」、多窗口稳（`project_bb_v2_tb_optimization.md`），后来整族被认定是在读波动率；
- 换边端点的因果泄漏让方向领先显示 +0.304、六格全同号，「看起来比任何真实信号都稳健」（`project_path2_edge_causality_lesson.md`）；
- 挖数据只用一个「跌掉九成以上 + 成交额贴着下限」的组合，就白得约 0.10（`issues/09`）。

这些偏差的量级（0.10～0.30）大于运气税（推演约 0.05～0.07），而且不随样本变大而缩小。一个宽、快、自主的搜索器，会优先把这类偏差送到排名最前面——这不是 agent 笨，而是搜索器对「哪里分数高」最敏感，偏差恰好就是分数最高的地方。现在的尺子（同日对照、波动配对、判整套）已经堵掉了波动率这一个，但幸存者偏差和因果泄漏还在，下一个没被列入禁区的偏差区也还在。**A 若包括「agent 自己判断候选是不是真的」和「agent 决定何时动用验证段」，就是让搜索器兼任裁判。**

## 二、替 B（人类主导）写的最强论证

**B1. 本项目每一次「agent 自主优化出好成绩」最后都被推翻了。** 见上面 A 的致命弱点。人主导至少能在每一步插进一次怀疑。

**B2. 人看图抓到过 agent 漏掉的前瞻偏差。** NVX、BRNS 的假买点，用户的三条观察全对，其中一条是 `tb.outcome` 用了买点之后的数据（`project_tb_buypoint_modeling.md`）。人对「这个买点在当时根本买不到 / 这段走势不像真的」的直觉，是代码检查覆盖不到的一类错误检测。

**B3. 只有一次的验证机会，不需要吞吐量。** 验证段只用一次，最多改一次再验（`issues/01` 访谈记录）。整个流程第一遍最多送 1～2 个候选去验证，agent 多跑一百条也只是在训练段上多排一百行，B 的慢不损失结果。

**B4. A 会把人的否决权架空。** agent 跑出一张一百行的账本、在关口交给用户「请批准动用验证段」，用户没有上下文，只能盖章。B 让用户全程在场，关口上的否决是真否决。

### B 的致命弱点

**人的形态在本项目里没有一次接近过门槛，而且人的试错不入账。**

- 用户提出的「孤立跳空放量大阴线企稳」：方向成绩比同日同波动普通买入 −3.5 点（默认口径）、−5.2 点（放宽后，分辨得出）（`project_gap_black_candle_study.md`）；
- 用户的「跳空高开 + 阴线 + 放量」在全市场方向领先约 +0.045（`project_tb_v1_revert_toxic_gate.md` 延伸验证），是大优势门槛的三分之一；**（审 advantage.md 后更正：这 +0.045 是对随机日基线的，含择时、不扣波动，不是对同日对照；按现在的尺子只会更小。它和上一条不是同一个形态，不能直接推出「换同日对照就不看涨」。）**
- 用户在 tb 毒药闸那次指定的口径（TR 中位数归一），实测弱于绝对跌幅（同一文件「口径拍板教训」）；
- 用户原来的看图办法有五个问题：只看赢家、按涨幅原值排、用 bo_only 当索引、扫描范围盖住验证段、不写成规则也不记账（`issues/14` 背景）。**（自我更正：这一条反对的是「人单干」，不是 B。那五个问题出自没有流程、没有 agent 参与时的独自浏览；B 本来就含 agent 的自动化辅助，而这五个问题正是在「agent 指出、用户拍板」的模式下修好的。这一条从 B 的致命弱点里撤下，只保留为「人单干不可行」的证据。）**

B2 是真的，但它说的是「人擅长挑错」，不是「人擅长找真货」；B 要的是后者。再加上 B 让人决定「下一步试什么」，这个决定主要靠看训练段里的赢家和输家形成，每看一次都是一次不入账的挑选——这正是挖数据三条纪律要堵的东西。

**还有一条只属于人的污染**：用户扫描过 2025-01..2026-06，看过 2026 上半年的大涨股（`issues/01`、`issues/14`）。用户说「没怎么看」，但脑子里的印象删不掉，用户提出的形态拿 2026-01 起的验证段去验，有多少算没碰过，没法量。代码可以按日期截断，人不行。（这一条要打折：agent 这边也不干净，见第六节第 5 条。）

## 三、两份最强论证合起来说明了什么

A 的致命弱点是「搜索器兼任裁判」，B 的致命弱点是「人的挑选不入账、人的眼睛没有找到过真货」。**两个致命弱点都不是「谁主导」造成的，而是「裁判不独立」造成的。** A 里裁判是 agent 自己，B 里裁判是看过训练段赢家输家的人自己。

本项目已经有一份更早的结论说的就是这件事：2026-07-25 的 agent team 定下「工作流 = 否决闸阵不是搜索引擎」，人类标注只有三种用途——诊断、单向否决（10～30 个样本）、语义来源，「绝不当目标函数」；同一份研究还把「agent team 当搜索循环」判死（`project_path2_app_optimization_workflow.md`）。这两条既不支持 A 也不支持 B，它们支持「裁判写成规则，人和 agent 都只当选手」。

## 四、假二分：按决策类型分权

「主导」把好几种性质完全不同的决定捆成了一个。拆开以后，每一种都有明显更合适的主人，而且这些主人不是同一个：

| 决定 | 性质 | 合适的主人 | 理由 |
|---|---|---|---|
| 提候选 | 生成，越宽越好（偏差另管） | 双方并行：用户出形态，agent 挖数据和读文献 | 两边的候选来源本来就不重叠 |
| 把形态写成规则、确认「是不是这个意思」 | 翻译 | agent 写，用户确认 | 只有用户知道自己的意思；`project_path2_app_authoring_skill_design.md` 已定「形态符合意图」由用户看图把关 |
| 下一步试什么（训练段内圈） | 可逆、高频 | agent，在事先定好的尝试预算内 | 每次尝试都入账；用户每步拍板既耗心智又不入账 |
| 收紧条件（看输的例子） | 最危险的一步，在训练段上拟合 | 谁做都要入账；规则见第七节 | 人看输家和 agent 比特征，本质都是在训练段上找区别 |
| 放弃一个候选 | 可逆 | 事先定好的规则，agent 执行；用户只能往更严的方向改 | 人对自己的形态有沉没成本，agent 有「再加一个条件」的惯性 |
| 毕业（送去验证的资格） | 规则判定 | 规则，agent 算；但 `issues/14` 第 5 步五条要改：第一条「训练段原始领先 ≥0.15」改成按扣掉运气（按规则自身稀疏度和试了几次算）、扣掉已知偏差区之后剩下的领先来判（constraints 反挑战，我接受） | 不该有人「觉得可以了」；按原始领先判，稀规则会凭被抬高的成绩毕业 |
| 动用验证段 / 动用那一次改了再验 | **不可逆** | 用户批准，但只能批准规则已判过线的候选 | 不可逆的事归人；人不能把没过线的送进去 |
| 上线、停用 | 不可逆、涉及钱 | 用户 | 同上 |
| 每周挑票 | 部署时的一层额外挑选 | 用户（已定） | 见第五节第 2 条：这一层目前没人验证 |
| 节奏（多久跑一遍） | 受新数据速度限制 | 基本由数据决定 | 第二遍起要等新数据，谁主导都快不了 |

按这张表分完，「agent 主导还是人主导」只剩下「训练段内圈谁来推」这一格。这一格交给 agent（在预算和账本里），其余按表。

## 五、两种方式都漏掉的约束

1. **两种方式共用同一个瓶颈。** 验证段只有一段、只用一次；第二遍起只能靠上线后的新数据。流程第一遍能诚实送去验证的候选只有 1～2 个，不管谁主导。所以 A、B 之争对结果的影响，远小于验证段怎么定（`issues/01` 仍在访谈中，未定稿）、尝试预算怎么打折、偏差禁区怎么划这几件还没定的事。

2. **每周挑票是一层没人验证的挑选。** 判优判的是「pattern 加买卖规则」的全部命中；部署时用户从名单里每周挑一只。用户挑的这一只，比名单平均好、差还是一样，现在没有任何设计去量。这一层不随 A、B 改变，但它直接决定用户真实拿到的结果。不花验证数据的补法：每日名单存档时连同用户挑了哪只一起存，上线后比较「挑中的」和「同一周名单里没挑的」。

3. **新数据攒得比草稿说的快，前提是验证用全部命中而不只是挑中的那只（推演）。** 背景文件第二节难题 1 的「每周一只、七个月 30 个买点」，是按用户挑中的票算的。每日名单是存档的，上线后的核对可以用名单上的全部命中（判优标准本来就是判全部命中对同日对照）；一个每周命中几次、分散在不同股票上的 pattern，新数据攒到 30 个买点用不了七个月。这会改变「流程卡在数据上」的严重程度，值得 lead 在总报告里核一下。

4. **成本。** agent 这边：全池每组参数约 55 秒，80 组约 75 分钟（`project_tune_gates_v3_review_2026_10.md`），算力不是约束。真正稀缺的是用户的注意力和那段验证数据。B 花的是前者，A 若无约束地动用验证段花的是后者，后者更贵，因为补不回来。

5. **agent 也不干净。** 我上面说「代码可以按日期截断，人不行」，但 agent 的先验同样被 2026 年污染：记忆文件和研究文档里有包含 2026 年结果的结论（跳空阴线研究用的是 2025-01..2026-06，营收研究的分年结果含 2026），模型本身的知识也到 2026 年 6 月。对纯技术形态这条影响大概不大，对带题材、带外部信息的方向影响更大。结论：验证段对人和 agent 都只是「pattern 成绩没被看过」，不是「这段行情没被知道过」；只有冻结之后才到来的新数据对两边都干净。

## 六、自审：我上面哪些论点是弱的

强论点（我愿意拿去和人争）：
- A 的致命弱点「宽搜索先找到系统性偏差」：有四条项目内实证，量级可比；
- B 的致命弱点「人的形态没接近过门槛、人的挑选不入账」：有实证，且账本规则本身写明看大涨段不算尝试；
- 「裁判不独立」是两边共同的病：直接从前两条推出，且与 2026-07-25 的旧结论一致；
- 每周挑票没人验证：从判优对象和部署方式的差异直接推出。

弱论点（只作参考，别拿来下结论）：
- A1 的「可持续性」：我没有证据说用户会因心智负担放弃流程，这是合理推测；
- A4 的运气税估计：按独立候选的简化推演，没实测；
- B4 的「人会变成盖章」：没有项目内实例，只是一般规律；
- 第五节第 5 条 agent 知识污染的量级：说不清；
- 第五节第 3 条新数据速度：取决于 pattern 的命中频率，现在没有 pattern，算不出具体月数。

补记（审两份稿子时发现、对我自己同样成立的两点）：
- **证据库的归因偏向**：关于「人和 agent 谁更擅长」的全部证据都来自 agent 写的票、记忆和报告。agent 的发现被详细记下，用户的贡献多被记成一句「用户拍板」或「用户纠正」。所以「人的独特长处很少」这类结论，有一部分可能只是记录方式造成的。我第二节里关于人的负面证据是实打实的实测成绩（跳空阴线 −3.5 / −5.2），不受这条影响；受影响的是「人在过程里帮了多少忙」这类判断。
- **「人主导」与「人单干」要分开**：项目里人的负面证据大多出自人单干（没有流程、没有 agent 参与），不能拿来否定 B。

我也要警惕自己的动机：红队的角色容易让我偏向「两边都不对、第三条路」这种看起来最稳的结论。我检查过一遍：第四节的分权表里，有好几格的答案是「agent」（内圈、执行放弃、算毕业），有好几格是「用户」（确认意思、不可逆决定、挑票），不是为了中庸而对半分，每格都有单独的理由。如果被问「非要在 A 和 B 里二选一」，我选 A，理由见下一节。

## 七、我的立场

**按用户给的二选一，选 A，但 A 必须先去掉两样东西：agent 不当裁判，agent 不决定动用验证段。** 准确说法是：规则当裁判，agent 推训练段内圈，用户在固定关口出形态、确认意思、批准不可逆的事。

理由按评判轴排：
1. 决定最终结果的是裁判是否独立和验证数据是否被浪费，这两样都应该写成事先定好的规则，不归任何一方「主导」；
2. 剩下唯一有争议的一格（训练段内圈谁推）交给 agent，因为它的每次尝试都能入账，而入账是打折的前提；用户的形态作为候选来源照样进内圈，地位和挖出来的候选一样；
3. 用户的心智负担放在三类事上：说形态、确认「是不是这个意思」、批准不可逆的事。这三类都是只有用户能做、且频率很低的事。

和 A 无关、但比 A 还是 B 更影响结果的几件事（建议 lead 一并报告）：
- **收紧那一步拆年用**（默认，待验证）：看输的例子找区别时只看训练段的一年，另一年留作内圈自查。现在的毕业条件有一条「训练段两年都同号」，如果收紧时两年的输家都看过了，这一条就失去检验意义；
- **尝试预算写进规则**：每个候选最多收紧几轮、每轮都算一次尝试（具体轮数待验证）；
- **每日名单连同用户挑了哪只一起存档**，上线后量用户挑票这一层的价值；
- **验证段的动用权写成规则**：只有过了毕业五条的候选能送；那一次「改了再验」怎么用，在第一次打开前就写好。
- **裁判要先接受独立审计**（审 constraints.md 时补上，也是对我自己立场的修正）：「规则当裁判」的前提是规则的实现真的照写的那样工作。本项目有静默失效的先例——tune-gates-v3 评审发现复核阶段被写死成必然撤回，项目 CLAUDE.md 引用的 eval-discipline skill 并不存在。裁判由 agent 写，就不能由同一个 agent 宣布它可信；上线前要换一个新会话做对抗性复核，再加上用手算数字写成的测试。没碰过的数据要靠物理隔离来锁（研究环境用截到训练段末尾的数据快照副本），不能只靠配置里的截止日期。
- **候选排名按「去掉已知偏差区之后的领先」排**，不按训练段原始领先排：一年只能送 1～3 个候选去验证，送的总是排名第一的；按原始领先排，第一名会偏向几项偏差叠加出来的组合。

## 八、对 constraints.md 和 advantage.md 的挑战

### 8.1 对 constraints.md（已发出，2026-10-15）

constraints 的核心主张：判决次数一年约 1～3 次是硬上限，A、B 的吞吐都过剩；假发现主要看规则命中稀不稀，不看试了几次；看图收紧会把规则变稀，对照页没排除看过的样本会把成绩抬高约 h/N；精度不随候选数上升，所以规则是一阶问题，A/B 是二阶问题，二阶上 A 略优。

我核过、同意的：h/N 口径成立（方向成绩 =（先上−先下）/全部买点，`research/02-resolution.md` 第 32 行；普通买点平均约 −0.02，所以每个看过的赢家抬高约 1/N）；对照页确实不排除看过的样本（`chart_workflow/contrast.py` 无任何读大涨段清单的代码）；「新数据核对用整份名单」与我第五节第 3 条独立得出同一结论；「验证段不打开会自己变大」是新的有用观察。

发出的七条挑战：

- **C1【强】固定的「可证实性下限 600 个独立买点」与已定决定冲突，并替用户做了方向选择。** `issues/12` 第六节第 5 条已批准「每周一只、约 30 个买点也可以，前提是领先足够大」。按 constraints 自己的公式，所需独立买点约 (2/领先)²，领先 0.4 只要约 25 个。固定的高频下限会把搜索推向高频规则——最常见、被做得最透的那类（文献效果 0.02～0.05 全是高频的），可能正好排除大优势最可能藏身的稀有事件区。这是方向取舍，应交给用户。
- **C2【强】「精度不随候选数变 → A/B 二阶」与它自己的数字矛盾。** 它第 3 节算过 π=0.2%、一年 20 个形态时池里有真货的概率只有约 4%；π 低时成功率 ≈ min(1, 池中真货期望数) × 精度，前一个因子只由候选数决定。反方向：一年只判 1～3 次，送的是排名第一的候选，而排名第一的偏向叠加偏差（它第 7 节的担心），搜得越宽精度可能越低。两个方向都说明候选数是一阶的，只是净效果符号不定；扭转符号的办法是按「去掉所有已知偏差区之后的领先」排名，不按训练段原始领先排名。
- **C3【强】第 4 节表格把 B 的吞吐算成人工劳动，曲解了 B。** B 下用户可以一次拍板「按这套规则挖 2000 条特征」。B 限制的是拍板次数，不是候选个数；A、B 的真区别是「看了上一步结果才决定的下一步」由谁做。
- **C4【中】「工具层面上锁，agent 没有任何读 2026 的路径」照现写法做不到**：`chart_workflow/config.py:22` 的 `train_end` 只是配置值，数据目录是全量的，agent 有 shell，过去的 agent 研究读过 2026。真锁 = 截到 2025-12-31 的物理快照副本 + 账本审计。另外，裁判也是 agent 写的，本项目有静默失效先例（tune-gates-v3 评审发现复核必然撤回；项目 CLAUDE.md 引用的 eval-discipline skill 不存在，已 ls 核实），裁判要先经独立审计才能信任。
- **C5【中】「只在名单前几名里挑」**：排序是没验证过的分数，本项目历史上的 score 在读波动率，限定前几名可能把「偏爱高波动白输约 0.04」固定下来而非封顶。
- **C6【中】2021-10..2023-12「只用来否决」挡不住最担心的那类假货**：底部类偏差越早越重，偏差假货在那段看起来更好、会被放过；它挡的是噪声假货，下限已经挡了；跨候选反复用于否决，它也不再干净。
- **C7【弱】排除看过的样本挡不住题材相关**（看过 5 只囤币股，规则会命中同周另外 20 只没看过的同题材股）；按年份拆开应当是默认，且能保住「两年都同号」这条毕业条件的检验意义。

### 8.2 对 advantage.md（已发出，2026-10-15；读的是它已与 constraints 交叉两轮后的 v3）

advantage 的核心主张：按决策类型分权，整体偏 A；人有证据的独特长处只有两项（数据外信息、看个别命中抓 bug），其余是「权」；放弃、开验证段、上线停用归「人事先批准、agent 机械执行的规则」；A 占优的原因是瓶颈上的活都可计数、可写成规则。

我接受的：S12 双钥匙及「人这把钥匙判价值选择，不判质量」，化解了我第一节 B4「人会变成盖章」的担心；它指出 +0.045 是对随机日基线的，我已据此更正第二节。

发出的七条挑战：

- **D1【强】「A 占优」的理由分辨不出 A 和 B。** 「瓶颈上的活交给工具执行」在 B（人主导、agent 自动化辅助）下同样成立。唯一把 A、B 分开的一格是「下一步试什么由 agent 排队」，它给的理由是「人的时间稀缺」，但它第 4 节自己引了「用户时间不是终点的瓶颈」。按唯一评判轴，这一格的论证是空的；撑得住的是精度论证（人看了结果再做的选择不入账、不能打折）。
- **D2【强】把票 14 的五个毛病记作「人主导的反例」是稻草人。** 那是没有流程、没有 agent 参与时的独自浏览，属于「人单干」；而这五个毛病恰恰是在「agent 指出、用户拍板」的 B 式协作下修好的。我自己第二节犯了同样的错，已更正。
- **D3【强】与 constraints「无剩余分歧」的对齐把 constraints 的错一起带进来了**：S7 与第 1 节的固定可证实性下限（同 C1，与 `issues/12` 第六节第 5 条冲突）；S6 的「挖数据规模只是次一级」（同 C2，π 低时候选数是必要条件，排名第一的偏向叠加偏差）。
- **D4【中】「工具硬截断」现状不成立**（同 C4）；它在 S4 提了「尺子由另一 agent 独立复核」，但独立审计应覆盖全部护栏，而不只是尺子。
- **D5【中】S14 附和「只在名单前几名里挑」**（同 C5）；它自己提的「名单全体 / 前几名 / 人挑的」三条线影子对照已足够，不需要排序约束。
- **D6【中】证据库有归因偏向**：关于「谁更擅长」的全部证据都出自 agent 写的票、记忆和报告，agent 的发现被详细记下，用户的贡献多被记成「拍板」。它自己列的「用户多次纠正 agent 的方法论框定」本身就是能力证据，不只是「权」。（这一条对三份稿子都成立，包括我的，见第六节补记。）
- **D7【弱】两处小矛盾**：「谁都不能拦对方的候选」与「人可以否决某个方向」、与 S3 的 bug 探测器拦截并存，建议改成「可以拦，每次拦都入账」；「内圈想转多快都行」挡不住未知的叠加偏差，建议加「送验证的排名按去掉已知偏差区之后的领先排」。

### 8.3 预先列出的审查清单

预先列出我会专门查的几类问题，免得审的时候被对方的框架带走：
- 有没有把「agent 能做 X」当成「agent 主导就好」——干活的能力和拍板的权力是两回事；
- 有没有引用 agent 在本项目的成功——本项目没有一个 pattern 被证实过有选股能力，任何「agent 擅长找 pattern」的说法在本项目里都没有正例；
- 有没有把用户的 B2 式成功（挑错）当成找真货的能力；
- 有没有把用户偏好（省心智）直接当评判轴，而没说清它怎么影响最终 pattern 的好坏；
- 有没有忽略验证段是共用瓶颈，从而高估了两种方式的差距；
- 有没有漏掉每周挑票这一层；
- 「瓶颈分析」有没有把吞吐量当成瓶颈——用户已说做得快、做得多本身不算。

## 九、再审结果

### 9.1 constraints：七条全部化解（第一轮）

constraints 七条全部接受，修订处在 constraints.md 就地注明「经 redteam 挑战后修订」，我逐处核过（第 95、125、139、168～178、204、235、252～256 行附近）：

- C1 化解：可证实性改成随领先变化，独立买点 ≥（2÷领先）²；稀规则还是密规则写成用户的方向选择。它补了一个我没想到的关键点：公式里的「领先」必须是扣掉运气（按规则自身稀疏度算）和已知偏差之后剩下的，否则稀规则能凭自己被抬高的成绩给自己放行（例：每周一个的规则要剩下 0.4，试 10 次时原始领先要约 0.5，试 100 次要约 0.57）。
- C2 化解：改成「规则是前提；宽的好处和坏处都是一阶，净效果取决于排名口径」，采纳按「去掉已知偏差区、再扣运气之后的领先」排名。它保留的一点我同意：宽是一阶因素，但 A、B 都能宽，所以宽不区分 A、B。
- C3 化解：第 4 节表格重写，第一行写明「宽不是 A、B 的区别」；最后一行承认「B 如果也把这些机械化、也成批挖，就已经是分权方案，只是名字不同」——这正是我「假二分」的论点。
- C4 化解：加第三个硬前提「裁判实现经独立审计」；锁改为截到 2025-12-31 的数据快照加账本审计。
- C5 化解：排序验过之后才限前几名；验全部命中还是只验前几名列为方向选择。
- C6 化解（降级）：它补充，C1 让稀规则重新进来后，这段早年数据挡「稀规则上的运气假货」的价值回来了一部分。我接受——我说「噪声假货已被下限挡住」只对密规则成立。
- C7 化解：默认按年份拆开。它核对了一个事实：第一份大涨段清单 r001 是两年混在一起的（2024 年 169 段、2025 年 131 段），要在第一圈之前分开；代价是判的那一年偶然波动约放大 1.4 倍。

constraints 反过来挑我的两处，都接受：
- 我 A4 的「运气税约 0.05～0.07」只对密而分散的规则成立（第一节已就地更正）；
- 我分权表里的「毕业 = 票 14 五条」没扣运气和偏差，已改（第四节「毕业」一行）。

### 9.2 advantage：七条全部化解（第一轮）

advantage 改到 v4，第 11 节有修订记录，第 7 节末列了撤回的论点；我核过第 0、1、2、5、S12、S14 各处：

- D1 化解：内圈归 agent 的理由从「人的时间稀缺」换成精度（agent 接触的信息全经工具、留在记录里，可计数、可限定为只看汇总；人看图后接触的信息不入账，还会把看过的样本带进成绩），强度标【中】；并承认 A、B 差距是二阶的。
- D2 化解：五个毛病改记为「人单干」，第 0 节加「本项目证据不能否定 B 本身」。
- D3 化解：固定高频下限改为按声称领先换算（与 constraints 的修订一致）；候选数改为一阶、符号取决于排名口径。
- D4 化解，并补了我没想到的一层：物理快照只挡无意读到，挡有意读到要靠用户在 Claude Code 权限设置里禁止研究会话读全量数据目录（用户操作域）；独立审计扩到全部护栏。
- D5 化解：验证段同时报名单全体和前几名，前几名也过线才默认只在前几名里挑。
- D6 化解：证据库偏向写进文件头；方法论审查挪回「能力」，限定为评估和工具层面的能力，不是找真货的证据。
- D7 化解：任何一方拦候选都入账写理由，看过成绩之后才拦的算一次尝试；送验证按去掉已知偏差区之后的领先排名。

### 9.3 三份稿子收敛后仍然没解决的事

两轮之内七加七条全部化解，三份稿子现在的结论基本一致：规则当裁判是前提（一阶）；规则到位后 A、B 只差「训练段内圈谁临场推进」这一格，归 agent，差距是二阶的。下面几点是收敛之后仍然悬着的，交 lead 判断：

1. **三方收敛本身是弱证据。** 三个 teammate 是同一个模型、读同一个证据库（而且是 agent 写的证据库），收敛更像「一个推理被检查了三遍」，不是三个独立来源互相印证。
2. **决定 A、B 的那一格只有推理支撑。** 「人看图后做的选择不入账、会把看过的样本带进成绩」是推理加一处代码事实，没有量过人和 agent 在内圈里各自造出多大的假领先。
3. **未知的叠加偏差没有机械挡法。** 禁区、两证齐赢、跨年代检查只挡已知类型；排名按「去掉已知偏差区之后的领先」能压低但挡不住未知的组合。最后只剩验证段和上线后的新数据兜底——这一点 A、B 都一样。
4. **真货可能本来就没有。** 如果这个股票池里根本没有方向领先 0.15 的东西，三份稿子比的只是「哪种方式失败得更便宜、更诚实」，答案不变，但用户的预期要按这个讲清楚。
