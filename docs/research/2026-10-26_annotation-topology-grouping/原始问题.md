## 引出本次任务的上一条用户消息（逐字）

> 标注界面如何显示 node 之间的逻辑关系，edit tab 显示的是每个 node 的定义，而 vocab tab 显示的是数量统计，但是似乎没有一处可以让用户定义 node 之间的关系，以及哪些 node 凑成一个 Pattern。
> 同样的，在主图中标注时，一个 box 代表一个 instance，那么这些 box 散落在 K线图 中，无法定义哪些 box 是用户意图中的一个 pattern，如图 [截图：原型副图里几条名称轨上的虚线框，左侧一个框孤立，右侧几个框（横盘、⊂ 横盘的缩量、放量突破、回踩）挨在一起] ，左侧的 box 明显是孤立的，而右侧的 boxes 似乎是一个 pattern 的组成成员。但是没有 pattern 的边界，而是将成员散落在 K线图 中

## lead 在上一轮给出的候选方案（只是候选，不是结论，团队应当批判地对待）

- 每个买点带一个 instance 范围，画在 bracket 轨上、与 app 的 match 范围同轨（用户的虚线、app 的实线）；放买点时左边界默认延到相连的框起点，不对就拖；范围里的框 = 成员，不在任何范围里的框 = 只标事件。
- 关系不另设编辑器：先后看位置；不靠位置的关系（如「回踩不破突破价」）写成后一个框的属性，由会话翻成边。
- 加一个 pattern tab：定义（用户一句话）、骨架（会话从各 instance 归纳，带出现次数，⚑ 可标错）、instance 列表。
- 理由：哪几个框构成「这个买点买的理由」只有用户知道；先后看位置就够；pattern 由哪些名称组成要跨图才看得出，交给会话归纳、用户纠错。
