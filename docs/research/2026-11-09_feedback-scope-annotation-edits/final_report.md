## 1. 结论

- **改标注属于反馈迭代的本职，不拦。** 标注在这套流程里是用户意思的说明书，不是定死的考题，也不是成绩的证据；判输赢的只有最后检查（2026 年起的数据），训练段上怎么改标注都碰不到它。用户 10-26「训练段上看着 app 改标注是自由，如实检验只靠盲看和留出数据」、10-18「护栏只拦撤不回的」两条决定都维持。
- **「第一轮定死、不满意另起 pattern」（B）被三方否掉：**
  - 诚实上买不到任何东西：spec 6.7 第 4 条已规定替补上场的算旧 pattern 的新版本，换名字不省检查次数，B 只是更费事的「改」；
  - 锁死错误（SMX 2025-11-24 建在数据错误上的正样本）、丢掉挂在旧名字下的东西（样本、⚑、反馈、mapping 都按 pattern 名挂，工具没有 pattern 改名 / 复制 / 删除，也不记新旧来历）；
  - 第一轮也不更「干净」：11 个正样本日之后 40 根内最高价是样本日收盘的 2.3～17 倍（SMX 那个 96 倍），本来就是看着后续大涨标的（`repro/mc_sample_outcomes.py`）；
  - 与现有文字直接冲突：spec 与说明书约十来处明文允许或预设「迭代中改标注」，禁止的只有「特征定义写下不改」一处；用户历史上已建 51 个框、删 40 个，建 13 个样本、删 2 个（`spec_audit.md`）。
  - `user_sim2` 走的 10 个场景里 7 个在 B 下要么留着用户已不认的东西，要么逼用户把其余样本挪到新名字下。
- **真正要管的是三件事**（都只报不拦，唯一撤不回的检查次数放在送检那一刻）：
  1. **每轮定格、翻转按原因分开报**：会话每轮开头把标注定格一份，这一轮之间用户改了什么、app 改了什么，翻转按原因分开报，「两边互相迁就直到 compare 全绿」看得见；
  2. **定级按「处」数，不按样本个数数**：否则在哪张图上多补几个样本，就能把一个特征推过半数；
  3. **检查次数按来历记**：送检过的 pattern，改来的、拆来的、替它上场的共用一本账；没送检过的随便拆、合、另起。
- **现存缺口：会话看不见「上一轮以来改了什么」。** 标注文件里有带时间的完整历史，但会话唯一允许的读法 `read_annotations` 只给当前状态（`repro/history_visibility.py`）。所以 spec 6.1 的改判提问、6.10「每轮读上次以来的变化」、6.3「是哪条改动造成的」现在都没有数据来源。补法小：读标注的入口加一个「截至上一轮」参数。
- **页面引导**：现有的引导只到控件级（按钮变灰带原因、框边停在样本日等）；「此刻最该做什么」的 `next`（spec 6.8）还没造、照字面也推不全；「做了会怎样」几乎没有（删除无确认无撤销、pattern 定义不说它决定定级、特征定义写完才锁且事先不说）。提案 G1～G7 见第 3.4 节，经 `user_sim2` 全部接受。

## 2. 要问用户的题（措辞经 `user_sim2` 以用户身份读过；详细见 `method_critic.md` 第 6 节）

1. **改标注算不算反馈迭代的本职？**（spec 第 1 节加一句明文）推荐：算——框、样本、属性、pattern 定义、归组随时能改，不拦；会话每版把「你改标注造成的」和「app 改的」翻转分开报。
2. **定级按「处」数，不按样本个数？**（改 spec 1.4「计数一律数样本」、票 15 的验证项 V-15-1）推荐：按处；pattern 页 features 区写处数，samples 表照旧写样本数。实测「底部平稳」现状 3/10，只在 CRNC 补 7 个一键正样本就 10/17 过半；按处数（同一张图上共用至少一个成员框、或成员框之间有用户手动挂的框套框的正样本算一处）现状 1/7，补 7 个仍 1/7，补全部 23 个 2/7。代价：哪几个样本算同一处由会话按成员框自动划，可能划错；用户不用维护它，只有划错会影响某个特征的级时，会话才附链接问「这几个是同一段走势吗」。
3. **送检过的 pattern，改来、拆来、替它上场的共用一本检查次数的账？**（改 spec 1.4「按单个 pattern 记」、说明书 ⑧「不跨 pattern 合起来数」）推荐：共用；没送检过的各自从 0 起。代价：拆成两个以后两个都背旧账的次数。
4. **特征定义的锁怎么落？** 推荐分两步：现在照旧写下即锁，但写之前在输入框提示「写下就不能改，意思变了另起一个词」；会话读改动的入口做好后放开改字（改了会话问「意思变没变」，变了另起一个词并逐张给链接改旧框）。第二步要同步改词条 `path2/GLOSSARY.md:141` 与说明书设计 3。

请过目、不用拍板的：每轮会话的固定动作（3.2）、改动类别表（3.1）、页面引导 G1～G7（3.4）。

## 3. 政策

### 3.1 改动类别（摘自 `method_critic.md` 3.2，经 `spec_audit` 核过、`user_sim2` 表态）

| 改动 | 迭代里能不能改 | 留痕 / 出题 | 会话随后做什么 |
|---|---|---|---|
| 纠错：数据错误上的样本、点错的日子、画错的框 | 随便改 | 不出题 | 下一轮重跑对照，翻转归入「你改标注造成的」 |
| 补充：新正 / 负样本、新框、补属性、新特征 | 随便改 | 新特征照旧挂 `unmapped`；看着后续加的不买理由按「新想法」（先量再盲看） | 定级、map、重跑对照 |
| 收窄：删正样本、挪回 `unsorted` 或别的 pattern | 随便改 | 报告里列出删掉 / 挪走的正样本，点名其中 app 原来认不出的 | 重跑对照；因计数换级的特征必报 |
| 改判 pos ↔ neg，收的框没变 | 能 | 会话问「改判的理由那天看得见吗」（现有 6.1；数据来源靠 3.2 补上） | 同现有 |
| 挪框边；换样本日（界面无挪日入口，只能删了重放） | 能（框边不能越过收了它的样本日） | 报告点名新放在 app 买点日上的正样本、挪到 app event 终点上的框边 | 重跑对照；框边只影响认出档位和 `diff tag`，不影响 match |
| 改特征的意思 | 不就地改，另起一个特征 | 见题 4 | 列出用旧词的框，请用户逐张决定换不换 |
| 改 pattern 定义 | 随时能改（现状） | 会话问一句：改说法 / 放宽 / 收窄 / 换了想法 | 放宽：重看旧的 `off_pattern`、`neg`（盲看作答不能改，失效的挂会话蓝标签、不再算朱红）；收窄：重看旧正样本；换了想法：转下一行 |
| 拆分、合并、另起 pattern | 随时能 | 只在送检那一刻问「它是从哪个送检过的 pattern 改来、拆来的吗」 | 见 3.3 |
| 改反馈 | 能改能删（现有） | — | — |
| 改盲看作答 | 不能（现有，撤不回） | — | 定义变了时整批挂标签 |

改标注时仍有的硬约束（都是现有的）：成员框不能越过样本日；露出后的盲看作答不能改；已写下的特征定义不能就地改；同一版没过、又没有新数据时不能再送检。

### 3.2 会话每轮的固定动作

1. **开头定格**：把「每台机器从 1 号起连续到齐的最大批次序号」（如 `{pc: 171, upc: 0}`）和这个 pattern 当时的样本编号集合，写进 `path2_apps/<app>/mapping.yaml` 的会话状态段。截法的理由：按文件名截会把另一台机器的文件整批算错；按时间截，晚同步来的批次会永远看不见；记「最大序号」也不行——Syncthing 默认按随机顺序拉文件（官方文档 folder `order` 默认 random，本机配置同），同一台机器的高序号批次可能先到；「从 1 起连续到齐」只会多报、不会漏报。写 mapping.yaml 不算 app 改版（上一份报告 R7 的指纹已排除它），mapping 读取忽略不认识的顶层键。
2. **求差**：给 `read_annotations` 加「截至那组序号」重放的参数（小，不违反「会话只经这一个入口读」）；后端用同一段代码出一个只读的「这个 pattern 自上次以来的变化」，会话求差和页面的 `edited n` 都用它。
3. **翻转按原因拆开**：match 只取决于样本日、judgment 和 app 的买点日，所以用户改标注造成的翻转只来自样本级变化（新增、删除、改判、挪 pattern），按样本编号比两份状态即可拆出，其余归 app。报告一版一行「翻了 n 张：app 改的 a、你改标注的 b」，点开看是哪几张。前提是 Python 版的 match（上一份报告 R17）；会话动 app 之前先用当前 app 把「上一轮 ∪ 现在」标注里的全部股票跑一遍存下买点日。
4. **定级重算**：特征因计数变化换级的必报；mapping.yaml 加顶层键 `levels:` 记各特征的级（不能塞进 `features:` 的值里，否则 mapping 被判有问题、compare 变灰），这也让 `excluded` 的特征不再永远算 `unmapped`。
5. **出题**：改判、定义文字变了、反馈范围里出现了用户的正样本；一轮 3～5 题以内。

一条反馈揭示的是 app 的问题还是标注的问题，按「标注里有没有这条区别」分流：有 → app 翻译走样，会话改 app；没有、只在反馈理由里 → 走上一份报告 R2 的账本，反复出现时请用户画一次升格成特征；和标注矛盾 → 出题问哪个对；用户的意思变了 → 请用户改 pattern 定义。

### 3.3 新 pattern、新版本与检查次数

- 版本只属于 app；标注改了不产生新版本。pattern 的身份是它的名字。
- 已送检过的 pattern，从它改出来、拆出来、替它上场的共用一本账，送检前报整本账的次数；没送检过的各自从 0 起（题 3）。
- 工具不记 pattern 之间的来历，所以在送检那一刻由会话问一句，答案记进账本；账本每行另记这次送检时标注读到哪里（3.2 的序号）。账本要放 repo 级固定位置（不能按 app 放），后端像读 mapping 那样只读投影。

### 3.4 页面引导（此刻该做 / 随时可做 / 此刻不能做）

| # | 类 | 页面上的样子 |
|---|---|---|
| G1 | 此刻该做 | `next` 一格，值照旧（`run_session` / `blind` / `review` / `you`），悬停解释当前值并加一句「标注随时可改，改了会话下一版报出来」；值是 `you` 时推得出就写当下最具体的一件（如「3 条反馈还红」）。数据：会话往 mapping.yaml 状态段写未答题数（「有题要问」工具推不出来）；其余照 6.8 |
| G2 | 随时可做的后果 | `next` 旁挂 `edited n`：会话上次读标注之后，这个 pattern 的样本、成员框、pattern 定义改了几处，悬停列出；**不改 `next` 的值**（标到一半被催会烦，也像出了事）；会话读过一轮清零 |
| G3 | 此刻不能做 | 禁项落在控件本身，灰掉、悬停写原因和替代做法：露出后的盲看答案按钮；特征定义格**写之前**提示「写下就不能改，意思变了另起一个词」；页头检查次数旁写同一版没过后最早可再查的日期。页头不列禁项清单——人是在点那个东西时困惑 |
| G4 | 改的后果写在改的地方 | pattern 定义框悬停「定级照这句话定」；compare 里框左端悬停 `start not compared`（已实现）；样本的 `judgment` 与 `delete` 悬停一句分流口诀「当天看得出不该买 → `neg`；样子就不是 → 挪到 `unsorted` 或别的 pattern；数据错了 → 删」；删样本时提示「这几个框只服务它，一起删吗」；删除可撤最近一次（删框是一批多条，要整批反写；刷新后再撤要等 3.2 的参数） |
| G5 | 阶段提示 | `review`（暂用中）旁注：据新标注改 app 就是新版本，复核前要重新送检、记次数；不拦改标注 |
| G6 | 两台机器 | 页头悬停写各台机器的标注截至哪一批、最后时间 |
| G7 | 计数口径 | pattern 页 features 区写处数，悬停写口径并列出哪几个样本算一处；samples 表照旧写样本数 |

不收：在 compare 里放 ▲ 时提示「这个样本只保住这天」（按处计数后对定级无害，提示只增加阅读负担）。

### 3.5 「处」的划法（会话默认，待验证，不问用户）

同一张图上，两个正样本**共用至少一个成员框，或两边成员框之间有用户手动挂的框套框**，就连在一起，按连通分量合（不认工具按几何推出来的「包住」）；一处里任一样本收了某特征，这处就算有它；没有成员框的正样本不计。只看用户看得见、点得动的成员关系，不看对照里本来就不比的框起点。名字候选 `occurrence`（一处），三份词表都没占用；不用「段」（「走势区段」「平台段」已占）。

这个划法是团队定稿后又改了两次才落下的（`method_critic.md` 3.7、附表 A3；`repro/mc_grading_unit.py`、`repro/nearest_counterexample.py`、`repro/mc_staircase.py`）。删掉 SMX 11-24 之后，「底部平稳」出现数 / 处数：

| 情形 | 按样本 | 全部成员框跨度交叠 | 最近成员框交叠 | 同名成员框交叠 | 共用成员框 | 共用成员框或手动框套框（采用） |
|---|---|---|---|---|---|---|
| 现状 | 3/10 | 1/6 | 1/6 | 1/6 | 1/8 | 1/7 |
| CRNC 补 7 个一键正样本 | 10/17 | 1/6 | 1/6 | 1/6 | 1/8 | 1/7 |
| 补全部 23 个 | 11/33 | 2/6 | 2/6 | 2/6 | 2/7 | 2/7 |
| 假想：每个样本当天另画一天的小框 | 3/10 | 1/6 | 3/10（退回按样本） | 1/6 | 1/8 | 1/7 |

- 「全部成员框跨度交叠」：长背景框（CRNC「底部平稳」05-08～11-19）会把同一张图上两次不相干的阶跃串成一处。
- 「最近成员框交叠」：被 `spec_audit` 的反例推翻——用户以后在样本日画一天的框记当天的买入理由（V-S1 记录里的候选画法）时，每个样本最近的框是自己的小框，退回按样本数。
- 「同名成员框交叠」：被 `user_sim2` 的反例推翻——台阶式的连续阶跃，第二次的旧平台就是第一次的新平台，用户画「站上新平台」框时起点常拉到阶跃前 18 根以上（7 个框里 5 个），第二次的框会盖住第一次的框尾，两次被并成一处。真数据：INDO 的框止于 2022-02-04，app 的下一次阶跃在 03-02，只隔 17 根；CRNC 框止于 2024-11-29，下一次阶跃在 2025-01-03，隔 23 根。用户会把这两处当成两次。
- 实测另发现：按现有的成员框自动推断，第二次阶跃上的样本会把第一次阶跃的框也收进来（页面挂 `dup`）。在用户把旧框点出去之前，四种划法都会并成一处；点出去之后，只有「共用成员框」能把两次分开。
- 「只认共用成员框」：会把 RGTI 拆成两处，违背一条有记录的用户决定——`.scratch/annotation-path2-implementation/v-s1-notes.md:112-118`（「装不下的意思」第 3 条），用户 2026-11-04 定 RGTI 2024-11-29、2024-12-04「当成同一个新平台上的两个买点」，当时是用同名框手动挂成框套框表达的（`spec_audit` 指出）。
- 「共用成员框或框套框（含工具按几何推出的包住）」：6 处，RGTI、QBTS 都并回；但台阶式阶跃里，后一次的框只要从阶跃前约 45 根（INDO）、75 根（CRNC）起画就会包住前一次，即使用户把前一次的框点掉也会误并，而用户在 CRNC 上画过约 45 根的提前量（`repro/shared_or_nested.py`）。所以只认用户**手动**挂的框套框。
- 采用划法：现状 7 处（RGTI 合一处，QBTS 拆两处——QBTS 用户倾向哪边没有记录）；补 7 个、补 23 个、每个样本加一天小框都仍是 7 处。已知还会划错的情形：同一张图上两次不相干的阶跃共用了同一个很长的背景框——那时会并成一处。
- **用户不维护连线**（`method_critic` 最后一处修订，`user_sim2` 坚持）：不要求用户为了计数把框点进点出。理由：每个样本各画一个框是说明书 ② 教的画法；用户亲手把 QBTS 12-03、RGTI 12-04、SMX 12-02 三个样本里默认收进来的前一个框点掉过，点回去等于撤销自己的决定、`dup` 一直挂着；用户也不知道哪一处会影响哪一级。做法：会话每轮用采用的划法和一种更松的划法（同名成员框交叠）各算一次级，只有某个特征的级在两种划法下不同时，才附链接出一道方向题「这几个是同一段走势吗」；pattern 页 features 区的处数悬停列出哪几个样本算一处。现状 7 处与 6 处没有任何一级会翻，今天不会出题。
- 实现注意（`spec_audit`）：没起名的框必须排除（先拖框后起名很常见，按名字查会把空名框误并）；按特征编号而不是名字认特征（改名、合并后只有编号稳定，mapping 也按编号）；成员框只取在样本日当天或之前结束的，和成员推断的读法一致。检查例子放进「样本日一天框」和「台阶式两次阶跃（INDO 2022-01 / 03-02）」两种情形。
- 「一处里任一样本有就算有」另有一种按处内样本比例算的取法，默认取前者，待验证。

## 4. 场景与实测要点

- **C5 补正样本的偏向**（`repro/user_sim2_c5_reach.py`，`method_critic` 复跑一致）：98 个多买日里，在 compare 里点一下就能补成正样本（自动带上成员框）的 23 个全落在用户画过框的大涨段，之后 20 根收益中位数约 +81%；要先画框才能补的 75 个约 −19%。最省事的补样本路线只通向赢家——伤害落在定级计数上，修法是按处计数（3.5），不是拦补样本。（不是可交易的变量，没有事先定的及格线，未登记为研究副产品。）
- **C1 删 SMX 2025-11-24 的坑**（`repro/delete_smx_slots.py`）：删了不能撤；只服务它的两个框不提示，删后会在剩下的 12-02 样本上冒成两个「画了没收 ◂」空槽，等于劝用户把建在坏数据上的框收进来；剩下那个样本的框也跨着假台阶。G4 的「删样本时提示一并删只服务它的框」专为此。
- **C2 框画长画短**：compare 本来就不比框的左端，app 也不读它（旧平台固定 15 根），拖框什么都不变。「旧平台要多长」是方向题，由会话问、答案写进 pattern 定义，app 改。
- **C8 改到 compare 全绿**：对最后检查无害；伤的是回归核对（考题变成 app 的快照）和 V-S1（「格式装不装得下意思」答不了）。靠 3.2 的分开报处理，不拦。
- **复制样本到新 pattern 会悄悄改依据**（`repro/reinfer_members.py`）：重放时 11 个里有 3 个按默认推断收的成员框和现存的不同。
- **pattern 定义**：随时可改可清空，却直接决定定级（6.1 定级表第一行「定义里说清的照定义定、不问」），会话现在看不见它改过。

## 7. 被否的做法

| 做法 | 为什么不 |
|---|---|
| B：第一轮定死，不满意另起 pattern | 第 1 节 |
| 按「接触过 app」给标注分新老、打记号 | 用户 10-26 已否；防的是撤得回的东西 |
| 补在 app 已买日子上的正样本「只保住这天、不进定级」 | 随 app 改版来回跳，定级被 app 牵着走；按处计数已达到同样目的（`user_sim2` 起初的要求，接受改法） |
| 每次删样本、加样本都问「理由那天看得见吗」 | 核实不了，没有信息量；只保留改判那一道 |
| pattern 定义写下即只读 | 会把用户推向 B；后果会话列得出来 |
| 在改标注那一刻问「这是不是替补」 | 改标注撤得回；来历只在送检时要紧 |
| `edited` 一出现就把 `next` 改成 `run_session` | 标到一半一直被催 |
| 页头列「此刻不能做」的清单 | 人在点控件时困惑，禁项落在控件本身 |
| 定级按族数 / 按图数 | 族是 app 的东西，会让定级跟着 app 改版走；按图会把同一张图上两次不相干的阶跃合错 |
| 「截至上一轮」按时间戳、文件名或最大序号截 | 3.2 第 1 条 |
| 会话把标注快照存进 git 或 scratchpad 当上一轮 | 标注文件只追加、旧状态都在；scratchpad 跨会话会丢，进 git 等于另存一份 |

## 8. 局限

- 只在 new_step 一个 pattern、10 个正样本上量过；「处」的划法在框画得很长或很碎的 pattern 上要重核，一天小框的情形只做了假想测试。
- 用户的反应来自 `user_sim2` 的模拟，不是用户本人；页面提案没有画界面。
- 多数机制落在还没造的第二段（定级、翻了哪几张、版本、检查账本），本报告给的是写进 spec 的口径，不是实施计划。
- 本轮没量任何特征与收益的关系，没有研究副产品登记。
