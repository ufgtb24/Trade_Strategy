# 建一套找优秀选股 pattern 的流程

## Destination

用户手里有一套能反复跑的找 pattern 流程：每跑一遍，就从看图、挖数据等来源拿到候选，做成一个 path2 pattern 加配套买卖规则并给出诚实的判决；判的标准不变——每天盘后在用户的目标股票池（中小盘、价位偏低）里扫出一份候选名单，用户看图挑（约每周买一只），按配套规则买卖，整套交易的结果（典型的一笔和平均的一笔）都明显胜过同一池子里同日随便买、按同一套规则买卖的对照（大优势，默认值见「照这份数据的分辨力，判优标准和终点要不要调」），在训练段成立，在按「没碰过的数据怎么分配：第一遍用哪段，以后每一遍用什么」分到的没碰过的数据上也看得出，之后靠每日名单存档在新数据上接着核对。本地图终于这套流程的规格和最小工具，验收是完整走通第一遍：从候选来源一直走到最后检查，过了还是没过都如实记账，每一步写成照着就能做的步骤（什么时候进入、什么时候放弃、放弃后退回哪一步）；第二遍以后的运行属于使用这套流程、不在图上，仓位也不在图上。

## Notes

- 领域：找 path2 走势 pattern 的流程，以及它产出的 pattern 的选股能力。用词以 `path2/CONTEXT.md` 为准（查词用 grep 定位后只读那一段）；对用户说话按项目 CLAUDE.md「白话解释」的约定。用户是策略方向的决策者：阈值、窗口这类数值先取默认并标「待验证」，不交给用户定。
- 流程的工作方式（2026-10-16 用户批准，来自 agent team 研究「找 pattern 的流程该 agent 主导还是人主导」，`docs/research/2026-10-15_workflow-agent-vs-human-led/final_report.md` 第 4、5 节）：规则当裁判，agent 推训练段内圈，用户握方向、规则批准、意图确认、验证段双钥匙和每周挑票。
  - 规则：agent 起草，另一个没参与编写的 agent 独立复核，用户批准一次后冻结；之后改动要用户批准并记账。防的是 agent 写的护栏静默失效，以及搜索的一方兼任裁判。
  - 训练段内圈（试一个 → 看结果 → 收紧或放弃 → 再试）：下一步试什么、收紧接不接受、什么时候放弃，由 agent 按规则推进，每一步记账、按尝试次数扣运气。用户可以随时插队、指定先试哪个方向、否决某个方向或提前放弃，否决也入账。防的是看图后的挑选不入账、成绩被悄悄抬高：看过的赢家留在规则命中里，看过的输家被条件剔掉，心里比了几十种差别账上只记一次。这条是推理加代码事实，未实测；第一圈只看一年的图时，比较同一条规则在看过的那年和没看过的那年上的成绩，就能顺手量出抬高了多少。
  - 用户：定方向；确认 agent 写出的规则是不是自己说的形态；每个候选送去验证前盲看 10～30 个命中例子，只挑错（买不到、像偷看未来、数据像错的），只能否决；验证段双钥匙——agent 交核对单，说明现在开能看出多大、再等几个月能看出多大，用户决定开不开；每周挑票并记账，以后对比名单全体、名单前几名、用户挑的三条线。任何一方拦候选都要入账写理由，看过训练段成绩之后才拦的算一次尝试。
  - agent 会话不持久，所以流程状态必须全落在文件里（账本、清单、规则版本、数据读取记录），任何新会话读了就能接着推内圈，把要用户做的事攒成批交给用户。
- 开工前提：护栏（2026-10-16 用户批准，同一份研究第 5 节）。下面几道护栏由 agent 补上，交另一个 agent 独立复核，再请用户批准；到位之前，看图圈照常转、只在训练段上转，任何候选都不送去验证。规则细则由「这套流程分哪几步、每一步怎么进、怎么退」定，建造从那张票的答案里拆成任务票。其中截断副本、看图只露 2025 年、打开清单自动记「看过」、记账类文件只存一份、对照页自动记账与按年份过滤这几样机制，由「看图标注省力化：阶段 0」先建（2026-10-17 用户批准），网页里所有看图的地方（含调试视图）都截到 2025 年；调参和特征研究工具仍读全量，接进流程时再改，在那之前不给本流程的候选算成绩。细则仍归那张票。
  1. 研究、看图、挖数据只用一份截到 2025-12-31 的数据副本，全量数据只在用户触发的那一次验证里用。防的是现在挡住 2026 年的只是一个配置项，agent 有 shell，过去的研究也读过 2026 年的数据。
  2. 看一年的图、在另一年上判。防的是看过的样本和同题材连带沾光进成绩：只排除看过的样本，挡不住同一周同题材的其他股票。
  3. 对照页排除用户看过的例子。防的是看过的赢家留在成绩里（现在对照页没有排除，代码核实过）。
  4. 每个候选事先设放弃条件。防的是沉没成本拖着规则越收越紧、命中越来越少。
  5. 可证实性检查：扣掉运气和已知偏差后剩下的领先，要大到在验证段的独立买点数下判得出来（默认约 ≥（2 ÷ 剩下的领先）² 个独立买点，待验证）。防的是把只能撞运气的候选送去，白白用掉验证段。
  6. 用到 path2 app 的候选，送验证前加「确认根不晚于买点」的运行期检查。防的是换边端点时静默丢掉因果约束，成绩里混进偷看未来。
  - 裁判代码（以上各项和判优计算）先由没参与编写的新会话做对抗性复核，再配用手算数字写成的测试。防的是裁判代码本身写错却没人发现。
- 护栏怎么取舍、怎么测、怎么复核（2026-10-18 用户同意，来自阶段 0 前后六轮复核的教训）：
  - 什么时候拦：放过去的东西事后发现不了、撤不回的才拦，比如露出 2026 年的数据、看过的图没记下；事后能发现、能修的，只记账加提醒，照常放行；只防代理存心绕开的、给还没用上的功能预先准备的，不建。能照着生成的东西就照着生成，不写完再事后核对。防的是护栏越加越多越严，误拦正常使用、返工一轮接一轮。
  - 留下的拦截怎么测：每道拦截既要测「坏的挡住」，也要测「正常的放过」；派建造时，需求里列出必须能顺利通过的日常场景，由建造方写成测试。防的是改坏实验只查得出漏拦、查不出误拦，误拦只能等复核员手动试出来。
  - 复核前先划线：派复核时写明这一轮防的是「不小心」，还是也防「存心绕开」，以及哪些漏洞事先接受。只有「正常使用时会悄悄弄脏结论」的问题才挡合并，其余记进票里。防的是对抗性复核每轮总能再找出一条路，没有停止线就收不了尾。
  - 现有护栏按这三条过一遍，归「形态卡怎么写、规则怎么从卡来」。
- 判优尺子（2026-10-07 改定，见「照这份数据的分辨力，判优标准和终点要不要调」）：判整套——pattern 加配套买卖规则，按规则算每笔交易实际赚多少，典型的一笔（中位数）和平均的一笔都要明显赢对照；对照 = 同一天、同一目标池里随便买，按同一套规则买卖（同日普通买入对照 `path2/CONTEXT.md:155` 的推广）。起点价格一律用次日开盘价（名单盘后才出）。首次穿越（`path2/CONTEXT.md:148`）与前瞻收益（`path2/CONTEXT.md:141`）两把尺子保留作体检，不当门槛；随机日基线和收益绝对值只报告、不判优。大优势在验证段上算数的六个条件见那张票结论第六节。
- 想法来源（已定）：文献里有记录的量价规律 + 用户看图时信的形态 + 从数据里系统地挖（2026-10-07 加入：用户认为公开的规律和常见形态里的优势多半已被做掉）。用户不信任文献，文献只作低权重参考，重点在用户的形态和挖数据。挖数据守三条纪律：①挖之前先定好最后检查用的数据，挖时绝不碰；②事先列清要试哪些、试了几条都记账；③只认最后检查那段数据上的结果。只在目标股票池里挖，素材是现有 detector 产出的走势事件与日线量价特征（含登记簿里已有的候选）。K 线以外的信息（如新闻）也可以融合（2026-10-07）。现有 pattern（bottom_burst、bb_v1、bo_only 等 app）已废弃，不当起点也不当参照；框架与底层 detector 可当零件。看图找规律按「看图找规律的工作流怎么设计」定下的流程做。
- 目标股票池（方向已定，具体口径由「候选名单的规格」定；那张票 2026-10-18 起往后放，在那之前看图、同日对照、挖数据都先用它推荐的默认池子，待验证）：中小盘、价位偏低。用户的理由四条都有——价格高了买不起几股、觉得这类票涨得猛、觉得大资金少碰机会没被做掉、习惯熟悉。落到口径上：低价是一条价格上限（默认 20 美元，待验证），不刻意往更低价钻；数据里没有市值，中小盘只能拿成交额近似，并用成交额下限去掉买卖困难的微型股；「涨得猛」由池子本身满足，判优尺子照样扣掉波动带来的成绩，不因此改尺子。事实：2026-10-05 价格低于 10 美元的约 2300 只，其中约 1400 只日成交额不到 100 万美元。历史上的「当时价格」：数据文件只存复权价，按复权价设价格上限会把后来反向拆股的股票错放进来或挡出去，要靠拆合股记录还原（下载脚本取到过但没存）。
  - 排除 SPAC 合并前后的壳期（2026-10-20 用户定，「那不是正常的股票」；当天已改进默认池子）：证券类别按今天的公司名认 SPAC 空壳，合并完改了名的认不出，合并后几个月漏进了池子，现在按价格认壳期排除。做法、影响和还没重新生成的正式清单记在「看图标注省力化：阶段 0」。
- 范围（2026-10-07 改定）：任何走势都可以，可以新写 detector、改框架；可以融合 K 线以外的信息（如新闻，来源见「能接哪些外部信息：从哪来、历史多长、会不会偷看未来、花多少」）；每个 pattern 配自己的买卖规则；仓位不在范围内；不补退市数据或更长历史（用户决定）。
- 图内动手（2026-10-16 用户批准，取代原来的「图内建造的例外」）：流程的工具，以及第一遍试跑里的建 app、调参、打开验证数据，都在图内用任务票来做，照项目的开发约定（worktree、测试、后台代理交付）。通用步骤只设计到第一遍用得上的程度，并记下哪些只适用于这一次。防的是一次都没做过就把流程想得太全，做出用不上的东西。
- 现有 skill 是流程的零件（2026-10-16）：`authoring-path2-app`、`authoring-path2-detector` 管结构设计和实现，`feature-study` 管动手前的便宜验证，`tune-gates-v3` 管调参；流程负责把它们串起来，补上三样：数据预算、配套买卖规则、上线后核对。
- 按需调用的 skill：涉及评估或下好坏结论 → 照项目 CLAUDE.md「编码规范」里的评估纪律（它提到的 eval-discipline skill 并不存在）；验证某个特征 / 形态与后续涨跌的关系 → `feature-study`；走势结构设计 → `authoring-path2-app` / `authoring-path2-detector`；调参相关的输出照 `tune-gates-v3` 第三节的人话译法表说。
- 数据纪律（2026-10-16 定，见「没碰过的数据怎么分配：第一遍用哪段，以后每一遍用什么」）：凡是读 pattern 成绩或特征之后涨跌的实验，包括挖数据和看图（看图也算读涨跌），都只在训练段 2024-01..2025-12 上做。2022-10..2023-12 是预检段（2026-10-18 起，原为 2021-10..2023-12，最早一年划给调试段，见下一条），只给准备送验证的候选做否决检查，不在上面挑选、调参或比较候选；2026-01-01 起是验证段，研究、看图、挖数据都不碰，只在用户双钥匙打开的那一次验证里用；验证段用完之后，裁判只有规格冻结之后到来的新数据。每段数据各记一本账，写明给哪些候选判过、各判几次。上线后新数据攒得多快，取决于规则在整份名单上每天命中多少，不取决于用户每周买几只。
- 调试段（2026-10-18 用户定）：已有数据里最早的一年 2021-10..2022-09 只用来调试看图工作流，看图、建卡、跑对照页都可以。调试用一本单独的调试账，不进正式账，不算尝试；看图范围在调试模式下硬截在 2022-09-30。防的是：还没把工具做好，就在调试时把训练段的样本和尝试次数用掉。代价：预检段少了一年，剩 2022-10..2023-12，否决检查的力度跟着变弱。
- 记账类文件（2026-10-17 用户批准，细节见「看图标注省力化：阶段 0」）：原始标注、看过记录、事实表快照、形态卡、操作日志、账本只存一份，由代码固定写到主目录，并进 git；这取代「做出最小可用的看图工作流」里「产物不进 git」对这几类文件的规定，清单、缓存等可重算的产物仍不进 git。防的是：几个 worktree 或几台机器各记一份，尝试账和看过集合被拆开；文件一丢，越用越省事的积累和扣运气的依据一起没了。两台机器都用来看图（用户 2026-10-17）：截到 2025 年底的训练数据副本必须两台一样：用主机 upc 上 2026-10-05 由现行下载脚本（自己复权）下的数据生成，原样拷到另一台（主机 pc）；pc 的行情是 8 月用旧脚本下的，带 Yahoo 对反向拆股的复权错误，不用于训练（用户 2026-10-17 确认）。账上登记用的是哪一份，本机对不上就停下。防的是：两台的原始行情不同（股票数、截止日期、复权时点都不同），同一张图算出的事实和成绩会不同。
- 报告规矩：任何 pattern 或特征的成绩，都同时报一份去掉 2022 年的版本（2021～2025 年价量信号的成绩主要靠 2022 一年撑着，见「文献里哪些量价规律扣掉波动率和大盘后仍能选股」）。
- 数据现状：`datasets/pkls/` 共 5778 只美股，2021-10 至 2026-10-05，全是仍在交易的股票（没有退市股）。
- 研究中顺手发现、过了及格线的副产品，写进所在票的 Answer，经用户批准后再登记到 `docs/feature_candidates.md`（规则见 `.claude/rules/feature-candidates-capture.md`）。
- 过往研究给的背景（现有 pattern 已废弃，以下只作教训）：bb 系过去的好成绩大多是在读波动率；bottom_burst 现在这套参数对同日对照的方向领先约 +0.006，偶然波动约 ±0.04，看不出选股能力；bb_v1 的研究结论是现有几个条件怎么组合都提不上去，要更准得找新判据。

## Decisions so far

- [这份数据能分辨多大的选股优势](issues/02-resolution.md): 分辨力看命中了多少只不同股票，而非买点数；照 bb 的扎堆程度、每年 1000 个买点、用满 4 年，方向领先要约 0.12、幅度约 4 个百分点才看得出，0.05 以下怎么都看不出；只有买点分散到上千只不同股票时门槛才降到 0.03～0.05。全市场口径，目标池另算。
- [文献里哪些量价规律扣掉波动率和大盘后仍能选股](issues/03-literature-patterns.md): 文献效果放到本项目尺子上普遍偏小，2010 年后多半减半，近年剩下的主要靠 2022 一年；几条与 bb「底部 + 暴涨」直接相反；候选清单交「走哪条路」，用户不信任文献，只作低权重参考。
- [幸存者偏差会把哪类 pattern 的成绩抬多高](issues/04-survivorship.md): 落在「要限定股票池」一档；底部类贴着「要补数据」的边，创新高类可忽略；池子按成交额和当时价格定、不按复权价；越近的数据越干净；留一条实施阶段验证项。
- [目标池里的分辨力和幸存者偏差有多大](issues/09-target-pool-resolution.md): 池子够大，门槛与全市场相同、仍看买点长相（4 年：扎堆约 0.12，分散约 0.03）；池子挡不住底部类的幸存者偏差，挖数据落在「要补数据」一档（一个简单组合就白得约 0.10）；推荐默认池为普通股、当时价格 ≤20 美元、日成交额 200 万～1 亿美元（待验证）。
- [照这份数据的分辨力，判优标准和终点要不要调](issues/12-criterion-vs-resolution.md): 优秀要能被证实；不补数据；目标改大优势（默认典型一笔每月多赚 3 个百分点以上，待验证）；废弃现有 pattern；外部信息与配套买卖规则进范围、仓位不进；判整套，对照用同一套规则，起点次日开盘；验证段只用一次，名单每日存档。
- [能接哪些外部信息：从哪来、历史多长、会不会偷看未来、花多少](issues/13-external-info.md): 先接三类免费信息——SEC 公告事件、SEC 财务数字、FINRA 空头持仓；一律按信息被接收的那一刻用；新闻免费的取不回训练段、社交讨论有删帖偏差，暂不接；大盘涨跌在同日对照下单独造不出领先，只能当「什么时候用」的条件。
