# 标注与扫描怎么安置：最终报告

本文件中所有项目内路径均相对 repo root。原问题见同目录 `原始问题.md`；事实盘点 `inventory.md`（inventory）、方案与评估 `options.md` v4（options）、历史查证与质疑 `challenge.md`（challenger）；截图与一次性脚本在 `repro/`。三方定稿时无分歧。

## 0. 结论

**用户拍板（2026-11-11）：采纳推荐 F；第 7.3 节默认做法照单采纳（仍标待验证）；前提「扫描界面是偶尔用的调试工具」成立。**

- **不拆页面，把扫描做成顶栏 `mode` 的第四档。** `mode` 从 `annotate / compare / app` 变成 `annotate / compare / app │ scan`。
  - `app` 从此只指「当前 pattern 的 app 在这只股票上现算」（`stores/view.ts` 的 `appSource = 'linked'`）。
  - `scan` 就是今天从扫描列表进去的那个视图（`appSource = 'scan'`）：扫描文件里的产物、扫描窗口的 K 线、扫描的 active pattern、Working Copy、诊断侧栏、拓扑面板，原样不动。
- **前三档的左栏换成找图清单**，分三页 `rally` / `random` / `charts`：大涨段清单直接铺开、带每行标过的 pattern 名与框数；`random` 列出这次抽过的图（只在页面内存里，刷新即清）；`charts` 列全部标过的股票。↑/↓ 挨个翻。前端从标注状态现算，后端不动。`scan` 档的左栏是今天的扫描面板与列表。
- 图组件（`KlineChart.vue`）、图表状态（`stores/view.ts`）、副图画法（`render/chart.ts`）全部共用；没有新页面、没有新地址，直达链接与改版报告链接（根地址 `#`）照旧。
- 这是用户提的第二条路（两种模式、界面不同、共用部分复用）的一种落法；比「顶栏加一个『标注 / 扫描』开关」少一个新概念、从扫描图去 `compare` 少一下；比「两个独立页面」少两个地址、少一次重读扫描文件，覆盖面不少。
- **推荐的前提要用户确认：扫描界面现在是偶尔才用的调试工具。** 若用户其实常用扫描界面，或想在 `compare` 里对着全池命中逐张挑刺，左栏分页签（方案 C+）更合适。
- **时机（默认，待用户过目）**：这一轮 annotation-round 交还、用户在 `compare` 里看完改版报告之后，下一轮开始之前，在独立 worktree 里一次做完。不改 V-S1 验收的对象，但不插在一轮中间。

## 1. 问题拆成两根轴

- **外壳轴**：扫描界面和标注界面怎么共处——用户问的「拆不拆」。
- **内容轴**：标注时左栏放什么。各外壳方案下答案几乎一样（找图清单），所以单列。
- **真正的缝不在 `mode`，在 `app` 的两种来源**：今天一个 `app` 按钮既可能是扫描文件里存好的产物（扫描窗口的 K 线），也可能是现算（全部 K 线）；从扫描 `app` 去现算 `app` 要先切 `compare`，反方向只能去左栏点一行（`stores/view.ts:197-205,269-275`；`KlineChart.vue:640-655`）。用户这次问「标注工具的 app 是不是扫描结果」，就是这个歧义造成的误解。
- 「独立页面」有三种读法，代价差很多：① 另一个地址、各自启动、各自一份状态（方案 A）；② 同一应用里的路由（地址不同、状态同一份）——项目没装 router、`#` 已被直达链接占用，除地址外与③无区别；③ 同一棵组件树换外壳（用户说的「两种模式」），有「加开关」（方案 B）与「`mode` 加一档」（方案 F）两种落法。

## 2. 关键事实

核实程度照各条所注；未注的是读代码或读文档确认。

### 2.1 页面现状

- **标注时空着的主要是左栏。** 左栏 `SidebarPatternPanel` + `SidebarScanPanel` + `SidebarResultList`（`path2_web_ui/src/components/App.vue:4-8`）在 `annotate`、`compare`、现算 `app`、扫描 `app` 四种状态下完全一样，没有任何按模式的分支；至少 220px、占满整页高，有扫描时按表格撑宽、最多半屏。标注时它不为任何东西服务。实测视口 2192 宽时左栏 220、图 1652、标注侧栏 320（`repro/s0_fresh.png`、`s1_annotate_noscan.png`）。
- 右栏与图上方的档位条**已经随模式换**：`annotate` / `compare` 右栏是 320px 标注侧栏，两种 `app` 是 280px 诊断侧栏；扫描的 pattern 下拉与参数只在扫描 `app` 出现（`ChartArea.vue:8,46-52`）。顶栏没有扫描专用控件；`tiers` 没有任何读者，规格 5.2 写着拟删、待用户确认。
- 页面上同时有两个「当前 pattern」：顶栏 `pattern`（标注的，决定 `compare` / 现算 `app` 跑哪个 app）与档位条里扫描的 active pattern 下拉，互不联动。
- 切模式时带过去：股票、档位、node 显隐、面板开关、标注的当前 pattern；清掉：焦点、候选、工具、反馈面板。从扫描 `app` 切到标注，实际只带股票代码（`inventory.md` 2.2）。
- 标注找图入口：顶栏 `symbol`、`rally`（浮层 278×740，正好盖在左栏位置、并压住图最左约 68px；300 段、242 只股票；每张图要点两下，看不出哪些标过；`repro/s9_rally_popover.png`）、`random`、直达链接；右栏 `pattern` 页样本卡、`feedback` 页各处也能打开图。
- 「哪些股票标过、标的哪个 pattern、正负几个、只画了框的」前端从标注状态现算即可（`annotate/model.ts:24-42,82-88`），后端不用动。

### 2.2 标注工具里 app 结果的来源与范围（逐行核实）

- 打开股票时对这一只现算：`stores/appLink.ts` 走 `/preview`。
- 反馈状态只对**有 picked 反馈的股票**跑（不含只有样本的），且只在 `compare` 下取。

- 所以标注这条线上，app 结果只出现在标过或正在看的股票上；「全池跑 app」只有扫描在做。

### 2.3 扫描界面的使用情况（只查了主目录；各 worktree 的 `outputs/` 不共用，不在内）

- 主目录现存扫描只有 11-03 的 `bo_only` 过得了数据墙，它是 11-04 match→hit 改名前的格式，网页里列表 0 行、图报错（扫描文件不做兼容，属预期）；其余 4 份过不了数据墙、打开回 409。没有 `new_step` 的扫描。`outputs/path2_web/wc.json` 不存在。11-03 以后标注目录有 182 批。
- 依赖扫描的大多只依赖**扫描文件或后端模块**（feature-study、旧 tune-gates、diagnose-event 常规路径；write-detector 和评估、漏检脚本连文件都不要）。真正挂在**界面**上的只有 diagnose-event 探索态读的 `wc.json`，以及借扫描入口测共用画法的 e2e。
- 由此推断扫描界面最近没人用——**这是推断，作为前提请用户确认**，不能写成「扫描可以下线」。

### 2.4 「从扫描结果进入同一张图接着标注」

- 代码里有这条路：顶栏点 `annotate`，股票不换、图窗重置。说明书的找图一节没写这种用法。
- 没有使用证据：标过的 7 只（CRNC、GEVO、INDO、KULR、QBTS、RGTI、SMX，全是 `new_step`）里 5 只在大涨段清单上、样本日在那段涨开始后不久；9 月到 10-28 的四份 `bb_pk` / `bb_v1` 扫描只碰上 INDO、RGTI，而这四份在标注开始前就打不开；`bo_only` 收了全池 3144 只，与谁都重合，不算证据。测「扫描→标注」的两条 e2e 从 11-04 起就是红的（最新扫描 0 行），不是本研究弄坏的。
- 没有证据 ≠ 不能做：推荐方案下仍是 1 下（点 `compare` 或 `annotate`），带着股票。

## 3. 历史决定：「标注不另开页面」今天还成立吗

- 规格 `.scratch/annotation-path2/spec.md` 5.1 的出处是票 01（`.scratch/annotation-path2/issues/01-structured-annotation.md`）第 1 节。当时的备选是旧的独立标注页 `AnnotChart.vue`（带 `?wf=` 整页替换、一个事件都不画、自带画法）；唯一理由是「防的是：标注和显示两套画法，标完对不回来」。
- **这条理由今天仍成立，并被 spec 5.8 加强**（`compare` 的 app 部分与 `app` 模式同一套画法、档位与 band 显隐是同一份状态）。但它约束的是「同一个图组件 + 同一份图表状态」，从没评估过外壳和左栏。
- **左栏在标注时是扫描，从来不是决定**：用户认可的原型 `mock_v4.html` 只有「图 + 右栏」两列、没有左栏（该文件已随 09047e4 删除，规格 5.1 引用的路径失效，需 `git show 09047e4^:docs/research/2026-10-28_annotation-web-loop/repro/mock_v4.html`）；实施票 04 范围写「不改现有的扫描流程」，左栏的扫描面板是范围外没碰留下来的。
- 当时研究默认「用户从扫描结果挑图」，还设计过「从扫描进来算接触过 app」的记号，10-26 被用户判为过度设计删掉；现在页面默认就是 `annotate`。
- **所以推荐方案不推翻 5.1**：它没有另开页面，被纠正的只是左栏的内容。

## 4. 方案与取舍

| 方案 | 形状 | 结论 |
|---|---|---|
| F | `mode` 四档 `annotate / compare / app │ scan`；左栏随档换 | **推荐** |
| B | 一个页面、顶栏加「标注 / 扫描」开关 | 与 F 状态组合一一对应、覆盖相同；多一个要起名的新概念（暂名 `page` 还和侧栏「某某页」撞字），从扫描去 `compare` 多一下 |
| A | 两个独立页面（`/` 与 `/scan`，各自一份状态） | 多覆盖的只有：扫描页天然没有抢键、两个浏览器标签时只有一个标注写入者；代价是按地址启动两套、跨页靠链接、来回切要重读扫描文件（39MB 级）、最像「割裂」 |
| C+ | 不分档，左栏分页签 `rally / random / charts / scan`，并把 `app` 按钮拆出 `scan` | 与 F 覆盖不同：能在 `compare` 下翻扫描列表逐张看全池命中；代价是「页签 × 模式 × 焦点」的组合守卫与「在 `compare` 里点扫描行落哪」的落点规矩。多出的那块没有使用证据，所以不推荐；若用户其实想这样用，它更合适 |
| D | 左边一条图标竖栏，清单做成抽屉 | 图最宽，但把「一眼看到哪些标过」又藏回浮层，违背用户第 2、9 条 |
| 0 | 结构不动，没加载扫描时左栏收窄 | 只作改动量基线：不解决找图，也不解决抢键 |
| E | 去掉扫描来源的 `app`，扫描文件只当股票清单 | 删掉扫描时的参数快照、Working Copy、临时计算这套调参工具，diagnose-event 也按扫描文件定位参数；覆盖少一块，排除 |

逐维比较见 `options.md` 第 3 节。要点：

- **找图每张**：现状 2 下、看不出哪些标过；F / B / A / C+ 1 下、标过的一眼可见、↑/↓ 挨个翻；D 2 下。
- **画框 / 样本 / `compare` / 反馈 / 从 `compare` 切到现算 `app` 看数字**：各方案都不变。
- **扫描**：F 多 1 下点 `scan`（加载扫描后自动在 `scan`）；从扫描图去同一只股票的 `compare` 仍 1 下。
- **后端**：各方案都不动。
- **「annotate 默认不看见 app 产物」（说明书第七节第 2 条）**：今天加载过扫描后，左栏在 `annotate` 下默认就并排摆着全池命中与收益——这是现状的越线；F / B / A / C+ 都消除它（训练段上主动去看 app 是用户的自由，票 01 第 46、91 行）。
- **F 不省屏幕**：左栏从 220（空着）变成约 278（大涨段清单多两列），图反而窄约 58px。F 换来的是左栏有用，不是图更宽；这正是用户上一问要的取舍（「直接显示在左侧列表」）。画框嫌图窄时可另给左栏一个收起开关，这次不做、待验证。
- **奥卡姆剃刀只用在覆盖相同处**：F 对 B、F 对 A 覆盖相同或 A 多出的部分有更便宜的替代；F 对 C+ 覆盖不同，取 F 的理由是「规则更简单 + C+ 多出部分无使用证据」，不是剃刀。

## 5. 推荐方案 F 的形状

- 顶栏：`symbol random │ mode annotate compare app │ scan │ tool … │ pattern … │ ref …`；顶栏的 `rally` 按钮去掉（进左栏）。
- 前三档左栏（线框图见 `options.md` 方案 F）：
  - `rally`：复用 `RallyList.vue` 的数据与排序，样式与按法照扫描列表；每行加标过的 pattern 名（业务内容，浅灰底）与框数——框数让「只画了框」和「完全没碰」看得出区别。
  - `random`：抽图入口仍是顶栏 `random`（1 下出一张）；这一页按抽的先后列出这次抽过的几张，可点回、↑/↓。只在页面内存里，刷新清空，不写文件、不写浏览器存储。spec 5.3「看过什么一律不记」防的是落盘的「看过」账本限制看哪些图（票 01 第 70 行：「记『看过』违背训练段随便看」），这份列表什么都没记、不限制任何东西，不违背它；措辞要在动手前改清楚。
  - `charts`：所有标过的股票（不限大涨段），一只一行，写 pattern 名、正负样本数、框数，只画了框的也列。与右栏 `pattern` 页样本表分工不同：后者是当前 pattern 的样本、按判断与骨架分行；`charts` 是全部 pattern 的股票目录，用来决定下一张去哪看。
  - 三页只列用户自己存下的东西（和这次 random 抽到的图）：不出现 app 的任何结果，也不出现「看过 / 没看过」。
- `scan` 档：与今天的扫描视图一模一样。
- 扫描专用的东西只在 `scan` 档起作用：扫描列表的按键（K1、K2）、Shift+P 参数抽屉（K3）、休眠草稿横幅（K4）各加「只在 `scan` 档」一个条件；扫描选股时清掉打开时给定的图窗（K5）。扫描列表在前三档隐藏而不卸载，保住滚动与虚拟列表位置（同 `rally` 浮层今天的做法）。
- 切换时股票怎么带：前三档 → `scan`，当前股票在扫描文件里就留着，不在就回扫描列表上次停的那只（扫描视图画不了扫描文件以外的股票；扫描结果只收命中过的股票，`path2_web/scan.py` 的 `_aggregate_multi`）。`scan` → 前三档：在 `scan` 里点过扫描列表的行，才把那只带回去；没点过就回到进 `scan` 前的那只（`no_scan` 空状态同理）——否则 A → `scan`（换成 B）→ 回来会落在 B、丢掉 A。`scan` 是四档里唯一可能「切模式会换图」的按钮，和今天「顶栏切模式图不换」的约定不一致，这条默认把它限制在用户主动点了扫描行的情形。
- `view.ts` 里 `mode` / `appSource` 两个状态的表示可以不改：顶栏把藏在一个 `app` 按钮里的两种来源拆成两个按钮（`scan` 按钮 = 今天的 `mode = app` + 来源是扫描；`app` 按钮 = 现算），左栏看「是不是扫描视图」换内容。要改的是几处动作：进出 `scan` 的股票规则、没有扫描文件时留在 `scan` 的空状态、扫描选股清图窗。**建议实施取这种「纯界面拆按钮」**：代码里有 15 处（`TopBar.vue`、`view.ts`、`KlineChart.vue`）、测试里有 13 个文件读 `appSource` 或 `mode = 'app'`；若把 `scan` 做成 `mode` 真正的第四个取值，这些都要改。

## 6. 时机、工作量、动手前要改的文档
