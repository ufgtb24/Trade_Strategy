## 0. 结论先行

写备注累，不是因为字多，而是三件事叠在一起：

1. **形态级的话每张图都要重写一遍。** 「为什么会涨」「什么情况就不买了」「买了以后什么时候卖」属于形态，不属于某一张图；同一形态标十张，就重复说十次。
2. **自由文本要用户自己想到该写什么，写出来还有歧义。** 「突破了两个峰」按最高价和按收盘在 QMMM 上结论不同；「近期放量」没说是哪几天。用户不知道下游要什么，也不知道自己哪句话有两种读法。
3. **操作本身绕。** 现在每张图要：按「框选起止」→ 拖框 → 按「点买点」→ 点 → 选正反例 → 打字。工具按钮来回切。

对应的改法：

- **两层**：「形态卡」一个形态只填一次；每张图只记「买点 + 是哪张卡 + 和卡哪里对不上」。同一形态从第二张图起：**点一下买点、按一下这张卡的数字键**，系统拿卡去对这张图，对得上就落盘跳下一张。
- **新形态时，先说一句，再在「事实表」上点选**：用户点下买点、先用一句话说出第一印象（打字、按住 V 说、或点自己用过的说法），系统才把那天及以前的客观事实算好列出来（按收盘越过几个峰、按最高价越过几个峰、哪几天放量、买点前缩没缩量、有没有派发……），用户在每行点「必须有 / 加分 / 无所谓 / 有它就不买」。同一说法两种读法结论不同时，行内出一道「两张并排小图 + 一句话」的二选一，一个形态只问一次。
- **逐张模式 + 快捷键**：放大框升级成「左图右表」，点图默认就是放买点，数字键认领、回车确认，落盘后跳下一张。
- **任何格子都能自己写、都能改推荐**（用户 2026-10-16 补充）：每组选项末尾都有「其他：___」，常驻的「我自己说」框随时可用；推荐值只是起点；库里没有的要素用户自己加。

推荐怎么出现、怎么不带偏用户，用一条规则统一：**在「说形态」时用户先动手、系统后出现**——买点用户先点、形态用户自己认领、新形态先说一句再看事实表，系统的推荐一律摆出不预勾，外部建议（大模型、通用知识、系统新提的要素）只在这张图交了之后以形态级选择题出现；**在「对规则」时系统先出信号、用户先判再看规则的读数。** 每一格都记下是谁先填的。

每张图的目标（待验证）：已认领卡且对得上 **2 下、约 4 秒**；新形态首张约 10 下加一句话；盲看核对 1～2 下。

## 1. 两层数据、两种模式

### 1.1 两层：形态卡 + 单张标注

| 层 | 填几次 | 装什么（对应 needs 编号） |
|---|---|---|
| 形态卡 | 一个形态一次，以后偶尔改（改即新版本） | 名字（自动起，可改，#11）、要素及其四态与口径（#5、#6；「有它就不买」的要素就是买前失效条件，#8）、触发（可多个，每个＝一个版本，标主版本，#7）、为什么会涨（模板单选 + 可补一句；看图时可缺，确认规则草稿前必须补，#10）、买后离场（不预选，不动则下游用统一止损，#9） |
| 单张标注 | 每张图一次 | 买点（可多个，每个挂一个触发，#1、#4）、属于哪张卡（#2）、判定（#3）、本图与卡对不上时的处置（#13）、先说的一句（#21）、是否抽中不预填（#20）、留痕（#16～#18）、可选备注（#19）；正例从第 1 阶段起不框范围（#12） |

关键性质：**改形态卡不需要回头重标。** 单张标注存的是「这天的客观事实 + 用户的判断」，卡改了口径，旧图按新口径重新对一遍即可。

### 1.2 两种模式：说形态 / 对规则

| 模式 | 用在哪 | 系统先出什么 | 用户做什么 |
|---|---|---|---|
| 说形态 | 大涨段清单（当前 `r002-bigmoves-2025`），看得到结果 | **什么都不先出**，连清单自带的决策日、最高点标记都等用户点了买点才显示（U1） | 点买点，认领卡；新形态时先说一句、再点事实表 |
| 对规则 | 规则草稿在 2025 年的全部命中（含没涨的），盲看：图只画到信号那天，不显示代码和日期（U3） | 只有信号标记 | 一键答「这天我会不会买」；答完才看到规则对各要素的读数，用来点原因 |

说形态是在采集「用户自己信什么」，要防止系统带偏；对规则是在检查「规则是不是用户的意思」，系统的信号本身就是被检查的对象，先出没问题，但规则的读数要等用户判完再给。顶栏写明当前模式。

## 2. 每个格子在界面上怎么填

「谁先」：用户先 ＝ 界面上先空着，用户动手；预填 ＝ 先放好值（只允许来自用户自己的卡和形态名字，needs 第 2.1 节的总规矩），用户不动就保留；摆出 ＝ 列成未选的选项，用户点了才算，不动＝未回应。

| 格子（needs #） | 层 | 界面上怎么填 | 谁先 | 必填？ |
|---|---|---|---|---|
| 买点（#1、#4） | 单张 | 点图；Shift+点 再加一个，点已有的取消；★ 标主版本 | **用户先**（4.1 第 1 条） | 判定为「是」时必填 |
| 属于哪张卡（#2） | 单张 | 右侧列出用户自己的卡（按用户自己最近用过的先后排，带数字键）；按数字 ＝ 认领并确认；回车 ＝ 认领排第一的那张；C 新形态；S 不是任何形态 | **用户先**；系统不显示「像哪张卡」的猜测（4.1 第 2 条） | 必填 |
| 判定（#3） | 单张 | 认领了卡就默认「是」；N 像但不是、E 数据有误、S 不是任何形态。文案随清单种类变（needs 第 6 节表） | 用户 | 必填（默认值即可） |

| 触发（#7） | 每个买点；汇总到卡 | 已认领卡：用户点的那天命中卡上哪个触发就自动挂上；新形态：摆出「这天发生了什么」的候选（回落收回 / 突破当天 / 连续突破最后一根 / 回踩企稳……）+「都不是，我说一句」；点了「都不是」才在旁边出「这天和它自己过去 60 天比最不寻常的几件事」作提示（`smart.md` 第 6 节） | 已认领：自动挂（日子是用户点的）；新形态：摆出，在先说的一句之后出现 | 必填 |

| 口径分歧（#6） | 卡，一次定 | 本图上两种读法结论不同时，那一行标【两种读法】，点开是两张并排小图 + 一句话，点 A / B，或「都不对，我是指：___」 | 用户 | 出现时必答 |

| 可知性（#14） | 单张 | 事实表只用买点当天及以前算；回顾型事件（`path2/CONTEXT.md:72`）到买点还没走完的，那一行写「到 07-14 还看不出来」且不能点「必须有」 | 自动 | — |
| 为什么会涨（#10） | 卡 | 3～5 个故事模板单选 + 可补一句 / 按住 V 说 | 摆出（不预选） | 看图时可空（进待回应）；确认规则草稿前必填 |
| 买后离场（#9） | 卡 | 单选：收盘跌破被突破的峰就走 / 跌破买点前低点就走 / 其他；旁注「不选就用统一止损」 | 摆出（不预选） | 可空 |
| 名字（#11） | 卡 | 按要素拼一个，回车即用，可改 | 预填 | — |

要素一律**只记方向和口径，不让用户填数**：「买点前一段明显放量」只记「哪几天、和什么比」，本图实际几倍由系统记下并写明比法（如「当日量 / 前 63 日均量」），阈值留给写规则的一方（needs #15）。

**用户自己写、改推荐的出口**：每组选项末尾「其他：___」；事实表底部「库里没有的，我自己说」，说的话由系统起草成新要素、在图上高亮请用户确认后进库；任何预填值点一下就能改。来源分三种记：用户自己写的 / 采纳推荐原样 / 改过的推荐（保留推荐原值）（needs 第 2.1 节）。

- 事实表**顺序固定**（峰与突破 / 成交量 / 涨跌与位置 / 派发 / 回踩，每张图一样），不按系统觉得重要的程度排序；长期没被点过的行折叠进「更多」，折叠只数用户主动点的次数，不数预填后保留的（U7）。
- 四态按钮：选中的那个是深底白字，未选的是白底灰框，始终有文字，不靠颜色区分。键盘：数字键按「必须有 → 加分 → 有它就不买 → 无所谓」循环；鼠标直接点。「加分」按钮旁注一行小字「以后每试一个加分项算一次尝试」（needs #5、auditor N5）。
- 「你先说的」只是标出对应关系，不替用户点；用户点了这一行，来源记「先说的」，没对上的行被点了记「从事实表采纳」（U2、needs 第 2.1 节 `said_first_match`）。
- 第 6 行这类「到买点那天还看不出来」的回顾型事件只显示、不能点「必须有」（needs #14）。
- 来自 2025 年以前的回看（如「离一年最高价」）只以数字出现，不画图、不叙述之后怎么走（U5、E3）。
- 前端照通用形式渲染每一行：「编号 + 文字 + 四态 + 图上标记日期 + 来源标签」，不为具体形态写分支（arch 第 4.3 节）。

### 3.7 像但不是 / 不是任何形态 / 数据有误

- **N 像但不是**：大涨段里全是赢家，这里的反例不是「它没涨」，而是「看着像我的形态，但当时我不会买」。按 N 后先问「像哪张」（用户自己的卡，数字键），再弹原因选项——直接取自这张图事实表的行（行本身带位置和口径，能直接变成「有它就不买」的条件，needs 裁决③）+「其他：___」；数字键一下，可跳过。只有「其他」写的原因才可以在图上点一根 K 线，不强制。选的原因回流成「有它就不买」的候选（进待回应，不直接改卡）。
- **S 不是任何形态**：一键跳下一张。整份清单载入即记为看过（needs #16），S 只额外记「看了、没认出形态」，不推断成反例（needs 第 7 节）。
- **E 数据有误**：一键，范围用跨源比对不一致的日子预填（`path2_web_ui/src/components/AnnotChart.vue` 已有的两份数据不一致提示），用户可拖改。

## 4. 推荐怎么呈现、怎么不带偏

### 4.1 规矩

1. **买点永远由用户先点，系统不预标候选日。** 买点是检验规则有没有复现用户意思的测试用例（needs 第 1 节「写规则⑤」）。按卡上的触发扫出候选日让用户点选，就是规则给自己出题、自己答，复现检查失去意义；省下的操作也只有一下。系统在用户点完、认领完之后才拿卡去对。（needs 已采纳。）
2. **「是哪个形态」由用户认领，系统不显示猜测。** 用户的卡本来就少，按自己最近用过的先后排、配数字键，认领只要一下，和接受猜测一样快；而猜测会让用户顺手接受一张自己未必会选的卡。拿掉之后，「用户认领 X，但卡 X 在这张图上对不上」反而成了最有用的信号——卡没写出用户看到的东西，正好进复现检查。系统按事实算出的「最接近哪张卡」只在后台记，用来统计用户认领与卡定义的一致率，以及在形态库「未归类」里排序。
3. **预填只在用户认领之后、只来自被认领的那张卡。** 不按跨形态的习惯预选：图没认领卡时多半是新形态，拿别的形态里的习惯预填，会把新形态往旧形态上拉。习惯只用来排序选项和折叠长期不点的行，而且只数用户主动点的（U7）。（smart 已删掉按习惯预勾。）
4. **系统的推荐一律摆出、不预勾。** detector 算出的事实、触发候选、「有它就不买」的常见项、故事模板、卖法选项都以未选的选项出现，用户不动 ＝ 未回应，不算采纳。一个形态只填一次，多点一两下的代价可以忽略；而「不动就算采纳」会把系统默认混成用户信念，留痕里也分不清是认同还是没看。只有用户自己卡上的值和形态名字可以预填。（needs 已采纳并写成总规矩。）
5. **先自己说、再看系统摆的东西（C2、U2）。** 新形态首张：先说的一句必填，之后事实表与触发候选才出现；事实表算外部框架（auditor N3：它是事实、不是意见，但仍是系统摆出来的），点它的行记「从事实表采纳」，与先说的一句对上的才记「先说的」。外部建议（大模型、通用知识、系统新提的要素）只在这张图交了之后、以待回应里的形态级选择题出现。用户自己的卡和说法可以一直显示，它们不算外部推荐。
6. **来源靠文字标签区分。** 用户自己的卡和词无标记；事实表的行是正文；与先说的一句对上的行标「你先说的」；系统提议标「系统提议 · 不是你的说法」，虚线框。
7. **每一格留痕**：来源三种（用户自己写的 / 采纳推荐原样 / 改过的推荐）+ 推荐方（自己以前的卡 / detector / 大模型 / 通用知识）+ 推荐原值；被拒的、点过又取消的也记（C1、F2）。每张图另记：模式、显示过几行事实表与哪些提议、有没有按 F 看过后续以及是在点买点之前还是之后（F1、U1③）；停留秒数和操作次数只作工具自身的度量，不进研究的信息契约。
8. **抽查**：按固定比例（默认 20%，待验证）随机抽图，不预填、不出外部建议（arch 第 4.3 节把 ux 的「无预填抽查」和 auditor C 节「留出不出推荐」合成一个机制）。已认领卡的图被抽中时，用户要亲手点出看重的几行，平均每张图多约 2 秒。比较只在同一张卡下的图之间做（U7）。它量的是「不给预填时用户会不会点出卡上那几条」——卡上的要素是不是用户真的在看的东西。
9. **对规则模式**：系统先出信号，用户先判，规则对各要素的读数在用户答 N / W 之后才出现；答完不揭晓结果（U3、auditor 第一轮第 7 点）。

### 4.2 说形态时少给后见之明（U1，已裁定做）

- 点买点之前，图上不画决策日、入场日、最高点、上下线，图头不显示决策日文字和涨幅数字，界面任何地方不出现含日期的条目编号。
- 初始窗口右边界在决策日后**随机** 3～15 根（待验证），不固定在决策日后 5 根——固定的话，用户会学到「右边界往左几根就是起涨点」。
- 按 F 展开后续，记下是在点买点之前还是之后。
- 点了买点之后，清单的标记照常画出来，用户可以对照。

理由：后面的暴涨一眼可见、决策日又画在图上时，用户容易把买点点在事后看最舒服的位置，而不是「当时能下手的位置」；买点是规则复现检查的测试用例，被事后最佳入场日锚住，规则就会去复现后见之明。代价：想看「这段后来涨成什么样」时要多按一下 F。

### 4.3 数据纪律在界面上的落点

- **清单下拉只列本轮允许看的清单。** 现在 `r001-bigmoves`（图窗最早到 2023-07-13，含 2024 年与预检段）还能在下拉里选到、照样出图（`auditor.md` 第 3 节第 1 条）。界面不列它；后端的下界截断按 `arch.md` 第 5.1 节「前置」做。
- **所有小图（分歧题、对齐看、盲看）只画 2025 年的 K 线**；2025 年以前的回看只以数字进事实表（E2、E3、U5）。
- **收紧时看的普通对照页在内圈只给 2025 年的图和数**，界面不显示 2024 行；2024 年只在判决时出现一次（U4）。
- **送给大模型的只有文字**：先说的一句与备注的转写文字（先剥掉代码、日期、价格数字）和要素库定义（A1）。第 3 阶段若做读图，图截到买点（A2），那是 smart 的组件，界面不额外送图。
- 池子里混进的 ETF / ETN（`auditor.md` 第 3 节第 3 条）应在生成清单时剔除；剔除之前，界面在这类图头上标「ETF / ETN，不是股票」字样，方便用户按 E 或 S 跳过。

|---|---|---|---|
| 右侧主角 | 先说的一句 + 事实表 | 「是哪个形态」的卡列表；事实表只在对不上或抽查时展开 | 同左，卡更多；多数图两下即过 |
| 一张图的动作 | 新建形态卡，约 10 下 | 2～3 下 | 2 下；新形态少了 |
| 分歧题 | 每个新口径问一次 | 很少（答过的口径记进卡） | 几乎没有 |
| 时间花在哪 | 说清第一个形态 | 看图本身 | 多数时间在对规则盲看（1～2 键 / 张）和答待回应 |
| 待回应 | 空 | 「必须有还是加分」「先跑哪个版本」「要不要加进有它就不买」「为什么会涨还没说」 | 加上系统提议（按形态归档）、合并建议 |
| 形态库 | 空 | 1～3 张卡 | 每张卡带状态：草稿 → 规则已确认 → 已试跑 → 已判决 |
| 说话 / 打字 | 每个新形态一句 | 很少 | 几乎不用；说过的话已变成「你用过的说法」，点一下就是先说的一句 |

「越用越方便」在界面上的来源全是用户自己的操作：形态卡让同一形态不用重说、两下即过；答过的口径不再问；说过的话变成可点的说法；自己用过的卡、原因、触发排在前面；系统想问的攒成选择题。读涨跌结果的「聪明」不进标注界面（`smart.md` 第 7.1 节信号 B）。

## 7. 快捷键、语音、批量、落盘

| 键 | 作用 |
|---|---|
| 点图 | 放买点（逐张模式下默认就是买点工具，不用先按按钮） |
| Shift+点 | 再加一个买点；点已有的买点取消 |
| 1–9（卡列表有焦点时） | 认领第 n 张卡并确认 |
| 1–9（事实表有焦点时） | 第 n 行在「必须有 → 加分 → 有它就不买 → 无所谓」间循环 |
| A / B | 分歧题选 A / B |
| 回车 | 当前默认动作（认领排第一的卡、算例外、保存），落盘并跳下一张 |
| C | 新形态 |
| N / S / E | 像但不是 / 不是任何形态 / 数据有误 |
| Y / N / W | 对规则模式：会 / 不会 / 不是我说的那种形态 |
| J / K | 下一张 / 上一张 |
| F | 展开 / 收起后续走势（会记下） |
| L | 对数 / 线性坐标 |
| 按住 V | 说话（进「我自己说」框） |
| Ctrl+Z | 撤销上一张的确认 |
| ? | 快捷键一览 |

数字键在两处含义不同，靠焦点区分：当前焦点区加粗外框，并在框角写「数字键：认领卡」或「数字键：点事实表」。

- **语音**：最早第 3 阶段，进入信号是有了点选之后用户仍说打字是瓶颈；优先本机模型（Linux 上浏览器自带识别能否用、会不会把音频外发，待验证）；用户已有输入法，未必需要（arch 第 5.4 节）。转写文字交给便宜的大模型对到事实表的行上，对不上的部分起草成新要素请用户确认。
- **落盘**：第 0 阶段保留现在的统一发送；第 1 阶段起回车 / 数字键认领就追加写一行完整快照到本次会话的文件、最新的那行算数，这份文件同时就是操作日志（arch 第 4 节）。抽屉保留作回看和撤销。
- **批量**：网格页 Shift 多选后批量 S / E；形态库「对齐看」里框选后批量移卡、拆卡。

## 8. 色盲与看图默认值（看现网页发现的）

2026-10-16 打开 `?wf=r002-bigmoves-2025` 截图看到两处问题，都和本次设计直接相关：

1. **K 线涨跌靠红绿色相区分**（`path2_web_ui/src/components/AnnotChart.vue` 的 candlestick 用 `#47b262` / `#eb5454`）。红绿正是色盲最难分的一对。改成**空心 = 涨、实心 = 跌**（明暗区分），量柱按涨跌用深浅区分。
2. **线性坐标把形态压扁**：QMMM 后段涨到约 380，涨前 1～2 元的整段结构在图上是一条贴底的直线，要看形态必须先缩放。默认改成对数坐标（L 切换）；说形态模式下初始窗口只到决策日后随机几根（4.2），纵轴随可见范围自适应，形态就能占满图。

界面其他状态一律靠饱和度、明暗、白字黑底和文字：四态里选中的 = 深底白字；系统提议 = 虚线框 +「系统提议」字样；主买点 = ★ + 实心三角，其他买点 = 空心三角 + 序号；对不上的要素 = 加粗 +「对不上」字样；分歧题两种读法 = 实线 / 虚线 + 「越过 / 未越过」字样；当前焦点区 = 加粗外框 + 文字说明。

这两处是界面问题，不是研究特征，不登记 `docs/feature_candidates.md`。本轮没有量任何东西与涨跌的关系，无副产品。
