# 在要用的地方量一条特征：现有工具能不能直接做

Type: research (AFK)
Status: resolved
Claimed: 2026-10-23 research subagent

## Question

### Purpose

一个 node 并进多种特征会让 match 变多，也会把不带信息的特征连噪声一起带进来，这张票找出判断「这一条该不该并进去」的现成办法。

已定的量法（方向文档第 3 节末）：不单独量；拿 app 跑两遍，一遍带这一条、一遍不带，只因为这一条才多 match 进来的那些图和同日普通买入对照比；看不出时先留着、标「待验证」。要查清：

- tune-gates-v3（`.claude/skills/tune-gates-v3/`）、feature-study（`.claude/skills/feature-study/`）、旧 tune-gates 的「去掉一道闸看该不该留」能不能直接做这件事；能的话怎么调用、在训练段上读哪份数据；不能的话差在哪、补多少。
- 「只因为这一条才多出来的 match」样本通常很少，现有工具在这种样本量下给出的是什么样的结论，怎么报「看不出」才不被读成「没用」。
- 「至少 k 条成立」的写法下，去掉一条的同时 k 要不要跟着变。

只在训练段上做，不读 2026 年的数据。

## Answer

**方向**（2026-10-23 主会话按用户「结构化标注今后是构建 path2 pattern 的唯一方式，一切为它服务」定）：以结构化标注里的特征为单位来量：一条特征就是标注里的一个勾选或一种子事件，也就是 app 里 where 的一个分支或一组子事件。底层计算尽量复用现有调参与特征验证的同日对照，入口挂在串循环的技能上，结果要能回到标注界面、按特征显示；现有工具差什么就以这个用法为准去补，不另起一套口径。

研究全文、数表与图：[research/05-measure-in-context.md](../research/05-measure-in-context.md)；实验脚本与原始输出：`.scratch/annotation-path2/scripts/05-*`。只读了截到 2025-12-31 的训练副本，没读面板缓存，没写账本。

### 一句话

能复用，但复用的是 tune-gates-v3 里面的计算代码，不是它的调参命令；feature-study 和旧 tune-gates 做不了这件事。在 bottom_burst 上真跑了一遍，全股票池四年约一分钟出结果；多出来的买点通常只落在几百只股票上，这份数据只分辨得出 0.07～0.19 以上的差别，所以结论几乎总是「看不出」，报法要专门防它被读成「没用」。「至少 k 条」去掉一条时 k 不变。

### 现有工具能不能直接做

- **tune-gates-v3 的计算代码：能。** 用 `.claude/skills/tune-gates-v3/scripts/daily.py` 的 `DailyEvaluator` 固定一份行情快照和一份逐日涨跌标签，带和不带两遍都在它上面跑：这条特征能用参数关掉时用 `evaluate(params)`，「不带」的版本是另一份声明时用 `evaluate_control(module, params)`。按「股票 + 日期」取差后，把多出来的那批交给 `scoring.py` 的 `WindowPlan.summarize` 算它比同日普通买入对照（`path2/GLOSSARY.md:114`）多出多少方向成绩，交给 `WindowPlan.stock_bootstrap` 估偶然波动。读哪份数据由调用时传入：传 `datasets/pkls_until_20251231`、标签截止日不晚于 2025-12-31。
- **tune-gates-v3 的调参命令：不能。** 它默认读含 2026 年的完整行情，一启动就在账本里为最后检查预留留着没碰过的数据，做的是参数搜索，没有「带 / 不带」模式，也不取差。
- **feature-study：不能，判法可借。** 它比的是 pattern 内部「过闸的和全部的」，不是「多出来的和同日普通买入」；标签是盘中口径；前提和取数绑在旧版调参的账本与扫描结果上。它把结论分成「确实有用 / 没用 / 判不了（附原因）」三栏的写法，下面的四选一照它的思路来。
- **旧 tune-gates「去掉一道闸看该不该留」：不能。** 它比的是整个 pattern 改前改后的成绩，只认扫描网格里有「最松一档」的参数，要走完整条旧流程，默认也读含 2026 年的行情。

### 还差什么、各补多少

1. **「不带这一条」的版本怎么产生。** 现在只能手改声明，或给每条特征配一个开关参数。要按特征显示，就得按名字找到 where 里的那一支并摘掉。等组合子有了带名字的分支，量的时候按名字摘：约 50～80 行加测试。名字和组合子的样子归「『至少 k 条成立』组合子和『底部』类复合事件的写法约定」那张票定；本票交给它两条输入：分支要有名字、和标注里的勾选同名；复合事件（`path2/GLOSSARY.md:62`）不论有没有某组子事件都产出，子事件只经 where 起作用，这样去掉一组子事件也只是改 where。
2. **量法本体**：跑两遍、两个方向取差、四选一判法、写结果记录。约 150 行加约 100 行测试；按股票分块并行约 20 行，v3 的评价器是单进程的。入口挂在串循环的技能上，计算代码按路径调用 v3 的那几个类。
3. **结果回到标注界面**：每条特征一条记录（字段见下面第 7 条要求），写记录约 30 行。存在哪、界面怎么显示，归「结构化标注」和「串循环的技能」两张票。
4. **一处口径冲突，要在地图上定。** v3 现在的同日对照是「同一天按当天波动切五档」，股票池是全部股票。已归档的旧 effort 判过这种配法会漏：偏爱平时很疯的股票，方向白输 0.02，最坏一年 0.08（登记簿 FC-016）。旧 effort 推荐改成「同一天、同一池子里波动最近的 10 只」，用自己的默认股票池，并写明调参工具接入时一并换。这些至今没做。新地图的 Notes 说这条结论沿用，本票方向又说复用 v3 的对照，两者现在指向不同的东西。建议：量特征只调用 v3 的对照代码，v3 一换，量法自动跟上；换不换、什么时候换是 v3 本身的事，同时影响调参和最后检查，量级约数百行。建议放进「没碰过的数据上的检查：沿用 tune-gates-v3，跨次计数怎么补」那张票，或另开一张。在换之前，专挑某种波动的特征会被白算好或白算差约 0.02，一般翻不动「看不出」。

### 多出来的少时怎么报

现有工具这时会误导：v3 打折后的分会把证据薄的正领先压向 0，只有一个时段有买点时直接记 0，读起来就像「没用」；打折保留的比例也不反映看不看得出。所以改用「领先 ± 2 倍偶然波动」这条线，四选一：

| 对用户说 | 条件 | 处理 |
|---|---|---|
| 看得出更好 | 线整条在 0 右边 | 并进去（训练段上只算参考，输赢仍只由最后检查判） |
| 看得出更差 | 线整条在 0 左边 | 不并 |
| 看得出没多大用 | 线整条落在 ±0.03 以内（0.03 待验证） | **建议默认不并、交用户定**：多出来的只是普通买入，会冲淡 pattern。照实验的宽度，多出来的要落在上千只不同股票上才可能出现 |
| 看不出 | 其余 | 先留着，标「待验证」 |

报「看不出」时，三件事要一起说：多出来几个买点日、落在几只股票上；这份数据最多分辨得出多大的差别；实测值，以及它还不能排除是 0、也不能排除其实好多少或差多少。例：「量比这条多带进来 4353 个买点日，只落在 323 只股票上；这份数据只分辨得出 0.13 以上的差别。实测比同日普通买入差 0.035，还不能排除是 0，也不能排除其实好 0.05 或差 0.12。先留着，标待验证。」另附整个 pattern 带和不带的领先差多少，调参和最后检查看到的是它。

### 「至少 k 条」去掉一条时 k 要不要变

不变。k 不变时，多出来的正好是「这条特征是凑够 k 的那一票」的那些；k 跟着减一，带这条特征的版本反而整个落在不带的版本里，多出来的为空，量到的是「降门槛」的效果。实验里两种情形都照预期出现：k 不变多出来 11316 个买点日，k 减一多出来 0 个。方向文档第 7 节已定 k 事先定、不按成绩挑，这和它一致。两个边界：k = n（每条都要）时，去掉一条是放宽，按「这一条挡掉了哪些」照样比；去掉后剩下的不够 k 条时，这条单独量不了，照实报。

### 硬要求（每条后面是它防的事）

1. 量法入口写死只读 `datasets/pkls_until_20251231`，标签截止日晚于 2025-12-31 就拒绝。防的是：v3 和旧 tune-gates 默认读含 2026 年的完整行情，照搬就把没碰过的数据混进训练段的量法。
2. 不经任何调参命令，不写样本使用账本。防的是：v3 一启动就为最后检查预留没碰过的数据，一次训练段上的量法会占掉最后检查的数据范围，而训练段本来不记账。
3. 带和不带在同一个评价器上跑（同一份行情快照、同一份逐日标签），按「股票 + 日期」取差。防的是：两次运行的数据或标签不同，差别被算到特征头上。
4. 同日普通买入对照、方向成绩、偶然波动都调用 v3 的同一份代码，不复制、不另写。防的是：量特征和调参、最后检查用两套口径，一处白得的领先在另一处被当成本事；v3 换对照时量法也会漏跟。
5. 多出来的、丢掉的两个方向都算，丢掉的不为空时一起报。防的是：特征改动碰到复合事件本身时，漏看它挡掉的买点。只改 where 时丢掉的恒为空，代码和实验都对得上。
6. 结论按「领先 ± 2 倍偶然波动」四选一；报「看不出」时同时报买点日数、股票数、这份数据最多分辨得出多大的差别和实测值；不拿 v3 打折后的分判。防的是：样本少时打折后的分被压到 0，「看不出」被读成「没用」。
7. 每条结果记录带特征名、app 版本、k 和这一组有哪几条、训练段范围、数据指纹，以及多出来的那些买点（股票、日期）。防的是：app 后来改过（别的特征进出、k 变了），旧结果还挂在标注界面上被当成现状；带上清单，界面才能把多出来的图调出来看。
8. 一次只去掉一条，k 不变；并进新特征时不同时改 k。防的是：「并进这一条」和「改门槛」混在一次差里分不开。

### 留待实施阶段验证

- **四选一判法的校准**
  - 验什么：「± 2 倍整只股票重抽偶然波动」这条线，在没有信息的假特征上误报「看得出」的比例。这个偶然波动不含全市场同日一起动的冲击，v3 自己说它是下限，所以这条线偏窄。
  - 何时触发：量法代码写好、第一次给真实特征出结论之前。
  - 怎么判：在训练段上造一批假特征，例如从同日同波动档的普通买入里抽，股票数和扎堆程度照真实的多出来的那批。「看得出更好 / 更差」合计误报不超过约 10%（待验证）。
  - 验证前能做什么：照默认出结论，旁边标「判法待校准」。
  - 没过怎么办：把 2 倍放宽到误报回到线内的倍数（例如 2.5 或 3），重跑这项检查，已出的结论按新倍数重判。
- **同日对照换配法以后结论变不变**
  - 验什么：v3 换成「波动最近的 10 只」和旧 effort 的默认股票池以后，已量过的特征四选一结论变不变。
  - 何时触发：v3 换对照的改动合进主目录时。
  - 怎么判：已量过的特征照原记录重量一遍，结论变了的列出来。
  - 验证前能做什么：照用五档对照。
  - 没过怎么办：按新结论处理；变成「看得出更差」的特征要从 app 里拿掉时，先问用户。
- **「看得出没多大用」那条 ±0.03 线和它的处理**：第一次有特征落进这一档时，向用户确认这条线和「默认不并」。在那之前照默认。

### 顺手量到的（待批准后登记）

「三条至少 2 条」改成「去掉量比、至少 1 条」时差出来的那批，即沉寂 ≥ 40 天、不同峰 ≥ 3 个恰好一条成立，且量比不到 10。它在 2024-01..2025-10 比同日普通买入多 +0.024，±2 倍偶然波动 +0.002～+0.047，刚好不跨 0；在 2022-01..2025-10 是 +0.017，−0.002～+0.036，跨 0。它是为演示「k 跟着变会量到什么」而量的对照，不跨 0 这条线是跑之前写进脚本的。按登记规则，它在一段上过了最低线，应追加到 `docs/feature_candidates.md`，状态 exploratory。要注明三点：用的是会漏的五档对照；只在一段过、刚过线；可能和 FC-008（`first_drought_min=40` 在 2025 窗上做负功）是同一件事。
