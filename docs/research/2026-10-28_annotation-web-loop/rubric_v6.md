## 使命与两条原则（用户定，一切取舍以此为准）

标注工具的使命：用户通过看图标注直接得到 path2 pattern。流程是：找图 → 标注 → 会话写 app → 拿 app 对标注 → 盲看 → 调参 → 最后检查。

1. **标注功能能高效、高质量地完成这个使命**：
   - 标得快、标得准；
   - 标出来的东西能直接变成 pattern；
   - pattern 能直接对回标注。
2. **用户友好、心智负担低**：
   - 用户要知道的概念、要记的规则、要认的词越少越好；
   - 看一眼就读对。

## 1. 项目特化

- **核心链路**：
  1. 在主图画框 → 起或选特征名 → 放买点（tool `point`，label `buy` / `no_buy`）→ 框归哪个买点（成员链）；
  2. 未归类页整行挪进 pattern（`move`）；
  3. pattern 页看 `features` 区、`app` 行、`instances` 表、页头 `next`；
  4. 会话在对话里出题，每题带链接 `#q=<id>`，工具按题号在侧栏显示这道题要看的图；
  5. `compare` 档对照 app → 点两段之间的签跳图。

- **流程**：用户拿到一张还没标的图（WHLRP），做一次核心标注任务。经过的状态按顺序是：

- **判什么**：把这串截图当成一次连贯操作：
  - 每一步，下一步该做什么看得出吗；
  - 前后两步衔接上了吗（上一步的结果在下一步看得到）；

  - 第 3.2 节对应操作（画框、改属性、指定框归哪个买点）的点击数是否超过基线（H13）。

## 术语表

方案层的词：它们的意思由方案决定，改动它们的含义或算法要用户拍板。正确含义如下。

- 特征：用户在图上认出并标下来的一样东西，如横盘、缩量、放量突破；可以是一个框标的那一段，也可以是框上的一条属性；跨图、跨 pattern 共用
- 特征名：特征的叫法，如「横盘」；随时可改，改了所有标着它的框跟着变，意思不变
- 定义：一句话说清一个特征什么算、什么不算；意思定下就不改，要改就另起一个特征
- 买点：一次命中里真正用于计算收益的那根 K 线；在工具里由用户用 tool `point` 放下，带 label
- label：用户给买点的判断，`buy` 或 `no_buy`
- 成员链：一个框归哪个买点；只在界面里定（N11）
- pattern：一个形态的声明，一组 node 加一组边；在工具里是一批买点的归属，一个买点只属于一个 pattern（N7）
- mapping：会话写 app 时为一个 pattern 写的清单，每个特征名一行，定一级：`must` 必须有 / `optional` 可有可无 / `must_not` 必须没有 / `excluded` 不放；随 app 进 git，不进标注文件；差签按它算
- 差签：某个买点的标注和 mapping 不一致之处，如 `−回踩` 表示 mapping 里「回踩」是 must、这个买点的标注里没有；buy、no_buy 用同一种算法（D5）
- app：一个走势形态的完整声明（拓扑 + where + 参数取值），由会话写出，可以独立扫描与评估
- match：一次完整命中；工具里 app 对某个买点的判断写 `match` / `no_match`
- detected：事件被检测出来（三档里最宽的一档）
- qualified：事件通过了所在 node 的全部 where
- matched：事件进了某一次 match（三档里最窄的一档）
- next：pattern 页头写的「这个 pattern 走到哪一步、等谁」
