# pattern 调参工作流重设计：最终报告

> **任务**：从整个业务系统的高度，按已形成的结论完善 tune-gates（执行端）和 feature-study（学习端），形成一个用户友好、功能强大的调参工作流。原始问题见同目录 `原始问题.md`，研究起点见 `背景与已定结论.md`。
> **团队**：learner（学习端）、executor（执行端）、stats（统计审查）、flow（用户工作流）。四份定稿文档和实验脚本都在同目录。本报告是 leader 的整合与裁决；各文档之间数字不一致时，以本报告 §10 为准。
> **证据**：本报告中所有项目内路径均相对 repo root。数字除标【推导】【猜测】外都有复现脚本（`repro/<成员>/`），全部只读 2026-09-07 那轮 bb_v1 的现存产物（定案前底座）。这些产物当前代码已再生不出，但作为方法实验仍然有效。
> **术语**：本文的「闸」指 where 阈值条件，包括过滤型字段（如最小 bo 数），和 `path2/CONTEXT.md` 里的「闸 / gate」（detector attempt 内部判据）同名不同义，见 §12。「回踩」指一个 tb 事件，是计数和去重的观测单位（团队文档里叫「回踩段」）。「买点 bar」即词表的「买点 / 样本 bar」。「工作点」指当前 `params.yaml` 的现役参数。

## 0. 一页结论

1. **调参真正稀缺的是时间上独立的样本，不是算力。**
   - bb_v1 长表 3522 万行，只对应 94781 个独立的（股，买点日）。
   - 同一只股票里的买点高度相关，按股的设计效应是 7~10；同一个回踩还被长表重复计数 1.22~1.44 倍。
   - 在现役参数附近，这份两年数据只能分辨约 3.5 个点（只验一个事先写好的改动）到 4.8 个点（筛一批改动）以上的首次穿越率差别。实测的真实效应多在 2~3 个点。
2. **问题 F 要修正：那一轮没找到稳健区域，主因是效应比噪声小，不是格子多。**
   - 挑选噪声只有被选格误差的 0.9~1.7 倍，格数跨 4 个数量级几乎不变；64、648、4096 格的子网格校正后同样 ≤0。
   - 0.150 的挑选偏差扫描之前就能算出来。
   - 「先减闸、再联合」的顺序仍然对，但更根本的约束是分辨力。
3. **筛参数必须在现役参数附近做，不能用「对其余参数取平均」的边际效应。**
   - 提高突破门槛 0.003→0.0075：取平均 +0.07 点，现役闸下 +3.13 点，闸全关 +0.06 点。
   - 交互和主效应同量级，平均效应估的是一个不会部署的量。
   - 原七层方案里的「按交互分组」「由粗到细换折」「响应面」「股票池逐轮淘汰」都判为不做（§9）。
4. **闸该不该存在由学习端判，但时间上独立的数据只能在调参之后开一次。** 所以一轮调参里：
   - 闸只做「删了不亏」检验；
   - 闸「确实有用」的判定和候选改动写进同一份事先冻结的清单，在两段没碰过的数据上各开一次；
   - 闸的判定只影响下一轮网格。bb_v1 本轮 6 道闸预期全部「判不了（样本不够）」。
5. **结构上不新增、不合并 skill。** tune-gates 升格为调参唯一入口，负责对话、状态和阶段推进；feature-study 保持独立，并被它调用。两端共用登记簿和新增的样本使用登记 `docs/sample_usage/<app>.jsonl`。
6. **用户体验：八个阶段，常规只停三次，全部在数据说话之后。**
   - 停 1：看过优势检查后确认开工。
   - 停 2：自动核查定不了时复核机制，可能不出现。
   - 停 3：独立验证之后定案，用户只能确认写入或整体不写。
   - 另有一个条件停点：开确认窗前预期把握不到一半时先问（§4.7）。
   - 用户只定一个数：「最小关心改进」，默认 2 个点；采纳规则有默认值，停 2 出现时顺带确认。说「继续调 bb_v1」，系统从持久产物推出下一步。
7. **9 月 8 日那两项定案的证据强度差很多，两项都还没经独立验证。**
   - 提高突破门槛是唯一站得住的改动：按回踩去重 z 3.13，筛选门槛 2.99，刚过线。它依赖 burst 闸开着，和 FC-006 不构成正面冲突。
   - 删峰龄闸测不出效应，但满足「删了不亏」。
8. **发现一个现有代码缺陷。** 长表汇总、稳健区识别、查格子、path2_web 的首次穿越汇总都按叶子实例去重，挡不住同一回踩被多个 burst 前缀重复计数，读数最多偏约 1.1 个点。实施时第一个修。
9. **建议的下一步：按本报告写实施计划并实施。** 计数缺陷修好、独立验证功能落地之前，**不要动 2022-09~2023-11-03 和 2026-03-02~06-18 这两段数据**。它们是 bb_v1 仅有的确认窗，用错口径开一次就烧掉了。

## 1. 从业务系统看调参

### 1.1 调参在 pattern 生命周期里的位置

```
写 pattern（authoring-path2-app / detector）
  → 这个 pattern 比随机买入有没有底子（优势检查）
  → 每道闸该不该存在（学习端）
  → 检测参数与阈值放哪（执行端）
  → 用没碰过的数据确认
  → 定案
  → 新数据积累后复验
```

原来两个 skill 各管中间一段，靠文档里的上下游条款衔接，「下一步该调哪一端」没有主人。2026-09-07 那一轮顺序做反，就出在这里。

### 1.2 资源是什么

- **算力**：每股反转循环加内存根治之后，已经不是瓶颈。新流程的筛选扫描只要 73 个检测组合，全宇宙几分钟【推导】。
- **样本**：固定股票池 × 固定时间窗里的买点。每一次「看了收益并据此做选择」都在消耗它。最稀缺的是时间上独立的数据：bb_v1 只有往前约 14 个月、往后约 3.5 个月两段。

所以「最节约资源」落到四件事：
- 每次比较用尽可能多的有效样本；
- 比较的总次数尽可能少；
- 同一段数据不重复挑选；
- 确认窗只开一次。

### 1.3 用户的心智预算

用户只该判断三件事：值不值得调、某个机制在业务上能不能接受、要不要采用。先后顺序、数据怎么分、用什么指标、怎么校正，全部由系统负责。

## 2. 改写设计的实测事实

| # | 事实 | 数字 | 出处 | 对设计的影响 |
|---|---|---|---|---|
| 1 | 样本比表面少一个数量级 | 3522 万行 → 94781 个独立（股，买点日）；按股设计效应 7~10；功效线 100 个 bar ≈ 10~25 个独立观测；长表实际含 4036 只有 match 的股票（台账的 1517 漏记了 OOM 打断的轮次） | stats e1、e2 | 所有误差按股去簇；功效线改为有效样本口径 |
| 2 | 同一回踩被重复计数 | 行 / 回踩 1.22~1.44 倍；点估计偏 0.5~1.1 点；突破幅度改动的 z 从 2.01 变成 3.13 | learner e4c；stats e2、e10 | 计数单位改为回踩；修代码缺陷 |
| 3 | 挑选偏差能事前算，和格数关系很弱 | 乘数 0.9~1.7（格数 64~265 万）；事前上界公式给 0.13~0.18，覆盖实测 0.150；子网格功效线 100 时校正后全部 ≤0 | stats e3 | 噪声地板计算器；修正问题 F |
| 4 | 平均主效应 ≠ 工作点上的效应 | 突破幅度：平均 +0.07、工作点 +3.13、闸全关 +0.06；差中差 z 3.08 | executor e1；stats e9 | 筛选在工作点做，闸全关的宽进点只作旗标 |

| 6 | 分辨力 | 单参数翻转的配对差误差 1.26 点，两参数同翻 2.19 点；筛选 x≈4.8 点，单个预写改动 x≈3.5 点 | executor e4；stats e10 | 开工前告诉用户；联合常退化为一次改一个 |

| 8 | 基线必须同日匹配 | 只按 ATR 层：2025 +6.8；× 同一 40 日窗：2024 −0.3；× 同一交易日：2024 +2.5 [−0.4, +5.4]、2025 +3.0 [+0.2, +5.8] | stats e5、e5b | 优势检查口径；匹配粒度进尺子指纹 |

| 10 | 数据覆盖 | 主目录数据到 2026-08-17；股票池不含退市股；notes 里「数据末端 2026-03-08，外推做不了」不成立 | executor §1.8 | 两段确认窗可用；往前窗只做配对差 |

## 3. 设计原则（由 §2 推出）

- **P1 先问有没有底子，再调。** 调参只能把已有优势磨锐；没有优势时，从很多组合里挑出来的最好成绩，期望上一定为正，但那是运气。
- **P2 尺子和退化档不进网格，其余参数一个都不由人事前否决。**
  - 尺子：label、基线、分层定义，以及运行口径。
  - 退化档：非法值、只剩一个合法值、机制上等于没设。
  - 人定取值范围的时点：看过优势检查之后，看任何档位收益之前。
- **P3 在将要部署的那组参数附近评估改动。**
- **P4 闸的存在性由学习端判；执行端对闸只能得出「删了不亏」。**
  - 加闸：要求显著为正，并在时间上不相交的数据里复现。
  - 删闸：只要证明损失上限小于用户不在意的差别。
  - 两条都不满足：固定现值。
- **P5 每次看收益都记账；时间上独立的数据，调参之后按事先冻结的清单只开一次。**
- **P6 开工前说清分辨力。** 「维持现役」「判不了」是正常结局，不是失败。
- **P7 首次穿越率是方向判定唯一的主指标。** 前瞻收益只报幅度，理由见登记簿 FC-009。
- **P8 进度从持久产物推出，只有人的裁定写账本。**

## 4. 用户工作流

### 4.1 skill 结构

| 方案 | 取舍 |
|---|---|
| 维持现状 | 顺序靠用户记，09-07 那一轮已证明会做反；「继续」没人接 |
| 新增编排 skill | 三份 description 抢同一批触发词；停点规则、人话译法要么重复、要么搬家；需求覆盖和下一行相同，多出来的只是文件分离 |
| 合并两个 skill | 学习端的独立用途（「排行榜前排都是 XX」、批量清登记簿）被迫背上调参状态机；批量多重性防线失去物理边界 |
| **tune-gates 升格为唯一入口（采纳）** | 触发词自然分工：参数、闸、调参、稳健区域归 tune-gates；特征、直觉、形态、登记簿归 feature-study。代价是 tune-gates 的 SKILL.md 要重排，学习端改动若影响流程要回头改它 |

两端都会消耗的持久资源放在两个 skill 之外：已有的登记簿 `docs/feature_candidates.md`，加上新增的样本使用登记。

### 4.2 用户怎么开口，路由到哪

编排入口的第一个动作永远是只读的状态探测。

| 用户会说 | 路由 |
|---|---|
| 「调一下 bb_v1 的参数」「bb_v1 重新调一轮」 | 从第一个未完成或已失效的阶段开始 |
| 「bb_v1 调到哪了」 | 只汇报进度与下一步，不动手 |
| 「继续调 bb_v1」 | 直接执行下一步，遇到停点才问 |
| 「峰龄闸还要不要」「这道闸该不该删」 | 在调参数据上做「删了不亏」检验；满足且用户确认它不是走势定义的一部分，才先删、标暂定；「确实有用」进下一份验证清单 |
| 「distinct_pk 定 3 还是 4」 | 已判「确实有用」的闸直接进联合网格；没判过的先走上一行 |
| 「验证一下 XX 有没有用」「XX 是不是只是波动率在起作用」「把登记簿里的候选跑一遍」 | feature-study 独立处理，结论进登记簿，下次调参自动读到 |
| 「bb_v1 到底比随机买好吗」 | 只跑优势检查 |
| 「新数据来了，上次定的参数还成立吗」 | 查样本登记，有没碰过的窗口就对现役参数做独立验证 |
| 「持有期改成 20 天再调」 | 停下来问：改尺子等于开一份新口径，之前的结论都不能直接比 |
| 「给 bb_v1 加个节点」 | authoring-path2-app。它的 Step 0 分诊里「只调参数」的分支要改成转 tune-gates（§7.5） |

跨会话限制要如实交代：新会话里只说「继续」两个字，任何 skill 都不会被触发，要带上 pattern 名或「调参」字样。

### 4.3 八个阶段

| # | 阶段（对用户只说业务名） | 系统自动做什么 | 用户 |
|---|---|---|---|
| 1 | 开局核对 | 认出 pattern；比较代码、底座、尺子自上一轮以来是否变过；从实际数据文件探测覆盖范围；在任何人看收益之前，把训练段（2024~2025）、往前确认窗、前向核对窗写进账本 | 不停 |
| 2 | 先看有没有底子 | 宽进点（检测参数在现役值、闸全关）和工作点，各自对比同一交易日、当日同一波动层的随机日，逐年判「有底子 / 还不能确定 / 没有」；同时算出分辨力，以及按用户关心的最小改进最多能同时动几个参数。全宇宙约 3~5 分钟【推导】，不需要一致性验证 | 不停，结论并入停 1 |
| 3 | 定范围 + 开工确认 | 每个检测参数提现值、松一档、紧一档；自动剔除尺子参数和退化档；标出每道闸在学习端的审定状态；估算耗时 | **停 1** |
| 4 | 筛参数 | 检测参数：在工作点（为主）和宽进点（旗标）两个底座上单翻转，另加两两翻转探针，每个回踩只计一次，按股去簇的 z 经多重比较校正。在役闸：在工作点上做「删了不亏」检验。自动附带算术归因、冲突检测与拆解、顺手发现的登记 | 不停 |
| 5 | 机制复核 | 能自动定的先定掉（如「是波动率代理」由学习端判）。留给人的两类问题合成一条消息：某个检测参数的机制在业务上能不能接受；建议删的闸是不是走势定义的一部分。顺带确认采纳规则，默认按训练数据上的证据从强到弱：先整套改动、再逐项退、最后维持现役；停 2 不出现时用默认 | **停 2**（有需要才出现） |
| 6 | 几个参数一起调 | 只把幸存参数放进联合网格，参照格是工作点，按噪声地板自动减档。样本只够一次改一个参数时，退化为「在单个改动里挑」，并如实告诉用户。之后按采纳规则机械展开成决策映射，与验证清单一起冻结写进账本，再发一条不打断的通知，报映射第一项的验证把握 | 不停；把握不到一半时停下来问（§4.7） |
| 7 | 用没碰过的数据验证 | 两段各开一次，用同一份清单，按事先写好的决策映射给出结论（§6.3） | 不停 |
| 8 | 定案 | 汇总训练期和验证期读数，按映射机械给出结论。用户只能确认写入，或整体不写、维持现役；不能换成别的配置，也不能只写一部分。不写时两段窗照样记为已用，理由记进账本。删闸验证不过时按映射退到不含删闸的配置，不临时问；本轮中途不改正式参数 | **停 3** |

顺序的理由：
- **优势检查在一切调参之前**：没有底子时，调参挑出来的成绩是运气（P1）。
- **定范围在优势检查之后、筛选之前**：看过各档收益再定范围，范围本身就成了又一次挑选。
- **机制复核在联合之前**：被人否掉的参数不该占联合网格的格数。
- **独立验证在定案之前**：定案时手上才有唯一无偏的数字。

### 4.4 三个停点说什么

完整模板见 `flow_用户工作流.md` §3.2，下面是必须包含的内容。

**停 1 · 开工确认**
- 底子：逐年说。bb_v1 是「2025 年有但不厚，2024 年还不能排除是 0」。
- 分辨力：筛参数时约 4.8 个点以上才分辨得出，只验一个预写改动约 3.5 个点，同时改两个参数再大七成左右。
- 请用户定「改进不到几个点不算数」（默认 2 个点），告诉他这个数用在三处，而且开跑后不能改。附带代价：两年数据下，底子多半只能判「还不能确定」。
- 每个检测参数的松紧取值；「范围最好现在定死」。
- 闸的预期：本轮只查「删了不亏」，各道闸有没有用在往前窗上只能分辨约 2.8~7.1 个点，预计全部「判不了」。
- 两段没碰过的数据留到最后各用一次，以及主确认的预期把握（bb_v1 约三分之二）；有想一起验证的想法现在说。
- 总耗时；如有超过半小时的一致性验证，并在这里批准。

**停 2 · 机制复核**
- 筛选结果一句话：「一共比了 N 个改动，k 个分辨得出」，刚过线的要说「刚过线」。
- 需要人判断的机制（如「确认根数加多可能只是多等几天再买，不是更会挑股票」）。
- 满足「删了不亏」的闸：买点变化，以及「是不是走势定义的一部分」；说明这是按调参数据的初步结论，最终判断等验证完，验证不过按事先写好的回退配置处理。
- 采纳规则：默认按训练数据上的证据从强到弱，先整套、再逐项退、最后维持现役。用户可以改，但必须在打开验证数据之前定。

**停 3 · 定案**
- 推荐改动，训练期两年读数和买点变化，扣掉挑选偏差后的数字，以及这组参数在训练数据上一共比较过几次。
- 往前窗读数（分辨得出 / 分辨不出，附本次验证的预期把握）、前向窗读数（有没有明显变差、方向是否一致）。
- 按映射得出的结论（采纳 / 暂定采纳 / 撤回），并说明两段数据已用掉。
- 用户只能确认写入，或整体不写、维持现役；不能换成别的配置，也不能只写一部分。

每个「有用 / 没用」的说法都必须带两样东西：
- **分辨力**：超不出就说「分辨不出」，不说「没用」。
- **效果靠多少个回踩撑着**：例如提高突破门槛靠每年 33~41 个掉出的回踩。

### 4.5 「继续」与状态

状态探测扩到两端，仍然只读。每个阶段都有「完成证据 + 是否仍有效」，有效性按四个指纹和数据窗判断：代码、底座、源码、尺子。「继续」按顺序检查，命中第一条就执行：

1. 有被打断的长任务：断点续跑，只说「接着跑，还剩约 N 分钟」。
2. 代码、底座或尺子自最近一个有效阶段以来变过：算出哪些阶段失效。如果是定案本身导致底座变化（当前底座快照 = 账本里采纳的候选），报「定案已落地」；否则报哪些结论不再有效、重做代价多大。
3. 有问过但没落账的人工裁定：带着已算好的证据重问，不重算。
4. 执行最早一个未完成的阶段。
5. 全部完成：汇报定案日期，以及下一次能做独立验证的最早日期。

写盘顺序约定：产物先写完，账本记录最后写。有账本记录就说明对应产物完整；有产物没记录就是半截状态。半截状态全集见 `executor_执行端方案.md` §9.5。

### 4.6 失败与降级

| 情形 | 用户看到 | 默认处置 |
|---|---|---|
| 两年都没有底子（误差上限低于最小关心改进） | 「没有可磨的，挑出来的好成绩多半是运气」 | 建议停，回去改结构 |
| 只有一年证实或两年都未证实 | 并入停 1，逐年说 | 继续，结论带「底子未证实」 |
| 筛选后没有分辨得出的改进 | 「单独松紧都没有大到分辨得出；其中这几道闸删了不亏」 | 维持现役，或走删闸加验证 |
| 现役参数最近的改动本身在分辨力以内 | 「不一定错，但也没被证明是改进」 | 放进验证清单做独立验证 |
| 学习端判某道闸是代理 | 「它靠挑低波动的票；删掉会真的损失，保持现状；要不要改成明确的波动率条件属于改结构」 | 固定现值，不问 |
| 两端结论方向相反 | 自动拆解，拆得开就在报告里说明 | 拆不开才停 |
| 推荐取值落在范围边缘 | 「真正好的区域可能在外面」 | 耗时 30 分钟以内自动扩（记一次挑选），超过就问 |
| 样本只够一次改一个参数 | 「同时改两个时，误差比你关心的改进还大」 | 只在单个改动里挑 |
| 改进伴随买点减少超过三成 | 并入停 2 或停 3 | 由用户在质量和数量之间取舍 |
| 独立验证否定或没给出确认 | 按 §6.3 判读表的人话 | 撤回或暂定；**禁止在同一段数据上换别的候选再验** |
| 没碰过的数据已经用完 | 「它在某日已经用来验过某候选，再验会偏乐观」 | 等数据积累，给出最早日期 |
| 学习端验证数据和调参数据对不上（自检门失败） | 「这批验证不作数，闸暂时保持现状」 | 这批判定作废，调参继续 |
| 本轮途中代码变了 | 「从某阶段开始的结论要重做，大约要多久」 | 重做受影响部分 |

### 4.7 什么时候停下来问

- **不可逆**：退役清理；改衡量尺子；写入正式参数（即停 3）；要验的候选不在事先写好的清单里；开确认窗时预期把握不到一半（往前窗只能开一次、不会随时间变长，前向窗会随数据积累变长，现在开还是等是业务决定）。「作废已有扫描结果」这个停点取消，因为研究声明改为窗口级，新开一份、旧的保留。
- **超过半小时**：正常一轮里只有「新接入 app 或改了 detector 之后的一致性验证」（约 47 分钟），并入停 1 批准。
- **真研究决定**：停 1、停 2、停 3；没有底子时要不要继续；筛选后无幸存怎么办；验证没通过怎么办。
- **红线**：一致性验证没通过；旧结果复现不出；几种读数互相矛盾；两端冲突拆不开；确认窗已为某份清单开过；本轮途中代码变了。

以下全部自动、不问：路由到哪一端；数据分段；指标选择；每个参数试几档；按噪声地板减档；冻结验证清单；读写登记簿与账本；断点续跑；归因与冲突拆解；删闸验证不过时按回退配置处理。

### 4.8 对用户的说法

完整译法表见 `flow_用户工作流.md` §5.2，在 tune-gates SKILL.md §三补齐。几条最容易说错的：

| 内部说法 | 对用户说 |
|---|---|
| 边际 / 优势检查 | 「比同一天、同样波动水平的随机买入日好多少」 |
| 置信区间含 0 | 「还不能排除是 0」（不说「在误差范围内」，会被读成「就是 0」） |
| 筛选幸存 | 「这一轮一共比了 N 个改动，这个差别仍然分辨得出」，刚过门槛加「刚过线」 |
| 非劣效 | 「关掉它，首次穿越率最坏也只差 x 点以内，删了不亏」 |
| 功效不足 | 「样本不够，判不了」 |
| 暂定采纳 | 「写进正式参数，但标暂定，等没碰过的数据攒够再确认」 |
| 学习端 / 执行端 / 阶段编号 / 账本字段 / BH / Holm | 不出现 |

## 5. 两端分工与接口

### 5.1 分工

| 事项 | 归属 |
|---|---|
| pattern 相对随机日有没有底子 | 执行端 `tune.edge` 计算并写账本；学习端只读 |
| 闸（where / 过滤型）有没有信号、方向、形状 | 学习端 |
| 新特征口径（K 线几何、≥3 口径） | 学习端（现状保留） |
| 检测参数筛选、阈值与档位、联合、组合回放、确认 | 执行端 |
| 在役闸「开 ↔ 关」对比（删闸证据） | 执行端在筛选扫描里顺带算（事后切，零检测成本） |
| 冲突对账 | 学习端负责四步，拆解数据直接读执行端长表 |
| 样本使用登记 | 两端共写同一份文件 |
| 编排、状态、停点 | tune-gates |

### 5.2 样本使用登记（账本）

- **位置**：`docs/sample_usage/<app>.jsonl`，git 跟踪，只追加，`.gitattributes` 设 `merge=union`。`tune-gates/apps/<app>/exposure.jsonl` 删除并入。工程验证（等价性复跑等）不写。
- **记录类型**：

| kind | 谁写 | 何时 | 是否算「烧」 |
|---|---|---|---|
| `discover` | 任何研究 / 执行端 | 登记一条待验证发现 | 烧该条目的轴 |
| `select` | 执行端 | `tune.cell` 每调用一次一条；`tune.screen`、`tune.find` 各一条 | 烧涉及的轴 |
| `decide` | 执行端 | 改 `params.yaml`；带 `selects_on`、`provisional`、`depends_on` | — |
| `edge` | 执行端 | 优势检查 | 不烧，计次数 |
| `preregister` | 两端 | 冻结验证清单 | 不烧 |
| `verify` | 学习端 | 每条闸判定 | 计次数 |
| `reconcile` | 学习端 | 对账结论 | 同 verify |
| `extrapolate` | 执行端 | 确认窗开窗 | 该窗对清单内假设用尽 |

- **公共字段**：`ts, actor, kind, app, fc[], axes[], window{start,end}, stock_rule, head_buffer, git_head, base_fingerprint, source_fingerprint, ruler_fingerprint, n_looks, ref`。
- **「烧」的定义**：某窗对某条轴已烧，当且仅当该窗的 label 参与过这条轴的假设提出、取值挑选或做不做的决定。时间重叠判定时，买点区间要加上 label 窗后缀。挑选次数按参数族记（与已烧轴池内 |Spearman| ≥ 0.3 算同族）。确认窗全局只开一次，开窗后才加的候选只算探索读数。同一时期换一批股票只算半新样本：能用来筛，不能用来最终确认。
- **回填**：FC-001~010 各写一条 `discover`；那一轮的决策识别写 `select`（工程验证那一行不写）；2026-09-08 两项定案写 `decide`，均为 `provisional`，突破幅度那项带 `depends_on = burst 闸开着`。

### 5.3 学习端 → 执行端：判定记录

契约就是登记里的 `verify` 记录，不另起文件。

| 字段 | 内容 | 执行端怎么用 |
|---|---|---|
| `axis` / `param` | node.field + 运算符 / 绑定的参数名 | 对上长表轴与网格维 |
| `label` | 首次穿越、公式、k、horizon、观测单位回踩、按买点 bar 加权 | 口径核对 |
| `population` | 只放开本闸、其余参数取判定所服务的配置，附参数快照 | 判定成立的条件 |
| `code` | `git_head` 与三个指纹 | 失效判断 |
| `sample` | 窗口、股票规则、每年回踩数与买点 bar 数、软冲突、最小可检出效应 | 别复用 |
| `verdict` / `direction` / `time_flags` | 有信号± / 代理 / 反转 / 不稳 / 无信号；时间维未定 / 未验证 | 准入 |
| `bucket` | 确实有用 / 没用删了不亏 / 判不了（附原因） | 直接转述给用户 |
| `curve` / `shape` / `effective_interval` / `suggested_levels` | 各切点读数、形状、描述性区间、≤4 个建议档位 | 联合阶段布档 |
| `ni` | 工作点关掉本闸的原始差与单侧 95% 下界 | 删闸依据 |
| `stats` | 闸级 Simes p、BH q、族大小、控制集、清单引用 | 审计 |

学习端只给区间和形状，不给单点阈值，避免学习端挑一次、执行端再挑一次。

**失效判据**：
- 源码或尺子指纹变了 → 判定失效。
- 底座变了 → 只打标，在新工作点补算；这一步用同一份数据、零新检测。
- `decide.depends_on` 里任一项变了 → 报「这条定案是在旧设置下做的，需要复核」。
- 历史关闭行没有指纹 → 查关闭日期之后是否有提交改过该轴 detector 的源码，纯 git 查询。

**对用户的三栏与默认动作**：

| 对用户 | 条件 | 默认动作 |
|---|---|---|
| 确实有用 | 有信号 +，且在时间上不相交的数据里复现过 | 下一轮进联合网格，档位取 `suggested_levels` |
| 没用，删了也不亏 | 工作点关掉它，原始差单侧 95% 下界 ≥ −δ | 停 2 问语义；确认子族复核；停 3 按规则写入 |
| 判不了 | 其余；原因四种：样本不够 / 还不能排除是某段行情特有 / 效果集中在少数股票或时段 / 它挑的其实是波动率低的票（代理） | 固定现值、不进网格、排进下一批 |

### 5.4 执行端 → 学习端：反向登记与不对称规则

执行端的切片观察一律登记成待验证条目，并写一条 `discover`。条目在原有字段之外加三项：`app / 轴`、机器可复现的发现样本、执行端动作（未执行 / 已临时执行）。

| 动作 | 要求 |
|---|---|
| 加闸 / 让闸进网格调阈值 | 学习端判「有信号 +」，闸级显著，并在时间上不相交的数据里复现 |
| 删闸 | 非劣效：工作点关掉它，首次穿越率差单侧 95% 下界 ≥ −δ。一轮内先以训练段证据为临时依据，由确认子族复核，停 3 按规则写入 |
| 两条都不满足 | 固定现值、不进网格、排进验证队列 |
| 学习端判「有信号 +」的闸，执行端想删 | 不许直接删，先对账 |
| 检测参数改动 | 执行端自己筛选 → 联合 → 确认；`selects_on` 对应特征有方向相反的记录时进对账；切片直接定案的一律 `provisional`，直到确认 |

bb_v1 工作点实测（按回踩去重、按股去簇、δ = 2 点，stats e10）：

| 删哪道闸 | 两年合并差 ± SE | 单侧 95% 下界 | 判读 |
|---|---:|---:|---|
| 峰龄 60→0 | +0.77 ± 0.76 | −0.48 | 删了不亏 |
| vol_spike 3→0 | −1.65 ± 1.54 | −4.18 | 不能删 |
| first_drought 40→0 | −1.39 ± 1.93 | −4.56 | 不能删 |
| distinct_pk 3→1 | −1.03 ± 1.05 | −2.76 | 不能删 |
| 单日跌幅 0.2→不设 | −1.00 ± 1.26 | −3.08 | 不能删 |

「不能删」不等于「有用」：这几道闸的效应同样分辨不出，只是分辨力不足以证明删了不亏。FC-010「vol_spike 整条轴无区分度」是在宽进底座上测的；在工作点闸阵下删它，并不能证明没有代价。

### 5.5 冲突对账

- **参数 ↔ 特征对应**：声明在 feature-study `apps/<app>/adapter.py` 的新常量 `PARAM_FEATURES`；执行端写 `decide` 时从这里取 `selects_on`。
- **触发**：写 `verify` 或 `decide` 时，发现同轴或对应特征上有方向相反的记录。后写的一方发起，由学习端执行。
- **四步**：
  1. **口径对齐**：同一个量、同一标签、同一观测单位、同一总体。
  2. **集合拆解**：在执行端长表上零新检测完成，按回踩身份拆出掉出组和新进组，宽进与工作点各做、逐年，固定报「效果靠多少个回踩撑着」。
  3. **伪闸重放**：在没碰过的数据上，在旧阈值总体里按特征事后切。
  4. **裁决回写**：选择效应 → 真冲突，以学习端判定为准；结构 / 交互效应 → 不冲突，定案标暂定；拆不开 → 暂定，结论为撤销时并入停 3。

**实例：FC-006「突破幅度越大首次穿越越偏下行」vs 提高 `exceed_threshold` 定案**
- 第一步：两者不是同一个量。FC-006 的分母是 20 日最高价，样本是 bo 全流，标签含 none；检测阈值比的是被突破 peak 的价格。
- 第二步（learner、executor、stats 三方独立一致）：

| 底座 | 年 | 总变化（点） | 只删掉掉出组 | 掉出的回踩 |
|---|---|---|---|---:|
| 工作点 | 2024 | +3.09 [+0.36, +6.07] | +3.32 | 33 |
| 工作点 | 2025 | +3.28 [+0.78, +6.11] | +2.89 | 41 |
| 宽进 | 2024 | −0.16 [−1.22, +0.86] | −0.02 | 474 |
| 宽进 | 2025 | +0.25 [−0.72, +1.18] | −0.35 | 587 |

- 裁决：宽进底座上删掉约 12% 的回踩而读数不变，所以「挑高幅度买点有利」在边际上不存在；增益只在 burst 闸打开时出现，属于**交互效应**，不与 FC-006 正面冲突。定案标暂定，`depends_on = burst 闸开着`。
- 第三步需要 detector 侧新增突破幅度字段，读数只作描述，不改变决定。本报告把它列为延后项（§7.6）。

### 5.6 指标与观测单位

| 环节 | 统一口径 |
|---|---|
| 标签 | 首次穿越四态（`path2/eval.py::match_first_passage`）；none 排除（长表里约 36~38%）；不用含 none 的 {−1, 0, 1} 打分 |
| 观测单位 | 回踩 `(symbol, tb.start, tb.end)`；同一检测组合内每个回踩只计一次，任一前缀过闸即算过闸 |
| 估计量 | 按买点 bar 合并的 `up/(up+down+both)`；推断按股去簇 |
| 效应量 | 点；原始差（交易上买到的，用于调参和删闸）与层匹配差（判断是不是代理）都报 |
| 分箱形状 | 每箱合并比例 + 箱 CI；首次穿越标签下不用中位数 |
| 二元方向 | 取回归系数符号 |
| 前瞻收益 | 副标签，只报幅度，不作方向判定、不进准入 |

## 6. 统计口径定案

各文档的数字以本节为准。

### 6.1 通用

| 项 | 定案 |
|---|---|
| 用户唯一的数 δ | 「最小关心改进」，默认 2 点；开工确认时定，开跑后不改（改了算新一轮）。用在三处：优势检查「无边际」= 上界 < δ；学习端「无信号」= 上界 < δ；删闸「删了不亏」= 单侧 95% 下界 ≥ −δ |
| 误差 | 按股去簇为主。时间维只作旗标：在 13 个 40 交易日窗上做 Cochran Q，p<0.05 标旗；窗数不足 20 时不做以时间为簇的主误差 |
| 优势检查基线 | Δ = 格首次穿越率 − Σ w_s · 随机日首次穿越率_s；层 s = 同一交易日 × 当日横截面 ATR%(20) 三分位；w_s = 格内去重后定向买点 bar 的层占比。按股整簇自助，pattern 与基线各自重抽；宽进点与工作点、逐年；匹配粒度进尺子指纹；往前窗不用于这一步 |
| 优势检查判读 | 下界 > 0：有边际；上界 < δ：停；其余：边际未证实（继续并标注）；宽进点没有、工作点有：优势来自在役闸，继续 |
| 闸存在性估计量 | 只放开被判的闸、其余参数取判定所服务的配置；报原始差，以及池内按 ATR 三层 × 同一 40 交易日窗标准化的层匹配差。不用随机日层斜率（2024 年池内与随机日的 ATR 层斜率方向不同） |

### 6.2 执行端

| 项 | 定案 |
|---|---|
| 尺子识别 | ① `RUN_CALIBER` 的运行口径字段；② label / 基线 / 分层定义代码的哈希（新增尺子指纹）；③ 某档让 `eval_meta` 的 `end_node` 变了；④ 某档的首部缓冲需求超过本窗 |
| 逐档探针 | 构造合法性（`Params.from_dict(strict)` + `build_pattern`）；等价档合并；少于两个合法档的参数不进筛选 |
| 退化格 | 闸类轴紧档计数等于松档时自动并入松档，不计格数、不作邻居；删 `FLAG_RULES` |
| 筛选设计 | 两个底座：工作点为主，宽进点作「依赖背景」旗标；检测参数取现值、松一档、紧一档，紧档保留 30%~70% 的买点，不跨已知机制断点；加两两翻转探针。bb_v1：73 个检测组合、36 个对比 |
| 筛选幸存 | 两年合并、按股去簇的 z 经 BH，q = 0.10；分年 z 与年交互 z 只作旗标；交互兜底：探针 \|z\| ≥ 2 且一方已幸存，另一方也进联合；维数上限由计算器给 |
| 删闸后当轮重算 | 停 2 同意删闸后，检测参数的翻转效应在删闸后的工作点上重算（事后切，零检测成本） |
| 功效线 | n_pl ≥ 1.96 · p(1−p) · deff / (1.2 · s_dec · δ²)，δ 以比例计。bb_v1 标定 p=0.5、deff=5、s_dec=0.62，得 n_pl ≥ 3.29 / δ²；δ = 2 点时每折约 8233 个买点 bar。另设保底每折 ≥ 30 个回踩。删除「每年 ≥ 100 买点」 |
| 噪声地板上界 | floor = 1.4 × √(p(1−p) · deff / (1.2 · n_pl · s_dec))；≥ δ 的网格不许扫；换 pattern 必须重测 deff 和 s_dec |
| 开工前分辨力 | SE_flip ≈ SE_level × √((1−r̄)/r̄)；闸类改动 r̄ 直接数，检测参数取标定值 0.85。筛选 x = (z_BH + 0.84) × SE_flip；单个预写改动 x = 2.8 × SE_flip；两个参数同改约 ×1.7。bb_v1：SE_level 3.01 → SE_flip 1.26 → 4.8 / 3.5 点 |
| 联合识别 | 保留「两折取较差 → r=1 邻域最小 → 排序」；参照格改为工作点；bootstrap 每个副本连筛选一起重做，并报入围频率与集合复现率（按股 bootstrap 只含个股噪声，是外推损失的下界，只用来判断值不值得开确认窗） |
| 不做 | 按 node 分组；换折由粗到细；响应面（需要平滑时只考虑逐轴单调约束）；股票池逐轮淘汰；分数阶或 2 档全因子平均效应 |

### 6.3 独立验证

**两段窗**（双向各留 40 个交易日隔离）：

| 窗 | 买点区间 | 用途 | 对 +3.2 点效应的检出把握 |
|---|---|---|---|
| 往前窗 | 2022-09 ~ 2023-11-03，全部股票 | 主确认；只做配对差（股票池不含退市股） | 单侧单检验约 78%，max-T 接近，Holm（m=5）首步约 53%【推导；用训练窗点估计、未扣选择偏差，是上界】 |
| 前向窗 | 2026-03-02 ~ 06-18 | 核对：非劣效 + 与训练期同号；误差约 2.7 点，最小可检出约 7.5 点 | 约 22% |

**时序**：调参之前不开任何新数据。联合之后冻结一份清单写进账本，两段各开一次。

**清单的两个子族**（每道闸只进一个子族，两子族无逻辑依赖）：
- **确认子族（执行端）**：候选配置 K 整体 + K 的每个组成改动 + 删闸非劣效 + 回退配置。全部单侧，族内 α = 0.05，默认 Westfall–Young 逐步 max-T（按股 bootstrap），Holm 作保守备选。决策映射一并预注册。
- **闸子族（学习端）**：K 中保留的在役闸的存在性，条件总体 = K；闸内 Simes 合成，闸间 BH q = 0.05；功效预检 MDE ≤ δ 才进族；结论只影响下一轮网格准入。
- **描述性读数**（如对账第三步的伪闸重放）：开窗前标明「不进族」，结果不改变本轮任何决定。

**bb_v1 的确认子族与决策映射**（K = 突破幅度 0.0075 + 删峰龄闸，均相对 09-08 之前的配置）：
- H1：K 整体优于改前配置。
- H2：K 下突破幅度的组成效应（K vs 只删峰龄闸）。
- H3：K 下删峰龄闸非劣（K vs 只改突破幅度，边界 −δ）。
- H4：回退配置 K′（只改突破幅度）优于改前配置。
- H5：回退配置 K″（只删峰龄闸）相对改前配置非劣。
- 映射：H1、H2、H3 全过 → 采纳 K；否则 H4 过 → K′；否则 H5 过 → K″；都不过 → 主确认记为「不显著」，前向窗核对首选配置 K，按判读表「不显著」一行读。前向窗只核对这一个配置。

**映射怎么来**：用户在联合之前定采纳规则（默认按训练数据上的证据从强到弱：先整套、再逐项退、最后维持现役），联合之后系统机械展开成具体映射，开窗前冻结，不另加停点。三个条件：
- 证据强弱的度量事先写死；
- 展开出的每个配置都进确认子族；
- 预告的验证把握按族内校正门槛、并用扣掉选择偏差后的效应来算。

停 3 只许整体否决：否决只减少采纳、不抬高误采纳率；否决后两段窗照样记为已用，不能改清单重开；否决理由记进账本（否决若取决于确认窗点估计，多轮下来留下的采纳在效应量上会偏大）。

**判读表**：

| 往前窗主确认 | 前向：非劣效不过 | 前向：非劣效过、与训练期同号 | 前向：非劣效过、与训练期反号 |
|---|---|---|---|
| 显著 | 撤回 | 采纳 | 暂定采纳；前向数据攒满 1 年后复验 |
| 不显著 | 撤回 | 暂定采纳，报告预期功效 | 不写进正式参数；已在正式参数里的维持暂定、不撤回；攒满 1 年后复验 |

反号只是中等证据：前向窗误差约 2.7 点，真效应 +3.2 点时点估计反号的概率约 12%。

**幸存者偏差规则**：偏差 ≈ π × H，π 为窗内买点里属于日后退市股票的比例（猜测 15%~30%，预注册取 0.3），H 用训练窗里「日后困境」在池股与其余股票的配对差代理。π·H > 1 点时，往前窗确认降为暂定，以前向窗为准。这一步要读收盘价，放在开窗前做。

**自动开窗条件**：清单、决策映射与每项预期把握早于开窗写进账本，且预期把握已告诉用户。映射第一项的预期把握（按族内校正、扣掉选择偏差后）低于 50% 时不自动开，停下来问（§4.7）。

## 9. 对原结论的裁决与被否决方案

### 9.1 问题 F

- **原结论**：格数越多选择偏差越大，265 万格算得动也白算；联合分析必须放在减闸之后。
- **修正**：
  - 挑选噪声乘数和格数几乎无关；那一轮失败的主因是效应小于噪声，可操作的主杠杆是功效线口径（stats e3，executor e2）。
  - 「先减闸再联合」仍然成立，但理由换成：减掉的维度让每个比较分到更多有效样本，比较次数也少。
  - 更根本的约束是：两年样本只分辨得出 3.5~4.8 点以上的差别。

### 9.2 原七层方案逐层裁决

| 层 | 原提议 | 裁决 |
|---|---|---|
| 1 | 不花数据就砍维度 | 保留并机械化：尺子自动识别、逐档合法性、等价档与退化格数据驱动合并。「定义性参数不调」已推翻 |
| 2 | 先验有没有边际 | 采纳：`tune.edge`，同日 × ATR 层匹配，三分支 |
| 3 | 边际效应替代格子 | 修正：不用平均边际效应，在工作点（主）和宽进点单翻转；where 闸的存在性归学习端，本轮对闸只做「删了不亏」 |
| 4 | 按交互强度分组 | 否决：数据分辨不出同 node 交互更强，bb_v1 检测参数都在 bo→burst→tb 一条链上；幸存者被截断后全因子本来就负担得起 |
| 5 | 由粗到细、每层换一折 | 否决换折：只有两个年折，换折后年交互无法估计、样本减半。「粗 → 细」由「筛选 → 联合」承担，挑选代价用连筛选一起重做的 bootstrap 计价 |
| 6 | 拟合响应面 | 否决：实测形状有平台、断崖和 U 形，二次曲面会造出假内部最优；改用有效样本功效线后联合网格只剩几十格，已无需求 |
| 7 | 扫描前算噪声地板 | 采纳并修正公式：不是 √(2 ln K)，改为 stats 标定式；由 δ 反推功效线；开工前给分辨力 |
| 可选 | 股票池逐轮淘汰 | 否决：算力不是瓶颈；四分之一池误差翻倍会误杀；噪声主要成分是同期行情，换股分不开 |

### 9.3 其他被否决的设计

| 设计 | 否决理由 |
|---|---|
| 全部参数各两档、2^N 全因子或分数阶，按平均主效应筛选 | 交互与主效应同量级，估计量错；本轮唯一有效的改动会被筛掉 |
| 一次 4 档宽扫描同时做筛选与联合 | 检测组合多 50 倍以上；统计上不省，复用程度由挑选次数决定 |
| 股票对半拆（含「两半区 × 年份」棋盘） | 同期两半共享行情；每阶段误差 ×1.41；38 个挪档中 9 个有窗级异质性 |
| 学习端在调参前用往前窗判闸 | 烧掉唯一有功效的确认窗，而闸存在性在该窗上本来就判不了；调参结果的闸组成还会被这段 label 选出来 |
| 幸存判据「\|z\|≥1 且两年同号」、入围频率 ≥ π | 前者零假设下同号 50%、幸存集合只复现 3%；后者 π 无依据、无误选率保证 |
| 基线只按 ATR 层匹配（FC-004 做法）或按 40 日窗匹配 | 漏掉同期行情；40 日窗内仍有择时 |
| 以「闸全关」为参照格 | 离工作点太远，比较变成非配对，误差翻倍以上 |
| 保留子抽样去簇、只把标签换成首次穿越 | 功效 6~9%，丢四到五成样本，时间维永远不跑 |
| 删闸非劣效界取 δ/2 | 让删闸比判「无信号」还难，违背风险不对称方向；这份数据下几乎永远删不掉 |
| 另起候选信号契约快照文件、保留 exposure.jsonl | 三处同步必漂，快照丢样本来源与检验次数 |
| 学习端给执行端单点阈值 | 同一决定上叠两次挑选 |
| 跨批次用 online FDR | 批次少、复杂度高；预注册批量加登记计次数替代 |

## 11. 局限与未决风险

- **标定只做过一次**：只在 bb_v1 一个 pattern、一份旧底座长表上做过。设计效应、定向 bar 占比、挑选噪声乘数，换 pattern 必须重测。
- **挑选偏差是下界**：所有 optimism 都来自按股 bootstrap，只含个股噪声、不含同期行情噪声。
- **同日匹配无外部真值**：「同日匹配比 40 日窗更对」是推导（label 窗完全重合），没有外部真值可对照。
- **退市比例是猜测**：往前窗退市股比例 π（15%~30%）需要实施时量化；超出规则时往前窗只能给暂定结论。
- **推导数字**：耗时（优势检查 3~5 分钟、筛选扫描几分钟、往前窗扫描约 13 分钟）、max-T 的检出把握、前向窗反号概率都是推导。
- **刚过线**：突破幅度 z 3.13，只高出筛选门槛 0.14，换一批数据完全可能不过。
- **底子判不出「没有」**：两年数据下，优势检查几乎判不出「没有底子」，多数结局是「还不能确定」。
- **方案偏重（leader 判断）**：执行端新增 5 个函数、学习端新增 5 个函数、账本 8 类记录。每一项都对应 §2 的一条实测事实或一条红线，但对单用户、少数几个 pattern 仍偏重。建议 bb_v1 首轮走完后复盘：没被用到的环节（例如联合阶段在「只够一次改一个参数」时整段退化）是否可以删减或合并。
- **跨会话触发边界**：新会话里单说「继续」触发不了任何 skill，这是 description 触发机制本身的边界。
