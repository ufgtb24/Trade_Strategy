# v3 评分口径评审（objective 分工）

日期：2026-10-05。本文给 AI 读；项目内路径相对 repo root。分工：「什么叫更好」以及它量得准不准。评审对象 `.claude/skills/tune-gates-v3/`（下称 skill），原问题见 [原始问题.md](原始问题.md)。

证据档：**已验证** = 本轮代码或数据实测；**推理** = 由已验证事实与代数推出、未单独实测；**推测** = 尚无直接证据。用户已拍板的方向（方向优先 + 收盘判穿越、按股票日计机会且只设下限、近期优先、允许暂用后复核）一律不推翻，只在指出具体缺陷时写成「取舍 + 代价」。

## 数据与方法（所有数字的口径）

- 数据：`docs/research/2026-10-02_v3-bb-training-calibration/` 的 parquet。bottom_burst，256 只股票池，H=40、k=5，收盘首次穿越，21 日窗口、252 日半衰、近期 126 日，与该轮协议一致。两折：fold1 搜索 2024-07-01..12-31 / 后段 2025-03-04..06-30；fold2 搜索 2024-07-01..2025-04-30 / 后段 2025-07-01..10-31。33 组参数按买点集合去重后每段 19~28 个。
- 原参数实际出买点的股票只有 10（fold1 搜索，255 个买点日）、12（fold2 搜索，356 个）、3（fold1 后段，30 个）、9（fold2 后段，180 个）。所有噪声数字都是**这个规模**下的值。
- 重抽：按股票整只有放回重抽 256 只（2000 次），同一组重抽权重作用于全部候选（保留候选间配对）。每次重抽重算主分 Z（skill 公式）、合并买点平均 P、近期加权的逐买点平均 PR、同配比普通对照 B。原样本复算与 `WindowPlan` 一致（最大误差 1.7e−16）。**按股票重抽不含「同一天全市场一起动」的时间冲击，因此对 Z 是噪声下限**；对候选间配对差影响较小（共享日期）。
- 额外读行情：close 与盘中判法对照、期限 H 对未触线比例的影响，读 256 只股票 2024-01-01..2025-06-30（在任何计算前裁切），该范围已作为 bottom_burst v3 开发数据登记（`docs/sample_usage/bottom_burst.v3.jsonl`）。没有读 2022–2023 或 2026。
- 脚本与原始结果：`repro/objective_noise.py`、`repro/objective_extra.py`、`repro/constraint_variants.py`、`repro/close_vs_intraday.py`、`repro/horizon_none.py` 及同名 `*_results.json`。

## 一、按严重程度排序的结论

### 1.【严重｜已验证】在实测规模下，主分分不出参数好坏；问题在样本，不在公式，而 skill 没有任何一步把这件事告诉用户

| 量（fold1 / fold2 搜索段） | 数值 |
|---|---|
| 原参数 Z 的重抽标准差 | 0.24 / 0.17 |
| 28 个去重候选 Z 的重抽标准差（中位） | 0.24 / 0.18 |
| 候选减原参数的配对差标准差（中位；四分位） | 0.12（0.04~0.23） / 0.08（0.05~0.18） |
| 重抽中第一名与原样本第一名相同的比例 | 59% / 36%（出现过 20 / 21 个不同的第一名） |
| 重抽排名与原排名的 Spearman 均值 | 0.68 / 0.60 |
| 搜索段分数对后段分数的 Spearman（Z / P / Δ） | +0.13 / −0.25 / +0.34；−0.44 / +0.04 / −0.39 |

- 证据：`repro/objective_noise_results.json` 的 `bootstrap_sd`、`rank_Z`、`search_to_check`。
- 换算到合理效应：旧版实测 bb_v1 真实效应约 2~3 个百分点的先上率，换成方向分约 `r×2×Δq ≈ 0.6×2×0.025 ≈ 0.03`（**推理**，r 为触线比例）。256 只股票下配对噪声中位 0.08~0.12，是效应的 3~4 倍。噪声大致按 1/√(出买点股票数) 缩；5000 只池子若约 200 只出买点，配对噪声中位约 0.02~0.03，与效应同量级（**推理**，未实测 5000 只）。
- 时段间漂移比股票抽样更大：同配比普通对照 B 在四段里是 −0.009 / −0.131 / −0.168 / −0.003，原参数 Z 是 +0.007 / −0.402 / −0.203 / −0.003（`calibration.md` §3 与本轮复算一致）。后段预测失败更像「不同时段效果本来就会差多少」，股票数加到 5000 也消不掉这一部分（**推理**）。
- **对设计的含义**：skill 刻意不把买点数、股票数当证据（`references/method.md`「时段内与时段间」），这是对的；但它也没给任何替代刻度，于是用户和 agent 都无从知道「这批数据能分辨多大的差别」。结果是：80 次搜索照常跑完、挑出噪声赢家、在最后验证上「新分 > 旧分」即暂用（`governance.py:393`，对零效应候选约是掷硬币），再在复核时必然撤回（见第 2 条）。这正是旧版「效应小于噪声」的同一个失败，只是换了一层皮、不再报出来。→ 新增建议 **N1**。

### 2.【严重｜已验证｜裁决链路属 selection 分工，此处只记评分侧事实】复核阶段的结论与复核数据无关：只要进入复核就必然撤回

- `scoring.comparison` 恒返回 `evidence_sufficient=False`、`improvement_lower=None`（`scoring.py:434-436`）；`governance.adoption` 在 `stage="review"` 时，确认分支要求二者成立，暂用分支要求 `stage=="final"`，于是只剩最后的撤回分支（`governance.py:384-397`）。
- 实测：`adoption({hard_constraints_passed: True, evidence_sufficient: False, score_difference: 0.3}, {}, "review", "provisional")` 返回 `rollback`；测试文件也把这当成期望（`tests/test_governance.py:215,229`）。
- 含义：ADR 0004「暂用之后复核」在当前实现里退化成「暂用一段时间后一律恢复原参数」，复核数据被消耗却不影响结论。评分侧的根因是第 1 条：没有任何已校准的证据刻度能让 `evidence_sufficient` 变真。已把事实发给 selection，由其提裁决规则。

### 3.【中高｜已验证】「方向主分严格 > 0」是行情闸，不是质量闸：下跌段里任何参数都调不动，最后验证落在下跌季度也一律拒绝

- fold2 搜索段（2024-07..2025-04，含 2025 年初下跌），28 个候选里 **27 个被 Z>0 卡掉**；原参数自己 Z=−0.203、B=−0.168，也不达标（`objective_noise_results.json` 的 `table`）。
- 反事实（`constraint_variants_results.json`）：只去掉 Z>0、保留其余要求，fold2 有 8 个候选可行且优于原参数，选中 `bo.exceed_threshold 0.003→0.006`：搜索段 Z −0.203→−0.026，对同配比普通买入的差 Δ=+0.151；它在后段的买点集合与原参数完全相同，故后段无差别（两折都是这个候选、都是这个结局，**对去不去这道闸没有给出好坏证据**）。去掉「Δ≥0」而保留 Z>0，fold2 仍是 0 个可行——绑定的就是 Z>0。
- 逻辑缺陷：选择本来就要求新分高于原参数（`run.py:286-289`、`governance.py:388`）。Z>0 额外要求的是「这套参数绝对方向为正」，回答的是「这个 pattern 值不值得做」，不是「哪套参数更好」。下跌段里它拒绝 −0.026、保留 −0.203，与「每次买入后方向更好」相反。最后验证通常只有几个月（`references/configuration.md` 示例为 3 个月），这道闸让采用与否取决于那几个月的大盘方向。
- 该闸原本的理由是「全未触线 z=0 不算有效向上」（`references/method.md` 搜索约束表）。去掉后的真实代价：原参数为负时，一个让买点大多不动（未触线）的候选会以 Z≈0 胜出；但它仍须过普通对照那道要求，而「不动」相对「先下」在方向分的定义里本来就算改善（三态取值 +1/0/−1 是 10-02 研究定下的）。
- **同一逻辑也适用于「Δ≥0」（与 selection 对齐后修订）**：它同样是绝对下限，回答「这个 pattern 是否胜过同日普通买入」，在原参数自己 Δ<0 时（fold2 原参数 Δ=−0.035）会拒绝比现役更好的候选、保留更差的现役。它防「改善全靠买在好日子」的作用是真的，但用「Δ 不低于原参数的 Δ」就能保住这个作用，且对称：原参数 Δ>0 时反而更严（fold1 原参数 Δ=+0.0165，可行数 6→5）。反事实（`constraint_variants2_results.json`）：删 Z>0、Δ≥0 改为 Δ≥原参数 Δ，fold1 可行且优于原参数 5 个、fold2 10 个，两折选中都仍是 `bo.exceed_threshold 0.003→0.006`。
- → 建议 **D2**：两道绝对下限都改成「不比现役差」；方向那道因与「新分须高于原参数」重复，直接删。需要用户一次方向确认（「下跌行情里，或现役本身不如普通买入时，比现在好但仍不够好的参数算不算改善」）。此条与 selection 的同名建议是同一条，文字以本文为准、selection 引用。
- **D2 在裁决链路上的代价（selection 实测，`repro/harm_sim_relfloor.py`，第二折后段规模、按股重抽、噪声为下限）**：最后验证的暂用率，零效应候选由约 18% 升到 35%，真改善 0.03 时由约 30% 升到 52%，变差 0.10 时 6.5%；复核沿用同一规则后两关都过的比例为 16% / 35% / 0.7%。误暂用翻倍，是因为原来那 18% 有一部分靠「那段时间大盘整体弱」把人拦下——好候选和零效应候选一起拦。好坏区分只略降（真改善 0.03 与零效应的暂用率之比：现行约 1.7 倍，D2 后约 1.5 倍），主要变化是暂用整体变多；要压误暂用，正路是第 1 条的样本规模问题，而不是保留一道按大盘涨跌拦人的线。该代价须随 D2 一起呈给用户。

### 4.【中｜已验证】绝对机会下限 30 既不是供给保障，也不是样本保障，还会在短的最后验证段里系统性卡掉稀疏 pattern

- 同一个 30 用在 1.5 年训练段和 3 个月最后验证段（`scoring.py:375`，`run.py:411` 的 `comparison` 共用同一 policy）。fold1 后段（4 个月）19 个候选里 12 个因不足 30 被卡，原参数恰好 30 个。
- 30 个买点日不代表 30 份证据：fold1 后段那 30 个来自 3 只股票；joint_11 的 42 个来自 3 只。同股票连续买点日高度相关（设计效应 7~10）。
- 「近期 126 日 ≥1」在任何非空候选上几乎恒满足；最后验证与复核段通常短于 126 日，近期两条就退化为总数两条的重复（`scoring.py:317`）。
- 真正起「保留基本供给」作用的是两条相对下限（总数、近期都 ≥ 原参数一半）。→ 简化建议 **D3**：删绝对 30 和近期 ≥1，留两条相对下限；样本够不够由 N1 回答，不再让一个计数假装回答。

### 5.【中｜已验证 + 推理】主分（窗口两层平均）与按买点直接合并的均值：噪声相当，差在业务含义和最近一月的权重

问题 1、2 的直接回答：

- **噪声没有被放大（已验证）**。担心的是「只有 1~2 个买点的窗口与几十个的同权」。实测单个买点日在 Z 里的权重最高可达平均的 4.5 倍（fold1）/ 12.5 倍（fold2），行级有效样本量只有买点数的 60%/54%；但按股票重抽的总波动 Z 反而略小于 P（28 个候选中位 0.24 vs 0.26、0.18 vs 0.20），配对差也相当（均值 0.152 vs 0.137、0.109 vs 0.107）。原因（**推理**）：bb 的买点日是同一股票的长串连续日，窗口内比例对「同一只股票重复出现」不敏感，抵消了稀疏窗口的高权重。时间块重抽未做。
- **排序大体一致，但单个候选可差很多（已验证）**。候选间 Z 与 P 的 Spearman 0.94 / 0.87，两折未加约束的第一名相同；但同一买点集合的 Z 与 P 可以差 0.12（fold1 原参数 Z=+0.007、P=−0.114；fold2 `burst.gap_max_0` Z=+0.002、P=+0.127），这个差距比合理效应（约 0.03）大，所以选哪个汇总方式会改变近邻候选的先后。统计上分不出谁对，是业务口径问题。
- **业务含义（推理）**。窗口均值等价于「每个有买点的月份分到同一份钱，当月几个买点均分」；当月只有一个买点时整份钱押在它身上。按买点合并等价于「每个买点等额」——这正是 ADR 0003 正文的字面假设（「资金不限制这项评价」），而 skill 第一段与 10-02 白话说明写的是「资金有限」。两份文档互相矛盾。真实的「资金有限」是每月最多 C 笔：信号多时窗口均值更贴近，信号稀时它高估了稀疏月份。5000 只池子下稀疏月份少，窗口均值近似合理。
- **最近一月欠权（已验证）**。全部起点等权枚举使首尾日期进入的窗口更少。在买点均匀分布时，最近 21 个交易日在 Z 中的总权重占比 7.3%~11.5%，而按日直接近期加权应为 12.8%~18.9%；最近 5 日只有应得的 15%~18%，最后一日约 5%（`objective_extra_results.json` 的 `*_weight_profile`）。252 日半衰在一个月内只差 6%，所以在最近一个月里，这个边缘欠权比近期加权本身的作用大得多，方向与「近期优先」相反。method.md 已写明首尾少覆盖，属已披露的代价。
- **结论**：不建议改公式（排序差异在 bb 上有限，换口径要花用户一次注意力）；建议只修文档（**D4**），把资金含义和边缘欠权写清楚。若团队整体走删减路线，替代方案是「逐买点按日近期加权的平均」，能删掉窗口机制与边缘欠权，代价是改变资金含义，需用户确认一次。

### 6.【中｜已验证】未触线的稀释：期限是主要旋钮，默认 H=20 让约七成买点未触线；收盘判法的副作用小

- 未触线比例（普通池，收盘口径，k=5，fold2 搜索段股票）：H=10 → 86%；**H=20 → 67%**（原参数买点 70%）；H=40 → 40%（原参数 42%）（`horizon_none_results.json`）。skill 默认 H=20（`run.py:149`、`references/configuration.md`「评价默认H20」），而 bb 真实对照用的是 H=40。
- 稀释的统计代价（**推理**）：三态值的均值是 `r(2q−1)`，单笔的方向信息量约与触线比例 r 成正比，H=20 时单个买点的方向信息约为 H=40 的一半，同等样本下噪声相对信号放大约 1.4 倍——在第 1 条已经噪声主导的情况下雪上加霜。代价是更长的期限要求各阶段之间多留约 20 个交易日的未来尾部。
- 随波动档变化：H=40 时未触线从最低波动五分位的 37% 升到最高五分位的 47%；按月在 25%~58% 之间摆动（单边下跌月份触线多）。bb 买点的当日波动分位中位数 0.91，多落在最高档，未触线偏多。同日同波动配比已把这部分对齐，不构成偏差，只是把差异压缩。
- 定义上的副作用（属已拍板口径的性质，不是缺陷）：普通池先上占比 q<0.5 的下跌段里，买点越多变成未触线，Z 越高（「不动」比「先下」好）。
- 收盘 vs 盘中（`close_vs_intraday_results.json`，53,380 个普通池股票日）：触线比例 59% vs 69%；方向反号只有 1.3%；盘中同日双触 0.03%；普通池方向均值 −0.056 vs −0.072，原参数买点合并均值 −0.160 vs −0.185。两种判法的波动尺度 M 完全一致（最大差 0）。收盘判法的主要副作用就是多了约 10 个百分点未触线，方向结论基本不变。另一个副作用是口径分叉：`path2/CONTEXT.md:148` 的「首次穿越」是盘中判法，v3 的同名量不是同一个数，与 feature-study 等既有研究结果不能直接比较（skill 已要求在用语上区分）。
- → 建议 **D5**（默认期限改 40，零代码）。

### 7.【低中｜已验证】统计折扣：建议从 skill 删除

- 默认关闭；10-02 真实对照中所有 6 组预定设置都没有改变选择（`calibration.md` §3）；它依赖的误差刻度 V 在作者自己的模拟里只有真实方差的 46%~72%（`2026-10-02_v3-direction-score-formula/final_report.md` §6）；本轮实测的噪声主体（股票抽样 + 时段漂移）它也没有建模（V 只用窗口序列）。
- 它占用：description 的触发词「启用统计折扣」、SKILL.md 一整段、method.md 一节、configuration.md 一节、报告里四五个字段、`scoring.py` 约 70 行（`normalize_shrinkage`、`_adjust_score` 与分支）、`tests/test_shrinkage.py`。删除不影响默认行为。→ **D1**。

### 8.【低｜已验证 + 推理】普通买入对照与固定 bo：设计基本合理，两处要说清

- 同日同波动五档配比、池中含候选自身（`scoring.py:228-240`）：256 只池子每格约 51 只，候选自身占比约 2%，对 Δ 的回拉可忽略；5000 只时更小。普通池方向随当日波动分位单调变差（fold2 最低十分位 +0.03 → 最高 −0.12~−0.14），所以按波动配比是必要的；最高五分位内部（0.8~0.9 / 0.9~0.95 / 0.95~1）为 −0.12 / −0.07 / −0.16，未见单调残余，五档配比够用（`objective_extra_results.json`）。
- 「Δ≥0」是观察门槛，不是证据：fold1/fold2 各卡掉 13/18 个候选，256 只下 Δ 的重抽标准差 0.17~0.25，对真实差接近 0 的候选是随机通过。它防的是「只靠买在好行情的日子拿高分」，这个作用是真的，与大盘方向无关；但写成绝对下限时与 Z>0 有同一个毛病（现役本身 Δ<0 时拒绝更好的候选），改成「不低于原参数的 Δ」见第 3 条 D2（初稿写「原样保留」，与 selection 讨论后修订）。无论哪种写法，文档里都不要暗示它提供了任何把握。
- 固定 bo 与 pattern 买入日期不同，两者的 Z 含择时，**能比的是各自对同配比普通买入的差 Δ**，不是 Z。bo 的评价调用 `assess(bo, bo, …)`（`run.py:316-317`），以自己为原参数，其中「可行」字段没有意义，报告里应只呈现 Z、B、Δ 与买点数。这是报告措辞层面的小修，不另立条目。

### 9.【低｜已验证】ADR 与实现多处不一致

- ADR 0002 标题与正文仍是「上涨空间优先」（已知）；ADR 0005 正文「主要成绩仍衡量逐买点日的上涨空间中位数」；ADR 0001 正文「当前实现用固定重抽空间中位数的较低分位参与排名」——实现已无重抽（`run.py:201` 拒收重抽配置）；ADR 0003 「资金不限制这项评价」与 skill「资金有限」冲突（第 5 条）。决策记录是后续 agent 理解「什么叫更好」的入口，四处都指向已被替换的口径。并入 **D4**。

## 三、建议新增

### N1｜分辨力刻度：每轮告诉用户「这批数据要差多少才分得出来」

做法：用已算好的逐日标签，对原参数的买点按股票整只重抽（几百次，向量化，秒级；`repro/objective_noise.py` 的 `StockMatrix` 约 40 行即是原型），得到主分的偶然波动；训练选出候选后，再对「候选 − 原参数」同样重抽得到配对差的波动。两处各在报告里给一句人话（「这批数据上，两套参数的方向成绩要差到约 X 以上才分得出来；过去实测参数改动的效果约 0.03」）。搜索前若原参数自己的波动已远大于合理效应，由 agent 先告诉用户「建议先扩大股票池再调」，而不是照常跑完。

- **(a) 修的失败**：bb 256 只这一真实情形——原参数 255 个买点日看起来不少，实际只来自 10 只股票，主分的偶然波动 0.24、配对差 0.08~0.12，是合理效应的 3~4 倍；skill 照常搜索 80 次、挑出噪声赢家（fold1 搜索段 +0.32 → 后段与原参数相同），最后验证对零效应候选按掷硬币暂用、复核必撤回。用户全程看不到「这次本来就分不出来」。
- **(b) 复杂度**：评分模块约 40 行（复用已有逐日标签，不重跑检测）；报告多 1~2 行；正常情况下用户不多看任何东西，只有数据明显不够时 agent 多发一句提醒（一次注意力）。不加新的配置键（重抽次数取固定值），不加阶段，不让用户定阈值。
- **(c) 为什么更简单的做法不够**：报告买点数、股票数（现状已有）——method.md 明确禁止把它们当证据，用户也无法把「255 个买点、10 只股票」换算成能分辨的差；「什么都不报、只说证据未校准」——等于把旧版「效应小于噪声」的失败原样保留但不再可见。按股票重抽漏掉时间冲击，只是下限；但「连下限都太大就别调」这个用途只需要下限，所以不必上更复杂的时间相关估计。
- **与旧版的区别**：只是一个数字和一句话，不是旧版的「最小桶数功效闸 + 多阶段」；它不自动阻断，也不进入排名。是否把它接进最后验证的裁决（例如改善需超过配对波动的某个倍数才暂用），属 selection 分工，本文不提。
- **实现边界（经 simplicity 裁决后定稿，超出即退回「只在报告里给这个数」）**：
  1. 只用训练段**原参数**的逐日标签，搜索前算一次；不按候选逐个算。（初稿还提了对选中候选算配对差，删去。代价：原参数自身的波动比近邻候选的配对差大约一倍——实测 0.17~0.24 对 0.08~0.12——报告措辞写成「方向成绩的偶然波动约 ±X，近邻参数之间的差别通常是它的一半左右」，不把 X 直接说成两套参数的可分辨差。）
  2. 不新增配置键；重抽次数取固定值；「合理效应约 0.03」写成标注「待验证」的默认参照，不让用户定。
  3. 不阻断流程，不进入排名，不进入采用规则；至多一次提醒（「建议先扩大股票池」）。
  4. 实现细节：`WindowPlan` 拒收同股同日重复行（`scoring.py:152`），有放回重抽必然产生重复，所以按「每只股票被抽中次数」做权重，直接从「股票×日期」的计数与方向和算窗口，不把重抽后的行塞回 `summarize`（`repro/objective_noise.py` 的 `StockMatrix` 即此写法，与正式实现逐值一致，误差 1.7e−16）。
  5. 规模目标约 40 行；超出就只报告这个数、不发提醒。

（只此一条新增。其余可想到的新增——时间块重抽、封顶资金模型 min(n, C)、逐时段胜率——都要么需要用户给参数，要么在 bb 实测里改变不了结论，按剃刀不提。）
