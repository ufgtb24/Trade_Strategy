# tune-gates 第一性原理重构草案：一个估计器代替一串阶段

> 状态：设计草案，未拍板、未实施。本文所有项目内路径均相对 repo root。
> 现状代码在 `.claude/skills/tune-gates/`（方法说明 `SKILL.md`、`reference.md`；决策层 `screen.py`、`region_find.py`、`region_core.py`、`validate.py`；过程参数 `tune.py` 的 `Settings`）。

## 0. 问题陈述

现在的调参流程由八个阶段、三个停点加一个条件停点组成，过程参数二十来个（`reference.md` §7 自己列了一打「尚无跨 app 实战校准的阈值」）。它是按「发现一个失效方式、补一个机制」的方式长出来的，每个机制局部都有道理，但彼此不知道对方存在，于是同一件事被做了好几遍、每遍各要一个门槛。症状：挑选偏差有六套局部答案（「三个分数并列呈报、不折中」就是承认合不起来），时段稳定有四套，质量与数量的权衡没有归宿、只能靠「买点少三成就问你」临场拍板。

本草案从目标出发重推一遍，把机制归到少数几个原语上，给出一个更整体的流程，并列出砍掉什么、留下什么、代价是什么。

## 1. 目标与四个原语

调参的目标只有一句：**在一个参数空间里选出未来表现最好的那一点，并诚实地说出它到底有多好。**

从这句话往下推，只需要四样东西，别的都是它们的实现细节：

| 原语 | 回答什么 |
|---|---|
| ① 效用 U(θ) | 什么叫「好」：质量（首次穿越率超出同日同波动层随机日基线多少）与数量（买点数）怎么合成一个数 |
| ② 噪声模型 | 一份数据算出的 U 有多大误差：按股牵连、按时段牵连 |
| ③ 挑选校正 | 在很多候选里挑最大值，挑中的数虚高多少 |
| ④ 独立验证 | 挑完之后，用没参与挑选的数据核一次 |

另有一层**治理**（账本、冻结、停点），它不估计任何东西，只保证 ①～④ 在有人参与的情况下仍然诚实。

## 2. 现有机制归位表

| 原语 | 现有实现 | 判断 |
|---|---|---|
| ① 效用 | δ（最小关心改进）；联合排序用「相对工作点的增量」；「买点少三成就问你」；层匹配随机日基线只在优势检查里用、联合排序不用 | 四块拼的，没有一个函数；数量没有归宿 |
| ② 噪声 | 按股去簇误差、设计效应实测、功效线、30 段买点下限、松紧档「保留 30%～70% 买点」带 | 核心是一体的；后两条是变相的功效门槛（保留带实际上在保证「翻转改变的样本够多到能测出来」，可由 SE_flip 公式推出，不必单独拍数） |
| ③ 挑选校正 | 筛选 FDR（q=0.10）、年份取最差、邻域取最差、按股重抽连挑选重做、对半分验证、账本「比较过几次」（只报不用） | **六套**，互为近似，互不合成 |
| 时段稳定（②的时间维） | 年交互 z、时间窗异质性 p<0.05、年份取最差、往后那段「方向一致」 | **四套** |
| ④ 验证 | 往前一段（族内 max-T）、往后一段（非劣效 + 同号）、四格判读表、幸存者偏差预检 | 两段各一套规则 |
| 治理 | 账本、冻结清单、停 1/2/3 + 条件停点、反向登记、`depends_on`、一致性验证 | 一致性验证是长表工程 QA，不属于方法 |

结论：过程参数多不是因为问题难，是因为 ③ 和时段稳定被重复实现，每个接缝各要一个门槛。

## 3. 方案：交叉拟合的挑选

**核心替换**：把 ③ 与时段稳定的十套机制换成一个——**交叉拟合（cross-fitted）的挑选流程评估**。

做法：把训练期数据按「股票折 × 时段块」切成块。每次留出一块，在其余块上按**固定的挑选规则**选出一个 θ，再到留出块上算 U；轮一圈，留出块上 U 的平均就是「这套挑选流程在样本外能拿到多少」的不偏估计，各时段块之间的分散度就是时段稳定性。全数据上按同一规则选出的 θ 是最终候选，它的样本外效用就用这个交叉拟合估计报。

它为什么能吸收现有机制：

- 对半分验证 = 它的两折版本；按股重抽连挑选重做 = 它的另一种近似。两者退役。
- 年份取最差、邻域取最差 → 从「红线」降级为「挑选规则的一种选项」（平台规则 vs 峰值规则）。哪种规则交叉拟合得更好，用数据比，不写进纪律。
- 年交互 z、时间窗异质性 p → 时段块的分散度直接呈现，不需要单独检验和阈值。
- 筛选 FDR → 单翻转筛选保留，但**只做剪枝**（效应在噪声内的维度不进联合网格）。剪枝不是「发现」，不对外报显著性，就不需要多重比较校正、不需要 q、不需要「刚过线」。
- 「比较过几次」→ 挑选规则机械化后，比较次数已在交叉拟合内部被计入；账本仍记，用于跨轮次的数据复用判断。

**效用函数 U** 显式化：

```
U(θ) = (首次穿越率(θ) − 层匹配随机日基线) × n(θ) / (n(θ) + n0)
```

- n(θ) = 该配置每年买点事件数（业务口径，不是去簇后的独立样本数——后者属于噪声模型②，两者分开）。
- n0 由用户按业务定（「一年大约能消化多少个买点」），在停 1 定下、记账本、开跑后不改，地位与 δ 相同。n0 → ∞ 退化为只看质量。
- δ 改为「U 的最小关心改进」，一个数同时管优势检查、剪枝、删闸非劣效。
- 饱和形状的来源：`BreakoutStrategy/mining/threshold_optimizer.py` 的 shrinkage 权重 w = n/(n+n0)。那里它一身兼两职（统计收缩 + 数量换算）且 n 按行数不去簇；本方案只借它的数量换算一职，统计收缩由 ② 单独负责，不重复惩罚。
- 联合排序的对象改为 U 相对工作点的差，而不是「首次穿越率相对工作点高几个点」；后者乘数量系数没有意义。

## 4. 收敛后的流程（五步）

| # | 步 | 做什么 | 停不停 |
|---|---|---|---|
| 1 | 定义 | 在读任何涨跌结果之前：划训练期与往后那段确认窗；定 U（n0）、δ；定参数空间（每维档位由噪声模型推保留带，不再拍 30%～70%）；定分块结构（时段块 × 股票折）；定挑选规则（平台 / 峰值，或两者都跑并比）。全部冻结进账本 | **停 1** |
| 2 | 扫描 | 全网格长表一次。单翻转剪枝：效应在噪声内的维度单档取正式值 | 不停 |
| 3 | 交叉拟合挑选 | 产出：全数据上选中的 θ；它的样本外 U 估计与误差；各时段块的分散；质量-数量前沿曲线（U 沿 n 的轨迹，供人看权衡是否合理）。误差太宽的格标「评估不了」，只留一条计算性的硬下限 | 不停 |
| 4 | 机制否决 | 用户只能**剔除**候选（机制上讲不通的），不能换候选；每次剔除记一次 `select` | **停 2**（可选） |
| 5 | 验证 + 定案 | 往后那段只开一次，检验冻结的 θ 相对改前不差出 δ 且方向一致；按事先写好的映射给结论；用户只能整体写入或整体不写 | **停 3** |

顺序的理由与现状相同：定义在看结果之前；否决在验证之前；验证在定案之前。

## 5. 砍掉 / 留下 / 改身份 / 分离

**砍掉**（及其阈值）：筛选 FDR（q）、交互兜底探针（|z|≥2）、年交互旗标、时间窗异质性检验（p）、换池旗标（δ/2）、刚过线、保留带（30%～70%）、对半分种子数、重抽 B、三个分数并列呈报、往前那段的 max-T 族、四格判读表、「买点少三成就问你」。

过程参数从二十来个降到约六个：δ、n0、每维档数、分块结构、验证 α、计算性样本下限。

**留下且身份不变**：按股去簇噪声模型（设计效应实测、功效线由 δ 反推）；账本；冻结清单；往后那段只开一次；停 1、停 3；`depends_on`；长表扫描与续扫口径守卫。它们对付的是人这一环的泄漏和工程正确性，估计器管不了。

**改身份**：
- 年份取最差、邻域取最差：红线 → 可比较的挑选规则选项。
- 「不引入 optuna / LHS / GP / racing」红线：原理上不再需要——搜索算法在被评估的流程内部，怎么搜都被诚实计分。实际上因为长表的前缀结构，网格照旧；这条改为「工程约束」而非「方法红线」。
- 往前那段确认窗：可并入交叉拟合当一个带幸存者标记的时段块，不再单独一套规则。它原来「只开一次」是防人反复看；挑选规则机械化并预注册后这层保护必要性下降。跨轮次数据复用的记账仍留。

**分离出去**：
- 一致性验证（长表 vs 引擎）：长表工程的 QA，不属于方法，文档归到工程节。
- 闸的存在性由 feature-study 定这条耦合：在统一 U 下「关闸」就是最松档，不需要「在役未审定只许开/关两档」的准入类别；「哪道闸有信号」这类研究性结论从调参里退出，归 feature-study。反向登记到 `docs/feature_candidates.md` 留作研究卫生。

## 6. 代价，老实说

- 训练期只有两年，时段块最多两个，时段分散度估得粗。数据限制，现状两折一样。
- 研究性结论（哪道闸显著）从调参里消失。这是应该的：调参只管选点，发现归 feature-study；两者纠缠正是补丁感来源之一。
- 停 2 之后的人为剔除仍是估计器外的挑选，只能靠账本记、靠往后那段兜底，与现状相同。
- 交叉拟合要跑 K 次挑选；`find` 是分钟级，现状按股重抽已跑 B=300 次重挑，算力不增反减。扫描仍是瓶颈，不变。
- 这是重写 `screen.py` / `region_find.py` / `validate.py` 的决策层，不是改几个阈值。可复用：长表扫描、`region_core` 的格张量、账本、验证守卫、`budget.py` 的功效线。

## 7. 已排除的替代方案

- **只加数量项、其余不动**：数量有了归宿，但 ③ 的六套重复实现和四套时段检验仍在，参数数量不减，补丁感不消。
- **回到 mining 的单目标 + 黑盒搜索**：简约感一半是靠不面对问题换来的——样本按行不去簇、五万次尝试没有「试了多少次」这一项、基线不按波动层匹配、没有留出与账本。老框架「score 是波动率读数」正是这三条的结果。
- **交叉拟合替代全部验证、取消往后那段**：交叉拟合估计的是训练期内的样本外表现，训练期之后的行情切换它看不到；且停 1 的人为定义（δ、n0、范围）在估计器之外。往后那段仍需一次。

## 8. 待拍板

1. U 的形状：饱和式 n/(n+n0) 还是别的（如仓位有限时的「前 k 个买点质量」）。取决于买点实际怎么用。
2. n0 取值口径：按年买点数还是按月。
3. 挑选规则：平台规则、峰值规则，还是两者都交叉拟合后取更好的。
4. 往前那段是否并入时段块（幸存者偏差 π=0.3 的处理随之改为块级标记）。
5. 是否先在 bb_v1 上用现有长表做一次离线对照：同一份数据，新估计器选出的 θ 与现状 `find` 的推荐差多少、样本外估计差多少。这是最便宜的验证方式，先于任何重写。

## 9. 实施顺序建议（若拍板）

1. 离线对照（第 8 条第 5 项）：只读现有长表，不改现有代码，脚本放 scratchpad。
2. 定 U 与 δ 口径，改 `budget.py` 的功效线输入。
3. 新写交叉拟合挑选模块，替换 `region_find.identify` / `joint_bootstrap` / split-half。
4. `screen.py` 降级为剪枝：去 FDR、去旗标，保留单翻转对比与噪声内判定。
5. `validate.py` 收成一段窗 + 一条映射。
6. `SKILL.md` / `reference.md` 按五步流程重写；`docs/explain/` 下四份说明文档同步。
