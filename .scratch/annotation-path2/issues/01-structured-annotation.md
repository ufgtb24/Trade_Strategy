# 结构化标注：存什么、界面和主视图怎么合

Type: prototype (HITL)
Status: resolved
Claimed: 2026-10-25 主目录 annotation-path2 分支会话

## Question

### Purpose

用户在图上留下的标注，是让代码学会用户所见、再拿代码对回用户所见的唯一原料，这张票定这份原料的样子。

做一个粗糙的原型给用户看，定下：

- 标注里存什么：事件（点选系统已有的，或自己框的）、事件的名字和可选的一句话、事件的角色（在 pattern 里扮演哪个 node，可空）、事件具备哪几条特征（打勾，不填数）、买点、正例 / 像但不买、所属 pattern（可「未归类」）、当时用的数据指纹。存成能和 app 输出叠在同一张图上比的格式。
- 界面：标注做成主视图的一个可编辑模式，还是保留独立页面再加事件图层；系统事件一键关掉只看干净 K 线；「当前 pattern」怎么切；新名字怎么起。
- 「拿 app 对标注」时两层怎么叠着显示：用户的框和 app 产出的事件差在哪、怎么一眼看出来。

方向文档第 8 节是这张票的方向，不重新论证：标注就是「用户期望的显示」，web_ui 的显示就是「app 实际的输出」，按意思对应，三处不对称（阈值只标有无、标注侧多出新种类和正例判断、显示侧多出 detected 档与尝试痕迹）；事件层不属于任何 pattern，买点和角色属于某个 pattern；先看特征和先定目标分阶段配合。存储要守方向文档第 10 节第 3、4 条：每批一个新文件、文件名带机器名、只新增不改旧文件；记数据指纹。

来自「训练段用多长：样本多，还是和现在的市场像」（已批准）：找图、大涨段清单读同一个训练段设置（默认 2021-10-08～2025-12-31），不各自写死年份。防的是：看图、盲看和调参说的不是同一批样本，结果互相对不上。

来自「在要用的地方量一条特征：现有工具能不能直接做」（已批准）：标注里的特征勾选要和 app 里 where 分支同名；界面要能按特征显示量特征的结果（四选一结论、多出来几个买点日 / 几只股票、能分辨的最小差别、实测值），并能把「多出来的那些买点」调出来逐张看；结果记录里带 app 版本，app 改过后旧结果要显示为过期。

现状：标注页 `path2_web_ui/src/components/AnnotChart.vue` 完全不画 path2 事件，`App.vue` 带 `?wf=` 时整页换成标注页；主视图的事件画法见 `path2_web/GLOSSARY.md` 的副图、band、bracket、诊断侧栏。

## Answer

**确认的倾向**（2026-10-25 与用户对定，2026-10-30 补充）：「标得顺手」和「标完能直接拿 app 对回来」冲突时选后者；「对得回」不靠让用户标注时就用 app 的事件和词，而靠会话标完后写的 mapping，加上对照时和主视图同一套画法。用户说明书 `.scratch/annotation-path2/manual.md` 是今后取舍的依据，优先于原型代码（用户 2026-10-30 定）；本答案把说明书 ①～⑤ 落成「界面、存什么、对照」三组规则，每条的完整理由见说明书对应节和第七节「所以然」。用词照 [标注、mapping、app 产出与对照：各环节东西的命名](14-naming.md)：级与 tag 种类一律写英文（用户 2026-11-01 定）。

**一句话**：标注是主视图的一个模式，标的时候只有 K 线、成交量和自己的框；框用用户自己的词，词表跨图共用；样本标「这天会不会买」，判断的依据是它收进的成员框；把词翻成 node、where 还是边、写 app，是会话的事，写进 mapping；对照只给状态，不比起止、不给数字。

### 1. 界面

- **主视图的一个模式**，不另开页面；`mode` 三档：`annotate` 只画 K 线、成交量、用户的框和样本，`compare` 叠上 app 的输出，`app` 只看 app 输出、和主视图一样。正式版建在现有 web_ui 主视图上，原型代码不沿用、只沿用决定。防的是：标注和显示两套画法，标完对不回来。
- **`annotate` 不画任何系统事件**，不提供「点系统事件来标」。防的是：描述被现成事件带偏；点选收下的框拿去对照，等于 app 自己考自己。
- **唯一例外是参照层**：用户的概念相对某个算出来的东西定义时（如「突破了前面好几个峰」），可按种类单开那一种（先只有峰），默认关、换股票自动关。防的是：这类概念离开参照标不出来；常开又把眼睛往算出来的东西上带。
- **对照时只给状态**：`compare` 档的悬停只出状态，不出诊断树里的实测值和门槛；要看数字回主视图的诊断侧栏。防的是：数字从悬停这个侧门回到对照里，把用户拉去一张张调门槛。
- **界面文字两类**，按 `~/.claude/rules/ui-text-style.md`：用户输入与会话输出用自然语言，程序固定文字用英文标识符风格；文字一律黑色，不靠色相区分。防的是：业务内容淹没在程序文字里。
- **顶栏**：`symbol`、`mode`、`pattern`（含 `unsorted · n` 和 `+ new`）、`tool`（`box` / `point`）、`tiers`（app 灰条右端 `tier tag` 的开关，默认开；框旁的 `missing` 不受它管，防的是关掉开关时「app 没认出你的框」悄悄消失）。
- **侧栏三页**：`selection`（选中的框或样本）、`features`（词表）、`pattern`（当前 pattern 总览，每轮最先看的地方）。不要 `json` 页（用户 2026-10-31 删）。
- **找图三个入口**：大涨段清单、`random`（股票池 × 训练段随机一段）、按代码打开；进来落在 `annotate`。训练段读同一个训练段设置（默认 2021-10-08～2025-12-31）。看过什么一律不记。防的是：只有大涨段清单时看不到「长得像却没涨」的图；记「看过」违背训练段随便看。
- **链接**：会话出题用的题目链接；另有按「股票 + 日期」、按样本编号打开的链接，会话认出用户贴的截图、报「翻了哪几张」时用。防的是：「你说的话要指到图上」的最后一步，用户要自己去找那张图。
- **显示的统一规则**以 [界面显示的对称与统一](15-display-consistency.md) 的 Answer 为准（计数一律数样本、正负对偶、凡数样本的数都能点开、样本卡在哪都挂同一组 tag）；其中 optional 块 `qualified` 写 `—` 一句已由用户 2026-10-31 更正为照常显示（见第 3 节 `tracked`）。

### 2. 存什么

- **词表**：用户自己的词，跨图、跨 pattern 共用；每个特征有编号、名字、定义（可先空着）。不分「名字类」「属性类」，任何词都能当框名也能当属性；不提供 app 的 where 名单和现成事件种类名作选项。改名一处生效；意思变了另起一个；`merge` 先预览波及多少框、可拆回；每个词旁显示用量。防的是：现成选项框住视线；每张图重写同一个特征，逼会话去猜两个说法是不是一回事。
- **定义只说「它是什么」**；它在某个 pattern 里是哪一级写在那个 pattern 的定义里。防的是：同一个特征在两个 pattern 里分量不同，写在特征定义里就互相打架。
- **框**：起止日期、名字（特征编号）、属性（特征编号 → `true` / `false` / `null`，未列即 `null`，`null` = 没看过、不当「没有」）、可选 `note`。框只记编号，改名只改词表一处。框不属于任何 pattern。属性的 `true` / `false` 只按样本日及以前看得到的判。防的是：后想到的特征被算成「少数图才有」；依据里混进后见之明。
- **框套框 = 属于**：时间上被包住的框默认属于外框，推断错了可摘、交叠的可手动挂；也可以不画小框，只在大框上挂属性。防的是：子事件（W 形底的两个低点）没有地方表达。
- **拖框不能越过收了它的任何样本的样本日**；选中框时 `member_of` 列出收了它的全部样本（含别的 pattern 的）。防的是：改框起止绕过成员冻结，旧样本的依据被悄悄改掉（原型实测过）。
- **样本**：样本日、所属 pattern（`null` = `unsorted`）、`judgment`（`pos` / `neg`）、`note`、成员框清单。同一天对两个 pattern 都有判断就各放一个。
- **成员框**：默认推断（样本日之前、离它近的一串框），可点进点出；必须在样本日当天或之前结束，跨过的收不进并提示 `crosses sample date`；样本是「当前样本」期间新画的框自动并进，换到别的样本后冻结。防的是：依据伸到判断那天之后（后见之明）；为别的样本补的框悄悄改掉早已定好的判断。
- **负样本**：必须挂在它像的那个 pattern 下（挂 `unsorted` 显示待选、算没填完）；不买的理由画成框或属性，一时画不出先写进 `note`；看到后来跌了才注意到的理由，在 `note` 里照实说。防的是：「像」没有对象；负样本是后见之明最容易混进来的地方。
- **pattern**：名字、一句 `definition`（会话搭骨架、定级时先读它）。
- **不存角色**：框在样本里扮演哪个 node 由会话按名字、位置、框套框推断，推不出才在图上问。防的是：每个框多一步，且逼用户标注时按 app 的结构想。
- **不存的**：看过什么；会话的题目和用户的回答（记在会话那边）。标注文件只由工具写，会话不写。
- **存储**：每批一个新文件、文件名带机器名、只新增不改旧文件；记数据指纹；框按日期存，不存系统事件编号。防的是：两台机器同步冲突；app 改了编号就对不上。

### 3. 对照

- **`compare` 档**：照主视图原样画 app 输出，档位到 detected，app 的 event 和用户的框叠在同一条轨上；换图不退出。换图不自动关，因为训练段上看着 app 标是用户的自由（用户 2026-10-26 定），如实检验靠盲看和没碰过的数据。防的是：只画 bound 时多数图上什么都没有，「看到了但不够格」那档看不见。
- **三层只给状态，不比起止、不给数字**：
  - `tier tag`：框被认到哪一档，`bound` / `qualified` / `detected` / `missing`；会话蓝的 `unmapped` / `excluded` / `optional` / `must_not` 说这个框在 mapping 里的地位，分开「app 没认出」和「app 本来就没被要求认它」。「认出」= app 那个 node 的 event 和框交叠，且一端落在框外 2 天以内。
  - `link tag`：相邻两段 app 连没连上，`connected` / `disconnected` / `not_qualified`；悬停只说差在哪一类（间隔不在边的范围内 / 接的是另一段 / 有一段没认出），不写实测间隔和门槛。
  - `match tag`：hit 与样本的比较，`matched` / `unmatched`。正样本：hit 的买点在样本日前后 3 天内，或样本日落在那次 hit 里 app 声明的买点 node（`eval_meta()` 的 end_node）那段事件中；负样本前后 1 天。不写死回踩。正样本 `unmatched`、负样本 `matched` 用朱红，朱红只用于「app 的判断和你相反」。
  - 防的是：看着实测值和门槛一张张放宽，app 变成拟合那几张图。
- **`diff tag`**：样本的成员框和 mapping 比，`−X` / `+Y` / `order` / `=`，只摆事实、不说谁错，是会话出题的依据；属性参不参与比较以票 [`diff tag` 不看属性：属性对不上时仍显示 =](13-diff-tag-attributes.md) 为准。
- **`chance_high`**：同样宽的框随机挪位置也被判认出的比例过三成，那一块挂它。防的是：铺满时间轴的东西随手一框也「认出」。
- **主要看法是 `pattern` 页**：页头 `app` / `samples` / `match` / `next`；features 区按 mapping 分层（`must` 各段按先后，`optional`、`must_not` 挂在依附的那段下写落法，最下面 `excluded`、`unmapped`）；samples 表按 judgment、`diff tag`、`match tag` 折行、问题排前，app 改版后结论翻了的挂「上一版是什么」的 tag、排最前，从那里打开图时样本日之后先藏（用户 2026-10-31 定）。单张图的 `compare` 是次要看法。防的是：一张张翻图漏看退化。
- **⚑**：用户觉得 mapping 某一行 map 错了就点那一行的 ⚑；会话改过后 ⚑ 弹起、旁边出现 `remapped`。防的是：异议说成一段话，会话不知道改哪一行。
- **`optional` 的落法是 `tracked`**：app 照样算出它在每个样本上成不成立，`qualified` 照常显示、可以拿去量，但不进求解、不决定买不买；pattern 定义写明「有一个就行 / 凑够几样」时，那几样一起落成「至少 k 条成立」（用户 2026-10-31 定，细节归票 06）。防的是：一条 `optional` 写成 where 就等于 `must`。
- **量特征的结论挂在 features 区那个特征上**，带 app 版本，过期标 `stale`；放宽的看因它多出来的买点，收紧的看因它去掉的买点（用户 2026-10-31 定），可点开逐张看。防的是：几周后回来忘了「这条为什么留在 app 里」。
- **有「取其一」时按分支拆开报**认出数。防的是：少见的分支只有一两张图撑着，合计数看不出。
- **没认出的按原因分流**，不让用户逐处拍板：结构性的会话直接修，只差门槛的留给调参，拿不准的出题问。
- **翻译与定级归会话**：词翻成 node、where 还是边，用现成 detector 还是新写，由会话按跨图证据定，写进 mapping，where 按用户的词命名；现成的先试，认不出先排除判定口径的问题；改别的 app 也在用的 detector 前先给用户看一列小图。定级照说明书 ④ 的定级表（只认 pattern 定义；只在负判断里出现的特征一定问，细则归票 [只在 negative sample 上出现的特征：定级时别被一半门槛吞掉](12-nobuy-only-feature-level.md)）。防的是：复用还是新建这种要跨图看的判断，落到用户标某个框的那一刻。

### 6. 留待实施阶段验证

1. **默认数值**（框外容差 2 天、match 容差正样本 3 天 / 负样本 1 天、`chance_high` 三成）。触发：第一批真实标注出第一份 `pattern` 页时。判法：会话逐个列出每个数让哪些框或样本翻了档，请用户过目（只看方向，不让用户定数）。验证前照默认值用；不合适就改数，不回头改本票的方向。
