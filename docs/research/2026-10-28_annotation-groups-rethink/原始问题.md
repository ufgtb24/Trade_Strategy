# 原始问题（逐字）

2026-10-28，「界面 grill」会话里用户的原话：

> 从整个标注流程的目标出发，思考用户会怎么用 group 这个概念，进而思考是否应该对 group 进行优化，以满足方便标注的最终目标。启用 agent team，先思考以哪些维度创建 team mates，然后再开始

> group 的优化方向还包括降低用户心智负担

## 背景：这个问题是怎么来的

对象是标注原型 `docs/research/2026-10-26_annotation-workflow-polish/repro/mock_v3.html` 侧栏 `pattern` 标签页底部的 `groups` 一节（代码在该文件 `sideSum()` 末尾，约 1197～1232 行）。在这之前，用户连着问了几轮（有些消息只留下摘录，用 … 标出）：

- 「pattern tab 的 groups 是谁生成的，用户？session？app?」
- 「也就是说 pattern 面板 groups 节的显示是根据不同阶段变换的：提交给会话前显示 by: sequence 提交后显示：by: required…对么？」
- 「group，主组 和 pattern 三者是啥关系？」
- 「pattern 页有三个阶段，我想知道 user，session 和 app 阶段 group 会有啥变化，列一个表说明…」
- 「这里面第二个是主组对么，其他都是偏离组？」
- 「组是一个比较混乱的概念，能不能解耦合…不要把这么多概念都归于【组】这一个词」
- 「我的理解对不对：组的内容都是用户的标注。组的的前缀形容词有两个来源：- 用户给出：buy，no_buy - 标注和 app 计算结果比较：主/偏离」

lead 当时的回答要点：

- 组里装的是用户的标注（买点和它收的框），这一点对。
- 组身上的标签其实有三个来源，不是两个：`buy` / `no_buy` 是用户标的；主 / 偏离（组头的 `=`、`−回踩`、`+派发`）是**用户的框和会话写下的对应表**比出来的，不看 app 算了什么；`app:buy k/n` 才是 app 的计算结果。三者会不一致：主组里的 buy 也可能 app 没买。
- 主 / 偏离只对 buy 说；no_buy 也按差别分组，但不叫偏离；还没有 app 时没有主 / 偏离，按顶层特征串（`by: sequence`）分组。
- lead 提过一个候选（**用户没有点头，团队不要当成既定方向**）：把 `groups` 换成一张 `instances` 表，三列 `label` / `diff` / `app` 各管一个来源，相同组合合并成一行 `×n` 加缩略图，保留 `→ pattern`；退役 groups、`by: sequence` / `by: required`、主组、偏离组这几个词。

## 当前 groups 身上背着的职责（lead 从代码读出，团队可核对补充）

1. 这个 pattern 下全部买点的唯一列表（缩略图点一下跳到那张图）。
2. `app:buy k/n` 在整个工具里唯一的落点。
3. 偏离组：buy 和对应表对不上（缺必须有 / 有必须没有）排最前。（更正，critic 2026-10-28 核出：polish 报告 83 行说的是反面——每张都顺手框、没写定义的背景特征若被预填成必须有，**根本不会出现偏离组**、哪里都看不出来；那道防线是会话单子上「这一类不预填」，不在 groups 里。lead 起初把它读成了偏离组的暴露职责，已改正。）
4. 像但不买按和对应表的差别分组。
5. 没有 app 时按顶层特征串分组，用来看一个 pattern 里是不是混了几种骨架（方向文档第 8 节「合不合并看骨架」）。
6. 整组挪到别的 pattern（`→ pattern` 下拉、对得上时一键 `→ 某 pattern`），未归类页靠它把一批买点归进 pattern。
7. 缩略图里的「画了没收」◂：一键把附近同名框收进成员。
