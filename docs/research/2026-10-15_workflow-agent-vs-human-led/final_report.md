## 0. 结论

1. **「谁主导」不是一阶问题。** 一阶问题是：裁判是否独立于搜索者，没碰过的数据是否被浪费。这两样要写成事先批准、经独立审计、由工具执行的规则，不归任何一方临场「主导」。A（agent 主导）和 B（人类主导）不加规则时都会浪费那一次判决；A 浪费得更快，造出来的假货也更像真的。
2. **规则到位后，A 和 B 只差一格：训练段内圈「看了上一步结果再决定下一步」由谁临场推进。** 「下一步」包括下一步试什么、收紧后接不接受、要不要放弃。这一格归 agent，理由是**精度**：agent 接触的信息全部经过工具、留在记录里，它的每个选择都能计数、按次数打折，也能限定成「只看汇总、不翻个股图」；人看图后的选择所接触的信息不入账，看过的赢家还会留在成绩里，看过的输家被条件剔掉。不是因为 agent 更快，也不是因为用户时间稀缺，这两样都不是瓶颈。论证强度是【中】：推理加一处代码事实，没有实测。
3. **整体更接近 A，但只能是「规则约束下的 A」。** 用户给出的二选一里选 A，前提是 agent 不当裁判，也不决定什么时候动用验证段。用户的决定少、杠杆大，且大多是**事先**做的：定方向、批准规则、审查方法论。临场做的只有几件：确认「这是不是我说的形态」、盲看命中例子挑错（只能否决）、同意打开验证段（双钥匙）、每周挑票。
4. **启动 A 有三个硬前提，不满足就不该启动：** ① 规则先于搜索；② 验证段物理隔离；③ 裁判代码先经独立审计。护栏到位之前，看图圈照常转，但只在训练段上转，任何候选都不送去验证。见第 4 节。

## 1. 评判轴与瓶颈

评判轴（用户指定「从找到最优股票的最终目标出发」）：最终拿到的 pattern 加配套买卖规则，在新数据上是否真有大优势。「在训练段上好看」不算，「做得快、做得多」本身也不算。判优标准沿用 `.scratch-archive/selection-pattern/issues/12-criterion-vs-resolution.md`：判整套，对照为同日普通买入对照（`path2/CONTEXT.md:155`）；体检用首次穿越（`path2/CONTEXT.md:148`）和前瞻收益（`path2/CONTEXT.md:141`）。

瓶颈按顺序排（`constraints.md` 第 2、3 节）：

1. **诚实判决的次数，硬上限。** 一年约 1～3 次，谁主导都改不了。
   - 验证段 2026-01-02 至 2026-08 初，约 150 个交易日（0.6 年），只用一次，失败后可加严再判一次；之后靠上线后的新数据。
   - 要在验证段看出方向领先 0.15，约需 176 个独立买点，即每个交易日约 1.2 个。
   - 规则每周只命中 1 个买点时，验证段只能看出约 0.36 的领先。
   - **验证段不打开就会自己变大**：每多等一个月，可用买点日多约 21 个。所以「何时打开」本身是有代价的决定。
2. **精度，即送去验证的那个候选是真货的概率。** 由四样决定：
   - 规则稀不稀、运气扣没扣：运气能凑出多大的假领先，主要看规则命中稀疏程度，不看试了多少次。每周 1 个买点的规则，试 30 来次就有一半机会凭运气在训练段凑出 0.15；每天 1 个以上、分散的规则，试上万次也凑不出（`constraints.md` 2.2 的表）。
   - 系统偏差漏不漏：已知单项偏差是目标 0.15 的 20%～70%，因果泄漏一类可达两倍；训练段上分辨不出，每一个混进来的假货都要花掉一次判决才被戳穿（2.3）。
   - 看图环节有没有抬高成绩（2.4，见第 2 节）。
   - 送去验证时按什么排名（第 3 节）。
3. **功效**：与第 1 项是同一硬约束的两面，由规则命中的独立买点数和它声称的领先共同决定。
4. **真货存不存在**：工作流决定不了。真货越稀，搜索的宽度越必要。

不是瓶颈的：
- **搜得快**：两种方式产出候选的速度都比判决次数快十倍以上。
- **用户时间**：假设每周 3 小时，人工节奏一年也有 10～25 个形态。只要不低于每周约 1 小时，结论不变（2.5）。
- **算力**：一个候选全池跑一遍约 1 分钟量级（2.6）。

**对草稿的更正。** `背景_工作流草稿.md` 写的「按每周买一只算，攒够 30 个买点约要七个月」把两件事混在了一起：上线后核对用的是**整份名单的全部命中**，名单每日存档就是为此；用户每周只买的那一只不是核对对象。所以新数据攒得多快，取决于规则命中多频繁，与用户买几只无关（`constraints.md` 2.1、`redteam.md` 第五节第 3 条）。
- 规则每天 1 个独立买点：约 8 个月攒够看出 0.15 所需的数据；每天 4 个：约 2 个月；每周 1 个：约 42 个月。
- 「每周一只、七个月 30 个买点」只适用于「用户挑的那一层」的影子对照。

## 2. 为什么不是「谁更会出好想法」

两边在本项目里都**没有成功先例**（`advantage.md` 第 2 节、第 7 节强论点 1、2）：

- **人**：
  - 经同日对照检验过的用户形态没有一个过线。「孤立跳空阴线企稳」方向成绩比同日同波动普通买入低 3.5 点（64 个买点）、低 5.2 点（720 个买点，分辨得出）（记忆 `project_gap_black_candle_study.md`）。
  - 「超涨是坏信号」「存在未兑现的利好」都被证伪。
  - 唯一像样的命中，是 tb_v1 在一个 pattern 内部区分好坏样本（AUC 0.70～0.73），属于样本内结果，所属的 app 也已废弃。
- **agent**：
  - bb 系的好成绩跨 27 个配置，对波动率回归的 R² 为 0.919（记忆 `project_path2_app_optimization_workflow.md`）。
  - 2026-07-25 已认定 score 是波动率读数之后，2026-08-10 一个 5-agent 调参流程仍报出 +115%、「过 gate」（记忆 `project_bb_v2_tb_optimization.md`）。
  - 写出过因果泄漏（方向领先显示 +0.304，六格全同号，记忆 `project_path2_edge_causality_lesson.md`）。
  - 写的护栏静默失效过：tune-gates-v3 的复核分支被写死成必然撤回（记忆 `project_tune_gates_v3_review_2026_10.md`）。
- **本项目造出过的「大」领先全是假的**：幸存者偏差约 0.10、证券混杂 +0.289（`docs/feature_candidates.md` FC-015）、因果泄漏 +0.304、波动率读数。挡住它们的都是机械的尺子和检查。
- bb 系的教训要人和 agent 各担一半：出处里查不到它由用户设计，成绩主要是 agent 用含波动率的目标反复调参推高的。缺的不是吞吐，而是事先写好的放弃条件，以及「搜索器不兼任裁判」。

所以不能按「谁会出好想法」分权。两个致命弱点同源（`redteam.md` 第三节）：A 的病是「搜索器兼任裁判」，B 的病是「看过训练段赢家输家的人兼任裁判，而且挑选不入账」，归根结底都是裁判不独立。2026-07-25 的 agent team 已有同向结论：工作流是「否决闸阵，不是搜索引擎」；人类标注只有三种用途——诊断、单向否决、语义来源，绝不当目标函数（记忆 `project_path2_app_optimization_workflow.md`）。

**看图环节特有的抬高**（`constraints.md` 2.4，推演；代码事实为强）：
- **种子赢家留在规则里。** 规则在训练段共命中 N 次，其中 h 次是用户看过的大涨段，方向领先就白得约 h ÷ N。h = 20 时，N = 150 白得约 0.13，N = 2000 约 0.01。
- **看过的输家被条件剔掉。** 每轮看 12 个输家，白得约 12 ÷ N。N = 300 时每轮约 0.04，收紧三轮约 0.12。
- **隐性多重比较**（`advantage.md` 第 2 节人第 4 条，推理）：人看一屏输家时比了几十种差别，只说出一条，账本只记 1 次。
- 「收紧」每加一个条件，规则就更稀，要扣的运气也跟着变大；人不会每轮重算。
- **代码核对**：
  - `chart_workflow/contrast.py` 的对照汇总在训练段全池上取命中，只按数据错误登记排除，没有排除用户看过的大涨段；
  - `chart_workflow/ledger.py` 文件头写明「大涨段轮不算尝试」。

**限定**：项目里人的负面证据大多出自「人单干」，即 `issues/14` 背景记的五个毛病：没有流程、没有 agent 参与时的浏览。这否定的是人单干，不是 B；那五个毛病正是在「agent 指出、用户拍板」下修好的（`advantage.md` 第 0 节第 5 条）。

## 3. 宽度：一阶，但不区分 A 和 B

（`constraints.md` 第 3 节，经 redteam 挑战后修订。）

- **好处一阶**：真货很稀时，候选池里有没有真货完全由候选多少决定。
- **坏处也一阶**：一年只判 1～3 次，送去的是排名第一的；搜得越宽，第一名越可能是几项偏差叠出来的组合。
- **净效果取决于排名口径**：
  - 按训练段原始领先排，坏处会被放大；
  - 改按「去掉所有已知偏差区之后的领先，再扣掉按规则自身稀疏度算的运气」排，好处保住，坏处被压到「未知偏差」那一块。
- **B 也能宽**：用户一句话批准「按这套规则挖 2000 条」，由 agent 执行就是。B 限制的是要人拍板的次数，不是候选个数。所以宽度不是选 A 的理由；规则先行才是。

## 4. 决策权分配（三方收敛版）

| 决策权 | 归谁 | 理由 |
|---|---|---|
| 定规则本身：可证实性条件、禁区、门槛、扣运气、排名口径、放弃条件、何时可开验证 | agent 起草 → 另一个 agent 独立审计 → 用户批准一次 → 冻结；改动要用户批准并记账 | 规则是一阶问题；agent 写的护栏会静默失效；用户的方法论审查是有记录的能力（见下） |
| 提出候选 | 双方并行、互不设卡：用户出看图形态；agent 挖数据、接外部信息、读文献，并把用户的形态编码成规则 | 双方都无成功先例，来源多样是便宜的保险；所有候选过同一套条件 |
| 形态写成规则后「是不是这个意思」 | agent 写，用户确认 | 只有用户知道自己的意思；与 `.claude/skills/authoring-path2-app/SKILL.md` 的「形态符合意图由用户看图把关」一致。意图契合是工具价值，不提高精度 |
| 下一步试什么（训练段内圈） | agent 按规则排队（附理由和预算消耗）；用户可以插队、按方向指定优先级、否决某个方向（否决入账） | 第 0 节第 2 条的精度理由；排队依据（能否证实、是否在偏差区外、是否和试过的重复）不读涨跌即可算出 |
| 收紧 | 两边都可以出点子；接不接受由规则判、agent 执行，每轮都算一次尝试 | 收紧是看图抬高和规则越收越稀的入口；计数和打折只有工具做得到 |
| 放弃 | 事先写好的停止规则；用户可以提前放弃，不能临场加轮数 | 人对自己的形态有沉没成本，agent 有汇报动机和「再加一个条件」的惯性 |
| 拦候选、挑错 | 机械门自动拦；用户在每个候选进验证前盲看 10～30 个命中例子，指出买不到、像偷看未来、数据像错的，只能否决；任何一方拦都要入账写理由，看过成绩之后才拦的算一次尝试 | 人对精度唯一有证据的直接贡献：NVX、BRNS 的前瞻 bug 是用户看图抓到的（记忆 `project_tb_buypoint_modeling.md`，单例）；泄漏是目标两倍大的偏差，逐年同号挡不住 |
| 动用验证段，包括那一次「改了再验」 | **双钥匙**：agent 交核对单（规则全满足、可证实性够、现在打开能看出多大、再等几个月能看出多大），用户按开关；任一方不能单独打开 | 不可逆、最稀缺、人担后果。质量部分是机械的，照单盖章正是设计意图；用户真正做的是价值选择：花在哪个候选上、现在开还是再等 |
| 节奏 | 判决节拍由新数据定；训练段内圈 agent 推进，把需要人的环节攒成批 | 速度不是目标；刹车是机械门，不是限速 |
| 每周挑票 | 用户。每周存档名单、名单排序、用户挑的那只和一句理由；上线核对同时算「名单全体 / 名单前几名 / 用户挑的」三条线 | 用户的钱和用法。这一层没被验证，一年约 50 笔，只看得出约 0.28 以上的差别，大概要一两年都说不清 |
| 只在名单前几名里挑 | **有条件**：只有名单排序作为整套的一部分在验证段上也过线，才默认限在前几名 | 本项目历史上的分数在读波动率；没验过的排序拿来约束挑选，可能把偏差固定下来 |
| 方向：目标、尺子、池子、预算、范围、稀规则还是密规则、上线、停用 | 用户 | 偏好与资源决定，agent 推不出来 |

**用户的能力和权力**（`advantage.md` 第 5 节）：
- **不可替代的权**：定方向；对不可逆资源的同意（开验证段、上线、停用、花钱）；自己所提形态的意图解释权；每周挑票。
- **有记录的能力**：
  - 方法论和论证审查：纠正过「调参是目标内优化，不是门槛筛选」「旧实现只是体检仪」，戳穿过四次动机性推理。这项作用在规则质量上，是一阶的。agent 审查擅长查代码和口径，用户擅长判断「这个框定是不是我要的问题」。
  - 看个别命中抓前瞻或语义 bug。
  - 数据里没有的信息，包括自己能不能照规则执行。
- **没有证据的**：看图时的整体判断作为**优势来源**（「像我要的 → 会涨」）。
- **限定**：证据库全由 agent 写成，用户的贡献多被记成一句「用户拍板」，所以对人的归因可能偏低。

**稀规则还是密规则是用户的方向选择，不应写死成固定的频率下限**（`constraints.md` 2.2）：
- 稀的规则要声称很大的领先（0.35～0.4 以上）才证实得了，训练段上还要更大才扣得完运气；
- 密的规则在 0.15 就证实得了，但文献里 0.02～0.05 的效果全是这一类，可能已被做掉；
- 「大优势更可能藏在稀有事件里」在项目里没有证据支持或否定。

## 5. A 的三个硬前提与先后顺序

**硬前提**（三份终稿一致）：

1. **规则先于搜索。** 以下几项在开挖之前写定、由工具执行：
   - **按领先换算的可证实性条件**：扣掉运气和已知偏差后剩下的领先，要在验证段的买点数下看得出，独立买点约 ≥（2 ÷ 剩下的领先）²。剩 0.15 约要 176 个，剩 0.4 约要 25 个。数值待验证，换观察期或买卖规则要重算。
   - 按年份拆开看与判（默认，见下），以排除看过的样本作补充。
   - 禁区。
   - 按尝试次数扣运气。
   - 送验证的排名口径（第 3 节）。
   - 放弃条件。
   - 用到 path2 app 的候选，送验证前先实施「确认根不晚于买点」的运行期检查（已验证可行、未实施；记忆 `project_path2_edge_causality_lesson.md`）。
2. **验证段物理隔离。** 现在 `chart_workflow/config.py` 的训练段终点只是配置值，`datasets/pkls/` 是全量数据，agent 有 shell，过去的研究也读过 2026 年的数据。
   - 挡无意读到：所有研究、看图、挖数据只指向一份截到 2025-12-31 的数据快照副本；账本审计谁何时读过哪段。
   - 挡有意读到：只能靠用户在 Claude Code 权限设置里禁止研究会话读全量数据目录，属用户操作域，由用户自行决定是否设置。
   - 全量数据只在用户触发的那一次验证运行里使用。
3. **裁判代码先经独立审计**：换一个没参与编写的新会话做对抗性复核，再加用手算数字写成的测试。先例：tune-gates-v3 复核分支写死；项目 CLAUDE.md 引用的 eval-discipline skill 并不存在。

**先后顺序**：
1. agent 先补便宜的护栏：按年份拆开、排除看过的样本、可证实性条件、放弃条件、截到 2025-12-31 的快照；path2 app 类候选还要加确认根检查。写好后交独立审计，再请用户批准。

**默认「看一年的图，在另一年上判」**（`constraints.md` 2.4，redteam 提出）：

## 7. lead 的补充意见

1. **「agent 主导」在操作上的含义。** Claude Code 的会话由用户启动、会话结束就忘。所以 A 落地后的样子不是「agent 自己一直在跑」，而是：
   - 任何一个新会话读账本和规则文件，就知道下一步该做什么，不等用户逐步指示就推进训练段内圈，把需要用户的环节攒成批，在固定时段一次交给用户；
   - 用户随时可以插队或否决。

   这要求流程状态全部落在文件里，与 `advantage.md` 第 2 节 agent 第 8 条「不持久」一致。它也是「流程交付成编排 skill 还是手册加工具」那道题的一条约束。
2. **决定 A、B 的那一格可以在第一圈里便宜地测一下**，回应 `redteam.md` 9.3 第 2 条「只有推理支撑」。用户只看 2024 年的大涨段时，同一条规则在 2024 年（看过）和 2025 年（没看过）上的领先差多少，就是看图抬高的直接读数，不花验证段。如果差很小，说明人推内圈的代价被高估了，B 那一格可以重新议；差很大，A 的理由就从推理升级为实测。这是在已经默认要做的「拆年」之上顺手多读一个数，不额外增加用户负担。
3. **三方收敛是弱证据**（`redteam.md` 9.3 第 1 条）：三个 teammate 是同一个模型，读同一个由 agent 写成的证据库。本报告的结论应看作「一个推理被检查了三遍」，不是三个独立来源互证。

## 8. 悬而未决与最不放心

1. **未知的叠加偏差没有机械挡法**：深跌、成交额贴下限、某种波动水平叠在一起。禁区、两证齐赢、跨年代检查只挡已知类型；排名口径能压低，挡不住未知组合。没有退市数据，就量不出叠加能有多大。它决定「宽」的净效果是正是负，对 A 和成批挖的 B 同样成立，最后只能靠验证段和上线后的新数据兜底。
2. **真货可能本来就没有。** 项目里最强的真实效应是营收惊喜，在全市场上属于公开规律，也没到大优势（记忆 `project_fundamental_gate_vs_anchor.md`）。如果这个股票池里没有方向领先 0.15 的东西，本报告比的只是「哪种方式失败得更便宜、更诚实」，答案不变，但用户的预期要按这个讲清楚。
3. **用户挑票这一层大概率长期说不清**：影子对照一两年内可能都没有结论。
4. **训练段到验证段的行情变化（缩水）量不出**，只能在门槛上留余量。
5. **验证段对人和 agent 都只是「新 pattern 的成绩没被看过」，不是「这段行情没被知道过」。** 用户扫描过 2026 上半年；记忆和研究文档里有含 2026 年结果的结论；模型知识到 2026 年中。对纯价量形态影响大概不大，对带题材或外部信息的方向更大。唯一对两边都干净的是规格冻结之后才到来的新数据。

## 9. 口径与限定

- 偶然波动「≈ 0.7 ÷ √独立买点数」来自 `.scratch-archive/selection-pattern/research/02-resolution.md` 的假 pattern 模拟，口径是方向领先、观察期 40 日、线距 5、全部买点等权；配套买卖规则或观察期变了要重算。「看出」= 观察值越过 2 倍偶然波动，真实值 2.8 倍时有八成把握；加严重验用 2.5 倍。
- 「独立买点 ≈ 买点数 × 0.7～1」只适用于分散长相；扎堆长相的门槛更高。
- 「试 K 个里最好的」按互相独立的候选取典型值；真实候选彼此相关时等效 K 更小，所以噪声风险的估计偏保守。
- 看图抬高（h ÷ N、12 ÷ N）、精度示意、用户时间（每周 3 小时）都是推演或假设，没有实测。
- 证据强弱沿用 `advantage.md` 的【强 / 中 / 弱】标注；第 0 节第 2 条，即决定 A、B 的那一格，是【中】。
