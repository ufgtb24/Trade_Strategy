# 原始问题（用户逐字记录，2026-08-31）

## 触发上下文

用户先通过 `/diagnose-event` 诊断 TRON bar 129（scan `20260828T025950`，pattern `bb_v1`）
「为啥不是 peak」。诊断结论：

- bar 129 **是** peak（pk6，price=0.492，在 i=136 登记），bb_v1 与 bo_only 的 peak
  候选集完全相同（peak 产生规则参数逐字一致）。
- 它在 bb_v1 的 UI 上不可见，因为 **peak 不是 Event、不出 stream**，前端唯一能渲染
  peak 的途径是某根 bo 事件的 `referenced_points` 卫星 marker，即「画得出来的
  peak = 被突破过的 peak」。
- bb_v1（`breakout_measure=close`）里 pk6 全程未被突破（i=147 那根 high=0.52 过线
  但 close=0.459 未过线），随后在 i=154 被 pk7@147 supersede 淘汰 → 从未进入任何
  bo 的 `referenced_points` → 前端一个点都画不出。
- 衍生缺陷：未被突破的 peak 在**任何** pattern 下都不可见（如 bar 187/205/212/224）。

随后用户问「为什么 bb_v1 的显示和 bo_only 不同，是否应该统一显示规则」，助手回答
「不该跨 pattern 统一显示（显示差异忠实反映 bo 集合差异），但『未被突破的 peak 完全
不可见』是真缺陷」，并给出 A（现状）/ B（补全 pk 可见性，需改后端因为 pk 不出 stream）
/ C（固定口径统一，反对）三个方向 + 一个低成本中间选项（增强
`no_active_peak_broken` gate 的 measured 字段）。
