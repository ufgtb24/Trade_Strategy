## 一、用户的最终目标与用法

- 用户要的是：每天盘后在目标股票池（美股中小盘、价位偏低，默认普通股、当时价格 ≤20 美元、日成交额 200 万～1 亿美元，待验证）里扫出一份候选名单，用户看图挑，**约每周买一只**，按配套买卖规则买卖。
- 判优标准（已定，见 `.scratch-archive/selection-pattern/issues/12-criterion-vs-resolution.md`）：判整套——pattern 加配套买卖规则，按规则算每笔交易实际赚多少；典型的一笔（中位数）和平均的一笔都要**明显**胜过对照；对照 = 同一天、同一目标池里随便买、按同一套规则买卖（`path2/CONTEXT.md` 的「同日普通买入对照」）。要「大优势」：默认典型一笔每月多赚 3 个百分点以上，体检用的方向领先（首次穿越）0.15 以上（待验证）；方向领先 0.02～0.05 用户明确不接受。
- 训练段默认 2024-01..2025-12；验证段 2026-01 起，**只用一次**（允许改一次再验但门槛加严）；之后靠每日名单存档在新数据上接着核对。数据 2021-10..2026-10，全是仍在交易的股票，没有退市股（有幸存者偏差，用户决定不买数据补）。
- 用户角色（用户全局指令）：用户是「策略方向的决策者」，不是参数的决定者；阈值、系数交给 agent 推算或取默认值标「待验证」；要节约用户的心智负担、加速决策。
- 用户不信任文献；认为公开规律和常见形态的优势多半已被做掉（「太阳底下没有新鲜事」），所以加了「带纪律地挖数据」；现有 pattern（bottom_burst、bb_v1、bo_only 等）全部废弃，框架与底层 detector 可当零件。

## 二、工作流草稿（用户选了「路一」，草稿未批准）

新终点：用户手里有一套能反复跑的找 pattern 流程。每跑一遍，就从看图、挖数据等来源拿到候选，做成一个 path2 pattern 加配套买卖规则，并按上面的标准给出诚实判决。地图交出这套流程的规格和最小工具，验收 = 完整走通第一遍（从候选来源一直走到最后检查，过与不过都如实记账）；每一步写成照着就能做的步骤（何时进入、何时放弃、放弃后退回哪一步）；第二遍以后的运行属于使用流程，不在图上。

草稿里提到的三个升级难题：
1. **没碰过的数据会被用完**：反复跑会不断检验新候选，每检验一次就消耗一次没碰过的数据；必须有「数据预算」——记录谁用过哪段、检验过的候选越多门槛越严；唯一能不断补充的裁判是上线后的新数据，按每周一只，攒够 30 个买点约要七个月。流程能跑多快卡在数据上，不在工具上。
2. **流程好不好只能靠跑一遍来证明**，验收不能是「找到优秀 pattern」（大优势的规律可能本来就少见），而是「完整走通一遍」。
3. 后半段（结构设计、便宜验证、配套买卖规则、最后检查、上线后核对）要写成通用步骤。

流程目前设想的环节（大致顺序）：
- 候选来源：看图工作流（用户看大涨段、说出形态）、带纪律地挖数据、外部信息（SEC 公告、SEC 财务数字、FINRA 空头）、文献（低权重）；
- 看图工作流的圈：找大涨段（会话生成，按相对自身波动排序、分组）→ 用户在 path2_web 多图标注里标形态 → 会话写成规则 → 对照页（数表 + 赢输并排图集，比同日对照）→ 用户看输的例子收紧或放弃 → 训练段达到大优势默认值且逐年同号才「毕业」；全程记账；
- 选方向（「第一遍试跑走哪条路」）→ 结构设计（现有 skill：`authoring-path2-app`、`authoring-path2-detector`）→ 动手前便宜验证（`feature-study`）→ 配套买卖规则 → 调参（`tune-gates-v3`）→ 最后检查（打开验证段一次）→ 上线后每日名单存档、新数据接着核对 → 用户每周看图挑一只。

已建好的工具：`chart_workflow/`（大涨段清单、对照清单、账本、跨源比对 Nasdaq 数据）+ path2_web「看图工作流」模式（一屏多图、框选、点买点、正反例、备注、批量发送）。第一份清单 `outputs/chart_workflow/lists/r001-bigmoves.json`（300 段）已生成，用户还没开始第一圈。
