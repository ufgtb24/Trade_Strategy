## 0. 结论

**v3 的骨架是对的，删掉旧版的那批复杂度也删对了；但它现在跑不完一轮有意义的调参，原因不在方法论，而在三类具体问题。**

1. **一处结构性矛盾（P0）**：复核阶段的结局在代码里是定死的——无论复核数据多好，一律恢复原参数。ADR 0004 的「暂用、之后复核」退化成「暂用一段时间后必然撤回」。
2. **几处会白白作废数据或卡死流程的工程坑（P0）**：全仓源码指纹几乎必然拦住数月后的最后检查；行情没更新就跑检查会先登记、再报错，把等了几个月的数据永久作废；省略回看起点会让短检查段落进预热期、买点为 0。
3. **真正的约束是信息量，而 v3 既没扩大信息、也不告诉用户信息不够（P1）**：在 bb 真实对照的 256 只股票规模下，训练挑选和在合格候选里随手挑一个几乎没有区别，最后检查对「真改善约 0.03」与「没改善」的区分力只有约 1.6 倍。另有两道绝对下限其实在看大盘方向、不在看参数好坏。
4. **搜索目标没对准用户要优化的东西（P1-3，汇报后补）**：Optuna 的目标是候选自己的方向主分，含买点日期的大盘 / 普涨背景；「相对同日普通买入对照的优势」与「买点数」只当门槛，过了门槛就没有任何推力。可选的统计折扣本该补上这两样，但移植旧框架时把逐候选的同日普通买入对照加回了目标，反而加重了大盘那一块。

修法以**删除、改几行、改默认值、改文档**为主。全队一致不建议引入任何新的统计机制（确认规则、功效闸、稳健区、参数个数限制都不做）；唯一新增的是一个只报告、不参与决策的「偶然波动」数字。统计折扣不删：修正一处返回值后作为默认搜索目标（P1-3），这是修移植走样，不是新增机制。四处方向已于 2026-10-06 由用户拍板，全部按推荐（§4）。

## 1. 第一性原理框架：调参这件事要回答什么、被什么约束

调参要回答的是一个**二选一决策**：把现役参数换成某个候选，未来交易会不会更好。由此推出三件事：

- **决策只需要一个干净的比较**：候选 vs 现役，在没参与挑选的数据上比一次。任何训练内的挑选规则（取最高、取最差、稳健区、打折）都只影响「把谁送去比」，不改变「比的结果有多可信」。这句只讲可信度；送检候选的期望质量仍取决于搜索在优化什么，所以搜索目标必须对准用户真正要的东西（P1-3）。
- **可信度的上限由信息量决定，不由流程决定**：候选和现役的成绩差有多大偶然波动，取决于买点来自多少只股票、多少个独立时段。流程再精巧，也变不出数据里没有的信息。旧版在 bb_v1 上「没找到稳健区」、v3 在 bottom_burst 上「选中的参数后段失效」，根因相同：参数改动的真实效果（约 0.03，方向分单位，由旧研究 2~3 个百分点换算，推理）小于这批数据的偶然波动。
- **规则只该检验「换了会不会更好」**：任何在候选和现役身上都不成立的绝对条件（比如「方向分必须为正」），在二选一里只会导致「保留更差的现役」。

按这个框架看 v3：它的架构（每个候选直接跑检测并评分、同日普通买入对照（同日同波动配对）、唯一候选只送检一次、使用记录防反复看留出数据）符合第一点；问题集中在第二点（信息不足而且看不见）和第三点（绝对下限），外加决策链末端的死分支与工程坑。

## 3. 问题与修法（按优先级）

### P0-1 ★ 复核必然撤回，且与复核数据无关（已验证）

- 代码：`scoring.comparison()` 把 `evidence_sufficient` 写死为 False、`improvement_lower/upper` 写死为 None（`.claude/skills/tune-gates-v3/scripts/scoring.py:434-436`）。`governance.adoption()` 中，「确认」分支要求 `evidence_sufficient=True`，「暂用」分支要求 `stage == "final"`，复核阶段其余分支全部落到 `rollback`（`scripts/governance.py:381-397`）。lead 已逐行核对。
- 复现：复核段新参数方向分 1.0、原参数 0.0、要求全过，仍返回 rollback（`repro/simplicity_repro.py` R1；R1b 枚举复核阶段全部输入组合，输出全是 rollback）。自带测试也把它当期望（`tests/test_run.py:105-106, 270-272`）。
- 后果：复核要预留并永久消耗一段新数据、等待一个完整的未来期限，却不影响结论；参数想长期留下，唯一办法是不跑复核。用户可见的说明把「确认采用」画成可能结局（`docs/explain/tune-gates_v3纲要_通俗解释.md:31-32`、`docs/explain/tune-gates_v3伪代码_通俗解释.md:86-87`），遮住了这一点。
- 修法（需用户拍板，§4 Q1）：
  - **A（推荐）复核沿用最后检查的同一条规则**：要求全过且新数据上观察到改善 → 状态「继续使用」（说明写「两次独立观察均改善，非统计确认」）；否则撤回。约 3~5 行，改 3 条测试的期望值。
  - **B 删掉复核**：暂用即现役，下一轮调参时自然重评。净删约 40 行，但推翻了用户在 ADR 0004 里选的「到期复核」。
  - A 与 B 的量化差别（正态近似，忽略机会下限与平局，推理）：真实效果为 0 的改动被长期留下的概率，A 约 25%、B 约 50%；这个概率**不随股票池变大而下降**（只看「是否改善」的检查对零效应本质上是抛硬币）。股票池变大改善的是对非零效应判对方向：全池时，变差 0.03 的改动在 A 下被留下的概率从 13% 降到 0.2%~5%，改善 0.03 的从 41% 升到 60%~91%（selection §11 问 2）。
- 同时删除：不可达的「确认」状态及其输入字段（`evidence_sufficient`、`improvement_lower/upper`、`lower/upper_unbounded`）、同样不可达的「明确变差」分支（`improvement_upper < 0`）、只接受一个固定值的 `adoption` 配置块（`run.py:216-218`），以及 SKILL / method / 白话说明里关于「确认」的保留说明。约 −20 行（selection D1）。将来真有校准过的确认规则时，本来就要重新冻结规则，届时再加。

### P0-2 ★ 全仓源码指纹几乎必然拦住最后检查，且没有回退途径（已验证机制 + git 节奏；外推为推理）

- `source_hash` 对 `path2/`、`path2_apps/`（全部 app，含历史残留）与 skill 脚本的所有 `.py` 求哈希（`scripts/run.py:59-68`）；最后检查和复核发现不一致即拒绝（`run.py:386-387`）。冻结记录里没有 git 提交号（`run.py:300`）。lead 已核对。
- 过去 4 个月 path2 / path2_apps 的 `.py` 改动最长间隔 31 天；bb 系最后检查最早要到 2027-02。期间改动任何一行（含未提交的本地改动），检查就被拒；搜索时若有未提交改动，连可回退的提交都不存在。拒绝发生在登记使用之前，数据不会作废，但这一轮走不下去。
- 修法：冻结时多记 `git rev-parse HEAD` 与「工作区是否干净」（约 3 行）；runbook 加一句「哈希不一致时在该提交的 worktree 里跑 validate，`TUNE_LEDGER_DIR` 指向主目录」。不删这道守卫（删了会让验证的不是当初冻结的检测代码），也不收窄到依赖分析（更复杂）。

### P0-3 ★ 行情没更新就跑检查，会先登记、后报错，数据永久作废（已验证）

- `run_check` 先 `usage.claim`（`run.py:397`），再建评价器读数据（`run.py:398`），每股行情不齐在 `daily.py:216-221` 报错；再跑时账本拒绝「已消耗」（`governance.py:314-315`）。SKILL.md 把它写成有意为之（「文件滞后时失败并保留使用记录」）。lead 已核对顺序。
- 本项目行情靠手动从 Yahoo 拉，「日期已到」与「数据已到」是两件事，这个情形很可能发生。
- 修法：把「每股行情是否到齐」的检查（只读文件末日期，不看涨跌，不构成暴露）挪到登记之前。净增约 5 行。只写文档提醒不够：违反一次的代价是数月数据。

### P0-4 省略回看起点会让短检查段整段落进预热期（已验证代码路径）

- 省略 `history_start` 时等于 `start`（`run.py:223`），前 63 个交易日的买点被排除（bb 的首部缓冲，`path2_apps/bottom_burst/dag_spec.py:95`；`daily.py:300`）；检查段短于约 3 个月时买点为 0 → 不采用，数据已记为用过。配置检查不核对缓冲（`run.py:243-246`）。
- 修法：`history_start` 默认取「start 往前推搜索范围内最大首部缓冲个交易日」，约 5 行，同时删掉一个人工决定。默认值与上一阶段冲突时，配置检查会在读任何数据前报错，安全（simplicity S8.1）。

### P1-1 信息量不足而且看不见（已验证，256 只股票规模）

| 量 | 第一折 / 第二折 | 出处 |
|---|---|---|
| 原参数的买点来自几只股票（搜索段 / 后段） | 10 / 3；12 / 9 | objective「数据与方法」 |
| 原参数主分按股票重抽的波动 | 0.24 / 0.17 | objective §1 |
| 候选减原参数的配对波动（中位） | 0.12 / 0.08 | objective §1；selection F2 |
| 真实改善为 0 时，训练赢家的「改善」中位数 | 0.19 / 0.19 | selection F2 |
| 植入真改善 0.03 的候选被选中的概率（对照：在合格者里随机挑） | 6.5%（4.5%）/ 2.6%（2.0%） | selection F2 |
| 搜索段分数对后段分数的 Spearman | +0.13 / −0.44 | objective §1 |
| 最后检查进入暂用的概率：δ=0 / +0.03 / −0.10（第二折后段） | 17.9% / 29.6% / 1.8% | selection F3 |

- 所有噪声数字是**下限**：按股票整只重抽不含「同一天全市场一起动」的时段冲击；四个时段之间原参数的同日普通买入对照在 −0.17~0 之间摆动，比股票抽样噪声更大，且不随股票数增加而缩小（推理）。
- 挑最高分还系统性偏向噪声大的候选（买点少、离现役远）：赢家的配对波动是候选中位数的约 1.45 倍（selection F2，已验证）。真实例子：第一折搜索段原参数 255 个买点，选中候选只有 162 个（约 64%，离「不少于一半」的下限不远）；以平均质量为目标、门槛以上不再偏好买点多时，挑最高天然往下限漂。当时统计折扣（该候选保留约 42%）也没改变这次选择（`docs/research/2026-10-02_v3-bb-training-calibration/calibration.md` §3）。对策见 P1-3。
- v3 刻意不把买点数、股票数当证据（`references/method.md`），这是对的；但它也没给任何替代刻度，于是「这次本来就分不出来」对用户和 agent 都不可见——旧版「效应小于噪声」的失败原样保留，只是不再报出来。
- 修法（全部是默认值或只报告）：
  1. **股票池默认取全部可用、结构合法的股票**（selection A1）：SKILL「开始时」第 3 步加一句，`references/configuration.md` 的 6 只股票示例换掉。零代码。这是唯一直接增加信息的杠杆；全池时配对波动按 1/√股票数 推算约 0.02~0.03，与真实效应同量级（推理，未实测；时段冲击不缩小，属乐观估计）。算力约 20 倍，80 次约 20 分钟（推理）。
  2. **默认观察期限由 20 个交易日改为 40**（objective D5）：H=20 时约 67%~70% 的买点在期限内两条线都没碰到，H=40 时约 40%；每个买点的方向信息约翻倍（已验证比例 + 推理信息量）。零代码；代价是各阶段多留约 20 个交易日的未来尾部。bb 真实对照本来就用 40。
  3. **偶然波动数字，只报告、至多提醒一次**（objective N1，经 simplicity 限定）：搜索前用原参数的逐日标签按股票整只重抽一次，报一句「方向成绩的偶然波动约 ±X，相近参数之间的差别一般是它的一半左右；过去实测参数改动的效果约 0.03（待验证）」；明显不够时提醒一次扩大股票池。不加配置键、不阻断、不进排名或采用规则；实现 ≤40 行，超出就退为只报这个数。实现注意：`WindowPlan` 拒收同股同日重复行（`scoring.py:152`），重抽要按「每只股票被抽中次数」加权，不能把重复行塞回去（原型 `repro/objective_noise.py` 的 `StockMatrix`，与正式实现逐值一致）。
  4. **开跑时告诉用户两件事**（selection A2）：最后检查与复核最早的出结论日期；训练里的差值是「挑选后的观察值，主要用来决定值不值得送检，不是预期改善」。两句文档。

### P1-2 两道绝对下限在看大盘方向，二选一时会留下更差的现役（已验证）

- 规则：方向主分严格 >0（`min_direction_score=0`）、对同日普通买入对照的差 ≥0（`baseline_tolerance=0`），训练、最后检查、复核共用（`scoring.py:24-33, 367-389`）。这是工程默认，ADR 里没有。
- 实例：第二折搜索段（含 2025 年初下跌）28 个候选 27 个被「主分 >0」卡掉；原参数自己主分 −0.203、对同日普通买入对照的差 −0.035，两道都不达标；有 10 个候选两项都优于原参数、机会也够，全被拒，结果保留 −0.203 的原参数。第一折后段原参数主分 −0.40，任何 δ 下暂用概率都 <1%，结论在打开数据前已注定。
- 逻辑：选择本来就要求新分高于原参数（`run.py:286-289`、`governance.py:388`），「主分 >0」额外检验的是「这个 pattern 这段时间值不值得做」，不是「哪套参数更好」。
- 修法（objective D2 = selection M2；需用户确认方向，§4 Q2）：删「主分 >0」；「对同日普通买入对照的差 ≥0」改为「不低于原参数自己的这个差」（对称：现役本身胜过同日普通买入对照时反而更严）。净减一个配置键，约 2 行 + 1 条测试。「pattern 当前整体方向为负 / 不如同日普通买入对照」改为报告里的醒目诊断。
- 实测：两折可行候选 5 / 10 个，两折选中的仍是同一个（`bo.exceed_threshold 0.003→0.006`）（`repro/constraint_variants2.py`）。
- **代价须原样交给用户**：256 只股票时，最后检查对零效应候选的暂用率由约 18% 升到约 35%，真改善 0.03 时由约 30% 升到 52%，变差 0.10 时 6.5%；配合 P0-1 的 A，两关都过分别为 16% / 35% / 0.7%（`repro/harm_sim_relfloor.py`）。原来的 18% 低，是因为那道线把整体弱的时段整段拦下（好候选和零效应候选一起拦），不是在区分候选好坏；区分力只从约 1.65 倍略降到约 1.5 倍。压低误暂用的正路是 P1-1 的股票池，不是保留一道按大盘涨跌拦人的线。

### P1-3 搜索目标没对准「相对普涨的优势 + 证据量」（汇报后用户复议补入；代码已核）

- 现状：
  - Optuna 的目标 = 候选的方向主分 Z（统计折扣关闭，即默认时；`scoring.py:307-316, 392-405`）。Z 含买点日期本身的大盘背景。
  - 同日普通买入对照只以硬要求进入搜索：「Δ = Z − B ≥ 0」与买点相对下限一起，作为约束交给 `TPESampler(constraints_func=…)`（`run.py:324-346`）；不达标的 trial 标为不合格，TPE 向合格区域采样（Optuna 文档行为：不合格者按违反总量排序，未在本仓实测），赢家只在合格者里按目标取最高（`run.py:286-289`）。最后检查再查一遍同样的硬要求，外加目标分高于原参数（`governance.py:382-387`）。
  - 所以过了门槛以后，比同日普通买入对照强多少、证据多足，都不影响排名——搜索在这两件事上是筛选，不是优化。后果：两个都合格的候选里，买点恰好落在上涨段的排前；以平均质量为目标时搜索往买点下限漂（P1-1 的 255 → 162 实例）。
- 统计折扣开启时也不对：`_adjust_score` 返回 S = B + λΔ = λZ + (1−λ)B（`scoring.py:62-103`）。B 随候选的买点日期而变，原样留在目标里；λ 越小 B 占比越大——它加重了大盘那一块，并不防普涨错觉。来源是移植走样：旧框架 `BreakoutStrategy/mining/threshold_optimizer.py:97-100` 的基线是全表标签中位数（`:603`），对所有候选是同一常数，argmax[baseline + w·(median − baseline)] ≡ argmax w·(median − baseline)，实际优化的是「打折后的超额」；v3 把基线换成逐候选配对后再加回，意思变了。
- 修法（Q4 待确认）：
  1. 搜索目标改为 λΔ：`_adjust_score` 返回 λΔ 而非 B + λΔ；|Δ|≈0 或误差估不出时返回 0。关闭折扣时目标为 Δ（相对优势、不打折），不再回到 Z。约 3~5 行 + 测试期望值。
  2. 默认开启——它就是目标，不再是「实验开关」；保留关闭开关；τ=0.1、带宽 80 沿用，报告里标「未校准」。description 删触发词「启用统计折扣」（不再需要点名开启）。
  3. 最后检查与复核按同一口径（λΔ）比较新旧参数，否则搜索优化一样东西、检查验另一样。
  4. 硬要求（买点相对下限、P1-2 改后的「Δ 不低于原参数」）保留为兜底，不承担优化；P1-2 的「删主分 >0」与目标改为相对优势一致。
- λΔ 给出两种推力：Δ 已扣同日普通买入对照（相对普涨）；Δ>0 时证据越足（买点越多、各时段越稳）λ 越大、分越高，是连续偏好，不是一刀切。
- 为什么 pattern 只读单只股票、目标却扣掉同日大盘，仍然自洽：目标扣掉的是买点之后的大盘，那块输入本来就预测不了，扣掉只去噪、不缺信息；输入里大盘与自身混在一起只会稀释信号，不构成配对错误（§11.6）。
- 已知不足（不阻止修法）：τ 手拍；V 在作者模拟里只有真值的 46%~72%（打折偏轻），也没单独建模时段漂移；Δ<0 时 λΔ 偏向证据薄的候选（更接近 0），由硬要求和最后检查兜底。λ 对买点数的偏好是「证据够不够」意义上的，证据足后自然消失；不随证据消失的买点数偏好属业务目标，见 §5、§11.4。
- 与防过度设计的关系：不新增机制，改的是现有代码一处返回值和一个默认值，净减一个触发词。

## 7. 修完之后能期待什么（推理，须如实告知用户）

- 即使全部修完、换成全池，**调参的期望收益本身就小**：真实效应量级约 0.03，挑选与检查仍会让约四分之一的零效应改动被长期留下（按定义无害）；变差的改动几乎留不下，真改善约 0.03 的改动大多能留下。v3 修好后的定位：搜索阶段是优化器（目标对准相对同日普通买入对照的优势与证据量，P1-3）；采用阶段是便宜、诚实的过滤器——最后检查能可靠做到的是拦住明显变差，不能确认改进。
- 时间线（bb，H=40，NYSE 日历）：现规则下最后检查最早约 2027-02（21 日买点窗）到 2027-04（63 日买点窗）出结论，复核再晚约 6 个月（`repro/timeline.py`；selection F5 / §11）。bb 谱系过去的数据已被 bb_v1 用到 2026-08-18，留出数据只能来自未来。

## 8. 局限

- 实测只覆盖一个 pattern（bottom_burst）、256 只股票、两个相互重叠的开发拆分；全池噪声是按 1/√股票数 推算的，未实测。全池实测需要先核对这些数据的使用登记，本轮未做。
- 噪声数字未含时段冲击，是下限；搜索→后段相关只有 19~22 个高度相关的候选，只作方向性参考。
- 「真实效应约 0.03」由旧版 bb_v1 的先上率效应换算，不是 bottom_burst 的实测。
- §11.4 中 5000 只股票时的折扣强度、等效 n0 都由 256 只股票的结果按股票数等比例推算，未实测；时段冲击占噪声比重大时，折扣会比推算的强。λΔ 目标的效果未做任何实测。
- 本轮额外读了 256 只股票 2024-01-01..2025-06-30 的行情（收盘 vs 盘中、期限与未触线比例），该范围已登记为 bottom_burst v3 开发数据（`docs/sample_usage/bottom_burst.v3.jsonl`），未读 2026 年数据。

### 11.4 问答中的补充分析（推理 + 已核数据，未实测）

- **v3 默认力度折算成旧框架 n0 约 220**：λ = τ²/(τ²+V)，若 V ≈ s²/n 则 λ = n/(n + s²/τ²)，等效 n0 = s²/τ²。第一折选中候选 162 个买点、λ≈0.423 → n0 = 162×(1−0.423)/0.423 ≈ 221，与旧框架主流程 n0=200（`threshold_optimizer.py:576`）相当。
- **任何固定 n0 在买点远多于它时都会趋于不打折**：全池（5000+ 只）时原参数约 5000~7000 个买点（按 256 只时 255 / 356 等比例推），n0≈200 下保留约 0.96~0.97，买点减半的候选约 0.93~0.95，只能对调领先幅度相差约 4% 以内的候选。对通用方法这是该有的性质（证据厚时让开），不是缺陷；稀疏 pattern 上它照常起作用。
- **把 n0 设成与股票数 × 时段长度成正比**：买点数 n 本身也与之成正比，样本量约掉，λ = r/(r+c)（r = 每股每日买点密度），不再随数据变化。它不会失效，但不再是「证据少所以少信」，而是固定汇率：按 256 只时的力度固定，原参数保留约 0.54、买点减半的候选约 0.37，后者的 Δ 要达到前者约 1.46 倍才胜出。
- **统计上不存在「大样本下持续偏好买点多」的折扣**：不确定性分两类——抽到哪些股票 / 买点（随买点数增加而缩小）；同一改动在不同时期效果不同（不随股票数缩小、只随时段变长缩小，且基本与买点数无关）。前一类在大样本下必然消失，后一类不区分买点多少。凡大样本下仍偏好买点多的规则都是业务偏好。另外统计上时段越长越可信、打折应越轻；与时段长度挂钩会抹掉这一点。
- **业务上的买点数偏好应由资金容量决定**：多出来的买点能否变成收益，取决于每天的信号是否已超过资金能接的数量（同时持仓数 × 持有期）。股票池 256 → 5000+，每日信号约多 20 倍，可能已从「不够用」变成「接不过来」，此时按密度给偏好会让搜索为数量放弃质量。持仓 / 退出规则未定（`docs/research/2026-10-02_v3-objective-and-shrinkage/final_report.md` §1），汇率定不了，现在不做。

### 11.5 用语更正与「绝对 vs 相对」（2026-10-06，lead 推理，未经团队复核）

**更正**：`path2/CONTEXT.md:152` 的随机日基线是「从全宇宙随机抽日算同一指标」，不限同一天；v3 的 B 是候选每个买点的同一天 × 当日波动五档配对。初稿与 10-05 的补充把两者混为一谈，P2-3 还建议把 v3 的对照改名为随机日基线——已全文改正。「同日普通买入对照」已于 10-06 经用户同意写入词表（`path2/CONTEXT.md:155`），与随机日基线并列，并在随机日基线词条补了一句区别。

**两种对照正好对应「相对 vs 绝对」之分**。一个 pattern 的绝对方向成绩可拆为三块：

| 组成 | 含义 | 怎么量 |
|---|---|---|
| 整体行情 | 这段时间大盘整体涨跌 | 随机日基线本身 |
| 择时 | 买点是否偏偏落在随后大盘上涨的日子 | 同日普通买入对照 − 随机日基线 |
| 选股 | 同一天里挑出的股票是否比别的股票走得好 | 候选 − 同日普通买入对照（= Δ） |

对随机日基线比 = 择时 + 选股；对同日普通买入对照比 = 只剩选股。同一段数据里比几套参数时整体行情对谁都一样，所以「调参用哪个对照」等价于「择时算不算分」。

**lead 的判断**：
- **调参目标只算选股（Δ / λΔ）**：择时由少数几段独立的大盘起伏决定，一年多的训练数据里只有寥寥几段，股票池再大也量不准（本报告 P1-1：原参数的同日普通买入对照在四个时段间摆动 −0.17~0，大于股票抽样噪声且不随股票数缩小）；让 Optuna 优化它就是拟合训练期那几段行情。参数真正能稳定改变的是「同一天留下哪些股票」。
- **绝对成绩用于「要不要交易、仓位多大」**：钱按实际涨跌赚；在大跌中频繁触发、每次跌得比别人少的 pattern，选股为正，只做多仍亏。报告里绝对成绩、对随机日基线、对同日普通买入对照三样都列，排名只用最后一个。
- **择时若真存在，单独验证**：用多轮涨跌周期的长历史，归 feature-study；成立的话做成显式的大盘状态条件，不靠参数调优撞上。

### 11.6 单股输入能否配相对目标（2026-10-06，lead 推理，未经团队复核、未实测）

**用户的论点（转述）**：path2 的输入是单只股票的 K 线，自身成分与大盘成分混在一起、剥不开；目标却扣掉同日普通买入对照、只留自身成分，剥离所需的大盘信息输入里没有。按信息量，配对应是「① 输入绝对走势 → 输出绝对走势」或「② 输入剥离大盘后的走势 → 输出剥离大盘后的走势」；但需求上想要「① 的输入 → ② 的输出」。

**判断：论点一半对。「① 的输入 → ② 的输出」可行，且就是 P1-3 的目标；同样输入下它比 ①→① 更容易学，不是更难。**

1. **「输入输出成分要一致」这个判据忽略了时间方向。** 输入里混的是买点**之前**的大盘，输出里含的是买点**之后**的大盘，不是同一个量。①→① 的输出里有一整块（未来大盘）是输入完全不知道的——按「信息量要够」的标准，恰恰是 ①→① 不满足。
2. **剥离不需要输入知道被剥掉的那块。** 输入只需含有关于「留下那部分」的信息；被剥掉的部分若本来就预测不了，输入不知道它无妨，剥掉等于去掉学不掉的噪声。反过来，往标签里加入与输入无关的成分，只会降低输入能解释的比例。故同一输入下，预测 ② 的输出 ≥ 预测 ① 的输出。
3. **用户说对的部分是输入质量。** 自身与大盘混在一起，同一形状可能来自大盘普跌、也可能来自个股自身；大盘普跌造成的形状会在同一天大批股票上同时出现，相对同日普通买入对照约为 0，只有个股自身造成的形状才可能拉开相对差距。pattern 分不开两者，信号被稀释——这是单股输入的天花板，不是配对错误。②→② 会比 ①→② 更准。
4. **例外：择时。** 若过去的大盘对未来大盘有一点预测力（如大跌后反弹），①→① 多出的那块不全是噪声，但它只有十几段可验证（§11.5），调参不优化它。

| 组合 | 输出含 | 输入能解释的 | 评价 |
|---|---|---|---|
| ① 入 → ① 出 | 未来自身 + 未来大盘 | 自身（被稀释）+ 极弱择时 | 多一块学不掉的噪声，最差 |
| ① 入 → ② 出（P1-3 提议） | 未来自身 | 自身（被稀释） | 可行；上限受输入混合限制 |
| ② 入 → ② 出 | 未来自身 | 自身（干净） | 最好；需把大盘数据接进 pattern，属架构改动 |

**① 入 → ② 出能找到 / 找不到什么**：能找到「不论成因、出现后平均跑赢同日同类股票的形状」；找不到「相对大盘超跌」这类须先知道大盘才能定义的信号。单股形状里能预测相对表现的信息本来可能就少，这也许是调参效应小于噪声的原因之一（推测）。

**撤回的说法**：问答中 lead 曾说「比大盘多跌了多少是 pattern 能从 K 线里看到的、可用来预测相对表现」——错误。detector 只读单只股票，算不出相对大盘的量，不能据横向超跌预测横向补偿。

**若要 ② 入**：让 detector 同时读大盘指数、算出相对大盘的走势，是 path2 架构层改动（现 detector 只读一只股票的数据）。顺序应是先用 feature-study 验证「相对大盘的走势」与之后的相对表现有无关系，再议架构。此为未量过的假设，未登记 `docs/feature_candidates.md`。
