# 模拟交易 label 设计 draft(payoff 视角)

> 作者:payoff(模拟交易设计师)。聚焦用户「视角2·收益性」,设计并论证「模拟交易 label」。
> 一句话定位:**`strategy_return` 是「选股 × 固定交易规则」联合体的利润读数,不是选股纯度的尺子。**

---

## 1. 定义与非对称变现语义

### 1.1 定义(沿用原 plan `match_strategy_return`,走势-无关)

对 `end_node` event 的买点窗 `[start_idx, end_idx]` 内每一个进场日 `t`,在 `[t+1, t+horizon]` 上模拟一条「静态止损 + 跟踪止盈」双线退出路径,取该进场日的收益;最后对所有有效进场日的收益取**均值**。

逐 bar 规则(与 mfr 共用同一买入锚、同一 horizon、同一越界跳过规则):

- 静态止损线 `SL = entry × (1 − stop_loss)`,固定不变。
- 跟踪止盈:当 `peak ≥ entry × (1 + take_profit)` 时激活;激活后跟踪线 `TL = peak × (1 − trailing)`,随 `peak` 上移。
- 当根生效保护线 = 激活前 `SL`;激活后 `max(SL, TL)`(激活后 TL 必然高于 SL,实际接管)。
- 同根 bar 先用「上根末状态」保护线判 `low` 是否触及(止损优先,保守),未触及再用 `high` 刷新 `peak`(当根新高不立即上抬当根保护线,避免 bar 内部看未来)。
- 全程未触发 → 到期 `t + horizon` 按 `close` 平仓。
- `t + horizon` 越界的进场日跳过;全部越界 → 返回 None。

### 1.2 非对称变现语义(用户核心洞察的形式化)

用户的原话:「跌被止损人为截断(不无限下跌)、涨逐利追 max price,所以真实交易的反馈是不对称的。」这条规则把这句话精确落成了一条 P&L 曲线的形状:

- **左尾有界**:无论价格跌多深,止损线把单次亏损封顶在 `−stop_loss`(8%)。一个 -83% 的暴跌(XAGE 案例)与一个 -9% 的缓跌,在止损触发后**实现的亏损几乎一样**(都 ≈ −8%)——暴跌多出的 -75% 被「人为截断」抹掉了。
- **右尾开放(到 horizon 为止)**:上涨方向没有封顶,跟踪止盈让你**尽量贴近峰值**退出(付出回撤 `trailing` 的代价)。涨得越多,实现收益越大,直到 horizon 用尽。

这就是「不对称」:下行被纪律截断、上行被贪婪追逐。它不是数学上 +/− 项权重不对称,而是**退出行为对涨跌的处理方式不对称**。

### 1.3 三个 label 的根本差异(已实测验证)

把 mfr / directional(端点收益)/ strategy_return 放一起,逐维对照:

| | mfr | directional(端点收益) | strategy_return |
|---|---|---|---|
| 路径相关性 | 路径**无关**(只取 `max(high)`) | 路径**无关**(只取 `close[t+N]`) | 路径**相关**(逐 bar 演进) |
| 对称性 | 不对称(只看涨) | **对称**(涨跌平等) | 不对称(跌截断、涨追逐) |
| 含交易规则 | 否 | 否(被动持有 baseline) | **是**(止损+跟踪止盈) |
| σ→期望 | 有偏(σ↑⟹E[mfr]↑,选择偏差) | 无偏(σ 只增方差不移期望) | 有偏(σ↑→跟踪止盈吃尖刺,sim↑,「波动率红利」) |
| 本质 | 乐观上界(幻想值) | 纯方向位移(选股信号) | 受纪律约束的**变现值** |
| **XAGE tb_208_213 实测** | **+1.33%** | **−77.00%** | **−8.00%** |

> 实测 repro:`docs/research/2026-07-30_label-design-directional-vs-payoff/repro/xage_sim.py`(切窗 2024-09-19..2026-03-08、horizon=40、8/20/10、tb_208_213 内联实现 simulation)。三个数均为真跑得出,非推测。

**关键观察**:同一个 match,三个 label 报出三个完全不同的真相——mfr 说「微涨」、directional 说「暴跌 77%」、payoff 说「止损封顶 -8%」。三者**没有一个是「对的」**,各自照亮一个侧面。这正是三 label 共存的实证依据。

**重要披露(skeptic 提示,已实测验证)**:payoff 的 −8% 是「**8/20/10 这组外生先验下的投影**」,**不是** sim 的客观读数。参数敏感性扫描(repro 同文件)显示 XAGE 的 sim 随先验变动:

| 外生先验 (sl/tp/trail %) | sim |
|---|---|
| 8/20/10(默认) | −8.00% |
| 5/15/8(更保守) | −5.00% |
| 3/0.5/0.5(极紧止盈+紧跟踪) | −0.56% |
| 15/20/10(宽止损) | −15.00% |
| 8/40/10(止盈永不激活) | −8.00% |

两点结论:(1) **sim 值是先验依赖的投影**,报告时必须标清先验,否则隐含扫参、与我自己的 §5.2 红线冲突;(2) 但 **XAGE 这个 case 的「符号为负」是稳健的**——skeptic 预测「紧止盈会翻正」,实测不成立(连 0.5%/0.5% 都只到 −0.56%,因为暴跌太决绝、紧跟踪也来不及锁利)。所以 XAGE 是一个**结论稳健(负)、幅度依赖先验**的 canonical example——它证明 mfr 的 +1.33% 是 fantasy 这点不靠参数选择,但 payoff 具体报多少要标清先验。其他 match 上符号本身可能随先验翻转,故披露先验是普适要求。

### 1.4 strategy_return 的独有价值 = 路径/顺序信息(skeptic 提示,我采纳)

feedback line 369 已点明:MFE/MAE 是**幅度**统计量、丢掉**顺序**——「先涨后跌」与「先跌后涨」可以有相同的幅度统计,但在任何止损/止盈规则下**结果相反**。

mfr 和 directional 都是路径无关的,都丢掉了顺序。**只有 strategy_return 编码了价格演变的顺序**:同一段「先涨 20% 后跌 20%」与「先跌 20% 后涨 20%」,mfr 相同(都见过 +20% 峰)、directional 端点相近、但 strategy_return 截然不同(前者触发跟踪止盈落袋、后者触发止损出局)。

这是 strategy_return **不冗余**的根本理由:它是三 label 中唯一能区分「路径顺序」的。任何用 mfr 或 directional 做选股评估的方案,都看不到这层信息。

### 1.5 诚实声明

`strategy_return` 仍是**参数化模型**,不是「真实利润」。跟踪止盈偏乐观(假设你能识别峰值并追踪,实盘会被来回打耳光);静态止损偏悲观(假设恰好在线上成交,实盘有滑点/缺口)。但它比 mfr 的「max high」幻想接近现实一个量级,且它是三 label 中唯一含路径信息的。

## 2. 它评估的是「选股 + 交易」联合体的利润,不是纯选股

### 2.1 用户的端到端类比,以及本 label 在其中的角色

用户类比:「端到端训练一个由两个模型组成的神经网络,输出是利润。」

把它拆开:

- `M_s`(选股模型)= pattern / dag。提供**进场时机**(买点窗)。
- `M_t`(交易模型)= 退出规则。本 label 里 `M_t` 是**固定规则**(静态止损 + 跟踪止盈,参数手设),不是学来的。
- `loss`(损失/奖励)= `-strategy_return`(利润)。

那么 `strategy_return` 在这个类比里扮演的是**联合系统的 loss / reward 信号**——它度量的是 `M_s` 与 `M_t` **配对后**的输出利润。这正是「端到端」三个字的含义:不分别评估两个模型,只看拼起来的最终盈亏。

### 2.2 关键:这是「半联合」(M_t 固定,非学习)

把 `M_t` 设成固定规则,意味着这个 label 回答的是一个非常具体的问题:

> 「**当**选股 pattern 与这条特定退出规则(8/20/10)配对交易时,利润是多少?」

而不是:

> 「选股 pattern 本身好不好?」

因为 `M_t` 固定,**优化 `M_s` 去最大化 `strategy_return` = 让选股去适配这条固定交易规则**——这正是 feedback §0 警告的「耦合」:分数变动时分不清是 pattern 该改、还是交易参数该改。

### 2.3 为什么不能当选股尺子:方向准确率相同的两个 pattern,sim 可差很多

设想两个 pattern,方向预测准确率都是 50%:

- pattern A 命中的是**平滑趋势股**——价格稳步上行,跟踪止盈能贴着峰值吃完大段涨幅,止损很少被触。`strategy_return` 很高。
- pattern B 命中的是**尖刺型股票**——价格频繁跳空/插针,止损常在真正启动前被打掉(甚至打在最低点),少数赢家又因回撤 `trailing` 提前下车。`strategy_return` 很低甚至为负。

两者的**选股方向能力相同**,但 `strategy_return` 天差地别——差额完全来自「路径可交易性」,那是交易层的事,不是选股层。所以 `strategy_return` 的数值里**混入了交易规则对路径的敏感度**,无法用来单独度量选股。

### 2.4 连「span 取均值」本身都含交易假设

plan 的设计是对买点窗内每个进场日取均值——这隐含一条交易假设:「我在窗内随机择日进场」。这是对「不确定哪天进场」的交易层建模,不是选股属性。又一个它属于联合体而非纯选股的理由。

## 3. 与选股评估的解耦边界

### 3.1 两个 label 分管决策栈的两层

把「从信号到钱」拆成两层决策:

| 层 | 问题 | 评估者 |
|---|---|---|
| Layer 1 · 选股纯度 | pattern 指出的方向,是真信号还是波动率噪声? | **directional**(视角1,对称) |
| Layer 2 · 下游变现 | 按纪律 X 交易这个 pattern,能赚/亏多少? | **strategy_return**(视角2,不对称) |

`strategy_return` 处于 Layer 1 **下游**:它 presuppose 了一个交易纪律,然后把 pattern 喂进去看产出。它不能反过来度量 Layer 1——因为它的不对称结构会**掩盖**选股缺陷(见 §6.3)。

### 3.2 边界一句话

> `strategy_return` 下游于「选股 × 一个特定交易规则」。把它当选股尺子 = 把那条交易规则焊进 pattern 的定义 = 耦合。这正是 feedback §0 把交易期望值移出自动 score 的同一理由。

### 3.3 「信息」vs「目标」——同一种耦合,人工场景下的出路

feedback §0 否决的是「把交易参数塞进**自动优化**的 score」——因为优化器会把 pattern 往耦合方向拉,且分数下降时归因模糊。

但当前是 **web UI 人工分析**工作流,人类是优化器。人类可以做一件自动优化器做不到的事:**把 `strategy_return` 当「信息」而非「目标」**。

- 当**信息**:「这个 match 如果按我的纪律交易,会变成 −8%」——这是对决策有用的**反事实投影**,人类用它理解局面,不拿它给 pattern 打分。
- 当**目标**:「我要挑 `strategy_return` 高的 pattern、淘汰低的」——这就**隐式**把 sim 当了选股优化目标,等于把交易规则焊进选股,耦合。**不正当。**

解耦的纪律因此是:**用 `strategy_return` 理解「若交易会怎样」,不用它选「哪个 pattern 更好」**。后者交给 directional。

### 3.4 UI 交互不变式(给 decoupling 的可操作定义)

解耦在 UI 层的可操作定义,我同意 decoupling 的裁定:

- **参数化形式**:`stop_loss_pct` / `take_profit_pct` / `trailing_pct`(百分点 float,API/前端/配置传百分点,`serialize` 入口 `/100` 转小数)。
- **不变式**:改这三个参数**只能联动 `strategy_return` 一个 label**,绝不能带动 `directional` 或 mfr(后两者根本不消费这些参数)。这条不变式在实现上几乎免费——`match_strategy_return` 是这三个参数的唯一消费者,`match_forward_returns` 不接它们。
- **无「训练端」**:payoff 是「评估端」(读利润),人工场景**没有反向自动调选股参数的「训练端」**——选股改进由人看两 label 对比手动完成。绝不把 payoff 接成自动优化目标(否则撞 feedback §0 红线)。

## 4. 在 web UI 人工分析中的正当用途

用户看 K 线、找规律时,`strategy_return` 帮他回答三类**与选股打分无关**的问题:

### 4.1 用途一:对 mfr 的现实主义校准(反幻想砝码)

mfr 是路径无关的乐观上界。XAGE 那种「40 天内盘中摸过 +1.3% 峰值」被 mfr 报成 +1.3%,但实盘你根本拿不到那个峰值(进去就套,止损打穿,真实 −8% 起步)。

`strategy_return` 摆在 mfr 旁边,作用是**砝码**:每当 mfr 报一个诱人的正数,sim 提醒你「按纪律交易的话,这个数其实可能是负的」。它不替代 mfr(mfr 作为乐观上界有其用),但**抵消 mfr 的系统性乐观偏置**。

### 4.2 用途二:用户个人风险偏好下的损益投影(给自己交易用)

用户有自己的交易纪律(比如「我永远用 8% 止损」)。`strategy_return` 直接告诉他:「**按你自己的纪律**,这个命中会变成 −8% / +17%」。这是**可操作的、给用户自己交易决策用的**数字——不是给 pattern 打分,是给「我是否愿意真金白银按这个信号下单」做参考。

这与「选股评估」彻底解耦:它服务的是用户的**下游交易决策**,不是 pattern 的质量评定。

### 4.3 用途三:命中路径的「性格诊断」(mfr 与 sim 的 gap)

同一个 pattern 的多个 match,看 `mfr − strategy_return` 的**缺口**:

- **gap 小**(mfr ≈ sim):路径平滑、跟踪止盈能吃下大部分涨幅 → 「趋势型」match。
- **gap 大**(mfr 高、sim 低甚至负):路径尖刺/插针,峰值摸到但抓不住、止损先被打 → 「尖刺型」match,实盘难做。

这帮用户**理解命中的性格分布**——pattern 命中的是干净趋势还是暴躁插针?这是对命中集特征的理解,不是对 pattern 方向能力的打分。

### 4.4 不正当用途(明确排除)

用 `strategy_return` 给 pattern 排名、挑「盈利 pattern」淘汰「亏损 pattern」——这把 sim 当了选股目标,隐式耦合(§3.3)。一旦这么做,你在用「未来利润」反选 pattern,既是循环论证又是前瞻偏差(§5)。

## 5. 参数性质与前瞻偏差警告

### 5.1 参数是「用户风险偏好声明」,默认 8/20/10

`stop_loss_pct` / `take_profit_pct` / `trailing_pct` 应被定义为**用户对自己的交易纪律的外生声明**——「我就是这样交易的」,在**看数据之前**就定好。默认值 8/20/10 是一个温和的波段交易风险姿态,可整体替换(比如用户更保守想用 5/15/8),但**一旦选定就当常数用**。

### 5.2 红线:严禁扫参选优(前瞻偏差)

> **一句话(skeptic 精化,建议进 final_report 原话)**:红线 =「**参数选择程序不得在样本上对 strategy_return 做 argmax**」。判定看**程序**不看**值**——两组参数同值,一个从资金管理规则算出(干净),一个试几组 label 选最高(污染),值一样、性质不同。

这是用户明确点名要我警告的事,也是本 label 最大的陷阱。

**扫参** = 尝试多组参数组合(如 SL ∈ {3,5,8,12}% × TP ∈ {15,20,30}% × trailing ∈ {5,10,15}%),挑 `strategy_return` 最高的那组。

这是**用 label(未来收益)去选参数,再用同一 label 报利润**——纯粹的循环 + 前瞻偏差:

1. 你在用**未来信息**(各 match 的未来价格路径)选出「在这段历史上表现最好的参数」;
2. 然后宣称「pattern 配这组参数能赚 X%」——但 X% 是你**用未来选出来的**,不是样本外的。

这与「用 label 反选特征」是同一类污染,只是污染源从 pattern 变成了交易参数。结论:在历史数据上调出来的「最优交易参数」**必然过拟合**,样本外一定坍塌。

### 5.3 连「事后观察」都污染(保守防御,代价写明)

甚至连「我发现 8% 止损比 5% 好,所以改用 8%」这种**基于扫描结果的**参数调整,都已引入未来信息——因为「8% 比 5% 好」这个判断本身就是用未来收益算出来的。一旦你让数据参与参数选择,就回不去了。

**为什么这么保守(skeptic 给的理由)**:实操里「人看了灵敏度表后心里被 argmax 吸引」**不可观测、不可审计**——无法证明你没受最高那行影响。所以 §5.3 是对这种不可审计性的防御。**代价**:参数必须从数据之外(资金管理规则、心理承受度、别的市场经验)定,不能从「哪个赚钱」定。这条代价要写进 final_report。

**灵敏度分析的合法用法**:允许报告参数敏感性表(§1.3 那种,诊断信息、看稳健性区间),**禁的是「据敏感性表选 argmax 当纪律」**。表本身无害,有害的是「看完表后据结果选参」这个程序。

唯一干净的路径:**参数来自数据之外的先验**(个人风险偏好、资金管理规则、交易习惯),定死,不复用数据校准。

### 5.4 对 UI 设计的牵连(给 leader / 实现侧的建议)

原 plan 在 `ScanConfigDialog` 把三个参数做成**可编辑输入框**(默认折叠)。这本身没错,但**可编辑输入框在语义上诱导扫参**——用户会忍不住「试试 5% 会怎样、试试 12% 会怎样」。

建议(供 final_report 裁定):

- 要么加一行 UI 警告:「参数应为你的固定交易纪律,勿据结果反调」;
- 要么把参数定位成「设一次、少改动」的偏好设置(类比 `label_horizon` 也是设一次的全局量);
- **绝不**提供「批量扫参对比」之类的便捷入口——那是把前瞻偏差做成功能。

### 5.5 固定参数下,sim 的正确解读

即便参数固定、零扫参,`strategy_return` 的正确解读仍是:「**在该风险偏好下的变现投影**」,而**不是**「最优交易利润」。因为退出规则本身(静态止损 + 跟踪止盈)是众多可能规则之一,换一套规则(如时间止损、波动率止损)数字会变。它是**一种**变现,不是**最优**变现。

## 6. 与方向性 label(directional)的共存关系

### 6.1 表面矛盾:对称 vs 不对称

- `directional`:正负**对称**——平等考虑涨跌,目的是检验「方向预测是否成立,剔除波动率混淆」。
- `strategy_return`:正负**不对称**——下行截断、上行追逐,目的是模拟「真实交易纪律下的变现」。

一个对称、一个不对称,数学上确实冲突,**不能合并**。

### 6.2 它们回答的是不同问题(所以可以共存)

| 问题 | 谁回答 |
|---|---|
| pattern 指出的方向,是真信号还是波动率噪声? | directional(选股纯度) |
| 按我的交易纪律,这个 pattern 能赚/亏多少? | strategy_return(联合利润) |

这是决策栈的两层(§3.1)。两个 label 各管一层,**互不替代、互不矛盾**——矛盾只在你想用同一个数同时回答两个问题时才出现,而那本就不该做。

### 6.3 关键论证:为什么 strategy_return 不能替代 directional(不对称会掩盖选股缺陷)

设想一个 pattern,方向预测准确率只有 **30%**(70% 的进场后价格下跌)。直觉上这是很差的选股。但用 `strategy_return` 看:

- 70% 的输家:止损把每次亏损封顶在 −8%,总贡献 ≈ 70% × (−8%) = −5.6%。
- 30% 的赢家:只要平均能追踪止盈吃到 +20% 以上,30% × 20% = +6%,就**足以覆盖损失**,整体 `strategy_return` 为正。

也就是说,**一个方向严重错误(30% 准确率)的 pattern,`strategy_return` 仍可能显示盈利**——因为止损封顶了高频小亏、跟踪止盈吃到了低频大赚。这就是「不对称掩盖选股缺陷」:sim 给你**虚假安慰**(「盈利了嘛」),而 directional 会如实告诉你「方向只有 30% 对,这是波动率-driven 的,不是真信号」。

结论:`directional` 是不可替代的选股纯度测试;`strategy_return` 不能取代它。

**XAGE 实测佐证**:tb_208_213 的真实位移是 −77%(directional),但 strategy_return 只报 −8%(止损封顶)。若用户只看 payoff,会觉得「不过是个小亏」,**完全意识不到 pattern 选中的是一个暴跌 77% 的灾难**——payoff 把选股缺陷(方向严重错误)掩盖在止损的保护伞下。directional 揭露的 −77% 才是选股该负责的真相。这就是 §6.3 论证的实证落地。

### 6.4 反过来,directional 能不能替代 strategy_return?

也不能。directional 只告诉你「方向对不对」,不告诉你「按你的纪律变现能拿多少钱」——后者是用户做下单决策时真正关心的。一个 directional 很好(方向 70% 对)的 pattern,如果命中的全是尖刺型、止损总被打在最低点,实盘照样亏钱。directional 看不到这层,只有 `strategy_return` 看得到。

### 6.5 共存结论:两个 label 正交,不是串联(撤回「必要非充分」旧说)

> **勘误**:本节早先版本写「directional 是 strategy_return 的**必要**非充分条件——方向不对一定不赚钱」。skeptic 与 directional 各自独立指出这与 §6.3 直接矛盾:§6.3 已证「方向准确率只有 30% 的 pattern 仍可能 sim 为正」(止损封顶 70% 小亏、尾部红利覆盖)。若方向 mostly 错也能盈利,「方向」就不是「必要」条件。**我认错,撤回「必要非充分」表述**,改用 directional 提出的 **2×2 正交分类**。

directional 与 strategy_return 是**两个几乎独立的信息维度**,彼此**无蕴含关系**(谁也不推出谁):

|  | **实战好(sim 正)** | **实战差(sim 负)** |
|---|---|---|
| **方向好(directional 正)** | **真 alpha**——方向能力变现,可信 | **路径不可交易**——方向对但尖刺/插针,止损总被打,需改 pattern 可交易性 |
| **方向差(directional 负)** | **警报:波动红利/虚假 alpha**——sim 正是 σ 尾部红利非方向能力,警惕 | **garbage**——方向错且不可交易,弃 |

四个格子都有意义,**正是「方向差+实战好」这一格让 directional 不可被替代**——只有它能拆穿 payoff 用交易技巧掩盖的选股方向缺陷(§6.3)。同理「方向好+实战差」让 payoff 不可被替代——只有它能看到「方向对但路径不可交易」的实盘风险。

**关系是「既非必要也非充分」,别留任何「必要」残余**(skeptic 坚持的硬点):
- **非必要**:§6.3 已证——方向准确率 30% 仍能 sim 为正(波动率红利)。所以「directional 正」不是「sim 正」的必要条件。
- **非充分**:§6.4 已证——方向对但路径不可交易,sim 仍可能为负。所以「directional 正」也不是「sim 正」的充分条件。
- 两个 label 的取值**互不蕴含**,2×2 四格每一格都真实可达。

**decoupling 的语义调和(救回一句真话)**:日常说的「方向不对一定不赚钱」之所以仍像对的,是因为「赚」歧义。拆开:
- 「赚」= **payoff 正数** → 方向差也可能(波动率红利,§6.3)。**不是**一定不赚。
- 「赚」= **真实 alpha 利润** → 方向差则**不可能**(正的 payoff 只是红利、是警报,不是真能稳定变现的方向能力)。**这句成立**。

所以严谨表述:**在 label 取值层,directional 与 sim 既非必要也非充分(正交);在语义层,「真实 alpha」确实要求方向对,但 payoff 的正数并不等于真实 alpha**——这正是 payoff 不能当选股尺子的又一证明(它的「正」可能是红利不是 alpha)。

两个 label **都需要**,且**正交互补**:directional 回答「方向对不对」(诊断),strategy_return 回答「能不能变现」(实战)。**单独看任一都盲**——只看 directional 不知道路径可不可交易,只看 strategy_return 不知道方向能力(被技巧掩盖)。这正是用户「可以做两个版本的 label」的正当性所在。

### 6.6 回答 directional:不应把端点收益并入 payoff 作「退化特例」

directional 问:端点收益 `close[t+N]/close[t]-1` 是否就是 strategy_return「到期平仓」分支的退化特例(= 无止损止盈的傻持)?若是,directional 是否该并入 payoff 作为一个「被动持有 baseline」档?

**技术上确实成立**:strategy_return 的「全程未触发 → 到期 `close[t+N]` 平仓」分支,其收益恰好等于端点收益。所以端点收益 = strategy_return 在「无任何线被触及」时的取值。

**但 directional 不应并入 payoff,理由有三:**

1. **「退化特例」关系是偶发的、非本质的**。它只在我当前这条特定 simulation 结构(有到期平仓分支)下成立;若我把 simulation 改成「无到期、永远跟踪」,端点收益就不再是任何分支。把 directional 的定义挂在某条交易模型的内部结构上,是本末倒置。

2. **XAGE 实测反证**:该 match 上 directional=−77%、payoff=−8%,**两者天差地别**。原因是每个进场日都早早触发了止损,payoff 根本没走到「到期平仓」分支。也就是说,「端点收益 = payoff 退化特例」只在罕见情况(无任何线触及)下才数值相等;绝大多数有干预的 match 上二者完全不同。把 directional 当 payoff 的子档,会丢掉 −77% 这个选股关键信息。

3. **directional 的本质属性 = 与交易规则解耦**,并入 payoff 会摧毁这一属性。directional 之所以是选股纯度尺子,正因为它**不依赖任何交易参数**;而 payoff 本质上依赖交易参数(§5)。把两者合并,等于让选股尺子沾上交易参数,这正是 feedback §0 警告的耦合。directional 必须保持「交易规则无关」的独立身份。

结论:directional 独立存在,不并入 payoff。二者是「交易规则无关(选股纯度)」与「交易规则耦合(变现)」的对照,不是父子档。

### 6.7 payoff 单独会产生「虚假 alpha」——三层规避(skeptic 修正:共读必要但不充分)

decoupling 与 skeptic 共同警示:payoff 的非对称(止损截断跌、逐利追涨)单独会造**虚假 alpha**(波动率红利,非方向 alpha)。高波动股的尖刺被跟踪止盈吃、回撤被止损截,波动率本身就能推高 payoff。这是 §1.3 表里 payoff 的「σ→期望」标「有偏」的原因,也是 feedback g 项「score 首先是波动率读数」在**交易层的翻版**——**strategy_return 同样首先是命中集波动率的读数**(skeptic 论点 B,论证链从 score 一路连到 sim)。

**我旧版 §6.7 写「directional 是解药」——过强,skeptic 修正正确**:directional(端点收益)只在**集合期望**上对 σ 中性,在**单 match 实现值**上**不**中性——方差随 σ 放大,排序顶部仍是高波动股。所以 directional **不能完全识破** payoff 的虚假 alpha:per-match 层两个 label 都带 σ 噪声,共读也未必看穿。「与 directional 共读」**必要但不充分**。

**完整规避 = 三层(skeptic 处方,我采纳)**:

1. **per-match 共读(directional + sim)**:必要,识别肉眼可见的背离(sim 正但 directional 负 → 警报)。但不充分(两 label per-match 都有 σ 噪声)。
2. **集合级统计闸(选股评估层,独立于任一 label)**:这才是识破虚假 alpha 的主力——
   - 命中集波动率倍数(已测 1.83–2.13× 全宇宙);
   - **控 σ 后 sim 的条件百分位**:类比「bo_only +72% lift 控 σ 后归零」——若 sim 的正期望控 σ 后归零,标红警告「这是波动率红利,非 alpha」;
   - 首次穿越方向检验(feedback c 项)。
   - 这三项属于选股评估层(检验「pattern 是不是在 surf 波动率」),不属于 payoff 内部——payoff 自己不加波动率惩罚项(那会把选股评估反向塞进交易层 = 再次耦合,feedback §0 同病方向反过来)。payoff 的职责是诚实报告联合体利润(含红利是它的诚实),识破红利靠选股评估层。
3. **UI 标注 sim 的波动率暴露**:在 sim 面板标出该命中集的波动率倍数 / 控 σ 后是否归零,让用户一眼看到「这个 sim 正是红利还是 alpha」。

> **归属裁定**:第 1 层(per-match 共读)是 web UI 人工分析自带;第 2 层(集合级统计闸)复用 feedback 已建的体检口径,是**选股评估层**的工具,不进 payoff;第 3 层(UI 标注)是 payoff 面板的诚实披露。三层各司其职,payoff 不越界去当选股度量。

## 7. 对 final_report 的建议(payoff 立场,已吸收三 teammate 共识)

1. **保留两个 label,且关系是正交非串联**:directional(对称,选股纯度)+ strategy_return(不对称,联合变现)是两个独立信息维度(§6.5 的 2×2),不是「directional 是 strategy_return 的前提」。final_report 不要写「串联/必要条件」,要写「正交互补,单独看任一都盲」。
2. **重新定位 strategy_return:独立交易层 readout,视觉隔离(三 teammate 共识)**。原 plan 把它当「与 mfr 同级的 label」**要改**——同级会诱导用户拿 sim 排名选股,等于 feedback §0 的错误从自动 score 搬到人工 UI(skeptic ★ + decoupling 裁定)。应作独立面板,明确标注「交易联合利润·非选股评估」。
3. **UI 闸门(防 §0 错误位移到人工排序,decoupling 裁定)**:默认排序键不是 sim;sim 独立面板;**无「按 sim 综合打分选 pattern」入口**;sim 参数(stop_loss_pct/take_profit_pct/trailing_pct)只联动 sim、不影响 directional/mfr(交互不变式 §3.4)。
4. **参数纪律(全队红线,skeptic 确认原样吸收)**:三参数为外生风险偏好声明,默认 8/20/10;**严禁扫参选优**(前瞻偏差);UI 加反扫参警告;报告 sim 值时必须标清先验(§1.3 披露);不提供批量扫参入口。
5. **XAGE 作为 canonical example**:用它说明三个 label 的分工——mfr +1.33%(fantasy)→ directional −77%(选股方向真相)→ strategy_return −8%(8/20/10 先验下的变现投影)。讲清两点:三 label 各自揭示什么;以及 payoff 的 −8% 是先验投影而非客观读数(§1.3 扫描表)。
6. **payoff 虚假 alpha 的规避 = 三层,不是「靠 directional 共读」一句**(§6.7,skeptic 修正):(a) per-match 共读(directional+sim)必要但不充分(directional 自己 per-match 也带 σ 噪声);(b) **集合级统计闸**(命中集波动率倍数 / 控 σ 后 sim 条件百分位 / 首次穿越检验)——这才是识破红利的主力,属选股评估层、复用 feedback 体检口径,不进 payoff 内部;(c) UI 标注 sim 的波动率暴露。payoff 不加波动率惩罚项(会再次耦合)。
7. **v1 范围 + 诚实成本(skeptic 战略疑虑,我采纳)**:payoff v1 定位为「**mfr 现实主义砝码 + 个人风险偏好投影**」(§4.1/§4.2),**不追求独立决策列**、必须配 directional 共读。诚实成本:web UI 里用户逐 match 看 K 线时**路径肉眼已可见**(K 线就是路径),sim 把路径压成一个数、损失恰是肉眼能看的细节——所以 sim 的「路径/顺序独有信息」在 UI 场景的增量 < 在无 K 线的自动 score 场景;但虚假 alpha / 诱导当尺子 / 参数敏感这些**风险并不因有 K 线而减少**。结论:sim 值得做(用户要解耦、它让「交易层」具体化、给 mfr 砝码),但 v1 克制定位、强约束共读,别高估其 UI 增量。
