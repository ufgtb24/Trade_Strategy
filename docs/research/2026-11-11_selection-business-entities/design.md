## 0. 结论

1. **能被选中的只有八种东西**：一族 hit、买点日（hits 行上的 ▼）、一次 hit、event、node、反馈、样本、框（entities 第 5 节；issue 也是实体，但图上没有它的位置，选中一条反馈时卡片里写它）。event 族、band 同一格里并着的几个、「用到某个 event 的全部 hit」、反馈收进来的那批、这张图上的全部样本都不是东西，只当走动范围或关系；点到它们所在的地方时实际选中什么，见 3.2。
2. **同一天叠着的几次 hit，整体有意义——它就是那天的买点日**：point 反馈、反馈状态、样本对照、调参计数认的都是它，里面的每一次只差内部切法（entities 4.2、sk C/D）。所以用户提议的前提不成立，改成：**点 ▼（或它那一列的格）选中这一天整体**，↓ 进去才落第 1 次；已经停在某一次上时按 ← / → 换天，落在同一种切法的那一次（现状本来就是这样，不是落第 1 次，sk 现场证实）。
3. **两组键，同一个判断**（2026-11-12 改，`切换规律.md`）：← / → 跨天（竖线会动），↑ / ↓ 留在同一天（竖线不动）。每根轴只看两个数——选中的东西在这根轴上「里面装着几个」「同一层还有没有别的」：里面两个以上就进去；否则本层有别的就换到旁边，落对应的那个；两样都没有、里面只有一个，就进那一个；都没有不响应。Esc 往上退一层，退到头再按才清空。选中物的种类只由点的东西决定。「还没选（`day –/n`）」这个状态取消，它其实是选中了外面那一层。
4. **选中 band 上的一个 event 后**（2026-11-12 改）：用到它的买点日有两个以上，← / → 落进去（点 step 后按 → 就是上一轮用户要的 1/11、2/11，Esc 一层层退回 step）；只有一个或没有，← / → 沿这条 band 换到旁边那格，落最像的那个（优先同一个起点）——new_plat 逐天长一格的走法保住了。这是通用规律套出来的结果，不是给 event 单设的规矩；原来「三条路交用户拍板」的经过留在第 12 节。
5. **显示栏按维度拆开、每个维度标准化**（用户第三次追加）：先把「选中一个东西时想知道的」梳成 29 个维度（5.1），再给要显示的定死规格——名字、固定位置、统一写法、不适用时一律灰色 `—` 占格、取值来源（5.2），并填出八种东西在 CRNC 现场的实际文字（5.3）。**推荐形态 C「维度格栅 + 选中卡」**：副图上方那一行分九格，种类、node、日期、叫法、区别、属于、两个键槽、Esc，位置永远不动；「买得对不对」与细节进右侧栏 `selection` 页顶上的卡，十一行、行序固定。上一稿推荐的 B（标签贴着竖线走）因为位置跟着竖线挪、违背「同一维度同一位置」，退为备选。另修一个现有毛病：走出视窗时图不跟着平移（sk `sk_06`）。
6. **Shift+C 一下复制选中的那一个**，不连按；同一样东西不论从哪条路选中都复制同一行，拼法对所有种类相同：栏的身份五格（种类、node、日期、叫法、区别）从左读到右，加卡的 `buys`、`hits` 两行，加编号。现有 14 种行留 9 种，砍 5 种（第 7 节）。
7. 六条方向已于 2026-11-12 全部拍板（见文首「拍板结果」）；第 1 条推翻了 spec 5.8 当天定的「▼ 点下去总是落定一次」，实施前要先改规格。

## 1. 实体与它们的四件事

「属于」写显示栏里它挂在谁下面，也就是 **Esc 会退到哪**——是你从哪一层走进来的，不一定是结构上唯一的上级（一次 hit 结构上属于一族，但从一条反馈、一个 event 走进来时挂在它下面；结构上的族写进卡片）。

| 实体 | 选中的是 | 属于（Esc 退到） | 装着 / 关联 | ← / → | ↑ / ↓ |
|---|---|---|---|---|---|
| **一族 hit** | 起点相同的那一串 hit | 无（Esc 清空） | 买点日 n 个、hit m 次 | 买点日两个以上：落进去，离竖线最近的那个；只有一个：换到旁边一族（图上只有这一族时进那一天） | 不响应 |
| **买点日** | 这只股票 app 买的一天（▼） | 走进来的那一层：一族（默认）、一条反馈或一个 event | 这天那个 ▼ 上的几次 hit | 那一层的上 / 下一个买点日，选中的仍是「那一天」 | 进去，落第 1 次（从 event 走进来时用到它的那次排第一；只有一次时两层合并，不响应） |
| **一次 hit**（停在它的某个买点日上） | 这一次，连同竖线所在的那个买点日 | 那个买点日（再往上是一族、反馈或 event）；从样本 / 框进来时是样本 / 框 | 它绑定的 event（band 上粗框） | 那一层的上 / 下一个买点日，落同一种切法的那次；在样本里换样本、落配对那次；在框里换到旁边的框、落在场的那次（2026-11-12 改） | 这天（样本日、框终点）的几次之间换 |
| **event** | band 上的一个 event | 它的 node；从样本 diagnose 的卡片点进来时是那个样本 | 用到它的 hit 与它们的买点日（卡的 `buys`、`hits` 写首尾与个数）；子 event（悬停） | 用到它的买点日两个以上：落进去，离竖线最近的那个；一个或没有：沿这条 band 换到旁边那格，落最像的那个（优先同起点；band 上只有它一个且牵出一天时进那一天） | 这条 band 上同一天结束的几个之间换 |
| **node** | 一条 band（点轨名） | 无 | 这条 band 上画出来的 event | 落进去：离竖线最近的那个 event | 不响应 |
| **反馈** | 一条反馈 | 无（所属 issue 写在卡片里，不导航） | 它收进来的买点日与 hit（和记号变朱红同一口径） | 收进来的买点日两个以上：落进去，离竖线最近的那个；只有一个：换到旁边一条反馈 | 不响应 |
| **样本** | 一个样本 | 无 | 样本日在场的 hit | 上 / 下一个样本（这张图上当前 pattern 的） | 进去，落在场的第 1 次（配对那次排第一） |
| **框** | 一个框 | 无（是成员框时卡片写属于哪个样本） | 框终点在场的 hit | 换到旁边的框（2026-11-12 改；原为不响应） | 进去，落在场的第 1 次 |

当前日（什么都没选）不是实体，Shift+C 照旧复制它兜底。

## 2. 选中模型

### 2.1 层与键

- hits 行这一侧是 **一族 ⊃ 买点日 ⊃ 一次 hit**。一次 hit 买好几天时（bottom_burst、bb_v1，sk 记 DDC 每次都买好几天）它出现在几个买点日下面，选中它时竖线落在其中一天——这就是用户说的「hit 买点」：一次 hit 在某一天的买点。
- 一条反馈、一个 event 也可以当最外层：**反馈 ⊃ 它收进来的买点日 ⊃ 一次 hit**；**event ⊃ 用到它的买点日 ⊃ 一次 hit**。
- band 这一侧是 **node ⊃ event**。
- 用户这一侧是 **样本 / 框 → 在场的 hit**。

两组键，任何时候都是同一句话。分界只看「里面装的东西怎么排」：沿日子排开的，用 ← / → 进；叠在同一天的，用 ↑ / ↓ 进。

- **← / →：跨天，竖线会动（2026-11-12 改，`切换规律.md`）。** 只看两个数：选中的东西里面装着几个沿日子排开的、同一层还有没有别的。**里面两个以上 → 进去**（一族、反馈、event 装着买点日，node 装着 event）：往右按找竖线右边最近的那一个，往左按找左边最近的，竖线那天本身就有就先落它；**只在落进去这一下**，那个方向没有就取另一边最近的（step 11-21 的 11 个买点日全在它右边，按 ← 也落 11-27）。**否则同一层有别的 → 换到旁边那个，落对应的**：买点日换买点日、一次 hit 换到旁边那天最像的那次（同一种切法）、样本换样本、框换框；只牵出一个或零个买点日的 event 换到这条 band 上旁边那格里最像的那个（优先同一个起点），只有一个买点日的族、反馈换到旁边一族、一条反馈。**两样都没有、里面只有一个 → 进那一个**（band 上只有一个 event 的 node）。走到头就停，不绕回。「同一层」= `in` 最后一节里面，`in` 为空就是整张图上的同种东西；选着叠在某一天里的一个时，跨天的同一层是那一天所在的那一串。
- **↑ / ↓：竖线不动，在同一天里进去或换。** 选中的东西里面装着叠在同一天的东西时——买点日装着这天的几次 hit，样本、框装着那天在场的几次——↑ / ↓ 进去（↓ 落第 1 次，↑ 落最后一次；样本、框当天只有一次在场时，同一天没有别的可换，照规律第三行进那一次）；在一次 hit 上，在这天的几次之间换；在 event 上，在这条 band 同一天结束的几个之间换。
- **规律自带三条后果**（2026-11-12 改）：一个键是进去还是换旁边由数据定，可预判靠键槽在按之前写明 `into …` 还是 `… k/n`（↑ / ↓ 已给了同一天那根轴、Enter 是反馈面板的保存，不另加「进去」键）；只装着一个的东西，从它到那一个没有键（本层唯一时除外）；换旁边时碰到里面有得挑的，下一下就被带进去，要越过它用鼠标点。一次 hit 绑定的 event 不算「装着」：它们散在不同的 band 上，不是一行里的一串。
- **Esc：往上退一层**，退到最外层后再按才清空。已有的几件照旧先退：反馈面板 → 亮着的工具 → 进行到一半的 Shift 配对 → 往上退一层 → 清空。点空白照旧一下清空。从 step 进去的那次 hit 按 Esc：那一天 → step → step 那条 node → 清空。

**点决定从哪种东西开始，按键只沿它的上下左右移动**：点 ▼ 或它那一列的格 → 买点日；点 hits 行底线 → 一族；点 band 上的东西 → event；点轨名 → node；点反馈记号 → 反馈；点 ▲ / 框 → 样本 / 框。之后按键只做三件事——横着换同一种的另一个、往下落进它装着的、往上退回装着它的——不会跳到不相干的种类。

**点了之后竖线落在哪**：买点日、一次 hit → 那一天；event → 它的终点（new_plat 起于 11-22 那格就是 11-26，sk 走查 (b)）；样本 → 样本日；框 → 框终点；一族、反馈、node → 不动。

**走出视窗时**：← / →、↑ / ↓、Esc 落到的东西在当前视窗外时，图平移到让它进来、两边留几根 K 线（会话默认）。现在走出视窗竖线就跑出画面、提示条照写 `day 7/11`（sk `sk_06`：视窗到 12-03，竖线走到 12-16）——**这是现有毛病，不是新设计引入的**。推荐的形态 C 栏位置固定，不会跟着出屏，但图上看不到选中物照样读不了，所以一并修；若选备选形态 B，它的标签贴着竖线，更必须修。用户自己平移、缩放把选中物拖出视窗时不追回（B 的标签此时贴在条的左 / 右边缘，带箭头与日期）。**走动引起的平移不关反馈面板**（sk D20）：现在主图、副图一发出视窗变化的事件就关面板（`path2_web_ui/src/components/KlineChart.vue` 约 1382 行），程序平移也会发这个事件；照此实施，点族底线开 family 面板后按 → 走出视窗，面板就被关掉、写了一半的 note 丢掉，和 6.13「当前那次还属于这一族时留着」冲突。所以按键走动带出的平移不算 6.13 说的「平移」，面板照 6.13 的去留规矩处理；留下时浮在原来的屏幕位置不动（会话默认，待验证）。用户自己拖、缩放仍照旧关面板。

### 2.2 落点

- 落进买点日（点 ▼、从一族 / 反馈 / event 按 ← / →、从一次 hit 按 Esc）：选中这一天整体，不替用户挑其中哪一次。
- 从买点日 ↓ 进去：落那个 ▼ 上族内顺序的第 1 次；这一天是从 event 走进来的，用到这个 event 的那次排第一；从样本、框进去，配对的那次排第一（和 diagnose 的 hits 组同一顺序）。
- 停在一次 hit 上按 ← / → 换天：落那天和当前这次**同一种切法**的那一次（两次 hit 绑定的 event 重合最多的，平手取靠前）——现在 `landIndex` 的规则，沿用。从 step 走进来时，这条规则让你一路停在用到这一根阶跃的那几次上。
- 点 band 上并着几个成员的一格：现在选中的那次 hit 用到其中哪个就选哪个，否则第 1 个。
- 再点同一个东西不换现在选中的（照旧）。

**对用户提议的回应**：用户说「若同日堆叠整体无意义，左右切到堆叠日就选中第 1 个」。堆叠整体就是买点日，有意义，所以分两层：在「天」这一层走，停在整天（复制、反馈、显示栏说的都是「这天买得对不对」，不会被读成只针对某一种切法）；进到「次」这一层才落第 1 次；在「次」这一层走，沿同一种切法（band 上的粗框不会每走一步就在两种切法之间跳）。用户以为现状是「落第 1 次」，其实现状就是沿切法（sk `sk_04`：从 11-27 第 2 次按 →，落 11-29 第 2 次）；若用户更看重好预测，「次这一层也一律落第 1 次」是第 10 节第 2 条的备选。

### 2.3 一次 hit 买好几天、两族同一天买

- 一次 hit 买好几天：停在这次 hit 上按 →，到下一个买点日时和它最像的就是它自己，于是选中的还是这次 hit、竖线挪了一天。显示上靠 `in` 的末节（`buy 2024-04-09`）和卡的 `buys` 分清停在哪天，复制的那行带 `buys`（第 7 节）。
- 两族同一天都买（new_step 现有数据里没有，规格 6.13）：一个买点日、两个 ▼。点哪个 ▼ 选中的都是这一天，卡的 `hits` 写 `families ×2`；路径写点的那一族；↑ / ↓ 只走那个 ▼ 上的几次（sk 质疑 5：不串到另一族）；← / → 只在那一族的买点日上走。从 event、反馈走进来时取用到它 / 收进它的那一族。会话默认，待验证。

### 3.3 沿 band 走：只牵出一个或零个买点日的 event（2026-11-12 改）

原稿这一节是「沿 band 逐格走没有了」。按已定的通用规律，它回来了，但范围由规律给出，不专设：

- new_plat、today、plateau 的格只被同一天的 hit 用到（牵出一个买点日），里面没得挑，所以 ← / → 沿这条 band 换到下一个终点日的那格，落最像的那个（优先同一个起点）。点 new_plat 起于 11-22 那格后按 →，就是新平台逐天长一格（img26 → img19 的走法）。竖线停在这个 event 自己的终点上；用到它的那次 hit 只画细框，不算选中。
- 没进任何 hit 的 event（档位放宽才画出来，上一轮的 U10）同样沿 band 换。
- step、old_plat 这类牵出好几个买点日的 event，← / → 落进它的买点日，不沿 band 走。沿 band 换到这样一个 event 时，再按就被带进去（规律的第三条后果）。
- 沿 band 走的格数随档位变（键槽 `events k/n` 的 n 数的是当前档位下这条 band 上有 event 结束的日子）。
- 和 hit 换天「落最像的那次」是同一句：换到旁边那个日子，落对应的那个。所以不把 event 族请回来当走动范围。

没验证：别的 app 上同一条 band 混着「牵出一天」和「牵出好几天」的 event、几串起点不同的 event 终点日交错时，走起来顺不顺。

## 4. 图上怎么画

规矩：**粗框只给选中的那一个；路径上的外层用它自己的「在用」样子；和它有关的加细框。**

- 选中的：▼（买点日）、hits 格（一次 hit）、band 格（event）、记号（反馈）、▲（样本）、框、轨名描黑粗边；一族被选中时它那行底线加粗。
- 外层：一族 → 那行底线加粗；反馈 → 记号黑粗边与贯穿的竖带（现在的样子）；event → 那一格黑细框；node → 轨名细黑边；样本 → ▲ 加粗。
- 位置：外层是反馈或 event 时，它的买点日上的 ▼ 加细框（现在 `hits_using`、`feedback` 两批的细框照旧）。
- 组成：选中一次 hit 时它绑定的 event 照现在加粗；选中买点日时这天几次 hit 绑定的 event 合起来加细框（不替你挑一次）；**选中样本时配对那次 hit 绑定的 event 加细框**（现在只给配对那一格加粗框；改细框，粗框留给 ↓ 进去后选中的那次。sk 质疑 6：沿样本走时组成仍看得见，只是细框）。
- 反馈的粗边与竖带跟着路径走：反馈是选中的或是外层时画，点了无关的东西就取消（现在点了别的也一直留着）。
- app 侧栏 hits 列表（上一轮 U13，sk D22）：选中买点日时，这天的几行都标出（和现在「这一批的行一直标着」同一种标记），不画当前行黑粗边；进到某一次后，那一行画黑粗边。选中一族时这一族的行都标出；选中 event、反馈时，用到它 / 收进它的那几行标出。
- 悬停：band 格的 `day k/n`（这一格在 event 族里第几个）去掉；`hits_using: n` 改成和卡同一个写法 `hits ×n`；格里几个成员逐行写 `events j/m 区别`，j/m 数的是这条 band 上同一天结束的 event，只数 event、不按 hit 拆（修 entities 盘点第 4 条、sk E3）。hits 格与 ▼ 的悬停 `same_day: m` 改成 `hits ×m`，`in_set` 去掉（↑ / ↓ 走的永远是那个 ▼ 上的全部几次）。

## 5. 显示栏

用户第三次追加：「把显示内容拆分维度，每个维度都标准化」。本节照这句改：先列「选中一个东西时想知道的」全部维度（5.1），再给要显示的那些维度定死规格（5.2），按规格填出八种实体在 CRNC 现场的实际文字（5.3），最后用这把尺子重评形态、改推荐（5.4），逐字 mock（5.5）。

### 5.1 选中一个东西时想知道的：29 个维度与放哪

放的地方：**栏**（副图上方那一行，5.2 的九格）、**卡**（右侧栏 `selection` 页顶上的「选中」卡，5.2 的十一行）、**悬停**、**图上**（已经画在图上的，不再写成字）、**别处**（顶栏、面板页头已有）。判据：按键走动时每一步都要看的进栏；想追问时才看的进卡；只对一个格子有用的进悬停；图上已经看得见、就在选中物旁边的不重复。原料是 entities 5.2 的「关键属性 / 挂在它身上的」与 sk 第四节的候选。

|---|---|---|---|---|
| 1 | 种类 | 选中的是什么东西 | 栏 `kind` | 本次问题的核心 |

### 5.2 维度规格表

**统一写法**（所有维度共用，同一种值在任何格、任何实体下都是这个样子）：

| 值的种类 | 写法 | 例 |
|---|---|---|
| 一天 | `YYYY-MM-DD` | `2024-11-27` |
| 一样东西的起止 | `起→止`（起止同一天只写一天） | `2024-10-31→2024-11-27` |
| 一组日子的首尾 | `首…尾 ×n`（只有一天写 `那天 ×1`） | `2024-11-27…2024-12-26 ×11` |
| 第几个 / 共几个 | `k/n` | `1/11` |
| 个数 | `×n` | `×22` |
| 一样东西的「身份」（路径的每一节、配对的另一方都用它） | `kind node date name`，不适用的跳过 | `event step 2024-11-21`、`sample 2024-11-29 a pos` |
| 区别 | `node→YYYY-MM-DD`（第一处不一样的子段及其终点，现成的 first_diff） | `step→2024-11-21` |
| 键槽去向 | 写被走的那一组，用复数名词：横着或竖着换到第几个 `复数名词 k/n`；落进去 `into 复数名词 ×n` | `buys 1/11`、`hits 1/2`、`events 1/2`、`samples 1/3`、`into hits ×2` |
| 程序固定词 | 等宽、黑字、英文标识符 | `in_hit`、`matched` |
| 用户起的名字（特征名） | 正常字体、浅灰底（界面规则） | `站上新平台` |
| 适用但是空的 | `none`（黑字，是一个取值） | 没有反馈盖住这天 |

**不适用时，全表一条规则：格子照占，写一个灰色 `—`；键槽不适用时键帽也画灰。** 理由：位置固定是这次的第一要求，整格不出现会让后面的格挪位置；留空白读起来像没加载完或排版坏了；灰色按界面规则正好留给「空着 / 没选上」的状态（sk D19 也提议把没用的键帽画灰）。「不适用」（这种东西没有这一维，灰 `—`）和「适用但是空的」（这一维有、这次没有，黑字 `none`）分开写，用户看得出是「不会有」还是「这次没有」。什么都没选时九格全是灰 `—`，格子的位置照样摆着。

**栏：副图上方一行，九格，从左到右固定，每格「标签 值」**（标签是程序固定词，等宽黑字；`kind` 的值放在白底 2 像素黑边的块里、字加粗，是整条栏里最显眼的一块）：

| 格 | 维度 | 名字 | 宽（字符，含标签） | 写法 | 取值来源 |
|---|---|---|---|---|---|
| 1 | 种类 | `kind` | 18 | `hit_family` / `buy` / `hit` / `event` / `node` / `feedback` / `sample` / `box` | 当前选中的种类 |
| 2 | 对应的 node | `node` | 15 | node 名，几个用逗号连 | 这样东西对应哪个 node，一种意思四种来源：event 所在的 node；node 本身；框经 mapping 对到的 node；反馈点出问题落在的 node |
| 3 | 日期 | `date` | 28 | 一天或起止 | 一族的起点；买点日那天；hit、event、反馈、框的起止；样本日 |
| 4 | 叫法 | `name` | 17 | 样本 `字母 判断`；框、node 写特征名 | 样本字母与 judgment；框的特征名；node 对到的特征名（`⇣`） |
| 5 | 区别 | `diff` | 24 | `node→YYYY-MM-DD` | 同一天叠着 ≥2 时，它和另几个的 first_diff（`render/walk.ts` 的 stackLabelTexts） |
| 6 | 属于 | `in` | 余下（至少 20） | 身份用 ` › ` 由外到内连 | 走进来的路径（选中模型） |
| 7 | ← / → 去向 | 键帽 `←/→` | 21 | 横着走 `复数名词 k/n`（`buys`、`samples`；2026-11-12 加 `events`、`hit_families`、`feedbacks`、`boxes`）；落进去 `into 复数名词 ×n` | 路径上那一串的位置与个数 |
| 8 | ↑ / ↓ 去向 | 键帽 `↑/↓` | 22 | 竖着换 `复数名词 j/m`：`hits j/m` 或 `events j/m`；落进去 `into hits ×n` | 竖线这一天、同一种东西叠着的几个：买点日那个 ▼ 上的几次 hit；样本日 / 框终点在场的几次 hit；这条 band 同一天结束的几个 event（各是哪一组写在卡的 `hits` 行与悬停） |
| 9 | Esc | `Esc` | 7 | 键帽（不参与截断）；悬停写退到哪（`up: buy 2024-11-27` / `clear`）；没有选中物、也没有面板 / 工具 / 配对可退时键帽画灰 | 路径的上一节 |

宽度 = 值的最长写法（含标签）+ 约 2 字符余量：`→`、`×`、键帽边框、`kind` 白块的边与内边距、中文特征名都比一个等宽字宽；格自己的左右内边距另算（sk 第五稿复核实测：只按字符数定宽会把日期、键槽、`kind hit_family` 截掉几像素）。格与格之间用细竖线隔开（各 3 字符）。九格加分隔约 176 字符 + `in` 至少 20，sk 量得用户屏幕一行约 218 字符，`in` 实得约 42。

**卡：右侧栏 `selection` 页顶上，十一行，行序固定，每行「标签 值」**，同一条不适用规则：

| 行 | 维度 | 名字 | 写法 | 取值来源 |
|---|---|---|---|---|
| 1 | 牵出的买点日 | `buys` | `首…尾 ×n` | 一族的买点日；一次 hit 的买点日；用到这个 event 的 hit 的买点日；反馈收进来的买点日 |
| 2 | 牵出的 hit | `hits` | `×n`，这些 hit 跨两族以上时接 `families ×k`；下面逐行写区别 | 一族的 hit；这天那个 ▼ 上的几次；用到这个 event 的 hit；反馈收进来的 hit；样本日 / 框终点在场的 hit |
| 3 | 组成 | `nodes` | 每个 node 一行：`node 起→止` | 一次 hit 每个 node 绑定的 event |
| 4 | 结构上的那一族 | `family` | 起点 `YYYY-MM-DD` | 买点日、一次 hit 所在那一族；一族反馈记的 `family_start` |
| 5 | 盖住它的反馈 | `feedback` | 每条一行：`起→止 状态 [原因标签]`；没有写 `none` | 范围盖住这天（这一族）的反馈；反馈本身写它自己 |
| 6 | 相关的样本 | `sample` | 每个一行：`字母 判断 YYYY-MM-DD ✓|✗`；没有写 `none` | 样本日离这天（这族的买点日）在容差以内的样本；样本本身写它自己；框写以它为成员框的样本 |
| 7 | 配对的另一方 | `paired` | 对方的身份；没有写 `none` | event：拿它当配对那一格的样本 / 框；样本、框：配对的那个 event；一次 hit：配对到它的样本 |

| 10 | 内部编号 | `id` | `[编号]` | hit_id、instance_id、反馈 / 样本 / 框的编号 |
| 11 | 复制行 | `copy` | 第 7 节的整行 | 第 7 节的拼法 |

### 5.4 三种形态，按这把尺子重评

| | A 单行混写（第二～四稿） | B 贴竖线的标签（第二～四稿推荐） | **C 维度格栅 + 选中卡（本稿推荐）** |
|---|---|---|---|
| 样子 | 一行：白块写复制行的前半（种类、日期、区别连成一句），后面路径、两个键槽 | 「是什么 + 键往哪走」一枚标签贴着当前日竖线；路径在条左；细节进卡 | 栏九格按维度排、位置固定（5.2）；细节进卡十一行、行序固定 |
| 拆成维度了吗 | 否：选中块是一句混写的话 | 一半：标签里仍是混写的一句 | 是：一格一维 |
| 同一维度同一位置 | 否：日期在白块里的位置随种类变（`buy 2024-11-27` 与 `event step 2024-11-21 used_by …`） | 否：标签跟着竖线走；不停在某天上的种类又放到最左 | 是 |
| 同一维度同一写法 | 大体是 | 大体是 | 是（5.2 统一写法） |
| 不适用时 | 不写，后面的东西往前挪 | 不写 | 灰 `—` 占格 |
| 一眼看出选中什么 | 白块在最左 | 白块在选中物正上方 | `kind` 白块永远在最左第一格 |
| 按键走动时 | 视线回条右端读键槽 | 不用挪眼睛 | 视线回条右端读键槽（位置永远同一处） |
| 「买得对不对」 | 只在悬停 | 卡里 | 卡里，行序固定 |
| 占的地方 | 不变 | 提示条一行 + 右侧栏卡 | 提示条一行 + 右侧栏卡 |
| 代价 | 最小 | 标签定位、避让、贴边；跟着竖线晃 | 栏里常有几个灰 `—`；窄窗口要藏标签（5.6） |

**推荐改为 C**。用户这次定的方向是「按维度拆开、每个维度标准化」，C 是唯一三条都满足的：一格一维、位置不随种类挪、写法统一。B 原先的长处「答案在选中物正上方、按键不用挪眼睛」，恰好靠的是位置跟着竖线走——和「同一维度永远在同一位置」正面冲突；它保住的是走动时少挪一次眼睛，C 用「键槽永远在同一处」换「用户记住一次就能读任何状态」，后者正是用户这次要的。A 的选中块是一句混写的话，这次被用户的要求直接排除。B 退为第 10 节第 5 条的备选。

C 的心智负担：记住九格的顺序一次（种类、node、日期、叫法、区别、属于、两个键、Esc），之后读任何状态都是同一套；不适用的灰 `—` 让「这一维这种东西没有」一眼可辨，不用猜是不是漏了。卡同理，十一行永远同一顺序。

### 5.5 用户四个现场的逐字 mock（形态 C）

记法：`│` 是格之间的细竖线；`[ ]` 是 `kind` 那块白底粗边；`—` 实际是灰色；`<↑/↓>` 表示键帽画灰（不适用）。只写栏；卡见 5.3。

## 6. 键位一览（给说明书用）

| 键 | 做什么 |
|---|---|

## 7. Shift+C：所选即所复制

按一下复制选中的那一个，不连按、不循环；底部提示条照旧显示复制的那行几秒。同一样东西不论从哪条路选中都复制同一行。

**拼法对所有种类相同**（第 5 节标准化的延伸）：`股票 pattern` + 栏的身份五格（`kind` `node` `date` `name` `diff`，按这个顺序、跳过 `—`）+ 卡的 `buys`、`hits` 两行（带行名、跳过 `—`）+ `[编号]`（没有编号的跳过）。用户把栏从左读到前五格，就是复制行的前半；卡的 `copy` 行给全文。行里不写 `k/n` 这类位置号（那是走动的位置，在键槽里看；会话靠日期、区别和编号定位）。

| 实体 | 行（CRNC） |

| 买点日 | `CRNC new_step buy 2024-11-27 hits ×2`（两族同一天买时 `hits ×3 families ×2`） |
| 一次 hit | `CRNC new_step hit 2024-10-31→2024-11-27 step→2024-11-21 buys 2024-11-27 ×1 [hit 编号]`（买好几天时 `buys` 是首…尾 ×n） |

## 8. 代价与改动面

**相对现在（方案 B），用户会失去的**：

1. 点 ▼ 或它那一列的格，不再直接落定其中一次 hit：要看某一种切法的组成、复制某一次，多按一下 ↓（或点侧栏 hits 行、diagnose 卡片）。这推翻 spec 5.8 当天定的「▼ 点下去总是落定一次」。compare 里 new_step 这种 app 没有用鼠标直接点到某一次的地方。
2. （2026-11-12 改）沿 band 逐格走保住了，但只对牵出一个或零个买点日的 event（new_plat、today、plateau 的格，没进 hit 的 event）；step 这类牵出好几天的按 → 是落进买点日。从只牵出一天的 event 到那一天没有键，要点 ▼（3.3）。
3. （2026-11-12 改）没进任何 hit 的 event 沿 band 换，上一轮的 U10 保住。新增一条代价：换旁边时碰到里面有得挑的（牵出好几天的 event、有好几个买点日的族），下一下被带进去，要越过它用鼠标点。
4. Esc 不再一下全清：从 step 进到的那次 hit 要按四下（或点空白）。
5. Shift+C 砍掉 4 种行、`hits_using` 并进 event 行；样本、框不再和当前那次 hit 写在一行；hit、event 行里不再有 `same_day j/m`。
6. 点 band 上的格不再顺带选中用到它的那次 hit；点样本不再顺带选中配对那次——**沿样本走时，配对那次的组成只以细框出现，要粗框得先 ↓ 进去**；进去以后 ← / → 换样本仍停在「次」这一层、落配对那次，所以整段走查只比现在多按一次（sk 质疑 6）。
7. 反馈记号的粗边与竖带不再「点了别的也一直留着」。
8. 显示栏常驻九格，不适用的格写灰 `—`，比现在一行字「满」；compare 下右侧栏样本那块被选中卡往下推。

**多出来的**：

1. 一眼看出选中的是什么：栏最左第一格永远是 `kind` 白块；每个维度永远在同一格、同一写法，记住一次就能读任何状态。不会再出现「选中 step、提示条写 `hits_using`」「选中 new_plat、提示条写 `event_family`」。
2. 买点日（反馈与判断的单位）一下就能选中、一下就能复制；点 ▼ 或格弹的反馈面板和选中的是同一样东西。
3. （2026-11-12 改）点 band 上一格之后一律选中那个 event，栏最左写 `event`。按 ← / → 是落进买点日还是沿 band 换，**仍由数据定**（牵出几个买点日），和现在跨天走 `hits_using`、不跨天走 `event_family` 的分法相近；不同的是现在点之前看不出、提示条第一格还换名字，改后键槽在按之前写明 `into buys ×n` 还是 `events k/n`，选中的始终是那个 event。event 与那些买点日、那几次 hit 之间键盘来回（牵出两个以上时）。
4. 一族在 app 模式也能点到，键盘从买点日按 Esc 也能到；node 从 event 按 Esc 能到。
5. 竖线总停在选中物自己的日子上，不会再「竖线那天是另一次 hit 的买点」；走出视窗时图跟着平移（修现有毛病）。
6. 没有 `–/n`；同一样东西复制出来永远同一行，且拼法对所有种类相同；键永远在同两个槽里。
7. 少三个界面名：`event_family`、`in_set`、`hits_using`（作为第一格）。
8. 选中 app 的东西时右侧栏不再写 `empty`：「买得对不对」（盖住它的反馈、相关样本的 ✓ / ✗）、组成日期、编号、复制全文在卡里，行序固定。

## 10. 需要用户拍板的方向

> **2026-11-12 已全部拍板**（见文首「拍板结果」）：1 这一天整体；2 最像的那次；3 不取下面三条路，改用通用规律（`切换规律.md`）；4 往上退一层；5 形态 C；6 只选中样本。下面是拍板前的原文，留作经过。

1. **点 ▼（或它那一列的格）选中什么。**
   - 这一天整体（推荐）：反馈面板、显示栏、复制说的都是同一样东西——这天买得对不对；看某一种切法多按一下 ↓。代价：改掉 spec 5.8 当天定的「▼ 点下去总是落定一次」；compare 里没有用鼠标直接点到某一次的地方。
   - 这天的第 1 次 hit（你的原提议，也是现在的做法）：少按一下；但一次点击两样当前（面板说这天、显示栏说其中一次），复制给会话的那行可能被读成只针对一种切法。
2. **停在一次 hit 上按 ← / → 换天，落哪一次。**
   - 同一种切法的那次（推荐，现在就是这样）：一路追同一种认法，band 上粗框不跳；从 step 走进来时一路停在用到这一根阶跃的那几次上。
   - 一律第 1 次：更好预测；但在两种切法之间看时，每走一步粗框可能跳到另一种。
3. **选中 band 上的一个 event 后按 ← / →。**（在决定：从一个 event 出发，按键是去看「它让 app 在哪些天买了」，还是去看「这条 band 上的下一个 event」。）
   - 落进用到它的买点日，没进任何 hit 的 event 不响应（推荐）：点 step 后按 → 就是上一轮你要的 1/11、2/11，竖线停在买点日上，Esc 一层层退回 step，全程键盘；规则只有一条，没进 hit 的 event 事先看得见（卡的 `buys`、`hits` 是灰 `—`，← / → 键帽画灰）。代价：不能用 ← / → 沿 band 逐格走（看平台逐天长改为点 ▼ 进到那次再走）；同一条 band 上别的 event 只能用鼠标点；上一轮的 U10「沿同一行看没进 hit 的格」没有了。
   - 同上，但没进 hit 的 event 沿这条 band 走到上 / 下一个 event：接住 U10。代价：同一个键在有 hit 的 event 上是「落进它的买点日」、在没 hit 的上是「换到旁边的 event」，意思随数据变——这正是你这次嫌的那类毛病，只是键槽里会写出来（`into buys ×11` 还是 `events 2/5`）。
   - 一律沿这条 band 走到上 / 下一个 event：任何 event 都按得动，同一条 band 上的 event 键盘都到得了，没进 hit 的也能走，按键不换种类。代价：从 event 到用到它的买点日没有键（点 step 后按 → 是下一个 step，看它让 app 在哪些天买要去点 ▼）；走的位置随档位按钮变、几族的 event 混着走（sk：等于把「event 族第几天」的毛病换个地方）。
4. **Esc。**
   - 往上退一层，退到头再清空（推荐）：键盘能从一次 hit 回到这一天、回到一族或 event，从 event 回到 node；显示栏路径的最后一节就是 Esc 会退到的地方。代价：清空要多按几下（点空白仍一下清）。
   - 一下全清（现在）：回到外层只能用鼠标点。
5. **显示栏的形态。**（在决定：显示栏是「每个维度一个固定格子」，还是「答案跟着竖线走」。你第三次追加要的是前者。）
   - C 维度格栅 + 选中卡（推荐）：副图上方一行九格，种类、node、日期、叫法、区别、属于、两个键槽、Esc，任何状态下位置和写法都不变，不适用的写灰 `—`；「买得对不对」和细节在右侧栏的卡里，十一行、行序固定。记住一次就能读任何状态，Shift+C 复制的就是前五格加卡的两行。代价：按键走动时要把视线挪到条右端读第几个；栏里常有几个灰 `—`；compare 下右侧栏的样本那块往下挪。
   - B 标签贴着竖线：「是什么、第几个」写成一枚标签贴在选中物正上方，按键时不用挪眼睛。代价：标签的位置跟着竖线、跟着种类变（不停在某一天上的种类放到最左），违背「同一维度同一位置」；标签里仍是混写的一句。
6. **点样本选中什么。**
   - 只选中样本（推荐）：复制的就是样本，选中的永远只有一样；配对那次的组成改细框，↓ 进去才加粗，之后 ← / → 换样本仍停在那一层。
   - 样本和配对那次同时当前（现在）：少按一下，复制要拼成一行。

## 12. 分歧与定法

> 2026-11-12：下面「选中 event 后 ← / → 走什么」的甲 / 乙之争已由用户的通用规律收掉——牵出两个以上买点日走甲、一个或没有走乙，两边各缺的那一块都补上了一半（见 `切换规律.md` 的三条后果）。下文留作经过。

**选中 event 后 ← / → 走什么**：两条路——甲「落进用到它的买点日」（和一族、反馈同一种关系）、乙「沿这条 band 走到上 / 下一个 event」。初稿取甲；第二、三稿按 entities 当时的倾向改取乙；中途 entities 转而同意甲，消息交叉，两份文档一度互相引用对方已放弃的立场（sk 指出）。最后按 lead 给的三条标准依次比，与 entities 一起定为甲：

| 标准 | 甲 | 乙 |
|---|---|---|
| ① 键的意思不随选中物的种类或状态变 | 打平：event 并进已有的「装着一串的东西按 ← / → 落进去」那条（一族、反馈已在里面），不新增规矩 | 打平：event 是纯横着走 |
| ② 每个有业务意义的实体都能只用键盘选到（含 event 与用到它的买点日 / hit 之间来回） | lead 点名的那一块有：event → 买点日 → 那次 hit → Esc 逐层退回 event，全程键盘。缺一块：同一条 band 上不在同一天结束的另一个 event，键盘到不了（只能点） | lead 点名的那一块没有：从 event 到用到它的买点日没有键，只能点 ▼，也退不回 event。有另一块：同一条 band 上的 event 键盘都到得了 |
| ③ 一眼说出选中的种类 | 打平：栏的 `kind` 格都写种类 | 打平 |

②是各缺一块。lead 在②里点名的是「event 与用到它的买点日 / hit 之间来回」，这一块甲有、乙没有，所以我和 entities 按甲推荐；**lead 判为各输一条、打平，交用户**：第 10 节第 3 条写成三条路（纯甲、甲加没进 hit 的沿 band 走、纯乙）连同代价，保留推荐与理由；entities.md、challenge.md 引用同一条。甲路真丢的：沿 band 逐格走（代价第 2 条）、同一条 band 上别的 event 键盘到不了、没进 hit 的 event 怎么走（第 10 节第 3 条）。sk 倾向甲路，理由：event 装着用到它的买点日，和反馈同一种关系，不新增规矩；乙路的位置随档位变、几族混走，等于把「event 族第几天」那个毛病换了个地方。entities、designer-2 两边的理由：甲接住上一轮用户要的 1/11、2/11 且全程键盘来回；乙任何 event 都按得动、接住没进 hit 的格、按键不换种类。

**点 hits 行的格选中什么**：初稿让格选一次 hit、▼ 选这一天；sk E6、走查 (a) 与 entities 指出 ▼ 就画在格里面、差几个像素换种类，且点格同样弹这一天的反馈面板，又是两样当前。改从：有 ▼ 的那一列的格和 ▼ 一样选这一天，没有 ▼ 的那一列（别的 app 才有）选一次 hit。已收拢。
