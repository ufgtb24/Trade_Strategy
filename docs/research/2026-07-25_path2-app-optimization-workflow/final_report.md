## 1. 工作流该是什么形状：取决于你的尺子有多准

工作流有两种形态，**选哪一种不是品味问题，是一个可以算出来的量说了算**。

### 1.1 判据：先过一道无模型的主闸，再用 `ρ_rel` 细化

#### 主闸（无模型，优先用这个）

> **在 contender 子集（过硬门、非前瞻的那批）里做两两配对比较，看 `|z|>2` 的占比。**
> 若它不显著高于纯噪声期望（约 5%），**就没有任何证据表明候选之间存在真实差异——到此为止，走闸阵。**

本项目实测：**1%**（低于 5%）。

主闸的好处是它**什么都不需要**：不需要高斯假设、不需要约定门槛、不需要估 `τ̂²`、不需要任何标定。它就是一个显著性计数。

#### 细化（有模型，主闸过了再用）

```
ρ_rel = τ̂² / (τ̂² + σ̂²)        在 contender 子集上算
```
- `τ̂²` = 候选之间**真实**质量差异的方差（矩估计：`max(0, S² − σ̂²)`）
- `σ̂²` = **配对**比较的抽样方差（同一批标的上评估所有候选，公共随机数）

含义：**观测到的冠军优势里，期望能兑现的比例**（高斯随机效应下的收缩系数）。

| `ρ_rel` | 工作流形态 |
|---|---|
| **< 0.2** | **闸阵**：目标函数只用来否决，幸存者按奥卡姆取。排序类工具全部退场 |
| **0.2 – 0.5** | **有限排序**：可以排，但必须记 K、付选择税、跨窗复核 |
| **≥ 0.5** | **排序工具回桌**：搜索是有回报的 |

**⚠ 上端那条线是容忍度旋钮，不是最优性边界——这一点必须说清，否则会被当成定理。**

取 `0.5` 的含义是"观测到的冠军优势里，真实成分多于虚假成分"。**但严格按期望收益算，只要 `ρ_rel > 0`，排序策略就永远弱优于闸阵**（排序的期望真实收益 `= ρ_rel · σ_obs · E[max_K] ≥ 0`，闸阵 + 奥卡姆 `= 0`）。

⟹ **"该不该排序"根本不由期望收益决定**，而由三件判据之外的东西决定：搜索的算力与人力成本、K 被消耗后未来断言的门槛抬升、以及**你会不会把 `1/ρ_rel` 倍的虚假增益当真而污染下游**。**把线画在 0.5，买的就是最后这一条。**

要更保守可提到 **0.6~0.65**（等价于要求真实增益还要盖过"纯噪声世界里搜 K 个候选会展示的那个海市蜃楼"），代价是把一部分真有信息的情形误判进闸阵档。

> **一段值得留下的过程记录**：初稿这里写的是 `0.618`，来自一个看起来很漂亮的推导（`ρ > √(1−ρ)` 的根，黄金比例）。复审时提出者自己戳破了它——**那个根号完全来自把"税"的基准换成了纯噪声对照，而换不换基准是选的，不是推的。** 代数只给出"兑现 = `ρ_rel` × 观测"这一条，**边界始终是选的**。
> 他的自评值得原样引用：**"一个'推导'如果推出漂亮常数，最可能的解释是某个自由选择被审美锁定了。"**

#### 三个实现细节（前两个错了会得出相反结论）

1. **必须在 contender 子集上算。** 同一批数据，全集算出 **0.993**、contender 算出 **0.000**——全集的 `τ̂²` 被"明显坏掉的候选"撑起来了。
2. **`τ̂²` 与 `σ̂²` 必须同口径（都用配对口径）。** 两者各自比边际值大一个因子 2，**但因子 2 在比值里正好约掉**。若有人顺手改成"边际 σ + 配对 τ"，结果会错 √2。
3. **成本秒级**（跑一次评估拿到逐买点明细即可）。

#### 这个判据本身有多硬——分开定级，不要打包

| 成分 | 等级 |
|---|---|
| 算 `ρ_rel` / 必须用 contender 子集 / 主闸的显著性计数 | **可靠**（推导 + 全集 0.993 vs contender 0.000 的实测对照） |
| "期望兑现 = `ρ_rel` 比例" | **机制推导**，假设：高斯随机效应、候选可交换。**本项目两条都存疑**（收益分布右尾极重；同族阈值候选单调嵌套） |
| 档位边界 0.2 / 0.5 | **约定，零测量支持**。代数只给出"兑现 = `ρ_rel` × 观测"，**边界始终是选的**——它是容忍度旋钮，不是最优性边界 |
| "档位与候选数无关" | **半真**：`E[max_K]` 之所以约掉，是因为基准也随 `E[max_K]` 缩放——**这一半是判据选择带来的，不是天然规律**。换成单次比较的 SE 作基准，K 就不再约掉 |
| 那次标定（`ρ_rel=0` 预测兑现 ≈0%，实测 3%） | **一次退化确认**——在取值域端点上预测端点值几乎没有鉴别力。它确认的是**未被证伪**，不是**被验证** |

**⟹ 判定本项目落在哪一档时，以主闸（1% < 5%）为准，`ρ_rel=0` 作旁证。**

### 1.2 本项目当前落在哪一档——以及一个必须说清的作用域限制

试跑读数：**主闸 `|z|>2` 占比 = 1%（低于纯噪声期望 ~5%）**，旁证 **`ρ_rel` ≈ 0**（contender 子集）。落在闸阵档。据此：

> **目标函数否决，奥卡姆选择。** 幸存者之间按结构简单性取，消耗零选择预算。

**但这个读数有两层限制，都不小**：

**限制 1 · 它是用一把已被证伪的尺子量的。** 附录 A.1 实测：现行目标函数在奖励波动率而非方向性优势。所有基于它的统计量（`τ̂²`、选择门槛表、跨期兑现率）**都是在这把尺子上算的**。
而且有直接反证：**同一批 contender，换一个度量就分辨得动**——`corr(score, 最大不利偏移深度) = −0.591 (p=0.003)`。
⟹ **"分辨不动"是尺子的属性，不是候选空间的属性。** 修好尺子之后必须**重算 `ρ_rel`**，档位很可能变。

**限制 2 · 它的作用域只覆盖机械邻域。** 那次测量的候选是"单旋钮邻域 / 删 where / 节点子集"这一类。**测量者自己写明了：没有测过 LLM 生成的新判据代码。** 而工作流的通道 C / D 产出的正是那一类。
⟹ **拿机械邻域的读数去否决语义候选的排序，是越界一整层。**

### 1.2b ★ 低读数的强制后继：分诊

**判据读数低，不必然意味着"该用闸阵"，也可能意味着"你的尺子坏了"。判据本身分不出这两者**——它只能告诉你"用这把尺子分辨不动"。

⟹ **`ρ_rel ≈ 0`（或主闸不过）时，必须先跑分诊，不许直接进闸阵档**：

> **分诊做法**：拿**同一批 contender**，换 2–3 个合理的替代度量，**在每个替代度量下重算 `|z|>2` 占比**。
>
> - **某个替代度量上分辨得动** ⟹ **尺子问题**。回阶段 0 修 label，修好后重量判据。
> - **所有合理度量上都分辨不动** ⟹ **空间问题**。闸阵档成立，而且**换尺子救不了**，该去换候选来源（通道 C/D）。

**本项目的分诊结果：明确是尺子问题**（同一批 contender 在"最大不利偏移深度"这个度量上分辨得动）。

**⚠ 实现上一个坑**：分诊要用**替代度量下重算的 `|z|>2` 占比**，**不要用两个度量之间的相关系数**——后者会被共享抽样噪声污染（本项目 `corr(score, MAE深度) = −0.591` 与 `τ̂²=0` 之间那点表面张力，最可能的调和就是两个统计量算在同一批买点上、抽样误差相关）。

**为什么写成"必须"而不是"建议"**：只写"靠阶段 0 体检去区分"，读者仍然会跳过；写成低读数的**强制后继**，体检就挂到了一个**必然会到达的位置**上。**这与 §8.3 是同一条纪律——把该发生的事挂到必经之路上，而不是写成一句提醒。**

成本近零：复用阶段 0 的 b 项同一批计算。

### 1.3 所以工作流的四件事是什么

无论落在哪一档，下面四件都成立——**只有第③件的形态随 `ρ_rel` 变**：

| # | 做什么 | 为什么 |
|---|---|---|
| **① 体检目标函数** | 阶段 0，全新工序 | 尺子错了，下游一切自动化都在放大错误 |
| **② 补上候选生成的盲区** | 阶段 1 通道 A | 所有自然的候选来源都只会"放松/新增"，产不出"删除" |
| **③ 按 `ρ_rel` 决定用闸还是用排序** | 阶段 2 | 分辨力不够时排序就是在选噪声；够时不排序就是浪费 |
| **④ 让每一步真的发生** | 贯穿 | 写进文档的建议不会被执行（§8.3 有实证） |

①②④ 与信噪比无关，任何情形下都成立。③ 是唯一随 `ρ_rel` 变形态的那件。

这也是「最优化 > 最自动化」的实际含义：**先量一下那件事做不做得成，再决定要不要自动化地去做。**

## 2. 工作流全景

```
用户一句话（"我想要一个匹配 XX 走势的 pattern" / "优化这个 pattern"）
   │
阶段 0  目标函数体检 ──── 不过 → 停下，先修尺子（六项检查，§3）
   │
阶段 1  候选生成 ──────── 四条通道并行（§4）
   │                      A 机械消融（含删除）· B 表达面扩张
   │                      C LLM 读失败归因 · D 人类形态直觉
阶段 2  评估与判定 ────── 闸阵过滤 → 幸存者按奥卡姆取（§5）
   │
阶段 3  人在环 ────────── 阻塞式，三个用途，硬预算 ≤20 判定/20 分钟（§6）
   │
阶段 4  定案与 holdout ── 终局窗只解锁一次（§7）
```

**循环在哪**：阶段 1↔2 是脚本内循环（廉价，无人值守）；阶段 0/3/4 是**用户外循环**（多次调用工作流，人在 run 边界而不是 pause 点）。

> **⚠ 一处必须坦白的不对称：这套流程主要服务「优化现有 pattern」，「从一句话新建 pattern」这一支基本没被设计。**
> 阶段 0（体检目标函数）、1（候选生成）、2（评估判定）、4（holdout）**全部预设已经有一个 pattern 在手**。而用户原话里"我想要一个匹配横盘后连续突破的 pattern"这条入口，走的仍然是现有 `authoring-path2-app` 的三层 gate（拓扑→detector→参数），**本研究没有对它做出任何改进，只是给它的验收口接上了阶段 0 与因果闸**。
> 把两支并列画在上图里是不实的，在此更正。**新建支的真实状态：现有 skill 够用，本研究只加了出口检查，没有加入口能力。**

**形态要求**：**幂等可重入的短 run + 持久 workdir**。人类环节是 run 的边界，不是进程内的暂停——因为 session 会中断、会 compact，状态必须活在磁盘上。

## 3. 阶段 0 · 目标函数体检

**这道工序此前完全不存在，是本研究最重要的方法论产出。**

为什么排在最前：一个未封堵的杠杆或一个度量错的口径，会让下游所有自动化**加速收敛到错误方向**。人不容易滑进去（人按走势语义设计结构），但最大化器会直奔而去。**记账做得再干净，记的都是一个错的数。**

### 前置 · 策略语义声明（无产物，但缺了它后面两项无效）

**七项里至少有两项（b / c）的"通不通过"判据依赖于策略打算怎么兑现。语义没声明，这两项就没有判据可用——而它们照样会跑出数来。**

至少声明三件事：

| 声明项 | 它决定了什么 |
|---|---|
| **信号在多长时间内兑现** | b 项替代口径的选择、c 项窗口的取值 |
| **由谁兑现**（pattern 自带出场 / 交给独立的卖出程序） | "期末收益为负"算不算 pattern 的缺陷 |
| **允不允许回撤到买入价以下** | MAE 类指标算体检项，还是算对下游的风险披露 |

**本项目的声明（2026-07-25 用户确认，写死）**：

- pattern 只负责**找入场点**，"未来一段时间内会涨"就是买点的定义
- 兑现由**尚未开发的独立卖出程序**负责，它在窗内择时
- **允许回撤到买入价以下** ⟹ 期末收益为负**不构成对 pattern 的指控**，但构成对卖出程序的约束
- **b 项替代口径 = 20 日内最高 vs 40 日内最高**（同为 max-high 语义，只换窗口）

⟹ **b 项在本项目的正确形式**：同一批候选分别用 20 日内最高与 40 日内最高重排，算两个排行榜的 Spearman。
**它问的不再是"度量维度是否一致"，而是"这个信号的优势对时间窗口有多敏感"**——直接对应卖出程序的择时容错空间：秩相关高 ⟹ 优势不依赖精确择时，卖出程序好写；低 ⟹ 必须卡在特定窗口内兑现，容错很小。

**⚠ 两个实施注意**：

1. **40 日口径把尾部缓冲从 20 天推到 40 天**，会进一步吃掉终局 holdout（§7 实测已只剩约 3.5 个月）。⟹ **b 项只在搜索窗上跑，不要占用终局窗。**
2. **这个检验本项目尚未做过。** 现有采集脚本（`repro/opt2_collect.py`）只跑了 `H=20`、且只有 2 个配置；秩相关需要多候选，补它要重跑一轮。

> **⚠ 这一步是被一次翻车逼出来的，写在这里免得再发生。**
> b 项初版选了"20 日持有到期"当替代口径，得到秩相关 −0.186，被当成"目标函数在度量另一个维度"的证据。**它其实只说明了替代口径换掉了持有期语义**（见 A.1 的用户异议）。
> 而这个语义讨论最后是**用户事后提出的，不是流程逼出来的**——恰恰是 §8.3 那种失效模式在本报告自己身上的复现。⟹ 按律②，声明缺失应当**让后续步骤跑不下去**，而不是写成一句提醒。

### 七项检查

| # | 检查 | 怎么做 | 不通过的判据 |
|---|---|---|---|
| **a** | **平凡对照** | 构造一个**零能力**规则（随机日买入；锚点后 k 天内最低收盘买），同口径算分 | 零能力规则的分接近或超过你的 pattern |
| **b** | **口径一致性** ⚠ | 换一个**与上面声明的持有期语义兼容**的替代度量，重排全部候选，算两个排行榜的 Spearman。**本项目 = 20 日内最高 vs 40 日内最高**（见前置节） | 相关系数低甚至为负 ⟹ 目标函数在度量另一个维度，**连"至少适合相对比较"都不成立**。**⚠ 前提是替代口径与持有期语义兼容，否则本项给出的是假警报——A.1 的用户异议就是实例** |
| **c** | **方向性检验** ★ | **首次穿越**：对称阈值 ±X%（取 4 档），统计"先触 +X"占比，与随机日对照 | 与随机日无差异或更差 ⟹ 这个形态**看不对方向**，幅度类 label 上的任何优势都是别的东西 |
| **d** | **因果可容许** | 见下方专节 | 买点锚点字段的 bar < 该 event 物化的 bar |
| **e** | **噪声标定** | 在**本 label 分布、本配置的样本**上 bootstrap 标定 SE，与你在用的常数比对 | 差距显著 ⟹ 所有"能否检出"的判断都要重算 |
| **f** | **硬门体检** | 用零信号配置压测每一道硬门，看它实际淘汰了多少 | 淘汰率接近 0 ⟹ 这道门不是防护，别把它算进防线 |
| **g** | **波动率暴露体检** ★ | 每个候选除 score 外，同时报 ① 命中集相对全宇宙的**波动率倍数** ② **波动率-月份匹配后的条件百分位** | 倍数显著 >1 **且**匹配后百分位 ≈0.5 ⟹ **这个候选的 lift 是波动率读数，不是形态优势，否决** |

**g 项为什么必须单列（而不是并进 A.4 那种"检查阈值量纲"）**：`max(high)/close` 型 label 对波动率单调——试跑实测跨 27 个配置回归「label 中位 ~ 命中集波动率倍数」得到 **R² = 0.919、Spearman = 0.968**。**⟹ 任何选择器的 score，首先是它的波动率暴露的读数。**

而 g 项的关键优势是**它与偏斜的成因无关**：量纲写错、结构性要求、还是别的什么，它都能抓到；而"检查阈值量纲"只能抓其中一类（试跑实测：本 app 的偏斜只有**一半**是量纲造成的，另一半住在"8 根内打穿 4 个不同峰"这种**天生就选快速运动的股**的结构性要求上，**没有量纲可归一**）。

**g 与 c 互补，都复用同一批买点、都是秒级**：**c 回答"看不看得对方向"，g 回答"分数是不是波动率换来的"。**

**⚠ 一处会静默出错的实现细节**：波动率面板的缓存 key **必须包含数据集路径**。否则搜索集与全量集的面板会串——**在 holdout 上跑 g 项时会读到搜索集的波动率分布，不报错，只是结论错**。（面板是纯派生物，丢了几分钟就能重建。）

**⚠ 更要紧：g 是七项里唯一"能可靠告诉你出了什么事、但给不出下一步"的检查。**

> a/b/c/e/f 项 FAIL 都有可执行处方（换口径 / 加对照列 / 重标定 / 撤掉装饰品门）。
> **g 项 FAIL 之后该怎么办是开放问题**——把目标函数改成对波动率中性？接受"这就是个波动率选择器"？还是撤回这个候选？**本方法只保证把这个问题摆到人面前，不保证有解。**
> 不标出来的话，读者会以为过了体检就有路可走。

> **⚠ 一个没有解的张力，写在这里免得被规格掩盖**：c 项要通用（阈值档不能写死成某个 app 的数字），就得让阈值从命中池自身的分布里算出来——**而"从哪个分位算""判据取多少比例""多少算失效"这几个数又都是人拍的**。
> ⟹ **修 app 特异性的代价，是把常数从 app 里挪到了判据里。** 这不算白拿。c 项因此同时是七项里**最锋利**的一项和**最依赖人拍常数**的一项，这个张力目前无解——**该做的是把这些常数显式列出来、算出即冻结以保跨轮可比，而不是假装它们不存在。**

**c 是本研究新增的、也是最便宜最锋利的一项**：复用同一批买点、秒级出结果、不受幅度类 label 上偏的影响，直接回答"这个形态看不看得对方向"。

> **⟹ 建议把首次穿越比例（对随机日的先涨比例差）作为任何新 pattern 的一等验收指标，与 score 并列。**

**e/f 的通用意义**：**任何从别处沿用来的统计常数（SE 公式、样本量下限、分位数硬门）都必须在自己的数据上重新标定。** 沿用是默认动作，标定不是——这个不对称是缺陷的温床。

### 因果可容许闸（d 项展开）

评分标准通常会封堵前瞻**特征**与**窗宽刷分**，**但很少有人封堵买点锚点**。

```
因果可容许闸：  买点锚点字段的 bar  ≥  该 event 物化的 bar
```

**关键实现要点：`materialized_at` 必须由 detector 自己声明，引擎猜不出来。** 同一个框架里，span 事件的物化时点可能是 `end_idx`（链式聚合类），也可能是 `start_idx`（确认类）——**恰好相反**。落地代价很小：detector 协议加一个属性 + `eval_meta` 加 `buy_at`。

**这道闸是机械可检的，不需要人做语义审查**——比"人工审查每个拓扑候选"落地容易一个量级。**它是层① 拓扑可搜索的前提条件。**

经验规则：span event 的 `end_idx` 天然可容许，`start_idx` 一般不可容许——**除非 `start_idx` 本身就是确认那根**（确认类 detector 就是这种）。

**⚠ 这道闸的射程有明确边界，别以为加了它就不用管入场了**：

> **拓扑候选（买点锚在某个 event 的某个字段上）由本闸机械抓住。**
> **但评估侧的自定义入场规则不在射程内**——例如"锚点后 k 天内最低收盘买"这类规则，`bo_end + k` **不是任何 event 上的字段**，协议表达不出来，断言也不会在它身上跑。**这类必须人工判。**

（阶段 0 的 a 项"平凡对照"正是为了兜住这一类：**闸管结构，平凡对照管规则。**）

> 试跑时它逮到两类东西：一个把买点锚在"事件尚未物化的那根"上的拓扑候选（分数是现任的 6 倍、|z|=17.8、三道硬门全过，等于**回到过去买**）；以及一条零选股能力的"买在事后最低点"规则。**这两个洞统计闸都拦不住。**
>
> 一个正面发现：`median_confirm` 这类"只取买点窗第一天"的排序口径，**恰恰就是这条闸在 label 侧的等价物**。它常被当作防缩窗刷分的措施，实际上它更重要的身份是因果闸的既有实例。

**体检不过就不要往下走。**

## 4. 阶段 1 · 候选生成：四条通道

### 通道 A · 机械消融（含删除方向）★ 补的就是这个盲区

**本研究最重要的结构性发现**：三条独立设计的候选生成通道——失败归因生成器、人类漏检通道、缓存用途清单——**全部只能产出「放松 / 新增」类候选，没有一条能产出「删除」**。这有结构性原因：

- 失败归因的输入是**失败记录**；一个节点存在时，不会产生"它不该存在"这类失败。
- 人会说"它漏了我要的股票"，**永远不会说"这个节点净贡献为零"**。
- 缓存的服务半径明明覆盖所有节点子集拓扑，却没人把"删掉一个节点"列进用途。

**做法**：从 `dag_spec.py` 机械枚举「每 node / 每 where / 每 edge 各删一次」。候选数 = `节点数 + where 子句数 + 边数`（试跑的那个 app 是 7 个；**这是公式，别记那个数**）。

**⚠ 但"完全不需要人"只对不改末端节点的删除成立。** 删掉链末端的节点会**改变 `end_node`**，也就改变了买点锚——**那是一个语义决定（`buy_at` 取哪个字段），必须过人或过因果闸**。见附录 A.3 的教学例子：同一个"删 tb"，买在末 bo 与买在首 bo 的分数差了 6 倍，而后者是前瞻。

**成本为零的机制根据**：事件流缓存的物化键是 **`(id(node.detector), node.consumes_stream)`——粒度是 detector 对象，不是 spec**。所以 edge / where / 节点子集的改动**全部复用同一次 detect**，零增量。

**⚠ 这条不变量会被静默破坏**：只要有人把一个阈值从 `NodeSpec.where` 挪进 detector 构造参数（或反过来，比如做"松检测/紧过滤"重构），缓存就开始给错结果**且不报错**。⟹ **detector 代码或 params 结构一动，就该重跑不变量检查**（方法见 `02_mech_mapping.md` §E-pre.0；现成脚本 `check_stream_cache_invariant.py` 在本目录）。

**额外好处**：删除类候选是**确定性可枚举**的，因此是层① 里**唯一能被 null 门槛校准覆盖**的部分（校准要求候选生成器可重放，"LLM 自由发明"那一档做不到）。**既最便宜，又最容易被正确判定。**

### 通道 B · 表达面扩张：被忽视的「层 2.5」与「层 2a」

原先的三层划分（拓扑 / detector 代码 / 参数）漏掉了两层，而它们恰好是"改动小、风险低、现有 skill 都覆盖不到"的真空：

**层 2.5 = 新增 where 谓词。** `where` 只能引用 Event 已暴露的字段——**这才是层② 与层③ 真正的接缝**。字段已存在时，加谓词只是 `dag_spec.py` 几行声明式代码：零 detector 改动、零风险，且新阈值**立刻进入零 detect 增量的免费快车道**。

现状大量已暴露字段完全没被用（计数字段、children 聚合、点事件的全部字段、所有事件的 `start_idx/end_idx` ⟹ 跨度）。现成脚手架已存在：`path2_apps/try_conplex_where/` 是带完整文档的 where 沙盒。

**层 2a = 常量提参。** detector 里的模块级常量与硬编码字面量提成参数是**纯机械改动**，立刻新增可搜索旋钮，且默认值不变时可用**零 DIFF 验证**。

> **层② 应细分三档**：**2a 常量提参**（机械）/ **2b 判据微调**（有摩擦：判据常是模块级私有函数，子类无法 override，只能 monkeypatch 或复制）/ **2c 新建 detector**（最贵）。当成一档就会漏掉最便宜的 2a。

⟹ **层 2.5 与 2a 是「LLM 出结构 + 机器出数值」最干净的分工点。**

### 通道 C · LLM 读失败归因 —— "让 claude code 介入"的答案

这条通道的关键洞察是：**批量诊断需要的数据早就在算了，只是被丢弃。**

- 评估器每次全宇宙扫描都会完整算出失败轨迹并 attach 到结果上，但下游只读 `matches`，**失败记录从不离开 worker**（代码注释自己写着"此路径目前无消费者"）。**⟹ 做批量归因不需要新 instrumentation，只需要停止丢弃**，detector 一行都不用改。
- 失败记录自带 **`code_location`（源码行号）+ `threshold_param`（对应的 yaml 参数名）+ `measured`（实测值）**。**⟹ LLM 顺着 `code_location` 去 Read 源码就介入了——不需要断点、不需要 IDE、天然可批量。**

> **⟹ 这条通道的方法论版本（比上面的具体发现更可复用）**：
> **在讨论"要加什么新 instrumentation"之前，先查有没有既存但未被消费的诊断通路。**
> 一个成熟系统里，失败信息常常已经被算出来了，只是没人接线——这比新增埋点便宜一个数量级，且零风险（不改判据、不改语义）。查法：搜索 detector / 引擎里"算了但没进返回值"的中间量，以及带 `TODO`/"目前无消费者"这类注释的字段。

**三条格式纪律**（都踩过坑）：

1. **输出形态是「根因直方图 + 钻取」，不是「每票一行的排行榜」**。gate 名称在整个库里只有十来个取值——一张十几行的表比几十条散文信息量大、token 还少。
2. **排序键不能用计数**（计数会把结构性噪声顶到榜首），要用 **计数 × 近失占比**。
3. **近失占比必须先做尺度归一**。诊断字段常是裸价格差，$5 的票和 $500 的票不可比。**试跑时两个 gate 的优先级在归一前后发生了反转**——裸口径完全看不出来。
4. **补 `threshold_param` 埋点时必须同时声明量纲**，否则这座"判据→参数键"的自动桥会**自动生产出跨股票不可比的参数**。

## 5. 阶段 2 · 评估与判定

### 闸阵（绝对闸，不做比较，不累积选择偏差）

| 闸 | 内容 |
|---|---|
| 硬门 | 样本量下限、下尾分位数、label 自检一致 —— **但每道门都要过阶段 0 的 f 项体检**，淘汰率接近 0 的门不算防护 |
| **因果可容许** | 见 §3 |
| **标注否决** | 见 §6，粗粒度二值 |
| **回归误伤** | 与改前 baseline 对拍，`added`/`removed` 两侧分布并排看，必看 `unchanged_count` |
| **两窗不崩** | 两个不相交时间窗都不能崩 |

### 判定纪律

0. **先算 `ρ_rel`（§1.1）决定本轮用哪套规则。** 秒级，且它决定下面两条哪条生效。**跳过这一步就是在凭感觉选方法论。**
1. **`ρ_rel < 0.2` ⟹ 绝对闸优先，幸存者按奥卡姆取**（结构更简单、样本量更大的那个）。**零选择预算消耗。**
2. **`ρ_rel ≥ 0.2`，或确实必须排序**（多个都通过、只能上一个）：
   - **记 K**，按门槛表报出对应的选择门槛
   - **两窗最差分为默认判据，禁止退化成单窗**。它是最有效的抗过拟合装置（试跑实测：把选择门槛砍掉 30~48%）
   - 估计量改进：`worst_score` 是次优的，应改为**"逐年减各自基线的 lift 再平均"**（配对 SE 降 37%）
   - **参数层取平台中心而非 argmax**——平台中心是收缩估计量，噪声按邻域点数开方衰减，且舍弃"恰好撞高"那一点。响应面上没有平台、只有尖峰的候选**直接淘汰**（这本身是一道免费的稳健性闸）
3. **一律配对比较**：同一批标的上评估所有候选（公共随机数）。参数邻域的配对能把方差缩 4.5 倍；结构候选几乎缩不动（命中样本重叠度极低）——**知道哪一层能缩、哪一层不能，比统一用边际方差重要**。
4. **公平性要求：结构候选必须跑完自己的内层参数搜索才准进比较。** 用未调参的分数判结构生死是**单向有偏**（只低估、不高估）⟹ **系统性毙掉好结构**。

   好在内层廉价：where 层配置的批量评估可以通过"detect 一次、solve 多次"降到几十分之一，且**结果逐字全等**（是精确复用，不是近似）。而且同一族的阈值候选通常是**单调嵌套**的，贡献的独立自由度远小于候选数，不会把有效 K 炸掉。

### ledger（跨 session 持久，append-only，进 git）

至少记：K 计数、每次查询用的窗口、holdout 解锁状态、每个候选是否完成内层调参。

**为什么 ledger 不是冗余功能，而是自洽性前提**：统计闸要求"K 由记账得来"，但**每次 skill 调用都是 fresh session，没有跨 session 的记账物，K 就无从数起**。任何"用 K 调整门槛"的方案，没有 ledger 就是空话。

**⚠ 机制层给不了帮助**：workflow 的 `budget` 是 **token 预算**，不是查询次数预算；`pipeline()` 无预算语义。**没有任何原生机制能强制"目标函数只被查询 N 次"**，必须靠落盘 ledger 自己实现。

## 6. 阶段 3 · 人在环

### 人类判断的三个用途（均不进优化循环，均不消耗目标函数的查询预算）

| # | 用途 | 需要多少标注 |
|---|---|---|
| ① | **诊断条件化过滤器**（把海量失败轨迹坍缩成一条可执行诊断） | **N=1 就有用** |
| ② | **单向否决闸**（"不许弄丢这些样本"） | N=10–30 |
| ③ | **候选生成的语义来源** | 不限 |

### 为什么绝不能当目标函数（结构性理由，不是统计理由）

`score` 有**减基线保护**——退化成基线时 lift ≡ 0，摆烂刷不到分。
**而 recall 没有：把过滤全放开，标注样本全命中，recall = 100%。**

⟹ **recall 进目标函数时，最优解本身就是退化解。** 这比"N=20 太吵"致命得多。

### 否决闸的协议

**为什么不可刷**：只能否决、过闸不加分 ⟹ **没有可攀爬的梯度**。

**但它会误伤，所以不能自动 reject**——闸会否决掉一个"合法地找到了更好机会集"的候选，因为标注编码的是用户**当前**的直觉。协议必须是**阻塞 + 归因 + 人裁三选一**：

| 人的裁定 | 动作 |
|---|---|
| **实现偏离**（判据被改坏了） | 必修，撤销或修正 |
| **设计偏离**（换了个更好的形态，我认） | 接受，**并更新标注集** |
| **存疑** | 撤销改动，标注不动 |

> 与"旧实现当 golden baseline 是体检仪不是设计裁判"同构。**附带好处：标注集从"一次写死的公理"变成"随用户意图演进、留痕的证据集"，因此它不需要是无误差真值，只需要是可被复核和修订的证据**——这把"人的判断可靠性"从一个必须测量的风险，变成一个不必依赖的假设。

### 标注集也会被消耗，只是慢

用同一组 20 个标注去筛 1000 个候选，就是在向这 20 个样本做选择。三条推论：

- 闸必须**粗粒度二值**（"全保住 / 没全保住"），**禁止做成"保住了几个"的连续分**（连续分泄漏快得多）
- 标注集也要计入查询次数
- **降低候选数同时保护两道闸**

### 红线

- **人提候选、人有否决权，但人从不排序。**
- **送到人眼前的队列，其排序口径必须与目标函数一致**——否则会悄悄把最贵的资源（人的注视）投在错的地方，**且不留痕迹**。
- **人的输入必须与目标函数正交**（形态语义）。用 score 相关量决定人看什么会破坏正交性——**而正交性正是"人类收窄候选能真实降低选择门槛"的合法性前提**。
- **人擅长相对判断、不擅长绝对判断**。判定设计成"与基线对拍"（抽 N 个已定案配置的命中让人判得基准率，新候选显著劣于基准率才拦），而非绝对阈值。
- **不要把"必须先标注"写成硬前置**——纯边距分析在零标注下已被实证可用，强制标注会卡死冷启动。

### 预算与两个静默陷阱

**硬预算：单次定案周期 ≤20 个人类判定 / ≤20 分钟。**

依据有三条，**没有一条是"收益递减"**（这点初稿写反了，见下）：
1. **人时线性不可压缩**——每个判定的成本恒定，20 个就是 20 个的时间，不会摊薄
2. **疲劳阈值**——连续判定的质量会掉
3. **标注集会被消耗**（本节上方那条）——判定次数直接进消耗账

> **⚠ 又一次转述失真，出现在本报告自己身上**：初稿写"依据不是疲劳，是实测的收益递减"。
> 两处都错：① 那个实测（四种廉价结构信号收窄"该看哪些"只有 1.0~1.77 倍）说明的是**命中率恒定**，即边际收益**恒定**，不是递减；② 原始表述是"**不只是**疲劳，**更是**……"，被压缩成"**不是**疲劳，是……"，**把唯一站得住的理由删掉了**。
> 这正是 §附录 B.2 第 3 条描述的那种失真——**转述丢的不是数字，是它的限定词**。

那个实测本身仍然重要，只是结论换个说法：**队列筛不动 ⟹ 第 200 次注视的命中率和第 20 次一样低 ⟹ 别设计"聪明排序省人力"的环节。** 原因是结构性的：节点存在性几乎无信息，选择性几乎全住在边约束的合取里。

**陷阱 1**：标注**存日期不存 bar 索引**。bar 0 = 当次加载窗口首根，随起始日期与缓冲变化——存 bar 下一轮会**静默错位**（不报错，只是指向别的日子）。
**陷阱 2**：**verdict 持久、attribution 按 params hash 失效**。"这是横盘后启动"是价格行为的事实，改参数不会让它变；"死在 gap_max"只对某组参数成立。⟹ **瞬时操舵文件与持久 ground truth 必须是两个文件。**

## 7. 阶段 4 · 定案与 holdout

**先盘清数据的真实边界**——这一步经常被跳过，而它决定了整个方法的天花板。试跑时实测出两条：

- **数据跨度有硬边界**，所有标的的首日相同 ⟹ "加数据把 n 提上去"这条出路有明确上限。
- **数据集是纯幸存者集合**（退市标的一只都没有）。⟹ 所有跨年结论都带**系统性向好**的污染。
  **两个方向性推论**：负面结论被**加强**（在对 pattern 有利的样本上都没测出优势，真实情况只会更差）；**越近的年份污染越轻**，所以最近的那段是数据里最干净的一段，最适合当终局 holdout。

**方案**：把可用窗分三类——
- **搜索窗**（2 个，留在循环里做两窗最差分正则化器）
- **终局 holdout**（最近的那段，**全生命周期只解锁一次**）
- **备用窗**

⚠ **终局窗要扣掉两头的缓冲**（首部指标 warm-up + 尾部 label 前瞻），**先算它还够不够过样本量硬门**。

> **本项目实测：不够。** 数据实际覆盖 2021-07-16 ~ 2026-07-13；按推荐切法，终局 holdout 只剩约 **3.5 个月**，按搜索窗 n=423 线性推算 **n≈120，过不了 n≥200 硬门**。
> ⟹ **规格里已写死分支**：`gate_mode: full`（够 n，报完整统计）/ `sign_only`（不够 n，只报"没崩/崩了"这个符号判断，不报数）。
> **落地第一件事是实测这个 n，不要照抄推算值**——这个数决定终局验收能说到什么程度。

### holdout 的强制方式，按可靠性排序

1. **数据通路隔离（最强，零绕过面）**：搜索 harness 只拿得到搜索集的 `data_dir`，holdout 走另一入口由人跑。**拿不到的数据不需要被禁止访问。**
2. **自惩罚记账**：用 `σ·E[max_N]` 把 holdout 做成账户——查得越多门槛越高。不需要人的自律，失败模式是温和退化而非硬失效。
3. ~~hook 强制~~：**拦不住脚本内部读文件**，是卫生机制不是安全机制。

### 一条会改变判断的诚实边界

试跑实测：**搜索窗上看到的提升，在另一个窗只兑现 3%**（这个数是硬的）。

> **⚠ 本报告曾在此处犯过一次它自己在批评的错误，保留在这里当教训**：初稿写"显著配对的跨期符号一致率只有 33%，比抛硬币差"。复审重算：那是从 **15 个配对**里挑出来的子集，5/15、双侧 p≈0.30，**与 0.5 无法区分**；而**全部 253 个配对的一致率是 69.2%**，`Spearman(窗A, 窗B) = +0.446 (p≈0.03)`——**是正的**。
> 初稿挑了最戏剧的子集、隐去了两个反向的数。**这正是全文在批评的"在噪声里读符号"。**

⟹ 修正后的表述：**holdout 的价值在于它会告诉你"搜索窗上的提升有多少能兑现"——本次是 3%。** 这个数低到足以作为停止搜索的信号，但它不等于"排序信息完全不跨期"。

## 8. 机制映射：claude code 用在哪

### 8.1 总答案：没有任何机制"擅长在批量数据中优化代码"

八个机制（skill / subagent / agent team / workflow / ralph-loop / background agent / hook / cron）**全都是「编排 LLM 回合」的机制，没有一个会评估候选**——评估永远是外部进程。**所以这个问题问错了。**

正确的问法是"回路里哪些是 LLM 回合、哪些是确定性代码"。这个问题的唯一答案是 **Workflow**（唯一让 JS 控制流 + 结构化 agent 返回 + 每 agent 独立上下文在同一个程序里组合的机制）。**但按 §1 的结论，本问题现在还用不上它。**

### 8.2 三条设计律

> **① 强制只能施加在「在强制边界上可见」的东西上。** 想让某个不变量可被机制强制，就得先把它抬到那个边界上——**机制能力反过来约束接口设计**。
> **② 能做成「不可表达」的，就不要退而求其次做成「检查」。**
> **③ 没有判断的地方，不要放模型。想让一个 agent "足够笨"，最笨的办法是不用 agent。**

**律 ② 的三个用法，一个比一个省事**：

1. **不可表达**：想强制"不许单窗打分"，不是加检查，而是让 `score()` **只接受多窗输入、只返回最差分——单窗打分函数根本不存在**。
2. **抛异常而非警告**：因果可容许闸写成断言，不是 `print`。
3. **★ 让遗漏自动显形为缺席，而不是靠检查去发现遗漏**：例如归因榜规定「**未声明量纲的 gate 直接落进 `excluded_no_unit`，不进榜**」。想让自己的 gate 被看见，唯一的办法就是去声明量纲——**没有人需要检查谁没声明，缺失自己就暴露了**。
   这一条比前两条更值得学：它把"合规"从**成本**变成了**进入门票**。凡是能这样设计的地方，都不需要强制机制。

**⚠ 律 ② 有一个高频误用，必须给出可操作形式**：它**不是**"不要有开关"。

> **律 ② 的可操作形式：不要新增一条通往错误的表达路径。判据是相对现状的净增净减，不是有没有开关。**

同一份规格里的两个开关，一个该加一个不该加，用这条判据一算就清楚：
- **该加**：把选点默认从 `argmax` 改成"平台中心"、`argmax` 降级为需写明理由的 opt-in ⟹ 错误路径**净减少**。
- **不该加**：给"单窗排序"加一个受支持的模式开关 ⟹ 它现在只是"不是默认输出"，加了开关就成了一等公民 ⟹ 错误路径**净增加**。

**三条的共同内核，可以当一句话记**：

> **把该发生的事，挂到必然会到达的位置上——而不是写成一句提醒。**

本报告里这条被用了三次：`unit` 未声明就不进榜（§8.2）；`ρ_rel` 低读数**强制**触发分诊（§1.2b）；缺阶段 0 结论就 raise、跑不下去（§9）。**每一次都是把"要记得做 X"改写成"不做 X 就走不到下一步"。**

**律 ① 的一个真实因果链**（值得记住，因为它说明这类问题是自己造成的）：hook 之所以看不见"这次评估用的是哪个时间窗"，是因为本项目"入口脚本不用 argparse、参数写在 `main()` 里"这条规范**把窗埋进了函数内部**，工具边界上看不见它。⟹ **想让它可强制，就得把窗抬到 env 或 CLI 上。**

一句话：**机制不是用来"跑循环"的，是用来"让错误做不出来"的；而没有判断的环节，根本不该有模型在场。**

### 8.3 「记得问用户」不会自动发生 ★ 为什么需要工作流而不是更好的建议

核实到的事实：一份既往研究里那句「需要用户提供 2-3 个具体漏检样本做 replay 验证」，**被三个不同 agent 在四处独立写下，然后全部落空**——一次都没发生。

⟹ **写进报告的建议不会被执行。人在环必须有机制承载。**

这是"为什么需要工作流"的唯一强论据，也是每个设计的验收标准：**每个步骤都必须回答"这一步靠什么机制强制发生"。"文档里写了要做 X"不算答案。**

**⚠ 一个必须坦白的自指弱点**：任何"落盘阻塞文件 + 每次调用先检测它"的方案，**本身也是一条约定在强制另一条约定**。唯一的缓解是把检测放进一个**物理入口**——`authoring-path2-app` 的 Step 0 是主会话 inline 且 `AskUserQuestion` 天生阻塞，是目前能找到的最接近强制的位置。**这个弱点不该被掩饰**；若认为缓解不够，宁可让方案缩水到只剩记账，也不要假装它是强制。

### 8.4 反面清单

| 机制 | 为什么在这里不该用 |
|---|---|
| **ralph-loop** 当搜索循环 | 收敛判据由模型自我裁定 + 无结构化台账 ⟹ 每轮把大量结果重灌上下文 |
| **cron** | session-only + 只在 REPL idle 时 fire + 有效期短，连"每晚跑一次"都做不到 |
| **hook** 当强制 | 是护栏不是引擎；拦不住脚本内部行为 |
| **agent team** 当搜索循环 | 无控制流、无 schema、无 resume，成本 ×N |
| **让 agent 直接读结果 JSON 挑最优** | 一份结果就 ≈25k token，且 LLM 排序不可靠。**大批量数值必须落盘由脚本聚合，agent 只读摘要** |
| **fan-out 并行评估** | **伪并行**：单个全宇宙 eval 已吃满 CPU，K=2/K=4 并发实测都比串行更慢。fan-out 的唯一价值是编排简化 |
| **background agent 跑长任务** | 它只需要"发起 + 轮询 + append ledger"，**没有需要判断的东西**。用 `nohup` 裸脚本 |
| **多保真度 / successive halving** | 判死。事件流缓存不是低保真档而是**精确降价**（结果逐字全等）；唯一真正的低保真档是抽样子集，而它**在关键区间失效**（真 top10 内秩相关崩到 0.47，真 top3 召回仅 66%） |
| **照搬大 trial 数的贝叶斯优化** | 参考实现的 trial 数是建立在"目标函数只有两个 numpy 操作"之上的；且参数层已搜穿，TPE 全在拟合噪声 |

### 8.5 三个实测坑（写工作流脚本时会踩）

1. **Workflow 的 `args` 被整体序列化成 JSON 字符串**（官方文档说 verbatim，实测不是）。模板必须写 `typeof args === 'string' ? JSON.parse(args) : args`。
2. **用 `node --check` 验证 workflow 脚本必须用 `.mjs` 扩展名**。用 `.js` 会因 CJS 解析**静默放过顶层 `return`**，给你假绿。
3. **动态模块重导入会静默串版本**（fork 型进程池）：已 import 过某模块名的 worker 把旧版本留在自己的 `sys.modules` 里，导致同一批候选评估**静默混用两个版本的代码**——不报错、不崩、结果是两版的混合物。**单次调用是假绿，连续 ≥6 次覆盖才暴露。**
   **修复**：每个候选用唯一模块名，永不重用。

> 第 3 条是本项目**第三次**出现"平凡场景测试通过、多候选差分才暴露"的同型缺陷。
> **⟹ 通用规则：凡是要批量评估 N 个候选的 harness，其自身正确性必须由「多候选差分自测」证明；单候选冒烟测试一律视为未测。**
> 最小形式：跑 N≥6 个已知应当互不相同的候选，检查 ① 结果集合基数**等于** N ② 每个结果与单独跑该候选时逐字一致。
> **"唯一模块名"是修复，这条是验收，两者都要**——修复对了但没验收，换个实现方式又会静默复发。

## 11. 这套方法本身的局限

- **本次把"优化"落到了"排除"上，但那是 `ρ_rel` 的读数决定的，不是方法的主张。** 而且那个读数有两层已知缺陷（§1.2）：它是用一把已被证伪的尺子量的，且作用域只覆盖机械邻域、没覆盖 LLM 生成的新判据。**⟹ 修好目标函数之后必须重算 `ρ_rel`；档位一变，排序类工具（贝叶斯优化、多保真度、K 调整门槛）就该回桌。** 本报告的反面清单（§8.4）里对它们的判死是**条件性的**，不是永久的。
- **阶段 0 的七项检查是从一次试跑归纳的，不是穷举。** 它们覆盖了"尺子度量错东西"的几种已知形态，但一定有没想到的。**其中 g 项（波动率暴露）就是试跑到一半才被逼出来的**——最初的六项里没有它，是补测发现"92% 的 label 方差由一个波动率倍数解释"之后才补上的。**这说明这张清单还会长。**
- **⚠ g 项自己有一个未分离的混杂**：全宇宙收盘价中位数只有 $13.8，**低价股与高波动高度共线**。所以"这是一个波动率选择器"与"这是一个低价股选择器"在本次分析里是**同一件事的两种说法**，没有被分开。两者的交易含义完全不同（前者关乎风险敞口，后者关乎流动性与可执行性）。**这是整份报告里最值得后续追一刀的地方。**
- **"删除通道"这个盲区是从三个样本归纳的**（三条独立设计的候选生成器都缺它）。三个不算多，但它有机制解释，不只是巧合。
- **机制层的强制能力有上限**，而 §8.3 那个自指弱点没有干净的解。任何声称"完全强制"的方案都值得怀疑。
- **本方法没有解决"如何生成好的语义候选"**。它只能保证坏候选被挡住、好候选被公平比较。**候选质量的上限仍然由人和 LLM 的领域理解决定**，这一段没有被自动化，本研究也不认为它应该被自动化。
- **⚠ 所有机器侧强制都挂在 evaluator 上，因此有一条零覆盖的旁路**：人直接改 `params.yaml` 然后收工、不跑任何评估——本方法对此**完全无效**。这是边界不是缺陷（不跑评估就没有"结论"需要被担保），但不该被掩饰：**它意味着这套东西保护的是"经过评估的决定"，不是"所有的改动"。**
- **实施细节上有一处会误导实施者的坑**（现场核实得到，写在这里免得被埋进规格）：给 detector 协议加 `materialized_at` 时，**Python 3.12 下 `runtime_checkable` 的 `isinstance` 会把 Protocol 里任何属性纳入必须项**，所以新属性必须照抄本项目已有的 `TYPE_CHECKING` 守卫写法；**真正的运行时强制来自 evaluator 里那句无默认值的 `getattr`，不是 Protocol**。以为 `isinstance` 会替你把关，就会漏。

### A.4 跨股可比性：lead 的假设被审计推翻，真缺陷类在更深一层

- ❌ **lead 的假设**（"价格量纲的量与跨股票共享常数比较"）**有零个实例**。全库没有任何绝对价格阈值。裸价格差只出现在**诊断字段**里，判据本身量纲自洽。
- ✅ **真缺陷类**：**价格-尺度无关（比率）≠ 跨股可比，因为比率仍然携带「波动率尺度」。** 固定的百分比阈值对低波动股与高波动股含义完全不同。**这也解释了为什么只看量纲扫不出来。**
- 审计出 5 个固定比率实例，**其中 3 个在流源节点上** ⟹ 影响连锁传导到整条链。codebase 里已有正确写法的典范（×ATR、÷自身基线、÷本根振幅）。

**⚠ 补测回来了，推翻了本节两条主要说法和 lead 的一条**（实测，含零-DIFF 自检：归一化实现的 `fixed` 模式必须逐字复现原结果，否则实验作废）：

**① 五个并列是错的，效应量差一个数量级。** 主犯只有一个：`bo.min_relative_height`（0.2），剂量-反应干净（0.05→0.92x / 0.20→1.56x / 0.60→2.75x 波动率倍数）。而审计里被重点点名的 `exceed_threshold=0.003` **几乎不产生偏斜**（0.0→0.05 只把倍数从 1.51 推到 1.72）。

**② 归一化只能解决一半，另一半没有量纲可归。** 把 `relative_height ≥ 0.2` 换成 `≥ k × rv63 × √window` 后，**bo 层的偏斜被完全消除**（1.56x → 0.96x，配平 n，两年一致）；但全 pattern 只从 2.46x 降到 ~1.8x——**另一半住在 `distinct_pk_min=4` 这类结构性要求上**（"8 根内打穿 4 个不同峰"天生就选快速运动的股）。**任何"按自身尺度归一"的修法都碰不到这一半。**

**③ ★ lead 说"这类修正是罕见的纯提 lift 杠杆"——被实测直接证伪。** 归一化后 score 从 +0.0719 掉到 **−0.0127**（配平 n≈423 后差约 **0.072**），而**波动率匹配后的真实质量几乎不变**（条件百分位差 ~0.035，t≈1.6，不显著），先涨残差全在噪声内。
> ⟹ **改量纲是诚实性修复，不是提 lift 的杠杆。** 而且它会**被目标函数重罚**——把归一化写成推荐动作，执行者会看到分数暴跌然后回滚。**诊断与处方必须分开：用 g 项验收，不要用 score 验收。**

**仍然成立的两条**：① 这是**语义选择不是技术错误**（判据本身量纲自洽，不是 bug）；② lead 那条"不消耗选择预算"要收窄——只在用户直接拍板一种形态时成立，把两种形态都拿去试就**照样进 K**（一般规律：**用与数据正交的信息做决定 ⟹ 不进 K；用数据挑 ⟹ 进 K**）。

**⟹ 这个选择长什么样，请原样交用户拍，不要替他拍**：

| 选项 | 它的意思是 | 实测后果 |
|---|---|---|
| **保持固定 0.2** | "我要的是**绝对意义上**走出 20% 台阶的形态" | 事实上主要在高波动股上开火；score 高，但那 0.072 分是波动率 |
| **改成自身尺度归一** | "我要的是**相对该股自己**罕见的抬升" | 命中集波动率回到全宇宙水平；score 掉到 ~0 |

**两条路都没有方向性优势。** 所以这不是"改了会更好"的选择，是"**你想要哪种形态语义**"的选择。**不能写成"应当自动改成归一"。**

**⚠ 而且不能用 score 在这两条路之间挑**——因为 score 在这条轴上度量的正是波动率而非优势，用它挑本身就是错的，不管进不进 K。**正确裁判是 g 项体检（绝对闸，不做比较，不进 K）。**

**⟹ 量纲审计仍值得做，但定位改为「让 score 变诚实」而不是「让 score 变高」。** 方法论条目不要写成"任何跨股共享阈值都必须归一"（只覆盖一半，且把诊断和处方搞反），**要写成阶段 0 的 g 项**（§3）——**g 项与偏斜成因无关，这一半那一半都抓得到。**

### A.4b ★ 目标函数上确实有一根"免费波动率杠杆"，而现任配置正踩在它的极值上

在真实搜索空间里**只动 `bo.min_relative_height`**（2025）：

| 值 | n | label 中位 | **score** | 波动率倍数 | **波动率匹配后 maxhigh 百分位** | 匹配后 hold 百分位 |
|---|---|---|---|---|---|---|
| 0.05 | 761 | 0.1234 | 0.0000 | 1.67x | 0.520 | 0.454 |
| 0.10 | 632 | 0.1570 | 0.0256 | 1.93x | 0.531 | 0.459 |
| **0.20（现值）** | 423 | 0.2293 | **0.0719** | 2.46x | 0.564 | 0.467 |

### A.5 批量诊断入口的三处硬伤（可直接对照修）

- **只覆盖"完全没命中"**（`if len(matches) > 0: continue`），看不见"命中在错时间 / 该命中 3 次只中 1 次"
- **丢掉 `threshold_param`**——那个字段直接写着该调哪个旋钮，加一行就能让输出可执行
- **漏检判据与目标函数口径不一致**（端点收盘涨幅 vs 窗内最高）⟹ 选出的是**大涨股**而非**该命中的形态**；"先大涨再全吐回去"的会被排到榜尾，而那正是"漏掉的机会"最典型的形态

### A.6 成本与规模的实测基准

| 项 | 值 | 证据等级 |
|---|---|---|
| 全宇宙 eval（7532 标的，官方路径） | 48–50 s | 真跑 |
| 换 `ex.map(chunksize=20)` 后 | 23–28 s | 真跑（1.7×，结果逐字一致） |
| 再修重复 ATR 计算后 | ≈8 s | **推算**（3.6× 已组件级验证，未端到端跑） |
| 独立交叉验证 | ≈26 s | 52.21 ms/标的 × 7532 ÷ ~15× 并行 |

**规划用 26 s。** 参数精确二分：**21 个 = 18 个 detector 构造参数 + 3 个 where 后置阈值**。

### B.2 上游转述比原始来源更不可信

三次"实测 > 文档"，性质递进：

1. **官方文档错**（工具契约说某字段 verbatim，实测被序列化了）
2. **lead 的转述错**（我说某字段的某种写法非法，实测合法；而**仓库里现存的模板早就在用那种写法**）
3. **teammate 转述 teammate 时丢失了认知状态**——最微妙也最值得记：那个数字**算术上完全正确**，错的是它的**证据等级**。原始测量里一半是端到端真跑、一半只是组件级验证，因此结论是**推算值**；转述一次之后，它变成了一个和真跑读数并列的数。

⟹ **纪律：lead / 上游 agent 的转述比官方文档更不可信，因为它多了一次压缩。**
⟹ **最省事的抓捕方式不是去跑探针，是去仓库里找现存的反例。**
⟹ **转述数字时必须连同证据等级一起转述**（真跑 / 组件级 / 推算 / 机制推断）。

> **⚠ 初稿在这里写了"本报告全文照此标注"——这句不实，已删。** 实际只有附录 A.6 那张表带了证据等级，§3–§8 的数字全是裸的。
> **这句自我表扬偏偏出现在主张"必须带证据等级"的那一节**，本身就是这条纪律有多难自觉执行的证据。留在这里当标记。
⟹ **对工作流的直接含义**：任何多层 agent 传递约束的环节都是错误注入点，**下游必须回到原始来源核实**。这与"绝不引用文档内嵌快照、要用就现场读代码"同构，只需推广到"也不引用上游 agent 的转述"。

### B.3 区分变量是「目标函数是否在环」，不是「候选由谁生成」

对照：
- **语义提名 + 目标函数裁决 = 成功**（某个旋钮之所以进消融名单，是因为一次**语义因果归因**先提名了它）
- **语义提名 + 无目标函数 = −79%**（一个全 opus 的 team 做了严谨的实证测量，但测的是**内部代理指标**——触发率 / 共线性 / gating 率，而不是目标函数；推荐的改动 10 天后被目标函数证伪）

**同一批人、同一种能力，差别只在有没有尺子。**

**但要区分两种代理用法**：代理**做决定**会选中坏候选（有效性损失，致命）；代理**做筛选**只会漏掉好候选（召回损失，可控且可量化）。上面那次失败是前者。
