# pattern 配置评分标准

判断「改了参数或判据之后，这个 pattern 是不是真的变强了」的统一口径。

适用于任何 path2_apps 下的 pattern 配置比较——调参、改 detector 判据、增删 where。
不适用于「某个特征是否与 label 相关」这类问题，那个走 `label-study` skill。

首次成文：2026-07-25（`2026-07-25_tb-recall-quality-tuning/final_report.md` 的方法论部分）。

---

## 1. 一句话

**score = 打了样本量折扣的、相对平凡基线的中位数超额。**

```
score = w · lift

lift  = median_配置 − median_基线
w     = n / (n + 200)
n     = 买点窗数（按 end_node 的 event_id 去重）
```

排序用 score，但**报告必须同时给出 lift 和 n**——score 是排序标量，不是业绩指标。

---

## 2. 为什么是这个形式

### 2.1 为什么必须减基线

不减基线，你优化的是"那一年行情好不好"，不是 pattern 本身。

真实教训：bottom_burst 在 2025 的 label 中位数是 0.1164、胜率 94.7%，看起来很漂亮。但同参数、去掉两道过滤的 bo_only 是 median 0.1234、胜率 93.6%——**过滤之后反而不如不过滤**。那 94.7% 的胜率只是这个 label 口径下的基率复读，不是 pattern 的功劳。

基线还必须**逐窗重算**。bo_only 自己在 2024 是 0.1159、2025 是 0.1234，市场本身有 +0.0075 的平移。基线跟着窗口走，这个平移就被自动消掉了。

减基线还有一个附带好处：把所有过滤全放开、退化成基线本身时，lift 恒等于 0。**摆烂刷不到分**——任何"改进"必须真的比不过滤更好。

### 2.2 为什么要收缩

小样本的中位数不可信。n=41 时中位数的抽样标准误约 0.032，一个看起来 +0.10 的 lift 完全可能是运气。

收缩的做法是让"信多少"跟着样本量走：n 小 → w 接近 0 → score 被拉向 0（等于说"这个数我不信"）；n 大 → w 接近 1 → score 还原成裸 lift。

`n₀ = 200` 沿用 `BreakoutStrategy/mining/pipeline.py::_shrinkage_score` 的在用值。它也有独立依据——n=200 恰好是能检出 +0.028（约基线 23%）lift 的量级，"在这里半信半疑"是自洽的：

| n | 中位数抽样 SE | 能检出的最小 lift（2 SE） |
|---|---|---|
| 40 | 0.032 | +0.063（基线的 51%）|
| 200 | 0.014 | +0.028（23%）|
| 800 | 0.007 | +0.014（11%）|

收缩相对"硬性数量下限"的好处是**没有悬崖**：n=199 且 lift 极高的配置不会被一刀砍掉，只是权重小一点。

## 3. 硬门（不进评分，不过即淘汰）

| 门 | 阈值 | 理由 |
|---|---|---|
| 样本量 | `n ≥ 200` | 取在 w=0.5 处，含义是"能进排序的配置至少一半信得过自己的观测值"。低于此连中位数都算不稳。|
| 下尾 | `q25 ≥ 0` | 挡住"抬高中位数、养出亏损尾巴"的配置。|
| 自检 | label 逐观测独立重算一致 | 数据链路唯一的正确性证明。失败即数据错位，先修再谈统计，**禁止注释掉检查**。|

硬门和收缩分工不同：收缩是连续惩罚，硬门是"算不出稳定统计量就别进排序"。n≥30 这类统计学惯例在这里太松——n=30 时能认出的最小 lift 要 +0.074，等于基线的 60%。

---

## 4. 防刷分：必带的对照列

label 是**买点窗内逐日均值**，而窗宽由 detector 的收窗逻辑决定。这意味着把窗收窄就能在窗数不变的情况下白拿一截 label——一个免费的刷分杠杆。

两条堵法，同时用：

1. **搜索期间冻结收窗规则**，只动产出判据与参数。要改收窗规则，单独一轮、单独论证。
2. **每个配置并报两列 label**：
   - `median`：窗内逐日均值（生产口径，与 web/`path2.eval` 一致）
   - `median_confirm`：只取买点窗第一天（`start_idx`）的 label，与窗宽完全无关

**排序一律用 `median_confirm`**，`median` 只作对照。两者背离就是窗宽在做功。

实战抓到过：`big_rise_k=3` 的窗均值最高（0.2187），但 confirm 当日反而更低（0.2073）——它的"优势"全部来自窗被拉长。只看窗均值就会选错。

---

## 5. 必报形状（不进评分，但必须可见）

只报一个 score 会掩盖结构性问题。每个候选都要与基线并排给出：

- 分位数：p10 / q25 / median / q75 / p90
- 负收益占比、买点窗数、买点日总数、平均窗宽
- outcome 分布（若 detector 有 outcome 概念）

**判定纪律**：若某配置在 q25 与 q75 上同时低于基线却宣称中位数取胜，视为中位数假象，不予采纳。

---

## 6. 禁用项

- **不得用买点之后才确定的量做筛选**。典型是 tb 的 `outcome`（rise/break/timeout）——它与 label 强相关（0.259 / 0.123 / 0.032），只留 rise 能把 score 从 0.0719 推到 0.0868，但 outcome 要等窗口关闭才知道，买入当天无从判断。这是前瞻偏差，实盘无法复制。
- 任何需要用到 `start_idx` 之后信息的特征，一律加 `posthoc_` 前缀单独报，不参与评分。

---

## 7. 复现口径（必须逐条对齐，否则数字不可比）

| 项 | 取值 |
|---|---|
| 宇宙 | `datasets/pkls/` 全集 7532 只 |
| 窗口 | 整年，如 `[2025-01-01, 2026-01-01]` |
| 切窗 | 双端缓冲：首部 `eval_meta.head_buffer_trading_days` 个交易日供指标 warm-up，尾部 `label_horizon` 供 label 可见；交易日→日历日比率 1.65 |
| 有效性 | 买点窗起点日期落在 `[start, end]` 内（前置组件可以伸进首部缓冲） |
| 去重 | 同 ticker 内按 end_node 的 `event_id` 去重——评估对象是买点窗，不是 match |
| label | `mean over t∈[start,end] of ( max(high[t+1..t+N]) / close[t] − 1 )`，N=20（`path2.eval.match_forward_returns`） |
| 参数来源 | `load_params()`（app 目录 params.yaml，SSoT），不要用 `Params.default()` |

**基线数值**（bo_only，同 bo 参数、无 burst/tb 过滤）：

| 窗口 | n | median |
|---|---|---|
| 2024 全年 | 23968 | 0.1159 |
| 2025 全年 | 29502 | 0.1234 |

换了窗口或换了 bo 参数，基线必须重算。

## 8. 跨期使用（可选，非硬门）

单窗口搜出来的配置本质上是拟合。若要提高信心，把候选拿到另一个整年窗口重跑，按**两年最差 score** 排序，两年都必须过硬门。

这条不是硬性要求（用户可以选择只在单窗口优化），但它能分辨出一类问题：改动前的 bottom_burst 在两年之间符号翻转（2024 +0.007，2025 −0.001），而定案配置两年都稳定为正且排序一致。这种一致性不能证明外推有效，但不一致几乎肯定意味着有问题。

注意诚实边界：在已知一个窗口结果之后再跑另一个窗口，**不是真正的样本外**。真正的验证需要未来数据。

---

## 9. 读数注意

- **score 不是收益率**。定案配置 2025 的 score 是 0.0719，但真实超额是 lift 的 0.1059（约 10.6 个百分点的中位数差）。score 只用于配置之间排序。
- **label 系统性上偏**。20 日 max-high 口径假设你能卖在窗口内最高点，不能当收益预期。它适合做相对比较，不适合做绝对承诺。
- **lift 可能包含入场位置的算术效应**。若配置 A 的买点在回踩低位、基线的买点在突破高位，分母更小自然 label 更高。这是真实的交易优势，但属于"入场时机"而非"选股能力"，报告里要说清楚。
- **观测非独立**：同一 ticker 会贡献多个买点窗，且全市场共享同一段行情。分位数与胜率都受此影响。

## 10. 一次完整比较长什么样

```
配置              n     median  conf    q25     score   gate
现状              41    0.1164  0.1164  0.0354  -0.0012 FAIL(n)
K0                577   0.2151  0.2107  0.0795  +0.0649 PASS
K0+mb1+pk4        423   0.2333  0.2293  0.0793  +0.0719 PASS   ← 定案
K0+mb1            912   0.2103  0.2043  0.0771  +0.0664 PASS
K0+pk4            285   0.2401  0.2401  0.0934  +0.0686 PASS
```

排序看 `score`（基于 `conf` 列算），但 `median` 与 `conf` 的背离、`q25` 是否守住、`n` 够不够，都要一眼可见。
