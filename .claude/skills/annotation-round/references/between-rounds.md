# 两轮之间：用户在流程外做的决定

交还（SKILL.md 第 9 步）之后、下一轮定格之前，用户不经网页、直接在对话里对这一版做决定时读。比如「阶跃应该算到 11-25」「这种冲高回落的以后别买」「下一轮改成……」，同一会话里接着说、隔天在新会话里说都算。每次记一个决定之前先读本文件；上下文被压缩过、或这段讨论已经拉得很长时，先重读再记。

这里的决定只记下来、提议改定义，不改 app：app 一律在下一轮定格之后再改（红线 1），否则下一轮没有改之前的对照。

## 1. 认出是决定

用户表了态的才记：「就这样」「同意」「以后都……」「下一轮改成……」，或在你给的几条路里选了一条。他在提问、想弄清楚、和你推敲时只回答，不记。只调参数取值的转 `tune-gates-v3`，不记。

## 2. 对上图

一个决定要对得上这个 pattern 已有标注的股票：有样本或反馈的股票才会被每轮的对照跑到，别的股票改完看不出改对没有。

- 他的话、或这段讨论里已经指着具体的股票和日期，而这些股票有标注 → 记下这些股票和日期，它们是下一轮要核对的考题。
- 没指着任何一张图，或指的股票没有标注 → 请他指出在哪几张图上看到的，在页面上放一个样本或写一条反馈，等标了再记。

## 3. 记进会话记录

在 `path2_apps/<app>/mapping.yaml` 的会话段 `conditions` 里当场记一行（格式与三种会写坏整份文件的笔误见 [ledger.md](ledger.md)「写法」）：

- `where`：拟落的位置（`node.where 名`；切法写 `node.cut`；还不知道落在哪写拟用的名字）。
- `from`：有关的反馈、样本编号；没有就写 `[]`。
- `state`：`"pending <日期> 两轮之间用户定：「<原话>」；图：<股票 日期、股票 日期>；待下一轮实施"`。讨论里谈出的细节（几条已定的结论、各自的例子）一行写不下时，写进最近一轮目录下的 `<最近一轮去掉 .json>.after.md`，这一行末尾写「细节见 <文件名>」。

他改主意、或这次决定改的是已有的某一行，就在那一行的 `state` 后面接着写，开头词换成现在的，不另起一行。

写完跑 `uv run python .claude/skills/annotation-round/scripts/round_state.py`，这个 app 那一行的「mapping 问题」「会话段问题」都是 None 才算记好。

## 4. 对照定义，提议改定义

定义是用户的话，只用他自己说出内容的话来改。

**每个记下的决定都先和定义原话对一遍**，不论下面属于哪一类：和定义里某句相反（不只是补充）时，点出那一句。相反的那句不能留着——下一轮归类、出题都要读定义，一句和他现在想法相反的旧话会把会话带偏。

按他的话分三类：

| 他的话 | 怎么办 |
|---|---|
| 自己说出了内容（「阶跃是一串，冲高那根也算」） | 原话照用，提议写进定义；和某句相反时，用它替换那一句 |
| 针对某张图说的（「QBTS 11-25 那根也算阶跃」） | 你按他的原话起草一句通用的话，注明出自哪句、哪张图，请他认可或改写；相反时同样替换 |
| 只是在你给的选项里选了一个（「同意」「按推荐」） | 不进定义：内容是你写的，写进去就是把 app 反过来翻译成定义。只记在会话记录里；和某句相反时，请他用自己的话重说那一句，或同意删掉它 |

**改在原处，不往后追加**：决定改的是定义里已有的意思（相反、收窄、放宽、说得更准），就改写那一句，旧说法不留；原文没涉及的才新加，放进相关的那一段。不在末尾写「补充：……」「更正：……」。定义只反映他现在的想法，不记历史（存储层的旧批次文件是两台机器同步用的，与此无关）。

具体做法：
1. 给他看现在的定义全文和改后的全文，标出改了哪几处、每处出自他的哪句话（删掉的标「你同意删掉」）。
2. 他同意了再写。先预览，确认无误后加 `--write` 写入：

   ```bash
   uv run python .claude/skills/annotation-round/scripts/write_definition.py <P> <新定义全文所在的文本文件>
   ```

   它和网页保存走同一个写入函数，新写一个批次文件，不改已有文件。写之前请他别在页面上同时改定义（后保存的会盖掉先保存的），写完请他刷新页面。
3. 写完在那一行 `state` 后面接「；<日期> 已写进定义」。下一轮摘要的「上一轮以来的变化」里会出现这次定义改动：账本里有这句话，就不再拿它出题。

他不同意改定义，就不改；决定照样记在会话记录里，下一轮照办。

## 5. 下一轮怎么接

下一轮第 2 步的摘要会列出这些 `pending` 行；第 3 步把它们放进清单第一段（用户已经定了，不再问）；第 7 步逐条交代兑现了没有；第 8 步把这一行开头词改成现在的去向（照 [ledger.md](ledger.md)），接着写「第 N 轮实施」。
