## 0. 结论

- **一个买点 = 一个 instance，买点存一份「成员框」清单**。默认由界面推断（从买点往前、隔得不远的那一串框，连同被它们包住的框），只在放买点那次停留里生效、离开这张图即冻结；推错了在买点的 edit 栏点名称块改。**不存范围、不拖边界**。
- **主图上 pattern 的边界就是 bracket 轨（`path2_web/GLOSSARY.md:45`）上的一条虚线**，从最早的成员画到买点，右端挂和主图同形的三角（实心 buy、空心 no_buy）；它由成员派生，标注模式下常驻。不在任何 bracket 下面的框就是「只标事件」——用户截图里左边那个孤立的框自然落在外面。对照时 app 的 match bracket 用实线画在同一条轨上。
- **点 bracket 或买点 = 选中这个 instance**：成员框加粗，其余框变淡，主图上两条竖虚线标出起止。这照搬主视图「点 bracket 高亮这次 match 的事件」，只多了「其余变淡」。
- **关系不设编辑器**：先后看位置，属于看框套框（已定 2），不靠位置的关系写成后一个框的属性（会话翻成后一个 node 的 where，见 topo.md 第 3 节）。名称轨的上下顺序按当前 pattern 里各名称的平均先后排，所以一个 instance 在副图上读起来是一道从左上到右下的台阶——先后关系不用任何额外元素就看得见。
- **侧栏 summary 改名 pattern tab**，管跨图那一层：pattern 的一句话定义；elements（一条竖排的名称胶囊链 = 骨架和对应表合成的一张，每个名字一行、带「出现在几个 instance 里」，有 app 时同一行加「由谁来认、认出几个」，相邻两行之间的 ↓ 挂 link 计数）；groups（按顶层成员名称序列分组，每组一个「→ pattern」下拉，「未归类 → 起名」和「拆出归错的」都用它）。
- **现有拓扑面板（`path2_web/GLOSSARY.md:50`）不进标注模式**，看图模式照旧。复用的是它的画法（左→右读先后、包含挂在下面、虚线 = 用户的），不是组件，也不是布局函数。

## 1. 标注全过程里会遇到的场景

| # | 场景 | 用户此刻要知道 / 要做的 | 推荐方案下看到什么 | 要做的操作 |
|---|---|---|---|---|
| S1 | 第一张图，还没有任何 pattern | 画框、放买点；买点挂「未归类」 | 放下买点的同时 bracket 轨出现一条虚线，盖住它前面那一串框 | 看一眼 bracket 盖得对不对；对就零操作 |
| S2 | 后续的图，已有 pattern P | 顶栏切到 P（先定目标阶段），照样画框、放买点 | 名称轨按 P 的先后排；bracket 同 S1 | 同 S1 |
| S3 | 一个买点前有几个框 | 这几个是不是这次买入的理由 | 选中买点：成员加粗、其余变淡；edit 栏 members 一排名称块，按先后、套框挂在父块里 | 推错时点名称块进出 |
| S4 | 两个买点共用一段框（再买一次） | 两个买点各由哪些框构成 | 两条 bracket 上下叠放，共用段被两条都盖住 | 第二个买点不想要第一段回踩：选中它，点掉那个块 |
| S5 | 只标事件、不挂买点的框 | 它不属于任何 pattern | 不在任何 bracket 下面；选中任何买点时它变淡 | 无 |
| S6 | 像但不买（no_buy） | 「像」的是哪几个框 | 同 S3，bracket 右端是空心三角 | 同 S3；不买的理由写 instance 注释 |
| S7 | 同一天两个 pattern | 各算各的 | 顶栏切到 B，在同一根 K 线再点一次，多一个属于 B 的买点和它自己的 bracket；非当前 pattern 的 bracket 整体变淡 | 一次点击 |
| S8 | 攒了一批「未归类」 | 哪些长得一样、算一个 pattern | pattern tab（当前 = 未归类）列 groups，每组一串名称胶囊 + 个数 + 买点列表 | 每组选「→ 已有 pattern」或「+ new」；点组里的股票日期跳到那张图核对 |
| S9 | 有了 pattern、会话写了 app 之后 | 我的 pattern 整体长什么样、每样东西由谁来认 | pattern tab 的 elements 竖链：名字、出现次数、属性、resolver、认出数、⚑ | 翻译不对点 ⚑；出现次数不对说明成员推错，回图上改 |
| S10 | 打开「对照 app」之后 | app 认没认出、连没连上、会不会在这买 | 主图：同一条 bracket 轨上 app 的实线 match；框旁 qualified / detected / missing；买点旁 app:buy / no_buy。选中买点：edit 栏成员块之间的箭头挂 ok / broken / pending（图上没有的只有这一样） | 看；let_go 照旧 |
| S11 | 同一买点前两段同名框，会话推不出角色（已定 3） | 哪一段是 | 会话的问题挂在这个买点上：edit 栏两个同名块带 `role?` | 点其中一块 = 「这个是」 |

## 2. 方案比较

七种根本不同的做法。「多几步」按一张图、默认推断对 / 错两种情况说。

| 方案 | 每张图多几步 | 要用户记住什么 | 消掉了哪种歧义 | 主图多了什么 | 和 app 的 match 显示能否一一对应 | 与已定 1～10 |
|---|---|---|---|---|---|---|
| **A. 存范围、拖左端**（lead 候选） | 对：0；错：拖一次 | 「范围里的都算」 | 孤立框 vs 一串。**消不掉**：夹在中间的无关框、再买一次时的第一段回踩、两个 pattern 时间交错；还新造一种：把成员往左拉长，它会掉出已拖过的范围 | bracket 虚线 + 左端拖柄 | 能（同轨虚 / 实） | 不冲突 |
| **B. 成员清单 + 默认推断 + 名称块改**（推荐） | 对：0；错：点 1～2 个块 | 无。bracket 底下就是成员；选中时被排掉的会变淡 | A 的全部，加上中间框、共用段、交错 | bracket 虚线；选中时加粗 / 变淡 | 能（bracket 同轨；成员 ↔ match 绑的事件） | 不冲突 |
| C. 先选买点、再在图上逐个点成员（无默认） | 每张图 = 成员个数次点击（3～5） | 「现在点框是在选成员」这个状态 | 同 B | 同 B | 能 | 不冲突，但每个框多一步，正是已定 3 想省掉的那种 |
| D. 套索圈选成组 | 一次圈 + 一次确认 | 圈选和拖框是同一块画布上的两种拖，要分清 | 名称轨上下排开，在时间轴上圈一块就等于 A 的范围，同样排不掉中间的框 | 圈出的轮廓 | 轮廓不是 bracket，对不上 | 不冲突 |
| E. 拓扑图当编辑器（面板上连名字、定 pattern 的结构） | 每个 pattern 连一次线；每张图把框挂到节点上 | 节点、边 | 关系的歧义 | 无 | 过度对应（直接就是 node） | 冲突已定 3、5（让用户想 node 和边）；面板和图上的位置是两个来源，会打架 |
| F. pattern 模板一键套到新图（预先摆出 P 的空名称轨或占位框） | 省掉选名字那一下 | 模板 | 名称选择 | 空轨 / 占位框 | — | 不冲突，但看着骨架标会把新规律挡在外面，占位框还容易被当成「看到了」 |
| G. 完全不显式、全靠会话推断 | 0 | 无 | 无（用户看不到推断） | 无 | 无 | 和用户原话的诉求相反（看不到边界）；已定 3「推不出才问」的前提是推断看得见 |

取 B 的理由：它和 A 在显示上完全一样（用户要的「边界」就是那条 bracket），差别只在存什么、怎么改；存成员能纠正 A 纠正不了的三种错，而默认推断让多数图上的操作数和 A 一样是零。C 是 B 去掉默认值，D 在时间轴上退化成 A，E、F、G 各自和已定或用户诉求冲突。

## 3. 推荐方案

### 3.1 主图

**示意（标注模式，选中了 2025-04-28 那个买点）：**

```
main     K 线 ……………………………┆………………………………┆……………………………………
                    ▲          ┆                ▲   △
                    buy        ┆                buy  no_buy
                               ┆                ┆
bracket       ┌╌╌▲           ┏━┿━━━━━━━━━━━━━━━━▲                 ← 选中：粗虚线、浅灰底
                             ┌╌┿╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌△            ← 像但不买，和上面共用前段
横盘                          ┏┅┅┅┅┅┅┅┅┅┅┓     ┆
缩量                              ┏┅┅┅┓ ⊂横盘   ┆
放量突破      ┌╌╌┐ (淡)                    ┏┅┅┅┓
回踩            ┌╌┐ (淡)                       ┏┅┅┓
```

- **bracket 轨**：标注模式下常驻。每个买点一条虚线，从最早的成员起点画到买点（成员越过买点时画到最晚的成员终点），右端三角和主图上的买点记号同形。时间上重叠的上下叠放。非当前 pattern 的整体变淡。没有编号、没有字。
- **选中**：点 bracket、点买点三角、点买点记号都选中这个 instance。成员框换粗虚线，其余框透明度降到约三成；主图上 instance 起点和买点各一条竖虚线。
- **名称轨的上下顺序**：当前 pattern 各 instance 里，这个名字在成员中的平均先后；不在任何 instance 里的名字排在后面、按这张图上最早出现排。一个 instance 读起来是一道台阶。名称轨顺序和 pattern tab 的 elements 顺序是同一个顺序。
- **框套框**：照原型，子框左下角 `⊂ 父名`。
- **对照开着**：app 的 match bracket 用实线画在同一条轨上（带主视图原有的圈号和买点三角）；框旁的状态签、买点旁的 app:buy / no_buy 签照原型。图上不画两框之间的 link——实测见第 4 节第 3 条。

截图：`ux_1_select_instance.png`（选中买点，成员加粗、左边那一串变淡）、`ux_2a_default_isolated.png`（53 天前的横盘默认不收、在 bracket 外）、`ux_2b_include_far_box.png`（点名称块收进来，bracket 跟着变长）、`ux_3_compare.png`（对照：用户的虚线 bracket 和 app 的实线 match ①② 同轨）。

### 3.2 侧栏

**edit tab，选中买点时**（原有的 pattern、label、instance 注释不变；原型里的 `role auto` 一行删掉——角色不手填不存，这一行用户既不能改也不用读，critic U7；下面加一段）：

```
members
 ┌横盘 ⊃ 缩量┐ → [放量突破] → [回踩] → ▲buy
others   [放量突破] [回踩]
```

- `members`：成员，按先后排，被包住的块画在父块的框里；块是用户的词（无衬线、深色、浅灰底），实线边。
- `others`：这张图上、买点之前开始、不是成员的框，虚线边。
- 点任何一块 = 进 / 出。悬停一块 = 主图上描出对应的框（同名两段靠这个分）。
- 不标「默认 / 改过」、不设「回到默认」：存的就是一份清单，没有一个会随规则变动的「默认」状态可回（critic F7）。
- 对照开着时，只在块之间的箭头上挂 `ok` / `broken` / `pending`。框的状态和 app:buy / no_buy 主图上已经有，这里不再挂一遍（critic U9）：

```
 ┌横盘 ⊃ 缩量┐ → [放量突破] →ok→ [回踩] → buy
```

**edit tab，选中框时**：不变（不列这个框属于哪几个买点——选中买点时图上就看得见，反查很少用；flow.md 4.1 同此）。

**pattern tab**（替代 summary；当前 pattern 由顶栏定）：

```
pattern  横盘突破回踩   app: bb_v1
定义    [横着走一段后放量越过前面好几个峰，回踩不破就买          ]
elements  n=4                                   new / old = qualified/n
 [横盘]       in 2/4   走势区段 sideways ⚠default_params  new 0/1   ⚑
   ⊃ [缩量]   in 2/4   unmapped                                    ⚑
   ↓
 [放量突破]   in 4/4   burst    new 1/2  old 1/1                   ⚑
     [放量] 3/3  [突破过好几个峰] 2/3  [突破前沉寂够久] 1/1 null 2
   ↓  ok 2  pending 1
 [回踩]       in 4/4   tb       new 1/2  old 1/1                   ⚑
groups  n=2
 │ [横盘]→[放量突破]→[回踩]   ×2  buy 1 app:buy 1/1 · no_buy 1 ▌app:buy 1/1▐   [→ pattern ▾]
 │  ┌────────────────────┐ ┌────────────────────┐
 │  │横盘    ▭▭▭▭        │ │横盘    ▭▭▭▭        │
 │  │缩量      ▭         │ │缩量      ▭         │
 │  │放量突破       ▭    │ │放量突破       ▭    │
 │  │回踩            ▭   │ │回踩            ▭   │
 │  │                ▲   │ │                  △ │
 │  └────────────────────┘ └────────────────────┘
 │ [放量突破]→[回踩]          ×2  buy 2 ▌app:buy 1/2▐                        [→ pattern ▾]
 │  （两张缩略，同上）
```
（`▌…▐` 表示反白的签：buy 里 app 漏买的、no_buy 里 app 误买的。）

- pattern 名是用户起的（业务内容），app 编号是灰色标识符（topo.md 5.2）。
- `定义`：pattern 想抓什么的一句话（方向文档第 12 节三处离不开语言之一）。
- `elements`：本 pattern 全部 instance 的成员里出现过的名字，每个一行。`in 2/4` = 出现在 4 个 instance 里的 2 个；认出数前面固定写 `new` / `old`，两种分数各带自己的标识符，不靠图例分（critic U13）。被包住的缩进一级带 `⊃`。属性是行下的小胶囊，数字是「看过的里面有几个是 true」，有没看过的加虚线签 `null n`（取其一自然呈现，如底部下 `W形 6/9`、`V形 3/9`）。有 app 时名字那一行右侧加 resolver（这个名字由谁来认，写词表规范词：`burst`、`tb`、`走势区段`、`平台段`，不带 node / atom 前缀，critic U10）、新 / 老认出数（只数本 pattern 成员框，flow.md 第 5 节）、⚑；属性不写 resolver——where 照用户的词命名（已定 5），写出来就是把属性名再抄一遍，只在这条属性没进 app 时挂一个虚线签 `unmapped`（critic U10）。没有 app 时这些都不出现。原 summary 底部的 `train_score` 一行删掉：它没有任何操作，「要看得问」交付单里本来就说（critic U11）。相邻两个顶层元素之间的 `↓` 有 app 时挂 link 计数。**这一条竖链就是骨架和对应表合成的那一张**，不另有表。
- `groups`：按顶层成员名称序列完全相同分组（子框、属性不进分组；flow.md 3.1），按个数从多到少。每组一串缩小的名称胶囊、个数、buy / no_buy 各几个（有 app 时各自后面跟 app:buy 几个——buy 和 no_buy 分开数，合在一起会把「像但不买被 app 买了」算成对的，critic U12；有问题的签反白）、`→ pattern` 下拉、组里每个买点一张缩略（flow、critic F9 / F10）：这个买点附近那段时间的名称轨缩小版，每个出现的名字一行、行首是它的名称块（块就是标签，不靠组头当图例），行序同主图名称轨；成员黑色实线、附近的非成员浅灰；买点三角实心 / 空心；不画 K 线，股票和日期放悬停，点了跳到那张图并选中这个买点。它顺带让「默认切短」造出的假小组一眼可见：成员左边紧挨着一个浅灰的框，落在「放量突破」那一行。下拉选已有 pattern = 整组归过去（同一个 pattern 选给两组 = 合并）；`+ new` = 起新名、建新 pattern。「未归类」里某组的骨架和已有 pattern P 最大那组完全相同时，不写字提示，下拉直接预选 P，点一下确认（flow）。P 下只有一组时不出组头那串胶囊（和 elements 重复），只列缩略。全工具只此一份 instance 列表。
- 当前 pattern 是「未归类」时版式相同，没有 app 那几格（`ux_4b_unsorted.png`）。有 app 时见 `ux_4a_pattern_tab.png`（与上面的示意同一个默认状态）。`↓ ok 2 pending 1` 的 pending 来自 TVRD 2024-12-26：app 在那段没有回踩事件；横盘和放量突破之间的 ↓ 没有计数，因为横盘接的是不在这个 app 里的走势区段，没有边可查。

**vocab tab**：删掉每个词下面的属性 true / false / null 计数表（挪进 pattern tab 的 elements 行），只留词、定义、用了几次。词的定义在 edit 和 vocab 两处都能改，保留：同一个字段不会不一致，edit 那处是名字第一次用时写，vocab 那处是回头统一整理措辞。

**拓扑面板**：标注模式下不出现（顶栏开关在标注模式隐藏，topo.md 4.1）。

### 3.3 鼠标动作（逐步）

1. **画框**：tool = box，在名称轨区域拖出一段 → 松手后 edit 栏出现名称按钮 → 点一个词（或在已有名称轨上拖，名称自动带上）。若这张图上这次停留里放过当前 pattern 的买点，新画或改过起止的框按默认规则判断一次：贴着那一串就并进它的成员，bracket 跟着变长；只加不踢。
2. **放买点**：tool = buy，点一根 K 线 → 买点归顶栏的当前 pattern，edit 栏切到这个买点 → bracket 立即按默认成员画出来 → 看 bracket 盖住的是不是这次买入的理由。
3. **核对 / 改成员**：点 bracket（或买点）→ 成员加粗、其余变淡 → edit 栏 members / others 两排块 → 点块进出（悬停看是哪个框）。
4. **再买一次**：在第二个回踩后点买点 → 默认会连第一段回踩一起收进 → 不要的话在 members 里点掉它。
5. **同一天另一个 pattern**：顶栏切 pattern → 在同一根 K 线再点一次。
6. **归组**：侧栏 pattern tab，顶栏选「未归类」→ 每组看胶囊串、点股票日期跳图核对 → 下拉选去处。
7. **拆出归错的**：顶栏选 P → pattern tab 的 groups 里自成一小组的那几个就是偏离的 → 下拉挪走；单个买点也可以在它的 edit 栏改 pattern（同一个字段的单个入口，留给例外）。
8. **对照**：顶栏 compare → 主图同轨叠画，框旁状态签、买点旁 app:buy / no_buy → 两框都 qualified 而 app:no_buy 时，选中买点看成员块之间哪个箭头是 broken。换图自动关（已定 4）。
9. **翻译不对**：pattern tab elements 那一行的 ⚑。

### 3.4 默认值从哪来

- **默认成员**：从买点往前，先收「跨过买点、或在买点前不远处结束」的框，再往前一个个接上「终点离当前最早成员的起点不远」的框，最后收进被成员包住的框。「不远」用同一个数：**20 根 K 线以内（待验证）**——ux 起初取 10，topo 取 20 并给了出处（bb_v1 允许回踩在末根突破之后最多 20 根内开始，即 `tb.max_span`），两人都偏向多收，取 20；它只是起点，不随哪个 app 的参数变。偏向多收：多收的框在 bracket 底下看得见、点一下排掉；少收的框伸在 bracket 左边外面，也看得见。critic 的 T5 指出空隙取 2～3 天会静默切掉「放量突破后先涨几天才回踩、那几天不框」的突破，这是放宽的理由。原型种子上的结果：TVRD 2025-04-28 收进横盘、缩量、放量突破、回踩；像但不买 2025-05-08 收进同一串（空隙 2 天时会收成空）；WHLRP 53 天前的横盘不收。
- **默认规则只在放买点那次停留里生效**（critic F7 三方口径，以 topo.md 5.1 为终稿）：放下买点时算一次；这次停留里新画或改动的框贴着那一串就并进，只加不踢（改短、挪远的成员不自动移出），点掉过的不并回，只并进当前 pattern 的买点；离开这张图即冻结，以后改默认规则也不改写旧买点。不采用「永不自动并进」（topo 原主张）：先点买点再框理由的画法下，那样每个框都要手点一次。
- **名称轨和 elements 的顺序**：成员的平均先后，界面现算。
- **groups**：顶层成员名称序列完全相同才算一组，界面现算。
- **骨架、groups、顺序都不存**；存的只有买点上的成员清单（保存时算好的框编号，不存「默认 / 改过」标记）和 pattern 的名字与定义（topo.md 5.4）。

### 3.5 出错怎么改

| 错在哪 | 怎么发现 | 怎么改 |
|---|---|---|
| 成员收多了 / 收少了 | bracket 盖住了不相干的框，或该收的框伸在 bracket 外；pattern tab 里冒出孤零零的小组 | 买点 edit 栏点块 |
| 买点挂错 pattern | P 的 groups 里自成一小组 | 那组的 `→ pattern`；或单个买点 edit 栏改 pattern |
| 框套框的父子推错 | 子框左下角的 `⊂ 父名` 不对 | 调框的起止（原型已有机制，本题不改） |
| 翻译错（会话把某个词接错了 node / where） | elements 那一行的 resolver 不对 | ⚑ |
| 同名两段角色不明 | 会话问，edit 栏两个同名块带 `role?` | 点其中一块 |

## 4. 拓扑面板能否复用（与 topo 对齐）

结论与 topo.md 第 0、4 节一致：标注模式下三个时期（无 app、对照、盲看露结构）都不复用组件；看图模式照旧。ux 一侧补三点：

1. **复用的是画法和一个交互**：画法 = 先后从左往右读、包含挂在下面、用户的东西用虚线；落在 edit 栏成员块链、pattern tab 的 elements 竖链和 groups 行。交互 = 主视图「点 bracket 高亮这次 match 的事件」，标注模式里变成「点 bracket 高亮这个买点的成员」，并新加「其余变淡」（topo 核过：主视图不淡化非组员；用户的框只有虚线、没有底色，光加粗不够醒目）。
2. **为什么竖排**：topo 实测现有布局函数画三个词的链就宽 404px，侧栏可用约 360px（topo.md 4.4）。横排的胶囊链放 groups 行（每组只有名字，能折行）；elements 每个名字一行还要挂出现次数、属性、resolver 和认出数，竖排正好一行一个，上下顺序又和名称轨对上。
3. **两框之间的连线不画在图上**（topo.md 4.2 提议对照时画）：mock 里实测，相邻两个成员首尾相接时，连线只有约 3px 横 + 30px 竖，正好被前一个框右侧的状态签盖住，看不见（`repro/mock.html` 里留了注释）。link 只在 edit 栏成员块之间的箭头上显示；图上一眼可见的是 app:buy / no_buy 签——两框都 qualified 而 app:no_buy，就是断在中间，选中买点看是哪一处。

## 5. 工作流各步用到什么（与 flow 对齐）

flow.md 第 2 节逐步列了每一步读哪些分组信息；ux 这边每个界面元素对应的步：

| 界面元素 | 用在哪几步（flow.md 第 2 节编号） | 删了会怎样 |
|---|---|---|
| bracket 虚线（派生） | 1 标注、4 对照 | 看不见程序认定的成员，推错没人改 |
| 选中时加粗 / 变淡 | 1、4 | 被排掉的、夹在中间的框看不出来 |
| edit 栏 members / others 名称块 | 1、4（状态签、link）、3（`role?` 回答） | 成员没处改，只能请会话代改，标注文件不再只由用户写 |
| 名称轨按平均先后排 | 1、4 | 一个 instance 的先后要横竖对着看 |
| pattern tab：定义 | 2、3 | 会话写第一版 app 只能从计数猜意图 |
| pattern tab：elements 竖链 | 3、4、6、7 | 骨架、对应表、link 汇总没处看 |
| pattern tab：groups + `→ pattern` + 每个买点的缩略 | 2、6、11 | 归组要逐个买点改，归错的拆不出去；没有缩略就只能凭股票代码和日期决定，假小组看不出是切短造成的 |

第 8～10、12 步（扫描、盲看、调参、最后检查）不用本题的任何元素；盲看露结构时 band 用用户的词归票 08（flow.md、topo.md 4.3）。

## 8. 不放心的地方

1. **默认成员规则只在 6 个种子买点上跑过**（原型 4 个 + mock 加的 2 个），真实标注的松紧、买点放在回踩里还是回踩后都会影响结果。
2. **elements 一行塞的东西偏多**：有 app 时名字、出现次数、resolver、认出数、⚑、属性胶囊同挤在约 360px 里，mock 截图（`ux_4a_pattern_tab.png`）已经显挤。实施时可能要把 resolver 和认出数放到第二行。
3. **名称轨的顺序会随当前 pattern 和成员变化**：切 pattern 时轨序会变，同一张图上看到的上下顺序不固定，可能打扰；mock 里只看了静态截图。
4. **同名两段靠悬停区分**：名称块上只有名字，同名两块要悬停才知道是哪个框；块上加日期会变成文字堆。

## 9. 最容易被误读的地方

- **bracket 不能拖**，它只是成员的显示；改成员只在买点 edit 栏点名称块。
- **「默认推断」不是一个持续的状态**：只在放买点那次停留里帮着填清单，之后清单就是用户的数据，规则再改也不动它。
- **成员 ≠ 框套框**：框套框是「小框属于大框」（子事件，`path2/GLOSSARY.md:62` 复合事件或 where 的来源）；成员是「这个框是这次买入的理由之一」。一个子框随父框成为成员。
- **elements / groups 里的「骨架」是用户一侧的**：成员名称按先后排成的序列，界面从标注现算，不是 app 的 node（`path2/GLOSSARY.md:76`）拓扑；app 只在 resolver 一格出现。
- **「不设关系编辑器」不等于不表达关系**：先后、属于已经由框的位置表达，不靠位置的写成属性；用户唯一新增的操作是改成员。
