# 标注和扫描怎么在一个页面里安顿：白话版

> 来源：同目录 `final_report.md`（2026-11-11），它综合了三名研究成员的产出：页面现状盘点、布局方案与评估、历史查证与质疑。三方定稿时无分歧。本次只做研究，没有改任何正式代码。

## 一句话版本

> **2026-11-11 你已拍板：按推荐做（加第四档 `scan`），第五节的默认做法照单采纳。**

不用拆成两个页面。建议在顶栏的模式按钮里加第四个按钮 `scan`，把旧的扫描界面整个收进这一档。其余三档（`annotate` / `compare` / `app`）的左栏改成找图清单：rally 清单直接铺开，并标出每段图标过哪个 pattern、画了几个框。图、画法、链接全部不变，后端不动。

要你定的只有一件事：**扫描放在哪**。推荐上面这个做法，它的前提是「扫描界面现在只是偶尔才用的调试工具」，这一点请你确认。

## 先认几个词

| 词 | 意思 | 出处 |
|---|---|---|
| 扫描 | 对全部股票逐只跑一遍选定的 app，把命中和统计存成一个结果文件；左栏的扫描列表就是这个文件的目录 | `path2_web/GLOSSARY.md:11` |
| app | 一个走势形态的完整声明（拓扑、条件、参数），能独立扫描和评估 | `path2/GLOSSARY.md:36` |
| pattern | 你起名、配一句定义的那种形态；样本挂在它下面 | `path2/GLOSSARY.md:73` |
| 样本 | 你在一张图上对某个 pattern 下的一次判断（正或负），连同依据的框 | `path2/GLOSSARY.md:152` |
| 反馈 | 你在 `compare` 里对 app 已经买了的地方挑刺写的话 | `path2_web/GLOSSARY.md:71` |
| 诊断侧栏 | `app` 模式右边那一栏：每个 node 的三档计数，能展开看卡在哪 | `path2_web/GLOSSARY.md:58` |

另外几个按钮名就地说清：`annotate` 是只看 K 线和你自己的框；`compare` 是你的框和 app 的结果叠在一起看；`app` 是只看 app 的结果。rally 清单是训练段里涨幅大的那些段，现在 300 段、242 只股票，藏在顶栏 `rally` 按钮的弹层里。

## 一、现在哪里空着、为什么

**空着的主要是左栏。** 左栏有三块：扫描用的 pattern 勾选、「扫描 ⚙ / 打开历史」按钮、扫描列表。不管你在哪个模式下，它都一模一样，没有任何为标注做的区分。标注时它什么都不干，约占屏宽一成，写着「未加载扫描结果」。顶栏和右栏其实已经按任务分好了，右栏在标注时是标注侧栏，在 `app` 下是诊断侧栏。

**这不是谁定下的布局。** 规格里那条「标注是主视图的一种模式，不另开页面」，当年否掉的是旧的独立标注页。旧页面自带另一套画法、一个事件都不画，怕的是「标注和显示两套画法，标完对不回来」。这条理由今天仍然成立，后来还加强过：`compare` 里 app 那部分和 `app` 模式必须是同一套画法、同一份显示状态。但它管的是图怎么画，从没讨论过左栏放什么。你当时认可的原型根本没有左栏。左栏留着扫描，是因为做标注那批工作时写了「不改扫描流程」，没人去碰它。

**扫描的东西还会漏进标注里捣乱**（只在这一页打开过扫描之后才出现）：
- 在空白处敲字母，会被抢进扫描的搜索框。之后按 Delete 删框、按 Esc 都失效。在浏览器里复现过。
- 在标注侧栏的输入框里写字时按上下键，会被跳到扫描列表的下一只股票，并强制切进扫描的 `app`，正在写的反馈面板也随之关掉。用一份前端副本做单独测试确认过，没在你的网页上按。
- `Shift+P` 在任何模式下都会弹出扫描的参数抽屉。

**你上次问的「标注里的 app 和扫描结果是不是一回事」**：不是一回事，但现在确实容易混。同一个 `app` 按钮有两种来源：
- 从扫描列表点进去时，画的是扫描文件里存好的结果。
- 从顶栏切过去时，是当场对这一只股票现跑 app。

标注这条线上，app 只在你打开的股票、有反馈的股票（`compare` 里算状态时）、有样本或反馈的股票（会话出改版报告时）上跑，所以看起来像「只对标过的股票做的扫描」。

## 二、推荐做法长什么样

```
标注时（annotate / compare / app 三档）
┌ symbol  random │ mode [annotate] compare app │ scan │ tool box point │ pattern «new_step» ┐
├ rally │ random │ charts ─────────────┬──────────────────────────────┬──────────────────┤
│ symbol  date        pattern     框数 │ K 线                          │ 标注侧栏          │
│ «TVRD»  2025-04-02  «new_step»  4    │ 成交量                        │ （compare 下多    │
│ «ACME»  2024-03-11              2    │ 副图                          │  一页 feedback）  │
│ «CRNC»  2024-11-22                   │                              │                  │
│ … 上下键挨个翻                         │                              │                  │
└──────────────────────────────────────┴──────────────────────────────┴──────────────────┘

扫描时（scan 档）：和今天的扫描界面一模一样
┌ symbol  random │ mode annotate compare app │ [scan] ─────────────────────────────────────┐
├ 扫描面板 + 扫描列表 ┬ 档位条 / 扫描的 pattern / 参数 ──────────────┬ 诊断侧栏 ┤
│                    │ K 线（扫描窗口）/ 副图                       │          │
└────────────────────┴──────────────────────────────────────────────┴──────────┘
```

**左栏三页**，都只列你自己存下的东西，不出现 app 的任何结果：
- `rally`：rally 清单直接铺开，点一下就打开那段图，不用再先点弹层。每行多两列，一列是这段图里标过的 pattern 名，一列是框数。有框数，「只画了框、还没放样本」和「完全没碰过」就能分开。顶栏的 `rally` 按钮去掉。
- `random`：抽图还是按顶栏的 `random`，一下出一张。这一页按先后列出这次抽过的几张，可以点回去、上下键翻。它只在页面里，刷新就清空，不存任何东西。规格「看过什么一律不记」防的是存下来、用来限制你看哪些图的「看过」记录，这份列表不在此列。
- `charts`：你标过的所有股票，不限于 rally 清单，一只一行，写 pattern、正负样本数、框数；只画了框的也列。它和右栏 `pattern` 页分工不同：`pattern` 页看的是当前这个 pattern 的样本，`charts` 是一份跨 pattern 的目录，帮你决定下一张去哪看。

**`app` 从此只指现算**，扫描文件里的结果只在 `scan` 档看，一个按钮管两种来源的混淆就没了。

**上面说的抢键毛病顺带修掉**：扫描列表的按键、`Shift+P`、扫描的草稿横幅都只在 `scan` 档起作用。

**它不让图变宽**：左栏从空着的 220 像素变成约 278 像素的清单，图反而窄约 58 像素。换来的是左栏不再空着，rally 弹层也不再盖住图的左边。画框时嫌图窄，可以以后再加一个收起左栏的开关。

**这算不算解决了你说的「割裂」**：只解决了一半。你 11-05 说最棘手的是「拖拽」和「rally 股票列表」：拖拽已在 11-08 解决，这次补上的是 rally 列表进左栏。点 `app` 时右栏换成诊断侧栏、图上方多出档位条，这些不动。

## 三、为什么选它，别的路代价在哪

| 做法 | 好处 | 代价 |
|---|---|---|
| **加第四档 `scan`（推荐）** | 一个页面、一排按钮，没有新概念；从扫描图去 `compare` 点一下 | 扫描列表不能和 `compare` 同时开着 |
| 两个独立页面 | 扫描页天然不会抢标注的键 | 多两个地址；来回切要重读扫描文件；最像「两个界面」，正好是你嫌的割裂 |
| 顶栏加「标注 / 扫描」开关 | 和推荐覆盖的东西一样 | 多一个要起名的新概念；从扫描去 `compare` 要点两下 |
| 不分档，左栏分页签，扫描是其中一页 | 能在 `compare` 里翻扫描列表，对着全池命中逐张挑刺 | 扫描列表的按键、点一行落在哪个模式都要另立规矩；而这种用法目前没有用过的迹象 |
| 左边一条图标栏，清单做成抽屉 | 图最宽 | 「哪些标过」又藏回弹层，正好是你抱怨过的 |

**为什么能把扫描当偶尔用的工具**：
- 11-04 改名以后，主目录里没有一份扫描能在网页里正常打开，也没人提过。
- 你标过的 7 只股票里，5 只来自 rally 清单，没有一张来自扫描结果。
- 测「从扫描进标注」的两条自动测试从 11-04 起就不通过，也没人发现。

这些只说明扫描界面最近没人用，不说明扫描能力没用：以后盲看要从全部股票里抽 app 的命中，那个能力一律保留。

**如果你其实常用扫描界面**，或者想在 `compare` 里对着全池命中一张张挑刺，那「左栏分页签」更合适，告诉我就按那条走。

## 四、什么时候做

建议放在这一轮之后：等会话第一次真跑完标注的一轮、你在 `compare` 里看完改版报告，再在单独的分支里一次做完，然后开下一轮。原因有两条：
- 它不改变这次验收要看的东西：标注格式、`compare` 的画法、反馈、链接都不动。
- 一轮做到中间换工具，出了问题分不清是哪边的。

## 五、请你过目的默认做法（都标「待验证」，用起来不顺再改）

- `scan` 档在没加载扫描时也能点：左栏是扫描按钮和空列表，图区写 `no_scan`。
- 从标注切到 `scan`：当前股票在扫描文件里就留着，不在就回到扫描列表上次停的那只（扫描界面画不了扫描文件以外的股票）。
- 从 `scan` 切回标注三档：在 `scan` 里点过扫描列表的某一行，就把那只带回来；没点过，就回到进 `scan` 之前那只。这样「标着 A、去扫描看一眼、回来」仍停在 A。
- 上下键在左栏清单里挨个翻；光标在输入框里时不起作用。
- 左栏清单不带「敲字母搜股票」，搜股票用顶栏 `symbol`。带过来就会重现抢键。`Shift+B`、`Shift+F` 照旧。
- rally 清单里「标过」按那一段图的日期范围算：样本日落在这段里才算 pattern，框落在这段里才计框数。
- 打开页面默认在 `annotate`、左栏默认 `rally` 页。
- 左栏这次不加收起开关。
- 新名字待你认了再进词表：第四档 `scan`、左栏三页 `rally` / `random` / `charts`、空状态 `no_scan`。

**留到第二段再说的**（这一轮不产生差别）：`compare` 下左栏要不要顺带显示每只股票上 app 和你的标注一不一致；盲看清单放左栏还是右栏。

## 六、局限

- 「扫描 `app`」那一种状态下各区域的样子是读代码得出的，没有正常截图：要截图得先跑一份新扫描，会往输出目录写文件，没跑。
- 各做法的「点几下」是按代码数的，没让你实测。
- 工作量是粗估，没有做原型。
- 「扫描界面没人用」只查了主目录的文件，是推断，所以写成请你确认的前提。
- 推荐的做法是质疑者在挑上一版方案时提出的，方案成员一轮就接受了；质疑者自己按同样几项查过一遍（不越红线、不省屏幕、`scan` 按钮可能换图），但没有第三个人专门挑过它的毛病。
