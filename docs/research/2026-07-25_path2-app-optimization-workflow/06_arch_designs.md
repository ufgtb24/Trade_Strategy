## 0. 正面回应 `skeptic` 的判决

他的判决是：

> 在目标函数被补齐之前，任何自动化搜索的产出都不可信；**而补齐之后，B0 极简基线就已经够用了。**

**前半句我完全接受，并把它升格为本设计的第 0 步（§1）。后半句我不接受，但我接受它的一大半。**

### 我让掉的部分（比他要求的还多）

**我原打算交的三个竞争设计里有两个应该被杀掉，而且是被 `opt` 的实测杀的，不是被论证杀的。**

`opt` 全宇宙实测：现任 pk4 score=0.0719，他扫的 32 个候选里最好的**合法**候选只高 **+0.0071**，而 K=10 的选择校正门槛就要 **0.0078** ⟹ **FAIL**。contender 之间 τ² 的矩估计取到 **0**——候选间的分数散布**完全能由噪声解释**。

> **这条实测顺带验证了我 v1 提的那个停止判据。** 我当时主张用 `τ̂² = max(0, S² − σ²)` 从 ledger 估候选间的真实质量方差，并说「`τ̂/σ < 0.5` 就该停」。**`opt` 独立跑出的第一个真实取值就是 `τ̂ = 0`。**
> 判据在它第一次被真实数据检验时就触发了。**这不是我的设计的胜利，是它的讣告**——它告诉我：在机械可枚举的邻域里，该停的时刻**已经到了**。

⟹ **「设计一个搜索引擎」是错的交付物。我不再提交任何以搜索能力为卖点的方案。**

**范围界定（`opt` 自己标的，很重要）**：他扫的是**机械可枚举的邻域**（参数 + 节点子集），**不是语义可生成的空间**（新 detector 判据 / 新边语义 / 新形态概念不在内）。正确读法是「**机械搜索到底了，语义生成没被测量**」。

### 我不让的部分：**B0 没有任何机制保证它自己的步骤会发生**

`hitl` 核实过一件事，我认为它是整个研究里最硬的一条论据：

> 那句「需要用户提供 2-3 个具体漏检 ticker + 日期做 replay 验证」，
> **被三个不同 agent 在四处独立写下**（`final_report.md` §4/§37/§162/§173 + 两份中间文档），
> **然后全部落空，方案照常实施，10 天后被目标函数证伪 −79%**（0.0719 → 0.0154）。

**B0 的第 1 步（人看 K 线落标注集）会以完全相同的方式落空。** 它是一句写在流程里的建议，没有任何东西在它没发生时停下来。

而且不止第 1 步——**B0 的三个步骤各有一处"不会自动发生"**：

| B0 步骤 | 靠什么发生 | 会怎么落空 |
|---|---|---|
| 1. 人跑 `scan-top-miss` → 看 K 线 → 落 `(ticker,date)` 列表 | **一句建议** | 与 2026-07-15 那次同构：写了，没做 |
| 2. Step 4 判据 2 从 `run_regress` 升级为跑 score | 改一段 skill 文字 | 文字改了，但**没有任何东西阻止下一次退化成单窗打分**（`sweep.py` 的 `worst_score` 在自动化里第一轮就烧 holdout）；**更根本的是目标函数本身有洞（§1），score 跑了也指错方向** |
| 3. `tune-pattern-strength` 原样跑 | skill 文字 | K 无从数起——B0 每次调用都是 fresh session，**没有跨 session 记账物** ⟹ **B0 无法执行 `skeptic` §10 要求它执行的 K 调整门槛** |

⟹ **我的定位不是「B0 + 搜索引擎」，是「B0 + 强制机制」。**
**而"强制机制"恰好就是工作流这个东西的定义**——它不是编排智能，是让约定变成物理约束。

### (iii) 的答案：B0 触达不了的具体候选

`skeptic` 只接受具体候选。我给两个，**并且先撤回一个我 v1 写过的**：

**❌ 撤回 X2「where 子空间的联合最优」。** 我 v1 说 B0 的坐标扫描只访问 31 点、联合网格 896 点。**`opt` 已经把这块搜过了，τ²=0。** 这个候选不存在。**我错在把"搜索空间大"当成"里面有东西"。**

**✅ 保留 X1：`tb.phase{1,2}_break_tol`，单位 ATR**（`hitl` 400 只重算确认，详 §2.4）。
B0 触达不了它，**不是因为 B0 搜得少，是因为通往它的三条信息通道在 B0 里全是断的**：
1. 「这道判据是高频杀手」——要从 `gate_failures` 才看得出，而 `eval_runner` **每次全宇宙 eval 都算了 ~1650 万条然后全丢**（`path2_web/eval_runner.py:73-78` 算并 attach，`:80` 之后只读 `res.matches`，注释自己写着"此路径目前无 gate_failures 消费者"）。
2. 「它是硬编码的 0 容差、不是参数」——要 `GateFailure.threshold_param=None` + `code_location` 才定位得到。
3. 「容差必须是 ATR 单位」——**裸埋点吐的是美元**，照表面读数实现会做出一个在 $0.17 票和 $169 票上语义不同的参数。

**✅ 新增 X3：那 2-3 个从未到达的漏检 ticker 本身。**
这是最诚实的一个 (iii)：它们不是"搜索空间里的一个点"，**它们是从未进入过任何搜索空间的信息**。`score = w·lift` 对漏检**结构性失明**——它只度量抓到的东西的质量，召回的分母对它不可观测（`hitl`）。B0 触达不了它们，**因为 B0 里没有任何东西在它们缺席时停下来**。

## 1. 第 0 步（前置条件）：目标函数补齐

**不修完不启动任何搜索。这不是注意事项，是前置条件。**

### 为什么它排在所有机制选型之前

| 洞 | 实测 | 强度 |
|---|---|---|
| **入场位置杠杆**（`skeptic`）：对全宇宙每个 bo 无差别执行「bo 后 k 天内最低收盘那天买」，**零选股能力、不看任何形态** | k=2→+0.0379 · k=5→+0.0645 · k=7→+0.0770 · k=10→**+0.0928** | 对照 bottom_burst 定案 lift 才 **+0.1099** |
| **前瞻杠杆**（`opt`）：`end_node` 从 tb 换成 burst | score **0.4359**（现任 6 倍）、**三门全过**、\|z\|=**17.8** | 纯前瞻 |
| （对照）**真实候选之间**的差异 | — | \|z\| = **0.95** |

> **两个洞的信号强度是真实差异的 19 倍。**

`skeptic` 说得对：**人不容易滑进去**（按走势语义设计结构时，"把入场点往回踩低位挪"不是会自然浮现的动作），**但最大化器会直奔它而去，且完全通过现有所有硬门。**

⟹ **这是「最优化 > 最自动化」最硬的技术依据：机制越强，错配放大得越厉害。**

### 强制机制：**让错的东西不可表达**

这一步的强制**不能靠"改评分标准文档"**——文档不阻止任何人写一个单窗打分函数。

| 弱 → 强 | 形式 | 为什么 |
|---|---|---|
| ❌ 最弱 | 在 `pattern_config_scoring_standard.md` 里加一段 | 下一个 agent 不会读，或读了图方便还是写单窗 |
| ⚠ 中 | hook 拦截 | **`mech` 实测确认拦不住**：hook 拦的是**工具调用**，Python 脚本内部的 `open()`/`read_pickle()`/`json.load()` 对它完全不可见。agent 跑 `uv run python x.py`，hook 只看到那一行命令串 |
| ✅ 最强 | **打分函数只接受多窗输入、只返回最差分；单窗打分函数根本不存在** | agent 想退化成单窗，**得自己重写打分函数**——那是留在 diff 里的显眼动作，不是"少传一个参数" |

**三条具体的**（修法本身由 `skeptic` 定案，我只定强制形式）：
1. `score()` 的签名**不接受单窗**。
2. **因果可容许闸**写成 evaluator 里的**断言**，违反即抛异常，不是打印警告：买点日期必须仅凭当日及之前信息可识别；两个违反形式 = 锚点靠未来确定 / 锚点被挪到事后才知的局部低点。
3. 加 `median_dipctrl` 对照列：任何配置同时报「相对 bo_only」与「相对平凡回踩入场」两个 lift。**后者是新基线。**

**一条来自 `mech` 的普遍教训，我把它升格为设计原则**：
> **强制只能施加在「在强制边界上可见」的东西上。**
> 现在 CLAUDE.md 规定入口脚本不用 argparse、参数声明在 `main()` 起始 ⟹ **窗埋在脚本内部 ⟹ 任何外部拦截器都看不见它**。
> 若要哪怕最弱的外部校验，就得把窗提到 env（`PATH2_EVAL_WINDOW=2025 uv run python sweep.py`，evaluator 缺它就拒跑）。这不违反无-argparse 规范。
> **⟹ 机制能力反过来约束接口设计。**

## 2. 推荐设计 · **强制骨架**

**它不是搜索引擎，是一副骨架**：把 B0 已有的正确步骤扣进去，让每一步在没发生时**停下来**。

工作流只做四件事：**降 K / 提 lift / 保证 1 和 2 真的发生 / 别让收益被统计错误吃掉。**

### 2.0 形态：幂等可重入的短 run + 持久 workdir

**`mech` 给的设计律，我全盘采用**：

> 不要设计「可恢复的长循环」，要设计「**幂等可重入的短 run + 持久 workdir**」。
> 每次调用 = 读 workdir 状态 → 做有界一段活 → 写回状态 → 退出。
> **人类环节是 run 边界，不是 pause。**

三条实测支撑，任一足够：
- `resumeFromRunId` **仅同 session 有效** ⟹ 人隔夜回来进度必丢。
- `AskUserQuestion` **只在主会话可用** ⟹ workflow/subagent/teammate 内根本问不了人 ⟹ **要问人就必须结束这一 run**。
- 人看 K 线是随时中断、可能跨天的活动（`hitl`）。

**⟹ 整个设计里没有一个"挂起等人"的环节。所有人在环点都是 run 的终点。**

### 2.1 状态：一个目录，进 git

```
path2_apps/<app>/opt/
  ledger.jsonl          # 一行一候选;K = wc -l                        进 git
  holdout_ledger.jsonl  # 一行一次查询(无论通过与否);N = wc -l          进 git
  labels.jsonl          # 人的判断,append-only,永不消费掉              进 git
  decision_log.jsonl    # 一行一轮:归因结论 + 已试过且失败              进 git
  variants/bbb_cand_0017.py   # 候选物化模块,唯一名永不重用(§2.6①)     进 git
  BLOCKED.md            # ★ 阻塞闸:存在即"轮到人了",人处理完删掉        进 git
  README.md             # 3 行:当前最优 params_hash / K / holdout N
  .cache/streams/       # detect 缓存                                 gitignore
```

**为什么必须是文件**（`mech` 的载体表）：`resumeFromRunId`（仅同 session）/ agent 上下文（compact 就丢）/ SendMessage（随 session 死）/ `TaskCreate`（session 级可视层，不是存储）/ `CronCreate`（session-only、不落盘、7 天过期）/ memory 目录（用途错，那是存"关于用户的事实"不是项目数据资产的家）——**全部不能跨 session。写进 git 的文件是唯一可靠载体。**

**两个会静默出错的陷阱，直接决定 schema**（`hitl`）：
- **标注存日期不存 bar 索引。** bar 0 = 当次加载窗口的首根，随 `start_date` 与 `head_buffer_trading_days` 变化（`eval_runner.py:61-65` 双端缓冲切窗）⟹ 存 bar 下一轮**静默错位**，不报错，只是指向别的日子。
- **`verdict` 持久（params-无关），`attribution` 按 params hash 失效。** "这是横盘后启动"是价格行为事实；"死在 `gap_max`"只对某组参数成立。

**两个文件不能合并**（`hitl` 强调）：`human-hint-r{N}.md`（瞬时操舵，消费后 `mv .consumed.md`）vs `labels.jsonl`（持久语义 ground truth，append-only、永不消费）。**把 labels 当 hint 消费掉会重蹈覆辙。**

### 2.2 四件事 × 每件事的强制机制

**这是本文的核心表。没有强制机制的行，我已经从设计里删掉了。**

| # | 事 | 具体动作 | **强制机制** |
|---|---|---|---|
| **A** | **降 K** | 人用形态语义把结构候选从 ~1000 收到 ~5 | **`AskUserQuestion` 阻塞**（主会话 inline）。不选就不往下走——**这是唯一天生阻塞的机制** |
| **A′** | 降 K 的**合法性** | 收窄用的信息必须与 score 数据**正交**（形态语义） | **evaluator 只接受"人已勾选"的候选清单文件**，没有该文件就拒跑。⚠ 若改用"score 预筛 1000 留 5"来降 K，那是把选择偏差藏起来，**门槛仍按 K=1000 算**——**"少搜"本身不给任何保护，只有"用正交信息少搜"才给** |
| **B** | **提 lift** | LLM 读 gate 归因表提结构/判据候选；人提形态方向 | **`gate_failures` 必须落盘**（改 `eval_runner`）。没有这张表 LLM 只能瞎猜——**这就是"让 claude code 介入 detector 代码级诊断"的全部内容**（§2.4） |
| **C** | **保证 A、B 真的发生** | 所有人在环点 | **`BLOCKED.md` 阻塞闸**（§2.3）。跑到该问人的地方就**落盘并退出**；下次调用**读不到人的答复就再次退出** |
| **D1** | 统计 · **目标函数洞** | §1 | **打分函数不接受单窗 / 因果可容许断言抛异常** |
| **D2** | 统计 · **选择偏差** | K 调整门槛 | **K = `wc -l ledger.jsonl`，代码算，不由人报。** evaluator 每次写 ledger 时顺手算 `k_gate` |
| **D3** | 统计 · **holdout 被烧** | 记账而非禁令 | **数据通路隔离**（`mech`：比 hook 强）——搜索 harness 只拿 `data_dir=<搜索窗>`，**holdout 走另一入口由人跑**。「拿不到的数据不需要被禁止访问」。每次查询**无论通过与否**都 append 一行 |
| **D4** | 统计 · **标注集被烧** | 标注也是被查询的数据 | 闸做成**粗粒度二值**（"全保住 / 没全保住"），**禁止做成"保住了几个"的连续分**——连续分泄漏快得多。标注集查询次数也计入 |

**关于 holdout 记账**（我 v1 的论点 3，`mech` 实测后仍成立）：`skeptic` 主张「整个生命周期只解锁一次」。我主张**用他自己的工具把它做成可记账的账户**——holdout 被查询 N 次后膨胀是 `σ_h·E[max_N]`，N=2 只要 +0.007、N=5 只要 +0.014、N=200 才 +0.033。**灾难不是"查了第二次"，是"查了 200 次而没记账"。** 这条比一条纪律强，因为它**自惩罚**：想多查就得拿更大的 lift 来换，不需要人的自律。
⚠ 两条限定：`σ_h` 必须现测（不能搬搜索窗的值），且配对比较的 SE 更小、应当用**配对 bootstrap**；iid 的 `E[max_N]` 是**下界**（第 2 次查询的候选是看了第 1 次结果之后设计的）。

### 2.3 `BLOCKED.md` —— 全设计唯一的新机制，也是打败 B0 的唯一战场

**问题**：`AskUserQuestion` 只在主会话可用，且一个 run 结束它就没了。跨 run、跨天的人在环点**没有任何原生机制承载**。

```
跑到人在环点 →  写 opt/BLOCKED.md  →  立即退出这一 run
                 ├─ 人要做什么(具体到"看哪几只票的哪几个日期")
                 ├─ 答复写到哪(labels.jsonl 的行格式 / 勾选清单文件)
                 └─ 为什么卡在这(一句话)

下次调用 → 第一个动作:检测 BLOCKED.md
           ├─ 存在且人未答复  → 复述内容,再次退出。★不往下走★
           └─ 不存在(人删了)  → 读人的答复,继续
```

**为什么这条能防住 2026-07-15 那次落空**：那次的失败模式是「建议被写下来，然后流程继续往前跑」。`BLOCKED.md` 让**流程物理上跑不下去**——不是提醒，是**缺文件即失败**。

**新建组件计数：1 个 markdown 文件 + 一条"每次调用先检测它"的约定。** 这是我全文唯一主张新建的机制。

### 2.4 「让 claude code 介入 detector 代码级诊断」的具体动作

用户自陈劣势 #2 是「不知如何让 claude code 介入」。**答案已经在代码里了，只是被扔掉了。**

- `eval_runner` 每次全宇宙 eval **已经完整算了 ~1650 万条失败轨迹然后全部丢掉**（`:73-78` 算并 attach，`:80` 之后只读 `res.matches`）。捡起来**零成本**，`path2/atoms/` 一行不用动。
- `GateFailure` 自带 **`code_location`**（`throwback.py:177` 这种行号）+ **`threshold_param`**（`params.yaml` 短名）。

⟹ **LLM 的介入动作 = 读聚合表 → 顺着 `code_location` 去 Read 源码 → 提改动。** 不需要断点、不需要 IDE、**天然可批量**——正是用户自陈劣势 #1（无法批量、一个一个排查）的解药。

**三条必须写死的口径**：
1. **worker 内聚合，不全量落盘**（1650 万条）。
2. **排序键是 `计数 × 近失占比`，不是计数。** `hitl` 实测裸计数表只有 11 行且 99% 是点探测器的结构性噪声。反例：`burst.chain_break` 计数 682 大，但 p50 超阈 **36 根**、近失仅 **3.1%**（量纲是**根数**，跨股票天然可比，结论稳）——**不是瓶颈**。
3. **★ 近失必须在无量纲口径上算**（下）。

#### 一条我自己踩出来又爬出来的坑（本文中心论点的微缩实例）

`hitl` 原表说 `tb.phase1_break` **80.7% 近失**。我现场定位到 `path2/atoms/throwback.py:161-167`：

```python
if measured_support < anchor:                     # ← 硬编码 0 容差,不是参数
    _emit_tb_gate(..., MeasuredKindAware(kind='anchor_delta',
                       value=measured_support - anchor),   # ← 裸美元差
                  0.0, atr_window, on_gate, op='>=', threshold_param=None)
```

**`measured` 是裸美元差**，而样本股价从 $0.17 到 $169——"差 0.2 美元"跨股票没有统一含义。我跑探针重算成 ATR 单位，`hitl` 随后用 400 只 pkl 独立复算（用 detector 自己的 ATR 口径），两边一致：

| gate | N | 裸价格差 p50 | **ATR 归一 p50** | ≤0.5 ATR | ≤1.0 ATR |
|---|---|---|---|---|---|
| `phase1_break` | 3818 | $0.311 | **0.653** | **39.8%** | 68.8% |
| `phase2_break` | 819 | $0.190 | **0.385** | **60.1%** | 82.3% |

1. **「80% 差一点点」是量纲假象。** 归一后 phase1 的破位中位数是 **0.65 个 ATR**——实打实破了大半个日波幅。
2. **但候选没死**：0.5 ATR 容差仍能救回 phase1 的 39.8% / phase2 的 60.1%。**X1 成立**（`hitl` 判定 (a)）。
3. **★ 优先级排序被反转，参数形式被钉死**：裸口径下 phase1≈phase2 看不出差别；ATR 口径下 **phase2 明显更边际**（0.385 vs 0.653）。容差**必须以 ATR 为单位**——绝对价格阈值在 7532 只票上没有统一语义。
4. 附带：`phase1_rise_before_confirm` 用的是 `rise/atr`（`:179`），**本来就归一了**，别顺手也去归一它。ATR 归一还对数据里的异常价（`close` 最大到 1e12 量级，疑似复权 artifact）**天然免疫**。

> **这就是"代理指标做决定会翻车"的微缩版，发生在我自己提的候选上，代价 5 分钟。**
> 「近失占比」是代理指标。在错误量纲下它不只是不准——**它给出了反向的优先级排序**。
> ⟹ **设计含义**：`hitl` 那条「补齐 `threshold_param`」若不同时**声明量纲**，这座「判据 → 参数键」的自动桥会**自动生产出跨股票不可比的参数**。补埋点必须连量纲一起补。

### 2.5 人在环：三个点，硬预算 ≤20 判定 / ≤20 分钟

**`hitl` 的硬预算是否决性的，我全盘服从。** 三个点合计 ~18 分钟：

| 点 | 做什么 | 量 | 强制机制 | 产出 |
|---|---|---|---|---|
| **H1 · 候选启发样本**（生成侧） | 看 `scan-top-miss` 榜前几只，说"这里该被抓、因为……" | **≤5 个**，5–10 min | `BLOCKED.md` | `labels.jsonl` 的 `should_match` 行 + **一行必填理由** |
| **H2 · 结构候选 gate**（降 K） | 勾选 LLM 提的 3–5 个候选留哪几个 | 3–5 项，3 min | **`AskUserQuestion` 阻塞** | 勾选清单文件（evaluator 的准入凭证，见 A′） |
| **H3 · 否决闸**（验收侧） | 看 `run_regress` 的 `added` **随机** 10 项 + 基线 10 项 | 20 项，4 min | `BLOCKED.md` | `labels.jsonl` 的 `bad_match` 行 |

**I/O 契约上限就是 `(区间, 二分, 一行文本)`**（`hitl` Q3）：区间 brush ✅（现有 UI 已产出，且匹配人的知觉对象）/ 二分勾选 ✅ / 一行自由文本理由 ✅（人**愿意**写"为什么"）；**打分 1–5 ❌**（跨时点不稳定）/ **候选间排序 ❌**（认知负荷 O(N log N)，且与"人不排序"红线冲突）/ 结构化多字段表单 ❌（会被跳过或胡填）/ `expected_role` ⚠ 仅可选（强制它 = 让人做机器该做的事）。

**四条来自 `hitl` 的修正，我原方案错了的地方**：

1. **H3 抽法从"按 forward_return 升序抽"改成"均匀随机抽"。** 我原想把人眼投在最可能暴露漂移的地方，`hitl` 指出这**破坏了人与 score 的正交性**——升序抽是用 score 相关的量决定人看什么，人就从独立的第二维度退化成 score 的放大器。**而正交性正是 A′（降 K 合法性）的前提。** 而且 `added` 的 return 分布本来就有下尾，**任何**候选（含完全正确的改动）都会有低 return 的新增命中，所以升序抽测的是"下尾里有多少看起来丑"，不是"是否引入语义漂移"。
2. **门槛从固定 3/10 改成「与基线对拍」。** Binomial(10,p) 判别力极弱（p=0.1 时见 ≥3 的概率 7%，p=0.3 时 62%），固定门槛只能区分 0.1 和 0.3、中间地带全糊。改成：同样随机抽 10 个**当前已定案配置**的命中让人判得基线 bad 率 `p0`，新候选的 `p1` 明显高于 `p0` 才拦。**相对判断是人类稳定得多的那一类**，还能抵消用户对"丑"的私人标准。基线只需测一次、可复用 ⟹ **稳态成本仍是 10 项**。
3. **H1 的 5 个改名「候选启发样本」，不叫回归闸。** N=5 做不了回归闸（若坏改动随机毁掉 30% 正例，N=5 抓到概率只有 83%，N=15 是 99.5%），但作为**候选生成的语义来源** N=1 就有用。**两者兼得的办法**：启发样本每周期新采 5 个，**回归闸吃跨周期累积的库存**（摊薄后每周期人时接近 0）。
4. **`labels.jsonl` 为空不是硬前置。** 我原想写成"新 app 必须先标 1 个正例才能启动"，`hitl` 反对：会**卡死冷启动**（用户在信息最少时被要求做最贵的判断），且纯边距分析在无标注时已被实证可用（§2.4 那张表就是零标注得出的）。改成**软推荐**：有标注则摘要多一列「⊆ 标注区域的失败计数」，没有则退化成全局边距排名，**退化后仍可用**。

**三条红线**（`hitl` 定，我采纳）：
- **人提候选、人有否决权，但人从不排序。**
- **闸是单向否决**：只能拒，不能加分。否则就成了刷分杠杆——**recall 没有减基线保护，放开一切即 100%**。
- **掉标注样本时不是自动 reject，而是阻塞 + 归因 + 人裁三选一**（修 / 接受并更新标注集 / 撤销改动）。因为闸会误伤"合法地找到了更好但不同的机会集"的候选。**这与项目已认可的重构纪律同构：旧实现当 golden baseline 是体检仪不是设计裁判**，必须区分**实现偏离**（回归，必修）与**设计偏离**（升级，接受）。

**别设计"聪明排序省人力"的环节**：`hitl` 588 只真跑，四种廉价结构信号收窄仅 **1.0–1.77x**（节点存在性几乎无信息：89.8% 的股票有 burst、90% 有 `dropped_matches`，选择性几乎全住在边约束的合取里）。**第 200 次注视的命中率和第 20 次一样低。人力省不下来，只能问在刀刃上。**

**节奏：攒批，不打断**（`hitl` Q4，无直接依据但两条间接依据）：用户自陈劣势 #1 就是「无法批量处理」，设计成一周期打断多次是在痛点上加码；且机器忙时 UI 也卡（`biz` 实测 fan-out 不买吞吐）。**代价可接受**——全宇宙 eval 是分钟级，"跑完才发现候选批全被毙掉"浪费的是分钟不是小时；还可在批开头先跑一次纯机器的健全性预检（每候选 1 次 eval）把明显崩掉的先毙掉。

### 2.6 机器侧：三条必须写死的实现红线

**都是"不写死就会静默出错"，不是最佳实践。**

**① 候选模块名唯一，永不重用**（`mech` 实测，最阴险的一条）

```
[2] pool 启动后新建的模块  → 可 import ✅（"import 缓存/sys.path/启动时机"不是问题）
[3] 重写同名模块,单次调用  → 看到新值 ✅  ← 假绿!
[4] 重写同名,连续 6 次覆盖 → 值集合 = {'A1','A2_REWRITTEN'} ❌ 部分 worker 持 stale
```

**已 import 过该模块名的 worker 把旧版本留在自己的 `sys.modules` 里，没 import 过的拿到新版本——同一批评估静默混用两个版本的代码**，不报错、不崩、结果是两个版本的混合物。而 [3] 单次调用恰好落在没 import 过的 worker 上给出**假绿**（正好复刻项目那条教训：单个测试的平凡场景抓不到，多候选 fuzz 才抓得到）。

⟹ **每个候选用唯一模块名 `bbb_cand_0017.py`，永不重用。** 由 [2] 保证新名字在已跑的 pool 里能正常 import，**不需要重启 pool**。零成本、零约束。
（与 ✔arch 现场读的 `eval_skeleton.py:101-113` 约束兼容：`app` 是字符串、worker 内 `importlib.import_module`、变体必须是**磁盘上可导入的模块**、闭包不可 pickle 跨进程。**这个约束反而是好事**——候选物化成文件 ⟹ 可审计、可复现、K 可数。）

**② 串行，不 fan-out**（`biz` 实测）
并发 K 个 eval **零增益甚至更慢**：K=2 → 52.2s vs 串行等价 49.6s；K=4 → 109.7s vs 99.2s。单 eval 已 CPU 饱和。
⟹ **任何"多 agent 并行探索不同分支各自跑评估"的设计是伪并行**，总墙钟不缩短。fan-out 只买编排便利。
⟹ 且**后台批量搜索与人在环交互式评估必须显式排队/排他**——`hitl` 与 `mech` 独立提出同一条。

**③ 不依赖回调，一切走 ledger**（`mech`）
后台脚本**每完成一个候选就 append + flush** `ledger.jsonl`；回调只当"顺手的提醒"。
⟹ 回调丢了 / session compact 了 / 终端关了，**真相都在磁盘上**，下次 `tail ledger.jsonl` 就知道跑到哪，随时 `wc -l` 看进度。**这把"`Bash(run_in_background)` 跑几小时可不可靠"从机制问题降级成不需要回答的问题。**
⟹ 长跑载体用 **`nohup python run_batch.py > batch.log 2>&1 &`**，**不用 background agent**（`mech` 修正了他自己的推荐）：这件事里**没有任何需要判断的东西**，而 background agent 是完整会话，会漂、会花 token。若真要用，它的全部工作也只是起那个脚本然后立刻结束——那还不如直接 `nohup`。
⟹ **不需要 `Monitor`**；若用，其过滤器**必须覆盖失败签名**——只 grep 成功标记时，崩溃和"还在跑"长得一模一样。

### 2.7 内层参数搜索：禁用 argmax，取平台中心（待 `opt` 裁决）

**矛盾**：5 个结构 × 36 组参数 = 180 次评估，取全局 argmax 则门槛按 K=180 算，**人降 K 挣的 ~+0.022 被内层吃掉大半**。

**解法**（lead 提出、已交 `opt` 裁决，**我按它设计并标注待确认**）：**内层一律取"平台中心"而非 argmax**。平台中心是邻域平均、是收缩估计量、**不利用参数空间内的噪声** ⟹ 内层从"选择"降级为"估计"，唯一发生选择的是跨 5 个结构那层，**有效 K 回到 5**。

**附带一道免费的闸**：**响应面上根本没有平台、只有尖峰的结构候选，直接淘汰**——这本身就是稳健性证据，且它补上了 `skeptic` 指出的缺口（"平台论证无法迁移到层①②，因为离散候选没有邻域"）——**参数响应面给了结构候选一个它自己没有的邻域**。

**算力上完全负担得起**：`mech` 实测 detect 缓存读回 **0.003s vs 重扫 20.9s**（全宇宙 4.7MB）。而且**缓存的服务半径比我原以为的宽得多**——`run_streams` 的物化键是 `(id(node.detector), node.consumes_stream)`（✔arch 读 `path2/dag/engine.py:47-66`），**只依赖 detector，与 edge 集合、where 子句、node 子集完全无关**。`opt` 生产规模验证：`{bo,burst,tb}` 的 streams 是各子拓扑的**超集**，**一次 detect 同时服务任意子拓扑**（含 `bo_only` 基线 = `keep=("bo",)`），单组 detect 服务了 **22 个精确评估**。
⟹ **5 个只改拓扑/where 的候选 = 1 次铺底，不是 5 次；** 加一个新 detector 的候选只需增量算那一条新流。**稠密响应面跑得起。**

## 3. 两个被否方案

### ❌ 否决 1 · 全自动多轮搜索循环（workflow 内 agent 批量出候选 + 无人值守收敛）

**四条实测各自独立足以否决它**：

1. **搜得更多没有回报。** `opt` 实测：32 个候选里最好的合法候选只高 **+0.0071**，K=10 门槛就要 **0.0078** ⟹ FAIL；**τ² 矩估计 = 0**。要让 Δ=0.005 在 K=40 下可分辨，需要 **n≈6000（当前 14 倍）**。而搜索量回报是对数级（K 40→1000，选择膨胀只从 0.028 涨到 0.042）——**合理候选量是 100~300，一个下午跑完，不要设计能跑上万轮的引擎。**
2. **搜得更自动反而更危险。** §1 的两个洞信号强度是真实差异的 **19 倍**，最大化器会直奔而去且**通过现有所有硬门**。
3. **它会烧掉 holdout 和标注集。** 自动循环每轮都要标量奖励，而唯一无偏的标量在不该反复看的数据上。`tune-pattern-strength` 第 6 步与 `sweep.py` 的 `worst_score` 排序**默认就是每候选跑两窗** ⟹ 搬进自动循环 = 第一轮烧掉 holdout。**这是最容易被忽略的一处误配**（人工低轮次下它是好实践）。
4. **它拆掉唯一的语义先验。** `authoring-path2-app` 的三层 gate + `AskUserQuestion` 是层① 候选质量的唯一来源，该 skill 的 Red Flags 已明文禁止"无人值守多轮改结构"。**更糟的是 `mech` 实测的静默降级**：含 `AskUserQuestion` 的 skill 被派进 subagent 时**不报错，只静默跳过确认**——三层 gate 无声失效，你看不出来。**「skill 能被 agent 调用」和「skill 在 agent 里能正常工作」是两回事。**

**唯一被保留的部分**：它的内层机械化（detect 缓存 + 批量 solve）被 §2.7 吸收——但**用途从"搜索"改成"画稠密响应面以找平台中心"**，即**从选择降级为估计**。

### ❌ 否决 2 · 人在判定侧密集（人当逐轮 reviewer / 人排序候选 / 标注做成目标函数）

1. **人当逐轮 reviewer**：`web-loop` 敢让 reviewer 每轮判 pass/fail，是因为 reviewer 是 LLM 看截图秒级返回。换成人类就是每轮阻塞几分钟到几小时——**正是用户自陈劣势 #1「无法批量处理，一个一个排查」**。⟹ **人只能在生成侧密集，不能在判定侧密集。**
2. **人排序候选**：认知负荷 O(N log N)，且"哪个候选 score 高"是 n=数万的统计问题，人眼完败。
3. **标注当目标函数**：理由是**结构性的而非统计的**——`score` 有减基线保护（退化成基线时 lift≡0，摆烂刷不到分），**`recall` 没有：放开一切过滤即 100%** ⟹ **recall 进目标函数时最优解本身就是退化解**。且 N≥200 才够当目标（10–17 人时，不现实），N=10–30 只够当闸。
4. **"聪明排序省人力"**：`hitl` 588 只实测把自己的提案跑死了（收窄 1.0–1.77x），并把这个失败记录保留了下来——**它的结论（人类时间不可压缩）反过来是整个设计的支点**。

**⟹ 人的正确位置**：生成侧（提候选方向、提漏检样本）+ 单向否决闸。**不在循环内，不做排序，不当目标函数。**

## 6. 诚实清单

### 我这轮推翻的自己（三条）

1. **撤回 (iii) 候选 X2「where 子空间联合最优」** —— `opt` 实测 τ²=0，那块空间里没东西。**我错在把"搜索空间大"当成"里面有东西"。**
2. **撤回"一天 = 全旋钮单因子消融"** —— 同上，且原论证把 n=1 的成功错误归因给了机制。
3. **撤回 D 队列的"按 forward_return 升序抽 + 固定 3/10 门槛"** —— `hitl` 指出升序抽**破坏人与 score 的正交性**（而正交性正是降 K 合法性的前提），且 Binomial(10,p) 判别力太弱。改随机抽 + 与基线对拍。

### 仍然未解决

1. **§2.7 的"平台中心替代 argmax"待 `opt` 裁决。** 我按它设计了。**若不成立，内层 180 次评估的 K 就要满额计入，人降 K 挣的收益被吃掉大半**——退路是把内层压到极少的点数，代价是可能落在非平台上。
2. **`opt` 那条"多保真度阶梯在评估已经很快的前提下还值不值"未裁。** 我的主线**不依赖多保真度**（§2.7 用 detect 缓存是为了**画稠密响应面**，不是为了省评估次数）——如果离了它就不成立，那说明方案有问题。这条我自认过关。
3. **`skeptic` 的目标函数修法未定案。** 我只定强制形式（不可表达），不选方案。
4. **人的判断可靠性无实测**（`hitl` 明确标注为本方案最大的未验证假设）。所以设计里**没有任何"标注一旦录入即不可撤销真值"的环节**——**标注是证据，不是公理**，靠只要二分不要打分 + 强制一行理由 + append-only/provenance 让漂移可见。
5. **★ `BLOCKED.md` 是协议不是代码强制——这是我这个设计的自指弱点。** 它靠"每次调用第一个动作是检测它"这条约定生效，**而这条约定本身也是一句建议**。我用一个约定去强制别的约定。唯一缓解：把检测写进 `authoring-path2-app` 的 **Step 0**（主会话 inline 跑、有 `AskUserQuestion` 天生阻塞的地方），让它成为流程的**物理入口**而不是流程中间的一句话。**我不假装这是完美的强制。**

### 一条方法论自评

本文最有价值的两次修正——**ATR 量纲**（§2.4）和**撤回 X2**（§6）——**都不是靠论证得到的**：一个靠我跑了 5 分钟数据，一个靠 `opt` 跑了全宇宙。

而我 v1 里所有"靠论证"的部分（搜索空间多大、候选多不够、机制多完备），**被实测删掉的比留下的多**。

这解释了为什么我最终推荐的东西**新建组件只有一个 markdown 文件**：

> **这个项目不缺搜索能力，也不缺分析能力。它缺的是让已经想明白的事情真的发生。**

**另附一条 lead 的方法论，我认为它该进设计**：这次 lead 转述 workflow 契约时引入了一个错误（"`phases` 字符串数组非法"，实为合法），被 `mech` 用仓库现存证据抓回。⟹ **任何工作流里"上游 agent 把约束转述给下游 agent"的环节，都是一个错误注入点。** 下游必须**回到原始来源核实**（读代码、读契约、跑探针），而不是信任上游摘要。这与 `authoring-path2-app` 现有红线同构（「凡具体参数值/边结构一律现场读代码，绝不引用任何文档内嵌快照，含本 skill 自己的文档」）——**把它推广成：也不引用上游 agent 的转述。**
